## 什么是文件？IO的对象是什么？

在 Linux 系统中，文件是一个被内核抽象化的 I/O 资源对象

在底层（存储）层面，文件由保存属性的 Inode 和保存实际内容的数据块（Data Block） 组成，文件名则存放在目录文件中

文件是是数据流（文件存储按照字节存储的，数据是本质上是一大块字节，流是运动中的一大块字节，数据流就是按时间顺序排列的字节序列）＋属性（inode大小、权限、时间戳）。

IO的对象？应用层和系统调用层运行在用户态，内核层和硬件底层运行在内核态

应用层：标准IO的对象是：文件流FILE \*。一个结构体里面包着文件描述符+用户缓冲区

系统调用层：文件IO的对象是：文件描述符int fd。一个非负整数。它本质是进程私有的文件描述符表的下标，指向内核中打开的该文件记录

内核层：struct file（内核对象）。内核里真正代表当前打开文件实例的结构体

硬件底层：数据块。磁盘上实际的物理扇区（0和1）

## Linux 系统中的文件有几种类型？分别是什么？

七种

普通文件（-）:最基础的文件类型，是数据在磁盘上的静态存储，内容以字节流的形式存在。

目录文件（d）:目录也是一种特殊文件，它不存储具体数据，而是维护了一张映射表，这张表记录了文件名及其对应的 inode 编号。Linux是通过目录文件将文件名与底层数据关联起来。

符号链接（软链接）(l)：符号链接本质是保存的目标路径字符串。

字符设备文件(c)：用于表示字符设备，这类设备以字符（字节）为单位进行数据传输，像流水一样面向数据流。

块设备文件(b)：用于表示块设备，这类设备以数据块（Block）为单位进行数据传输。

本地套接字(s):用于进程间通信（IPC），它允许不同主机上的进程通过网络交换数据。应用程序通过读写套接字文件描述符，即可实现网络通信

命名管道(p):也称为 FIFO（先进先出） 特殊文件，同样用于进程间通信，但通常是同一台主机上的无亲缘关系进程。数据在内核空间中流动，遵循先进先出的原则。它在文件系统中只是一个访问的“入口”或“参照点。

## 什么是标准IO库？

标准IO库是标准C库的一部分，是封装操作系统底层的系统调用接口，通过自带的用户缓冲区，将多次零散的I/O请求合并成批量操作，可以减少系统调用次数（用户态和内核态之间的切换）。

## 什么是文件流？

文件按照字节的方式存储在内存中，分为静止的块存储和流存储，只要涉及访问、输入输出就是以流的方式。它是按照时间顺序存储的字节序列。

## 标准IO的缓存机制有几种？分别是什么？如何刷新缓存？

行缓存，遇到换行符，缓冲区被填满时，切换输入输出，主动使用fflush刷新缓冲区，文件关闭，进程终止

全缓存，和行缓存一样，区别是遇到换行符不会停止

无缓存，不进行缓冲直接调用IO输出

## fgets和gets的区别？

gets没有长度限制，会导致缓冲区溢出，不保留换行符

fgets会指定最大长度

## 如何设置文件指针的位置？如何获取文件指针的位置？

标准IO，通过`int fseek(FILE *stream, long offset, int whence`函数设置偏移量，`int whence`可以设置成从文件开头偏移，从当前位置偏移，从文件末尾偏移`offset`个字节,offset > 0表示向右（文件末尾）移动。

获取位置用`ftell`函数

文件IO：通过`off_t lseek(int fd, off_t offset, int whence)`函数，和上面的一样。返回值是新的偏移量

## 如何重定向文件流的方向？（从一个文件指向另一个文件）

使用标准IO：`FILE *freopen(const char *pathname, const char *mode, FILE *stream)`

作用：关闭当前的`stream`的文件流（第三个参数），重定向到`pathname`指定的文件（第一个参数）

使用文件IO：`int dup2(int oldfd, int newfd)`

作用：让`newfd`（第二个参数）重定向到第一个参数`oldfd`

feof函数，如果到达文件结尾会返回非零值，否则返回0

## 对目录的操作有哪些函数？为什么没有写目录的函数？

打开目录：opendir()，读取：readdir()，关闭目录：closedir()

因为目录是一种特殊的文件，目录存放的是文件名和inode编号。主要是由内核维护的，用户直接写入会有安全隐患。

原因：目录文件在磁盘中是有严格的字节对齐，记录长度和校验，如果用 `write()` 乱写几个字节，会破坏数据块对齐、导致内存与磁盘缓存不一致、并引发并发竞争，最终造成文件系统损坏或内核崩溃。

## 什么是文件描述符？如何表示？最大范围是多少？遵循什么原则？

文件描述符是是内核为了高效管理已打开文件（设备、套接字、管道等）而创建的非负整数索引，本质上是进程级文件描述符表的下标，程序通过这个整数来操作对应的 I/O 资源，而不用关心底层硬件细节。

用非负整数表示，每个进程启动就会从3开始递增（这三个固定占用0-2，0是stdin，1是stdout，2是stderr）

linux的一个进程最大能打开1024个文件。

遵循最低未使用原则，只要打开新文件内核就会从0开始找最低的没被占用的文件描述符进行分配。

## 什么是函数库？Linux系统中的函数库有几种类型？有什么区别？

函数库是预先被编译好的，可以被其他程序调用的二进制代码集合。

分为两种：

静态库：以.a为结尾，在程序的编译阶段被链接，直接将库中的代码复制到可执行文件中，最终文件大，多进程独立加载副本，更新库后需要重新编译，编译完成后的可执行文件不依赖外部文件

动态库：通常以.so结尾，在程序的编译阶段会记录依赖，最终文件小，多进程共享同一份文件，更新后不需要重新编译，程序启动时设备必须有对应版本的动态库

## 如何制作静态库？如何制作动态库？（写出步骤）

静态库：

1.先写功能源文件，`add.c`

2.对功能源文件进行编译生成目标文件.o,`gcc -c add.c -o add.o`

3.使用ar工具打包成静态库，`ar -cr libmyadd.a add.o`

4.编译主程序并链接静态库，-L：指定库所在路径，-l：指定库名（省略lib和.a），`gcc main.c  -lmyadd -L. -o main_static`

动态库：

1.先写功能源文件，`add.c`

2.生成位置无关代码 PIC，`gcc -c -fPIC add.c -o add.o`

3.-shared 生成动态库,`gcc -shared add.o -o libmyadd.so`

4.编译主程序，链接动态库,`gcc main.c -lmyadd -L. -o main_dynamic`

5.配置动态库路径(临时环境变量、系统配置、系统默认库)

## 总结：标准IO和文件IO的区别？

标准IO依赖的是标准C库，有标准C库自带的用户缓冲区，可移植性好。标准IO主要运行在用户态，必要时会陷入内核（这个陷入是用户主动写的执行指令，cpu执行指令，进入内核态），操作对象是指向FILE结构体的指针。标准IO是通过用户态的缓冲机制来减少系统调用的次数，系统调用会让cpu切换用户态和内核态，每次切换都会让寄存器执行保存恢复等操作。所以这样可以减少cpu的消耗，适合批量小数据处理，比如文本处理。

文件IO依赖Linux内核，由Linux内核提供。无用户态缓冲区，文件IO发起在用户态，执行在内核态，操作对象是文件描述符。文件IO是每次调用都会立即触发系统调用，陷入内核态。因为无用户态缓冲，所以实时性强，适合需要即时响应的场景，比如硬件控制，网络通信

## 什么是系统调用？

系统调用是用户态向操作内核的接口，应用程序向系统调用发出调用，cpu执行指令，然后从cpu从用户态切换成内核态。每次系统调用会进行模式切换，需要保存或者恢复寄存器状态，会影响性能。
