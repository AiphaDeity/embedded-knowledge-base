# Linux是什么？核心特点有哪些？

Linux是有一种操作系统内核，而我们常说的linux系统是基于linux内核和gun项目组成的完整操作系统，它的特点是开源免费和自由，安全性高，可定制性高，网络支持性高，一切皆文件的系统管理方式。

# Linux主要用在哪里？

服务器和云计算，嵌入式设备，超级计算机。

# Linux 和windows有哪些不同？

Linux:FHS标准化管理文件，权限管理机制高，开源免费，主要是命令行交互，主要应用于服务器嵌入式超级计算机等。

windows:盘符管理文件，用户默认权限高，商业，主要是图形交互，主要应用于笔记本电脑等。

# Linux中的软连接和硬链接有什么区别？

软链接的命令是：ln -s 被链接的文件/目录(绝对路径) 创建软链接文件名称 ,软链接的创建文件和源文件的inode号不同，删除源文件后创建文件无法访问，可以链接目录，可以跨文件系统。本质是创建一个文件保存文件的绝对路径字符。

硬链接的命令是： ln 被链接的文件 创建硬链接文件名称，不能跨文件系统，删除文件后可访问。本质上是在当前分区的 inode 表里，给某个已经存在的 inode 编号多加了一个“文件名”，源文件和链接文件必须在同一块硬盘的同一个分区里。

Linux的名字是linus（linux的开发人）和unix的组合。linux是启发于unix开发的一个开源的操作系统。

# apt的工作原理？如果下载失败怎么办？

分为四个操作，用户操作，联网操作（无网跳过），执行操作，状态更新

首先用户执行apt命令，系统对命令进行解析，判断操作需不需要联网，若不需要直接进行执行操作。有网操作是apt处理安装，先读取软件配置，再下载元数据，更新本地元数据缓存，再下载软件包到缓存目录，解析依赖和却确定要下载的包版本。无网操作是删除类命令，直接调用dpkg执行卸载操作。有网是调用dpkg执行底层安装/升级操作。最后安装或者升级或者卸载操作执行完，系统会更新本地数据库。

下载失败：

一般是更新软件源，然后尝试修复，再检查网络等，重新下载安装，还要看错误类型，有些是设备能联网但apt报错，还得看报错原因连接超时还是，就需要换成国内源。如果系统时间和实际时间相差大也会报错。

# dhcp是什么？dns是什么？

DHCP动态主机配置协议：当电脑连接网络时自动给电脑分配一个可用的ip地址，不用手动配置。  
DHCP工作原理：可以分为四个步骤发现（设备寻找服务器），提供（服务器提供ip及配置），请求（客户端确认所选的IP），确认（服务器最终分配ip,客户端应用配置）

DNS是域名系统：将人类易读的域名解析为计算机网络可识别的 IP 地址从而实现网络资源的准确定位与访问。

工作原理：用户向DNS服务器发送查询请求，询问该域名对应的ip地址是多少，然后DNS服务器查询并把ip地址返回给用户主机。

# 简述gcc的编译过程？

预处理:gcc -E 1.c -o 1.i。将源文件中的文件包含展开，条件编译，宏定义替换，注释替换成空格，生成.i的预处理文件

编译gcc -S 1.i -o 1.s。会分析文件中的词法，语法，语义错误，将预处理文件转换成汇编文件

汇编gcc -c 1.s -o 1.o，将汇编文件转换成机器能识别的二进制文件

链接gcc 1.o -o 1.exe，会进行符号解析，重定向，段合并。将多个.c文件和库链接生成可执行文件。

# 环境变量的作用是什么？

和PATH环境变量的本质区别：用来配置程序的环境，是用来告诉程序你是谁、你家在哪、你喜欢说什么语言、你喜欢用什么编辑器。

# PATH环境变量的作用是什么?

本质上是保存多个目录路径，路径之间用"："号隔开，可以在任意目录下启动程序，输入命令后shell会按照从左到右的顺序依次寻找PATH中列出的所有目录，直到找到程序名执行并运行，找不到会报错。

# Makefile是什么？为什么要使用它？

makefile是用于构建自动化编译多文件项目，避免每次修改代码都要输入很多代码和避免修改一个文件也要重新编译的问题。由目标文件，依赖文件，命令组成。使用它可以省时间，只重新编译修改的文件。避免每次敲很长的代码。自动化处理依赖链，修改一个.h文件make会自动处理和它有关的文件重新链接生成文件

# Makefile 中常用的自动变量有哪些？

目标，依赖，命令

\$@目标文件

\$<第一个依赖

\$^全部依赖（会自动去除重复的依赖文件）

\$?比目标新的依赖

\$+全部依赖（不去重）

\$\*只匹配主干部分，main.c，\$\*的值就是main是主干，.c是匹配

# 操作系统如何识别一个文件？

在 Linux 内核中，每一个文件对象（VFS inode）都由两个数值共同唯一确定：

`dev_t`（设备号）：标识这个文件位于哪一块硬盘、哪一个分区

`ino_t`（inode号）：标识这个文件在这个分区内的索引位置

操作系统识别一个文件，用的不是“单一的身份证号（inode）”，而是“设备号 + inode”的组合。（非常重要）

设备号是什么？设备号由两部分组成，在 Linux 系统中，设备号其实是一对数字：

- 主设备号（Major）：表示设备类型（或者说由哪个驱动程序管理）。比如所有的 SCSI/SATA 硬盘都是 `8`，所有 U 盘也是 `8`。
- 次设备号（Minor）：表示第几个设备/第几个分区。比如 `1` 代表第一个分区，`2` 代表第二个分区。

inode 号本质上是一个指针，它指向硬盘上具体的物理扇区（LBA地址）。

硬链接必须创建在“同一个分区（即同一个文件系统）”内，软链接完全不受“同一分区”的限制，它可以轻松跨文件系统（分区）。

# 那为什么硬链接删除文件后仍可以访问？

删除文件时，系统只是把该文件的 inode 位图 和 数据块位图 标记为“空闲”（即“可重用”标签）。但注意： 只有当这个 inode 的硬链接计数（nlink）降为 0 时，才会打上这个标签。如果有硬链接还在，这个标签永远不会被打上。

Linux 文件系统通过 “设备号 + Inode” 实现物理寻址，通过 “目录项 + 链接计数” 实现多路径引用管理。硬链接是物理层面的多对一映射（限于同一设备），软链接是逻辑层面的路径抽象（无关设备）。理解删除与恢复的本质，关键在于区分 inode 回收条件（`nlink` 降零）与 路径解析机制（软链接的特殊性）。

# 环境变量和PATH变量的关系

环境变量和PATH本质上都是键值对，子进程会继承父进程，查看方式env或者echo \$PATH（PATH）或echo \$HOME，设定方式也一样。

核心区别是：shell(命令行)依赖PATH去搜索命令，其他变量只是被应用程序读取用作配置。结论：shell是在查找阶段，只去看PATH变量，其他的环境变量是在程序运行期间阶段，应用程序可以自由读取其他的变量来调整行为，比如英语，中文

shell的本质是用户层和操作系统内核之间的交互桥梁，通过解析用户的指令，通过系统调用向操作系统内核发出请求，然后内核根据调用，调度驱动程序，再操作硬件，硬件执行后将结果返回shell，展示给用户。

**最终闭环：**

Shell 启动时，会读配置文件（如 `.bashrc`），在内存里建立一张独一无二的 “环境配置表”（里面包含唯一的 `LANG`、唯一的 `HOME`、唯一的 `PATH` 等）

敲命令时，Shell 依赖 `PATH` 找到程序文件。

Shell 调用 `fork` + `execve`，把这张 “环境配置表”（envp） 原封不动（或经过修改）传给新程序。

新程序启动后，通过 `getenv("LANG")` 查看这张表，按照你的唯一偏好来运行

**最终总结：**

环境变量是进程运行时的‘键值对配置上下文’。`PATH` 是专门服务于 Shell 命令查找的特例，而其他变量则承载了用户偏好、路径定位和运行时行为等配置信息，供应用程序在启动后通过 `getenv()` 读取
