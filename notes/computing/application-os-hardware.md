# 应用程序、操作系统和硬件怎样配合

在带操作系统的设备上，可以从应用程序、操作系统和硬件三个层次追踪一次操作。以 Linux 应用读取串口为例，应用持有已经打开的设备文件描述符，内核通过驱动管理设备，串口控制器负责按波特率实际接收数据。

## 顺着一次读取走

1. 应用调用 `read()`，交给系统一个文件描述符、目标缓冲区和期望读取的最大字节数。
2. 内核识别文件描述符关联的设备。串口有可读数据时，读取路径把符合当前终端配置的数据交给应用。数据尚未准备好时，阻塞行为取决于文件的打开方式和终端配置。
3. 应用检查返回值。正数是实际读到的长度，可能小于请求长度。应用决定这些字节能否组成完整协议帧。

## 区分两种边界

系统调用接口让用户态程序请求内核服务。指令集架构规定处理器向软件提供哪些指令和机器行为。应用里普通的算术指令也会在处理器上执行，访问设备这类受操作系统管理的操作才需要相应的内核接口。

在 STM32 裸机程序中，同一类读取问题仍然要追数据从外设到应用缓冲区的路径。常见入口变成寄存器或 HAL 驱动接口，后面再看轮询、中断或 DMA 负责哪一段。
