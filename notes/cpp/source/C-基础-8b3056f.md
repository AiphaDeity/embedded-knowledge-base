# C++学习第一性原理

C语言的第一性原理：**面向过程、内存手动管控、极简结构化编程**，核心是「告诉计算机每一步做什么」。

C++不是C的升级版，而是**兼容C的全新编程范式**。90%的初学者踩坑，都是用C的思维写C++代码。

**C++终极第一性原理（核心总纲）**：**在C的高效、底层内存可控的基础上，用「抽象、封装、复用、多态」解决大型程序的复杂度问题，兼顾性能与工程化**。

简单一句话：C负责「把事做对」，C++负责「把大事做好、做大、维护好」。

---

## C++ 四大底层第一性原理（所有语法的根）

所有C++语法、特性、关键字，全部都是这4条原理的延伸，记住即可推导所有知识点。

**原理1：完全兼容C，保留极致性能（C++的根基）**

这是C++区别于Java/Python的核心优势。

- **本质**：C++没有为高级特性牺牲底层效率，C的指针、内存、位运算、结构体、流程控制在C++中全部可用。
- **核心逻辑**：高级特性（类、继承、多态）是**编译期语法糖**，运行时几乎无额外开销。
- **对你的意义**：你扎实的C基础，是学C++最大的优势，不用重学底层内存逻辑，只需叠加新思维。
- **避坑点**：不要抛弃指针、手动内存，C++高级开发者依然大量使用底层C特性。

**原理2：用「封装」解决数据与行为分离的混乱（OOP核心根基）**

C语言的致命缺陷：**数据（结构体）和操作数据的函数是分开的**。

C语言写法（痛点）：

```c
// C语言：数据和函数分离
struct Student { char name[20]; int age; };
void printStudent(struct Student s); // 函数独立在外
```

当代码量上万行，你无法快速知道「哪个函数操作哪个数据」，代码极度混乱。

**C++封装原理**：**将数据（成员变量）和操作数据的行为（成员函数）捆绑成一个整体（类/对象）**，并隐藏内部细节，只暴露可用接口。

**核心价值**：高内聚、低耦合，数据受保护，不会被随意篡改。

**原理3：用「继承」解决代码重复造轮子（复用性）**

C语言痛点：没有代码复用机制，相似功能的结构体、函数只能复制粘贴，维护成本极高。

**C++继承原理**：允许一个类复用另一个类的所有属性和方法，只需要扩展新功能，无需重写旧代码。

**底层本质**：编译期代码复用，无运行时开销，是纯粹的工程优化。

**原理4：用「多态」解决统一接口、不同实现（扩展性）**

C语言痛点：想要实现「同一类行为，不同对象不同表现」，只能写大量if-else判断，拓展性极差。

**C++多态原理**：**一个接口，多种实现**，父类定义规范，子类自定义细节，新增功能无需修改旧代码。

**核心价值**：开闭原则——对扩展开放，对修改关闭，是大型项目的核心基石。

## C与C++ 核心思维范式跃迁（必看！脱C入C++的关键）

学不会C++，99%是思维没转过来，而非语法不会。

| 维度 | C语言（面向过程） | C++（面向对象+泛型） |
|-|-|-|
| 核心思想 | 怎么做（步骤、流程、逻辑） | 谁来做（对象、实体、属性+行为） |
| 代码核心 | 函数、流程、算法 | 类、对象、模板 |
| 数据关系 | 数据是被动的，被函数操作 | 数据是主动的，自带行为 |
| 复用方式 | 函数复用、头文件引用 | 继承、组合、模板泛用 |
| 适用场景 | 小型工具、底层驱动、算法 | 大型项目、框架、复杂业务 |

**一句话跃迁**：C写代码是「步骤堆砌」，C++写代码是「定义实体，让实体自己干活」。

## C++ 所有核心特性的第一性原理推导

不用死记语法，从根源推导每个特性的存在意义。

**1. 命名空间 namespace —— 解决C的命名冲突**

**C语言问题**：全局变量、函数名全局唯一，大型项目多人协作极易重名冲突。

**C++原理解决方案**：用命名空间隔离代码域，不同域可以重名。

**本质**：代码分区管理，工程化必备。

**通俗理解**：C是所有人在一个大房间说话，C++是分房间说话，互不干扰。

**2. 引用 &amp; —— 替代C的指针传参，更安全简洁**

**C语言问题**：指针传参繁琐、易空指针、易越界、可读性差。

**C++原理解决方案**：引用是**变量的别名**，底层依然是指针，但是语法安全、无需解引用、不能为空。

**核心第一性原理**：**保留指针的高效（直接操作原数据），消除指针的安全隐患**。

**3. 类与对象 class —— 封装思想的落地载体**

**C结构体缺陷**：只能存数据，不能存函数，数据公开可随意修改。

**C++类升级**：结构体的终极升级版，**数据+行为捆绑+权限控制**（public/private/protected）。

**底层真相**：类在编译后，依然是C的结构体+全局函数，只是语法层面做了封装，零开销。

**4. 构造/析构函数 —— 自动化内存与对象初始化**

**C语言问题**：结构体变量需要手动初始化、手动释放内存，遗漏就会bug、内存泄漏。

**C++原理解决方案**：对象创建自动初始化（构造），对象销毁自动清理（析构）。

**第一性原理**：**将资源的申请和释放绑定对象生命周期，杜绝人为失误**。

**5. 重载（函数/运算符）—— 简化同名逻辑复用**

**C语言问题**：功能相似的函数，必须起不同名字（addInt、addDouble），冗余繁琐。

**C++原理解决方案**：参数不同，函数名可以相同，编译器自动匹配。

**本质**：编译期静态多态，简化代码，统一接口语义。

**6. 模板 template —— 泛型编程，解决类型重复代码**

**C语言问题**：写一个排序函数，int、float、double需要写多份重复代码。

**C++原理解决方案**：一套代码适配所有数据类型，编译期自动生成对应类型代码。

**第一性原理**：**算法与数据类型解耦**，极致的代码复用。

**7. STL标准库 —— C++工程化的终极体现**

**C语言问题**：没有通用容器，数组定长、无法动态扩容，链表、哈希表需要手写。

**C++原理解决方案**：封装好的容器（vector、string、map）+算法（sort、find）。

**本质**：把所有人重复写的底层数据结构，做成统一、高效、安全的工业标准工具。

## C++ 三大编程范式的第一性层级

C++是唯一支持三种主流范式的语言，层级从基础到高阶，学习顺序绝对不能乱：

**第一层：兼容面向过程（你已掌握的C）**

基础语法、流程控制、指针、内存、结构体，是一切的基础。

**第二层：面向对象OOP（C++核心）**

封装、继承、多态（静态、多态）、类、对象、生命周期，解决代码复杂度。

**第三层：泛型编程（C++高阶）**

模板、STL、类型推导，解决代码通用性，是现代C++的核心。

**学习铁律**：先吃透对象思维，再学泛型，不要上来死磕STL和模板。

## C到C++ 最关键的10个思维转换（必背）

1. C关注**过程与步骤**，C++关注**实体与关系**。
2. C的结构体只是数据容器，C++的类是完整的功能模块。
3. C靠指针操作一切，C++优先用引用，指针只用于底层特殊场景。
4. C手动管理初始化/销毁，C++靠对象生命周期自动管理。
5. C函数是孤立的，C++函数属于对象，有归属、有权限。
6. C代码复用靠复制粘贴，C++复用靠继承、组合、模板。
7. C没有接口规范，C++靠多态统一标准，方便拓展。
8. C不区分权限，数据全公开，C++封装保护核心数据，只读不改。
9. C手写所有数据结构，C++优先使用STL工业容器。
10. C追求能用、高效，C++追求**好维护、好拓展、可复用、高性能兼顾**。

## 零基础过渡C++ 最优学习路径（基于第一性原理）

拒绝碎片化学习，按「原理→语法→实战」顺序推进：

**阶段1：C++基础兼容层（3天）**

命名空间、引用、函数重载、默认参数、const强化、bool类型。

**核心目标**：改掉C的老旧写法，适配C++基础语法规范。

**阶段2：面向对象核心（7天，重中之重）**

类与对象、成员权限、构造析构、拷贝构造、静态成员、this指针。

**核心目标**：彻底建立封装思维，会用对象思维写代码。

**阶段3：OOP进阶（5天）**

继承、组合、多态、虚函数、纯虚函数、抽象类。

**核心目标**：掌握代码复用与项目拓展的核心逻辑。

**阶段4：泛型与STL（7天）**

模板、string、vector、map、set、常用算法、迭代器。

**核心目标**：掌握现代C++工程开发标准写法。

**阶段5：进阶特性（后续深耕）**

智能指针、内存管理、右值引用、Lambda、多线程。

---

## 终极总结：C++ 一句话第一性原理

**C++ = C的极致性能 + 面向对象的工程化管理 + 泛型的通用复用能力**

所有C++语法，都是为了解决三个问题：**代码乱、重复多、拓展难**，且全程不牺牲C的底层性能。

只要吃透这个核心，你学任何C++知识点都能瞬间理解「为什么要有这个特性」，而不是死记硬背语法。

## C++ 发展历程

**2.1 C++ 之父：Bjarne Stroustrup（本贾尼・斯特劳斯特卢普）**

1. 1979：开发预处理程序`Cpre`，给 C 增加类机制，项目命名 `C with Classes`（带类的 C）——C++ 雏形
2. 1983：`C with Classes` 正式更名 C++（`++`取自 C 自增运算符，寓意 C 语言的升级扩展）
3. 1985：第一款商用 C++ 编译器发布；出版经典教材《The C++ Programming Language》，C++ 正式商用
4. 1987：GNU C++ 发布，开源生态成型，Linux 社区开始使用 C++
5. 1990\~1992：Borland、微软、IBM 推出商用 C++ 编译器，Windows 商业软件大规模采用 C++

**2.2 ISO 标准化时间线（核心标准）**

1. C++98（1998）：第一套国际标准，完整规范面向对象核心语法（类、继承、多态、命名空间、STL 初代）
2. C++03（2003）：小版本修复，修正 C++98 语法漏洞、优化标准库细节，无重大新特性
3. C++11（2011）—— 现代 C++ 分水岭 里程碑版本，新增大量核心特性：自动类型推导 auto、右值引用、移动语义、Lambda、智能指针、范围 for 循环、统一初始化。现在企业开发最低要求 C++11。
4. C++14：C++11 小幅扩展，简化语法、补充标准库工具
5. C++17：结构化绑定、if constexpr、文件系统库、并行算法，工程实用性大幅提升
6. C++20：重大更新，模块 module、协程 concept、范围库 ranges，彻底解决头文件依赖痛点
7. C++23：完善模块、优化标准容器、增强编译期计算，持续强化性能与编译效率

**补充关键认知**

- C++ 不存在 “淘汰旧版本”，企业项目普遍混用 C++11/17/20，学习优先吃透 C++11 及以上现代语法，不要只学老式 C++98 写法。
- 所有新标准向下兼容 C 语言，你之前写的 C 代码可以直接在 C++ 编译器编译运行。

## 拓展：串联前文 C++ 第一性原理（适配 C 转 C++）

**总纲第一性原理**

C++ = C 的底层高性能 + 面向对象解决大型代码混乱 + 泛型编程消除重复代码，全程不牺牲运行效率

**分原理结合本节内容解读**

1. 兼容 C、保留底层控制 对应应用：嵌入式、系统内核、游戏引擎需要直接操作内存 / 硬件，纯 C 太简陋，高级语言底层受限，C++ 完美折中。
2. 面向对象（封装 / 继承 / 多态）解决工程复杂度 对应应用：大型软件（WPS、游戏引擎、数据库）代码百万行级别，纯 C 函数 / 结构体分散无法维护，类与对象实现模块化。
3. 泛型 + STL 消除重复造轮子 对应应用：音视频、数据库需要大量容器、排序算法，不用像 C 手写链表、动态数组，标准库开箱即用。
4. 双模式内存管理平衡安全与灵活 对应应用：实时系统、游戏需要极致性能时手动管理内存；常规业务使用智能指针自动释放，规避内存泄漏。

**C 语言 vs C++ 核心思维区别**

- C：面向过程，关注步骤、流程，适合小型底层工具；数据和操作完全分离
- C++：面向对象为主，关注实体、模块、关系，适合百万行大型工程；数据 + 行为绑定，支持复用与扩展

## C 语言转 C++ 专属学习建议

1. 不要用 C 思维写 C++：禁止全程只用结构体 + 指针，优先练习类、引用、STL 容器。
2. 学习顺序固定：基础语法（命名空间 / 引用 / 重载）→ 面向对象（封装、继承、多态）→ 现代 C++11 特性 → STL 容器与算法 → 内存管理（智能指针）
3. 实践方向选择

   - 嵌入式方向：侧重 C++ 基础 + 类 + 内存管理，少钻研复杂模板
   - 游戏 / 后端：重点吃透 STL、多态、现代 C++ 特性
   - 音视频：兼顾底层指针与泛型算法
4. 版本选择：练习、项目统一使用 C++11 及以上标准，摒弃老旧 C++98 写法。

## 本节核心背诵总结

1. C++ 由 Bjarne 创造，本质是带面向对象、泛型扩展的兼容型高性能语言；
2. 标准化里程碑 C++98（基础）、C++11（现代 C++ 起点）、C++20（模块 / 协程革新）；
3. 优势：底层可控、双模式内存、多编程范式、高性能；核心赛道：游戏、音视频、嵌入式、高性能服务；
4. 核心底层逻辑：在不丢失 C 性能的前提下，解决大型项目代码复用、维护、扩展难题。

## C++ 编译完整底层流程（核心重点，原文四步编译法 + 原理拓展）

C++ 源代码`.cpp` 到可执行文件分 4 个独立阶段，每一步都有明确作用，对应底层编译原理

## 四步分步编译（g++ 完整命令，Windows 终端执行）

**① 预处理（-E）**

作用：展开头文件、替换 #define 宏、删除注释、处理条件编译 命令：

```bash
g++ -E helloworld.cpp -o helloworld.i
```

输出文件后缀：`.i` 纯文本预处理文件

**② 编译（-S）**

作用：把预处理后的 C++ 代码翻译成汇编代码 命令：

```bash
g++ -S helloworld.i -o helloworld.s
```

输出文件后缀：`.s` 汇编文本文件

**③ 汇编（-c）**

作用：汇编器将汇编指令转为 CPU 可识别二进制机器码，生成目标文件 命令：

```bash
g++ -c helloworld.s -o helloworld.o
```

输出文件后缀：`.o` 二进制目标文件（无法直接运行）

**④ 链接（无参数）**

作用：链接器把多个`.o`目标文件 + 系统标准库（iostream、libgcc 等）合并，生成操作系统可执行程序 命令：

```bash
g++ helloworld.o -o helloworld.exe
```

Windows 输出：`.exe`；Linux/macOS 输出无后缀可执行文件

## 一步到位编译（日常开发使用）

省略四步手动拆分，直接从.cpp 生成可执行文件，学习后期写代码全部用这个：


运行程序（终端）

## 标准输入输出流 cin /cout（C++ 核心，区别 C 的 printf/scanf）

**3.1 流的核心概念**

流（stream）：数据有序传输的抽象模型，数据像水流一样从一端流向另一端。 C++ 把输入、文件读写全部封装为流类，所有 IO 操作统一使用`<<`插入、`>>`提取运算符。

**3.2 流类继承结构图解读**

![图片展示了C++流类的继承结构图。最顶层基类为`ios`，其下有两个分支，分别是`istream`（输入流，派生`ifstream`文件读、`iostream`标准IO）和`ostream`（输出流，派生`ofstream`文件写）。`iostream`同时继承`istream`和`ostream`，`fstream`则继承`iostream`。该图与文档中对C++流类继承结构的解读相呼应，直观呈现了各流类之间的继承关系。](/feishu-assets/311d02b19a31.jpg)

C++流类继承图

1. 顶层基类：`ios` 所有流的父类，定义基础 IO 属性；
2. 两大分支： 

   - `istream`：输入流（读取数据），派生`ifstream`文件读、`iostream`标准 IO；
   - `ostream`：输出流（写入数据），派生`ofstream`文件写；
3. `iostream`：同时继承输入 + 输出，实现控制台读写；
4. `fstream`：文件读写专用流。

**3.3 标准输入输出对象**

1. `cout`：`ostream`预定义全局对象，控制台输出，运算符 `<<`（插入）
2. `cin`：`istream`预定义全局对象，控制台输入，运算符 `>>`（提取）
3. 头文件依赖：必须引入 `#include <iostream>`
4. 命名空间：`cout/cin` 存放在`std`命名空间，两种写法：

```cpp
// 写法1：全程加std::（工程推荐，避免命名污染）
std::cout << "hello";
int age;
std::cin >> age;

// 写法2：全局引入命名空间（自学小代码常用）
using namespace std;
cout << "hello";
cin >> age;
```

**3.4 endl 与 \n 核心区别（高频考点补充）**

1. `endl`：换行 + 强制刷新输出缓冲区，立刻打印到屏幕；频繁大量输出时效率低；
2. `\n`：仅单纯换行，不刷新缓冲区，缓冲区满后统一输出，性能更高；

```cpp
cout << 123 << endl; // 换行+刷新缓冲区
cout << 456 << '\n'; // 仅换行，不刷新
```

**3.5 完整输入输出示例**

```cpp
#include <iostream>
using namespace std;

int main()
{

    string name;
    // 输出
    cout << "请输入姓名和年龄：" << endl;
    // 输入，自动跳过空格、回车
    cin >> name >> age;
    cout << "姓名：" << name << "，年龄：" << age << endl;
    return 0;
}
```

## 程序注释

注释：仅用于开发者阅读，编译时完全忽略，不生成机器码，不影响程序运行。

**三类注释写法**

**（1）单行注释 //**

从`//`开始到本行末尾全部注释，支持任意位置，推荐日常使用。

```cpp
int score = 90; // 学生考试分数
// int temp = 100; 注释掉整行代码
```

**（2）多行块注释 /\* \*/**

跨多行注释，起始`/*`，结束`*/`

```cpp
/*
int a = 10;
int b = 20;
int sum = a + b;
*/
```

**（3）预处理批量注释 #if 0 ... #endif**

适合注释几百行大段代码，完美解决多行注释嵌套报错问题

```cpp
#if 0
这里可以放任意多行代码
包含/* */也不会报错
int test = 123;
#endif
```

**关键禁忌：多行注释不能嵌套**

错误写法（编译器识别第一个`*/`直接结束注释，剩余代码报错）

```cpp
/*
    /* 内层注释 */  // 此处*/提前闭合，后面代码失效
    int num = 10;
*/
```

解决方法：内层全部改用`//`单行注释。

**注释编写规范补充**

1. 函数上方写块注释，说明功能、参数、返回值；
2. 复杂逻辑行尾加单行注释；
3. 不写无意义注释（`i++;//i自增`）；
4. 废弃代码不要直接删除，注释保留便于回溯。

1. 命名严格遵循前文驼峰 / 下划线规范；

# C++ 命名空间

## 命名空间简介

**定义**

命名空间是 C++ 专属代码隔离机制，通过 `namespace` 关键字划分独立代码域，不同域可以存在完全相同名称的变量、函数、类，不会产生命名冲突。

**诞生的根本原因（C 语言致命缺陷补充）**

C 语言所有全局标识符（变量、函数）共享唯一全局作用域，多人协作、引入第三方库极易出现重名报错：

- 场景 1：自己写一个`add()`加法函数，引入的图形库也有`add()`，编译直接报重定义；
- 场景 2：项目分网络、数据库、UI 模块，模块间同名变量无法区分。

**三大核心价值**

1. 杜绝命名冲突：不同模块、第三方库同名标识符互不干扰；
2. 模块化分层管理：按业务 / 功能划分代码域（网络命名空间、日志命名空间、工具命名空间）；
3. 提升可读性与维护性：通过命名空间快速区分代码归属模块，大型项目必备工程特性。

**标准库实例佐证**

C++ 所有标准 IO、容器、算法全部放在 `std` 命名空间：`std::cout`、`std::cin`、`std::vector`，就是为了不和用户自定义标识符冲突。

## 命名空间基础定义与访问

**2.1 定义语法**

```cpp
namespace 空间名
{
    // 可存放：变量、函数、类、结构体、其他命名空间
    int a;
    int add_int(int a, int b)
    {
        return a + b;
    }
}
```

**2.2 原文示例完善（修复文档残缺代码）**

```cpp
namespace myspace1
{
    int a = 10;
    int add_int(int a, int b)
    {
        return a + b;
    }
}

namespace myspace2
{
    int a = 20; // 和myspace1同名变量，无冲突
    int add_int(int a, int b)
    {
        return a - b;
    }
}
```

**2.3 访问命名空间成员：作用域解析运算符 ::**

语法：`命名空间名::成员名` 

作用：明确指定要访问哪一个空间内的标识符，无歧义。

```cpp
#include <iostream>
int main()
{
    // 分别访问两个空间的同名变量、函数
    std::cout << myspace1::a << std::endl;    // 输出10
    std::cout << myspace2::a << std::endl;    // 输出20

    std::cout << myspace1::add_int(5,3) << std::endl; // 8
    std::cout << myspace2::add_int(5,3) << std::endl; // 2
    return 0;
}
```

**补充知识点：全局域 ::**

单独使用`::变量名`代表访问全局命名空间（不属于任何自定义 namespace 的全局变量）：

```cpp
int num = 100;
namespace test
{
    int num = 10;
    void func()
    {
        std::cout << num;   // 输出10（本空间内）
        std::cout << ::num; // 输出100（全局变量）
    }
}
```

## using 关键字（简化书写的语法糖）

`using` 作用：省去重复书写 `命名空间::`，分为两种使用方式。

**3.1 方式 1：引入单个成员（推荐工程开发）**

语法：`using 命名空间::成员;` 仅把指定一个标识符引入当前作用域，不会污染全局命名空间，冲突风险极低。

```cpp
using std::cout;
using std::endl;

int main()
{
    cout << "测试" << endl; // 直接使用，无需std::
}
```

**3.2 方式 2：引入整个命名空间（自学小 Demo 常用，大型项目不推荐）**

语法：`using namespace 命名空间名;` 将空间内所有标识符全部导入当前作用域，简化代码，但存在重名隐患。

```cpp
using namespace std;
int main()
{
    cout << "hello";
    cin >> x;
}
```

**3.3 using 关键字核心注意事项（文档补充拓展）**

1. 大型项目禁止全局写 `using namespace std;` 若自己定义`vector`、`string`、`cout`，会和 std 库标识符冲突，编译报错；
2. 仅允许在函数内部、局部作用域使用`using namespace xxx;`，局部生效不污染全局；
3. 多层 using 冲突时，编译器优先匹配局部自定义标识符；
4. 代码规范分级建议： 

   - 练习、小型测试程序：`using namespace std;` 方便；
   - 企业项目、库开发：只用`using std::cout;` 导入单个成员，或全程写`std::`。

**冲突示例（踩坑演示）**

```cpp
#include <iostream>
using namespace std;

int cout = 100; // 变量名和std::cout重名，编译报错
```

## 匿名命名空间（无名称 namespace）

**定义语法**

namespace 后不写空间名称，即为匿名命名空间：

```cpp
namespace
{
    int val = 99;
    void print_msg()
    {
        std::cout << val;
    }
}
```

**核心特性（重点）**

1. 作用域仅限当前`.cpp`源文件，其他文件无法访问；
2. 无需`空间名::`，同文件内直接访问内部成员；
3. 底层等价 C 语言 `static` 修饰全局变量 / 函数，但功能更强（可存放类、模板）；
4. 多文件项目中，不同文件的匿名命名空间互相独立，完全隔离。

**冲突场景访问写法**

如果局部变量和匿名空间成员重名，用空`::`指定匿名空间：

```cpp
namespace
{
    int x = 10;
}
int main()
{
    int x = 20;
    std::cout << x;    // 20 局部变量
    std::cout << ::x;   // 10 匿名命名空间变量
    return 0;
}
```

**和 C static 对比补充**

- C 语言：`static int x;` 仅限制全局变量文件私有，不能修饰结构体、类；
- C++ 匿名 namespace：可封装变量、函数、类、模板，模块化私有代码，现代 C++ 优先替代 static。

## 嵌套命名空间 + 命名空间别名

**5.1 嵌套命名空间定义**

在一个 namespace 内部再定义子 namespace，实现多层级模块化：

```cpp
namespace project
{
    namespace net // 网络模块子空间
    {
        void send_data(){}
    }
    namespace log // 日志模块子空间
    {
        void print_log(){}
    }
}
```

**5.2 多层访问语法：连续::**

```cpp
project::net::send_data();
project::log::print_log();
```

**5.3 命名空间别名（简化深层嵌套书写）**

当嵌套层级很深，每次写完整路径繁琐，可以给长命名空间起短别名： 语法：`namespace 别名 = 原完整命名空间路径;`

```c
// 给深层网络空间起别名
namespace net = project::net;
net::send_data(); // 等价 project::net::send_data();
```

**5.4 C++17 简化嵌套写法（拓展补充，文档未提及）**

C++17 支持一行简写多层命名空间：

```cpp
namespace project::net
{
    void recv(){}
}
```

**5.5 嵌套命名空间优势**

1. 层级清晰：项目→模块→功能，代码结构一目了然；
2. 深度隔离：不同业务子模块彻底分隔，几乎不会出现命名冲突；
3. 别名机制大幅简化长路径调用。

## 高频易错点 + 本节核心总结

**7.1 高频踩坑清单**

1. 混淆`.`和`::`：`.`用于对象访问成员，`::`专门访问命名空间 / 类静态成员；
2. 全局滥用`using namespace std`，引发标识符重定义；
3. 忘记匿名命名空间仅单文件生效，其他文件调用报未定义；
4. 多层嵌套命名空间漏写`::`，路径书写错误；
5. 混淆全局域`::`与普通空间访问符。

**7.2 核心背诵总结**

1. 命名空间`namespace`核心目的：解决 C 语言全局命名冲突，实现代码模块化分层；
2. `::`作用域解析符，唯一访问命名空间成员的基础语法；
3. using 两种用法：单成员导入安全推荐，全空间导入仅适合小型 Demo；
4. 匿名 namespace 替代 C static，内容仅本文件可见，实现代码私有化；
5. 嵌套 namespace 实现多层业务分层，可用`namespace 别名 = 长路径`简化调用；
6. 标准库全部存放在`std`命名空间，是学习命名空间最常用的实例。

# 基本数据类型bool布尔和string字符串

## C++ bool 布尔类型

**基础概念**

1. 命名来源：英国数学家 乔治・布尔，专门存储逻辑真假值，是 if、while、逻辑运算的基础。
2. C++ 核心定位：`bool` 是原生内置基础数据类型，无需引入头文件即可直接使用。
3. 两个字面常量： 

   - `true`：逻辑真，底层数值为 1
   - `false`：逻辑假，底层数值为 0

**内存占用细节（文档补充）**

理论上仅需 1bit 存储 0/1，但计算机内存寻址最小单位为字节：

- 实际内存占用：1 字节（8bit）
- 数组中 bool 数组每个元素同样占 1 字节，不会压缩 bit 位。

**隐式类型转换（C++ 独有核心特性）**

任意数字、指针、字符都可以自动转为 bool：

1. 0、空指针 NULL/nullptr、'\0' → 转换为 false
2. 所有非 0 数字、非空指针、任意可见字符 → 转换为 true 示例：

```cpp
bool b1 = 100;   // true
bool b2 = -5;    // true
bool b3 = 0;     // false
bool b4 = '\0';  // false
bool b5 = nullptr;// false
```

**布尔值输出控制：boolalpha /noboolalpha**

默认情况下 cout 打印 bool 只会输出数字`1`/`0`；

`boolalpha` 开启文字输出（true/false）；

`noboolalpha` 切回数字模式。

```cpp
#include <iostream>
using namespace std;

int main()
{
    bool flag = true;
    cout << flag << endl;          // 默认输出：1
    cout << boolalpha << flag << endl;  // 输出：true
    cout << noboolalpha << flag << endl;// 恢复输出：1
    return 0;
}
```

**高频使用场景补充**

3. 逻辑运算：`&& || !` 的运算结果全部为 bool
4. 容器判断：string.empty ()、vector.empty () 返回 bool

1. 不要写 `if(flag == true)`，冗余，直接 `if(flag)`；
2. 不要用 `1` 代替 true、`0`代替 false，降低代码可读性；
3. C 语言`_Bool`不能用于函数重载区分参数，C++ bool 可以。

## C++ std::string 字符串类

**前置基础**

1. string 属于标准库，存放在`std`命名空间；
2. 必须头文件：`#include <string>`；
3. 和 C 风格字符串区分： 

   - C 字符串：`char[]` / `char*`，以`\0`结尾，操作函数在`<cstring>`；
   - C++ string：封装好的类，自动管理内存，无需手动处理结束符。

**string 四种初始化方式（文档整理 + 完整示例）**


**string 支持的运算符（拼接、比较）**

2. `+=`：直接追加到原有字符串，效率更高

```cpp
string a = "abc";
```


**4.3 std::string 内存优势（对比 C char\*）**

1. 自动扩容、自动释放内存，不会内存泄漏；
2. 自带长度记录，无需遍历计算长度（C strlen 每次遍历）；
3. 直接支持运算符拼接、比较，不用调用 strcat/strcmp；
4. 支持内置查找、截取、插入删除全套工具，不用手写逻辑。

**4.4 注意事项**

1. `"abc"` 是 C 风格`const char[4]`，不是 string 对象，但可以隐式赋值给 string；
2. `string`不能直接传入 C 标准 IO 函数`printf`，需要`.c_str()`转换；
3. find 返回值类型是`size_t`（无符号整数），判断找不到必须和`string::npos`对比，不要用 int 接收。

```cpp
int main()

    bool hasData = true;
```

## C vs C++ 核心差异总结

**bool 布尔类型总结**

1. C++ `bool` 原生基础类型，无需头文件；C99 靠`_Bool`，依赖`<stdbool.h>`；
2. C++ 支持任意数值隐式转 bool，逻辑判断更简洁；
3. cout 可打印 true/false 文字，C printf 只能输出 0/1。

**string 字符串总结**

1. C：底层`char*`，手动管理内存，操作依赖`<cstring>`库函数；
2. C++：std::string 封装类，自动内存管理，内置拼接、查找、截取、比较功能；
3. string 支持运算符`+ == < >`，代码可读性远高于 C 的 strcat/strcmp；
4. `.c_str()` 作为兼容接口，无缝对接 C 语言旧代码。

**高频考点背诵**

1. bool 占 1 字节，非 0 为 true，0 为 false；boolalpha 控制布尔文字输出；
2. string 必须引入`<string>`，属于 std 命名空间；
3. size () 获取长度，find 找不到返回 string::npos，c_str () 转 C 字符串；
4. string 支持`+=`拼接、直接`==`比较，是 C++ 替代 char \* 的标准工具。



# C++ 函数

## 函数基础

**1.1 函数定义与核心作用**

定义:

将一段独立功能的代码封装为代码块，通过函数名调用执行。

**三大核心价值（C 语言同样适用，C++ 在此基础拓展）:**

1. 代码复用：相同逻辑仅写一次，多处调用，消除重复代码；
2. 结构分层：主函数简洁，复杂逻辑拆分到子函数，可读性大幅提升；
3. 易维护调试：仅修改函数内部即可全局生效，无需修改每一处调用。

**函数完整三要素:**

函数声明（原型）、函数定义（实现体）、函数调用。

**1.2 函数声明（函数原型）**

作用:

提前告知编译器函数的返回值类型、函数名、参数列表，允许函数定义写在调用代码后方，支持多文件跨模块调用。

语法:

```cpp
返回值类型 函数名(参数类型1 参数名1, 参数类型2 参数名2,...);
// 参数名可省略，仅保留类型也合法
返回值类型 函数名(类型1, 类型2);
```

示例:

```cpp
// 完整声明
int add_int(int a, int b);
// 简写声明（仅写类型）
void print();
```

**1.3 函数定义（实现）**

包含声明信息 + 函数体（实际执行代码），是函数真正逻辑载体。

语法:

```cpp
返回值类型 函数名(形参列表)
{
    // 函数体逻辑
    return 返回值; // void函数可省略return
}
```

示例:

```cpp
int add_int(int a, int b)
{
    return a + b;
}

void print()
{
    cout << "无返回值函数" << endl;
}
```

**1.4 函数调用**

通过函数名 + 实参触发函数执行，分 4 种调用形式：

1. 无返回值无形参：`print();`
2. 无返回值有形参：`add(1,2);`（丢弃返回值）
3. 有返回值无形参：`int res = getNum();`
4. 有返回值有形参：`int res = add(10,20);`

**1.5 参数传递：按值传递（基础）**

文档基础知识点：传递实参副本，函数内部修改形参不会影响外部实参。

**补充拓展（衔接后续引用章节）**

C++ 除值传递外，还支持引用传递、指针传递，可以修改外部原始数据，解决值传递无法修改实参的痛点。

```cpp
// 值传递示例：修改形参不影响外部变量
void change(int x)
{
    x = 100;
}
int main()
{
    int a = 10;
    change(a);
    cout << a; // 输出10，原值不变
    return 0;
}
```

**1.6 完整执行流程补充（文档缺失）**

1. 程序运行到函数调用处，保存当前函数现场（栈帧、局部变量）；
2. 实参拷贝 / 绑定给形参；
3. 跳转至被调函数内部执行；
4. 执行 return，携带返回值；
5. 销毁被调函数局部变量，恢复调用现场，继续向下执行。

## 函数重载（C++ 独有核心特性，C 语言不支持）

**2.1 定义**

同一作用域内，函数名相同、参数列表不同的一组函数，称为函数重载。

**设计目的:**

统一功能接口，不同数据类型 / 参数数量使用同一个函数名，无需区分`add_int`、`add_double`这类冗长命名。

**2.2 合法重载三大硬性条件（缺一不可）**

1. 同一作用域（同一个 namespace / 类 / 全局域）；
2. 函数名完全一致；
3. 参数列表存在差异（满足任意一条即可）： 

   - 参数个数不同；
   - 参数对应类型不同；
   - 参数顺序不同（多类型参数调换）。

**关键红线：返回值类型不能单独作为重载区分依据:**

```cpp
// 非法重载，仅返回值不同，编译报错
int func(int a);
double func(int a);
```

**2.3 重载底层实现原理：名字修饰（名称重整 name mangling）**

1. 阶段：编译期完成，属于静态绑定（早绑定），运行时无开销；
2. 逻辑：编译器将函数名 + 参数类型拼接生成全局唯一符号，链接器以此区分同名函数；
3. 文档示例拆解：

```cpp
void display(int a){}    // 修饰后符号：_Z7displayi
int display(double a){}  // 修饰后符号：_Z7displayd
```

后缀`i`代表 int，`d`代表 double，实现区分。

> C 语言无名字修饰，同名函数直接重定义报错，因此 C 不支持重载。

**2.4 重载调用匹配规则（编译器优先级）**

1. 精确匹配（最高优先级）：实参类型、数量完全对应某一重载版本，直接调用；
2. 隐式类型转换匹配：无精确匹配时，自动转换基础类型（int→double、char→int）；
3. 最佳匹配原则：选择转换次数最少的重载版本；
4. 歧义报错：多个重载转换代价相同时，编译器无法抉择，报调用模糊。

**重载完整示例:**

```cpp
#include <iostream>
using namespace std;

// 重载1：int单参数
void display(int a)
{
    cout << "整数：" << a << endl;
}
// 重载2：double单参数
void display(double a)
{
    cout << "浮点数：" << a << endl;
}
// 重载3：两个int参数
void display(int a, int b)
{
    cout << "两整数：" << a << " " << b << endl;
}

int main()
{
    display(10);      // 精确匹配int版本
    display(3.14);    // 精确匹配double版本
    display(1,2);     // 匹配双参数版本
    display('a');     // char隐式转int，调用第一个重载
    return 0;
}
```

## 函数默认参数（缺省参数）

**3.1 定义**

声明 / 定义函数时，为形参预设默认值；调用时不传对应实参，自动使用预设值。

**作用:**

兼顾函数灵活性，减少重复传参，等效实现多套调用接口，部分场景可替代简单重载。

**3.2 语法规范**

```cpp
返回值类型 函数名(类型1 变量1=值1, 类型2 变量2=值2, ...)
```

**3.3 强制语法规则：靠右原则（高频考点）**

一旦某个参数设置默认值，该参数右侧所有参数必须全部设置默认值；左侧无默认、右侧有默认属于非法写法。

```cpp
// 合法：默认参数全部靠右
void func(int a, int b = 10, int c = 20);

// 非法：中间参数有默认，右侧无
void func(int a = 10, int b, int c = 20);
```

**3.4 调用规则**

1. 传入实参 → 优先使用传入值，覆盖默认值；
2. 不传实参 → 自动读取声明 / 定义中预设的默认值；
3. 传参从左向右匹配，不能跳过左侧参数直接给右侧默认参数传值。

**3.5 补充拓展（文档缺失）**

1. 默认参数仅写在函数声明中（头文件），定义内部不要重复赋值；
2. 默认参数支持常量、全局变量、常量表达式，不能使用局部变量；
3. 默认参数与重载同时存在易产生调用歧义，需谨慎搭配。

**示例:**

```cpp
// 声明设置默认值
void show(int num, string msg = "默认提示");

int main()
{
    show(100);          // msg使用默认值"默认提示"
    show(200, "自定义");// msg覆盖默认值
    return 0;
}

// 定义不重复写默认值
void show(int num, string msg)
{
    cout << num << " " << msg << endl;
}
```

## 内联函数 inline

**4.1 定义与本质**

普通函数前添加`inline`关键字即为内联函数；本质仍是标准函数，具备完整语法检查、类型校验，区别仅在编译展开方式。

**核心作用:**

消除函数调用开销（栈帧创建、跳转、返回）：编译阶段将函数体代码直接复制插入到每一处调用点，替代函数跳转。

**关键特性：编译器建议而非强制:**

`inline`只是给编译器的优化建议，存在两种特殊情况：

1. 短小频繁调用函数：编译器自动执行内联展开；
2. 复杂函数、递归函数、循环庞大：编译器忽略 inline，按普通函数编译。

**4.2 适用场景（推荐使用）**

1. 函数体短小（1\~5 行简单逻辑，加减、取值判断）；
2. 调用频率极高（循环内、高频工具函数）；

**4.3 禁止使用场景（滥用缺陷：代码膨胀）**

1. 函数体庞大、多层循环、复杂分支；
2. 递归函数（无法展开）；
3. 包含大量静态变量、复杂对象创建的函数； 频繁内联大型函数会使最终可执行文件体积暴涨。

**4.4 内联函数 VS C 语言带参宏（#define）核心对比（文档整理扩充）**

```cpp
{
    int x = ADD(1+2,3)*2;  // 文本替换：1+2+3*2 = 9，逻辑错误
    int y = add(1+2,3)*2;  // 参数先计算，(3+3)*2=12，结果正确
    return 0;
}
```

## 哑元参数（占位参数）

**5.1 定义**

函数参数列表中仅写数据类型、不定义变量名的参数，称为哑元 / 占位参数；函数体内无法读取、使用该参数，仅作占位。

**语法:**

```cpp
返回值类型 函数名(类型1 变量1, 类型2);
// 类型2无变量名，为哑元参数
```

**5.2 核心特性**

1. 无变量名，函数内部不能访问该参数；
2. 调用函数时必须传入对应数量实参，匹配参数列表长度；
3. 仅用于统一函数签名，不参与逻辑计算。

**5.3 四大标准使用场景**

1. 接口兼容、遗留代码升级：修改函数功能时，不改变原有参数个数，保证旧代码调用不报错；
2. 统一重载函数签名：多组重载保持参数数量一致，简化调用逻辑；
3. 模板编程适配：模板推导需要固定参数位置，实际逻辑不需要该参数；
4. 运算符重载强制语法要求：部分重载运算符语法强制要求固定参数个数，使用哑元填充。

**哑元参数完整示例:**

```cpp
// 第二个int为哑元参数，无变量名
void func(int a, int)
{
    cout << a << endl;
    // 无法使用第二个参数，无变量名
}

int main()
{
    func(10, 99); // 必须传两个实参，第二个数值仅占位，函数内丢弃
    return 0;
}
```

## 全章节高频易错点总结

**函数基础**

1. 声明与定义参数列表必须匹配，返回值不能不一致；
2. void 函数可省略 return，有返回值函数必须每条分支 return 对应类型；
3. 值传递修改形参不会影响外部实参。

**函数重载**

1. 仅返回值不同无法构成重载；
2. 跨命名空间 / 跨类的同名函数不属于重载；
3. 隐式转换过多会产生调用歧义编译报错。

**默认参数**

1. 默认参数必须靠右，不能中间断档；
2. 声明与定义不要重复书写默认值；
3. 避免默认参数与重载混用引发歧义。

**内联函数 inline**

1. inline 只是建议，编译器有权拒绝展开；
2. 复杂、递归函数不要加 inline，造成代码膨胀；
3. 优先使用 inline 替代带参宏，规避宏运算 bug。

**哑元参数**

1. 哑元参数必须传入对应实参，不能省略；
2. 函数内部无法读取哑元参数，不要尝试定义变量使用。

# 引用

## 引用基础简介

**引用本质**

引用是已存在变量的别名，和原变量共用同一块内存，不会开辟新空间。 设计目的：替代 C 语言指针传参，保留直接操作原数据的效率，同时简化语法、规避空指针 / 野指针风险。

**标准语法**

```cpp
数据类型& 引用名 = 原变量;
```

示例：

```cpp
int num = 123;
int& ref = num; // ref是num的别名，操作ref等价操作num
```

**四条强制硬性规则（必记）**

① 声明时必须初始化，禁止空引用

```cpp
int& ref; // 编译报错，没有绑定任何变量
```

② 绑定的变量类型必须完全一致

```cpp
double d = 3.14;
int& ref = d; // 报错，类型不匹配
```

③ 绑定对象终身不可更换`ref = b` 不是修改引用指向，只是把 b 的值赋值给原变量，引用依旧绑定最初的变量。

```cpp
int a=10,b=20;
int& r = a;
r = b; // a的值变成20，r仍然是a的别名
```

④ 普通引用不能绑定字面量、临时值

```cpp
int& r = 100; // 非法，100是临时右值
```

**底层补充**

编译器底层会把引用优化为指针逻辑，运行效率和指针完全一致；只是编译器自动屏蔽取地址、解引用操作，不用开发者手动处理。

## 引用结合函数（最常用场景）

**引用作为函数形参**

优势：不会拷贝实参，节省内存；函数内修改引用会直接改变外部原始变量，语法比指针简单。

```cpp
#include <iostream>
using namespace std;

// 引用传递，可修改外部变量
void change(int& x)
{
    x = 999;
}

int main()
{
    int a = 10;
    change(a);
    cout << a; // 输出999，原值被修改
    return 0;
}
```

**引用作为函数返回值（重点避坑）**

✅ 允许返回：全局变量、函数内 static 静态局部变量（生命周期不会随函数结束销毁）

❌ 绝对禁止返回：普通局部变量（函数执行完栈内存销毁，引用指向非法内存，程序崩溃）

```cpp
// 正确写法
int& getStatic()
{
    static int num = 100;
    return num;
}

// 错误写法
int& errorDemo()
{
    int temp = 99;
    return temp; // 局部变量销毁，野引用
}
```

拓展：返回普通引用的函数可以当作左值直接赋值

```cpp
getStatic() = 200; // 合法，修改静态变量值
```

## const 常引用（只读引用，工程高频）

**定义与语法**

`const`修饰的引用，只能读取原变量，无法通过引用修改数据，两种写法完全等价：

```cpp
int val = 123;
const int& r1 = val;
int const& r2 = val;
```

**核心独有特性（普通引用不具备）**

① 可以绑定字面量、临时常量 

```cpp
const int& r = 100; // 合法，编译器自动生成临时变量承接字面量
```

② 可以绑定 const 修饰的常量

```cpp
const int MAX = 1000;
const int& r = MAX; // 合法
int& r2 = MAX;      // 普通引用报错
```

**普通引用 vs 常引用核心区别**

- 普通引用 int&：可读可改；不能绑定常量 / 字面量；适合需要修改外部数据的场景
- 常引用 const int&：仅可读、禁止修改；支持绑定常量 / 临时值；适合仅读取、不想拷贝数据的场景

## 常引用结合函数（企业标准写法）

**常引用做函数形参（优先推荐）**

只读取数据、不修改外部变量，全程无拷贝，兼顾性能与数据安全，字符串、自定义类传参一律使用`const &`。

```cpp
#include <iostream>
#include <string>
using namespace std;

void printStr(const string& s)
{
    // s = "test"; 编译报错，常引用只读
    cout << s << endl;
}

int main()
{
    string str = "C++常引用";
    printStr(str);
    printStr("临时字符串"); // 常引用可直接传字面量
    return 0;
}
```

**常引用做函数返回值**

规则和普通引用一致，不能返回普通局部变量；返回值只读，无法赋值修改。

```cpp
const int& getNum()
{
    static int x = 50;
    return x;
}
// getNum() = 100; 非法，const返回值不可修改
```

## 引用 &amp; 指针全方位对比

1. 初始化规则 引用：声明必须立刻绑定变量，不存在空引用 指针：可先声明不赋值，支持空指针`nullptr`
2. 指向修改 引用：绑定后永久固定，不能切换绑定对象 指针：随时赋值，自由修改存储的内存地址
3. 数据访问 引用：直接使用别名，无需任何符号 指针：必须用`*`解引用才能访问存储的值
4. 安全程度 引用：编译器全程校验，无空值、野内存风险 指针：极易出现空指针、野指针、内存越界，bug 高发
5. 适用场景 引用：函数传参（读写 / 只读）、简化常规业务代码 指针：底层内存操作、动态内存分配、多级寻址、数组

## 完整综合演示代码

```cpp
#include <iostream>
#include <string>
using namespace std;

// 普通引用传参
void modifyData(int& x)
{
    x *= 2;
}

// 常引用只读传参
void showString(const string& s)
{
    cout << "文本：" << s << endl;
}

// 返回static普通引用
int& staticRef()
{
    static int num = 10;
    return num;
}

int main()
{
    // 基础引用
    int a = 5;
    int& refA = a;
    refA = 10;
    cout << "原变量a：" << a << endl;

    // 常引用绑定字面量
    const int& constRef = 999;
    cout << "常引用值：" << constRef << endl;

    // 引用修改实参
    modifyData(a);
    cout << "修改后a：" << a << endl;

    // 常引用传参
    string info = "C++引用学习";
    showString(info);
    showString("临时文字参数");

    // 返回引用作左值
    staticRef() = 88;
    cout << "静态变量值：" << staticRef() << endl;
    return 0;
}
```

## 高频易错点（加粗重点）

1. 普通引用不能绑定数字字面量，只读场景必须用 const &
2.  函数返回引用严禁返回普通局部变量，仅允许全局 /static 变量
3.  `ref = 变量` 只是赋值操作，不会改变引用原本绑定的对象
4.  只读传参统一使用 const &，避免值拷贝同时防止数据被误改
5.  开发规范：需要修改外部数据用普通引用 &，仅读取用 const &；底层内存操作才使用指针

# 动态内存分配与释放

## new 与 delete 基础概念

1. 核心定义`new`、`delete`是 C++ 专属操作符，用于堆内存的运行时分配与释放，替代 C 语言`malloc/free`。

- new：运行时向堆申请内存，自动计算内存大小、支持直接初始化；分配类对象时自动调用构造函数完成初始化，返回对应类型指针，无需强制转换。
- delete：释放 new 申请的堆内存，归还操作系统；释放类对象前自动调用析构函数清理资源。

1. 堆与栈补充拓展（文档缺失）

- 栈内存：局部变量、函数形参，函数执行结束自动销毁，无需手动释放，空间小；
- 堆内存：new 分配的内存，生命周期不受函数限制，必须手动 delete 释放，空间大，适合大数据、数组、对象长期存储。

## 单个元素内存分配与释放

**new 分配单个变量三种语法**

```cpp
// 写法1：仅分配内存，内置类型不初始化（随机脏值）
int* p1 = new int;

// 写法2：分配内存并默认初始化为0
int* p2 = new int();

// 写法3：分配内存并指定初始值
int* p3 = new int(666);
```

**delete 释放单个内存规范**

```cpp
delete p1;  // 释放堆内存
p1 = nullptr; // 释放后置空，杜绝野指针
```

重点规则：单个 new 申请的内存，只能用无方括号`delete`释放，不能写`delete[]`。

**完整示例**

```cpp
#include <iostream>
using namespace std;

int main()
{
    int* p = new int(100);
    cout << *p << endl;  // 取值：100
    delete p;
    p = nullptr;
    return 0;
}
```

## 数组批量内存分配与释放

**new [] 分配数组四种语法**

```cpp
// 写法1：分配5个int，无初始化，内容随机
int* arr1 = new int[5];

// 写法2：分配5个int，全部默认初始化为0
int* arr2 = new int[5]{};

// 写法3：部分初始化，剩余元素自动补0
int* arr3 = new int[5]{1,2,3};
// 数组内容：1,2,3,0,0
```

**delete [] 释放数组规范**

数组必须配套带方括号`delete[]`释放，告知编译器数组元素数量，完整调用所有元素析构函数：

```cpp
delete[] arr3;
arr3 = nullptr; // 释放后置空指针
```

**易错红线**

```cpp
int* arr = new int[10];
delete arr;  // 严重错误！new[] 必须匹配 delete[]
```

**数组完整示例**

```cpp
#include <iostream>
using namespace std;

int main()
{
    int* arr = new int[4]{10,20,30,40};
    for(int i=0;i<4;i++)
    {
        cout << arr[i] << " ";
    }
    delete[] arr;
    arr = nullptr;
    return 0;
}
```

## new/delete 对比 C 语言 malloc/free（扩展补充）

new 优势:

1. 自动计算内存大小，不用手动写`sizeof(int)`；
2. 支持直接初始化，malloc 仅分配内存，值随机；
3. 返回对应类型指针，无需强制`(int*)`转换；
4. 类对象自动调用构造 / 析构函数，malloc/free 只操作裸内存；
5. 内存分配失败可自定义异常处理（malloc 仅返回 NULL）。

malloc/free 短板:

1. 需要手动计算类型字节，强制类型转换；
2. 不会调用构造、析构，无法直接管理 C++ 类对象；
3. 仅分配原始内存，无初始化能力。

## 强制使用规范（加粗核心考点）

1. 严格匹配释放规则

`new 单个元素` ↔ `delete 指针`

`new[] 数组` ↔ `delete[] 指针` 

混用会造成内存残留、程序崩溃、未定义行为。

1. 杜绝内存泄漏 每一次 new /new []，必须配套 delete /delete []；函数内动态内存若不返回指针，函数结束前必须释放，否则堆内存永久占用。
2. 禁止重复释放 同一块堆内存不能多次执行 delete，例如：

```cpp
int* p = new int;
delete p;
delete p; // 未定义行为，程序大概率崩溃
```

1. 释放后指针必须置空 delete 仅回收堆内存，指针变量本身仍保存旧地址，变成野指针；赋值`nullptr`后，再次 delete 空指针不会报错，提升代码安全性。
2. 空指针安全特性 对`nullptr`执行 delete 不会触发崩溃，代码可增加容错判断。

## 综合完整演示代码

```cpp
#include <iostream>
using namespace std;

int main()
{
    // 1. 单个动态变量
    int* single = new int(888);
    cout << "单个值：" << *single << endl;
    delete single;
    single = nullptr;

    // 2. 动态数组
    int* arr = new int[3]{11,22,33};
    for(int i=0;i<3;i++)
    {
        cout << arr[i] << " ";
    }
    cout << endl;
    delete[] arr;
    arr = nullptr;

    return 0;
}
```

## 高频易错点总结

1. new [] 数组不能用普通 delete 释放，会产生内存泄漏与程序异常
2. 动态内存用完必须释放，长期不释放会导致内存泄漏，程序占用内存持续上涨
3. 释放内存后指针一定要赋值 nullptr，防止野指针二次访问 / 二次释放
4. new 支持原地初始化，malloc 无法初始化数据，是 C++ 动态内存核心优势
5. new 分配类对象自动执行构造函数，delete 自动执行析,malloc/free 不支持面向对象资源管理

# 类和对象

## 面向过程 VS 面向对象核心区别

1. 面向过程（C 语言思想） 核心思路：关注执行步骤、流程，数据和操作函数完全分离。 特点：

- 代码拆分为独立函数；
- 数据是被动载体，被函数修改；
- 适合小型简单程序，代码量大后结构混乱。

1. 面向对象（C++ 核心思想） 核心思路：万物皆对象，把数据 + 操作数据的行为封装成整体。 特点：

- 模块化极强，代码复用、扩展简单；
- 数据受权限保护，安全性更高；
- 适合大型、复杂工程项目。

配图逻辑解读：冰箱、大象都是独立对象，各自拥有专属属性（特征）和行为（功能），互不干扰。

## 类与对象基础概念

1. 对象 现实 / 程序中具体实体，有独立特征与行为。 例：冰箱（对象）：属性 = 容量、温度；行为 = 制冷、开门。
2. 类 对同一类事物的抽象模板，统一描述这类事物共有的属性、行为。
3. 类与对象关系 类 = 模板 / 图纸；对象 = 根据模板造出的实例。 
4. 一句话：先定义类，再实例化生成对象。
5. 静态的属性和动态的行为

## 类的定义语法

```cpp
class 类名
{
    访问权限控制符:
        成员变量（属性）;
        成员函数（行为）;
}; // 末尾分号不可省略
```

重点规则：类内不写权限修饰时，默认全部为 private 私有。

示例代码：

```cpp
class Student
{
private: // 默认私有，外部无法直接访问
    int age;
public:
    // 成员函数
    void setAge(int a)
    {
        age = a;
    }
    int getAge()
    {
        return age;
    }
};
```

## 两种对象：栈对象 &amp; 堆对象

**栈区局部对象**

定义方式：`类名 对象名;` 

内存：栈自动分配，出作用域自动销毁，无需手动释放。

 访问成员：`.` 点运算符。

```cpp
Student s;
s.setAge(18);
cout << s.getAge();
```

**堆区动态对象**

定义方式：`类名* p = new 类名;` 

内存：堆手动分配，生命周期自主控制，用完必须`delete`释放。 

访问成员：`->` 箭头运算符。

```cpp
Student* pStu = new Student;
pStu->setAge(20);
delete pStu;
pStu = nullptr;
```

**栈对象 vs 堆对象对比**

- 内存位置：栈 / 堆
- 生命周期：作用域结束自动销毁 / 程序员手动释放
- 访问符号：`.` / `->`
- 优缺点：无需管理内存、使用简单；生命周期灵活，但易内存泄漏

## 类所占内存大小（高频考点）

1. 空类占用 1 字节 无任何成员变量 / 函数的空类，编译器分配 1 字节，保证每个对象拥有独立内存地址，区分不同实例。

```cpp
class Empty{};
cout << sizeof(Empty); // 输出 1
```

1. 访问权限不占用内存 public/private/protected 仅编译期做访问检查，运行时不占用对象空间。
2. 成员函数不占对象内存 所有成员函数统一存放在代码段，所有对象共享同一份函数代码，不会每个对象复制一份。
3. 只有成员变量决定类大小 对象内存仅存储成员变量，同时遵循系统内存对齐规则，实际占用会向上补齐对齐字节。

示例：

```cpp
class Test
{
    int a; // 4字节
    double b; // 8字节
public:
    void func(){} // 不占内存
};
// 内存对齐后 sizeof(Test) = 16
```

## 核心加粗重点规则

1. class 定义结尾必须加分号，漏写会编译报错
2. 类默认访问权限为 private，外部不能直接读取私有成员变量
3. 栈对象用。访问成员，堆对象指针用 -> 访问成员，不能混用
4. 成员函数、访问控制符均不占用对象内存，只有成员变量影响类大小
5. 空类大小固定 1 字节，目的是保证每个对象拥有唯一内存地址
6. new 创建的堆对象必须配套 delete 释放，释放后指针置空防止野指针

## 完整综合示例代码

```cpp
#include <iostream>
using namespace std;

// 定义学生类
class Student
{
private:
    int age; // 私有成员变量
public:
    // 成员函数
    void setAge(int a)
    {
        age = a;
    }
    int getAge()
    {
        return age;
    }
};

int main()
{
    // 1. 栈对象
    Student s1;
    s1.setAge(18);
    cout << "栈对象年龄：" << s1.getAge() << endl;

    // 2. 堆对象
    Student* pS = new Student;
    pS->setAge(20);
    cout << "堆对象年龄：" << pS->getAge() << endl;
    delete pS;
    pS = nullptr;

    // 空类大小测试
    class Empty{};
    cout << "空类占用字节：" << sizeof(Empty) << endl;
    return 0;
}
```

# 构造函数

## 构造函数基础通用概念

**构造函数定义**

构造函数是类专属特殊成员函数，创建对象时自动调用，核心职责：初始化对象成员、申请资源（堆内存、文件句柄、锁等），保证对象创建后处于合法可用状态。

**核心硬性特征**

1. 函数名必须和类名完全一致，区分大小写；
2. 无任何返回值，不能写 int/void/auto，连 void 都禁止；
3. 支持函数重载（参数个数 / 类型不同即为不同构造）；
4. 一般声明为`public`，私有构造仅单例 / 内部创建对象场景使用；
5. 对象生命周期起点自动调用，无法手动主动调用。

**完整标准语法**

```cpp
class 类名 {
public:
    // 构造函数 : 初始化列表 { 函数体 }
    类名(形参列表) : 成员1(初始值), 成员2(初始值) {
        // 构造函数体：赋值、业务逻辑、资源申请
    }
};
```

**构造函数三大分类**

1. 默认构造函数（无参 / 全默认参数）
2. 有参构造函数（1 个及以上参数）
3. 拷贝构造函数（补充拓展：文档未提及，高频考点）

---

## 初始化列表

**2.1 初始化列表定义**

初始化列表是写在构造函数参数括号后、函数大括号前的初始化语法，执行时机早于构造函数体，直接完成成员初始化，而非先创建再赋值。 语法模板：

```text
类名(参数) : 成员名1(初始化表达式), 成员名2(值), 成员3{值}
{ 构造函数体 }
```

> C++11 起支持大括号初始化`成员{值}`，避免窄化转换，推荐优先使用。

**2.2 初始化列表核心优势**

1. 效率更高 构造函数体内是「先默认构造成员 → 再赋值覆盖」两步； 初始化列表直接一步构造成员，自定义类、容器可省去一次拷贝 / 临时对象开销。
2. 解决语法强制限制：部分类型只能用初始化列表初始化，函数体内赋值直接编译报错。
3. 区分同名成员与形参，逻辑清晰。

**2.3 必须使用初始化列表的 4 种强制场景（文档原文 + 拓展）**

**场景 1：const 修饰的成员变量**

const 变量一旦创建不可修改，构造函数体里赋值属于二次修改，非法；必须在初始化阶段直接给定初始值。

```cpp
class Test {
public:
    const int a;
    // 正确：初始化列表初始化const
    Test(int x) : a(x) {}
    // 错误：a已经初始化，函数体内赋值修改const
    // Test(int x) { a = x; }
};
```

**场景 2：引用类型成员**

引用创建时必须立刻绑定有效变量，不存在 “空引用”；构造函数体执行时成员已默认构造（引用无默认构造），无法后续绑定。

```cpp
class Test {
public:
    int& r;
    // 正确：列表绑定外部变量
    Test(int &x) : r(x) {}
    // 错误：引用无默认构造，函数体内无法赋值绑定
};
```

**场景 3：无默认构造的自定义类成员**

若成员是另一个类，且该类没有无参默认构造函数，编译器无法自动构造该成员，必须手动在初始化列表传参构造。

```cpp
class A {
public:
    A(int x) {} // 只有有参构造，无默认构造
};
class B {
public:
    A obj;
    // 正确：列表手动构造A对象
    B() : obj(10) {}
    // 错误：编译器尝试A::A()，不存在，编译失败
    // B() { obj = A(10); }
};
```

**场景 4：成员变量与构造函数形参同名**

区分成员`this->a`与形参`a`两种写法，初始化列表更简洁直观。

```cpp
class Test {
public:
    int a;
    // 列表：a代表成员，括号内a是形参
    Test(int a) : a(a) {}
    // 函数体内写法：需要this指针区分
    // Test(int a) { this->a = a; }
};
```

**2.4 关键坑点：初始化顺序≠列表书写顺序**

成员初始化严格按照类内声明顺序执行，和初始化列表书写先后无关，极易产生未定义行为。 示例：

```cpp
class Test {
    int x; // 先声明
    int y; // 后声明
public:
    // 先初始化x(y)，此时y未初始化，值随机
    Test(int val) : y(val), x(y) {}
};
```

解决方案：初始化列表内不要用同对象其他成员作为初始化值。

## 默认构造函数（文档 2 内容 + 拓展）

**3.1 定义**

无需传入任何实参即可调用的构造函数，两种合法形式：

1. 无任何形参的构造函数；
2. 所有形参都带有默认值的有参构造函数。 作用：`类名 obj;` 无参创建对象时自动调用，初始化成员默认值。

**3.2 两大分类：隐式默认构造、显式默认构造**

**1）隐式默认构造（编译器自动生成）**

触发条件：用户完全没有自定义任何构造函数（无默认、无有参、无拷贝），编译器自动合成一份无参构造。 特性：

- 内置基本类型（int/double/ 指针）：不会清零，内存残留随机脏值；
- 自定义类成员：调用其自身默认构造；
- 无任何自定义逻辑，空函数体。 失效场景（编译器不再生成隐式默认构造）： 只要手写任意一种构造（有参 / 拷贝），编译器放弃合成默认构造。

**2）显式默认构造（程序员手动编写）**

分两类写法：

写法 1：无参构造:

```cpp
class Person {
public:
    // 显式无参默认构造
    Person() {
        age = 0;
        name = "";
    }
    int age;
    string name;
};
// 调用：Person p;
```

写法 2：全部参数带默认值:

```cpp
class Person {
public:
    // 所有参数都有默认值，可充当默认构造
    Person(int a = 0, string n = "") {
        age = a;
        name = n;
    }
    int age;
    string name;
};
// 无参调用：Person p;
// 传参调用：Person p(18, "张三");
```

**3.3 C++11 关键字 =default 强制默认构造**

补充文档未提及语法，推荐使用：

```cpp
class Test {
public:
    // 显式告诉编译器生成默认构造，即使写了其他构造
    Test() = default;
    Test(int x) { a = x; }
    int a;
};
```

**3.4 类型判断工具：std::is_default_constructible**

头文件 `<type_traits>`，编译期判断类型是否支持无参构造创建对象。

```cpp
#include <type_traits>
bool res1 = std::is_default_constructible<Person>::value;
// res1=true：存在默认构造
bool res2 = std::is_default_constructible<A>::value;
// res2=false：A只有有参构造，无默认构造
```

**3.5 易错场景**

1. 仅写有参构造，不写默认构造：`Person p;` 直接编译报错；
2. 同时存在无参构造 + 全默认参数构造：调用`Person p;` 产生二义性，编译器分不清调用哪个，禁止同时定义；
3. 内置类型隐式默认构造不会自动置 0，数组、局部对象容易出现脏数据。

## 有参构造函数 + explicit 关键字

**4.1 有参构造定义**

接收一个或多个形参的构造函数，创建对象时传入自定义数值，精准初始化成员，避免默认值不符合业务需求。

**4.2 四种参数类型详解**

**普通参数**

无默认值，实例化必须传对应实参，简单直观。

```cpp
Person(int a, string n) { age = a; name = n; }
Person p(20, "李四");
```

**默认参数**

部分 / 全部参数设置默认值，不传则使用默认值，兼顾灵活性。

```cpp
Person(int a = 18, string n = "未知") {}
Person p1;      // 全默认
Person p2(25);  // name使用默认
```

**哑元参数（无用参数）**

形参声明但函数内完全不使用，多用于重载区分、兼容旧接口、语法占位。

```cpp
// 哑元int，仅用来区分重载
Person(int a) {}
Person(int a, int) {}
Person p(10, 0);
```

**引用参数**

形参为引用，传递大对象时避免拷贝，降低性能开销，常搭配`const`防止修改源数据。

```cpp
Person(const string& n) { name = n; }
string s = "王五";
Person p(s); // 无拷贝，直接引用原字符串
```

**4.3 对象实例化四种调用方式（栈 + 堆）**

**栈区对象（局部 / 全局）:**

1. 标准括号写法：`Person p(18, "张三");`
2. 等号构造写法：`Person p = Person(18, "张三");`
3. 单参专属隐式写法：`Person p = 18;`（无 explicit 时生效）
4. C++11 列表初始化：`Person p{18, "张三"};`

**堆区对象（new 动态分配）:**

```cpp
// 无参
Person* p1 = new Person;
// 有参
Person* p2 = new Person(20, "李四");
// 释放
delete p1;
delete p2;
```

**4.4 explicit 关键字核心详解（高频考点）**

**作用:**

修饰仅接收单个参数的构造函数，禁止编译器自动隐式类型转换，规避隐性 bug、提升代码可读性与安全性。

无 explicit 时的隐式转换（隐患示例）:

```cpp
class Person {
public:
    Person(int a) { age = a; }
    int age;
};
// 编译器自动隐式转换：int → Person
Person p = 18; 

// 函数传参隐性转换
void func(Person per) {}
func(20); // 等价 func(Person(20))，无意识转换易出错
```

加 explicit 禁止隐式转换:

```cpp
class Person {
public:
    explicit Person(int a) { age = a; }
    int age;
};
// 报错：禁止隐式转换
// Person p = 18;
// 合法：显式手动调用构造
Person p(18);
Person p2 = Person(18);
Person p3{18};
// 函数传参必须显式构造
func(Person(20));
```

**使用场景总结**

1. 单参数构造一律推荐加`explicit`，杜绝无意隐式转换；
2. 多参数构造无需 explicit（不存在单值隐式转换）；
3. 数值转对象、字符串转对象场景，防止类型混淆逻辑错误。

**三大构造函数核心区别**

**初始化列表必背 4 条强制规则**

1. const 成员只能列表初始化；
2. 引用成员只能列表初始化；
3. 成员类无默认构造，必须列表传参构造；
4. 同名形参与成员，列表初始化更简洁高效。

**explicit 使用口诀**

单参构造加 explicit，隐式转换全禁止； 多参构造不用管，显式调用才合法。

**默认构造失效 3 种情况**

1. 手写任意有参构造，编译器不再生成隐式默认构造；
2. 同时存在无参构造 + 全默认参数构造，调用二义性编译报错；
3. 类包含引用 /const/ 无默认构造成员，编译器无法合成隐式默认构造。

## 完整综合实操代码示例

```cpp
#include <iostream>
#include <string>
using namespace std;

class Student {
public:
    // const成员、引用成员，必须初始化列表
    const int id;
    int& ref_age;
    string name;

    // explicit单参构造，禁止隐式转换
    explicit Student(int id_, int& a) : id(id_), ref_age(a) {
        name = "未知";
    }

    // 全默认参数，显式默认构造
    Student() : id(0), ref_age(id) {
        name = "默认学生";
    }

    // 有参构造，初始化列表区分同名参数
    Student(int id_, int& a, string name) : id(id_), ref_age(a), name(name) {}
};

int main() {
    int age = 18;
    // 默认构造
    Student s1;
    // 有参显式构造
    Student s2(1001, age);
    Student s3(1002, age, "小明");

    // 错误：explicit禁止隐式转换 Student s4 = 1003;
    cout << s1.name << " " << s1.id << endl;
    return 0;
}
```

# 析构函数

## 析构函数核心定义与作用

析构函数是类的一种特殊成员函数，当对象的生命期结束时自动调用；用来释放对象占用的资源（如动态内存、网络连接等），确保程序的安全性和稳定性。

构造函数负责创建对象、申请资源，析构函数是它的逆操作：销毁对象、归还外部资源，避免：

- 堆内存泄漏（new 内存没释放）
- 文件句柄泄漏（打开文件未关闭）
- Socket、数据库连接、锁资源长期占用

## 析构函数自动触发三大时机（文档原文）

1. 局部栈对象离开作用域 函数执行结束、代码块`{}`结束时，局部对象生命周期终止，自动调用析构。
2. 堆区动态对象执行 delete /delete []`new`出来的对象不会自动销毁，必须手动`delete`，才会执行析构；不 delete 则资源永久泄漏。
3. 全局 / 静态对象在程序退出时 main 函数执行完毕、进程即将销毁前，统一调用全局、static 静态对象的析构。

## 析构函数标准语法格式

**文档原文**

```cpp
class 类名 {
public:
    ~类名() {
        // 资源清理逻辑
    }
};
```

**补充说明**

- 析构只能写在类内，一般对外开放为`public`；私有析构仅特殊设计（禁止外部销毁对象）；
- 函数体内部写释放资源逻辑，无任何参数列表。

## 析构函数四大核心特性（文档原文）

1. 命名规则特殊 函数名由波浪号`~` + 完整类名组成，必须和类名大小写完全一致，`~`不可省略。
2. 无任何返回值 不能写 int、double、void、auto 等任意返回类型，连 void 都禁止。
3. 不接收任何参数 括号内必须为空，不能定义形参，无法传参调用。
4. 不可重载，一个类仅有 1 个析构函数 不能写多个不同参数的析构，不存在重载版本。

**补充特性**

- 无法手动主动传参调用；仅 placement new 等极少场景可显式调用`对象.~类名()`；
- 析构执行顺序和构造完全相反。

## 编译器自动合成默认析构（拓展，文档未提及）

1. 合成条件 程序员没有手动自定义任何析构函数时，编译器自动生成一份隐式默认析构。
2. 默认析构行为

- 函数体为空，不会主动释放`new`分配的堆内存；
- 只会自动依次调用类中成员子对象的析构函数；
- 内置基础类型（int、char、指针）无析构逻辑，不会做任何清理。

1. 必须手写自定义析构的场景 类内使用`new/new[]`开辟堆内存、持有文件 / 网络 / 锁等外部资源，必须手动写析构释放，否则内存泄漏。

错误示例（内存泄漏）：

```cpp
class Test {
public:
    char* p;
    Test() {
        p = new char[100]; // 堆内存申请
    }
    // 无自定义析构，编译器默认析构不会delete[] p
};
```

正确写法：

```cpp
~Test() {
    delete[] p;
    p = nullptr; // 置空野指针，防止重复释放崩溃
}
```

## 析构执行顺序（结合构造顺序知识点）

**类包含自定义子对象（组合关系）**

- 构造顺序：先构造所有内嵌成员对象 → 再执行当前类构造函数体
- 析构顺序：先执行当前类析构函数体 → 逆序销毁所有内嵌子对象

> 成员构造 / 析构只看类内声明顺序，和初始化列表书写顺序无关。

**栈多个局部对象**

栈对象遵循后进先出 LIFO：后定义的对象先析构，先定义的后析构。

```cpp
void func() {
    Person p1; // 先构造
    Person p2; // 后构造
    // 退出时：先析构p2，再析构p1
}
```

**继承父子类**

构造：父类构造 → 子类成员构造 → 子类自身构造 析构：子类自身析构 → 子类成员析构 → 父类析构

## C++11 析构控制关键字 =default / =delete

1. `~类名() = default;` 强制编译器生成默认空析构；即使类中写了其他构造函数，依然提供默认析构。
2. `~类名() = delete;` 删除析构函数，该类无法正常销毁对象，不能定义栈对象，堆对象 delete 会编译报错。

## 高频拓展：虚析构 virtual \~ 类名 ()

**适用场景：多态继承**

父类指针指向子类对象，执行`delete 父类指针`时，如果父类析构不加`virtual`，只会调用父类析构，子类堆资源无法释放，造成内存泄漏。 正确示例：

```cpp
class Base {
public:
    virtual ~Base() { // 虚析构，多态安全
        cout << "父类析构" << endl;
    }
};
class Son : public Base {
    char* buf;
public:
    Son() { buf = new char[20]; }
    ~Son() {
        delete[] buf;
        cout << "子类析构，释放堆内存" << endl;
    }
};

int main() {
    Base* ptr = new Son();
    delete ptr; // 先调用Son析构，再Base析构
    return 0;
}
```

## 析构函数高频易错点汇总

1. 析构无参、无返回、不能重载，一个类只能有一个；
2. 默认析构不会释放 new 堆内存，有指针资源必须手动自定义析构；
3. 栈对象自动析构，堆对象必须手动 delete 才会执行析构；
4. 多态继承父类析构必须加 virtual，否则子类资源泄漏；
5. 析构函数内不要抛出异常，会直接导致程序崩溃；
6. 析构释放指针后赋值`nullptr`，避免二次 delete 野指针；
7. 禁止手动 delete 栈上局部对象，产生未定义行为、程序崩溃；
8. 全局 / 静态对象析构时机晚于所有局部栈对象。

## 完整可运行演示代码

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Person {
    char* name;
public:
    // 构造函数：堆内存分配
    Person(const char* str) {
        cout << "构造函数执行，分配姓名堆内存" << endl;
        int len = strlen(str);
        name = new char[len + 1];
        strcpy(name, str);
    }

    // 自定义析构函数：释放堆资源
    ~Person() {
        cout << "析构函数执行，释放name堆内存" << endl;
        delete[] name;
        name = nullptr;
    }
};

void testStackObj() {
    Person p("小明"); // 栈对象，函数结束自动析构
    cout << "test函数即将退出" << endl;
}

int main() {
    cout << "===== 测试栈局部对象 =====" << endl;
    testStackObj();

    cout << "\n===== 测试堆动态对象 =====" << endl;
    Person* p = new Person("小红");
    cout << "手动执行delete释放堆对象" << endl;
    delete p;

    return 0;
}
```

**运行输出说明:**

1. 进入 testStackObj，创建栈对象自动调用构造；
2. test 函数退出，自动执行 p 的析构释放内存；
3. new 创建堆对象仅执行构造，不 delete 不会析构；
4. delete 触发析构，释放堆内存。

# 构造与析构的调用顺序及成员管理

## 构造、析构基础调用时机（区分栈对象 / 堆对象）

**堆区对象（new 创建）**

**构造触发:**

执行 `new 类名(参数)` 分配堆内存瞬间自动调用构造函数，完成成员初始化。

**析构触发:**

必须手动执行 `delete 指针` / `delete[] 数组指针` 才会调用析构； 若不执行 delete，对象生命周期不会结束，析构永远不执行，堆内存 / 资源永久泄漏。

```cpp
// 堆对象
Person* p = new Person(18); // new → 调用构造
delete p;                   // delete → 调用析构
```

**栈区局部对象（定义在函数 / 代码块内）**

**构造触发:**

代码执行到对象定义语句时立刻调用构造函数。

**析构核心规则：栈对象析构遵循「后进先出 LIFO」:**

- 后定义（后创建）的对象，先析构；
- 先定义（先创建）的对象，后析构。 示例直观理解：

```cpp
void test()
{
    Person p1; // 先构造
    Person p2; // 后构造
    // 函数结束销毁栈：先析构p2，再析构p1
}
```

## 类包含自定义类成员（组合关系，文档重点）

**2.1 组合场景构造执行顺序**

规则：先构造所有内嵌成员对象，再执行当前外层类自身构造函数

1. 按照类内声明顺序依次构造每个子对象（和初始化列表书写顺序无关）；
2. 全部子对象构造完成后，执行外层类构造函数体。

示例：

```cpp
class A {
public:
    A(){ cout << "A构造" << endl; }
};
class B {
public:
    B(){ cout << "B构造" << endl; }
};

class Outer {
    A a;  // 先声明
    B b;  // 后声明
public:
    Outer(){ cout << "外层Outer构造" << endl; }
};
```

创建 `Outer obj;` 输出顺序：

```text
A构造
B构造
外层Outer构造
```

**2.2 组合场景析构执行顺序**

规则：先执行外层类自身析构函数，再逆序销毁所有内嵌成员对象

1. 先执行外层类析构函数体，释放自身资源；
2. 按照与声明相反的顺序析构子对象。

承接上面代码，obj 销毁时输出：

```text
外层Outer析构
B析构
A析构
```

**2.3 关键补充：初始化列表对子对象的影响**

子对象若无默认构造，必须在初始化列表传参构造； 但初始化列表书写顺序不改变成员真实构造顺序，仅由类内声明决定，容易产生未定义行为。

```cpp
Outer() : b(), a() // 列表先写b再写a，但实际还是先构造a再构造b
{ }
```

## 类中包含指针类型成员（文档模块 + 深度拓展）

**3.1 指针成员核心问题**

指针本身只是存地址，编译器默认构造 / 默认析构不会自动分配、释放指针指向的堆内存：

1. 构造时：仅指针变量本身分配内存，不会自动 new 堆空间；
2. 默认析构：只会销毁指针变量本身，不会执行 delete，造成内存泄漏；
3. 拷贝赋值时：默认拷贝只会浅拷贝地址，多个对象共用同一块堆内存，析构时重复 delete 程序崩溃。

**3.2 规范管理流程（三 / 五法则配套）**

**1）构造函数：分配堆内存:**

```cpp
class Person {
    char* name;
public:
    Person(const char* str) {
        int len = strlen(str);
        name = new char[len + 1]; // 指针指向堆
        strcpy(name, str);
    }
```

**2）析构函数：释放堆内存:**

```cpp
    ~Person() {
        delete[] name;
        name = nullptr; // 置空防止野指针二次释放
    }
```

**3）必须补充拷贝构造、重载赋值运算符（浅拷贝灾难拓展）:**

若不自定义，编译器生成默认浅拷贝：两个对象的 name 指向同一块堆内存；两个对象析构时先后 delete 同一片内存 → 崩溃。 正确深拷贝示例：

```cpp
// 拷贝构造（深拷贝）
Person(const Person& other) {
    int len = strlen(other.name);
    name = new char[len + 1];
    strcpy(name, other.name);
}
// 赋值运算符重载（深拷贝）
Person& operator=(const Person& other) {
    if (this == &other) return *this; // 防止自赋值
    // 释放旧内存
    delete[] name;
    // 分配新内存拷贝数据
    int len = strlen(other.name);
    name = new char[len + 1];
    strcpy(name, other.name);
    return *this;
}
```

**补充：C++11 移动构造 / 移动赋值（五法则）:**

类持有堆资源时，推荐实现：构造、拷贝构造、移动构造、赋值重载、移动赋值、析构。

## 多场景构造 &amp; 析构顺序完整对比

**4.1 栈局部对象（组合类）:**

```cpp
void func()
{
    Outer o1; // 构造：A→B→Outer
    Outer o2; // 构造：A→B→Outer
    // 函数退出析构：o2(Outer→B→A) → o1(Outer→B→A)
}
```

**4.2 堆对象（组合类）:**

```text
Outer* p = new Outer; // new：A→B→Outer构造
delete p;              // delete：Outer析构 → B → A
```

**4.3 继承场景对比（高频考点）:**

构造顺序：父类 → 子类内嵌成员 → 子类自身

析构顺序：子类自身 → 子类内嵌成员 → 父类

> 多态场景父类必须加 `virtual ~父类()` 虚析构，否则子类资源无法释放。

## 高频易错点汇总

1. 栈对象析构永远后进先出，和定义顺序相反；堆对象析构仅由 delete 控制，无 LIFO 规则；
2. 内嵌子对象构造只看类内声明顺序，初始化列表书写顺序无效；
3. 组合析构：先外层，后子对象；构造：先子对象，后外层；
4. 指针成员依赖手动 new/delete，默认析构不释放堆内存；
5. 带指针成员的类，只写析构不够，必须实现深拷贝拷贝构造与赋值重载，避免重复释放崩溃；
6. 全局 / 静态对象：main 执行完毕后才析构，晚于所有局部栈对象；
7. 不要手动调用栈对象析构，会重复释放资源导致崩溃；仅 placement new 场景允许显式调用析构。

## 完整综合演示代码

```cpp
#include <iostream>
#include <cstring>
using namespace std;

// 内嵌子对象类
class A {
public:
    A() { cout << "【构造】A" << endl; }
    ~A() { cout << "【析构】A" << endl; }
};
class B {
public:
    B() { cout << "【构造】B" << endl; }
    ~B() { cout << "【析构】B" << endl; }
};

// 包含指针成员 + 内嵌子对象的外层类
class Outer {
    A a;
    B b;
    char* buf; // 指针堆成员
public:
    Outer(const char* str) {
        cout << "【构造】Outer 开始" << endl;
        int len = strlen(str);
        buf = new char[len + 1];
        strcpy(buf, str);
        cout << "【构造】Outer 结束" << endl;
    }

    ~Outer() {
        cout << "【析构】Outer 开始，释放buf堆内存" << endl;
        delete[] buf;
        buf = nullptr;
        cout << "【析构】Outer 结束" << endl;
    }
};

void testStack()
{
    cout << "==== 创建栈对象o1 ====" << endl;
    Outer o1("第一个栈对象");
    cout << "==== 创建栈对象o2 ====" << endl;
    Outer o2("第二个栈对象");
    cout << "==== test函数即将退出，栈对象开始析构 ====" << endl;
}

int main()
{
    cout << "===== 测试栈对象LIFO析构 =====" << endl;
    testStack();

    cout << "\n===== 测试堆对象 =====" << endl;
    Outer* p = new Outer("堆对象");
    cout << "执行delete释放堆对象" << endl;
    delete p;
    return 0;
}
```

**代码输出逻辑说明:**

1. 栈内 o1、o2 构造均先 A、再 B、再 Outer；
2. 函数退出先析构 o2（Outer→B→A），再析构 o1；
3. new 堆对象同样 A→B→Outer 构造，delete 时先 Outer 释放堆 buf，再 B、再 A。

1. 初始化列表、默认 / 有参构造、explicit；
2. 析构函数基础特性；

# 拷贝构造函数

## 拷贝构造函数简介（文档原文）

**定义：**

拷贝构造函数是特殊构造函数，使用一个已经存在的同类对象，去初始化新建对象。

**核心作用：**

快速复制已有对象的全部成员数据，生成一份新对象。

## 标准语法格式（文档原文）

```cpp
class 类名
{
public:
    // 写法1：函数体内赋值
    类名(const 类名& other)
    {
        // 拷贝逻辑
    }

    // 写法2：搭配初始化列表（推荐，效率更高）
    类名(const 类名& other)
        : 成员1(other.成员1), 成员2(other.成员2)
    {
        // 额外拷贝逻辑
    }
};
```

## 关键注意事项（文档原文 + 拓展）

1. 参数必须为 `const 同类引用 const 类名&`

   - 加`&`引用：避免传值触发无限递归拷贝构造；
   - 加`const`：保证不会修改源对象，只读更安全。
   - 禁止写成 `类名(类名 other)` 值传递，编译死递归。
2. 编译器自动生成默认拷贝构造 用户没有手写拷贝构造时，编译器自动合成一份，行为为逐成员值拷贝（浅拷贝）。
3. 默认拷贝构造的致命缺陷 若类包含`new`动态分配的指针成员，默认浅拷贝会让多个对象共用同一块堆内存，程序运行崩溃。此时必须手动自定义拷贝构造实现深拷贝。

## 拷贝构造函数自动调用的三种场景（文档未提及，必考拓展）

满足任意一种情况，编译器自动调用拷贝构造：

1. 用已有对象直接初始化新对象

```cpp
Person p1("张三");
Person p2 = p1;  // 触发拷贝构造
Person p3(p1);   // 触发拷贝构造
Person p4{p1};   // C++11列表初始化，触发拷贝构造
```

1. 函数形参为类对象（值传递）

```cpp
void func(Person per) {} // 值传参，实参拷贝生成形参临时对象
func(p1);
```

1. 函数返回值为类对象（值返回）

```cpp
Person test()
{
    Person temp("李四");
    return temp; // 返回时调用拷贝构造（编译器优化可能省略）
}
```

## 浅拷贝（文档原文）

**浅拷贝行为**

默认拷贝构造仅逐字节复制成员变量：

- 普通内置类型 (int、string、double)：直接复制数值，无问题；
- 指针成员：只复制指针地址值，不新开堆内存。

**浅拷贝带来两大致命问题**

1. 双重释放（重复 delete） 两个对象的指针指向同一块堆内存；对象析构时先后执行`delete[]`，重复释放同一片内存 → 程序直接崩溃。
2. 
3. 野指针 + 内存泄漏 其中一个对象提前析构释放堆内存后，另一个对象的指针变成野指针；后续读写 / 释放都会触发未定义行为。

**浅拷贝内存模型:**

对象 p1：name 指针指向堆`new char[]` 

执行`Person p2 = p1;`浅拷贝 

p2.name = p1.name（只复制地址） 

p1、p2 共用同一块堆内存 

p1 析构：delete [] name，堆内存释放

p2.name 变成野指针，p2 析构再 delete → 崩溃

## 深拷贝

**核心思路**

自定义拷贝构造，遇到指针成员时：

1. 单独开辟一块全新堆内存；
2. 将源对象指针指向的数据完整复制到新堆；
3. 新对象指针指向自己独立的堆内存。

**文字图解**

对象 p1：name 指向堆 A 深拷贝构造 p2： 新建堆 B，把堆 A 字符串复制到堆 B p2.name 指向堆 B p1、p2 内存完全独立，析构互不干扰，无重复释放风险。

## 完整代码演示

**示例 1：默认浅拷贝，程序崩溃**

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Person
{
public:
    char* name;
    Person(const char* str)
    {
        int len = strlen(str);
        name = new char[len + 1];
        strcpy(name, str);
    }
    // 编译器自动生成默认浅拷贝构造
    ~Person()
    {
        delete[] name;
        cout << "释放name内存" << endl;
    }
};

int main()
{
    Person p1("小明");
    Person p2 = p1; // 浅拷贝，p1.name与p2.name地址相同
    // 函数结束析构p2、p1，两次delete同一块内存，程序崩溃
    return 0;
}
```

**示例 2：自定义深拷贝构造，修复崩溃**

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class Person
{
public:
    char* name;
    // 有参构造
    Person(const char* str)
    {
        int len = strlen(str);
        name = new char[len + 1];
        strcpy(name, str);
    }

    // 自定义深拷贝构造函数
    Person(const Person& other)
    {
        // 1.开辟独立堆内存
        int len = strlen(other.name);
        name = new char[len + 1];
        // 2.拷贝数据内容
        strcpy(name, other.name);
        cout << "深拷贝执行，创建独立内存" << endl;
    }

    ~Person()
    {
        delete[] name;
        name = nullptr;
    }
};

int main()
{
    Person p1("小明");
    Person p2 = p1; // 调用深拷贝构造，两块独立内存
    // 析构分别释放各自堆内存，程序正常运行无崩溃
    return 0;
}
```

## 拓展知识点：三法则（资源管理类必背）

如果类手动自定义了拷贝构造函数，说明该类管理动态堆资源，必须同时实现另外两个函数，合称三法则：

1. 拷贝构造函数（深拷贝）
2. 重载赋值运算符`operator=`（深拷贝）
3. 析构函数（释放堆内存）

**补充赋值重载深拷贝模板:**

```cpp
Person& operator=(const Person& other)
{
    // 防止自赋值：p1 = p1
    if (this == &other)
        return *this;

    // 释放当前对象旧内存
    delete[] this->name;

    // 开辟新内存复制数据
    int len = strlen(other.name);
    this->name = new char[len + 1];
    strcpy(this->name, other.name);
    return *this;
}
```

## 高频易错点总结

1. 拷贝构造参数必须是`const 类名&`，值传递会无限递归报错；
2. 无自定义拷贝构造时编译器生成浅拷贝，带指针类一定不能依赖默认；
3. 浅拷贝核心问题是共享堆内存，析构双重释放直接崩溃；
4. 深拷贝关键：为指针成员单独 new 一块内存，复制数据而非地址；
5. 函数值传参、值返回对象会隐式调用拷贝构造，可改用引用传参减少拷贝开销；
6. 仅内置类型、string 容器等无需手动深拷贝，string 内部封装自动管理内存；
7. 只写深拷贝构造不重载赋值运算符，`p1 = p2`依旧会触发默认浅拷贝，存在隐患。

# this指针

## this 指针简介

**定义:**

`this`是隐藏在普通成员函数形参列表中的内置指针，类型为`类名* const`，永远指向调用该成员函数的当前对象。

**底层编译原理（文档示例拓展）:**

程序员写的构造 / 普通成员函数：

```cpp
Person(int age) { age = age; }
```

编译器底层自动改写，隐式追加`Person* this`形参：

```cpp
// 编译器内部真实形式
Person(int age, Person* const this) { this->age = age; }
```

调用对象方法时，编译器自动把对象地址传入 this 形参：

```cpp
Person p(18);
// 等价底层：Person::Person(18, &p);
```

**核心作用:**

在成员函数内部，通过`this->`精准访问当前调用对象的成员变量、成员函数。

## this 指针使用硬性限制（文档原文）

1. 不能手动写在函数形参列表 this 是编译器自动隐藏参数，代码里不能写出`func(Person* this)`，编译报错。
2. 不能出现在初始化列表 初始化列表执行阶段，对象内存还未完全构造，禁止使用 this。
3. 仅能在类的普通成员函数内部使用 全局函数、外部函数无法访问 this。
4. 静态成员函数中禁止使用 this 静态函数属于类本身，不绑定任意对象，没有对应的 this 指针。

## this 指针四大使用场景（文档原文 + 代码演示）

**场景 1：区分同名成员变量与函数形参**

当成员变量名和形参完全相同时，直接写变量名代表形参；`this->变量`代表对象成员。

```cpp
class Person {
public:
    int age;
    // 形参age 和 成员age重名
    void setAge(int age) {
        this->age = age; // this->age：对象成员；等号右侧age：形参
    }
};
```

替代方案：初始化列表（无需 this）

```cpp
Person(int age) : age(age) {}
```

**场景 2：返回当前对象引用，实现链式调用（核心用途）**

函数返回`*this`（当前对象本体），支持连续点调用成员函数。

```cpp
class Person {
public:
    int age;
    string name;

    Person& setAge(int age) {
        this->age = age;
        return *this; // 返回当前对象引用
    }
    Person& setName(string n) {
        this->name = n;
        return *this;
    }
};

int main() {
    Person p;
    // 链式调用，连续执行多个方法
    p.setAge(20).setName("张三");
    return 0;
}
```

**场景 3：返回当前对象指针**

需要返回对象地址时，直接 return this；多用于容器、自定义内存管理场景。

```cpp
Person* getSelf() {
    return this;
}
```

**场景 4：成员函数内销毁自身对象（文档提及拓展）**

仅适用于堆上 new 出来的对象，栈对象不能使用，否则程序崩溃。

```cpp
void destroySelf() {
    delete this; // 释放当前堆对象内存，自动调用析构
}
// 使用：
Person* p = new Person();
p->destroySelf();
```

⚠️ 销毁后不能再访问任何成员，this 指向野指针。

## 拓展：静态成员函数为什么不能用 this？

1. 静态成员函数存储在代码段，不属于任何对象，调用时不需要创建对象；
2. 静态函数调用方式：`类名::静态函数()`，没有对象地址传入；
3. this 指针依赖对象地址，无对象则不存在 this，编译直接报错。

```cpp
class Person {
public:
    static void test() {
        // cout << this->age;  // 编译错误，静态函数无this
    }
};
```

## 进阶拓展：this 底层隐藏特性

**this 指针本身是常量指针 类名\* const this**

this 的指向不能修改，不允许写`this = nullptr; this = &other;`。 只能修改`this->成员`的值，不能修改 this 存储的地址。

**const 成员函数的 this 为 const 类名\* const this**

const 修饰的成员函数承诺不修改对象成员，this 指向被 const 修饰的常量对象：

```cpp
void show() const {
    // this->age = 10; // 报错，无法修改成员
    cout << this->age;
}
```

**this 指针存储位置**

- 栈调用：this 作为函数隐式参数，存放在函数调用栈帧；
- 不是对象成员，sizeof (类) 不会包含 this 指针大小。

## 完整综合示例代码

```cpp
#include <iostream>
#include <string>
using namespace std;

class Person {
private:
    int age;
    string name;
public:
    // 1. 区分同名参数
    Person(int age, string name) {
        this->age = age;
        this->name = name;
    }

    // 链式调用：返回*this
    Person& setAge(int age) {
        this->age = age;
        return *this;
    }
    Person& setName(string name) {
        this->name = name;
        return *this;
    }

    // 返回对象指针
    Person* getObjAddr() {
        return this;
    }

    void printInfo() const {
        cout << "姓名：" << this->name << " 年龄：" << this->age << endl;
    }

    // 堆对象自销毁
    void selfDestroy() {
        delete this;
    }
};

int main()
{
    Person p(18, "小明");
    // 链式调用
    p.setAge(20).setName "张三";
    p.printInfo();
    cout << "对象地址：" << p.getObjAddr() << endl;

    // 测试堆对象自销毁
    Person* p2 = new Person(16, "小红");
    p2->selfDestroy();
    return 0;
}
```

## this 指针高频易错点总结

1. this 是编译器隐式参数，不能手动写到形参，不能在初始化列表使用；
2. 静态成员函数、全局函数、友元函数内不能使用 this；
3. this 是`类名* const`，指针本身不可修改，只能修改`this->成员`；
4. `return *this`返回引用实现链式调用；`return this`返回对象地址；
5. `delete this`仅能用于 new 创建的堆对象，栈对象执行会崩溃；
6. const 成员函数的 this 是常量对象指针，无法修改成员变量；
7. 不要在对象销毁后继续使用 this 或保存的 this 指针，会变成野指针；
8. 成员变量与形参重名时，两种解决方案：`this->成员` 或 初始化列表。

# 拷贝赋值函数

## 拷贝赋值函数简介

**定义**

拷贝赋值函数也叫拷贝赋值运算符重载 `operator=`，属于类特殊成员函数； 作用：把一个已经存在的对象的数据，赋值给另一个同样已经存在的对象。

> 区分关键：
> 
> - 拷贝构造：新建对象时，用旧对象初始化；
> - 拷贝赋值：两个对象都已创建完成，执行 `obj1 = obj2` 赋值操作。

**标准语法格式（文档标准模板）**

```cpp
class 类名 {
public:
    // 拷贝赋值运算符重载
    类名& operator=(const 类名& other)
    {
        // 1. 自赋值检测，防止自己赋值给自己
        if (this != &other)
        {
            // 2. 释放当前对象旧动态资源
            // 3. 从源对象拷贝数据，深拷贝分配新内存
        }
        // 4. 返回*this，支持链式赋值
        return *this;
    }
};
```

**三大强制规范（文档重点）**

**（1）必须做自赋值检查 `if(this != &other)`:**

场景：`m1 = m1;` 若不判断，会先释放自身堆内存，后续读取`other`数据时内存已销毁，产生野指针、程序崩溃。

**（2）返回值必须为 `类名&`（当前对象引用 `return *this`）:**

目的：支持连续链式赋值 `m1 = m2 = m3;`

**（3）动态资源类必须手动管理内存:**

编译器自动生成的默认赋值仅浅拷贝；类包含`new`指针成员时，必须手动实现深拷贝，防止双重释放、内存泄漏。

## 浅拷贝与深拷贝（文档原文 + 图解解读）

## 浅拷贝（默认拷贝赋值行为）

**原理:**

编译器自动生成的默认`operator=`仅逐成员值拷贝：

- 普通内置变量（int、double）直接复制数值；
- 指针成员仅复制内存地址，不会开辟新堆空间。

![图片展示了浅拷贝内存示意图，用于说明浅拷贝带来的问题。图中左侧为m1对象，右侧为m2对象，m1的数据和数据大小成员通过值拷贝，m1的指针成员m_data通过指针地址拷贝。m_data指向的内存空间在m1析构时被new分配，m2析构时也new分配相同内存，导致双重释放，两个对象指针指向同一块堆内存，程序异常终止。](/feishu-assets/8db1bb0227a6.jpg)

浅拷贝内存示意图

**带来两大致命问题:**

1. 双重释放崩溃 两个对象指针指向同一块堆内存；两个对象生命周期结束时，析构函数先后`delete`同一块内存，程序直接异常终止。
2. 野指针 + 内存泄漏 一个对象析构释放堆内存后，另一个对象指针变为野指针；读写、再次释放都会触发未定义行为。

## 深拷贝（自定义拷贝赋值实现）

**完整执行步骤（图解标注流程）:**

![图片展示了MyClass对象m1和m2的内存示意图，用于说明深拷贝内存示意图完整执行步骤。m1和m2分别有数据（m_data）和数据大小（m_size）成员，m1通过new申请堆内存。执行深拷贝时，先将旧空间释放，再重新申请一块空间，将源对象堆内完整数据复制到新空间，最后将当前对象指针指向新分配的堆内存，支持链式调用。该图直观呈现了深拷贝过程中内存操作的流程。](/feishu-assets/df2a19b31995.jpg)

深拷贝内存示意图

1. 自赋值校验，排除`obj=obj`；
2. 释放当前对象原本持有的旧堆内存，避免内存泄漏；
3. 根据源对象数据大小，重新申请一块全新独立堆空间；
4. 将源对象堆内完整数据复制到新空间；
5. 将当前对象指针指向新分配的堆内存；
6. 返回`*this`支持链式调用。

**优势:**

赋值后两个对象拥有完全独立的堆资源，析构互不干扰，无重复释放、野指针风险。

## 完整实战代码示例

示例：带 char \* 指针的类，实现深拷贝赋值:

```cpp
#include <iostream>
#include <cstring>
using namespace std;

class MyClass
{
private:
    char* m_data;
    int m_size;
public:
    // 普通有参构造
    MyClass(const char* str)
    {
        m_size = strlen(str);
        m_data = new char[m_size + 1];
        strcpy(m_data, str);
    }

    // 拷贝构造（配套深拷贝）
    MyClass(const MyClass& other)
    {
        m_size = other.m_size;
        m_data = new char[m_size + 1];
        strcpy(m_data, other.m_data);
    }

    // 拷贝赋值运算符重载（深拷贝核心）
    MyClass& operator=(const MyClass& other)
    {
        // 1. 自赋值检测
        if (this == &other)
        {
            return *this;
        }

        // 2. 释放自身旧内存
        delete[] m_data;

        // 3. 分配新内存、拷贝数据
        m_size = other.m_size;
        m_data = new char[m_size + 1];
        strcpy(m_data, other.m_data);

        // 4. 返回自身引用，支持链式赋值
        return *this;
    }

    // 析构释放堆内存
    ~MyClass()
    {
        delete[] m_data;
        m_data = nullptr;
    }

    // 打印数据
    void show() const
    {
        cout << "数据：" << m_data << " 长度：" << m_size << endl;
    }
};

int main()
{
    MyClass m1("C++拷贝赋值");
    MyClass m2("测试文本");
    m2.show();

    // 调用拷贝赋值函数
    m2 = m1;
    m2.show();

    // 链式赋值
    MyClass m3("临时");
    m3 = m2 = m1;
    m3.show();

    return 0;
}
```

## 高频易错点与避坑总结

1. 拷贝构造 ≠ 拷贝赋值

   - 新建对象初始化 → 拷贝构造；
   - 已有对象互相赋值 → 拷贝赋值。
2. 省略自赋值检测的致命后果：自身赋值时先释放内存，读取源数据崩溃。
3. 深拷贝赋值必须先释放自身旧堆内存，否则旧内存丢失，造成内存泄漏。
4. 返回值不能写成`void`，否则无法链式连续赋值。
5. 只自定义拷贝构造、不重载`operator=`：执行`m1=m2`仍会调用编译器默认浅拷贝，存在双重释放风险。
6. 三法则配套要求：只要类管理动态堆资源，必须同时手写 析构 + 拷贝构造 + 拷贝赋值 三个函数。
7. 静态数组、`std::string`、容器无需手动深拷贝，内部自动管理内存，依赖默认浅拷贝完全安全。
8. 浅拷贝仅适用于无`new`动态内存的简单数据类。

# 常函数与函数对象

## 常函数 const 成员函数

**1.1 定义与语法（文档原文）:**

**定义:**

在成员函数形参列表后加`const`修饰的成员函数，称为常函数。

**标准语法:**

```cpp
class 类名
{
public:
    // const写在括号后面，不能写前面
    返回值 函数名(参数列表) const
    {
        // 函数体
    }
};
```

**1.2 const 底层原理（文档重点拓展）**

常函数的`const`本质是修饰隐藏的`this`指针：

- 普通成员函数：`类名* const this`（指针地址不可改，可修改对象成员）
- const 常成员函数：`const 类名* const this`

  1. this 指针本身不能改变指向；
  2. this 指向的对象被 const 限定，禁止修改任何普通成员变量。

**1.3 常函数核心作用**

保证函数执行过程中不会修改对象任何成员变量，只读访问，提升代码安全； 常对象只能调用常函数，若无常函数则编译报错。

**1.4 mutable 关键字：常函数中可修改的成员（文档补充）**

默认规则：常函数内禁止修改所有普通成员变量； 若有少量变量需要在只读函数内修改（如缓存、计数、日志标记），将变量用`mutable`修饰：

```cpp
mutable int cache; // mutable变量不受const函数限制
```

无论是否在 const 常函数内，mutable 成员都能随意读写。

**1.5 常函数与普通函数重载调用规则（文档原文）**

同一个类中，同名函数一个加 const、一个不加，构成函数重载：

1. 普通（非常）对象调用：优先匹配无 const 普通函数；若无普通版本，才调用常函数；
2. const 常对象调用：只能匹配const 常函数，无法调用普通非 const 函数。

## 常对象 const 对象

**2.1 定义（文档原文）:**

用`const`关键字修饰的类对象，对象创建完成后，整体状态只读，不允许修改成员。

**2.2 三种创建语法**

1. 栈区常对象

```cpp
const Person p1(18);
```

1. 常指针指向堆对象

```cpp
const Person* p2 = new Person(20);
```

1. 常引用（绑定任意对象，只读访问）

```cpp
Person temp(10);
const Person& ref = temp;
```

**2.3 常对象硬性限制（文档原文）:**

1. 常对象只能调用 const 常函数，调用普通非 const 成员函数直接编译报错；
2. 常对象不能直接修改任意普通成员变量；
3. mutable 修饰的成员除外，常对象仍可修改 mutable 变量。

## 高频易错点汇总

1. const 修饰成员函数必须写在参数括号后面，写在返回值前无效（那是修饰返回值）；
2. 常函数内不能修改普通成员变量，mutable 成员例外；
3. 常对象无法调用无 const 的普通成员函数；
4. const 修饰的是 this 指针，静态成员函数无 this，不能定义为 const 常函数；
5. mutable 只能修饰类内成员变量，不能修饰函数；
6. 常引用`const 类名&`、常指针`const 类名*`同样属于只读对象，遵循常对象调用规则；
7. 常函数与普通同名函数构成重载，编译器根据调用对象是否为 const 自动匹配；
8. 不能通过常对象指针 / 引用修改成员，底层 this 带 const 限制。

## 完整可运行综合代码示例

```cpp
#include <iostream>
#include <string>
using namespace std;

class Person
{
private:
    int age;
    mutable int logCount; // mutable：常函数内可修改
public:
    Person(int a) : age(a), logCount(0) {}

    // 普通非const函数（可修改成员）
    void setAge(int a)
    {
        age = a;
    }

    // const常函数（只读，仅mutable可改）
    void showInfo() const
    {
        logCount++; // mutable变量允许修改
        cout << "年龄：" << age << " 访问次数：" << logCount << endl;
        // age = 100; // 报错：常函数不能修改普通成员age
    }
};

int main()
{
    // 1. 普通对象
    Person p1(18);
    p1.setAge(20); // 可调用普通函数修改成员
    p1.showInfo(); // 存在普通版本优先普通，无则调用常函数

    // 2. const常对象
    const Person p2(30);
    p2.showInfo(); // 合法：只能调用const常函数
    // p2.setAge(99); // 编译报错：常对象禁止调用非const函数

    // 常指针
    const Person* ptr = new Person(25);
    ptr->showInfo();
    delete ptr;

    return 0;
}
```

**代码运行逻辑说明:**

1. `showInfo()`是 const 常函数，内部只能修改 mutable 修饰的 logCount；
2. 普通对象 p1 既能调用修改成员的 setAge，也能调用只读 showInfo；
3. const 常对象 p2、常指针 ptr，只能执行 showInfo，无法调用修改对象的 setAge；
4. 多次调用 showInfo 时 logCount 自增，验证 mutable 不受 const 限制。

# 静态成员

## 静态成员简介

**定义:**

被`static`关键字修饰的类成员，归属类本身，不属于任何单个对象。

**三大核心作用:**

1. 数据共享：所有类对象共用同一份静态数据，修改一处全部生效；
2. 节省内存：无需每个对象独立存储一份公共数据，只存一份；
3. 无对象即可调用：静态函数 / 变量可直接通过`类名::`访问，不用实例化对象。

**分类:**

静态成员分为两类：静态成员变量、静态成员函数。

## 静态成员变量 static 变量

**2.1 语法规则（文档原文）**

步骤 1：类内仅声明，不可初始化:

```cpp
class Person
{
public:
    static int count; // 仅声明，不能赋值
};
```

步骤 2：类外定义 + 初始化（强制要求）:

```cpp
// 类外初始化，不加static，必须加类名::作用域
int Person::count = 0;
```

**2.2 硬性注意事项**

1. 类内只能声明，不能直接初始化静态变量；
2. 类外初始化时不能写 static，必须带`类名::`标识归属；
3. 静态变量存储在全局静态数据区，不在栈 / 堆，不随对象创建销毁；
4. 程序启动分配内存，程序结束才释放，生命周期贯穿整个程序。

**2.3 核心特性：全局共享**

无论创建多少个类对象，内存中只存在唯一一份静态成员变量，所有对象读写的是同一个数据。 示例：统计创建对象总数

```cpp
class Person
{
public:
    static int count;
    Person() { count++; } // 每创建对象计数器+1
};
int Person::count = 0;

int main()
{
    Person p1;
    Person p2;
    cout << Person::count; // 输出2，两个对象共享count
    return 0;
}
```

**2.4 三种合法访问方式**

1. 类名直接访问（推荐，无需对象）：`Person::count`
2. 对象访问：`p1.count`
3. 对象指针访问：`&p1->count`

**2.5 访问权限限制**

静态变量若为`private/protected`，外部无法直接访问，只能通过静态成员函数 / 普通成员函数读写。

## 静态成员函数 static 函数

**3.1 语法格式（文档原文）**

写法 1：类内直接定义:

```cpp
class Person
{
public:
    static void showCount()
    {
        cout << count << endl;
    }
    static int count;
};
int Person::count = 0;
```

写法 2：类内声明，类外定义:

```cpp
class Person
{
public:
    static void showCount();
    static int count;
};
// 类外定义，不加static，加类名::
void Person::showCount()
{
    cout << Person::count;
}
int Person::count = 0;
```

**3.2 核心特性（文档重点）**

1. 归属类，所有对象共用同一份函数代码；
2. 没有 this 指针（关键限制）；
3. 不依赖对象实例，无对象也能调用；
4. 不能声明为`virtual`虚函数，不可重写；
5. 不能加`const`修饰（const 依赖 this 指针）。

**3.3 访问权限对照表（文档原版）**


<table v-pre><tbody><tr><td>访问目标</td><td>静态成员函数能否访问</td><td>原因说明</td></tr><tr><td>静态成员变量</td><td>✅ 可以直接访问</td><td>静态数据属于类，无对象也存在</td></tr><tr><td>静态成员函数</td><td>✅ 可以直接调用</td><td>同属类，无需对象</td></tr><tr><td>非静态成员变量</td><td>❌ 禁止直接访问</td><td>依赖 this 指针，静态函数无 this</td></tr><tr><td>非静态成员函数</td><td>❌ 禁止直接调用</td><td>非静态函数需要对象 this 指针</td></tr></tbody></table>


**拓展：静态函数如何访问非静态成员？:**

只能手动传入对象 / 对象指针间接访问：

```cpp
static void printAge(Person p)
{
    cout << p.age; // 通过传入的对象访问非静态age
}
```

**3.4 静态函数三种访问方式**

1. 类名调用（最优）：`Person::showCount();`
2. 对象调用：`p1.showCount();`
3. 指针调用：`(&p1)->showCount();`

## 静态成员典型使用场景（文档全部场景 + 解读）

1. 对象计数器 静态变量记录构造 / 析构次数，统计当前存活对象数量。
2. 全局统一配置 存储项目全局参数、开关，所有对象共用一套配置。
3. 单一共享资源管理 全局唯一连接池、数据库句柄、硬件资源。
4. 通用工具函数 与对象状态无关的工具方法（数学计算、字符串处理），不用创建对象直接调用。
5. 单例模式 静态私有实例变量 + 静态获取实例函数，保证全局仅一个对象。
6. 全局日志 统一日志输出流，所有类共用一套打印接口。
7. 缓存数据 缓存高频查询结果，减少重复计算，全局共享缓存。

## 静态 / 非静态成员互访完整规则总结

**普通非静态成员函数（有 this 指针）:**

- 可访问静态变量、静态函数；
- 可访问自身非静态变量、调用非静态函数； 双向全部支持，无限制。

**静态成员函数（无 this 指针）:**

- 仅能访问静态变量、静态函数；
- 无法直接读写非静态成员，只能传对象间接访问。

## 高频易错点汇总

1. 静态成员变量必须在类外初始化，类内仅声明，不能赋值；
2. 类外初始化静态变量时不能加`static`关键字；
3. 静态函数无 this 指针，不能直接操作普通成员；
4. 静态变量生命周期全局，对象销毁不会释放静态变量；
5. private 静态成员外部不能直接访问，需静态接口封装；
6. 静态函数不能用 const、virtual 修饰；
7. 不要用对象频繁访问静态成员，优先`类名::`访问语义清晰；
8. 拷贝、赋值不会复制静态变量，静态数据全局唯一，不受对象拷贝影响。

## 完整综合演示代码

```cpp
#include <iostream>
using namespace std;

class Person
{
private:
    int age;          // 非静态成员，每个对象独立
    static int count;  // 静态变量，全局共享
public:
    // 普通构造函数
    Person(int a) : age(a)
    {
        count++; // 普通函数可访问静态变量
    }

    // 普通成员函数，可访问所有成员
    void showInfo() const
    {
        cout << "年龄：" << age << " 当前总人数：" << count << endl;
    }

    // 静态成员函数
    static void getTotal()
    {
        // cout << age;  // 报错，无this不能访问非静态age
        cout << "全局总人数：" << count << endl;
    }

    // 静态函数间接访问非静态成员
    static void printObjAge(Person p)
    {
        cout << "传入对象年龄：" << p.age << endl;
    }

    // 析构，计数器自减
    ~Person()
    {
        count--;
    }
};

// 类外初始化静态变量
int Person::count = 0;

int main()
{
    // 无需创建对象，直接调用静态函数
    Person::getTotal();

    Person p1(18);
    Person p2(20);

    // 对象访问静态函数
    p1.showInfo();
    p2.showInfo();
    p1.printObjAge(p2);

    // 类名访问静态函数
    Person::getTotal();
    return 0;
}
```

## 运行逻辑说明

1. 静态 count 全局唯一，创建对象自增，销毁自减；
2. 静态函数`getTotal()`无法直接读取 age，必须传入对象才能访问；
3. 普通成员函数`showInfo()`可同时读取静态、非静态成员；
4. 不实例化对象，依然可以通过`Person::getTotal()`调用静态函数。

## 单例模式归属

创建型设计模式，专门控制对象实例的创建数量。

## 单例模式核心简介

**定义**

单例模式确保一个类在整个程序生命周期内只能拥有唯一实例，并对外提供统一全局静态方法来获取该实例。

**两大核心特点**

1. 唯一性：全局全程只存在一个对象，禁止外部随意 new；
2. 全局访问：无需手动创建对象，通过类静态方法统一获取。

**三大核心实现思想（硬性规则）**

1. 私有化构造函数 private：外部无法通过`类名()`、`new 类名`创建对象；
2. 类内静态私有成员：保存唯一实例（饿汉为对象、懒汉为对象指针）；
3. 公有静态 get 方法：全局唯一入口，返回单例实例。

## 实现方式一：饿汉式单例

**核心特性（文档原文）**

类加载阶段（程序启动、静态变量初始化）直接创建实例；无论代码是否使用该单例，对象常驻内存。 天然线程安全，无需加锁。

**完整实现代码**

```cpp
#include <iostream>
using namespace std;

class SingletonHungry
{
private:
    // 1. 私有构造，禁止外部实例化
    SingletonHungry()
    {
        cout << "饿汉式：类加载时自动创建实例" << endl;
    }
    // 禁止拷贝构造、拷贝赋值，防止生成多个实例
    SingletonHungry(const SingletonHungry&) = delete;
    SingletonHungry& operator=(const SingletonHungry&) = delete;

    // 2. 私有静态对象，程序启动直接初始化
    static SingletonHungry instance;

public:
    // 3. 公有静态获取实例接口
    static SingletonHungry& getInstance()
    {
        return instance;
    }
};
// 类外初始化静态实例（程序启动执行）
SingletonHungry SingletonHungry::instance;

int main()
{
    // 全程获取同一个对象引用
    SingletonHungry& s1 = SingletonHungry::getInstance();
    SingletonHungry& s2 = SingletonHungry::getInstance();
    cout << &s1 << endl;
    cout << &s2 << endl; // 地址完全相同，为同一实例
    return 0;
}
```

**优缺点**

✅ 优点：实现简单、天然线程安全； ❌ 缺点：程序启动直接占用内存，若全程不使用该单例，造成内存浪费。

## 实现方式二：懒汉式单例

**核心特性（文档原文）**

延迟加载：第一次调用 getInstance () 时才创建实例，未使用时不占用内存； 原生单线程安全，多线程环境下会创建多个实例，需要加互斥锁优化。

**基础单线程版（不支持多线程）**

```cpp
#include <iostream>
using namespace std;

class SingletonLazy
{
private:
    SingletonLazy()
    {
        cout << "懒汉式：第一次调用才创建实例" << endl;
    }
    // 禁用拷贝、赋值
    SingletonLazy(const SingletonLazy&) = delete;
    SingletonLazy& operator=(const SingletonLazy&) = delete;

    // 静态指针，初始为nullptr
    static SingletonLazy* instance;

public:
    static SingletonLazy* getInstance()
    {
        // 第一次调用才new对象
        if (instance == nullptr)
        {
            instance = new SingletonLazy();
        }
        return instance;
    }
    // 释放单例内存接口
    static void destroy()
    {
        if (instance != nullptr)
        {
            delete instance;
            instance = nullptr;
        }
    }
};
// 静态指针初始化为空
SingletonLazy* SingletonLazy::instance = nullptr;

int main()
{
    SingletonLazy* s1 = SingletonLazy::getInstance();
    SingletonLazy* s2 = SingletonLazy::getInstance();
    cout << s1 << endl << s2 << endl;
    SingletonLazy::destroy();
    return 0;
}
```

**多线程风险说明**

多线程同时执行`if(instance == nullptr)`，会同时判定为空，多次 new 生成多个对象，破坏单例唯一性。 拓展方案：双检锁 DCL + volatile 关键字实现线程安全懒汉式。

## 饿汉式 vs 懒汉式 对比表（文档原版拓展）

## 单例模式关键避坑拓展（文档未提及高频考点）

1. 禁用拷贝构造、拷贝赋值 默认编译器生成浅拷贝，会复制出新实例，破坏单例；必须用`=delete`删除拷贝构造与赋值运算符。
2. 内存释放处理

- 饿汉式静态对象：程序结束由系统自动回收，无需手动释放；
- 懒汉指针版本：需提供静态 destroy 接口手动 delete，避免内存泄漏。

1. 私有化析构函数拓展 若析构私有，外部无法 delete；适合饿汉式，懒汉若私有析构则只能内部释放。
2. 禁止外部 new 实例 构造函数 private，外部`new Singleton()`直接编译报错，从根源限制多实例。

## 单例模式典型业务使用场景

1. 全局日志管理器：项目全程仅一套日志输出接口；
2. 数据库连接池：全局唯一数据库连接管理对象；
3. 配置文件管理器：统一读取全局配置，避免重复加载配置；
4. 硬件资源管理器：声卡、摄像头、串口等独占硬件资源；
5. 缓存管理类：全局唯一缓存容器；
6. 窗口管理器、全局工具类。

# 友元

## 友元简介（文档原文）

**定义:**

友元是 C++ 提供的访问机制，允许指定函数 / 指定类直接访问另一个类的 `private` 私有、`protected` 保护成员。

**核心特性:**

1. 打破类的封装隔离，仅给指定对象开放内部权限；
2. 友元关系单向、无交换性、无传递性、不可继承；
3. 仅在特殊业务场景使用，不可滥用。

**三大分类:**

1. 友元全局函数：普通全局函数作为类的友元
2. 友元成员函数：其他类的成员函数作为友元
3. 友元类：整个类作为当前类的友元

**使用场景:**

外部逻辑需要频繁读取 / 修改类的私有成员，不想提供大量`get/set`接口时使用（如运算符重载、打印输出流`operator<<`）。

## 友元全局函数

语法格式（文档原文）:

```cpp
class 类名
{
public:
    // 类内使用friend声明全局友元函数
    friend 返回值 函数名(参数列表);
private:
    int num;
};

// 类外正常实现全局函数，无需加friend
返回值 函数名(类名 obj)
{
    // 可直接访问obj私有成员num
}
```

**关键规则:**

1. 友元函数不属于类成员，没有 this 指针；
2. 访问非静态私有成员：必须传入类对象 / 对象引用；
3. 访问静态私有成员：无需对象，可直接`类名::静态变量`；

**示例代码:**

```cpp
#include <iostream>
using namespace std;

class Person
{
private:
    int age;
    static int count;
public:
    Person(int a) : age(a) {}
    // 声明全局打印函数为友元
    friend void printPerson(Person p);
};
int Person::count = 10;

// 全局友元函数
void printPerson(Person p)
{
    // 直接访问私有非静态成员age
    cout << "年龄：" << p.age << endl;
    // 直接访问私有静态成员count
    cout << "静态计数：" << Person::count << endl;
}

int main()
{
    Person p(18);
    printPerson(p);
    return 0;
}
```

## 友元成员函数

定义:

将另一个类的某一个成员函数声明为本类友元，仅该函数可访问私有成员，其他函数无权限。

**实现前提（拓展重点）:**

必须做前置类声明，编译器提前识别外部类； 语法模板：

```cpp
// 前置声明类A
class A;

class B
{
public:
    void show(A& a); // B的成员函数，后续作为A的友元
};

class A
{
private:
    int data = 100;
public:
    // 指定B的show函数为本类友元
    friend void B::show(A& a);
};

// 类外实现B::show
void B::show(A& a)
{
    cout << a.data; // 合法，友元可访问私有data
}
```

**完整示例:**

```cpp
#include <iostream>
using namespace std;

// 前置声明
class Student;

class Teacher
{
public:
    void lookScore(Student& s);
};

class Student
{
private:
    int score = 99;
public:
    // Teacher::lookScore 为本类友元
    friend void Teacher::lookScore(Student& s);
};

void Teacher::lookScore(Student& s)
{
    cout << "学生分数：" << s.score << endl;
}

int main()
{
    Student s;
    Teacher t;
    t.lookScore(s);
    return 0;
}
```

## 友元类

**定义:**

将一整个类声明为当前类友元，该友元类中所有成员函数都能访问当前类私有、保护成员。

**语法:**

```cpp
class A
{
private:
    int num = 66;
public:
    // 声明B是A的友元类
    friend class B;
};

class B
{
public:
    void func(A a)
    {
        cout << a.num; // B全部函数可访问A私有成员
    }
};
```

**核心单向特性:**

仅 B 能访问 A，A 不能访问 B 的私有成员，不会自动双向授权。

## 友元使用四大硬性注意事项（文档原文）

1. 无交换性（单向） A 声明 B 为友元 ≠ B 自动把 A 当成友元；想要双向互访，必须两边互相声明友元。
2. 无传递性 A 友元是 B，B 友元是 C；A 不能访问 C 私有成员，友元关系不传递。
3. 不可继承 父类的友元关系不会继承给子类；子类无法凭借父类友元权限访问目标类私有成员。
4. 破坏封装性 封装核心是隔离私有数据，友元直接打破访问权限控制，尽量少用。

## 友元优缺点（文档原文）

**优点：**

1. 灵活性高，无需对外暴露大量`get/set`接口即可访问私有成员；
2. 简化运算符重载、打印流、跨类协作等复杂代码逻辑。

**缺点：**

1. 破坏面向对象封装特性，数据访问权限失控；
2. 提高类之间耦合度，后期修改、维护、单元测试难度上升；
3. 权限无法精细管控（友元类会开放全部函数权限）。

## 高频易错点汇总

1. `friend`仅写在类内声明处，函数 / 类外部实现时不能加 friend；
2. 友元全局函数不是类成员，没有 this 指针；
3. 友元成员函数必须前置声明目标类，否则编译识别失败；
4. 友元类仅单向授权，不会自动双向；
5. 父类友元不能被子类继承，子类无对应访问权限；
6. 传递、交换都不生效，多层类之间不会自动共享友元权限；
7. 频繁使用友元会破坏封装，优先考虑`get/set`接口替代；
8. 友元不能修饰构造、析构、静态函数以外的特殊场景。

## 综合完整代码（全局友元 + 友元类演示）

```cpp
#include <iostream>
#include <string>
using namespace std;

class Girl
{
private:
    string name;
    int age;
public:
    Girl(string n, int a) : name(n), age(a) {}

    // 1. 全局函数友元
    friend void showGirl(Girl g);
    // 2. 友元类Boy，Boy全部函数可访问私有成员
    friend class Boy;
};

// 全局友元函数
void showGirl(Girl g)
{
    cout << "姓名：" << g.name << " 年龄：" << g.age << endl;
}

// 友元类Boy
class Boy
{
public:
    void printInfo(Girl g)
    {
        // 直接访问Girl私有成员
        cout << "闺蜜信息：" << g.name << " " << g.age << endl;
    }
};

int main()
{
    Girl g("小美", 17);
    showGirl(g);

    Boy b;
    b.printInfo(g);
    return 0;
}
```

# 运算符重载

## 左值 &amp; 右值基础概念

1. 左值 lvalue 拥有确定内存地址、可被取地址，能放在赋值号左边。 核心特征：可赋值、可取地址 

示例：普通变量`int a;`、对象、数组元素、`++a`表达式。

1. 右值 rvalue 无固定内存地址，多为临时数据 / 字面量，不能放在赋值左侧、不能取地址。 核心特征：不可赋值、无法取地址 

示例：数字字面量`100`、`a+5`运算结果、`a++`表达式。

```cpp
int a = 10; // a左值
int b = a + 5; // a+5是右值
++a = 20; // ++a返回左值，合法
a++ = 30; // a++返回右值，编译报错
```

## 运算符重载简介

1. 定义 对 C++ 已有运算符重新定义逻辑，让运算符支持自定义类对象运算，替代冗长成员函数调用。
2. 核心目的 代码直观简洁，`obj1 + obj2` 远优于 `obj1.add(obj2)`；支持`cout<<对象`、`cin>>对象`等自然写法。
3. 四大硬性限制（加粗重点）

① 不能创造全新运算符，仅能重载语言已存在的符号

② 不可修改运算符原有优先级、结合性

③ 不能改变运算符操作数个数（双目永远两个操作数）

④ `.` `::` `.*` `sizeof` `?:` 无法重载

## 两种重载实现方式

**成员函数重载**

写在类内部，`this`指针默认代表左操作数

- 双目运算符：仅传 1 个参数（右操作数）
- 单目运算符：无参数 语法模板：`返回值 operator运算符(参数) const {}`

**友元全局函数重载**

类外全局函数，声明为`friend`才能访问私有成员，左右操作数全部作为参数传入

- 双目运算符：2 个形参
- 单目运算符：1 个形参 语法模板：`friend 返回值 operator运算符(参数1, 参数2);`

**两种方式适用场景**

- 成员重载：左右操作数都是本类对象
- 友元重载：一侧是内置类型、一侧是自定义类（如`5 + obj`）；`<<`/`>>`流运算符只能友元重载

## 各类运算符重载规范与模板

**双目算术 / 关系运算符（+ - \* / == &gt; &lt;）**

表达式格式：`L # R` 成员函数模板

```cpp
// 算术
const MyClass operator+(const MyClass& R) const;
// 关系，返回bool
bool operator==(const MyClass& R) const;
```

友元函数模板

```cpp
friend const MyClass operator+(const MyClass& L, const MyClass& R);
friend bool operator==(const MyClass& L, const MyClass& R);
```

**单目运算符（负号 -、!、\~）**

表达式格式：`# O`，运算结果为右值 成员模板

```cpp
const MyClass operator-() const;
```

友元模板

```cpp
friend const MyClass operator-(const MyClass& O);
```

**赋值运算符（= += -= \*=）**

左操作数必须是左值，返回自身引用，支持链式赋值 成员模板（赋值运算符只能成员重载，不能全局友元）

```cpp
MyClass& operator+=(const MyClass& R);
```

**自增 / 自减 ++ --（高频区分考点）**

**前自增 ++obj**

先修改，返回自身左值引用，支持链式赋值 

成员：`MyClass& operator++();` 

友元：`friend MyClass& operator++(MyClass& O);`

**后自增 obj++**

哑元`int`占位区分前自增，返回修改前临时副本（右值） 

成员：`const MyClass operator++(int);` 

友元：`friend const MyClass operator++(MyClass& O, int);`

前后自增对比

- 前 ++：返回引用，原地修改，可连续赋值
- 后 ++：返回临时拷贝，无法赋值，哑元 int 仅作区分标识

**流插入 &lt;&lt;/ 流提取&gt;&gt;（cout cin 专用）**

只能全局友元重载，`ostream/istream`是左操作数，无法写成类成员 输出 << 模板

```cpp
friend ostream& operator<<(ostream& out, const MyClass& obj);
```

输入 >> 模板

```cpp
friend istream& operator>>(istream& in, MyClass& obj);
```

返回流引用，实现链式调用：`cout << obj1 << obj2;`

## 核心加粗必记规则

1. 赋值运算符 =、+= 仅支持成员函数重载，禁止全局友元
2.  <<和>> 输入输出流运算符只能用全局友元，不能写类内成员
3.  后自增必须增加 int 哑元参数，用来和前自增区分，参数无需传值
4.  前自增返回引用（左值），后自增返回临时对象（右值）
5.  成员重载默认 this 为左操作数；友元重载两个操作数全部作为形参传入
6.  运算符重载不会改变优先级、操作数数量，不能自创运算符
7.  重载 == 时建议同步重载！=，重载 > 同步重载 <，保证逻辑完整

## 综合完整示例（复数类演示 + 全部常用重载）

```cpp
#include <iostream>
using namespace std;

class Complex
{
private:
    int real;
    int imag;
public:
    Complex(int r = 0, int i = 0) : real(r), imag(i) {}

    // 1. 成员重载 + 双目加法
    Complex operator+(const Complex& c) const
    {
        return Complex(real + c.real, imag + c.imag);
    }

    // 2. 成员重载前++
    Complex& operator++()
    {
        real++;
        imag++;
        return *this;
    }

    // 3. 成员重载后++，int哑元
    const Complex operator++(int)
    {
        Complex temp = *this;
        real++;
        imag++;
        return temp;
    }

    // 4. 重载+= 赋值
    Complex& operator+=(const Complex& c)
    {
        real += c.real;
        imag += c.imag;
        return *this;
    }

    // 友元：输出流 <<
    friend ostream& operator<<(ostream& out, const Complex& c);
    // 友元：等于 ==
    friend bool operator==(const Complex& a, const Complex& b);
};

// 友元实现输出
ostream& operator<<(ostream& out, const Complex& c)
{
    out << c.real << "+" << c.imag << "i";
    return out;
}

// 友元实现相等判断
bool operator==(const Complex& a, const Complex& b)
{
    return a.real == b.real && a.imag == b.imag;
}

int main()
{
    Complex c1(1,2), c2(3,4);
    Complex c3 = c1 + c2;
    cout << "c1 + c2 = " << c3 << endl;

    ++c1;
    cout << "前++c1：" << c1 << endl;
    c1++;
    cout << "后++c1：" << c1 << endl;

    c1 += c2;
    cout << "c1 += c2：" << c1 << endl;

    if(c1 == c2) cout << "相等" << endl;
    else cout << "不相等" << endl;
    return 0;
}
```

## 运算符重载核心总结

1. 本质是语法糖，底层仍是函数调用，只是写法简化；
2. 两种重载方式按需选择，流运算符、左右类型不一致优先友元；
3. 返回引用实现链式操作（赋值、流输出），返回临时对象用于算术、后自增；
4. 严格区分左值右值，前自增可赋值、后自增不可赋值；
5. 禁止重载`.` `sizeof`等固定运算符，不可修改运算符原生规则。

# 继承

## 继承基础概念与语法

1. 继承核心定义 继承是 OOP 三大核心特性之一，让派生类（子类）复用基类（父类）全部成员，同时拓展自身独有功能。 

示例：英雄基类统一封装血量、攻击；射手、法师作为子类继承通用属性，再新增专属技能。

1. 两大核心作用① 代码复用：公共逻辑只写在父类，子类直接继承，消除重复代码；② 多态实现前置基础：没有继承就无法实现运行时多态。
2. 标准继承语法

```cpp
// 基类（父类）
class Base{
public:
    int num;
};

// 派生类（子类）
class Son : 继承方式 Base{
    // 子类独有成员
};
```

三种合法继承方式：`public` / `private` / `protected`

## 三种继承方式与权限对照表

**权限总规则**

父类`private`私有成员永远无法在子类内直接访问，只是会被继承到子类内存中；只有 public/protected 能被子类直接操作。

<table v-pre><tbody><tr><td>继承方式</td><td>父 public 成员在子类</td><td>父 protected 成员在子类</td><td>父 private 成员</td><td>推荐场景</td></tr><tr><td>public 公有继承</td><td>public</td><td>protected</td><td>不可访问</td><td>绝大多数业务项目（标准用法）</td></tr><tr><td>private 私有继承</td><td>private</td><td>private</td><td>不可访问</td><td>极少使用，仅内部封装</td></tr><tr><td>protected 保护继承</td><td>protected</td><td>protected</td><td>不可访问</td><td>多层派生场景</td></tr></tbody></table>


加粗重点规范：日常开发统一使用public 公有继承，可读性最好、符合面向对象设计思想。

## 继承中四大特殊成员函数

**构造函数**

调用顺序：先父类构造 → 后子类构造调用规则

1. 子类构造不手动指定父类构造时，编译器自动调用父类无参默认构造；
2. 父类只有带参构造、无默认构造，子类必须在初始化列表显式调用；

```cpp
class Son : public Base{
public:
    // 初始化列表显式调用父类带参构造
    Son(int n) : Base(n){}
};
```

**析构函数**

调用顺序：先子类析构 → 后父类析构 规则：析构函数无法手动调用父类，编译器自动逆序释放资源，无需写初始化列表。

**拷贝构造函数**

调用顺序：先父类拷贝构造 → 后子类拷贝构造 子类拷贝构造必须在初始化列表传入对象给父类，完整写法：

```cpp
Son(const Son& obj) : Base(obj){
    // 拷贝子类独有成员
}
```

若不手动写，编译器自动调用父类默认拷贝构造，浅拷贝会存在资源问题。

**拷贝赋值运算符 operator=**

执行顺序：先子类赋值逻辑，再显式调用父类赋值 标准重写模板：

```cpp
Son& operator=(const Son& obj){
    if(this != &obj){ // 防止自赋值
        Base::operator=(obj); // 显式调用父类赋值
        // 赋值子类独有成员
    }
    return *this;
}
```

## 继承中的静态成员（静态变量 / 静态函数）

1. 静态成员可被子类继承访问 父类`public/protected`静态变量、静态函数，子类可直接使用；父类 private 静态子类无法访问。
2. 同名隐藏（隐藏≠重写） 子类定义和父类同名静态变量 / 静态函数时，发生名称隐藏：子类域优先匹配自身成员，父类同名被屏蔽。 访问被隐藏父类静态成员：`Base::静态变量` / `Base::静态函数()`。
3. 核心限制（加粗） 静态成员函数不支持多态，静态函数属于类，无 this 指针，无法和虚函数配合实现运行时多态。

## 高频必记加粗核心规则

1. 父类 private 成员会被子类继承存储，但子类内部永远不能直接访问
2. 构造顺序：先父后子；析构顺序：先子后父，不可逆
3. 子类拷贝构造、拷贝赋值必须手动调用父类对应函数，否则仅执行父类默认版本
4.  三种继承优先使用 public，private/protected 继承工程极少使用
5. 子类同名静态成员只会隐藏父类，不属于函数重写，静态无多态
6. 初始化列表是唯一能调用父类构造、拷贝构造的位置，函数体内无法调用

## 完整综合演示代码

```cpp
#include <iostream>
using namespace std;

// 父类
class Base{
protected:
    int num;
public:
    Base(int n = 0) : num(n){}
    // 拷贝构造
    Base(const Base& b){
        num = b.num;
    }
    // 拷贝赋值
    Base& operator=(const Base& b){
        if(this != &b){
            num = b.num;
        }
        return *this;
    }
    void show(){
        cout << "父类num:" << num << endl;
    }
    static int staticVal;
};
int Base::staticVal = 100;

// public公有继承子类
class Son : public Base{
private:
    int subNum;
public:
    // 初始化列表调用父类构造
    Son(int b = 0, int s = 0) : Base(b), subNum(s){}
    // 子类拷贝构造
    Son(const Son& obj) : Base(obj){
        subNum = obj.subNum;
    }
    // 子类拷贝赋值
    Son& operator=(const Son& obj){
        if(this != &obj){
            Base::operator=(obj);
            subNum = obj.subNum;
        }
        return *this;
    }
    void print(){
        cout << "父成员:" << num << " 子类成员:" << subNum << endl;
    }
    // 同名静态变量，隐藏父类
    static int staticVal;
};
int Son::staticVal = 200;

int main()
{
    Son s1(10,20);
    s1.print();

    // 拷贝构造
    Son s2 = s1;
    s2.print();

    // 拷贝赋值
    Son s3;
    s3 = s1;
    s3.print();

    // 静态成员隐藏演示
    cout << "子类静态：" << Son::staticVal << endl;
    cout << "父类静态：" << Base::staticVal << endl;
    return 0;
}
```

# 多重继承

## 多重继承基础概念

1. 定义 单个派生类同时继承多个不同基类，一次性复用多个类的属性与方法，适合组合多种独立功能模块。
2. 核心风险 多个父类存在同名成员时，直接访问会产生二义性编译报错，必须通过`类名::成员`指定来源。
3. 标准语法（推荐完整写法，每个父类单独标注继承权限）

```cpp
class A{};
class B{};
// 子类同时公有继承A、B
class C : public A, public B
{
};
```

## 三种继承结构区分

**链式单继承（多层单继承）**

一条单向继承链，每个类仅一个直接父类，无多父类。

```cpp
class A;
class B : public A;
class C : public B;
```

结构：A → B → C，C 可逐层拿到 A、B 所有成员。

**扇形多重继承（普通多继承）**

子类同时继承多个无关联独立父类，不存在公共顶层基类，无菱形冗余问题。

```cpp
class A{};
class B{};
class C : public A, public B{};
```

**菱形（钻石）继承（多继承经典坑点）**

两个中间类同时继承同一个公共基类，再由一个子类同时继承这两个中间类，形成菱形结构。

```cpp
// 顶层公共基类
class A{};
class B : public A{};
class C : public A{};
// 汇聚子类，同时继承B、C
class D : public B, public C{};
```

菱形原生两大严重问题（加粗重点）

① 内存冗余：D 对象中存在两份 A 的成员变量，一份来自 B、一份来自 C，占用双倍内存；

② 访问歧义：直接调用 A 内成员编译器分不清走 B 还是 C 路径，直接报二义性错误。

## 虚继承 virtual（解决菱形继承专用方案）

1. 核心作用 使用`virtual`修饰中间类的继承关系，让多条继承路径共享唯一一份公共虚基类实例，消除重复内存与访问歧义。
2. 虚继承标准语法

```cpp
class A
{
public:
    int val;
};
// 中间类使用virtual虚继承顶层基类A
class B : virtual public A{};
class C : virtual public A{};
// 汇聚子类正常继承B、C，仅保留一份A
class D : public B, public C{};
```

1. 虚继承构造特殊规则（必考） 普通继承：中间子类负责调用上层父类构造； 虚继承：虚基类 A 的构造函数，必须由最底层汇聚子类 D 在初始化列表显式调用，中间类 B、C 的初始化列表对 A 的调用会被编译器忽略。

```cpp
class A
{
public:
    A(int v){ val = v; }
    int val;
};
class B : virtual public A
{
public:
    B(int v) : A(v){} // 此处A构造失效
};
class C : virtual public A
{
public:
    C(int v) : A(v){} // 此处A构造失效
};
// 汇聚子类必须手动初始化虚基类A
class D : public B, public C
{
public:
    D(int v1, int v2, int v3) : B(v1), C(v2), A(v3)
    {
        // 只有这里的A(v3)会执行，全局只存在一份A
    }
};
```

规则总结：虚基类初始化权交给最终派生类，中间层无法初始化虚基。

## 多继承同名成员歧义解决办法

当多个父类存在同名变量 / 函数，直接访问报错，两种解决方案：

1. 访问时显式指定类域：`d.B::val`、`d.C::func()`
2. 在子类内部重写同名函数，屏蔽父类歧义接口

## 加粗核心必记规则

1. 多重继承允许一个子类拥有多个直接父类，单一继承链仅一个直接父类
2. 菱形不使用虚继承会产生两份公共基类数据，内存浪费 + 访问二义性
3. virtual 虚继承让所有派生路径共享唯一一份虚基类实例，根治菱形缺陷
4. 虚基类构造只能由最底层汇聚子类显式调用，中间类对虚基构造无效
5. 多父类存在同名成员时，必须加`类名::`限定，否则编译报歧义错误
6. 开发规范：无特殊组合需求优先单继承，多重继承谨慎使用，菱形结构必须加 virtual

## 完整演示代码（菱形虚继承对比）

```cpp
#include <iostream>
using namespace std;

// 公共虚基类
class Base
{
public:
    int num;
    Base(int n) : num(n){}
};

// 中间类虚继承Base
class Mid1 : virtual public Base
{
public:
    Mid1(int n) : Base(n){}
};
class Mid2 : virtual public Base
{
public:
    Mid2(int n) : Base(n){}
};

// 汇聚子类，必须初始化虚基类
class Son : public Mid1, public Mid2
{
public:
    Son(int m1, int m2, int b) : Mid1(m1), Mid2(m2), Base(b){}
};

int main()
{
    Son s(10,20,100);
    // 仅有一份Base::num，无歧义
    cout << s.num << endl; // 输出100
    return 0;
}
```

**无虚继承错误对比（删除 virtual 后）**

```cpp
class Mid1 : public Base;
class Mid2 : public Base;
class Son : public Mid1, public Mid2;
// s.num 编译报错，存在Mid1::Base::num 和 Mid2::Base::num两份数据
```

# 多态

## 虚函数基础

1. 定义

 基类使用`virtual`修饰的成员函数，是实现运行时多态的核心基础。语法模板

```cpp
virtual 返回值 函数名(形参列表) {
    函数实现;
}
```

2.核心作用 ：

开启动态绑定：用基类指针 / 引用接收子类对象时，程序运行阶段自动匹配子类重写的函数。

3.关键细节：

子类重写虚函数时，`virtual`可省略，函数依旧保持虚函数特性。

## 函数重写（覆盖 override）

定义 ：

父子继承关系下，子类重新实现基类虚函数，称为重写。严格重写规则（全部满足才算重写）

1. 必须存在公有继承关系；
2. 基类函数必须加`virtual`；
3. 函数名、参数个数、参数类型完全一致；
4. 返回值相同（支持协变返回，初学暂不深究）。标准示例

```cpp
class Base {
public:
    virtual void show() {
        cout << "基类函数" << endl;
    }
};

class Son : public Base {
public:
    // 重写基类虚函数，virtual可省略
    void show() {
        cout << "子类重写函数" << endl;
    }
};
```

**重写 vs 重载 核心区分**


<table v-pre><tbody><tr><td>对比项</td><td>函数重载</td><td>函数重写</td></tr><tr><td>作用域</td><td>同一个类 / 全局域</td><td>父类与派生类之间</td></tr><tr><td>参数要求</td><td>参数个数 / 类型必须不同</td><td>参数列表完全一致</td></tr><tr><td>返回值</td><td>无强制限制</td><td>必须匹配（协变除外）</td></tr><tr><td>绑定时机</td><td>编译期静态绑定</td><td>运行期动态绑定</td></tr></tbody></table>


## 多态总览

1. 多态分类

- 静态多态（编译期多态）：编译阶段确定调用函数，代表：函数重载、运算符重载
- 动态多态（运行时多态）：程序运行才确定调用函数，依靠虚函数实现，是 OOP 核心

1. 动态多态四大必备条件（缺一不可，加粗重点）

① 存在公有继承关系；

② 父类声明 virtual 虚函数；

③ 子类完整重写该虚函数；

④ 使用基类指针 / 基类引用指向子类对象。

**多态底层原理（vtbl 虚函数表）**

1. 带有虚函数的类，内部自动生成虚函数表 vtable，存储本类所有虚函数地址；
2. 每个对象自带一个虚表指针`vptr`，指向所属类的虚函数表；
3. 基类指针调用虚函数时，运行时通过 vptr 查表，找到子类重写的函数地址执行。

**多态标准使用示例**

```cpp
void printInfo(Base& obj) {
    obj.show(); // 同一接口，传父对象走父方法，传子对象走子方法
}

int main()
{
    Base b;
    Son s;
    printInfo(b); // 输出基类函数
    printInfo(s); // 输出子类重写函数，实现多态
    return 0;
}
```

## 虚析构函数

1.  作用场景 使用`new`创建子类，用基类指针接收，最后通过基类指针`delete`释放对象。 若无虚析构，只会执行基类析构，子类资源无法释放，造成内存泄漏。
2. 语法

```cpp
virtual ~类名() { }
```

1. 核心规则（加粗）只要类存在被继承的可能，基类析构一律加 virtual；纯虚抽象类必须写虚析构。错误示范

```cpp
class Base {
public:
    ~Base(){} // 非虚析构，delete子类指针只会调用父析构
};
Base* p = new Son;
delete p; // 子类析构不执行，内存泄漏
```

正确写法

```cpp
class Base {
public:
    virtual ~Base(){}
};
```

## 纯虚函数 &amp; 抽象类

**1. 纯虚函数定义**

基类只声明接口，不提供实现，语法末尾赋值`=0`：

```cpp
virtual 返回值 函数名(参数) = 0;
```

**2. 抽象类规则**

1. 包含至少一个纯虚函数的类 = 抽象类；
2. 抽象类不能直接创建实例对象，仅用来做父类定义统一接口；
3. 派生类必须全部重写所有纯虚函数，否则子类依旧是抽象类，无法实例化。

**示例**

```cpp
// 抽象基类，定义统一接口
class Shape {
public:
    virtual void getArea() = 0; // 纯虚函数
    virtual ~Shape(){}
};

// 子类重写全部纯虚函数，变为普通类，可以创建对象
class Circle : public Shape {
public:
    void getArea() override {
        cout << "圆形面积" << endl;
    }
};
```

## 加粗必背核心规则

1. 动态多态四要素：公有继承 + 基类 virtual + 子类重写 + 基类指针 / 引用
2. 重写要求函数名、参数列表完全一致，仅返回值允许协变
3. 静态多态编译绑定，动态多态运行查表绑定，底层依靠 vtable 虚函数表
4. 基类指针释放子类对象时，析构必须加 virtual，否则子类析构不执行，内存泄漏
5. 纯虚函数`=0`，包含纯虚函数的抽象类无法实例，子类必须全部实现纯虚接口
6. 重载同域、重写父子域，二者不能混淆

## 完整综合演示代码

```cpp
#include <iostream>
using namespace std;

// 抽象基类（纯虚函数）
class Animal {
public:
    // 纯虚函数
    virtual void speak() = 0;
    // 虚析构
    virtual ~Animal() {
        cout << "动物基类析构" << endl;
    }
};

// 子类1：重写纯虚函数
class Dog : public Animal {
public:
    void speak() override {
        cout << "汪汪汪" << endl;
    }
    ~Dog() {
        cout << "狗子类析构" << endl;
    }
};

// 子类2：重写纯虚函数
class Cat : public Animal {
public:
    void speak() override {
        cout << "喵喵喵" << endl;
    }
    ~Cat() {
        cout << "猫子类析构" << endl;
    }
};

// 多态统一接口
void voice(Animal& ani) {
    ani.speak();
}

int main()
{
    Dog d;
    Cat c;
    voice(d);
    voice(c);

    // 动态内存测试虚析构
    Animal* p = new Dog;
    delete p;
    return 0;
}
```

# 模板

## 模板总基础

1. 模板核心作用：模板是 C++ 泛型编程唯一原生机制，核心思想：一份通用代码，适配所有数据类型，不用为 int、double、string、自定义类重复写逻辑完全相同的代码。
2.  两大分类函数模板：通用工具函数（交换、求最值、求和等）类模板：通用容器（自定义数组、队列、配对类，标准库 vector/map 底层都是类模板）
3.  三大核心优势

① 消除大量重复冗余代码，大幅降低维护成本；

② 编译器类型校验，不存在 void \* 无类型的安全漏洞；

③ 同时支持内置基础类型、自定义类、结构体，通用性极强。

## 函数模板

**标准定义语法**

`template` 为模板声明关键字，`<>`内是类型形参，`typename`/`class` 完全等价，工程推荐`typename`可读性更好。

```cpp
// 写法1（推荐）
template <typename T>
T maxVal(T a, T b)
{
    return a > b ? a : b;
}

// 写法2 老式语法
template <class T>
void swapTwo(T& x, T& y)
{
    T temp = x;
    x = y;
}
```

- T：类型占位符，编译时自动替换为调用时的真实数据类型；
- 一个模板可以写多个类型参数：`template<typename T1, typename T2>`

**三种调用方式（完整示例）**

**① 隐式类型推导（日常最常用）**

编译器根据传入实参自动识别 T，无需手动写尖括号

```cpp
int a = 10, b = 20;
cout << maxVal(a, b); // 自动推导 T = int

double x = 3.14, y = 2.71;
cout << maxVal(x, y); // 自动推导 T = double
```

**② 空尖括号 函数名&lt;&gt;()**

强制调用模板版本，跳过普通重载函数匹配逻辑

```cpp
swapTwo<>(a, b);
```

**③ 显式指定模板类型（无法自动推导时使用）**

部分场景参数无法推导类型，必须手动写明`<类型>`

```cpp
maxVal<int>(5, 8);
```

**普通函数 VS 模板优先级规则（必考）**

普通同名函数 > 函数模板 如果存在参数完全匹配的普通函数，编译器优先执行普通函数；无匹配普通函数才会实例化模板生成代码。 示例：

```cpp
// 普通int专用函数，优先级更高
int maxVal(int a, int b)
{
    cout << "执行普通函数" << endl;
    return a > b ? a : b;
}
// 函数模板
template<typename T>
T maxVal(T a, T b)
{
    cout << "执行模板函数" << endl;
    return a > b ? a : b;
}
int main()
{
    maxVal(1,2);    // 优先调用普通int函数
    maxVal(1.1,2.2);// 无匹配普通函数，调用模板
}
```

**底层实例化原理（加粗重点）**

模板本身只是代码蓝图，不是可执行函数；只有代码触发调用时，编译器才会生成对应类型的独立函数实体。

1. 仅写模板、不调用：编译器只检查基础语法，不生成机器码；
2. 第一次用 int 调用：单独生成一份`int maxVal(int,int)`；
3. 第一次用 double 调用：单独生成一份`double maxVal(double,double)`；
4. 每种数据类型都会生成独立函数，不同类型函数互不共享代码；
5. 这个替换生成实体的过程，称为模板实例化，全程自动完成，无需手动操作。

**拓展：模板特化（文档补充缺失）**

针对特殊类型单独定制模板实现，优先级高于通用模板：

```cpp
template<typename T>
void show(T t) { cout << "通用类型" << endl; }
// 字符串特化版本
template<>
void show<const char*>(const char* s) { cout << "字符串特化" << endl; }
```

## 类模板

**定义标准语法**

支持单个 / 多个类型参数，`class`/`typename`通用

```cpp
// 单类型参数通用数组容器
template <typename T>
class MyArr
{
private:
    T data[100];
public:
    void set(int idx, T val);
    T get(int idx);
};

// 多类型参数 键值配对类
template <typename K, typename V>
class Pair
{
public:
    K key;
    V value;
};
```

限制规则：同一个作用域内，不能同时存在**同名普通类与类模板**，会编译冲突。

**类模板实例化使用规则**

创建对象必须在类名后 `<真实类型>`，C++17 之前无法自动推导

```cpp
MyArr<int> intArr;       // T=int 整型容器
MyArr<double> dArr;      // T=double 浮点容器
Pair<string, int> p;     // K字符串 V数字
// 错误写法 MyArr arr; 缺少模板参数，编译报错
```

**类模板外部成员函数实现（高频易错）**

类外写模板成员函数，必须重复`template`声明，类名后加`<T>`

```cpp
template <typename T>
void MyArr<T>::set(int idx, T val)
{
    data[idx] = val;
}

template <typename T>
T MyArr<T>::get(int idx)
{
    return data[idx];
}
```

**类模板带构造函数完整示例**

```cpp
template<typename T>
class Box
{
private:
    T val;
public:
    Box(T v) : val(v){}
    void print()
    {
        cout << val << endl;
    }
};
// 使用
Box<int> box1(100);
Box<string> box2("模板类");
```

## 模板二次编译机制（底层补充）

模板编译分为两个阶段，分两次代码检查：

**第一阶段：解析阶段（未实例化，仅检查语法）**

1. 校验括号、分号、关键字等基础语法错误；
2. 对于未知占位类型 T 的运算、函数调用，暂时不校验合法性，默认合法。

**第二阶段：实例化阶段（调用后完整校验）**

1. 将模板占位符 T 替换为真实传入的数据类型；
2. 完整校验所有运算、函数调用是否适配当前类型，类型不匹配直接抛出编译错误。 例：模板内写`T::func()`，T 为 int 时第二阶段编译直接报错。

## 加粗必背核心规则

1. template 是模板标识，typename 与 class 定义类型参数完全等价；
2. 函数模板支持自动类型推导，类模板实例化必须手动指定`<类型>`；
3. 同名普通函数优先级高于函数模板，优先匹配普通重载；
4. 模板只是代码模板，调用时才实例化，每种类型生成独立代码；
5. 类模板外部实现成员函数，必须前置 template，类名携带`<T>`；
6. 模板分两次编译：未实例化仅查语法，实例化后完整校验类型逻辑；
7. 不能共存，会引发编译冲突。

## 完整综合演示代码

```cpp
#include <iostream>
#include <string>
using namespace std;

// 1. 函数模板：交换两个变量
template<typename T>
void swapVal(T& a, T& b)
{
    T temp = a;
    a = b;
}

// 2. 类模板：通用盒子容器
template<typename T>
class Box
{
private:
    T data;
public:
    Box(T d) : data(d){}
    void show();
};

// 类模板外部方法实现
template<typename T>
void Box<T>::show()
{
    cout << "容器内容：" << data << endl;
}

int main()
{
    // 函数模板隐式推导
    int m = 1, n = 2;
    swapVal(m, n);
    cout << m << " " << n << endl;

    // 显式指定模板类型
    double x = 1.5, y = 9.9;
    swapVal<double>(x, y);

    // 类模板实例化
    Box<int> boxInt(666);
    Box<string> boxStr("C++类模板");
    boxInt.show();
    boxStr.show();
    return 0;
}
```

# 标准模板库（STL）

## STL 整体简介

1. STL 全称 Standard Template Library 标准模板库，是 C++ 标准内置、大量预定义好的类模板 + 通用算法集合，全部基于泛型模板实现。
2. 核心价值 不用手写数组、链表、哈希表、排序、查找等底层数据结构，开箱即用，统一标准，跨平台团队通用。

STL 六大核心组件

## 容器总分类（三大类）

**顺序容器：线性连续 / 链式存储，元素有序**

底层内存连续或链表，元素存入顺序就是遍历顺序 代表：`vector`动态数组、`deque`双端数组、`list`双向链表、`forward_list`单向链表、`string`字符串

**关联容器：按键自动排序，底层红黑树**

内部自动按 key 升序，查找速度稳定 O (logn) 代表：`set`集合、`map`键值对、`multiset/multimap`允许重复 key

**无序关联容器：哈希表存储，查找更快**

底层哈希表，无自动排序，查询平均 O (1) 代表：`unordered_set`、`unordered_map`

**容器适配器（基于顺序容器封装）**

无独立内存结构，依赖底层顺序容器实现功能 代表：`stack`栈、`queue`普通队列、`priority_queue`优先队列

容器选择核心依据（加粗）随机下标快速访问 → vector；频繁中间插入删除 → list；头尾高频操作 → deque；需要键值自动排序 → map；快速哈希查找 → unordered_map

## 迭代器（STL 统一访问标准）

1. 定义 迭代器是容器内置 “通用指针”，提供统一遍历接口，所有算法（sort/find）只接收迭代器作为参数。
2.  基础运算符

- `*it`：解引用，获取迭代器指向元素
- `it->成员`：元素是类对象时访问内部成员
- `++it / it++`：向后移动一位
- `--it`：双向迭代器支持向前移动
- `begin()`：首元素迭代器
- `end()`：末尾后一位，不可解引用（边界哨兵）
- `rbegin()/rend()`：反向遍历迭代器

**五类迭代器能力分级（从弱到强）**

关键规则：算法仅使用迭代器支持的最小能力；vector 迭代器可以加减跳跃，list 不支持。

## vector 动态数组（顺序容器重点）

**核心特性**

1. 底层连续一块堆内存，支持下标随机访问，读写速度极快；
2. 自动动态扩容，默认扩容系数 1.5\~2 倍；
3. 尾部插入`push_back`效率极高，中间插入会整体后移元素；
4. 元素类型统一，支持内置类型、自定义类。

**三种初始化写法**

```cpp
#include <vector>
vector<int> v1;                // 空容器
vector<int> v2(10, 0);         // 10个元素，全部初始0
vector<int> v3 = {1,2,3,4,5};  // 列表初始化
```

**vector 全套核心成员函数**


<table v-pre><tbody><tr><td>方法</td><td>功能</td></tr><tr><td>size()</td><td>返回当前有效元素个数</td></tr><tr><td>empty()</td><td>容器为空返回 true</td></tr><tr><td>clear()</td><td>清空所有元素，容量不变</td></tr><tr><td>push_back(val)</td><td>尾部追加元素（最常用）</td></tr><tr><td>pop_back()</td><td>删除末尾元素，无返回值</td></tr><tr><td>front()</td><td>获取第一个元素</td></tr><tr><td>back()</td><td>获取最后一个元素</td></tr><tr><td>v[i]</td><td>下标访问，不检查越界，越界崩溃</td></tr><tr><td>at(i)</td><td>下标访问，越界抛出异常，安全</td></tr><tr><td>erase(it)</td><td>删除迭代器指向元素，后续元素前移</td></tr><tr><td>insert(it, val)</td><td>迭代器位置插入元素</td></tr><tr><td>reserve(n)</td><td>预分配内存，减少频繁扩容</td></tr><tr><td>capacity()</td><td>返回当前总容量（&gt;=size）</td></tr></tbody></table>


**三种遍历方式**

```cpp
vector<int> v = {10,20,30};
// 1. 下标遍历
for(int i=0;i<v.size();i++) cout << v[i];
// 2. 迭代器遍历（通用，所有容器都能用）
for(vector<int>::iterator it = v.begin(); it != v.end(); it++) cout << *it;
// 3. C++11范围for（最简）
for(auto x : v) cout << x;
```

**反向遍历示例**

```cpp
for(auto it = v.rbegin(); it != v.rend(); it++){
    cout << *it;
}
```

## STL 通用算法补充（文档拓展）

头文件 `<algorithm>`，全部接收迭代器区间 [begin, end) 

**常用：**

`sort(begin, end)` 升序排序（vector 随机迭代器可用，list 不可）`find(begin, end, val)` 查找元素，返回对应迭代器`reverse(begin, end)` 反转容器

## 加粗必背核心规则

1. STL 三巨头：容器存数据、迭代器统一访问、算法批量操作
2. vector 内存连续，随机访问快，中间插入删除性能差；list 链表不连续，中间操作快
3.  end () 是末尾哨兵，不指向有效元素，绝对不能解引用`*v.end()`
4. `[]`无越界检查，生产代码优先使用`at()`防崩溃
5.  迭代器分级，只有 vector/deque 支持`it + n`跳跃访问
6.  vector 扩容会重新分配内存，原有迭代器全部失效
7.  所有 STL 算法依靠迭代器实现，不直接操作容器

## vector 完整综合示例

```cpp
#include <iostream>
#include <vector>
#include <algorithm> // sort算法
using namespace std;

int main()
{
    vector<int> vec = {5,2,9,1,3};
    // 尾部添加
    vec.push_back(7);
    // 下标与at访问
    cout << vec[0] << " " << vec.at(1) << endl;
    // 首尾元素
    cout << "首：" << vec.front() << " 尾：" << vec.back() << endl;

    // 排序算法
    sort(vec.begin(), vec.end());
    // 迭代器遍历
    for(auto it = vec.begin(); it != vec.end(); ++it)
    {
        cout << *it << " ";
    }
    cout << endl;

    // 范围for遍历
    for(auto num : vec) cout << num << " ";

    vec.clear();
    if(vec.empty()) cout << "\n容器已清空";
    return 0;
}
```
