# 数据结构绪论

## 数据结构与算法基础知识

### 什么是数据结构

- 数据结构是计算机**存储、组织和管理数据**的方式，主要研究如何高效地管理数据。
- 通俗理解：数据结构就是**存储数据的方式**，即数据元素之间关系的组织与存储形式。
- 数据结构研究的内容可概括为**三要素**：**逻辑结构**（数据元素之间的逻辑关系）、**存储结构**（数据在计算机中的实际表示）、**数据的运算**（定义在逻辑结构上的操作）。

### 什么是算法

- 算法是**针对特定数据结构设计的一组操作步骤**，是对特定问题求解步骤的描述，也是操作数据的具体方法。
- 算法的**五个特性**：**有穷性**（必须在有限步内结束）、**确定性**（每一步含义明确、无歧义）、**可行性**（每一步都能在有限时间内执行）、**输入**（有 0 个或多个输入）、**输出**（至少 1 个输出）。
- 评价算法优劣的标准：**正确性、可读性、健壮性**，以及**时间效率高、存储量低**。

### 数据结构与算法的关系

- 著名公式：**程序 = 数据结构 + 算法**（Niklaus Wirth）。
- 数据结构是**容器**（数据怎么存），算法是**如何"查、取、改、放"容器里数据的方法集合**。
- 两者相辅相成：数据结构是算法的载体，算法是定义在数据结构上的运算；选择合适的结构能显著简化算法并提升效率。

### 数据结构涉及到的算法

定义在数据结构上的常见运算/算法包括：**查找算法、排序算法、插入与删除、遍历**等；常用的算法设计策略有**分治算法、动态规划、贪心算法**。这些内容将在后续章节逐一展开。

## 逻辑结构与存储结构概述

### 逻辑结构

逻辑结构是从**逻辑关系**上描述数据元素之间的关系，与存储方式无关，共 4 类：

- **集合结构**：元素同属一个集合，除"属于 / 不属于"外无其他关系。
- **线性结构**：元素之间是**一对一**关系，如顺序表、链表、栈、队列。
- **树形结构**：元素之间是**一对多**关系，如树、二叉树。
- **图状结构（网状结构）**：元素之间是**多对多**关系，如图。

### 存储结构（物理结构）

存储结构是数据在计算机内存中的**实际表示方式**，主要包括 4 种：

1. **顺序存储结构**：将逻辑上相邻的元素依次存放在**连续的存储空间**中，使元素存储地址的顺序与逻辑顺序保持一致，从而实现高效的顺序访问与随机访问。优点：随机访问快（O(1)）、内存紧凑；缺点：插入删除需移动大量元素、需预分配固定空间。
2. **链式存储结构**：元素存放在**不连续的内存空间**中，通过**指针**链接各元素以保持逻辑关系。优点：插入删除灵活（无需移动元素）、可动态扩展；缺点：不能随机访问、每个结点需额外指针空间。
3. **索引存储结构**：为数据元素建立**辅助结构（索引表）**，通过索引加快查找，而不必遍历所有数据。优点：查找快；缺点：增加索引表空间与维护成本。
4. **哈希（散列）存储结构**：通过**哈希函数**将关键字映射到特定存储地址，建立关键字与存储位置的直接对应关系。本质是"**空间换时间**"——通过预分配额外内存避免遍历查找，增删查平均 O(1)。工作流程分三步：**① 取 Key**：以唯一的键作为检索标识；**② 哈希运算**：通过固定哈希算法将 Key 换算成内存索引地址；**③ 存取 Value**：根据计算出的索引地址精准地存入或读取数据。

### 逻辑结构与存储结构如何组合

同一逻辑结构可选用不同的存储结构，实际应用中按"访问模式 + 数据规模"选择最优组合：

| 逻辑结构 | 常用存储结构 | 应用例子 | 为什么这样组合 |
|-|-|-|-|
| 线性表 | 顺序存储 | 日程表、温度记录、字符串 | 随机访问快（O(1)），内存紧凑，适合频繁查询、少插入删除 |
| 线性表 | 链式存储 | 音乐播放列表、LRU 缓存 | 中间插入/删除快（O(1)），无需移动元素 |
| 线性表（栈） | 顺序 / 链式 | 函数调用栈、撤销操作 | 只需在一端操作，顺序存储更高效 |
| 线性表（队列） | 循环顺序存储 | 打印机任务队列 | 固定大小，避免假溢出 |
| 树（二叉树） | 链式存储 | 文件系统（目录树）、二叉搜索树 | 动态扩展，指针灵活表示父子关系 |
| 树（堆） | 顺序存储 | 优先队列（任务调度） | 用数组下标天然维护完全二叉树，节省指针空间 |
| 图 | 邻接表（链式） | 微博关注关系 | 稀疏图节省空间，快速遍历邻居 |
| 图 | 邻接矩阵（顺序） | 地图各城市间有无直达航班 | 稠密图判断边是否存在仅 O(1) |
| 集合 / 字典 | 散列存储 | 缓存（Redis）、数据库索引（部分） | 增删查平均 O(1)，常数时间极快 |
| 索引结构（B+ 树） | 索引 + 链式 | MySQL InnoDB 主键索引 | 结合多路搜索树与叶子结点的有序链表，适合磁盘存取 |

## 算法效率的度量

### 时间复杂度

- **定义**：算法运行时**基本操作执行次数随输入数据规模 n 增长的变化趋势**，用**大 O 表示法**（如 O(1)、O(n)、O(n²)）定性描述执行效率，而不直接度量具体运行时间。
- **计算基本步骤**：

  1. 确定输入规模 n（通常是数组长度、字符串长度、图的顶点/边数等）；
  2. 找出基本操作——执行次数最多的操作，通常在最内层循环或递归中，如比较、赋值、算术运算；
  3. 计算执行次数函数 T(n)，即基本操作执行的总次数关于 n 的表达式；
  4. 转换为大 O 表示法：**保留最高次项、去掉系数与低次项**。例：T(n) = 3n² + 2n + 1 → O(n²)。
- **常见复杂度排序**：O(1) < O(log₂n) < O(n) < O(nlog₂n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)
- **典型例子**：单层循环 → O(n)；双重循环 → O(n²)；折半查找 → O(log₂n)；循环变量翻倍（for (i = 1; i < n; i \*= 2)）→ O(log₂n)；分治算法（归并排序、快排平均）→ O(nlog₂n)。



### 空间复杂度



- **定义**：算法运行过程中**临时占用的额外存储空间**（不包括输入数据本身所占空间）随输入规模 n 增长而变化的度量，同样用大 O 表示法，如 O(1) 表示常数额外空间、O(n) 表示线性额外空间。
- **计算基本步骤**：

  1. 明确输入规模 n；
  2. 统计额外分配的内存：固定数量的变量 → O(1)；一维数组长度与 n 成正比 → O(n)；二维数组 n×n → O(n²)；递归调用栈深度（每次调用占用常数空间）→ O(深度)；递归中每个栈帧都分配数组 → 累加；
  3. 忽略输入数据本身占用的空间（除非题目要求包含，但通常单独说明）。
- **典型例子**：冒泡排序 O(1)；快速排序平均 O(log₂n)（递归栈深度）；归并排序 O(n)（辅助数组）。



## 数据结构的学习方法



- **抓主线**：逻辑结构 → 存储结构 → 运算（算法），对每个数据结构都按"是什么、怎么存、能做什么"三个问题学习。
- **先理解再记忆**：画结构图辅助理解，动手实现代码并运行验证；学习每个结构后总结其时间复杂度与适用场景。
- **善用对比表**：把相似结构（顺序表 vs 链表、各类查找/排序算法）整理成对比表格，考前快速复习。
- **算法学习三步**：理解思路 → 用小程序例模拟运行 → 写代码实现并测试边界情况。



# 线性表



## 线性结构概述



- **定义**：线性结构是数据结构的一种基本类型，指数据元素之间具有"**一对一**"线性关系的结构。简单说，除第一个和最后一个元素外，其他元素都有且只有一个前驱和一个后继。
- **特点**：

  - **存在唯一首尾**：有唯一的第一个（首节点）和最后一个元素（尾节点）；
  - **元素有序**：元素按特定顺序排列，位置可编号（第 1 个、第 2 个…）；
  - **逻辑关系简单**：除首尾外每个元素都有唯一前驱和后继，逻辑上形成一条"线"；
  - **存储方式两种**：顺序存储（连续内存，可随机访问但插入删除效率低）或链式存储（不连续内存加指针，插入删除高效但不能随机访问）；
  - **遍历方式明确**：通常只能沿线性顺序遍历，部分结构（如双向链表）可双向遍历。
- **线性表的种类**：顺序表、单链表、双向链表、循环链表，以及栈、队列、双端队列等受限的线性表。



### 顺序存储与链式存储对比



| 对比项 | 顺序存储 | 链式存储 |
|-|-|-|
| 存储空间 | 连续的内存单元 | 不连续，用指针链接 |
| 随机访问 | 按下标 O(1) 定位 | 需从头遍历，O(n) |
| 插入 / 删除 | O(n)，需移动大量元素 | 已知结点时 O(1)，只需改指针 |
| 空间开销 | 无额外指针，密度高 | 每结点多一个（或多个）指针域 |
| 容量 | 固定，需预分配 | 动态扩展，无容量限制 |



## 线性表的顺序表示和实现（顺序表）



- **定义**：用一组**地址连续的存储单元**依次存储线性表的数据元素，即以数组的形式存储，逻辑相邻的元素物理位置也相邻。
- **特点**：

  - 支持**随机访问**：通过下标可在 O(1) 时间内定位任意元素；
  - 插入 / 删除需要移动大量元素：在位置 i 插入平均移动 n/2 个元素，删除平均移动 (n-1)/2 个元素。
- **基本操作时间复杂度**：按位置访问 O(1)；按值查找 O(n)；插入 O(n)；删除 O(n)。
- **优点**：随机访问快、存储密度高、内存紧凑。
- **缺点**：容量固定需预分配（易浪费或溢出）；插入删除效率低。
- **应用场景**：日程表、温度记录、字符串等"频繁查询、少插入删除"的场景。



## 线性链表（单链表）



- **定义**：用一组**任意的存储单元**存储线性表元素，每个结点包含**数据域**和**指针域**（存放后继结点的地址）。头指针指向第一个结点，最后一个结点的指针域为 NULL。
- **头结点**：可在首元结点前附加一个头结点，使空表与非空表的处理统一，插入/删除首元结点时无需特殊处理；头指针指向头结点。
- **特点**：逻辑相邻物理不一定相邻；不能随机访问，查找需从头遍历 O(n)；插入删除只需修改指针，已知位置时为 O(1)；动态分配内存，无容量限制。
- **基本操作**：建立链表（头插法 / 尾插法）、按值/按序号查找、插入（p->next = q）、删除（p->next = p->next->next）。
- **应用场景**：

  - 邻接表（图的存储）；
  - 多项式相加（按指数链接）；
  - 实现 LRU 缓存（最近最少使用）的简易版本；
  - 频繁在头部插入 / 删除的场景。



## 双向链表



- **定义**：每个结点含**数据域、前驱指针 prior 和后继指针 next**，可双向遍历。
- **优点**：从任一结点出发都能找到前驱；在已知结点 p 之前插入或删除结点的时间复杂度为 O(1)。
- **代价**：每个结点多一个指针域，空间开销更大。
- **应用场景**：浏览器前进/后退、LRU 缓存（配合哈希表）、文本编辑器的光标移动等。



## 循环链表



- **定义**：最后一个结点的指针域指向头结点（或首元结点），使链表首尾相接成环；从任一结点出发都能遍历整张表。
- **循环双链表**：头结点的 prior 指向尾结点，尾结点的 next 指向头结点。
- **优点**：方便从任意位置出发遍历；常设置**尾指针**，可在 O(1) 时间内访问首尾结点并实现"首尾相接"的插入删除。
- **应用场景**：约瑟夫环问题、操作系统进程调度就绪队列、循环播放的音乐列表等。



# 栈和队列



## 栈



- **定义**：栈是限定**仅在表尾进行插入或删除操作**的线性表。表尾端称为**栈顶（top）**，表头端称为**栈底（bottom）**；不含元素的空表称为**空栈**。
- **特点**：遵循**后进先出**（Last In First Out，LIFO）原则，后入栈的元素先出栈。
- **基本操作**：入栈 Push、出栈 Pop、取栈顶 GetTop、判空/判满、求栈长，均为 O(1)。
- **顺序栈**：用数组实现，top 指针指示栈顶位置；注意栈满判断与扩容。
- **链栈**：用单链表实现，栈顶即链表头部，入栈出栈均为 O(1)，无容量限制。
- **应用场景**：

  - 函数调用栈（递归调用、系统栈）；
  - 表达式求值（中缀转后缀、后缀表达式求值）；
  - 括号匹配检测；
  - 数制转换（如十进制转二进制，用栈实现逆序输出）；
  - 撤销操作（undo）、浏览器后退；
  - 迷宫求解等回溯问题。

## 队列



- **定义**：队列是只允许在**一端（队尾 rear）进行插入**、在**另一端（队头 front）进行删除**的线性表。
- **特点**：遵循**先进先出**（First In First Out，FIFO）原则。
- **基本操作**：入队 EnQueue、出队 DeQueue、取队头 GetHead，均为 O(1)。
- **双端队列（deque）**：允许在两端进行插入和删除的队列，是队列的扩展变体。



## 链队列



- **定义**：用链表实现的队列，设置**队头指针 front 和队尾指针 rear**；插入在队尾（rear 后插入），删除在队头（front 处删除）。
- **优点**：无容量限制、动态扩展，适合长度不确定的场景；入队出队均为 O(1)。
- **应用场景**：广度优先搜索（BFS）的辅助队列、消息队列（进程间通信）、任务调度等。



## 循环队列



- **定义**：把顺序队列臆造成**环状结构**，当 rear 到达数组末尾时回绕到数组开头，用数组 + 头尾指针实现。
- **解决的问题**：**假溢出**——普通顺序队列中 rear 已到数组末尾、但 front 之前仍有空闲空间时无法再入队；循环队列通过回绕复用这些空间。
- **关键公式**（设数组容量为 MAXSIZE）：

  - 队空条件：front == rear；
  - 队满条件（牺牲一个存储单元）：(rear + 1) % MAXSIZE == front；
  - 入队：rear = (rear + 1) % MAXSIZE；
  - 出队：front = (front + 1) % MAXSIZE；
  - 队列元素个数：(rear - front + MAXSIZE) % MAXSIZE。
- **应用场景**：打印机任务队列、操作系统缓冲区、CPU 就绪队列、BFS 遍历等。



# 数组



## 数组的顺序表示与实现



- **定义**：数组是**相同类型数据元素**的有限集合，每个元素由**下标**唯一确定；n 维数组可以看成"数据元素的线性表"的推广。
- **顺序存储**：数组通常用连续内存存储，按**行优先**（C 语言）或**列优先**（Fortran）排列。
- **寻址公式**（行优先，m 为列数，L 为每个元素占用的字节数）：LOC(a[i][j]) = LOC(a[0][0]) + (i × m + j) × L
- **特点**：随机访问 O(1)、存储密度高；但插入删除不便、容量固定。
- **应用场景**：矩阵运算、图像像素存储、表格数据等。



## 矩阵的压缩存储



- **压缩存储的目的**：对**特殊矩阵**（对称、三角、对角矩阵）和**稀疏矩阵**，只存储非零/不重复的元素，节省存储空间。
- **对称矩阵**：A[i][j] = A[j][i]，只需存下三角（或上三角）共 n(n+1)/2 个元素，映射到一维数组。
- **三角矩阵**：只存上三角或下三角部分（再加一个常数），空间约 n(n+1)/2。
- **对角矩阵（带状矩阵）**：非零元素集中在主对角线附近，按带状（每行固定若干元素）存储。
- **稀疏矩阵**：非零元素很少（通常不足 5%）：

  - **三元组表**：存储（行号，列号，值）三元组，节省空间，但访问某元素需查找；适合非零元素数量和位置相对稳定的场景；
  - **十字链表**：每行每列各设一个链表，适合运算中非零元素数目和位置变化较大的场景（如矩阵加法和乘法）。



# 树和二叉树



## 树的基本概念



- **定义**：树是 n（n ≥ 0）个结点的有限集合。n = 0 时为空树；非空树满足：有且仅有一个根结点；其余结点可分成 m（m ≥ 0）个互不相交的子树。
- **基本术语**：

  - **度（Degree）**：结点拥有的子树数量；树的度是各结点度的最大值；度为 0 的结点称为**叶子（终端结点）**；
  - **双亲 / 孩子 / 兄弟**、**祖先 / 子孙**、**层次**、**深度（高度）**、**森林**（m 棵互不相交的树的集合）；
  - **重要性质**：树的结点总数 n = 所有结点的度之和 + 1（即 n = 边数 + 1）。
- 注意区分：在**B-树**语境中，结点的子树数与其关键字数 N 满足"**子树数 = N + 1**"（见 8.3）。



## 二叉树



- **定义**：每个结点**最多有两棵子树**的树，且子树有**左右之分，次序不能颠倒**。
- **特殊二叉树**：

  - **满二叉树**：每一层都充满结点，深度为 k 时共有 2ᵏ - 1 个结点；
  - **完全二叉树**：除最后一层外每层都满，最后一层的结点集中在左侧。



### 二叉树的性质



1. 第 i 层上最多有 **2^(i-1)** 个结点（i ≥ 1）；
2. 深度为 k 的二叉树最多有 **2ᵏ - 1** 个结点（k ≥ 1）；
3. 对任何一棵二叉树，**叶子结点数 n₀ = 度为 2 的结点数 n₂ + 1**；
4. 具有 n 个结点的完全二叉树的深度为 **⌊log₂n⌋ + 1**；
5. 完全二叉树按层序编号后：结点 i 的双亲为 **⌊i/2⌋**，左孩子为 **2i**（≤ n），右孩子为 **2i + 1**（≤ n）。



### 二叉树的顺序存储



- 用**数组按层序**存储结点，通过下标（性质 5）天然体现父子关系。
- **适合**：完全二叉树（空间利用率高，父子下标直接计算）。
- **缺点**：普通二叉树需补空结点，可能浪费大量空间。



### 二叉树的链式存储（二叉链表）



- 每个结点含**数据域 data、左孩子指针 lchild、右孩子指针 rchild**。
- n 个结点的二叉树共有 2n 个指针域，其中 **n + 1 个为空指针**（这些空指针可用于线索化）。
- **适合**：一般二叉树，动态扩展，指针灵活表示父子关系。
- 扩展：**三叉链表**在结点中增加双亲指针 parent，便于快速找到双亲。



## 遍历二叉树



- **四种遍历方式**：

  - **先序（前序）遍历**：根 → 左子树 → 右子树；
  - **中序遍历**：左子树 → 根 → 右子树；
  - **后序遍历**：左子树 → 右子树 → 根；
  - **层次遍历**：从上到下、从左到右逐层访问（借助队列实现）。
- 时间复杂度均为 O(n)，空间复杂度（递归栈深度）最坏 O(n)；三种深度遍历都有递归与非递归（显式栈）两种写法。
- **由遍历序列确定二叉树**：**先序 + 中序**或**后序 + 中序**可以唯一确定一棵二叉树；仅凭先序 + 后序不能唯一确定。
- **应用**：表达式树（中序遍历得中缀表达式、后序遍历得后缀表达式）；二叉排序树中序遍历得到递增有序序列；线索二叉树优化遍历。



```c
void PreOrder(BiTree T) {
    if (T != NULL) {
        visit(T);              /* 访问根结点 */
        PreOrder(T->lchild);   /* 遍历左子树 */
        PreOrder(T->rchild);   /* 遍历右子树 */
    }
}
```



## 赫夫曼树



- **概念**：给定 n 个权值作为 n 个叶子结点，构造二叉树使**带权路径长度 WPL 最小**，称为最优二叉树，即**赫夫曼树**。
- **带权路径长度**：WPL = Σ（叶子结点权值 × 该叶子到根的路径长度）。
- **构造算法**：

  1. 将 n 个权值看作 n 棵只有根结点的树；
  2. 每次选取两棵**权值最小**的树合并为一棵新树，新树根的权值为两树权值之和；
  3. 重复上述过程，直到只剩一棵树，即为赫夫曼树。
- **特点**：权值越大的叶子离根越近；n 个叶子结点的赫夫曼树共有 **2n - 1** 个结点，且没有度为 1 的结点；赫夫曼树形态不唯一（左右子树可交换），但 WPL 唯一且最小。
- **赫夫曼编码**：利用赫夫曼树构造**前缀编码**——左分支记 0、右分支记 1，从根到叶子的路径即为编码；出现频率高的字符编码短，从而实现数据压缩；任何字符的编码都不是其他字符编码的前缀。
- **应用**：数据压缩（如 ZIP）、通信编码等。



# 图



## 图的定义与术语



- **定义**：图 G = (V, E)，由**顶点集合 V** 和**边集合 E** 组成；边可带方向（有向图）或不带（无向图）。
- **常用术语**：

  - **有向边（弧）**：&lt;v, w&gt;，v 为弧尾，w 为弧头；**无向边**：(v, w)；
  - **完全图**：无向完全图有 n(n-1)/2 条边，有向完全图有 n(n-1) 条弧；
  - **顶点的度**：无向图中为关联该顶点的边数；有向图中为**入度 + 出度**；
  - **路径、路径长度、简单路径、回路（环）**；
  - **连通图 / 连通分量**（无向图），**强连通图 / 强连通分量**（有向图）；
  - **生成树**：连通图的极小连通子图，含 n 个顶点、n - 1 条边；
  - **网**：带权值的图；**稀疏图 / 稠密图**：按边数相对顶点数的多少划分。
- **握手定理**：无向图所有顶点的度之和 = 2 × 边数。



## 图的存储结构



### 邻接矩阵（顺序存储）



- 用二维数组 A[n][n] 表示顶点间关系：A[i][j] = 1（或权值）表示顶点 i 到 j 有边。
- **优点**：判断两顶点是否有边 O(1)；稠密图空间利用率高；无向图的矩阵对称，可只存上/下三角。
- **缺点**：空间复杂度 O(n²)，稀疏图浪费空间。
- **应用**：判断地图各城市间有无直达航班等稠密图场景。



### 邻接表（链式存储）



- 每个顶点对应一个链表，链表中的结点是该顶点的邻接点；由顶点表 + 边表组成。
- **优点**：空间复杂度 O(n + e)，稀疏图节省空间；遍历某顶点的所有邻接点快。
- **缺点**：判断两顶点是否有边需遍历链表；有向图出度易求、入度需遍历全表（可建立逆邻接表）。
- **应用**：微博关注关系等稀疏图场景。



此外还有**十字链表**（用于有向图，便于求入度和出度）与**邻接多重表**（用于无向图，便于删除边）等存储结构。



## 图的遍历



- **深度优先搜索（DFS）**：类似树的先序遍历，借助递归（系统栈）。从某顶点出发，访问后递归访问其**未访问**的邻接点，一条路走到底再回溯。时间复杂度：邻接表 O(n + e)，邻接矩阵 O(n²)。
- **广度优先搜索（BFS）**：类似树的层次遍历，借助**队列**。先访问起点，再依次访问其所有未访问的邻接点，再访问邻接点的邻接点，逐层扩展。时间复杂度同上。
- **应用**：求连通分量、生成树/生成森林；拓扑排序、无权图最短路径（BFS）、二分图判定（BFS 染色）等。
- 遍历连通图可得到一棵生成树；遍历非连通图得到生成森林。



## 最小生成树



- **概念**：连通网（带权连通图）的生成树中，**各边权值之和最小**的生成树称为最小生成树（n 个顶点、n - 1 条边、连通、无回路）。
- **Prim 算法（加点法）**：从任一顶点开始，每次选择连接"已选顶点集合"与"未选顶点集合"之间的**最小权值边**，把新顶点加入集合，直到所有顶点都被选中。适合**稠密图**，时间复杂度 O(n²)（与边数无关）。
- **Kruskal 算法（加边法）**：按权值**从小到大**依次选择边，只要不构成回路就加入生成树，直到选出 n - 1 条边（用并查集判环）。适合**稀疏图**，时间复杂度 O(e·log e)（e 为边数）。
- **注意**：最小生成树可能不唯一（存在权值相等的边时），但最小总权值唯一。
- **应用**：网络布线、交通网建设的最低成本方案等。



# 查找算法（一）——静态查找表



查找表分为**静态查找表**（只做查找，不修改表）和**动态查找表**（查找的同时可插入、删除）。衡量查找效率的核心指标是**平均查找长度**：ASL = Σ（查找第 i 个元素的概率 × 比较次数），等概率时即所有元素比较次数的平均值。



## 静态查找表之顺序表的查找（顺序查找）



- **思路**：从表的一端开始，将关键字与表中元素逐个比较，直到找到或查完全表。
- **效率**：等概率成功时 ASL = (n + 1) / 2；失败时需比较 n + 1 次；时间复杂度 O(n)。
- **优点**：对表无任何要求（有序无序均可），适用于顺序表和链表；**缺点**：效率低。
- **优化**：设置**哨兵**——把待查关键字放在表头 a[0]，循环中省去越界判断，减少比较次数；非等概率场景可把查找概率高的元素放在前面。



## 静态查找表之有序表的查找（折半查找）



- **思路**：仅适用于**有序的顺序表**（需随机访问）。每次取中间元素与关键字比较，相等即成功；关键字大则查右半，小则查左半，每轮将查找范围缩小一半。
- **算法框架**：low = 0，high = n - 1，mid = (low + high) / 2；比较 a[mid] 与 key 后调整 low 或 high。
- **效率**：等概率成功时 ASL ≈ log₂(n + 1) - 1，时间复杂度 O(log₂n)。
- **判定树**：折半查找过程对应一棵二叉判定树，树高为 ⌊log₂n⌋ + 1，比较次数不超过树高。
- **优点**：效率高；**缺点**：仅适用于有序顺序表，插入删除需移动元素，适合表不常变动的静态场景。
- **变体**：插值查找、斐波那契查找（了解即可）。



```c
int BinarySearch(int a[], int n, int key) {
    int low = 0, high = n - 1;
    while (low <= high) {
        int mid = (low + high) / 2;
        if (a[mid] == key) return mid;        /* 查找成功 */
        else if (a[mid] > key) high = mid - 1;
        else low = mid + 1;
    }
    return -1;                                 /* 查找失败 */
}
```



## 静态查找表之索引顺序表（分块查找）



- **思路**：把表分成若干**块**，块内可以无序、**块间有序**（后一块的所有关键字均大于前一块）；建立**索引表**记录每块的最大关键字和起始位置。查找时先查索引表（顺序或折半）确定所在块，再在块内顺序查找。
- **特点**：是顺序查找与折半查找的折中——查找较快，同时块内无序便于插入删除。
- **效率**：ASL = 索引查找 ASL + 块内查找 ASL；当每块大小取 s ≈ √n 时最优，ASL ≈ √n。
- **适用场景**：既需要较快查找、又需要频繁插入删除的表，如按学号分块的学生成绩档案。



# 查找算法（二）——动态查找表



## 动态查找表之二叉排序树



- **定义**：二叉排序树（BST）满足：左子树上所有结点的关键字 **小于** 根结点，右子树所有结点的关键字 **大于** 根结点，且左右子树也分别是二叉排序树。
- **重要性质**：对二叉排序树进行**中序遍历**，可得到递增有序序列。
- **查找**：从根开始，关键字小则走左子树、大则走右子树，相等即命中。
- **插入**：在查找失败的位置插入新结点（新结点总是作为叶子插入）。
- **删除**分三种情况：

  - 叶子结点：直接删除；
  - 只有一个孩子：用其孩子顶替；
  - 有两个孩子：用**中序前驱（或中序后继）**顶替，再删除该前驱/后继。
- **性能**：最好情况（树较平衡）O(log₂n)；最坏情况退化为单链表（如按有序序列依次插入）O(n)。
- **应用**：动态查找表、符号表等。



## 动态查找表之平衡二叉树（AVL）



- **定义**：平衡二叉树（AVL 树）中任意结点的**左右子树高度差不超过 1**。
- **平衡因子 BF** = 左子树高度 - 右子树高度，取值只能为 -1、0、1。
- **插入后失衡的调整**（四种旋转）：

  - **LL 型（左左）**：对失衡结点做一次**右旋**；
  - **RR 型（右右）**：对失衡结点做一次**左旋**；
  - **LR 型（左右）**：先对左孩子**左旋**，再对失衡结点**右旋**；
  - **RL 型（右左）**：先对右孩子**右旋**，再对失衡结点**左旋**。
- **性能**：树高保持 O(log₂n)，查找、插入、删除最坏情况均为 O(log₂n)。
- **应用**：需要频繁查找且数据动态变化的场景（如 Java 的 TreeMap / TreeSet 底层）。



## 动态查找表之 B-树和 B+ 树

### B-树（多路平衡查找树）

- 一棵 m 阶 B-树满足：每个结点最多有 **m 棵子树、m - 1 个关键字**；所有**叶子结点在同一层**；每个结点内关键字有序。结点的**子树数 = 关键字数 N + 1**。
- **查找**：从根开始，在结点内做顺序/折半查找，未命中则按相应指针进入子树继续。
- **特点**：树矮、路宽，适合**磁盘存储**——每个结点对应一个磁盘块，可显著减少磁盘 I/O 次数。
- **应用**：文件系统、数据库索引。

### B+ 树

- 与 B-树的区别：**全部关键字都出现在叶子结点**，叶子结点包含全部关键字 + 记录指针，并按关键字有序链接成链表；非叶子结点只作索引；查找**必须走到叶子层**。
- **优点**：支持高效**范围查找**（沿叶子链表顺序扫描）；磁盘 I/O 次数稳定。
- **应用**：MySQL InnoDB 主键索引、文件系统目录索引等。

| 对比项 | B-树 | B+ 树 |
|-|-|-|
| 关键字位置 | 所有结点都可存储关键字 | 全部关键字都在叶子结点，非叶子结点只作索引 |
| 叶子结点 | 各叶子相互独立 | 叶子结点含全部关键字 + 记录指针，且链接成有序链表 |
| 查找路径 | 可能在非叶子结点命中即结束 | 必须查找到叶子结点 |
| 范围查找 | 需中序遍历多个结点 | 沿叶子链表顺序扫描即可 |
| 典型应用 | 文件系统、数据库索引 | MySQL InnoDB 主键索引 |

## 动态查找表之哈希表

- **思想**：通过**哈希函数** H(key) 将关键字直接映射到存储地址，理想情况下查找、插入、删除均为 O(1)。本质是"**空间换时间**"。
- **工作流程**：取 Key → 哈希运算 → 存取 Value。
- **常用哈希函数**：

  - **直接定址法**：H(key) = a × key + b；
  - **除留余数法**：H(key) = key mod p（p 通常取不大于表长的质数）；
  - **数字分析法、平方取中法、折叠法**等。
- **冲突及解决**：

  - **冲突**：不同关键字映射到同一存储地址；
  - **开放定址法**：线性探测（+1、+2…）、二次探测（+1、-1、+4、-4…）、再哈希法；
  - **链地址法（拉链法）**：把同义词挂在同一链表上（如 Java HashMap 的做法）。
- **装填因子** α = 表中记录数 / 表长；α 越大冲突越多，通常取 α ≤ 0.7～0.8。
- **性能**：平均查找长度取决于装填因子、哈希函数与冲突处理方法，与元素个数 n 无直接关系；理想情况 O(1)。
- **应用**：字典、缓存（Redis）、编译器符号表、数据库索引（部分）等。

| 查找算法 | 适用结构 | 平均时间 / ASL | 特点 |
|-|-|-|-|
| 顺序查找 | 任意线性表 | O(n)，ASL = (n+1)/2 | 无序也可查，效率低 |
| 折半查找 | 有序顺序表 | O(log₂n) | 需随机访问，表不常变动 |
| 分块查找 | 索引顺序表 | 约 O(√n) | 块间有序、块内无序 |
| 二叉排序树 | BST | O(log₂n)～O(n) | 动态查找，中序有序 |
| 平衡二叉树 | AVL 树 | O(log₂n) | 动态且保持平衡 |
| B-树 / B+ 树 | 多路查找树 | O(log₂n) | 磁盘友好，支持范围查找 |
| 哈希查找 | 散列表 | 平均 O(1) | 空间换时间，需处理冲突 |



# 排序算法（一）——插入、交换与选择排序



排序是把无序序列按关键字有序排列的过程；若关键字相等的元素在排序前后的相对次序不变，则称该排序算法是**稳定的**。数据量小可全部装入内存的排序称为**内部排序**。



## 内部排序之直接插入排序



- **思路**：将第 i 个元素插入到前面已有序的子序列中，类似抓扑克牌时把新牌插入手中已排好的牌。
- **效率**：最好情况（已基本有序）O(n)；平均和最坏情况 O(n²)；空间 O(1)；**稳定**。
- **适用**：数据量小、基本有序的序列。



## 内部排序之冒泡排序



- **思路**：相邻元素两两比较，逆序则交换；每趟排序把当前最大元素"冒"到序列末尾。
- **优化**：若某一趟没有发生任何交换，说明序列已有序，可提前结束。
- **效率**：最好情况 O(n)；平均和最坏情况 O(n²)；空间 O(1)；**稳定**。
- **适用**：数据量小的简单场景。



## 内部排序之快速排序



- **思路**：分治思想。选一个**基准**（通常取首元素），一趟划分把序列分成"小于基准"与"大于基准"两部分，再对两部分递归排序。
- **效率**：平均 O(n·log₂n)；最坏 O(n²)（基准选取不当，如序列本身已有序）；空间 O(log₂n)（递归栈，平均）；**不稳定**。
- **优化**：三数取中、随机选取基准，可有效避免最坏情况。
- **特点**：平均性能最好的内部排序之一，适合数据量大、乱序的数据。

```c
int Partition(int a[], int low, int high) {
    int pivot = a[low];
    while (low < high) {
        while (low < high && a[high] >= pivot) high--;
        a[low] = a[high];
        while (low < high && a[low] <= pivot) low++;
        a[high] = a[low];
    }
    a[low] = pivot;
    return low;        /* 返回基准的最终位置 */
}
```

## 内部排序之简单选择排序

- **思路**：每趟从**未排序部分**中选出最小元素，放到已排序部分的末尾。
- **效率**：任何情况下都是 O(n²)（比较次数固定为 n(n-1)/2）；空间 O(1)；**不稳定**（例如序列 [5, 5', 3]，第一趟交换后 5 与 5' 的相对次序改变）。
- **优点**：移动次数少（最多 n - 1 次移动）；**缺点**：比较次数固定。



# 排序算法（二）——树形选择与归并排序



## 内部排序之树形选择排序



- **思路（锦标赛排序）**：利用**完全二叉树**进行两两比较，胜者（较小元素）逐层上升，根结点即为最小值；选出后把该叶子置为 ∞（或最大值）重新比较，得到次小元素，重复直至全部排好。
- **效率**：比较次数为 O(n·log₂n)，减少了简单选择排序中的重复比较；但需要较多辅助空间存储胜者树/败者树。
- **改进**：**败者树**——比较时记录败者、胜者继续向上，减少与"冠军"重复比较的次数。
- **注意**：胜者树实现的排序不稳定；树形选择排序也是**堆排序**的思想前身（堆排序用数组原地维护该树，空间 O(1)）。



## 内部排序之归并排序

- **思路**：分治 + 合并。将序列递归地分成两半，分别排序后再把两个有序子序列**合并**成一个有序序列（2-路归并）。
- **合并过程**：双指针比较两个子序列，需借助**辅助数组**。
- **效率**：任何情况下均为 O(n·log₂n)；空间 O(n)（辅助数组）；**稳定**。
- **适用**：需要稳定排序的场景；链表排序；**外部排序**——数据量大到内存放不下时，先分块在内存排序后写回外存，再多路归并（外部排序的基础）。

## 附录：排序算法复杂度对比表

| 排序算法 | 最好时间 | 平均时间 | 最坏时间 | 空间 | 稳定性 |
|-|-|-|-|-|-|
| 直接插入排序 | O(n) | O(n²) | O(n²) | O(1) | 稳定 |
| 冒泡排序 | O(n) | O(n²) | O(n²) | O(1) | 稳定 |
| 快速排序 | O(n·log₂n) | O(n·log₂n) | O(n²) | O(log₂n) | 不稳定 |
| 简单选择排序 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 |
| 树形选择排序 | O(n·log₂n) | O(n·log₂n) | O(n·log₂n) | O(n) | 不稳定 |
| 归并排序 | O(n·log₂n) | O(n·log₂n) | O(n·log₂n) | O(n) | 稳定 |
| 堆排序（补充） | O(n·log₂n) | O(n·log₂n) | O(n·log₂n) | O(1) | 不稳定 |

记忆要点：**稳定的排序**有直接插入、冒泡、归并；**平均时间 O(n·log₂n)** 的有快速、归并、堆、树形选择；**不稳定的**有快速、简单选择、堆、树形选择。
