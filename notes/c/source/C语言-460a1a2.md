# 基础知识

## C语言简介

What：C语言是一种**通用的过程式的**，**兼具高级语言的易读性**和**低级语言操控能力**的，**编译型**编程语言。还具有**可移植性好**，**运行效率高**，**资源占用少**的特点**。**

Why：学习C语言会直面**内存模型**，**指针**，**栈与堆**，**系统调用**，能够真正理解**操作系统**，**编译器**，**网络协议栈**等底层软件的工具原理。在**操作系统内核**，**嵌入式系统**，**高性能服务器**，**数据库引擎**，**语言与编译器**，**安全与逆向**等领域具有不可替代的作用。

Who：**系统/内核开发者**，**嵌入式工程师**，**后端与基础设施工程师**，**游戏引擎与图形工程师**，**高性能计算工程师**

How：**开发工具链**，**环境搭建**，**核心语言要素**（基础语法，函数，数组与字符串，指针，动态内存，结构体与联合体，文件I/O，预处理器，高级话题），**性能调优**，**安全编程**。

## 程序的定义

What：C 语言程序是由**一个或多个函数**和**外部变量**组成的、符合 **C 语言语法**和**语义**的**源文件集合**，经过**编译**、**链接**后，生成在**特定操作系统上可直接或间接执行的目标代码实体**。

## gcc编译器

**源文件 .c**

  ├─ **预处理 (cpp)** → 展开 #include, #define, 条件编译

  ├─ **编译 (cc1)** → 生成汇编代码 .s

  ├─ **汇编 (as)** → 生成目标文件 .o （可重定位机器码 + 符号表）

  ├─ **链接 (ld**) → 把多个 .o + 库文件解析符号、重定位，生成可执行文件

## 单个文件的基础框架和完整框架

基础框架：

- **`#include`**：引入标准库头文件。
- **`main` 函数**：程序的入口，操作系统执行时最先调用的函数。
- **`return 0`**`;`：向操作系统返回退出状态，0 表示成功。

完整框架：

- **文件头注释**（作者、版本、描述）
- **必要的头文件包含**
- **常量和宏定义**
- **自定义类型**（`typedef struct`）
- **全局变量限制作用域**（`static`）
- **函数声明与定义分离**
- **`main` 函数参数处理**（`argc`, `argv`）
- **防御性编程**（`NULL` 检查、字符串长度限制）
- **错误处理**（返回错误码或 NULL）
- **资源清理**（`free`）
- **条件调试输出**
- **使用 `const` 保证参数只读**

# 基本数据类型

定义：基本数据类型是 C 语言中由语言本身预先定义、不可再拆分的数据类型，是构成所有复合数据类型的原子单元。

分类：

- **整数类型**：`char`、`short`、`int`、`long`、`long long`（C99 起），分别用 `signed`/`unsigned` 修饰有符号与无符号版本
- **浮点类型**：`float`（单精度）、`double`（双精度）、`long double`（扩展精度）
- **布尔类型**：`_Bool`（C99 引入），包含 `<stdbool.h>` 后可用 `bool`/`true`/`false`
- **空类型**：`void`，表示无返回值、无参数或指向未知类型的指针

常见尺寸与范围（64 位 Linux 环境，具体以 `sizeof` 为准）：

- `char`：1 字节，范围 -128 到 127（无符号 0 到 255）
- `short`：2 字节，-32768 到 32767
- `int`：4 字节，-2147483648 到 2147483647
- `long`：8 字节，-2^63 到 2^63-1
- `float`：4 字节，约 6 到 7 位有效数字
- `double`：8 字节，约 15 到 16 位有效数字

注意事项：

- **类型大小依赖平台**：`int` 在 16 位平台为 2 字节，跨平台开发应使用 `<stdint.h>` 中的定宽类型（`int32_t`、`uint8_t` 等）
- **溢出**：整型运算超出范围时发生回绕（无符号）或未定义行为（有符号），浮点运算产生 INF/NaN
- **隐式类型转换**：赋值、运算时不同类型自动转换，遵循"小类型向大类型、有符号向无符号"的规则，可能丢失精度
- **显式类型转换**：使用强制类型转换运算符 `(type)expr`，程序员必须自己保证安全
- **`sizeof`**：运算符而非函数，编译期求值，用于获取类型或变量的字节大小，如 `sizeof(int)`、`sizeof x`



# 变量

定义：变量是**在内存中开辟的一块命名的存储空间**，用于保存程序运行过程中可以改变的数据，具有类型、名字、存储位置和值四个要素。

声明与定义：

- **声明**：告诉编译器变量的名字和类型，不分配内存，如 `extern int x;`
- **定义**：分配内存并（可）初始化，如 `int x = 10;`
- 一个变量只能定义一次，但可以声明多次

命名规则：

- 由字母、数字、下划线组成，**不能以数字开头**
- 不能与关键字（`int`、`if`、`return` 等）重名
- 大小写敏感：`count` 与 `Count` 是两个不同变量
- 建议使用有意义的名字，如 `student_count` 而非 `sc`

初始化：

- **未初始化陷阱**：局部变量未初始化时值是**不确定的垃圾值**，使用前必须赋值
- 全局变量和静态变量未初始化时自动置为 0
- 初始化方式：`int a = 0;`、`int b; b = 5;`、`int arr[3] = {1, 2, 3};`

作用域与生命周期：

- **局部变量**：定义在函数或代码块内，作用域为所在块，生命周期为块执行期间，默认存储在栈上
- **全局变量**：定义在函数外，从定义处到文件结束均可见，生命周期贯穿整个程序
- **静态变量**（`static`）：局部静态变量延长生命周期至程序结束，但作用域不变；全局静态变量限制为仅本文件可见
- **外部变量**（`extern`）：跨文件使用全局变量时声明

注意事项：

- 变量必须先声明（定义）后使用
- 避免与全局变量同名造成遮蔽（shadowing）
- 循环体内频繁使用的变量可在块内定义，避免不必要的大作用域
- 使用 `const` 修饰不被修改的变量，提高可读性与安全性

# 常量

定义：常量是**程序运行过程中值不能被改变的量**，包括字面常量与符号常量两类。

字面常量：

- **整型常量**：十进制 `123`、八进制 `0173`（前缀 0）、十六进制 `0x7B`（前缀 0x），后缀 `L` 表示 long、`U` 表示 unsigned
- **浮点常量**：`3.14`、`1.5e-3`（科学计数法），后缀 `f` 表示 float、`l` 表示 long double
- **字符常量**：单引号括起的单个字符，如 `'A'`，值为字符的 ASCII 码；转义字符如 `'\n'`、`'\t'`、`'\\'`
- **字符串常量**：双引号括起的字符序列，如 `"Hello"`，末尾自动追加 `'\0'`，类型为 `char[]`
- **枚举常量**：枚举中定义的具名整数值

符号常量：

- **宏定义**：`#define PI 3.14159`，预处理阶段直接文本替换，无类型检查，不占内存
- **const 限定**：`const double PI = 3.14159;`，编译期类型检查，占用内存，可以通过指针间接修改（需要类型转换）

转义字符表（部分）：

- `\n` 换行、`\t` 水平制表、`\r` 回车、`\0` 空字符、`\\` 反斜杠、`\'` 单引号、`\"` 双引号、`\a` 响铃、`\xhh` 十六进制字符

注意事项：

- `#define` 宏名通常全大写，与变量区分；宏替换是文本级的，注意括号，如 `#define SQUARE(x) ((x)*(x))`
- 字符串常量末尾的 `'\0'` 占一个字节，定义字符数组时要留足空间
- 字符 `'A'` 与字符串 `"A"` 不同：前者是 1 字节整数 65，后者是 2 字节（`'A'` 和 `'\0'`）
- 优先使用 `const` 而非 `#define` 定义真正的常量（类型安全、可调试）

# 存储类型

定义：存储类型（存储类别说明符）用于**控制变量的存储位置、作用域和生命周期**，C 语言共提供 `auto`、`register`、`static`、`extern`、`typedef` 五种存储类别说明符。

各类说明符详解：

- **auto**：默认的存储类别，修饰局部变量，变量存储在栈上，进入块时创建、离开块时销毁。由于是默认行为，写 `auto` 几乎没有意义
- **register**：建议编译器将变量放入寄存器以加快访问。现代编译器已能自动优化，`register` 仅作提示；变量**不能取地址**（不在内存中）；C11 起 `register` 语义弱化
- **static**：

  - 修饰局部变量：生命周期延长至程序结束（存储于静态存储区），但作用域仍限于所在函数/块，多次调用间保留值
  - 修饰全局变量/函数：限制为**仅本文件可见**（内部链接），防止与其他文件的同名符号冲突
- **extern**：声明变量/函数已在其他文件中定义，用于跨文件引用，**不分配内存**
- **typedef**：为已有类型起别名，如 `typedef unsigned int uint32_t;`，属于类型定义而非变量存储类别（语法上归类于此）

存储期分类：

- **自动存储期**：普通局部变量，栈上，块结束即销毁
- **静态存储期**：全局变量、static 局部变量、static 全局变量，程序开始分配、程序结束释放，未初始化自动置 0
- **动态存储期**：`malloc`/`calloc`/`realloc` 分配、`free` 释放，由程序员控制
- **线程存储期**：`_Thread_local`（C11），每个线程独立副本

注意事项：

- 局部变量默认 auto；`static` 局部变量若未初始化自动为 0，且只初始化一次
- 不要过度使用 static 局部变量保存状态，会让函数变得不可重入
- 头文件中一般只放 `extern` 声明，全局变量的定义放在唯一一个 .c 文件中，避免重复定义链接错误

# 数据的输入输出

定义：C 语言本身**没有输入/输出语句**，I/O 全部通过标准库函数实现。最常用的是控制台函数 `printf`/`scanf` 和字符函数 `getchar`/`putchar`。

printf 格式化输出：

- 语法：`printf("格式控制字符串", 输出列表);`
- 常用格式符：

  - `%d` 十进制整数、`%u` 无符号整数、`%ld` long、`%lld` long long
  - `%x` 十六进制、`%o` 八进制、`%c` 字符、`%s` 字符串
  - `%f` float/double、`%e` 科学计数法、`%g` 自动选择、`%p` 指针地址
  - `%%` 输出百分号
- 宽度与精度：`%5d` 宽度至少 5、`%-5d` 左对齐、`%05d` 补零、`%.2f` 保留两位小数、`%8.2f` 宽度 8 保留 2 位
- 转义字符：`\n` 换行、`\t` 制表

scanf 格式化输入：

- 语法：`scanf("格式控制字符串", &变量1, &变量2, ...);`
- **必须传地址**：除数组名（本身是地址）外，其他变量必须加 `&`
- 常用格式符：`%d`、`%f`、`%lf`（double 必须用 %lf）、`%c`、`%s`、`%x`
- `%s` 读到空白（空格/换行）为止，不能输入含空格的字符串；`%c` 会读取包括空白在内的任意字符
- 返回值：成功匹配并赋值的项数，可用于错误检查

字符输入输出：

- `getchar()`：从标准输入读一个字符，返回其 ASCII 码或 EOF
- `putchar(c)`：输出一个字符
- `gets`/`puts`：整行读写（`gets` 无边界检查，已被 `fgets` 取代，不安全）

缓冲区与安全：

- 标准输入输出默认行缓冲，输入以回车刷新
- `scanf("%d", &n)` 后换行符残留在缓冲区，紧接 `getchar()` 会读到残留换行，需用 `getchar()` 清空或用 `" %c"` 跳过空白
- **安全建议**：使用 `fgets(buf, sizeof buf, stdin)` 读取字符串防止缓冲区溢出；scanf 使用 `%Ns` 限定宽度（如 `%31s`）
- 检查 `scanf` 返回值与 EOF，正确处理输入失败

# 运算符和表达式

定义：运算符是**告诉编译器执行特定运算的符号**，由运算符和操作数组成的合法序列称为**表达式**，表达式求值产生一个结果。

运算符分类：

- **算术运算符**：`+`、`-`、`*`、`/`、`%`（取余，仅整数）。注意整数除法向下取整（C99 起向零截断），`5 / 2 = 2`；浮点除法 `5.0 / 2 = 2.5`；`%` 的操作数不能为 0
- **关系运算符**：`>`、`>=`、`<`、`<=`、`==`、`!=`，结果为 1（真）或 0（假）
- **逻辑运算符**：`&&`（与）、`||`（或）、`!`（非），**短路求值**：`a && b` 中 a 为假则不计算 b；`a || b` 中 a 为真则不计算 b
- **位运算符**：`&`（按位与）、`|`（按位或）、`^`（异或）、`~`（取反）、`<<`（左移，低位补 0）、`>>`（右移，无符号补 0，有符号通常算术右移补符号位）
- **赋值运算符**：`=` 及复合赋值 `+=`、`-=`、`*=`、`/=`、`%=`、`<<=`、`>>=`、`&=`、`|=`、`^=`
- **条件运算符（三目）**：`条件 ? 表达式1 : 表达式2`，唯一的三元运算符
- **逗号运算符**：`expr1, expr2`，从左到右求值，整个表达式取最后一个值
- **其他运算符**：`sizeof`（字节大小）、`&`（取地址）、`*`（解引用）、`->`（结构体指针访问）、`.`（结构体成员访问）、`[]`（下标）、`()`（函数调用/强制转换）

优先级与结合性（高到低，常用部分）：

- `()[]->.`（最高）
- `!~++--+`（一元正）`-`（一元负）`*`（解引用）`&`（取地址）`(类型)`（强转）`sizeof`
- `*/%`
- `+-`
- `<<>>`
- `<<=>>=`
- `==!=`
- `&`
- `^`
- `|`
- `&&`
- `||`
- `?:`（右结合）
- `=` 及复合赋值（右结合）
- `,`（最低）

注意事项：

- **优先级易错**：`*p++` 等价于 `*(p++)`；`a < b == c` 等价于 `(a < b) == c`；复杂表达式多用括号明确
- **副作用与序列点**：`i = i++ + 1` 这类在同一表达式中多次修改同一变量是**未定义行为**；`&&`、`||`、`,`、`?:` 以及完整表达式结束处是序列点
- **比较浮点数**：不要直接用 `==` 比较浮点数，应判断差值小于某个极小量
- 位运算只对整数使用；左移/右移位数不能大于类型位宽
- 逻辑运算结果恒为 0/1，位运算结果不是

# 程序结构和控制语句

定义：程序的执行流程由**顺序、选择、循环**三种基本结构组成，C 语言通过各类控制语句实现这三种结构。任何复杂的程序都可以由这三种结构组合而成。

三种基本结构：

- **顺序结构**：语句按书写顺序依次执行，是程序默认的执行方式
- **选择结构**：根据条件判断选择执行分支，对应 `if/else`、`switch/case`
- **循环结构**：条件满足时重复执行某段代码，对应 `while`、`do-while`、`for`

选择语句：

- `if` 语句：

  - `if (条件) 语句;`
  - `if (条件) 语句1; else 语句2;`
  - `if / else if / else` 多分支：`if (a) {...} else if (b) {...} else {...}`
  - 条件为 0 视为假，非 0 视为真；`else` 与最近的 `if` 配对（小心悬空 else）
- `switch` 语句：

  - `switch (整型表达式) { case 常量: ... break; default: ... }`
  - 表达式必须是整型或枚举；每个分支结束时通常要 `break`，否则会**贯穿（fallthrough）**到下一个分支
  - `default` 处理所有未匹配情况，可放在任意位置

循环语句：

- `while (条件) 语句;`：先判断后执行，条件为假时循环体一次都不执行
- `do { 语句; } while (条件);`：先执行后判断，循环体**至少执行一次**
- `for (初始化; 条件; 更新) 语句;`：三部分都可省略（省略条件为死循环），常用于已知次数的循环
- 循环变量更新要在循环体内或 for 的更新部分完成，否则死循环

跳转语句：

- `break`：跳出**最近一层** switch 或循环
- `continue`：跳过本次循环剩余语句，进入下一次迭代
- `return`：从函数返回，可携带返回值
- `goto`：无条件跳转，仅在跳出多层循环等场景谨慎使用

注意事项：

- 判断相等用 `==`，误写为 `=` 是常见错误（`if (x = 5)` 恒真且改变 x 的值）；可用 `if (5 == x)` 反向书写防御
- 循环内小心**边界条件**（差一错误），例如 `for (i = 0; i <= n; i++)` 会执行 n+1 次
- `switch` 的 case 后忘记 `break` 会导致逻辑错误
- 浮点数作循环条件可能因精度产生意外行为，尽量用整数计数
- 死循环不一定全是错误：服务器主循环、事件监听常用 `while (1)`

#  数组

定义：数组是**相同类型元素的有限有序集合**，所有元素在内存中**连续存放**，通过下标访问，数组名是首元素的地址（常量，不可赋值）。

一维数组：

- 定义：`类型 数组名[元素个数];`，如 `int scores[5];`
- 初始化：

  - 全部初始化：`int a[5] = {1, 2, 3, 4, 5};`
  - 部分初始化：`int a[5] = {1, 2};` 其余元素自动补 0
  - 省略长度：`int a[] = {1, 2, 3};` 长度由初始化列表决定
  - 全部置 0：`int a[5] = {0};`
- 访问：`a[0]` 到 `a[4]`，**下标从 0 开始**，`a[i]` 等价于 `*(a + i)`
- 数组名是常量地址，不能整体赋值、不能自增自减

二维数组：

- 定义：`类型 数组名[行数][列数];`，如 `int matrix[3][4];`
- 初始化：`int m[2][3] = {{1,2,3},{4,5,6}};` 或 `int m[2][3] = {1,2,3,4,5,6};`
- 内存中按**行优先**连续存放；省略第一维长度时 `int m[][3]` 合法（必须能确定行宽）

字符数组与字符串：

- 字符数组：`char s[6] = {'H','e','l','l','o','\0'};`
- 字符串字面量初始化：`char s[] = "Hello";` 自动在末尾加 `'\0'`，长度至少为字符数 + 1
- 字符串函数（`<string.h>`）：`strlen`（长度，不含 `'\0'`）、`strcpy`/`strncpy`、`strcat`/`strncat`、`strcmp`/`strncmp`、`strchr`、`strstr`

数组与指针的关系：

- 数组名退化为指向首元素的指针（除 `sizeof` 和 `&` 操作时）
- 指针可以指向数组元素并遍历：`int *p = a;` 后 `p[i]`、`*(p+i)` 与 `a[i]` 等价
- 函数形参 `int a[]` 实际是 `int *a`

注意事项：

- **越界访问**是未定义行为，C 不做边界检查，可能破坏相邻内存导致难以排查的 bug
- 数组大小必须是编译期常量（C99 支持变长数组 VLA，但不建议滥用）
- `strcpy`/`strcat` 不检查目标容量，应改用带长度限制的 `strncpy`/`strncat` 或自己控制边界
- 函数间传递数组实际传递的是指针，函数内 `sizeof(形参数组)` 得到的是指针大小，需同时传长度参数

# 聚合数据类型

## 结构体

- 定义：结构体是一种**聚合数据类型**，**可以将不同类型的多个数据成员组合成一个逻辑单元**。**每个成员占用独立的内存空间**（按顺序存储，可能含填充对齐），**可同时存多个值**。
- 作用：**组织相关数据**，**方便传递/返回**，**构建复杂数据结构**，**模拟面向对象**。
- **基本结构体定义**：定义结构体类型 + 同时声明变量（有标签）
- **同时定义和声明**：定义匿名结构体 + 同时声明变量（无标签，仅此一次）
- **结构体类型别名**：先用 typedef 定义类型别名，再单独声明变量（最常用）
- **嵌套结构体**：结构体可以包含其他结构体作为其成员
- **结构体数组**：可以定义结构体类型的数组,以存储多个相同类型的结构体
- **结构体指针**：可以使用指针来指向结构体,常用于动态内存分配和传递结构体给函数。
- **匿名结构体**：可以定义没有名称的结构体,并在定义变量时直接使用

## 联合体

- 定义：联合体是一种**特殊的数据类型**，**它允许多个成员共享同一块内存空间**。**后赋值的成员覆盖前面。**
- 作用：**节省空间**，**数据类型转换（类型双关）**，**协议解析**，**实现变体记录（带标签的联合体），变长数据处理（联合体+指针+长度），联合体和枚举的结合使用，硬件寄存器访问（联合体+位域结构体）**

## **位域**

- 定义：位域是**结构体（或联合体）中的一种特殊的成员**，它允许以**比特位**为单位指定成员占用的内存宽度，而不是按字节对齐。
- 作用：**节省内存**，**硬件寄存器映射**，**协议/文件格式解析**，**提高可读性，高效位操作**
- 注意事项：
- **不能取地址**，**位宽不能超过基础类型**，**可移植性差**（位域在内存中的排列顺序是编译器定义的）
- 在结构体中位域成员和非位域成员**可以混合使用**，但需要注意它们的**存储方式和对齐**
- **混合定义**：位域与非位域成员在结构体中混合使用时，非位域成员会按正常对齐方式存储，而位域成员会根据宿主类型的规则进行存储。
- **对齐与填充：**非位域成员通常会在位域之前或之后引入额外的填充,以确保对齐。这可能导致结构体的整体内存布局变得复杂并增加额外的内存开销。因此，混合使用位域和非位域成员时,应注意对齐带来的潜在浪费。

## 枚举

- 定义：枚举是 C 语言中定义整数常量集合的用户自定义类型，用于给一组相关的整数值赋予有意义的名字。
- 作用：**提高可读性**，**降低耦合**，**编译期检查**，**简化调试**，**命名空间隔离**

# 函数

## 函数

- 定义：函数是一段封装好的代码，有输入(参数)，输出(返回值)以及函数名。
- 作用:避免重复代码，模块化与可读性，便于调试与维护，复用与协作
- 用途:主函数入口，常用操作封装，回调函数。递归场景，接口设计
- 头文件与函数的关系:主要体现在函数声明上，头文件通常包含了函数的声明。而这些声明会在源文件中被包含(通过#include)。使得其他文件可以调用这些函数，头文件中只包含函数的声明。而函数的定义通常在点c文件中

函数的基本结构:

- 函数声明:告诉编译器函数的存在及其返回类型和参数类型。通常写在main()函数之前或者头文件中。
- 函数定义:包含函数的具体实现，定义了函数的行为。
- 函数调用:在main()函数或其他函数中，通过函数名调用函数并传递参数。

函数的参数:

- 形参:形参是函数定义中声明的参数，它是函数接收数据的占位符，用于描述函数在执行时将会使用的变量。形参是在函数的定义部分给出的，代表函数调用时将传入的值，但本身在函数定义时没有具体的值。
- 特点:形参在函数内部起作用，函数调用时实参的值被复制到形参中。形参是局部变量，仅在函数的执行过程中有效，函数结束后形参就被销毁。
- 实参:实参是函数调用时传递给形参的实际值或变量。实参为函数执行提供了具体的输入。当调用函数时，实参的值会被复制，给形参函数执行时使用这些值。
- 特点:实参可以是常量，变量，表达式等。实参可以在函数外部定义，并且在函数调用后，它们的值不会被形参的操作改变(除非通过指针或引用的方式传递)
- 形参和实参的关系:在函数调用过程中，实参的值被按值传递给形参，这意味着实参的值被复制到形参中，函数内的任何操作都不会影响到实参本身。换句话说形参的变化不影响实参，除非使用指针或特殊方式传递。
- 指针与引用传递的例外:虽然c语言默认的是按值传递，但通过指针可以修改实参的值。使用指针作为形参时，可以让函数修改实参的值。
- 错误情况:函数未声明或声明不一致，返回类型错误或没有匹配的return语句，函数参数不匹配，返回局部变量的地址。

注意事项:

- 返回值:除void函数外，必须用return返回值类型需声明一致。
- 参数传递:C是值传递，修改形参不影响实参，想修改实参需传递指针。
- 作用域:函数内定义的变量仅局部有效，跨文件使用时需用extern声明。
- 递归必须有终止条件，否则导致栈溢出。
- 函数不可嵌套定义(不能在函数内定义另一个函数)，但可以声明或调用。



## 多文件编译

定义:将程序按功能拆分到多个 .c / .cpp 源文件和 .h 头文件中，分别编译成目标文件（.o / .obj），最后链接成一个可执行文件的过程。

作用:缩短编译时间，模块化与可维护性，复用。

用途:中大型项目，库开发，任何需要拆分代码规模，分模块测试的场景。

核心规则:

头文件放声明，源文件放定义

用#ifndef或#pragma once防止头文件重复包含。

全局变量跨文件，声明仅在一个.c中定义。

## 递归函数

定义：递归函数是**在函数体内直接或间接调用自身**的函数。递归是一种分治思想：把一个大问题分解为规模更小、结构相同的子问题，直到遇到可以直接求解的边界情况。

递归的两个要素：

- **递归出口（基线条件）：最小规模问题的直接解，不再递归调用自身。没有递归出口会无限递归，最终栈溢出崩溃**
- **递归步骤（递推关系）**：将问题规模缩小并调用自身，逐步逼近递归出口

经典示例：

- 阶乘：`n! = n * (n-1)!`，出口为 `0! = 1`
- 斐波那契：`fib(n) = fib(n-1) + fib(n-2)`，出口为 `fib(0)=0, fib(1)=1`
- 汉诺塔：将 n 个盘子从 A 借助 B 移到 C，分解为三步
- 树/链表的遍历：深度优先遍历天然适合递归
- 快速排序、归并排序等分治算法

递归的执行过程：

- 每次调用都会在**栈上压入新的栈帧**（局部变量、参数、返回地址）
- 递归深度受栈空间限制（通常几 MB），过深会栈溢出（Stack Overflow）
- 递归函数执行分为"递"（深入调用）与"归"（逐层返回）两个阶段

递归与迭代的比较：

- **递归**：代码简洁、逻辑清晰，适合树形/分治结构；但开销大（每次调用有函数调用开销）、深度受限
- **迭代**：用循环实现，效率高、无栈开销；但某些问题（如树遍历）代码复杂
- 能迭代就不递归（性能敏感场景）；递归深度大时改用迭代或尾递归优化

注意事项：

- 必须确保每次递归都**改变参数并逼近出口**，否则死循环
- 斐波那契这类重复计算问题，朴素递归指数级复杂度，应使用记忆化（缓存结果）或改为迭代
- 尾递归：递归调用是函数最后一步操作时称为尾递归，部分编译器可优化为循环（不增长栈）
- 递归函数中避免使用静态变量保存状态，否则不可重入
- 大型递归使用前评估最大深度，防止栈溢出

## goto语句

定义：`goto` 是 C 语言中的**无条件跳转语句**，程序执行到 `goto` 时直接跳到指定的**标签（label）**处继续执行。

语法：

- 定义标签：`标签名: 语句;`（标签名遵循标识符规则）
- 跳转：`goto 标签名;`
- 例：

```c
loop:
    printf("hello\n");
    count--;
    if (count > 0)
        goto loop;
```

作用：

- **跳出多层循环**：`break` 只能跳出最近一层，用 `goto` 可以直接跳出嵌套的多层循环
- **统一错误处理**：多个失败路径集中跳转到函数末尾的清理代码（释放资源、返回错误码），这是内核代码中的常见模式
- **状态机跳转**：某些解析器/状态机实现中直接跳转到对应处理状态

注意事项：

- **可读性差**：滥用 goto 会使程序流程混乱、难以阅读和维护，Dijkstra 曾提出"goto 有害论"（结构化编程思想）
- **不能跳进另一个函数**，不能跳过变长数组的定义
- 不要跳过一个已初始化变量所在的作用域进入其内部（绕过初始化）
- **使用原则**：只向前跳转、只用于错误处理和跳出多层循环，且跳转距离越短越好
- 现代 C 中，多层循环可用 `return`（封装为函数）或标志变量替代 goto，多数情况下应优先使用结构化语句
- 代码审查中 goto 需要明确注释说明跳转目的

总结：goto 不是不能用，而是**必须克制地用于特定模式**（统一退出、深度跳出），绝大多数场景应使用 if/while/for/break/return 等结构化控制语句。

# 指针

## 指针的概念与运算：

定义:指针是一个**变量**，它存储另一个变量的**内存地址**。变量存储在内存中，每个**变量占据一定的内存空间**，并有**唯一的地址**。

声明语法：类型 \*指针名;，如 int \*p; **表示 p 能存放 int 变量的地址**。  
两个关键运算符：&（取地址符）：取得变量的地址。     \*（解引用符）：通过指针访问指向的变量。

作用:**函数内部修改外部变量**，**动态内存管理**，**高效传递大块数据**，**实现数据结构**，**访问硬件/特殊地址**。

指针的算术运算:

- 指针加法:当对指针进行加法运算时，指针会移动到它所指向类型的下一个元素位置。加法运算的步长取决于指针所指向的数据类型的大小。
- 指针减法:指针减法会将指针向数组的前一个元素移动。
- 指针相减:如果两个指针指向同一个数组中的元素，则它们的差值表示两个元素之间的距离。以元素为单位，而不是字节为单位。
- 指针与整数相加减:指针加上一个整数时，会将指针移动若干个元素的位置。与加法相似，指针减去一个整数时，会将指针移动到前面的元素。
- 指针的比较运算:指针可以进行比较运算，用来判断两个指针是否指向相同位置或不同位置。

## 指针常量与常量指针

定义：**常量指针（pointer to const）是"指向常量的指针"，指针指向的内容不能被修改；指针常量**（const pointer）是"指针本身是常量"，指针保存的地址不能被修改。二者修饰的对象不同，极易混淆。

区分方法与记忆技巧：

- `const int *p;` / `int const *p;`：**常量指针**。`const` 在 `*` 左侧，修饰指针指向的**内容**。`*p = 10;` 非法，`p = &y;` 合法
- `int *const p;`：**指针常量**。`const` 在 `*` 右侧，修饰指针**本身**。`p = &y;` 非法，`*p = 10;` 合法
- 记忆口诀：**const 在 `*` 左边，修饰的是"内容"；const 在 `*` 右边，修饰的是"指针"**；"左值右指"

组合形式：

- `const int *const p;`：指针和指向的内容都不可修改
- 判别方法：从右向左读——`p` 是一个 `const` 修饰的 `int *`（指针常量），或 `p` 指向 `const int`（常量指针）

典型应用：

- 函数形参用常量指针保证**只读不写**：`void show(const char *s);`，既能防止函数内误改数据，又能接收字符串字面量
- 全局只读数据表：`const struct config *get_config(void);`
- 嵌入式寄存器只读映射、查找表等

注意事项：

- 常量指针可以指向非常量变量，只是不能通过该指针修改它
- 把非常量指针赋给常量指针是合法的（收窄权限）；反向把常量指针赋给非常量指针是**非法/警告**（放开权限），需要强制类型转换并自行负责
- 常量指针指向的内容依然可以被其他非常量指针修改，`const` 只是编译器层面的约束
- `const` 修饰的变量最好在定义时初始化，因为之后不能直接赋值



## 指针数组与数组指针

定义：**指针数组是"数组元素为指针"的数组；数组指针**是"指向数组"的指针。两者声明的 `*` 和 `[]` 结合顺序不同，含义完全不同。

声明语法与区分：

- 指针数组：`int *arr[5];`——`[]` 优先级高于 `*`，所以 `arr` 先与 `[5]` 结合成数组，元素类型是 `int *`，即 5 个指向 int 的指针
- 数组指针：`int (*p)[5];`——括号使 `p` 先与 `*` 结合成指针，指向的类型是 `int[5]`，即指向含 5 个 int 元素的数组
- 记忆：**先看标识符与谁结合**——与 `[]` 结合是数组（指针数组），与 `*` 结合是指针（数组指针）

指针数组的典型应用：

- 字符串数组：`char *names[] = {"Alice", "Bob", "Cindy"};`——每个元素指向一个字符串，比二维字符数组省内存
- 命令行参数：`int main(int argc, char *argv[])`，`argv` 即指针数组
- 指针表驱动：函数指针数组、错误信息表等

数组指针的典型应用：

- 指向二维数组的某一行：`int a[3][4]; int (*p)[4] = a;`，`p` 指向含 4 个 int 的数组（一行），`p + i` 跳到第 i 行
- 函数形参接收二维数组：`void show(int (*m)[4], int rows);`（等价于 `int m[][4]`）
- 与动态分配结合：`int (*p)[5] = malloc(10 * sizeof(int[5]));` 构造二维数组

区别要点：

- `sizeof(arr)` 在指针数组中是整个数组的大小；数组指针本身是指针，大小固定（8 字节）
- `arr[i]` 得到指针，`p[i]` 得到数组（退化为首元素指针）
- 使用前明确意图，必要时用 typedef 简化：`typedef int Row[4]; Row *p;`

注意事项：

- 指针数组中的指针必须指向有效内存（或 NULL），否则解引用是野指针
- 数组指针加减以"所指数组大小"为步长，`p+1` 跨过一整行
- 声明优先级复杂时加括号并做注释，避免歧义

## 指针函数与函数指针

定义：**指针函数是"返回值为指针的函数"；函数指针**是"指向函数的指针"。前者是函数，后者是指针，二者名字相近、本质不同。

声明语法与区分：

- 指针函数：`int *func(int a);`——`func` 是函数，返回 `int *`（指向 int 的指针）
- 函数指针：`int (*fp)(int a);`——`fp` 是指针，指向一个"参数为 int、返回 int"的函数
- 记忆：**函数名先与 `()` 结合是函数（指针函数）；先与 `*` 结合是指针（函数指针）**

函数指针的用法：

- 赋值：`fp = &func;` 或简写 `fp = func;`（函数名即地址）
- 调用：`(*fp)(10);` 或简写 `fp(10);`
- 声明参数完全匹配：返回类型、参数个数与类型必须一致，否则未定义行为
- 函数指针数组：`int (*handlers[4])(int);` 可用于表驱动（如命令分发）
- 常用 typedef 简化：`typedef int (*Handler)(int); Handler h = func;`

应用场景：

- **回调函数**：函数指针作为参数传给其他函数，如 `qsort(arr, n, sizeof(int), cmp_int)`、信号处理 `signal(SIGINT, handler)`
- **表驱动编程**：用函数指针数组实现菜单、命令解析、状态机转移表
- **接口/多态**：结构体成员保存函数指针，模拟面向对象的虚函数（如 Linux 文件操作 `file_operations`）
- 动态加载：`dlsym` 获取符号后转为函数指针调用

指针函数的注意事项：

- 返回的指针**不能指向函数内的局部变量**（函数返回后栈空间失效），应返回静态变量、全局变量、堆内存或外部传入的指针
- 返回堆内存时，调用方负责 `free`，并约定所有权
- 返回 NULL 表示失败时，调用方要先判空再使用

函数指针的注意事项：

- 指向的函数必须与指针类型完全匹配，用 `-Werror` 等严格编译选项尽早发现类型不匹配
- 不要对函数指针做算术运算（函数地址无意义）
- 空函数指针调用会崩溃，调用前检查是否为 NULL
- 函数指针类型可读性差，优先用 typedef 起别名

## 2级指针

定义：二级指针（双重指针）是**指向指针的指针**，它保存的是另一个指针变量的地址。声明语法：`int **pp;`，即 `pp` 指向 `int *p`，`p` 指向 `int`。

解引用层级：

- `pp`：指针变量本身，存放的是 `p` 的地址
- `*pp`：得到 `p`（即 `p` 的值，一个 `int *`）
- `**pp`：得到 `p` 指向的 `int` 值
- 示例：

```c
int x = 10;
int *p = &x;   // p 指向 x
int **pp = &p; // pp 指向 p
printf("%d", **pp); // 输出 10
```

典型应用场景：

- **在函数内修改指针变量的值**：C 是值传递，想修改调用方的指针本身必须传指针的地址（二级指针）：

```c
void allocate(int **pp, int n) {
    *pp = malloc(n * sizeof(int)); // 修改调用方的指针
}
int *arr = NULL;
allocate(&arr, 10); // arr 被真正修改
```

- **链表/树等数据结构**：插入、删除节点需要修改头指针时，用二级指针简化（如 `void insert(Node **head, Node *n)`）
- **二维数组的模拟**：`int **m = malloc(rows * sizeof(int*));` 每行再分配，得到可动态调整的"二维数组"
- **main 函数参数**：`char *argv[]` 等价于 `char **argv`，即指向字符串指针数组首元素的指针
- 获取指针数组的地址、多级间接寻址（三级指针 `***ppp` 虽少见但语法合法）

注意事项：

- 每层解引用都要保证对应指针已指向有效内存，否则**空指针/野指针解引用崩溃**
- 动态分配二维数组后要按行释放再释放行指针数组，防止内存泄漏
- 函数参数用二级指针时，调用方必须传一级指针变量的地址（`&p`），而不是传 `p`
- 不要滥用多级指针，超过二级通常可用结构体封装提高可读性
- 判空要从外层向内层逐层进行：先判 `pp`，再判 `*pp`

## 野指针的成因及规避。

定义：野指针是**指向无效内存地址的指针**，解引用野指针属于未定义行为，轻则读到垃圾值，重则段错误（Segmentation Fault）或破坏数据，是 C 程序最常见的崩溃与安全漏洞来源。

野指针的主要成因：

- **未初始化**：局部指针变量定义后未赋值，其值是栈上的随机垃圾：

```c
int *p;       // 未初始化，野指针
*p = 10;      // 非法写入随机地址
```

- **指针越界**：指针越过数组边界后继续移动/解引用
- **释放后未置空（悬垂指针）**：`free(p)` 后内存已归还系统，但 `p` 仍保存原地址，再访问是未定义行为
- **返回局部变量地址**：函数返回指向局部变量的指针，函数返回后栈帧失效：

```c
int *bad(void) { int x = 1; return &x; } // x 已销毁
```

- **错误使用已失效的内存**：指向栈上已出作用域的变量、已关闭的文件句柄相关缓冲等

规避方法：

- **初始化指针**：定义时立即初始化，`int *p = NULL;`，没有目标就置 NULL
- **使用前判空**：解引用前检查 `if (p != NULL)`；`free(p)` 本身对 NULL 安全
- **free 后立即置 NULL**：`free(p); p = NULL;`，避免二次释放与悬垂访问
- **不返回局部变量地址**：需要返回数据时用静态变量、堆内存或由调用方传入缓冲区
- **控制数组边界**：遍历时严格按长度限制，不越界；使用带边界检查的字符串函数
- **借用工具**：启用 `-Wall -Wextra -fsanitize=address` 编译，运行 AddressSanitizer/Valgrind 检测内存错误
- **养成所有权意识**：明确"谁分配谁释放"，释放后所有指向该内存的指针都要失效处理

注意事项：

- 野指针不等于 NULL 指针：NULL 指针解引用会立即崩溃（可查），野指针可能"碰巧"指向合法内存造成隐蔽的脏数据，更难排查
- 多线程共享指针时，释放与使用需要同步，否则出现悬垂访问
- 即使置 NULL 也不能 100% 防止悬垂（可能有多个拷贝指向同一块内存），关键是**不访问已释放的内存**

## 动态内存分配

定义：动态内存分配是**在程序运行期间按需向堆（heap）申请/释放内存**的机制。堆内存不受栈大小的限制，生命周期由程序员控制，是链表、树、变长数据等结构的实现基础。

四个核心函数（`<stdlib.h>`）：

- **malloc**：`void *malloc(size_t size);` 分配 size 字节，**不初始化**（内容为垃圾值），失败返回 NULL
- **calloc**：`void *calloc(size_t n, size_t size);` 分配 n\*size 字节并**全部初始化为 0**
- **realloc**：`void *realloc(void *ptr, size_t new_size);` 调整已分配块的大小，可能搬移数据并返回新地址；失败返回 NULL 且原块保持不变
- **free**：`void free(void *ptr);` 释放 malloc/calloc/realloc 分配的内存，归还堆

标准使用模式：

```c
int *arr = malloc(n * sizeof(int));
if (arr == NULL) {          // 必须检查失败
    // 错误处理
    return -1;
}
// 使用 arr ...
free(arr);                  // 使用完毕释放
arr = NULL;                 // 置空防悬垂
```

常见错误：

- **忘记释放（内存泄漏）**：长时间运行的程序内存持续增长，最终耗尽。泄漏在程序退出时由 OS 回收，但服务器类程序不可接受
- **重复释放（double free）**：同一指针 free 两次，未定义行为，通常崩溃
- **释放后使用（use-after-free）**：free 后仍访问内存，悬垂指针问题
- **越界写入**：写入超出分配大小，破坏堆元数据，可能后续崩溃
- **释放非堆指针/错位释放**：free 栈上变量或指针的中间位置，未定义行为
- **malloc 后忘记检查 NULL**：极端情况下失败导致空指针解引用
- **分配大小错误**：如 `malloc(n)` 应为 `malloc(n * sizeof(int))`；数组越界边界错误

检测与治理：

- 编译/运行期工具：`-fsanitize=address`（AddressSanitizer）、Valgrind（`valgrind --leak-check=full ./prog`）
- 约定所有权：谁分配谁释放，函数间传递时明确转移或保留
- 结构体销毁函数集中释放：`void list_free(Node *head)` 遍历释放
- 记录分配/释放配对（日志或宏封装）辅助定位泄漏

注意事项：

- `malloc(0)` 行为是实现定义的，不要依赖
- `realloc` 返回值必须重新赋值给原指针，失败时原指针仍有效，不要直接 `p = realloc(p, ...)` 覆盖丢失
- 动态分配的内存默认不对齐要求之外的布局负责，但都满足基本对齐
- 嵌入式等受限环境慎用动态分配（碎片化、不可预测），改用静态池或栈

## 文件操作

定义：文件操作是**通过标准库函数对磁盘等外存上的文件进行读写**的过程。C 语言以"流"（stream）抽象文件，通过 `FILE *` 指针操作，打开后必须关闭。

文件打开与关闭：

- `FILE *fopen(const char *filename, const char *mode);` 打开文件，失败返回 NULL
- 模式：

  - `"r"` 只读（文件必须存在）、`"w"` 只写（清空重建）、`"a"` 追加（不存在则创建）
  - `"r+"` 读写（必须存在）、`"w+"` 读写（清空重建）、`"a+"` 读写追加
  - 加 `b` 表示二进制模式：`"rb"`、`"wb"`（Windows 下区分，Linux 下无差别）
- `int fclose(FILE *fp);` 关闭流并刷新缓冲区，失败返回 EOF

顺序读写函数：

- 格式化：`fprintf(fp, "%d", x);`、`fscanf(fp, "%d", &x);`
- 字符：`fgetc(fp)`（返回 int 或 EOF）、`fputc(c, fp)`
- 字符串：`fgets(buf, size, fp)`（安全，读到换行或 size-1 字节）、`fputs(s, fp)`
- 二进制块：`fread(buf, size, count, fp)`、`fwrite(buf, size, count, fp)`，返回成功读写的元素个数

随机访问：

- `int fseek(FILE *fp, long offset, int whence);` whence 为 `SEEK_SET`（文件头）、`SEEK_CUR`（当前位置）、`SEEK_END`（文件尾）
- `long ftell(FILE *fp);` 返回当前位置距文件头的字节数
- `void rewind(FILE *fp);` 回到文件开头（等价 fseek 到 0）
- `fseek(fp, -10, SEEK_END);` 从文件尾向前偏移

文件结束与错误判断：

- `int feof(FILE *fp);` 返回非 0 表示已到文件尾
- `int ferror(FILE *fp);` 返回非 0 表示发生错误
- `clearerr(FILE *fp);` 清除 EOF 和错误标志
- 注意：**先读后判断**，`feof` 只有在读取越过结尾后才置位，不要用它作循环唯一条件

文本文件与二进制文件：

- 文本模式：内容按字符处理，读写发生换行符转换（Windows），适合人可读数据
- 二进制模式：逐字节原样读写，适合结构体、图片等，配合 `fread`/`fwrite` 读写结构体数组

注意事项：

- **必须检查 fopen 返回值**：文件不存在、权限不足等都会返回 NULL，直接使用是空指针解引用
- **用完必须 fclose**：否则缓冲区数据未落盘、文件描述符泄漏（打开文件数有限）
- 文件操作失败要处理：写入用 `fflush`/`fclose` 确认成功
- 结构体直接 fwrite 写文件的可移植性差（字节序、填充对齐、平台差异），跨平台需序列化
- 不要用 `gets`（已移除）；字符串读取统一用 `fgets`
- 字符串 `%s` 格式化读写注意缓冲区大小，用宽度限制或 `%Ns`
- 大文件用 `fseek`/`ftell` 处理随机访问时注意 `long` 范围（大文件用 `fseeko`/`ftello`）





# 用户自定义数据类型

定义：用户自定义数据类型是**程序员基于基本数据类型和已有类型构造的新类型**，包括 typedef 别名、结构体、联合体、枚举、位域，以及与指针组合形成的复合类型。它让数据描述更贴近业务语义，提高可读性与复用性。

typedef（类型别名）：

- 语法：`typedef 已有类型 新名字;`
- 应用：

  - 简化复杂声明：`typedef int (*Handler)(int);` 之后 `Handler h;`
  - 定宽类型：`typedef unsigned char uint8_t;`（或直接使用 `<stdint.h>`）
  - 结构体别名：`typedef struct {...} Point;`
- 作用：提高可移植性（换平台只改一处）、增强可读性、封装内部类型
- 注意：typedef 不是宏，不进行文本替换，有类型检查；不要在头文件中重复 typedef 同一名字（易冲突）

结构体（聚合不同类型）：

- 定义与使用详见"聚合数据类型→结构体"章节
- 与 typedef 结合是最常用的定义方式：

```c
typedef struct {
    char name[32];
    int age;
    double score;
} Student;
```

- 支持结构体数组、结构体指针、嵌套结构体、作为函数参数/返回值（建议传指针减少拷贝）

联合体（共享内存）：

- 多个成员共享同一块内存，大小取最大成员，同一时刻只有一个成员有意义
- 典型应用：类型双关、协议解析、寄存器访问（详见"聚合数据类型→联合体"）

枚举（具名整型常量集合）：

- 给一组相关的整数值有意义的名字，如错误码、状态、方向
- 支持 typedef 组合：`typedef enum { OK, ERR } Status;`
- 详见"聚合数据类型→枚举"

自定义类型的设计建议：

- 命名用**类型名大写或驼峰**（`Student`、`STATUS_CODE`），变量名小写，区分清晰
- 结构体命名采用"名词短语"，函数指针成员描述"能力"
- 接口头文件中暴露类型声明，实现细节放 .c 文件（不透明指针，信息隐藏）
- 自定义类型应配套提供创建/销毁/访问函数，封装内部布局，便于后续演进
- 避免过度设计：能用基本类型清晰表达时不必强行封装

# 嵌入式c语言的高级用法

定义：嵌入式 C 语言的高级用法指**面向单片机/嵌入式系统的 C 编程技巧**，核心是直接操作硬件：寄存器、内存、中断、位操作，并受资源（RAM/ROM/功耗）与实时性约束。

volatile 与 const：

- **volatile**：告诉编译器该变量可能被外部因素（中断、硬件、多线程）随时修改，**禁止优化掉读写**。硬件寄存器声明、中断共享变量必须加：

```c
volatile uint32_t *REG = (volatile uint32_t *)0x40000000;
```

- **const**：只读数据放 ROM/Flash（节省 RAM），如查表、固件版本；函数形参加 const 保证只读
- 组合：`volatile const` 表示硬件寄存器只读，如状态寄存器

位操作（寄存器控制）：

- 置位：`REG |= (1 << 3);`
- 清位：`REG &= ~(1 << 3);`
- 翻转：`REG ^= (1 << 3);`
- 读取某位：`if (REG & (1 << 3))`
- 连续位域设置：先清后或：`REG = (REG & ~(0xF << 4)) | (val << 4);`
- 位域结构体映射寄存器：`typedef struct { uint8_t a:1; uint8_t b:3; } Flags;`（注意可移植性）

中断服务函数（ISR）：

- ISR 要**短小快速**，只做标志置位/数据保存，耗时处理放主循环
- 中断与主循环共享的变量用 volatile，必要时关中断保护临界区
- 不要在 ISR 中调用不可重入函数（printf、malloc）
- 中断里用标志位通知主程序：`volatile uint8_t flag = 1;`

内存管理策略：

- 裸机慎用 malloc/free：碎片化、时间不确定，改用**静态数组+固定池**分配器
- 栈空间受限，递归深度要严格控制，避免大局部数组
- 利用链接脚本将常量放 Flash、变量放 RAM；`__attribute__((section()))` 自定义段

模块化与分层：

- 驱动层/中间层/应用层分离，驱动提供 `xxx_init/read/write` 接口
- 用函数指针实现硬件抽象（HAL），同一逻辑可移植到不同 MCU
- 头文件用 `#ifndef` 保护，外设寄存器地址用宏集中定义
- `static` 限制函数/变量作用域，封装模块内部细节

常用技巧：

- 断言 `assert` 与自定义错误宏，便于调试
- 条件编译区分调试/发布：`#ifdef DEBUG`
- 看门狗（Watchdog）喂狗防死机；低功耗模式切换
- DMA 搬运数据减少 CPU 占用；定时器/中断驱动代替忙等待
- 打印调试信息可重定向到串口，`printf` 重定向（fputc 接 USART）

注意事项：

- 寄存器操作注意**读-改-写**的原子性，多任务下需临界区保护
- 位域在内存排列由编译器决定，跨编译器可移植性差，寄存器映射优先用宏位操作
- 优化选项（-O2）下未加 volatile 的寄存器读写可能被删除，这是嵌入式最常见的"神秘 bug"
- 所有硬件地址访问都要确认是合法映射区，防止硬件错误访问（总线错误）
