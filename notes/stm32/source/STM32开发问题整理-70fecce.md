# 第一版

## 通用输入输出控制器（GPIO）

### 什么是 GPIO？它的核心作用是什么？

GPIO是一个通用输入输出的控制器，它的核心作用是作为芯片与外部设备之间通信的接口，可通过设置不同的端口模式将引脚设置为输入、输出、模拟、复用功能模式。输入时CPU通过IDR寄存器感知外部电平变化，输出时通过ODR寄存器或者BSRR寄存器驱动外部设备

### STM32 的 GPIO 有几种工作模式？分别是什么？分别适用于什么场景？

一共有4种工作模式

输入模式：用于读取外部的数字信号，检测外界的高低电平变化。比如按键、传感器

输出模式：用于直接驱动外部设备，主动输出高或低电平去控制外设。比如LED、蜂鸣器、继电器、电机

模拟模式，用于DAC模拟电压输出和ADC模拟电压输入，处理连续变化的电压信号。比如光敏电阻、土壤温湿度传感器

复用功能模式，可以将引脚控制权交给内部外设硬件，引脚不再受`GPIO->ODR` 控制，由芯片内部的 UART/SPI/I2C/TIM 硬件直接接管，比如GPS模块，OLED屏幕

### 推挽输出和开漏输出的核心区别是什么？（为什么 I2C 要用开漏输出？）

推挽输出是由内部两个MOS管主动拉高/拉低，输出阻抗低

开漏输出是只能主动拉低，拉高需要外部上拉电阻提供

I2C用开漏的原因：一是实现多主机的线与仲裁，防止总线短路（采用推挽输出的话，如果一个主机发高电平，一个主机发低电平，会导致电源短路烧毁芯片）。二是支持电平转换，通过选择上拉电阻的电压来匹配不同电压的从设备（为啥不用放大电路，因为放大电路（尤其是运放/三极管放大）通常是**单向**且**强推挽**的，而 I2C 是**双向**且需要**线与**的）

### 上拉输入和下拉输入的区别？什么时候用？

主要区别是当外部没有输入信号时，内部电阻把引脚强行拉到什么默认电平

上拉输入是 ，内部通过电阻连接VDD，悬空时默认高电平，用于按键检测、通信接口

下拉输入是，内部通过电阻连接GND，悬空时默认低电平，用于按键检测，各种传感器（平时输出低电平，检测到信号时输入高电平）

### GPIO 的模拟输入模式和数字输入模式有什么区别？

数字输入模式经过施密特触发器进行整形，可配置上下拉电阻，最终将外部信号转换为 0 或 1 存入 IDR，供 CPU 读取。

模拟输入模式则强制断开施密特触发器和上下拉电阻，让外部模拟电压原封不动地进入 ADC，由 ADC 进行精确量化。

两者的核心区别在于是否经过数字整形电路，以及是否由 ADC 进行转换

### 为什么配置 GPIO 前必须先使能时钟？

首先是省电，STM32复位后所有外设时钟默认关闭，必须先使能才能使用。*默认关闭是因为STM32 是 CMOS 数字电路，CMOS 电路的功耗公式是P=C×V²×f（功耗=寄生电容 x 供电电压² x 时钟频率），RCC产生的时钟信号本身是连续的方波信号，本身一直就在不停的反转，会消耗动态功耗。*

第二所有的寄存器由 D 触发器构成，D 触发器必须在时钟沿到来时才能锁存数据到输出端

第三是总线传输本身需要时钟同步，CPU 通过 AHB 总线访问 GPIO 寄存器时，总线上的地址、数据、控制信号都需要时钟来同步。如果 GPIO 控制器的时钟关闭，AHB 总线到 GPIO 的这段通路处于休眠状态，数据传输根本无法完成

因此配置 GPIO 前必须先通过 RCC 寄存器使能对应 GPIO 端口的时钟

### STM32 GPIO 的驱动能力是多少？如何保护引脚？

驱动能力分**单个引脚和芯片整体限制：**单个GPIO的引脚能力通常分两档，标准驱动和高驱动模式，标准驱动可安全的拉出和灌入±8mA的电流，高驱动模式下可提升+-20mA，对于stm32F407来说，单个引脚的最大电流能力约为25mA。**芯片整体限制**，绝对不能让所有引脚都同时输出20mA。芯片存在一个总电流限制，通常所有GPIO的电流总和不能超过80mA至100mA。

保护引脚的方式：核心思路是限流（过流）、钳位（过压）、隔离（电气切断）。 串联限流电阻、 使用TVS二极管（防静电与浪涌），使用驱动芯片/隔离器（驱动大功率负载）。隔离是防止这种噪声、高压或地电位差通过导线传导回MCU的防火墙

### GPIO 的 ODR 和 IDR 寄存器有什么区别？

ODR是输出数据寄存器，可读可写，CPU通过写它来控制引脚输出电平，读它可获取当前输出的电平值

IDR是输入数据寄存器，只读，通过读它来感知外部电平

### 如何通过位操作快速翻转 GPIO 电平？

通过BSRR寄存器实现GPIO快速翻转，先读取ODR判断当前的电平，**若为高**，向BSRR的高16位对应的BR位写1拉低，**若为低**，向 BSRR 的低 16 位对应的BS写 1 置高。BSRR 是只写寄存器，单条指令即可完成原子操作，不会被中断打断，避免了 ODR 读-改-写导致的位冲刷风险。HAL 库的 `HAL_GPIO_TogglePin` 底层也是用此方式实现。

### 如何用 GPIO 实现按键检测？需要处理什么问题？

首先将GPIO时钟使能，将GPIO配置为输入模式，选择内部上拉输入，按键接一端接GPIO引脚，一边接GND，未按下时读到高电平，按下时读到低电平。

实际中要处理按键抖动的问题，机械按键的触点在闭合和断开瞬间，金属片会弹跳多次，产生 5\~20ms 的杂乱脉冲，按一次键，CPU 可能检测到几十次按下-松开，因此要选择软件延时消抖或定时器消抖或硬件消抖

### 多个 GPIO 引脚如何实现流水灯？如何优化？

流水灯实现：使能 GPIO 时钟，将多个引脚配置为推挽输出，与 LED 相连（共阴极接法）。通过依次向 ODR 或 BSRR 写入不同值，控制 LED 轮流点亮。

优化方案包括：①用 BSRR 代替 ODR 实现原子操作，避免中断位冲刷；②用位带操作直接读写单个引脚，代码最简洁；③用定时器中断代替 HAL_Delay，实现非阻塞流水，解放 CPU；④用查表法或结构体封装，方便扩展复杂花样和移植

### GPIO 中断的配置步骤是什么？

1. 使能GPIO和AFIO的时钟
2. 配置GPIO为中断模式
3. 配置NVIC
4. 编写中断服务函数
5. 写回调函数
6. 主循环处理

***注意：F103 的 EXTI 引脚映射（比如 PA0 映射到 EXTI0）由 AFIO 管理，因此如果不开 AFIO 时钟，EXTI 就不知道PA0 要触发中断，中断配置会失效。F407：不需要，EXTI 映射由 SYSCFG 管理，SYSCFG 时钟默认开启***

### **扩展：**什么是 GPIO 的复用功能（AF）？配置时需要注意什么？

GPIO的复用功能是将GPIO引脚直接交给内部其他硬件外设控制

- 配置时需要注意查数据手册的复用功能映射表，F1引脚可复用的功能是硬件固定的，F4是通过 AFRL/AFRH 寄存器选择。
- 注意要同时打开三个时钟，GPIO时钟，外设是中国，AFIO时钟（F1需要，F4不需要）
- 注意输出类型要匹配外设协议，I2C要配置成开漏，USART/SPI推挽

### **扩展：**AFIO 时钟什么时候必须开启？

只要操作AFIO的寄存器，就必须开，具体是：

- 配置外部中断（EXTI），用于指定EXTI线映射到对应的端口，需要写 `AFIO_EXTICRx` 寄存器。
- 使用引脚重映射（Remap）,将一个外设的默认引脚重映射到其他引脚，需要配置 `AFIO_MAPR` 寄存器
- 配置事件输出（Event output），把一个内部事件（如定时器溢出）输出到外部引脚时，需要配置 `AFIO_EVCR` 寄存器
- 调试引脚复用（释放JTAG引脚），如果想把默认被 JTAG 占用的引脚（如 PA15、PB3、PB4）当作普通 GPIO 或其他功能使用，需要配置 AFIO 的 `MAPR` 寄存器来关闭 JTAG 功能，只保留 SWD

***注意：AFIO = Alternate Function I/O，复用功能 I/O 模块，STM32F1 独有的外设，挂在 APB2 总线。F4/F7/H7 等新系列不再有独立 AFIO 外设，复用功能由 GPIO 寄存器直接管理。***

## 时钟控制器（RCC）

### STM32 的时钟系统有哪些时钟源？各自特点是什么？

HSE高速外部时钟，特点是精度极高，需要外部晶振

HSI高速内部时钟，特点是精度差（±1%），启动极快，使用内部RC

LSE低速外部时钟，特点是精度极高，极低功耗，需要外部晶振

LSI低速内部时钟，特点是精度极差（±5%），成本最低，完全独立

PLL锁相环倍频放大器，把 HSI 或 HSE 的输入频率乘以某个系数，输出给系统做主时钟。

MCO微控制器时钟输出：把芯片内部的时钟信号通过引脚输出到外部，用来给外部芯片提供时钟，或者用示波器测波形。

***注意：F1和F4的低速外部时钟都是32.768kHz。LSE 是全球标准（32.768kHz）不变；LSI 则因芯片设计而异，F1 是 40k，F4 是 32k。写看门狗时需注意LSI的频率会影响实际的超时时间***

### HSE、HSI、LSI、LSE、PLL 分别是什么？适用场景？

HSE是外部无源晶振，适用于系统主时钟、USB/CAN/串口等对精度有要求的通信

HSI是内部RC震荡器，适用于上电默认时钟，作为紧急备用时钟（HSE起振失败时用）；低成本无晶振应用

LSE是外部音叉晶体，适用于RTC（实时时钟）专用，掉电靠电池供电

LSI是低功耗内部RC振荡器，适用于独立看门狗（IWDG）专用（主时钟挂了也能复位），RTC的低成本备胎

PLL是锁相环倍频器，用来把低频的HSE或HSI倍频到系统最高主频

### 什么是时钟树？STM32 的时钟信号是如何分发到各个外设的？

时钟树是STM32内部时钟信号从时钟源到外设的完整分发路径图

时钟信号由时钟源（HSE，HSI，LSE，LSI）产生，经过PLL锁相环（先预分频再倍频再输出分频）然后得到系统主时钟SYSCLK。再通过AHB（HCLK）、APB1（PCLK1）、APB2（PCLK2）三级总线逐级分频，最终经 RCC 时钟使能寄存器分配给每个外设

### 为什么要配置 AHB、APB1、APB2 时钟分频器？

满足不同的外设硬件限制，APB1和APB2总线上挂载的外设硬件最高承受频率不同，必须分频保护不超频

降低系统功耗，频率越高功耗越大，有些外设不许需要那么快，降频能显著节省功耗

保证时序精度与降低干扰，总线频率会影响外设内部波特率发生器等时序的分频计算精度，同时，降低总线频率能减缓引脚翻转的边沿速率，从而减小 EMI（电磁干扰），提升通信稳定性

### 如何计算系统时钟频率？以 72MHz 为例说明配置步骤。

以 F103 为例，系统时钟通常由 HSE（8MHz）经 PLL 倍频得到。

HSE 直接进入 PLL，设置 PLLMUL = ×9，得到 PLLCLK = 8MHz × 9 = 72MHz。

System Clock Mux 选择 PLLCLK 作为 SYSCLK，即 SYSCLK = 72MHz。再经 AHB 预分频器 /1 得到 HCLK = 72MHz，APB1 预分频器 /2 得到 PCLK1 = 36MHz，APB2 预分频器 /1 得到 PCLK2 = 72MHz。

### 什么是时钟安全系统（CSS）？它的作用是什么？

CSS（时钟安全系统）是 STM32 用于监控 HSE 的硬件保护机制。

当 HSE 失效时，CSS 自动将系统时钟切换到 HSI，关闭 HSE 和 PLL，并产生 NMI 中断通知软件处理。它的作用是保证系统在外部晶振故障时仍能继续运行，提高系统可靠性。CSS 只监控 HSE，中断为不可屏蔽中断，处理函数中不能延时。

### 外设时钟使能为什么要单独开启？不开启会怎样？

一是降低功耗，复位后所有时钟默认关闭，用什么打开什么

二是模块化管理，每个外设独立开关，可以精准控制功耗，低功耗模式下只保留必要的外设时钟

不开启时钟，寄存器无法存储数据，总线传输需要同步

### MCO 引脚的作用是什么？如何输出时钟信号？

MCO微控制器时钟输出：一是把芯片内部的时钟信号通过引脚输出到外部，用来给外部芯片提供时钟，二是用示波器测量内部时钟频率进行调试。

F103的MCO时钟源可选PLLCLK/2、HSI、HSE、SYSCLK。

### 低速时钟（LSI/LSE）主要用于哪些外设？

低速内部时钟LSI，用于独立看门狗（IWDG），保证主时钟失效时看门狗依然能独立运行；也可以作为 RTC 的备用时钟源，但精度差。

低速外部时钟LSE，用于 RTC 实时时钟，提供精准的日历时间和低功耗唤醒源。（RTC 在 VDD 断电后可切换到 VBAT 纽扣电池供电，继续走时。）

### HSE 不起振可能是什么原因？如何排查？

**硬件原因：**

负载电容不匹配，晶振损坏或者虚焊、PCB走线过长或者干扰、供电电压不稳、晶振类型选错

**软件原因：**

时钟源配置错误、启动超时时间太短、引脚复用冲突

**排查步骤：**

第一阶段是检查软件配置：查手册确认引脚，检查 CubeMX 是否选对了无源晶振模式，超时时间是否足够，引脚是否冲突。

第二阶段是物理硬件排查：用万用表测 OSC_IN/OSC_OUT 电压是否在 VDD/2，用示波器看有无正弦波，检查焊接，替换晶振和匹配电容。

第三阶段是运行诊断与保护：在代码中检查 HSERDY 标志位确诊起振状态，并开启 CSS 时钟安全系统。一旦运行中 HSE 失效，CSS 会自动切换到 HSI 并触发 NMI 中断，保证系统正常运行。

## 通用异步收发器（UART：Universal Asynchronous Receiver/Transmitter）

### UART 是什么？特点？

 UART是通用异步收发器，用于两个设备之间通过两根数据线（TX、RX）加共地进行全双工通信。特点是异步、串行、全双工、点对点、帧格式固定

### UART 传输数据的数据格式是什么？

UART 帧格式 = 1 位起始位 + 5\~9 位数据位（LSB先发）+ 0/1 位校验位 + 1/1.5/2 位停止位。最常见配置是 8N1（8数据位、无校验、1停止位），加上起始和停止，每字节共 10 位。

### 什么是波特率？什么是比特率？

波特率是每秒传输的码元个数。比特率是每秒传输的比特个数。比特率=波特率×每个码元携带的比特数。码元是码元是信号变化的最小单位。在二进制中码元只有两种状态（0 和 1），UART 用二进制，所以波特率和比特率数值相等。

### 为什么 UART 通信双方的波特率需要配一样？不一样会怎样？

UART 没有时钟线，接收方靠起始位对齐后，用自己的波特率推算采样点。

不一样会导致采样点会逐位偏移，累积到半个位宽就采错，导致乱码、帧错误。

实际要求双方波特率误差小于 2%\~3%。

### 什么是同步通信？什么是异步通信？

同步通信有单独的时钟线，收发双方共用同一个时钟，全程同步

异步通信没有时钟线，靠起始位和约定的波特率对齐

### UART 的不同物理层标准下的连接有哪些？分别从电压、特点、常见接口、连接方式说明。

**TTL/CMOS标准**

电压：0V（低） / 3.3V 或 5V（高）

特点：单端信号，点对点，距离极短（<1m），易受干扰。STM32 的 UART 引脚直接输出 TTL

常见接口：开发板排针、杜邦线、USB-TTL 模块

连接方式：

```text
设备A TX  →  设备B RX
设备A RX  ←  设备B TX
设备A GND —  设备B GND（必须共地）
```

**RS-232**

电压：负逻辑，逻辑1 = -3\~-15V，逻辑0 = +3\~+15V

特点：单端、点对点、距离约15m、速率<1Mbps。抗干扰一般

常见接口：DB9（9针）、DB25

连接方式：交叉连接，但需经过电平转换芯片（如 MAX232、MAX3232）

```text
MCU TX → MAX232 → RS-232 TX → 对方 RX
MCU RX ← MAX232 ← RS-232 RX ← 对方 TX
共地
```

**RS-485**

电压：差分，A-B 差压 +2\~+6V 为逻辑1，-2\~-6V 为逻辑0

特点：差分抗干扰强，半双工（两线）或全双工（四线），多点总线，距离可达1200m，速率10Mbps

常见接口：接线端子、DB9

连接方式：

```text
总线型：所有节点 A 接 A，B 接 B。
两端加 120Ω 终端电阻。
半双工时，MCU 需控制 DE/RE 引脚切换收发方向（通常用 MAX485 等芯片）。
全双工需四线（TX+/-，RX+/-），类似 RS-422。
```

**RS-422全双工差分**

电压：差分，A-B 差压 +2\~+6V 为逻辑1，-2\~-6V 为逻辑0

特点：全双工（四线），点对多（一主多从），距离1200m，速率10Mbps

常见接口：端子、DB9

连接方式：

```text
主机 TX+ → 从机 RX+
主机 TX- → 从机 RX-
主机 RX+ ← 从机 TX+
主机 RX- ← 从机 TX-
共地，加终端电阻
```

### UART 的使用场景？

UART 的核心价值是：简单、低成本、全双工、点对点异步通信。适用于设备之间短距离、低速率、不需要共享总线的数据传输场景。例如：调试打印、模块通信（GPS/蓝牙/WiFi）、设备互联、工业多机（RS-485）、固件升级

### 分析 UART 的硬件系统框图，说明 UART 的收发路线（可参考任何一个芯片手册中的 UART 硬件系统框图，可以截图标注收发路线）。

发送流程：

1. 将串口数据写入内存
2. 程序将内存中的数据填入串口控制器的DR寄存器
3. DR寄存器中的数据自动传入发送移位寄存器
4. 发送移位寄存器按波特率、将数据从TX引脚逐位发送出去

接收流程：

1. 当RX引脚上有数据时，数据依次流入接收移位寄存器
2. 接收移位寄存器接收完成后，硬件自动将数据写入DR寄存器
3. 程序读取DR寄存器的数据，写入内存中使用

### UART 发送数据有哪几种方式？（查询/中断/DMA）各自优缺点？

轮询是CPU死等，适合几个字节的调试信息

中断是发一个字节打断一次占用较少，适合实时响应

DMA是硬件自动搬运（几乎不占 CPU），适合大块数据，有别的任务

### UART 接收数据时如何处理帧错误、溢出错误、奇偶校验错误？

帧错误（FE）是波特率不匹配、线路干扰、对方发送异常、停止位被拉低。会导致当前帧数据不可信，但不影响后续接收。处理方式：丢弃当前帧，记录错误计数、必要时重新同步。

溢出错误（ORE）是CPU 没及时读走 DR，新数据到来，硬件强制覆盖，旧数据永久丢失。会导致数据丢失，且 `RXNE` 标志位（接收数据寄存器不为空）可能还处于置位状态，后续判断会出错。处理方式：立即读 `SR` 再读 `DR`（读 DR 时先读 SR 可以清标志），丢弃丢失的数据，加快读取速度。

奇偶校验错误（PE）是传输中某一位翻转，导致校验位与数据不匹配。会导致当前帧不可信。处理方式：丢弃当前帧，请求重传。

### 如何实现 UART 的不定长数据接收？（空闲中断 + 接收中断）

空闲中断+接收中断：原理是接收中断（RXNE）：每收到一个字节，触发一次中断，把数据存进缓冲区。空闲中断（IDLE）：总线连续静默 1 个字节时间（约 10 个比特时间）后，硬件自动触发 IDLE 中断，说明一帧发完了。

还有长度前缀+接收中断。接收中断可用DMA替代，减少CPU压力

## 中断控制器（NVIC 与 EXTI）

### 什么是中断？STM32 中断执行流程？

中断是 CPU 在执行程序过程中，遇到外部或内部事件时，暂停当前程序，转去执行对应的处理程序（ISR），处理完后再返回原程序继续执行的过程。

执行流程：

1. 主程序正常运行
2. 外设/引脚发送中断请求
3. NVIC中断优先级裁决
4. CPU自动现场保护（把很多寄存器压入当前的堆栈）
5. 取中断向量+跳转
6. 执行ISR（中断服务程序）
7. CPU恢复现场（将压入的寄存器依次弹出）
8. 返回主程序

### 中断和异常有什么区别？

系统异常由内核事件、硬件故障、指令触发，由内核管理(NVIC参与优先级)。通常是在（1\~15）向量表开头

外部中断由外设/引脚（EXTI、UART、TIM、DMA）触发，NVIC管理。通常在（16+）系统异常之后

### 什么是中断嵌套？STM32 如何实现它？

中断嵌套就是高抢占优先级中断可以打断低抢占优先级中断，实现先处理高抢占优先级后处理低的

过 NVIC 配置每个中断的抢占优先级和响应优先级实现，抢占优先级不同才能嵌套，相同则不能；响应优先级只决定同时挂起时的顺序。硬件自动压栈/出栈，并支持尾链和迟到优化，保证嵌套高效

### 什么是 NVIC？它有哪些核心功能？

NVIC是嵌套向量中断控制器，负责中断的使能、优先级裁决、挂起管理和嵌套控制

核心功能：使能中断、配置抢占/响应优先级、处理中断挂起、以及在响应时提供向量地址

### STM32 的优先级分为哪两种？它们之间有什么区别？

分为抢占优先级和响应优先级，数值越小优先级越高。

抢占优先级是决定能不能打断别人

响应优先级是在抢占优先级相同时，决定谁先执行。

如果抢占优先级和响应优先级都相同，则比较自然优先级

### 什么是优先级分组？STM32 支持哪几种分组？

优先级分组是将中断优先级的4个优先位，划分给抢占优先级和响应优先级。一共五种，组 0 是 0 位抢占 + 4 位响应，组 1 是 1+3，组 2 是 2+2，组 3 是 3+1，组 4 是 4+0。

### 什么是 EXTI？STM32 的 GPIO 中断线是如何映射的？

EXTI是外部事件/中断控制器，负责检测GPIO引脚的边沿跳变，产生中断请求给NVIC，或产生事件脉冲触发其他外设。

通过AFIO（F1系列）复用功能IO控制器，SYSCFG（F4系列）系统配置器，将具体的EXTI中断线映射到对应的GPIO端口上。

### 如果多个中断同时到来，STM32 如何决定先响应哪个？

先看抢占优先级高的先响应，抢占优先级相同的看响应优先级，响应优先级相同看自然优先级

### 中断服务函数（ISR）的名字是固定的吗？在哪里可以找到？

是固定的，每个中断对应的ISR中断服务函数名字由启动文件和中断向量表预先定义好。在启动文件中，参考手册中可以找到

### 在编写中断服务函数（ISR）时，有哪些注意事项？

核心原则是快进快出，只做最紧急最简短的事，复杂的处理交给主循环。注意事项：

第一：禁止使用阻塞函数，禁止使用浮点运算（除非有FPU），禁止动态内存分配，禁止调用不可重入函数

第二：必须清楚中断标志位，否则会反复进入

第三：与主循环共享的变量要加防止优化volatile关键字，多字节变量要加临界区保护

第四：合理配置抢占优先级，避免过深嵌套

第五：HAL库回调函数中只置标志位，复杂逻辑交给主循环

### SysTick 中断是干什么用的？它有什么特点？

SysTick是系统滴答定时器，是一个Cortex-M 内核自带的24 位递减计数器。

作用是：给整个系统提供统一的时间基准，HAL库的时基、RTOS的心跳，精确定时，低功耗唤醒都依赖SysTick

特点是：内核自带的组件，是24位的递减计数器，无预分频器，属于系统异常

### 为什么串口中断只接收一次数据就卡死了？

因为HAL库的接收中断是一次性的，收完1个字节后，HAL库会把接收中断使能位清零，如果不在回调函数中重新调用，中断就不会再触发了

### 在 Bootloader 跳转到 APP 后，中断就不工作了，为什么？

Bootloader 跳转到 APP 后中断不工作，根本原因是 VTOR（向量表偏移寄存器）仍然指向 Bootloader 的向量表。Cortex-M 中断响应时，CPU 从 VTOR 指向的向量表里取 ISR 地址，如果 VTOR 没改，中断就会跳到 Bootloader 的 ISR。

解决方法是在 APP 的 main 开头重定位 VTOR 到 APP 的起始地址同时 Bootloader 跳转前要关中断、清挂起标志、设置 MSP；APP 要重新初始化时钟和外设

***注意：VTOR 不重定位导致中断失效这个问题，只有在Bootloader + APP双程序架构下会出现，例如OTA 远程升级***

### **扩展：**在 Linux 驱动中，中断上下文为什么不能用信号量？

信号量在获取不到信号量时，会主动睡眠。而中断上下文不能睡眠，原因：

第一：中断上下文没有 task_struct，调度器无法保存和切换任务

第二：中断可能打断任意进程，睡眠会导致被打断的进程被永久挂起

第三：硬中断期间会屏蔽其他中断，睡眠会导致系统实时性崩溃

如果需要睡眠应当放在进程上下文里执行

## 直接存储器访问控制器（DMA）

### 什么是 DMA？它的核心作用是什么？

DMA是直接存储器访问控制器，主要是实现寄在外设数据寄存器和内存之间，或内存和内存之间自动搬运数据。不占用CPU

### DMA 传输和 CPU 传输有什么区别？优势是什么？

DMA传输是硬件独立搬运，CPU 只需初始化源地址、目标地址、长度，然后就可以去干别的，搬完一整块才触发一次中断通知 CPU。CPU的传输本质上都是CPU亲自执行指令搬运数据，每次中断开销大。

优势是解放CPU，传输速度快，中断频率低，适合大批量、高速、实时的数据搬运场景

### STM32 的 DMA 有几个通道？通道和外设的映射关系是怎样的？

F1系列是通道架构，外设和通道之间是硬件固定映射的

F4系列是数据流+通道架构，每个DMA控制器，有8个数据流，每个数据流有8个通道，可以通过软件选择8个通道之一。可以外设请求先映射到某个通道，再配置数据流去选择这个通道。可以通过DMA 请求映射表查看。外设到通道（硬件定死），数据流到通道（软件可选）

### DMA 的传输模式有哪几种？（正常模式/循环模式）

正常模式：传输完指定长度后自动停止，需要重新启动，适合单次批量传输

循环模式：传输完后自动重装载，永不停歇，适合连续周期性的数据流，如 ADC 连续采样

双缓冲模式（F4及以上支持）：使用两个缓冲区交替工作，DMA 写一个缓冲区时 CPU 处理另一个，实现零等待并行，适合高速数据流

### 什么是 DMA 的通道仲裁？优先级如何设置？

DMA通道仲裁是用于管理多个数据流/通道对系统总线的竞争访问，确保数据传输有序进行

分软件和硬件优先级，软件优先级分为四个等级，最高，高，中，低。由寄存器配置。硬件优先级无法设置，编号低的优先级高

### DMA 传输完成后如何通知 CPU？有哪些方式？

三种方式：

第一：中断方式，使能传输完成中断（TC）、半传输中断（HT）或错误中断（TE），在 NVIC 中使能对应通道/数据流的中断，在 ISR 中处理；

第二：轮询方式，CPU 主动查询 DMA 状态寄存器的 TCIF 标志位，适合简单场景；

第三：HAL 库回调方式，调用HAL库函数启动传输，HAL 自动处理中断并调用对应的回调函数

正常模式只通知一次，循环模式每次循环都通知，双缓冲模式每个缓冲区满时通知

### 内存到内存、内存到外设、外设到内存三种传输方向的配置区别？

由DMA_SxCR寄存器中的DIR[1:0]位配置，区别：

00是外设到内存，外设到内存时，外设地址不递增、内存地址递增

01是内存到外设，内存到外设时，外设地址不递增、内存地址递增

10是内存到内存，PAR 放源地址、M0AR 放目标地址，两者都要递增，同时要关闭外设流控

### 为什么 ADC+DMA 可以实现多通道连续采样而不占用 CPU？

本质上还是因为DMA是独立的硬件控制器，能自动搬运数据。

ADC 配置为扫描模式和连续转换模式，硬件自动依次转换多个通道；每转换完一个通道，ADC 硬件产生一个 DMA 请求信号；DMA 收到请求后，自动把 ADC_DR 里的数据搬运到内存数组中，并自动递增内存地址；配合 DMA 循环模式，数组填满后自动回到开头，实现无休止采样。整个过程，CPU 只需要初始化一次，之后完全不参与搬运，可以去做其他任务

### DMA 传输中数据宽度（字节/半字/字）不匹配会导致什么问题？

会导致数据截断、数据错位、数据填充错误。

### UART 发送数据，使用 DMA 和中断的区别？各自适用场景？

DMA是硬件自动搬运，适合发送大数据，高速，低功耗的场景

中断是CPU搬运，适合数据量小，简单实时性的场景

### DMA 传输一半中断（HT）和传输完成中断（TC）分别有什么用？

实现提前检验和双缓冲机制，检验是搬完一半可提前验证数据是否正确。双缓冲机制是在DMA传输一半时通知CPU处理，这样DMA一边继续搬运，CPU一边继续处理，可以提高效率

### 如何实现 DMA 的双缓冲（Ping-Pong）？适用场景是什么？

通过软件模拟：把一个数组切成两半，利用 HT 和 TC 中断，DMA 写前半时 CPU 处理后半，DMA 写后半时 CPU 处理前半，实现并行。

通过硬件双缓冲：F4系列及以上，通过DMA内部两个地址寄存器实现自动交替切换，只需一个 TC 中断，软件通过 CT 位判断当前 DMA 在写哪个缓冲区

## 模数转换器（ADC）

### 什么是 ADC？模数转化的流程是什么？

ADC模数转换器是把连续变化的模拟电压信号转换为离散的数字量

流程分四步：采样、保持、量化、编码。采样是用开关把外部电压接入采样电容；保持是断开开关，让电容维持这个电压；量化是把电压与参考电压比较，映射到离散电平；编码是把量化结果编码成二进制数字存入数据寄存器

### STM32 的 ADC 是什么类型？有什么特点？

STM32的 ADC 是逐次逼近型（SAR）

核心原理：用二分搜索的方式，从最高位（MSB）到最低位（LSB），逐位比较，确定每一位是 0 还是 1

主要特点：

分辨率可调：12位，并可软件配置为6/8/10/12位。

通道丰富：多达19个转换通道，包括16个外部通道和3个内部通道

转换模式多样：支持单次、连续、扫描、间断四种模式。

触发方式灵活：支持软件触发、外部引脚触发、定时器事件触发。

数据对齐与搬运：数据支持左对齐/右对齐，并支持DMA自动搬运结果。

分组管理：分为规则组和注入组，注入组可打断规则组转换。

安全监控：内置模拟看门狗，可监测电压越限并产生中断。

转换速度快。

### ADC 的分辨率、精度、量化误差有什么区别？

分辨率是看硬件位数，量化误差是看原理误差，精度是看综合误差。

分辨率：ADC 能分辨的最小模拟量变化，由位数决定，N 位分辨率 = VREF / 2^N。12 位、3.3V 参考时约 0.806mV/LSB。

量化误差：模数转换固有的原理性误差，即模拟连续值与量化后离散值之差，理想情况下最大 ±1/2 LSB。位数越高量化误差越小，只能减小无法消除。

精度：实际测量结果与真实电压的偏差，是综合指标，包含量化误差、失调误差、增益误差、参考电压漂移、电源噪声、温度漂移等。

### 如何计算 ADC 的转化时间？

总转换时间 = 采样时间 + 转换时间。

采样时间：采样电容充电的时间，可配1.5、7.5、55.5个周期

转换时间：SAR 逐位比较的时间，12 位ADC逐次逼近需要12.5个ADC时钟周期（0.5是同步周期）

计算流程：先算总周期数=采样周期+转换周期。再算总转换时间=总周期数/ADC时钟

### 已知参考电压 3.3V，读数为 2048，对应输入电压是多少？

输入电压=ADC读数/满量程（12位是4096）\*参考电压

Vin =2048 / 4096 × 3.3V = 1.65V

### 如何配置 ADC 的采样时间以适应不同信号源内阻？

ADC 采样时间配置的核心是保证采样电容有足够时间充电到输入电压，且误差小于 0.5 LSB。信号源内阻越大，充电越慢，采样时间必须越长。

内部采样保持电容通过外部信号源内阻和ADC 内部采样开关导通电阻充电，

先算等效电阻 R=R_source+R_sw=11kΩ，再算时间常数 τ=R×C_adc=88ns，然后再算最小采样时间由 12 位精度要求误差<0.5LSB 得 t_min=9τ=792ns，换算成 ADC 周期数 N=t_min/T_ADCCLK≈11.1，最后查档位选择最接近且大于计算值的采样周期。

### ADC 支持哪些转换模式？（单次/连续/扫描/间断）

支持四种转换模式：单次、连续、扫描、间断。

单次是触发一次转一个通道后停止，连续是触发一次后反复自动转换，扫描是一次触发依次转换多个通道，必须配合 DMA，间断是把扫描序列分成若干小组，每次触发只转一组

### ADC 有哪些触发方式？

软件触发：向 CR2 写 SWSTART（规则组）/ JSWSTART（注入组）启动

外部事件触发：通过定时器 TRGO、EXTI 线、定时器捕获/比较事件等触发转换

规则组和注入组：各自独立的触发源选择寄存器，可以分别配置。触发边沿可选上升沿、下降沿或双边沿

实战中，单次采样用软件触发，周期性采样用定时器 TRGO 触发，外部事件同步用 EXTI 触发。常见组合是定时器触发 + 扫描 + DMA，实现多通道连续采样不占 CPU。

### ADC 的数据对齐方式有哪些？

右对齐：12 位数据放在寄存器低 12 位（DATA[11:0]），高 4 位为 0，读出后直接使用。

左对齐：数据放在高 12 位（DATA[15:4]），低 4 位为 0，主要用于需要直接截取高 8 位结果的场景。

### 单通道 ADC 轮询模式的代码流程是什么？

HAL 库流程：

1. 使能 ADC1 时钟（`__HAL_RCC_ADC1_CLK_ENABLE`），配置 ADC 时钟分频（ADC 时钟 = APB2 / 分频，不超过 14MHz）。
2. 将采样引脚 GPIO 配置为模拟输入（`GPIO_MODE_ANALOG`）。
3. 配置 ADC 句柄：分辨率、对齐方式、扫描/连续模式、触发方式（软件触发）。
4. 配置规则通道：通道号、采样时间（`ADC_ChannelConfTypeDef`）。
5. 使能 ADC 并校准：F1 需调用 `HAL_ADCEx_Calibration_Start`，上电校准可提高精度。
6. 启动软件转换：`HAL_ADC_Start`。
7. 轮询等待转换完成：`HAL_ADC_PollForConversion(&hadc, 超时)`。
8. 读取结果：`HAL_ADC_GetValue(&hadc)`。
9. 不需要时调用 `HAL_ADC_Stop` 停止。

```c
__HAL_RCC_ADC1_CLK_ENABLE();          // 1. 使能时钟（ADC时钟=APB2/6=12MHz）

GPIO_InitTypeDef GPIO_InitStruct = {0};// 2. 引脚模拟输入
GPIO_InitStruct.Pin = GPIO_PIN_0;
GPIO_InitStruct.Mode = GPIO_MODE_ANALOG;
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

hadc1.Instance = ADC1;                // 3. 配置句柄
hadc1.Init.ScanConvMode = DISABLE;    //    单通道非扫描
hadc1.Init.ContinuousConvMode = DISABLE;
hadc1.Init.ExternalTrigConv = ADC_SOFTWARE_START;
hadc1.Init.DataAlign = ADC_DATAALIGN_RIGHT;
HAL_ADC_Init(&hadc1);

ADC_ChannelConfTypeDef sConfig = {0}; // 4. 规则通道 PA0 = 通道0
sConfig.Channel = ADC_CHANNEL_0;
sConfig.SamplingTime = ADC_SAMPLETIME_55CYCLES_5;
HAL_ADC_ConfigChannel(&hadc1, &sConfig);

HAL_ADCEx_Calibration_Start(&hadc1);  // 5. 校准

HAL_ADC_Start(&hadc1);                // 6. 启动
HAL_ADC_PollForConversion(&hadc1, 100);// 7. 等待EOC
uint16_t value = HAL_ADC_GetValue(&hadc1); // 8. 读结果
```

### 为什么要使用 ADC+DMA？

连续转换模式下，每次转换完成都需要 CPU 及时读走 DR，否则新结果会覆盖旧数据；多通道扫描时搬运量更大，会占用大量 CPU 时间。

DMA 可在 ADC 转换完成（EOC 触发 DMA 请求）时自动把 DR 数据搬运到内存缓冲区，CPU 零参与，只需在缓冲区取用数据。

多通道扫描 + DMA + 循环模式：转换结果按通道顺序自动存入数组，硬件自动完成采样-搬运-循环，CPU 可并行处理显示、控制、通信等任务。

适用于多路传感器采集、音频采样、示波器/波形采集等需要高速连续采样的应用。

### 什么是 ADC 过采样？有什么好处？

ADC 过采样就是用远高于信号所需采样率的频率，对信号进行多次采样，然后累加平均或抽取，用多次采样换取更高的有效分辨率。

每 4 倍过采样理论上可以提高 1 位有效分辨率，同时抑制随机噪声、提高信噪比。

好处是提高精度、抗混叠、平滑信号

代价是转换时间变长、吞吐率下降。

适合温度、压力、电池电压等低速高精度测量，不适合高速信号

### ADC 注入组和规则组有什么区别？

规则组最多 16 个通道，优先级低，只有一个数据寄存器 ADC_DR，多通道时必须配合 DMA

注入组最多 4 个通道，优先级高，可以打断规则组转换，每个通道有独立的 JDR1\~JDR4 数据寄存器，不需要 DMA。

两者触发源独立，规则组正序转换，注入组倒序转换。规则组用于常规周期采样，注入组用于紧急插队或同步采样

*注意：规则组存在的意义：一是规则序列最大长度是 16，但 ADC1 最多可有 19 个通道，且同一个通道还可以占据多个规则序列位置，需要注入序列来覆盖更多通道。二是突发情况需要临时打断规则序列的转换。*

### ADC 读数为 0 或偏小，可能是什么原因？

参考电压问题：VREF+ 或 VDDA 异常会直接导致读数出错，需要用万用表测 VREF+ 是否为稳定的 3.3V。

信号源和引脚问题：比如信号源内阻过大、引脚虚焊、引脚被配成其他功能、内部上下拉未关闭，导致实际到达引脚的电压偏低。

软件配置问题：比如没开时钟、通道选错、对齐方式搞错、没有校准、触发源配置错误。

采样时间问题：高内阻信号源采样时间不够，电容充不满，读数偏小。

排查顺序：先测参考电压和引脚电压，再检查软件配置，最后加大采样时间验证

## 内部集成电路总线（I2C）

### I2C 是什么？特点？

I2C内部集成电路总线，是一种同步、半双工、多主多从的串行通信总线特点：

- 两线制：SCL（时钟线）+ SDA（数据线），占用引脚少、布线简单
- 同步、半双工：由主机产生 SCL 时钟按位同步传输，任一时刻只能单向发送
- 多主多从：支持多主机总线仲裁，每个从机有唯一 7 位（可选 10 位）地址
- 开漏输出 + 上拉电阻：线与（wired-AND）结构，天然支持多设备挂接与电平转换
- 速率标准：标准模式 100kbit/s、快速模式 400kbit/s、高速模式 3.4Mbit/s
- 应答机制：每字节传输后接收方回 ACK/NACK，保证传输可靠
- 每次传输以 START 开始、STOP 结束，数据帧长度灵活

### 描述 I2C 主设备连接从设备的寻址过程。

1. 发起起始信号（Start）：主设备在SCL为高电平期间，将SDA线由高拉低，产生起始条件，总线进入忙状态。
2. 发送地址帧（7位/10位）：主设备发送从机地址，通常为7位地址，高位（MSB）先发。
3. 发送读写位（R/W）：紧跟在地址后的第8位是数据方向位，0表示写（发送），1表示读（接收）。
4. 等待应答（ACK/NACK）：发送完前8位后，主设备释放SDA线，在第9个时钟周期检测SDA电平。若从机地址匹配，从机会拉低SDA发出ACK应答；若无匹配从机，SDA保持高电平为NACK。
5. 数据传输与停止：收到ACK后，主从设备开始按字节（8位+1位ACK）进行数据传输。通信结束时，主设备在SCL为高时拉高SDA，产生停止信号（Stop）释放总线

### 画出 I2C 的相关信号时序图：

#### **开始信号&停止信号时序图：**

**开始信号 START**：SCL 保持高电平时，SDA 由高电平跳变为低电平（先让 SDA 为高，再拉高 SCL，然后拉低 SDA）。

```text
SCL:  -----+        +----------
           |        |
           +--------+
SDA:  ---------+
               +----------
    ^ SDA 在 SCL 高电平期间由高变低 = START
```

**停止信号 STOP**：SCL 保持高电平时，SDA 由低电平跳变为高电平（先让 SDA 为低，再拉高 SCL，然后拉高 SDA）。

```text
SCL:  -----+        +----------
           |        |
           +--------+
SDA:  ---------+        +----------
               +--------+
    ^ SDA 在 SCL 高电平期间由低变高 = STOP
```

#### **应答信号&非应答信号时序图：**

每个字节（8 位）传输完后，**第 9 个时钟周期为应答位**，此时 SDA 控制权交给接收方：

- **ACK（应答）**：接收方在第 9 个时钟高电平期间把 SDA 拉低，表示"已收到，请继续"。
- **NACK（非应答）**：接收方不拉低 SDA（保持高），表示"不再接收 / 无此设备 / 数据异常"。

```text
        第1~8位(数据)    第9位(ACK)
SCL:  -----+   +-+   +-+   +-
           |   | |   | |   |
           +---+ +---+ +---+
SDA:  -- D7 -- D6 -- ... -- D0 -- +   <- 接收方拉低 = ACK
                                   +-- (保持高 = NACK)
```

主机发送数据后：从机应答（ACK）则继续发下一字节；收到 NACK 则发 STOP 或重复 START 结束本次传输。

#### **数据传输时序图：**

数据传输遵循"**SCL 高电平数据稳定、SCL 低电平数据变化**"原则：

- 每个 SCL 周期传输 1 位数据，**MSB 先行**（高位在前）。
- SCL 低电平时发送方改变 SDA 电平；SCL 高电平时 SDA 保持稳定，接收方在此时采样。
- 8 位数据后跟 1 个 ACK 位，构成一个完整字节帧。

```text
SCL:  --+   +-+   +-+   +-+   +-
         |   | |   | |   | |   |
         +---+ +---+ +---+ +---+
SDA:  -- D7 -- D6 -- D5 -- ... -- D0 -- ACK
         ^           ^
     SCL 低电平    SCL 高电平
     允许 SDA 变化  SDA 必须稳定(采样点)
```

### 画出或文字描述出 I2C 的通信协议：

#### 主机给从机发送一个字节的通信协议

主机发起，寻址写，发送1字节，结束。

1. 起始：主机在SCL高电平期间拉低SDA，发出Start信号。
2. 寻址：主机发送“7位从机地址 + 0（写）”。
3. 从机应答：匹配的从机在第9个时钟周期拉低SDA，发出ACK。
4. 发送数据：主机发送8位数据（高位先发）。
5. 从机应答：从机接收完8位数据后，再次拉低SDA发出ACK。
6. 停止：主机在SCL高电平期间拉高SDA，发出Stop信号，释放总线。

#### 主机给从机连续发送多个字节的协议

主机发起，寻址写，循环发送N个字节，结束。

1. 起始：主机发出Start信号。
2. 寻址：主机发送“7位从机地址 + 0（写）”。
3. 从机应答：匹配从机发出ACK。
4. 循环发送数据（核心区别）：

   - 主机发送第1个8位数据 -> 从机发出ACK。
   - 主机发送第2个8位数据 -> 从机发出ACK。
   - ...（重复此过程N次）...
   - 主机发送第N个8位数据 -> 从机发出ACK。
5. 停止：主机发出Stop信号，结束通信。

#### 主机接收从机发送一个字节的通信协议

主机发起，寻址读，从机发1字节，主机发NACK结束。

1. 起始：主机发出Start信号。
2. 寻址：主机发送“7位从机地址 + 1（读）”。
3. 从机应答：匹配从机发出ACK。
4. 接收数据：从机向主机发送8位数据。
5. 主机非应答（关键考点）：主机接收完8位数据后，必须发送NACK（非应答）。即主机在第9个时钟周期保持SDA为高电平，通知从机“我只要这一个字节，别再发了”。
6. 停止：主机发出Stop信号，结束通信。

#### 主机连续接收从机发送的多个字节的协议

主机发起，寻址读，循环接收，最后一个字节由主机发NACK结束。

1. 起始：主机发出Start信号。
2. 寻址：主机发送“7位从机地址 + 1（读）”。
3. 从机应答：匹配从机发出ACK。
4. 循环接收数据（核心区别）：

   - 从机发送第1个8位数据 -> 主机发送ACK（拉低SDA，告诉从机“继续发下一个”）。
   - 从机发送第2个8位数据 -> 主机发送ACK。
   - ...（重复此过程N-1次）...
   - 从机发送第N个（最后一个）8位数据 -> 主机发送NACK（保持SDA高电平，告诉从机“发完了，别发了”）。
5. 停止：主机发出Stop信号，结束通信。

### 简述一次完整的 I2C 写操作流程。

主设备发起起始信号，发送7位从机地址 + 0（写位），等待从机ACK应答后，开始循环发送“8位数据 + 等待ACK”，数据发送完毕后，主设备发出停止信号释放总线

### I2C 硬件接口有哪些引脚？各自作用？

I2C硬件接口主要依靠SCL串行时钟线和SDL串行数据线，外加电源和接地引脚。SCL和SDL都是采用开漏输出，必须外接上拉电阻到VCC

SCL：用于传输主设备产生的同步时钟信号。

SDA：用于在总线上双向传输数据。

电源引脚：提高工作电压。接地引脚：提供电平参考零点

### I2C 的使用场景？

主要应用于板级、短距离、低速、多器件的通信场景

传感器的数据采集、存储器和RTC实时时钟、屏幕显示模块

### I2C 的时钟速率有哪几种标准？（标准模式/快速模式/高速模式）

标准模式（Standard Mode）：100 kbit/s，最通用

快速模式（Fast Mode）：400 kbit/s，工程中最常用

快速模式+（Fast Mode Plus）：1 Mbit/s

高速模式（High-Speed Mode）：3.4 Mbit/s

### I2C 总线挂死（SDA 被拉低）如何恢复？

I2C 总线挂死通常是因为从机在通信中途被打断，一直拉低 SDA 等待时钟。

恢复方法是：先关闭 I2C 外设，把 SCL 和 SDA 配置为 GPIO 开漏输出；然后手动发送 9 个时钟脉冲，并在每个时钟高电平期间检测 SDA，如果 SDA 释放就提前结束；最后生成一个 STOP 条件，让从机复位内部状态机；再重新初始化 I2C。如果无效，可以硬件复位从机或整个系统断电重启。

预防措施是使用合适的上拉电阻、降低速率、增加总线滤波

### 分析 GPIO 模拟 I2C 通信的代码（iic_io.c）：代码拷贝到文档，所有代码加注释分析。

GPIO 模拟 I2C（软件 I2C）不依赖硬件 I2C 外设，用任意两个 GPIO 按 I2C 时序手动翻转电平实现

优点：引脚可任意选择、时序完全可控、便于调试。以下为典型 `iic_io.c` 实现（STM32 HAL 库）

```c

#define __IIC_IO_H

#include "main.h"   // 包含HAL库定义

/* 引脚定义：可根据实际接线修改 */
#define IIC_SCL_PIN       GPIO_PIN_6
#define IIC_SDA_PIN       GPIO_PIN_7
#define IIC_GPIO_PORT     GPIOB
#define IIC_GPIO_CLK_ENABLE()  __HAL_RCC_GPIOB_CLK_ENABLE()

/* IO操作宏：写SCL/SDA，读SDA */
#define IIC_SCL_H()   HAL_GPIO_WritePin(IIC_GPIO_PORT, IIC_SCL_PIN, GPIO_PIN_SET)
#define IIC_SCL_L()   HAL_GPIO_WritePin(IIC_GPIO_PORT, IIC_SCL_PIN, GPIO_PIN_RESET)

#define IIC_SDA_L()   HAL_GPIO_WritePin(IIC_GPIO_PORT, IIC_SDA_PIN, GPIO_PIN_RESET)
#define IIC_SDA_READ()  HAL_GPIO_ReadPin(IIC_GPIO_PORT, IIC_SDA_PIN)

/* 函数声明 */
void IIC_Init(void);
```

```c
#include "iic_io.h"

/* 微秒级延时：简单循环，可根据主频调整 */
static void IIC_Delay(void)
{
    // 72MHz下，循环约5次大概1us，具体用示波器校准
    for (volatile uint32_t i = 0; i < 10; i++);
}

/* 初始化I2C引脚：开漏输出，外部需接上拉电阻（通常4.7kΩ） */
void IIC_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    IIC_GPIO_CLK_ENABLE();  // 使能GPIOB时钟

    GPIO_InitStruct.Pin = IIC_SCL_PIN | IIC_SDA_PIN;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_OD;  // 开漏输出
    GPIO_InitStruct.Pull = GPIO_NOPULL;          // 外部已有上拉，内部不再开
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_HIGH;
    HAL_GPIO_Init(IIC_GPIO_PORT, &GPIO_InitStruct);

    // 初始状态：释放总线，SCL和SDA都为高
    IIC_SCL_H();
    IIC_SDA_H();
}

/* 产生起始信号：SCL高电平期间，SDA由高变低 */
void IIC_Start(void)
{
    IIC_SDA_H();       // 先确保SDA为高
    IIC_SCL_H();       // SCL拉高
    IIC_Delay();
    IIC_SDA_L();       // SCL高时，SDA拉低 → 起始条件
    IIC_Delay();
    IIC_SCL_L();       // 钳住SCL，准备发送数据
    IIC_Delay();
}

/* 产生停止信号：SCL高电平期间，SDA由低变高 */
void IIC_Stop(void)
{
    IIC_SDA_L();       // 先确保SDA为低
    IIC_SCL_H();       // SCL拉高
    IIC_Delay();
    IIC_SDA_H();       // SCL高时，SDA拉高 → 停止条件
    IIC_Delay();
}

/* 发送一个字节：MSB先发，共8位 */
void IIC_Send_Byte(uint8_t txd)
{
    for (uint8_t i = 0; i < 8; i++)
    {
        // 准备数据位：从最高位开始
        if (txd & 0x80)
            IIC_SDA_H();
        else
            IIC_SDA_L();
        txd <<= 1;         // 左移，准备下一位
        IIC_Delay();
        IIC_SCL_H();       // 拉高SCL，从机采样
        IIC_Delay();
        IIC_SCL_L();       // 拉低SCL，准备下一位
        IIC_Delay();
    }
}

/* 等待从机应答：返回0表示ACK，1表示NACK */
uint8_t IIC_Wait_Ack(void)
{
    uint8_t ack = 0;
    IIC_SDA_H();          // 主机释放SDA（开漏输出写1）
    IIC_Delay();
    IIC_SCL_H();          // 拉高SCL，从机应在此时拉低SDA
    IIC_Delay();
    if (IIC_SDA_READ())   // 读SDA，若为高则表示NACK
        ack = 1;
    else
        ack = 0;
    IIC_SCL_L();          // 拉低SCL，结束应答位
    IIC_Delay();
    return ack;
}

/* 主机发送应答（ACK） */
void IIC_Ack(void)
{
    IIC_SDA_L();          // 拉低SDA表示应答
    IIC_Delay();
    IIC_SCL_H();
    IIC_Delay();
    IIC_SCL_L();
    IIC_Delay();
    IIC_SDA_H();          // 释放SDA
}

/* 主机发送非应答（NACK） */
void IIC_NAck(void)
{
    IIC_SDA_H();          // 保持SDA高表示非应答
    IIC_Delay();
    IIC_SCL_H();
    IIC_Delay();
    IIC_SCL_L();
    IIC_Delay();
}

/* 读取一个字节：ack=1时发送ACK，ack=0时发送NACK */
uint8_t IIC_Read_Byte(uint8_t ack)
{
    uint8_t receive = 0;
    IIC_SDA_H();          // 释放SDA，准备输入
    for (uint8_t i = 0; i < 8; i++)
    {
        receive <<= 1;    // 左移一位，准备接收新位
        IIC_SCL_H();      // 拉高SCL，从机输出数据
        IIC_Delay();
        if (IIC_SDA_READ())  // 读SDA，高位在前
            receive |= 0x01;
        IIC_SCL_L();      // 拉低SCL，准备下一位
        IIC_Delay();
    }
    if (ack)
        IIC_Ack();        // 发送应答
    else
        IIC_NAck();       // 发送非应答
    return receive;
}

/* 向指定设备的指定寄存器写入一个字节（以AT24C02为例） */
void IIC_WriteReg(uint8_t dev_addr, uint8_t reg_addr, uint8_t data)
{
    IIC_Start();
    IIC_Send_Byte(dev_addr << 1 | 0); // 设备地址+写方向
    IIC_Wait_Ack();
    IIC_Send_Byte(reg_addr);          // 寄存器地址
    IIC_Wait_Ack();
    IIC_Send_Byte(data);              // 要写入的数据
    IIC_Wait_Ack();
    IIC_Stop();
}

/* 从指定设备的指定寄存器读取一个字节 */
uint8_t IIC_ReadReg(uint8_t dev_addr, uint8_t reg_addr)
{
    uint8_t data;
    IIC_Start();
    IIC_Send_Byte(dev_addr << 1 | 0); // 设备地址+写
    IIC_Wait_Ack();
    IIC_Send_Byte(reg_addr);          // 寄存器地址
    IIC_Wait_Ack();

    IIC_Start();                      // 重复起始条件
    IIC_Send_Byte(dev_addr << 1 | 1); // 设备地址+读
    IIC_Wait_Ack();
    data = IIC_Read_Byte(0);          // 读一个字节，发NACK
    IIC_Stop();
    return data;
}
```

要点分析：

1. 开漏输出 + 外部上拉  
SCL 和 SDA 配置为 `GPIO_MODE_OUTPUT_OD`。写 1 时引脚为高阻态，靠外部上拉电阻拉高；写 0 时强拉低。这样既实现了线与，又可以直接读 `IDR` 获取总线电平，不需要频繁切换输入/输出模式。
2. 延时函数  
`IIC_Delay()` 是一个简单的空循环，实际延时约 1\~2µs，对应约 200\~400kHz 的 I2C 速率。可根据从机支持的最大速率调整循环次数。
3. 时序核心

   - 起始：SCL 高时 SDA 下降沿。
   - 停止：SCL 高时 SDA 上升沿。
   - 发送字节：SCL 低时改变 SDA，SCL 高时从机采样。
   - 等待应答：第 9 个时钟周期，主机释放 SDA，从机拉低表示 ACK。
4. 重复起始（Restart）  
在 `IIC_ReadReg` 中，先写寄存器地址，然后再次发送起始信号，再发读地址。这是 I2C 读寄存器的标准流程，避免中间释放总线。
5. 设备地址  
`dev_addr` 是 7 位地址，发送时左移 1 位，最低位补读写方向。例如 AT24C02 地址为 `0xA0`（写），`0xA1`（读），7 位地址是 `0x50`。

## 串行外设接口（SPI）

### SPI 是什么？特点？

SPI串行外设接口是一种高速、全双工、同步串行通信总线，广泛用于 MCU 与外围器件的高速数据交换。

特点：

四线制：SCLK、MOSI、MISO、CS 四根线，结构简单

全双工：MOSI/MISO 可同时收发，互不干扰

同步：由主机产生 SCLK 时钟，按位同步传输，无波特率匹配问题

高速：速率可达几十 MHz（STM32F1 最高约 PCLK/2），远超 I2C/UART

一主多从：通过片选线 CS 硬选从机，无需软件寻址，开销小

无应答机制：协议层不含 ACK，可靠性靠协议校验与状态查询保证

四种工作模式：由 CPOL（时钟极性）/ CPHA（时钟相位）组合决定采样边沿

### SPI 总线由哪几根线组成？各自的作用是什么？

SPI 总线由 4 根线组成：

SCLK串行时钟线：同步时钟，由主机产生，决定数据收发的节奏。

MOSI主机输出从机输入：主设备输出、从设备输入，用于主机向从机发送数据。

MISO主机输入从机输出：主设备输入、从设备输出，用于从机向主机回传数据。

CS/SS片选线：片选信号，低电平有效，主机拉低哪个从机的 CS，就表示要和哪个从机通信

### SPI 的四种模式是什么？分别画图表示。

SPI 的四种模式由 CPOL（时钟极性）和 CPHA（时钟相位）两个位组合决定：

CPOL：决定 SCLK 空闲电平。CPOL=0 空闲为低电平，CPOL=1 空闲为高电平。

CPHA：决定数据采样边沿。CPHA=0 在第一个边沿采样，CPHA=1 在第二个边沿采样。

```text
Mode 0：CPOL=0（空闲低）, CPHA=0（第一个边沿=上升沿采样）
SCLK:  ___+----+___+----+___+----+___
           |    |    |    |    |    |
           +----+    +----+    +----+
           ^         ^         ^       <- 上升沿采样点
MOSI:  -- D7 ------ D6 ------ D5 -- ...

Mode 1：CPOL=0（空闲低）, CPHA=1（第二个边沿=下降沿采样）
SCLK:  ___+----+___+----+___+----+___
           |    |    |    |    |    |
           +----+    +----+    +----+
               ^         ^         ^   <- 下降沿采样点
MOSI:  -- D7 ------ D6 ------ D5 -- ...

Mode 2：CPOL=1（空闲高）, CPHA=0（第一个边沿=下降沿采样）
SCLK:  ---+____+----+____+----+____+---
           |    |    |    |    |    |
           +----+    +----+    +----+
           ^         ^         ^       <- 下降沿采样点
MOSI:  -- D7 ------ D6 ------ D5 -- ...

Mode 3：CPOL=1（空闲高）, CPHA=1（第二个边沿=上升沿采样）
SCLK:  ---+____+----+____+----+____+---
           |    |    |    |    |    |
           +----+    +----+    +----+
```

### 画出 Mode 0 下的 SPI 时序图，并标注出采样点。

Mode 0（CPOL=0，CPHA=0）：SCLK 空闲低电平，**上升沿采样、下降沿切换数据**，MSB 先行，一次传输 8 位（可配置）。

```text
CS   ‾‾‾‾\___________________________________________________________/‾‾‾‾
         拉低（选中从机）                                          拉高（取消选中）

SCK  ______/‾‾‾\___/‾‾‾\___/‾‾‾\___/‾‾‾\___/‾‾‾\___/‾‾‾\___/‾‾‾\___/‾‾‾\______
          ↑    ↓   ↑   ↓   ↑   ↓   ↑   ↓   ↑   ↓   ↑   ↓   ↑    ↓   ↑    ↓
         采样1    采样2   采样3    采样4    采样5   采样6    采样7    采样8
```

时序要点：

1. 主机先拉低 **CS**，选中从机并通知其开始监听时钟。
2. SCLK 输出连续 8 个时钟脉冲，空闲为低电平。
3. 每个**上升沿**，主机与从机互相采样对方数据线（主机采 MOSI 发来的方向即从机读 MOSI；从机在上升沿前把 MISO 数据准备好）。
4. 8 个时钟后一个字节完成，主机拉高 **CS** 结束传输。

HAL 库一次字节传输：`HAL_SPI_Transmit(&hspi1, &data, 1, 100)`。

### SPI 的使用场景？

SPI 适合高速、全双工、协议简单（无寻址开销），因此它最适合板内、短距离、大数据量、对速度要求高的场景。支持SPI的设备模式

第一是存储器，如 SPI Flash 和 SD 卡

第二是显示设备，如 TFT 屏幕，追求高刷新率

第三是高速传感器和 ADC/DAC

第四是通信模块，如无线模块和以太网控制器。

### 描述一次 SPI 写操作的完整流程（主设备发送一个字节到从设备）。

选中从机：主机把目标从机的 CS 引脚拉低，从机被激活。

准备数据：主机将要发送的字节写入发送数据寄存器（TX），硬件自动移入移位寄存器。

输出时钟：主机产生 SCLK 时钟脉冲，从机按其采样边沿读取 MOSI。

逐位发送：每个时钟周期移位寄存器移出 1 位到 MOSI（MSB 先行），共 8 位；同时从机在 MISO 上回发自己的数据（全双工，即使只写也会收到一字节，常用作回读/状态）。

完成检测：主机等待传输完成标志（TXE/BSY）或超时，读走 MISO 收到的数据。

结束：拉高 CS，释放从机。

### 如何在一个 SPI 总线上连接多个从设备？可以有哪几种连接方式？做个对比。

SPI 总线多从机连接有两种方式：独立片选和菊花链。

独立片选是 SCK、MOSI、MISO 共享，每个从机各占一根 CS，主机通过拉低对应从机的 CS 来选中它，优点是灵活、速率不受限，缺点是用引脚多。

菊花链是 CS 共享，数据从主机 MOSI 进入从机1，从机1 输出接到从机2 输入，像接力棒一样串下去，最后从最后一个从机接回 MISO，优点是省引脚，缺点是速率受限、必须整链一起通信、而且从机必须支持菊花链模式。

### SPI 没有应答机制，如何确保数据正确接收？

通过软件方式实现：

第一，读状态寄存器，检查 BUSY、错误标志

第二，读回验证，写入后读回来比对

第三，CRC 校验，适合大块数据传输

第四，利用全双工特性，主机发数据时从机通过 MISO 回传状态

第五，应用层自定义请求-应答协议

### 什么是 SPI 的"三线制"模式？

三线制 SPI 是把标准四线 SPI 的 MOSI 和 MISO 合并成一根双向数据线 SDIO，只剩 SCK、SDIO、CS 三根线。

因为只有一根数据线，所以它是半双工通信，主机通过切换引脚方向来分时收发。

优点是省一根引脚和一根 PCB 走线，缺点是速度减半、需要方向切换，只有支持三线协议的从机才能用。

常见的三线 SPI 器件有部分 ADC、EEPROM、OLED 驱动和 RC522 读卡芯片

### 如何处理 SPI 从设备的"忙状态"？

SPI 从设备在执行内部操作时，会进入忙状态（Busy），此时它不响应新的 SPI 命令。主机必须等它忙完，才能继续通信

第一，查询状态寄存器，读 BUSY 位直到清零，最通用

第二，检测专用的 BUSY 或 RDY 引脚，不占用 SPI 总线

第三，固定延时，根据数据手册等待最大操作时间，简单但浪费时间

第四，用中断方式，从机的 DRDY（Data Ready）引脚接到 EXTI，CPU 完全解放

第五，DMA + 状态查询，适合大批量数据传输。

实战中，Flash 常用状态寄存器轮询，ADC 和传感器常用 DRDY 中断，屏幕刷图用 DMA。

## 定时器（TIM）

### STM32 定时器有哪些类型？它们之间有什么区别？

STM32（F1 系列）定时器按功能从弱到强分**三种**：

基本定时器（TIM6/TIM7）：只有时基（定时）功能，无输入捕获/输出比较，主要用于定时、触发 DAC 转换。

通用定时器（TIM2/3/4/5）：具备时基 + 输入捕获 + 输出比较 + PWM + 编码器接口等功能，最常用（TIM2/TIM5 为 32 位计数器）。

高级定时器（TIM1/TIM8）：包含通用定时器全部功能，额外支持互补输出、死区插入、刹车输入，用于电机控制等。

| 对比项 | 基本定时器 | 通用定时器 | 高级定时器 |
|-|-|-|-|
| 代表 | TIM6/TIM7 | TIM2/3/4/5 | TIM1/TIM8 |
| 计数器位数 | 16 位 | 16 位（TIM2/5 为 32 位） | 16 位 |
| 输入捕获/输出比较 | 无 | 有 | 有 |
| PWM 输出 | 无 | 有（4 通道） | 有（含互补输出） |
| 死区/刹车 | 无 | 无 | 有 |
| 典型用途 | 定时、触发 DAC | 定时/PWM/捕获/编码器 | 电机驱动、全桥控制 |

### 什么是定时器的时基单元？有哪些寄存器组成？

时基单元是定时器计数与定时的核心，由三个主要寄存器组成：

PSC（预分频器寄存器）：对输入时钟分频，分频系数 = PSC+1，把高频时钟降到可用的计数频率。

CNT（计数器寄存器）：实际计数的值，每个计数时钟沿加 1（或减 1）。

ARR（自动重装载寄存器）：计数目标值，CNT 达到 ARR 时产生更新事件（溢出），并按配置重新装载。

工作过程：时钟 → PSC 分频 → 驱动 CNT 计数 → CNT 到达 ARR → 产生更新事件（UIF 置位/触发中断或 DMA）→ CNT 归零重新计数，循环往复。

相关寄存器还有：`CR1`（控制方向/对齐）、`RCR`（重复计数寄存器，高级定时器，可让每 N 次溢出才产生一次更新）、`SR/DIER`（状态与中断使能）。

### 如何计算定时器的溢出时间？公式是什么？

定时器的溢出时间（即计数器从 0 数到 ARR 并回绕所需的时间）由定时器时钟、预分频器（PSC）和自动重装载值（ARR）共同决定。

定时器溢出时间（更新周期）公式：

**T_overflow = (PSC+1) × (ARR+1) / f_ck**

其中：PSC 为预分频值，ARR 为自动重装载值，f_ck 为定时器输入时钟频率。

换算成频率：**f = f_ck / ((PSC+1) × (ARR+1))**

例：f_ck = 72MHz，PSC = 7199（分频 7200 倍），ARR = 999：

T = 7200 × 1000 / 72MHz = **0.1s = 100ms**，即每 100ms 溢出一次。

***注意：16 位定时器 PSC/ARR 最大 65535（TIM2/TIM5 为 32 位）；ARR 值对应 CNT 从 0 计到 ARR，共 ARR+1 个计数。***

### 定时器有哪几种计数模式？（向上/向下/中心对齐）

定时器有三种计数模式，由 CR1 的 DIR（方向）和 CMS（中心对齐）位配置：

向上计数模式：CNT 从 0 递增到 ARR 后溢出（产生更新事件），再回到 0 重新计数。最常用，定时中断、普通 PWM 都用它。

向下计数模式：CNT 从 ARR 递减到 0 后溢出，再重装载为 ARR。适合倒计时类应用。

中心对齐模式（向上/向下）：CNT 先向上数到 ARR，再向下数到 0，形成三角波，在顶部和底部各产生一次更新事件（或仅顶部）。用于需要对称波形的 PWM（如电机控制、H 桥驱动）。

### 定时器有哪些时钟源？

四类时钟源：

第一，内部时钟 CK_INT，来自 APB 总线，经倍频后得到，最常用

第二，外部时钟模式 1，来自外部引脚 ETR、TI1、TI2，可用于脉冲计数和编码器

第三，外部时钟模式 2，仅来自 ETR 引脚，经预分频后直接作为计数时钟

第四，内部触发输入 ITRx，来自其他定时器的 TRGO，用于定时器同步和级联。

基本定时器 TIM6/TIM7 只支持内部时钟，通用和高级定时器支持全部四类

### 什么是 PWM？什么是占空比？

PWM 是脉冲宽度调制，它用数字方波的高电平时间比例来模拟模拟量。在一个周期内，高电平时间越长，负载感受到的平均电压或功率就越大。

占空比就是高电平时间占整个周期的百分比。比如占空比 50%，平均电压就是电源电压的一半

STM32 用定时器产生 PWM，频率由 PSC 和 ARR 决定，占空比由 CCRx 决定。PWM 广泛用于 LED 调光、电机调速、舵机控制和 D/A 转换

### PWM 的频率和占空比分别由哪些寄存器决定？

以最常用的边沿对齐向上计数模式为例：

PWM 频率由 **PSC** 和 **ARR** 决定：f_PWM = f_ck / ((PSC+1) × (ARR+1))。PSC 分频时钟，ARR 决定一个周期的计数个数。

PWM 占空比由 **CCRx（捕获/比较寄存器）**决定：占空比 = CCR / (ARR+1) × 100%。当 CNT < CCR 时输出有效电平，CNT ≥ CCR 时翻转。

### 高级定时器的互补输出和死区插入是什么？

互补输出是高级定时器 TIM1/TIM8 特有的功能，每个通道除了正常的 OCx 输出外，还有一个互补的 OCxN 输出，两者电平相反，用于驱动 H 桥或三相逆变器的上下桥臂。

死区插入是为了防止上下桥臂直通短路：在互补输出切换时，强制插入一段两者都关断的时间，即死区时间，由 BDTR 寄存器的 DTG 位配置。死区时间必须大于 MOS 管的关断时间，确保一个桥臂完全关断后，另一个才导通。高级定时器还支持刹车输入，过流时能立即封锁输出，保护功率管。

这些功能主要用于电机控制和数字电源

配套还有刹车输入（BKIN）：检测到故障（过流/过压）时硬件强制输出安全电平并关断 PWM，保证系统安全。

### 什么是输入捕获？能用来做什么？

输入捕获：定时器在输入引脚检测到指定边沿（上升沿/下降沿）时，硬件把当前 CNT 计数器的值自动锁存到 CCRx 寄存器，并产生捕获事件（中断/标志）。无需 CPU 参与，精度可达 1 个计数时钟。作用：

测量脉冲宽度/周期：连续两次捕获同一沿，差值 × 计数时钟周期 = 周期/脉宽（频率计、脉宽测量）。

PWM 输入测量：一路测频率、一路测占空比，如读取遥控器/传感器 PWM 信号。

外部事件计时：记录事件发生的精确时刻（如编码器脉冲、外部中断时刻）。

超声波测距：测量回波高电平脉宽换算距离。

与编码器配合：辅助计算速度/位置。

### 如何用定时器测量一个高电平的脉冲宽度？

用输入捕获测量高电平脉冲宽度（两次捕获法）：

1. 把通道配置为输入捕获，先捕获上升沿：硬件把 CNT 值锁存到 CCR1，记录 T1。
2. 切换捕获极性为下降沿，再捕获一次：记录 T2。
3. 高电平脉宽 = (T2 - T1) × 单个计数周期 = (T2 - T1) × (PSC+1) / f_ck。

*注意：若脉宽可能超过 CNT 溢出周期，还需在更新中断里累计溢出次数，否则计数会回绕（可把 PSC 调大使计数周期足够长）。*

### 定时器配置好后，为什么一启动就立刻进入中断？

根本原因：更新事件标志（UIF）在配置阶段已经被置位了，启动中断后它立刻触发了一次

定时器一启动就进中断，是因为在配置时基单元时（写 PSC 和 ARR），硬件会自动产生一次更新事件，把 UIF 标志置 1。此时中断还没使能，标志位一直挂着。当你调用 HAL_TIM_Base_Start_IT 使能中断后，硬件检测到 UIF=1 且 UIE=1，立刻触发一次中断。

解决方法：

启动前清除更新标志：`__HAL_TIM_CLEAR_FLAG(&htim, TIM_FLAG_UPDATE)` 或调用 `HAL_TIM_Base_Start_IT` 后再主动清一次。

养成顺序习惯：配置 → 清标志 → 使能中断 → 启动计数。

若用寄存器，检查 `TIM->SR` 的 UIF 并写 0 清除。

### HAL_Delay() 为什么不能在中断服务函数中使用？

HAL_Delay() 不能在中断服务函数（ISR）中使用，原因：

它是忙等（阻塞）函数：HAL_Delay 基于 SysTick 的 uwTick 变量做 while 轮询，在中断里会长时间占用 CPU，阻塞同优先级及更低优先级中断，实时性崩溃。

中断嵌套优先级问题：如果该中断优先级高于 SysTick（或 SysTick 被屏蔽/暂停），uwTick 不再增长，HAL_Delay 会永远等待（死循环卡死）。

不可重入/非中断安全：若主循环正在调用 HAL_Delay，此时中断里又调用它，状态互相干扰；在 SysTick 中断里调用则直接死锁。

替代方案：

中断里需要"延时"时，改用非阻塞方式：置标志/启动定时器，把耗时处理放到主循环或任务中。

用定时器中断产生精确延时（硬件定时器不依赖 SysTick）。

RTOS 中在任务里用 `osDelay`（它让出 CPU，不在中断里用）。

### SysTick（系统滴答定时器）是什么？它和通用定时器有什么区别？

SysTick（系统滴答定时器）是 Cortex-M 内核自带的24 位递减计数器，专门用于提供系统时基（节拍）。HAL 库配置它每 1ms 产生一次中断，维护全局变量 uwTick，HAL_Delay/HAL_GetTick 都基于它。区别：

| 对比项 | SysTick | 通用定时器（TIMx） |
|-|-|-|
| 归属 | Cortex-M 内核外设（所有 M3/M4 都有） | 芯片厂商外设（挂在 APB 总线） |
| 计数器位数 | 24 位 | 16 位（TIM2/5 为 32 位） |
| 功能 | 仅递减计数 + 中断（作时基） | 定时/PWM/输入捕获/编码器等丰富功能 |
| 时钟 | HCLK 或 HCLK/8（可配置） | APB1/APB2 预分频时钟 |
| 主要用途 | 系统节拍、RTOS tick、HAL 延时基准 | 具体硬件时序（PWM、测量、计数） |

一句话：SysTick 是"系统心跳"，通用定时器是"干活的外设"。

### 独立看门狗和窗口看门狗有什么区别？

独立看门狗（IWDG）和窗口看门狗（WWDG）都用于防程序跑飞，但IWDG 只防死机不喂狗（程序卡死）；WWDG 还能防程序错乱乱喂狗

| 对比项 | 独立看门狗 IWDG | 窗口看门狗 WWDG |
|-|-|-|
| 时钟源 | LSI 独立 RC（约 40kHz），不依赖主时钟 | PCLK1（APB1 主时钟），依赖系统时钟 |
| 喂狗时机 | 任意时刻喂（溢出前即可） | 必须在**窗口期内**喂（过早/过晚都复位） |
| 计数器 | 12 位递减（独立预分频） | 7 位递减 + 窗口比较 |
| 可关闭 | 启动后不可关闭，抗干扰强 | 由软件位控制，可关闭 |
| 中断 | 无 | 有提前唤醒中断（EWI），可在复位前处理 |
| 超时范围 | 较宽，可到数秒 | 较短，μs\~ms 级 |

## 灵活静态存储器控制器（FSMC）

### 什么是 FSMC？它的核心作用是什么？

FSMC是灵活静态存储器控制器

核心作用是用于扩展外部存储器的控制器，负责把 CPU 的 AHB 总线访问请求转换为外部存储器的读写时序作用

支持访问多种存储器类型：SRAM、ROM、NOR Flash、NAND Flash、PC 卡设备

时序可编程：读写时序可通过寄存器灵活配置，适配不同器件

降低 CPU 开销：访问由硬件完成，速度快、时序精确稳定。

### FSMC 支持哪些类型的存储器？（SRAM/PSRAM/NOR/NAND）

SRAM：静态随机存取存储器，读写速度快，无需刷新

PSRAM：伪静态 RAM，接口类似 SRAM，但内部有刷新

NOR Flash：可随机读取，支持 XIP（代码就地执行）

NAND Flash：大容量、低成本，按页读写，需坏块管理

PC Card：16 位 PC 存储卡，属于较老的接口标准

### FSMC 的 Bank 划分是怎样的？每个 Bank 支持什么设备？

FSMC 把外部地址空间 0x6000_0000 \~ 0x9FFF_FFFF 共 1GB 划分为 4 个 Bank，每个 Bank 256MB：

Bank1（0x6000_0000 \~ 0x6FFF_FFFF）：支持 NOR/PSRAM/SRAM，内部又分 4 个子区域，对应片选 NE1\~NE4，每个子区域 64MB；LCD 通常接在 NE1 上。

Bank2（0x7000_0000 \~ 0x7FFF_FFFF）：NAND Flash。

Bank3（0x8000_0000 \~ 0x8FFF_FFFF）：NAND Flash。

Bank4（0x9000_0000 \~ 0x9FFF_FFFF）：PC Card。

每个 Bank 的时序（建立时间、保持时间、位宽、突发模式等）完全独立配置，互不影响。

### 如何用 FSMC 驱动 TFT-LCD 屏幕？（8080 接口）

用 FSMC 驱动 8080 接口的 LCD，核心是把 LCD 当作一个 SRAM。

8080 接口有数据线 D0\~D15、片选 CS、写使能 WR、读使能 RD 和寄存器选择 RS。FSMC 没有 RS 引脚，所以把 LCD 的 RS 接到 FSMC 的某根地址线上（如 A0），通过访问不同地址来产生 RS 的高低电平。比如 RS 接 A0 时，访问 0x60000000 就是写命令，访问 0x60000002 就是写数据。FSMC 会自动产生 CS、WR、RD 的时序，CPU 只需要往对应地址写数据即可。

相比 GPIO 模拟，FSMC 速度快、代码简单、CPU 占用低。配置时要注意时序参数（ADDSET、DATAST 等）和 16 位数据宽度下地址的步进

### FSMC 的地址线和数据线是如何工作的？

数据线 D0\~D15（16 位模式）或 D0\~D7（8 位模式）是双向的，FSMC 根据当前是读还是写自动切换方向。在 16 位数据宽度下，FSMC 内部 HADDR 会自动右移 1 位再输出到外部地址线，因为每个地址对应 2 个字节，HADDR 的 bit0 被丢弃

地址线 A0\~A25 由 FSMC 驱动，CPU 发出访问地址后，FSMC 自动选中对应 Bank/片选并输出地址信号。

### FSMC 配置中需要设置哪些时序参数？（建立时间/保持时间等）

地址建立时间 ADDSET、地址保持时间 ADDHLD、数据建立时间 DATAST、总线周转时间 BUSTURN、时钟分频 CLKDIV 和数据延迟 DATLAT。

其中 ADDSET、DATAST、BUSTURN 是最常用的，分别控制地址建立、数据保持和读写切换的空闲时间。ADDHLD 只在地址数据复用总线上使用，CLKDIV 和 DATLAT 只在同步模式下使用。

配置时根据外部存储器数据手册的时序要求，把时间换算成 HCLK 周期数即可。如果使能扩展模式，读时序和写时序可以分别独立配置

### 为什么用 FSMC 驱动 LCD 比 GPIO 模拟快很多？

主要有四个原因：

指令数不同：GPIO 模拟一次 16 位写入需要 6\~8 条指令（写数据、拉低 WR、拉高 WR、控制 RS 和 CS 等），而 FSMC 只需要一条 STR 指令，地址译码和时序产生全部由硬件自动完成。

数据位宽：FSMC 支持 16 位总线一次传完，GPIO 模拟时数据线往往分散在多个端口，需要多条指令。

时序稳定：FSMC 硬件时序严格精确，不受中断和编译器优化影响；GPIO 模拟如果被中断打断，WR 脉冲宽度会变长，可能导致时序错误。

CPU 占用：GPIO 模拟时 CPU 全程死等，FSMC 发完指令就返回，CPU 可以去干别的事。

### FSMC 和 LTDC 有什么区别？

FSMC是静态存储器控制器，把 LCD 当作 SRAM 来操作，通过 8080 并行接口读写屏幕的寄存器/显存。屏幕自带的驱动 IC 负责刷新，CPU 需要参与数据搬运

LTDC是专用显示控制器，它直接输出 RGB 时序（VSYNC、HSYNC、DE、PCLK 和数据），驱动没有驱动 IC 的裸屏。它需要外扩 SDRAM 作为显存，硬件自动不断刷新屏幕，CPU 完全不参与，支持双图层混合

### 如何用 FSMC 外接 SRAM 扩展内存？

- 选型：确认 SRAM 容量，位宽，供电电压和封装。
- 硬件连接：数据线 D0\~D15 接 I/O0\~I/O15，地址线 A0\~A18 一一对应，CS 接 NE1，OE 接 NOE，WE 接 NWE，UB/LB 接 NBL1/NBL0
- 配置：使能 FSMC 时钟，在 CubeMX 里选择 Bank1、NE1、SRAM、16 位数据宽度，时序按 SRAM 手册设置
- 使用：SRAM 映射到 0x60000000 起始地址，可以直接用指针读写，或者用编译器扩展语法把大数组放到该地址
- 注意：SRAM 掉电数据丢失，访问速度受 FSMC 时序限制，比内部 SRAM 慢，Cortex-M4 没有 cache，不需要考虑缓存一致性

### FSMC 读写 NAND Flash 需要注意什么？

- 硬件连接上，NCE、CLE、ALE、NWE、NOE、R/B 要正确连接，R/B 用于检测忙状态。
- NAND 是页设备，不能随机字节访问，必须按命令、地址、数据的流程操作，通过 CLE 和 ALE 区分。
- 时序参数要按 NAND 手册配置，留足余量。
- 必须使用 ECC 校验，FSMC 支持硬件 ECC，写入时计算 ECC 存入 spare area，读取时校验纠错。
- 必须进行坏块管理，建立坏块表，跳过坏块。
- 写前必须先擦除，擦除按块，写入按页，操作后检查状态。
- 注意 Ready/Busy 信号，等待操作完成。
- 数据宽度、地址周期、写保护、DMA、Cache 一致性等也要注意。
- 裸机使用建议配合文件系统或 FTL，实现磨损均衡

## 数模转换器（DAC）

### 什么是 DAC？它的核心作用是什么？

DAC数模转换器，是把数字量转换成对应的模拟电压输出的设备，作用：

- 产生模拟信号：把数字代码按比例转换为 0\~VREF+ 的电压
- 输出任意波形：配合 DMA 和定时器触发，输出正弦波、三角波、锯齿波及任意自定义波形
- 模拟控制：调节音量、偏置电压、参考电压、电机/功放控制等
- 信号源：作为函数发生器、音频信号源（如播放 WAV）

### STM32 的 DAC 有几个通道？分辨率是多少？

通常有2个通道，可以单独工作也可以同时更新，分辨率为 12 位，可以配置为 8 位或 12 位模式

### DAC的输出电压范围是多少？如何计算输出电压？

DAC 的输出电压范围由参考电压决定，理论上是 VREF- 到 VREF+，通常 VREF- 接 0V，VREF+ 接 3.3V，所以范围是 0\~3.3V。但实际因为输出缓冲器的存在，输出范围会略窄，大约 0.2V 到 VREF+ 减 0.2V。

计算公式是 Vout = VREF+ × (DOR / 2^N)，其中 DOR 是写入数据寄存器的值，N 是分辨率位数。12 位时 2^N 等于 4096，如果写入 2048，输出就是 3.3 × 2048/4096 = 1.65V。最小分辨率 1 LSB 约 0.806mV

### DAC 有哪些触发方式？（软件触发/定时器触发/外部触发）

软件触发：写 SWTRIGx 位，手动控制，但每次转换都要 CPU 参与，适合低频、非周期场景

定时器触发：由定时器TIM2/4/6/7/8等的 TRGO 更新事件触发周期性自动触发，配合 DMA 可以输出任意波形，适合音频和波形发生器

外部触发：由外部事件EXTI 线9触发，适合与外部系统同步的场景。

### 什么是 DAC 的波形生成模式？可以生成哪些波形？

DAC 的波形生成模式是STM32内部硬件自动产生特定波形的功能，配置在 DAC_CR 的 WAVE 位。它可以生成两种内置波形：噪声波和三角波。

噪声波由线性反馈移位寄存器产生，输出随机跳变

三角波由内部递增/递减计数器产生，输出线性上升和下降。两种波形的幅度都由 MAMP 位控制，并且必须配合触发源，比如定时器触发或软件触发。

如果要输出正弦波、锯齿波、音频等任意波形，需要配合 DMA 和定时器触发，把波形数据表搬到 DAC 数据寄存器

### DAC+DMA 如何实现连续波形输出？

把波形采样点提前存在内存查找表 → 定时器按固定频率触发 DAC → DAC 发出 DMA 请求 → DMA 把数组中的下一个数据自动搬运到 DAC 数据寄存器 → DAC 转换输出。DMA 使用循环模式（Circular），搬运完整个表后自动回到表头继续，形成连续不断的波形，全程不需要 CPU 参与。

### DAC 的输出缓冲器（Buffer）有什么作用？什么时候需要关闭？

DAC内核直接输出的驱动能力很弱（输出阻抗高），输出缓冲器是一个内置运算放大器，用于：

增强驱动能力：能直接带动外部负载，运放输入、音频电路等

降低输出阻抗：输出电压不随负载大小而明显跌落

简化电路：隔离负载对 DAC 电阻网络的影响

什么时候关闭：需要高精度时或者低功耗应用时

### DAC 和 PWM 实现模拟输出有什么区别？

DAC是将数字量直接转换成真实的模拟电压，输出连续、精度高，不需要滤波。优点是精度高、无需滤波，适合音频和精密电压输出

PWM是通过改变高频方波的高电平时间比例（占空比）来等效模拟量，它输出的本质上还是数字方波，必须经过低通滤波器才能变成平滑的模拟电压。优点是效率极高、资源丰富、分辨率灵活，适合 LED 调光、电机调速、舵机控制

### 如何用 DAC 生成正弦波？

1. 预先在内存里生成一个周期的正弦波查找表
2. 配置定时器按固定频率产生 TRGO 触发
3. 配置 DAC 选择该定时器为触发源
4. 配置 DMA 为内存到外设、循环模式
5. 启动 DMA 和定时器，DMA 会自动把正弦表的每个点搬到 DAC 数据寄存器，DAC 转换输出，循环往复，形成连续正弦波。

### DAC 输出噪声大可能是什么原因？如何优化？

原因有：

- 电源和参考电压纹波大，VREF+ 不稳定
- 模拟地和数字地混在一起，布线不合理
- DAC 配置不当，如缓冲器使能错误、数据对齐错误、DMA 传输异常
- 数字信号耦合到模拟输出
- 负载阻抗太低或走线过长

优化措施包括：

- 在 VREF+ 和 VDDA 加去耦电容，使用高精度基准芯片
- 模拟地和数字地分开单点连接
- 缩短输出走线，远离高频信号
- 在输出端加 RC 低通滤波；根据负载决定是否使能缓冲器
- 使用 DMA 减轻 CPU 负担
- 必要时外接精密运放做缓冲

综合来看，要保证电源干净、接地合理、配置正确、滤波到位

## 看门狗（IWDG 与 WWDG）

### 什么是看门狗？它的核心作用是什么？

看门狗本质上是一个独立于 CPU 主流程运行的硬件递减计数器。

它的核心作用是监控程序是否跑飞或死机：程序正常运行时，需要周期性地喂狗（重装载计数器）；一旦程序因死循环、跑飞或硬件异常停止喂狗，计数器溢出后就会触发整个芯片复位，把系统拉回正常状态

### 独立看门狗（IWDG）和窗口看门狗（WWDG）有什么区别？

| 对比维度 | IWDG（独立看门狗） | WWDG（窗口看门狗） |
|-|-|-|
| 时钟源 | 独立的 LSI（低速内部 RC，约 40kHz），不依赖主时钟 | APB1 总线时钟 PCLK1，依赖主时钟 |
| 计数器 | 12 位递减计数器（0\~4095），减到 0 溢出复位 | 7 位递减计数器（0\~127），减到 0x3F 及以下复位 |
| 喂狗窗口 | 只要在溢出前任意时刻喂狗即可（无窗口上限） | 必须在上窗口（CR 高 6 位）与下窗口（0x40）之间喂狗：喂早或喂晚都会复位 |
| 中断 | 无中断，溢出直接复位 | 计数器到 0x40 时产生提前唤醒中断（EWI），可先保存现场再复位 |
| 关闭方式 | 一旦启动无法关闭（只能上电/外部复位） | 启动后同样有写保护，难以软件关闭 |
| 适用场景 | 检测程序完全跑飞/死机，粗粒度保护 | 检测程序执行时序被破坏（过快/过慢），更严格 |

### IWDG 的时钟源是什么？为什么叫"独立"？

是 LSI，芯片内部的低速 RC 振荡器，独立是因为 LSI 独立于主时钟树，不依赖 HSE、PLL 和 HCLK。即使主时钟挂了，LSI 依然能正常工作，IWDG 也能继续计数并复位系统

### IWDG 的超时时间如何计算？公式是什么？

IWDG 是一个 12 位递减计数器（重装载值 0\~4095），超时时间由**预分频器、重装载值和 LSI 频率**共同决定，公式为：

$$T_{out} = \frac{Prescaler \times Reload}{f_{LSI&#125;&#125; = \frac{4 \times 2^{PR} \times RLR}{f_{LSI&#125;&#125;$$

其中：`PR` 为预分频器系数（0\~6，对应分频 4/8/16/32/64/128/256，即分频系数 = 4×2^PR）；`RLR` 为重装载值（0\~4095）；`f_LSI` 约 40kHz。

举例：LSI=40kHz，PR=4（即 64 分频），RLR=625，则 $T_{out} = 64 \times 625 / 40000 = 1s$。

几个注意点：

最大超时时间：PR=6（256 分频）、RLR=4095 时，$T_{max} = 256 \times 4095 / 40000 \approx 26.2s$。

LSI 是 RC 振荡器，精度不高（频率随温度、电压漂移），设计超时时间时要留足裕量，喂狗周期不要卡在临界值上。

喂狗动作必须在超时之前完成，即喂狗周期 < T_out。

### 什么是"喂狗"？喂狗的时机和频率如何确定？

是指在计数器溢出之前，向 IWDG 的键寄存器写入 0xAAAA，把计数器重新装载为 `RLR` 设定的值，从而避免溢出复位。喂狗本质就是向看门狗"报到"，告诉它"程序还活着"。

喂狗时机和频率的确定原则：

喂狗周期 < 超时时间：一般取超时时间的 1/2 \~ 1/4 作为裕量，抵消 LSI 精度误差和中断阻塞带来的延迟。

放在必经路径上：喂狗代码要放在程序正常执行的必经位置（如主循环关键任务处理完之后），确保"喂狗"本身能证明程序确实执行到了关键位置。

不要只在中断里喂狗：如果在定时器中断里喂狗，即使主程序已经死循环，中断照常触发、照常喂狗，看门狗就形同虚设，检测不到主流程异常。

不要在每条语句后都喂狗：那样会失去监控意义；正确做法是在一段关键逻辑完成之后喂一次，中间如果卡死，超时就会复位。

### IWDG 一旦启动能否关闭？为什么？

不能关闭。IWDG 一旦启动（向 `IWDG_KR` 写入 0xCCCC），硬件上就无法再通过软件关闭，只有上电复位（POR/PDR）或 NRST 外部复位才能让它重新初始化。

原因（设计意图）：

IWDG 的定位是永不失效的最后防线。如果软件能关闭它，那么程序跑飞后万一刚好执行到关闭看门狗的代码，看门狗就彻底失效了，违背了它存在的意义。

硬件上，IWDG 的使能状态被设计为只能置位、不可清除，并配合键寄存器（KEY）写保护机制防止误操作。

这也是 IWDG 与普通定时器的本质区别：普通定时器是工具，可以随时启停；IWDG 是保险，启动后就不允许退保。

需要注意：软件复位（如 `NVIC_SystemReset()` 触发的系统复位）不会关闭 IWDG，复位后它依然在运行。所以在 Bootloader 中也要注意喂狗，防止升级/跳转过程中被复位。

### 什么情况下应该使用 IWDG 而不是 WWDG？

选择 IWDG 还是 WWDG，本质是选择粗粒度死机保护还是严格时序保护。

**优先用 IWDG 的场景：**

只要"程序跑飞就复位"的通用场景，主时钟可能失效的场景，低功耗场景，工业现场、无人值守、不允许长时间死机的设备。

**优先用 WWDG 的场景：**

需要检测程序执行时序被破坏，需要提前预警，主时钟稳定、需要精确窗口控制的场合。

### 调试模式下 IWDG 会继续计数吗？如何处理？

会继续计数。因为它使用的是独立的 LSI 时钟，不受 CPU 暂停的影响。如果不处理，打一个断点看变量，几秒钟后看门狗就会复位系统，导致调试无法进行。  
处理方法是：在初始化代码中调用 `__HAL_DBGMCU_FREEZE_IWDG()`，使能调试冻结功能。这样当 CPU 被调试器暂停时，IWDG 的计数器也会自动暂停，防止误复位。需要注意的是，这个函数只在调试模式下有效，在正常运行（非调试）时，看门狗依然是全速运行的

### IWDG 的预分频器和重装载寄存器如何配置？

第一，向 IWDG_KR 写 0x5555 解除写保护

第二，配置 IWDG_PR 设置预分频系数，范围 0\~6 对应 4\~256 分频

第三，配置 IWDG_RLR 设置重装载值，范围 1\~4095

第四，等待 IWDG_SR 的 PVU 和 RVU 位清零，确保寄存器同步完成

第五，向 IWDG_KR 写 0xCCCC 启动看门狗

之后在主循环里定期写 0xAAAA 喂狗。用 HAL 库的话，调用 HAL_IWDG_Init 会自动完成以上流程，喂狗用 HAL_IWDG_Refresh。CubeMX 里勾选 IWDG 并设置分频和重装载值即可

### 系统在低功耗模式下 IWDG 是否还在运行？

IWDG 是否在低功耗模式下运行，取决于进入哪种低功耗模式以及软件是否开启了 LSI：

第一，睡眠模式下，主时钟和外设照常运行，LSI 工作，IWDG 继续计数，所以长时间不喂狗会导致复位。

第二，停机模式下，取决于 LSI 是否保持开启。因为 LSI 是独立时钟源，只要在进入 Stop 前没关闭 LSI，IWDG 就会继续工作；如果为了极致省电关闭了 LSI，IWDG 也会停止。所以低功耗下需要监控时，通常选择停机模式 + IWDG。

第三，待机模式下，整个 1.8V 电源域断电，LSI 强制停止，IWDG 停止运行。退出 Standby 相当于复位，程序重新初始化。

实战中，如果用停机模式 + IWDG，唤醒后必须尽快喂狗，防止唤醒初始化时间过长导致看门狗误复位。

## RS485和CAN总线

### 什么是 RS485？它和 RS232、RS422 有什么区别？

RS485（EIA-485 标准）是一种基于差分平衡传输的串行通信物理层标准。它只规定电气特性（电平、阻抗、驱动能力），不规定上层协议，因此可以承载 Modbus、Profibus 或自定义协议，是工业现场总线中最常用的有线通信方式之一。

它与 RS232、RS422 的主要区别如下：RS232 采用单端（对地）信号，典型距离约 15 米，1 对 1 连接，全双工，逻辑电平为 ±3\~±15V；RS422 采用差分信号，典型距离约 1200 米，1 主多从（接收多），全双工，差分电平 ±2\~±6V；RS485 采用差分信号，典型距离约 1200 米，多对多（典型 32 节点），半双工（4 线接法可全双工），差分电平 ±1.5\~±5V。

### RS485 的差分信号是如何表示逻辑 0 和逻辑 1 的？为什么它的抗干扰能力强？

接收端以 A、B 两线的电压差 UAB = VA − VB 判定逻辑电平：逻辑 1 为 UAB ≥ +200 mV（典型：A=+3.5V，B=+1.5V）；逻辑 0 为 UAB ≤ −200 mV（典型：A=+1.5V，B=+3.5V）；两线差值在 −200 mV \~ +200 mV 之间属于不确定区，应避免。

抗干扰能力强的根本原因在于差分传输：外部干扰会同时叠加在 A、B 两根线上，两线差值基本不变（共模抑制），接收端只识别两线差值，因此抗干扰能力强、传输距离远（典型可达 1200 米）。

### RS485 总线组网有哪些特点？一主多从结构的布线要点是什么？为什么要接 120Ω 终端电阻？

RS485 组网特点：远距离通信（典型可达 1200 米，与速率和线缆质量相关）；多设备组网（单条总线可挂多个设备，典型 32 个，使用低负载芯片可扩展更多）；抗干扰能力强（差分传输有效抵抗共模干扰，适合工业复杂电磁环境）；双向半双工通信（同一时刻只能一个方向，需控制方向切换）；布线成本低（仅需一对双绞线 A、B 和参考地线）。

一主多从布线要点：主站（Master）发起通信、从站（Slave）响应，设备地址需唯一；总线采用手拉手（菊花链）连接，避免星型连接；使用屏蔽双绞线，屏蔽层单端接地，参考地 GND 独立；支线尽量短（建议 ≤0.3 米）；远离强电电缆和干扰源。

120Ω 终端电阻跨接在 A 与 B 之间，匹配总线特性阻抗，吸收信号反射、减少波形畸变；不接终端电阻时信号会在总线末端反射，造成波形畸变和误码，影响通信稳定性。

### MCU 的 UART 为什么不能直接接入 RS485 总线？常用的电平转换芯片有哪些？

MCU 的 UART 输出的是 TTL 单端电平，而 RS485 总线要求差分信号，TTL 电平无法直接驱动差分总线，也不具备差分传输的抗干扰能力，因此需要 RS485 收发器完成 TTL ↔ 差分电平转换。

常用器件：MAX485 / SP485 / ISL83485 等半双工收发器芯片（带 DE 发送使能、RE 接收使能）；USB 转 RS485 适配器（PC 调试用）；RS232 转 RS485 转换器（兼容老设备）。

### RS485 半双工通信为什么必须控制 DE/RE 方向？切换方向时要注意什么？

RS485 是半双工总线，只有 A、B 一对差分线，同一时刻只能有一个方向传输，因此必须通过 DE（发送使能）/RE（接收使能）控制收发方向：DE/RE 为高电平进入发送模式，为低电平进入接收模式（注意 RE 为低电平有效，实际使用中常将 DE 与 RE 并联，由 GPIO 统一控制）。

切换方向注意事项：发送前先拉高 DE/RE 进入发送模式，发送完成后拉低 DE/RE 回到接收模式；半双工必须严格“先切方向、再收发”；发送完成后要留出总线释放时间（一般不少于 1 个字节时间）再切回接收，否则会撞车或丢失首字节。

### Modbus 是什么协议？RTU 数据帧由哪几部分组成？常用的功能码有哪些？

Modbus 是由 Modicon（现施耐德电气）提出的通信协议，基于主从（Master/Slave）架构，主站发起请求、从站响应；支持 RTU（串口）和 ASCII 两种传输模式，工业中 RTU 更常用；开放免费、易于实现，常用于 PLC、传感器、变频器、仪表等设备通信。

Modbus RTU 数据帧由四部分组成：地址（1 字节，1\~247，0 为广播地址不返回）+ 功能码（1 字节，定义操作类型）+ 数据域（N 字节，具体的操作数据）+ CRC16（2 字节，低字节在前、高字节在后）。RTU 帧内字节间不能停顿，帧与帧之间空闲时间 ≥ 3.5 个字符时间，用于从站判断一帧结束。

常用功能码：01（0x01）读取线圈状态、02（0x02）读取离散输入、03（0x03）读取保持寄存器、04（0x04）读取输入寄存器、05（0x05）写单个线圈、06（0x06）写单个寄存器、15（0x0F）写多个线圈、16（0x10）写多个寄存器。

### 什么是 CRC16 校验？计算时要注意什么？（低字节在前）

RTU 模式采用 CRC16 校验（多项式 0x8005 的反射形式 0xA001，初值 0xFFFF），校验范围覆盖地址 + 功能码 + 数据域（不含 CRC 本身），发送时低字节在前、高字节在后。

计算要点：CRC 寄存器初始化为 0xFFFF；逐字节与 CRC 异或后，按位右移 8 次，每步若最低位为 1 则与 0xA001 异或；所有字节处理完后得到的值即为 CRC16。发送顺序必须低字节在前；同时要保证帧间空闲时间 ≥ 3.5 个字符时间，否则从站可能把一帧拆成两帧导致 CRC 错误。

### 什么是 CAN 总线？它和 RS485 相比有哪些特点？

CAN（Controller Area Network，控制器局域网）是一种多主、异步、半双工的串行通信总线协议，由德国 Bosch 公司在 20 世纪 80 年代推出，最初用于汽车电子通信，是工业控制、汽车电子等领域最重要、应用最广泛的现场总线之一。特点：高可靠性（具备差错检测、自动重发机制，抗电磁干扰能力强）；实时性好（基于优先级的总线仲裁）；多主节点（任意节点均可主动发送数据，无需中心主站）；组网灵活（只需 CAN_H、CAN_L 两根信号线）。

与 RS485 相比：RS485 只是物理层标准（EIA-485），一主多从、半双工，无总线仲裁机制，需靠上层协议（如 Modbus）避免冲突；CAN 是完整的协议（物理层 + 数据链路层），多主架构、自带非破坏性位仲裁，帧内含 CRC 校验和 ACK 应答，有错误检测与自动重发机制，可靠性更高。RS485 布线简单成本低，适合中小规模工业组网；CAN 更适合对实时性、可靠性要求高的场景（汽车、机器人等）。

### CAN 总线有哪五种帧类型？数据帧和遥控帧有什么区别？

CAN 总线共有 5 种基本帧：数据帧（发送节点向接收节点传送数据，最常用、最核心，分为标准帧 11 位 ID 与扩展帧 29 位 ID）；遥控帧（接收节点向具有相同 ID 的发送节点请求发送数据）；错误帧（任何节点检测到总线错误时发出，刻意打破位填充规则、破坏当前数据传输并通知所有节点）；过载帧（接收节点尚未准备好接收新数据时，请求发送节点延迟发送）；帧间隔（将数据帧或遥控帧与前面的任何帧隔开，强制提供总线空闲时间，确保节点有时间处理上一帧）。

数据帧与遥控帧的区别：遥控帧结构类似数据帧，但没有数据段，且 RTR 位为隐性（1），数据帧的 RTR 位为显性（0）；即便数据帧长度为 0（没有数据段），两者依然可通过 RTR 位的显隐性严格区分；遥控帧的数据长度码（DLC）必须以所请求对应数据帧的 DLC 来表示。

### 标准帧和扩展帧的格式有什么区别？

标准帧与扩展帧的核心区别在于 ID 位数和仲裁段长度：标准帧 ID 为 11 位，扩展帧 ID 为 29 位。

标准帧宏观结构：帧起始 1 位（显性）+ 仲裁段 12 位（ID 11 位 + RTR 1 位）+ 控制段 6 位（IDE 1 位 + r0 1 位 + DLC 4 位）+ 数据段 0\~64 位 + CRC 段 16 位（CRC 15 位 + DEL 1 位）+ ACK 2 位 + 帧结束 7 位（隐性）。

扩展帧：仲裁段为 32 位（SRR 1 位 + IDE 1 位 + ID 18 位 + r1 1 位 + RTR 1 位），控制段为 r1 1 位 + r0 1 位 + DLC 4 位，其余段与标准帧相同。

### CAN 是如何实现非破坏性优先级仲裁的？为什么 ID 越小优先级越高？

CAN 采用非破坏性总线仲裁机制。总线空闲时，最先开始发送消息的单元获得发送权；多个单元同时开始发送时，各发送单元从仲裁段的第一位开始逐位仲裁。

核心是利用线与机制（Wired-AND）：显性位（逻辑 0）会自动物理覆盖隐性位（逻辑 1），发送隐性位却读到显性位的节点仲裁失利，从下一位开始转为接收状态；连续输出显性电平最多的单元可继续发送，即 ID 数值越小优先级越高（因为高位更早出现显性位）。仲裁过程对高优先级帧是非破坏性的：获胜节点继续发送自己的帧，不会因冲突而重发，这正是 CAN 实时性好的原因。

### 什么是 CAN 的位时序？如何根据 APB1 时钟计算波特率？（Tq、BS1、BS2、采样点）

时间份额 Tq 是 CAN 总线位时间的最小基本单位。一个完整的“位”由多个 Tq 组成（通常设定为 8\~25 个），Tq 的绝对时间长度由波特率预分频器（BRP）和振荡器频率决定。位时间分为四段：同步段 SS（固定 1 Tq）、传播时间段 PTS（补偿网络物理延迟）、相位缓冲段 PBS1（可加长）、相位缓冲段 PBS2（可缩短），采样点位于 PBS1 与 PBS2 交界处。

关键公式：tq = (BRP + 1) × tPCLK；波特率 = 1 / (1 × tq + tBS1 + tBS2)；tBS1 = tq × (TS1 + 1)；tBS2 = tq × (TS2 + 1)。

配置推演（42MHz APB1 时钟 → 500 kbps）：位时间 = 1/500k = 2μs；设 BRP + 1 = 7，tq = 7/42MHz ≈ 166.7ns；总时间片 = 2μs / 166.7ns = 12 个 tq；分配 SYNC = 1、BS1 = 8、BS2 = 3，采样点 = (1+8)/12 = 75%。最终 CAN_BTR 寄存器填入：BRP = 6、TS1 = 7、TS2 = 2。

### 什么是硬件同步和再同步？SJW 的作用是什么？

由于发送单元和接收单元可能存在时钟频率误差及传输路径（电缆、驱动器等）上的相位延迟，会引起同步偏差，接收单元需要通过硬件同步或再同步调整时序进行接收。

硬件同步：接收单元在总线空闲状态检测出帧起始（SOF）时进行的同步调整；当检测出隐性到显性的边沿时，视为位的起始（SS），所有节点以此边沿对齐位时间。硬件同步只在帧起始时进行一次。

再同步：接收过程中检测出总线上的电平变化（边沿）时进行的同步调整；每当检测出边沿时，根据 SJW 值通过加长 PBS1 段或缩短 PBS2 段调整同步；如果发生了超出 SJW 值的误差，最大调整量不能超过 SJW 值。

SJW（同步跳转宽度）定义了每次再同步时可以延长或缩短的最大 Tq 数量。例如 SJW=2 时：隐性→显性边沿延迟 2 Tq 出现在 PTS 中，则在 PBS1 后插入 SJW 长度调整同步；边沿提前出现在 PBS2 中，则在 PBS2 中减小 SJW 长度调整同步。

### STM32 的 bxCAN 有哪些工作模式？发送邮箱和接收 FIFO 是如何工作的？如何用 HAL 库发送一帧数据？

bxCAN 有三种主要工作模式：睡眠模式（低功耗状态，硬件复位后的默认模式，时钟停止但邮箱仍可访问；软件置 SLEEP=1 请求进入，将 SLEEP 清零或硬件检测到 CAN 总线活动即可唤醒）；初始化模式（只有在此模式下才能配置波特率 CAN_BTR 及位定时参数，此时总线传输完全停止；软件置 INRQ=1 请求，硬件置位 INAK=1 确认）；正常模式（完成初始化后参与总线通信；软件请求后，硬件必须监测到连续 11 个隐性位才真正切入）。

发送邮箱：bxCAN 有 3 个发送邮箱，经历 4 种核心状态——空（可写入新消息，置 TXRQ 后进入挂起）、挂起（等待参与硬件优先级仲裁，置位 ABRQ 可中止并恢复为空）、已安排（在所有挂起邮箱中赢得最高优先级，等待总线空闲）、发送（硬件正在物理层发送，成功则变空）。

接收 FIFO：2 个接收 FIFO（FIFO0/FIFO1），每个具有 3 级深度；状态有空（FMP=0）、PENDING_1/2（挂起 1 或 2 条消息，软件读取后置位 RFOM 释放邮箱）、PENDING_3（已填满，必须尽快处理）、上溢（FIFO 满时又收到新消息，FOVR=1，新消息被丢弃或覆盖，取决于配置）。

HAL 库发送一帧数据示例：定义 CAN_TxHeaderTypeDef 并设置 StdId = 0x123、IDE = CAN_ID_STD、RTR = CAN_RTR_DATA、DLC = 1，填充 TxData[0] = 0x2C，然后调用 HAL_CAN_AddTxMessage(&hcan1, &TxHeader, TxData, &TxMailbox) 将报文添加到空闲发送邮箱并请求发送。

## 实时操作系统（FreeRTOS）

### RTOS 与裸机开发的核心区别？

裸机开发：程序在主循环（while(1)）中按顺序轮询执行，靠中断抢占处理紧急事件，任务间用标志位、状态机协调，逻辑复杂时耦合度高、难以维护，实时性依赖中断和轮询周期。

RTOS 开发：把应用拆分为多个独立任务，由内核调度器按优先级抢占调度；任务间通过队列、信号量、互斥量等机制通信与同步；高优先级任务可随时抢占低优先级任务，实时性由内核保证。核心区别在于：有任务并发与抢占式调度、有标准化的任务间通信原语、模块化好、实时响应有保障，代价是内核占用一定的 ROM/RAM 和上下文切换开销。

### 任务有哪几种状态？如何切换？

FreeRTOS 任务有 4 种状态：运行态（Running，正在占用 CPU，单核上同一时刻只有一个任务处于该状态）、就绪态（Ready，已就绪等待调度器分配 CPU）、阻塞态（Blocked，因等待延时、队列、信号量等事件而暂停，不占用 CPU）、挂起态（Suspended，通过 vTaskSuspend() 主动挂起，只能由 vTaskResume() 恢复）。

切换由调度器完成：在每个时钟节拍（tick）中断或事件到来时，调度器从就绪队列中选出最高优先级任务切换为运行态；任务调用 vTaskDelay() 或等待队列/信号量时进入阻塞态；等待的事件发生后回到就绪态，等待再次被调度。

### 任务优先级如何设计？抢占如何发生？

FreeRTOS 中优先级数值越大优先级越高（范围由 configMAX_PRIORITIES 配置）。设计原则：实时性要求高、响应要快的任务（如通信收发、控制回路、报警处理）给高优先级；界面刷新、日志等非关键任务给低优先级；不要把所有任务都设成同一高优先级；优先级个数够用即可，太多会增加调度开销。

抢占的发生：当一个高优先级任务进入就绪态（例如延时结束、收到信号量/队列数据、被中断唤醒）时，调度器立即暂停正在运行的低优先级任务，保存其上下文并切换到高优先级任务，这就是抢占式调度。若多个任务优先级相同，则按时间片轮转调度（configUSE_TIME_SLICING 开启时）。

### HAL_Delay() 和 osDelay() 的区别？

HAL_Delay() 是基于 SysTick 的阻塞式（忙等待）延时：延时期间 CPU 一直在循环中空转，不释放 CPU，其他任务无法运行，浪费处理器资源；在 FreeRTOS 工程中若直接使用，还会拖慢整个系统调度。

osDelay() 是 CMSIS-RTOS 对 vTaskDelay() 的封装，属于 RTOS 延时：任务调用后立即进入阻塞态、让出 CPU，调度器转去运行其他就绪任务，延时由内核 tick 计数，时间到后任务回到就绪态。因此 RTOS 工程中应优先使用 osDelay()/vTaskDelay()；若必须使用 HAL_Delay()，需确认其内部已重定向到 vTaskDelay（部分 CubeMX 生成的工程会自动处理）。

### 空闲任务（Idle Task）的作用是什么？

空闲任务（Idle Task）是系统启动时自动创建的最低优先级任务（优先级 0），在没有任何其他任务处于就绪态时运行。

作用：① 回收被删除任务的资源——被 vTaskDelete() 删除的任务，其任务控制块（TCB）和栈内存由空闲任务在后续调度中释放（动态内存方案下）；② 提供空闲钩子函数 vApplicationIdleHook()，可在系统空闲时进入低功耗模式或做后台统计；③ 保证调度器始终有任务可运行。空闲任务不能被阻塞（不能调用会使其阻塞的 API），但可以被高优先级任务随时抢占。

### FreeRTOS 中任务间的通信如何实现？

FreeRTOS 任务间通信与同步的主要机制：队列（Queue，传递数据拷贝）、信号量（二值/计数信号量，用于同步和资源计数）、互斥量（Mutex，保护共享资源，带优先级继承）、事件标志组（Event Group，等待多个事件组合）、任务通知（Task Notification，轻量级单对单通知）、流缓冲/消息缓冲（Stream/Message Buffer，字节流式传递，较新版本提供）。

选择原则：要传数据用队列或流缓冲；只做同步用信号量；保护共享资源用互斥量；等待一组条件用事件标志组；单个任务接收通知且数据量小时用任务通知（最省资源、最快）。

### 队列（Queue）为什么是数据拷贝而非传指针？

队列采用数据拷贝而非传指针，是为了保证数据的一致性与隔离性：发送方传入的数据往往存放在任务栈或局部变量中，发送后发送方可能立即修改或释放该内存；若只传指针，接收方读取时数据可能已被改写，产生竞态和难以排查的错误。

数据拷贝机制：发送时把数据完整复制到队列内部的存储区，接收时再从队列复制出来，收发双方互不影响，数据安全可靠。代价是大数据结构拷贝开销较大，因此实际工程中，小数据（几个到几十字节）直接拷贝；大数据结构可改为在队列中传指针，但必须保证指针指向的内存在整个生命周期内有效且访问互斥，或使用流缓冲。

### 二值信号量、计数信号量、互斥信号量的区别？

二值信号量：取值只有 0 和 1，主要用于事件同步（如中断通知任务“数据到了”）或简单互斥；无所有权概念，任何任务都可以 give/take，可在中断中使用（xSemaphoreGiveFromISR）。

计数信号量：计数值可以大于 1，用于资源计数（如缓冲池空位）或记录多次事件；同样无所有权。

互斥量（Mutex）：专门用于保护共享资源，有所有权——只能由获取它的任务释放，并支持优先级继承（缓解优先级反转）；递归互斥量允许同一任务重复获取；互斥量不能在中断服务函数中使用。总结：同步用二值信号量、计数用计数信号量、互斥访问共享资源用互斥量。

### 什么是优先级反转？FreeRTOS 如何解决？

优先级反转：高优先级任务 H 等待低优先级任务 L 持有的资源，而此时中优先级任务 M 抢占 L，导致 H 长时间得不到 CPU——实际运行顺序变成 H 等 L、L 被 M 抢占，低优先级任务反而拖住了高优先级任务。

FreeRTOS 的解决办法是互斥量的优先级继承机制：当 H 等待 L 持有的互斥量时，L 的优先级被临时提升到 H 的优先级，使 L 不会被 M 抢占，得以尽快运行并释放互斥量，随后 L 恢复原优先级。优先级继承显著缩短了反转持续时间，但不能完全消除所有问题，设计时还应避免死锁（如两个任务互相等待对方的资源）。

### 什么是任务通知？它相比队列有什么优势？

任务通知是 FreeRTOS 提供的高效任务间通信机制：每个任务自带一个 32 位通知值，其他任务或中断可通过 xTaskNotify()/xTaskNotifyGive() 直接修改目标任务的通知值并解除其阻塞，目标任务通过 xTaskNotifyWait()/ulTaskNotifyTake() 等待和读取。

相比队列的优势：① 开销极小——无需创建队列、信号量等内核对象，不额外占用内存；② 速度快——直接操作任务控制块，官方测试比信号量快约 45%、更省 RAM；③ 灵活——32 位通知值可携带数据，也可用作二值/计数信号量或事件标志的简化版。局限：只能单对单通知、无法缓冲多条消息、通知值只有 32 位，多任务广播或大数据传输仍需队列/信号量。

### 在你的项目中，为什么要引入 FreeRTOS？

（结合项目）引入 FreeRTOS 的主要原因：① 并发需求——项目同时有显示刷新、按键扫描、传感器采集、串口/CAN 通信、控制算法等多路功能，裸机超级循环难以合理分配 CPU 和保证时序；② 实时性——高优先级任务（通信、控制）可被抢占调度及时响应，关键逻辑不被长耗时任务阻塞；③ 模块化——每个功能独立成任务，用队列/信号量解耦，代码清晰、易维护易扩展；④ 资源利用率——阻塞延时（osDelay）让出 CPU，避免忙等待浪费；⑤ 生态成熟——CubeMX 可直接生成 FreeRTOS 工程，与 CMSIS-RTOS、LVGL 等配合完善。典型架构：UI 任务 + 采集任务 + 通信任务 + 控制任务，按优先级分层调度。

### FreeRTOS 的内存管理有哪几种方案？（heap_1 到 heap_5）

heap_1：只分配不释放，实现最简单、确定性强、无碎片，适合从不删除任务或内核对象的场景。

heap_2：支持释放，但不合并相邻空闲块，长时间反复分配释放会产生碎片，适合块大小相对固定的场景。

heap_3：直接包装标准库 malloc/free，通过挂起调度器保证线程安全，堆大小由编译器/链接脚本决定。

heap_4：在支持释放的基础上，按地址排序并合并相邻空闲块，能有效减少碎片，是官方推荐的默认方案，绝大多数场景适用。

heap_5：与 heap_4 算法相同，但支持多个不连续内存区，通过 vPortDefineHeapRegions() 定义各堆区，适合分散 RAM 的芯片。选型建议：默认用 heap_4；芯片有多个分散 RAM 区用 heap_5；极致简单且不释放内存用 heap_1。

## 轻量级图形库（LVGL）

### LVGL 是什么？它的核心特点是什么？

LVGL（Light and Versatile Graphics Library）是一个开源的嵌入式图形库，纯 C 语言编写，专为资源有限的 MCU 设计，是目前嵌入式领域应用最广的 UI 库之一。

核心特点：① 轻量——占用 RAM/Flash 小，可运行在只有几十 KB RAM 的单片机上；② 控件丰富——内置按钮、标签、图表、滑块、列表、开关、进度条等 30 余种控件；③ 显示灵活——支持 RGB565、ARGB8888 等多种颜色格式和不同分辨率屏幕；④ 功能完善——动画、主题、多语言字体、抗锯齿、控件样式等开箱即用；⑤ 开源免费（MIT 许可）；⑥ 可移植性强——只需实现屏幕刷新回调和底层驱动即可运行；⑦ 与 FreeRTOS 等 RTOS 配合成熟。

### 给你一个裸的 STM32+屏幕，能不能把 LVGL 跑起来？（把 LVGL 移植到 STM32 上，需要做哪些工作？）

把 LVGL 跑在裸 STM32+屏幕上，需要完成：① 显示驱动：初始化屏幕（FSMC/SPI/RGB 接口）并实现 lv_disp_drv 的 flush_cb 回调，把 LVGL 的绘制缓冲区内容刷新到屏幕；② 配置 lv_conf.h：设置颜色深度（LV_COLOR_DEPTH，如 16/32）、分配绘制缓冲区（单缓冲或双缓冲，一般不小于屏幕面积的部分比例）和 LVGL 内存池（LV_MEM_SIZE）；③ 提供时钟：周期调用 lv_tick_inc(ms)（用 SysTick 或定时器），供 LVGL 内部计时；④ 输入设备（可选）：注册触摸屏/按键/编码器的 read_cb；⑤ 初始化与运行：lv_init() 创建界面控件，然后在主循环或 RTOS 任务中周期性调用 lv_timer_handler()（通常每 5\~10ms 一次）驱动 UI 刷新；⑥ 若用 RTOS，把 lv_timer_handler 放入独立 UI 任务，并通过互斥量保护 UI 操作。

### RGB565 和 ARGB8888 有什么区别？

RGB565 是 16 位颜色格式：红色 5 位、绿色 6 位、蓝色 5 位，每像素 2 字节，共可表示 65536 种颜色；内存占用小，是 MCU 嵌入式屏幕最常用的格式。

ARGB8888 是 32 位颜色格式：Alpha 透明度 8 位 + 红 8 位 + 绿 8 位 + 蓝 8 位，每像素 4 字节，可表示 1670 万种颜色，并支持透明度混合。

区别与选型：ARGB8888 颜色更丰富、支持 alpha 透明效果，但内存占用是 RGB565 的两倍；MCU 内存紧张时优先 RGB565，需要高质量图像或透明效果时用 ARGB8888。LVGL 中通过 LV_COLOR_DEPTH 宏统一配置，两者不能混用，须与屏幕实际驱动格式一致。

### LVGL 的缓存区（Buffer）配置有哪些？双缓冲有什么好处？

LVGL 的绘制缓冲（draw buffer）有几种配置方式：单缓冲——一个缓冲区，LVGL 绘制完成后调用 flush_cb 送显，送显期间要等待完成才能绘制下一帧；双缓冲——两个缓冲区，一个正在 flush 到屏幕（可配合 DMA 搬运），另一个同时供 LVGL 绘制下一帧，交替使用；按大小分，又可分为全屏缓冲和部分缓冲（buffer 小于全屏时 LVGL 分块渲染、逐块刷新）。

双缓冲的好处：① 提升帧率——绘制与送显流水线并行，CPU 等待大幅减少；② 避免画面撕裂（tearing）——不会出现屏幕上半部分是旧帧、下半部分是新帧的情况；③ 配合 DMA 传输时 CPU 几乎零等待。代价是内存占用翻倍，实际工程常在“内存允许”和“流畅度”之间折中，例如 320×240 RGB565 屏幕常用 1/10\~1/4 屏大小的双缓冲。

### LVGL 怎么处理中断中的 UI 更新？

LVGL 不是中断安全的：不能在中断服务函数（ISR）中直接创建、修改控件或调用 lv_timer_handler()。

正确做法：ISR 中只做“通知”——置一个标志位，或通过队列/信号量（RTOS 下用 xQueueSendFromISR / xSemaphoreGiveFromISR）把事件或数据发给 UI 处理上下文；然后在 lv_timer_handler() 所在的 UI 上下文（主循环或 UI 任务）中读取标志/数据，再执行 lv_xxx 更新界面。输入设备（触摸、按键）的中断同样只上报事件，由 LVGL 的 read_cb 在定时器中读取。这样保证所有 UI 操作都发生在同一个线程化的上下文里，避免竞态。

### 创建一个带点击事件的按钮，代码怎么写？

示例（LVGL v8 风格）：

```c
static void btn_event_cb(lv_event_t * e) {
    lv_event_code_t code = lv_event_get_code(e);
    if (code == LV_EVENT_CLICKED) {
        lv_label_set_text(label, "Clicked");
    }
}
void create_ui(lv_obj_t * parent) {
    lv_obj_t * btn = lv_btn_create(parent);
    lv_obj_set_size(btn, 100, 50);
    lv_obj_center(btn);
    lv_obj_add_event_cb(btn, btn_event_cb, LV_EVENT_CLICKED, NULL);
    lv_obj_t * label = lv_label_create(btn);
    lv_label_set_text(label, "OK");
    lv_obj_center(label);
}
```

要点：lv_btn_create() 创建按钮；lv_obj_add_event_cb() 注册事件回调；LV_EVENT_CLICKED 是点击释放事件；回调中通过 lv_event_get_code() 判断事件类型，再执行相应处理。

### 如何实现一个动画？

```c
lv_anim_t a;
lv_anim_init(&a);
lv_anim_set_var(&a, obj);                       // 动画作用对象
lv_anim_set_values(&a, 0, 100);                  // 起始值 / 结束值
lv_anim_set_time(&a, 500);                       // 时长(ms)
lv_anim_set_exec_cb(&a, set_x_cb);               // 每帧回调：把值应用到对象属性
lv_anim_set_path_cb(&a, lv_anim_path_ease_out);  // 缓动曲线
lv_anim_start(&a);

```

要点：lv_anim_t 描述一个动画——对象、起止值、时长、执行回调（每帧把当前动画值赋给 x/y/opacity 等属性）和缓动路径；动画由 lv_timer_handler() 自动驱动，无需额外延时；还支持 delay（延迟启动）和 repeat（重复次数）等参数。

### 加载新页面时出现白屏，是什么原因？

常见原因：① lv_timer_handler() 没有周期性调用或调用频率太低——UI 只渲染了初始帧或完全不刷新；② 绘制缓冲区配置错误或 flush_cb 未正确实现——LVGL 画好的内容没有真正送到屏幕；③ 内存不足——LV_MEM_SIZE 设置过小，控件创建失败；④ 颜色深度不匹配——LV_COLOR_DEPTH 与屏幕实际格式（RGB565/ARGB8888）不一致导致花屏或黑屏；⑤ 页面切换时删除了仍在被引用/动画使用的对象，或动画回调访问了已释放对象；⑥ 屏幕初始化失败、背光未打开、DMA 传输未完成。

排查思路：确认 tick 正常、timer_handler 周期调用、flush_cb 能正确刷屏（先画一个纯色测试）、检查内存余量（lv_mem_monitor）、核对颜色深度与屏幕参数、检查对象生命周期。

### 在 STM32 这种资源有限的芯片上跑 LVGL，遇到过什么挑战？

主要挑战与对策：① 内存紧张——绘制缓冲区和对象内存（LV_MEM_SIZE）占用大，对策是用部分缓冲+分块渲染、关闭不需要的功能（抗锯齿、阴影、动画复杂度）、减少常驻控件；② CPU 性能——复杂动画、大屏刷新耗 CPU，对策是用 DMA 加速 flush、降低帧率、尽量局部刷新（样式变化只重绘受影响区域）；③ Flash 限制——中文字体资源很大，对策是用 lv_font_conv 只生成用到的字符子集、选择小字号或内置字体；④ 刷新流畅度——单缓冲容易闪烁/撕裂，对策是双缓冲+DMA；⑤ 与 RTOS 协作——UI 任务和其他实时任务争抢 CPU，需合理设优先级并给 UI 加锁。建议开启 LV_USE_PERF_MONITOR 查看 FPS 和 CPU 占用，量化优化效果。

### 调试 UI 正常显示，但触摸没反应，可能是什么问题？

可能原因：① 输入设备驱动未注册或 read_cb 未实现——没有调用 lv_indev_drv_register()，LVGL 根本不会读取触摸；② read_cb 返回的数据格式不对——状态（LV_INDEV_STATE_PR/RELEASED）或坐标范围与屏幕不匹配；③ 触摸芯片本身没工作——I2C/SPI 通信失败、复位/中断引脚配置错误、上电时序不对；④ 坐标方向/分辨率未转换——触摸坐标系与屏幕坐标系不一致，点了没反应或点错位置；⑤ 触摸类型配置错误——LV_INDEV_TYPE_POINTER 与 ENCODER 等类型混用；⑥ 在中断里直接处理触摸而没有通过 read_cb 交给 LVGL。

排查方法：先用串口把 read_cb 读到的坐标和状态打印出来，验证触摸芯片是否上报数据；再检查注册流程、坐标转换和初始化时序；最后确认 lv_timer_handler 在周期运行（read_cb 由它驱动）。

### LVGL 的任务调度和 FreeRTOS 如何配合？

典型配合方式：创建独立 UI 任务（优先级取中低），在任务循环中周期调用 lv_timer_handler()（每 5\~10ms 一次）驱动 LVGL 内核；lv_tick_inc() 用 SysTick 或专门定时器周期喂给 LVGL（CubeMX 的 LVGL+FreeRTOS 工程模板会自动完成）。

数据交互：采集/通信任务通过队列、信号量或任务通知把数据发给 UI 任务，UI 任务收到后更新控件；因为 LVGL 非线程安全，所有 UI 操作必须集中在 UI 任务上下文执行，若确有多任务访问则用互斥量包住 lv_timer_handler 和控件修改。

优先级设计：UI 任务优先级要低于实时控制/通信任务，避免界面刷新阻塞关键逻辑；但也不能太低导致界面卡顿，通常给中间优先级。整体上形成“实时任务高优先级 + UI 低优先级 + 队列解耦”的架构。

## 看懂原理图

### 拿到一张 STM32 开发板原理图，第一步应该看什么？

先看**整体框架和电源**，再按"电源 → 最小系统 → 外设"的路径逐块展开：

- 看图纸信息：标题栏中的项目名称、版本、设计者、页数，先弄清楚整板由哪几页原理图组成，各页负责什么功能模块。
- 先找**电源部分**：供电从哪里来（USB/DC 座/电池）、有几个电压域（5V/3.3V 等）、用什么芯片稳压（LDO 还是 DC-DC），这是整板工作的前提。
- 再找 **MCU 最小系统**：MCU 本体、晶振（HSE/LSE）、复位电路、启动配置（BOOT0/BOOT1）、下载调试接口（SWD/JTAG），确认最小系统能跑起来。
- 最后看**外设电路**：LED、按键、串口、SPI Flash 等，逐个分析与 MCU 的连接关系。
- 注意跳线帽、可选焊盘、默认配置等"可选电路"，它们往往决定板子的工作模式。

### 如何从原理图中找到 MCU 的型号和封装？

在原理图中找到 MCU 所在器件（位号通常是 U1），查看它的 **Value / Part Number / Comment** 属性，即可得到完整型号，例如 `STM32F103C8T6`；封装看 **Footprint** 属性（如 LQFP48、LQFP64、UFQFPN48），也可以通过引脚编号范围（1\~48、1\~64 等）反推引脚数。

拿到型号后要会解读命名规则：`STM32F103C8T6` 中 **C** = 48 引脚、**8** = 64KB Flash、**T** = LQFP 封装、**6** = 工业级温度范围。型号核对后，再对照数据手册确认该封装的引脚定义和引脚分布图，检查原理图中电源脚、地脚、BOOT 脚是否齐全。

### 电源部分原理图需要关注哪些要点？（稳压、滤波、去耦电容）

电源部分是整板的"心脏"，需要依次关注：

- **输入来源与电压**：USB 5V、DC 座、锂电池还是 Type-C？输入是否先经过保险丝、防反接、ESD 保护。
- **稳压电路**：LDO（如 AMS1117-3.3）还是 DC-DC（如 MP1584）？LDO 压差大、效率低但纹波小，适合小电流；DC-DC 效率高但纹波大，注意电感、续流二极管、反馈分压电阻。
- **滤波电容**：电源入口一般有较大容值的电解/钽电容（10uF\~100uF）做低频储能，旁边并联 0.1uF 陶瓷电容滤高频噪声。
- **去耦电容**：每个 MCU 电源引脚（VDD/VDDA）旁应就近放置 0.1uF 电容，这是数字电路稳定工作的关键，原理图上体现为"每个电源脚一个电容"。
- 电源指示 LED 及其限流电阻、电源开关、测试点也值得留意。

### 如何判断一个引脚是用于 GPIO 还是复用功能？

主要看**网络标号的命名**：以 `PA0`、`PB5`、`PC13` 这类"端口+引脚"命名的是 GPIO；以 `USART1_TX`、`SPI2_SCK`、`I2C1_SDA` 这类"外设+功能"命名的说明引脚工作在**复用功能**。

其次看**引脚所接的器件**：接 LED、按键、蜂鸣器的引脚一般是 GPIO；接 CH340 的 TXD/RXD、接 SPI Flash 的 CS/SCK/MISO/MOSI、接传感器的 SCL/SDA 的引脚，一定是复用功能。

最后结合**数据手册的引脚复用表**确认：手册会列出每个引脚支持哪些复用功能（F1 是固定映射，F4 通过 AFRL/AFRH 寄存器选择），原理图上的网络名应与手册复用表一致。

### 复位电路（NRST）的原理图怎么看？按键和电容的作用是什么？

NRST 复位电路一般由三部分组成：**上拉电阻 + 复位按键 + 滤波电容**，都连接到 NRST 引脚。

- **上拉电阻**（约 10kΩ）：把 NRST 默认拉高到 3.3V，保证芯片正常运行时复位脚为高电平、不复位。
- **复位按键**：一端接 NRST，一端接 GND。按下时把 NRST 拉低，产生低电平复位脉冲。
- **滤波电容**（约 0.1uF）：与上拉电阻构成 RC 滤波，吸收按键抖动和外界干扰，避免误复位；同时上电瞬间电容充电，NRST 保持一段时间的低电平，完成**上电复位**。

RC 时间常数决定复位脉冲宽度，一般保证复位低电平持续几十微秒以上，满足芯片复位时序要求。

### 晶振电路（HSE/LSE）的原理图怎么看？负载电容如何计算？

晶振电路主要看三处：晶振本体、两个负载电容、以及可选的反馈电阻/限流电阻。

- **HSE 高速晶振**（如 8MHz）：接在 OSC_IN/OSC_OUT（PD0/PD1 或 PH0/PH1）两脚之间，两侧各接一个负载电容到 GND。
- **LSE 低速晶振**：32.768kHz，接在 OSC32_IN/OSC32_OUT 上，同样配两个负载电容，用于 RTC 和低功耗时钟。

**负载电容计算**：晶振手册会给出所需负载电容 CL，计算公式为 `CL = C1×C2/(C1+C2) + Cs`，其中 Cs 是 PCB 杂散电容（约 3\~5pF）。通常取 C1 = C2，则 `C1 = C2 = 2×(CL − Cs)`。例如 8MHz 晶振要求 CL=12pF，取 Cs=4pF，则 C1=C2≈16pF（常用 15pF）。电容选不对会导致起振困难或频率偏差。

### 如何从原理图中确认下载/调试接口（SWD/JTAG）的接线？

先找到调试接口器件（位号常为 J1/P1/CN1），常见的有 4Pin、5Pin、6Pin、10Pin、20Pin。然后核对每个引脚的网络标号：

- **SWD 四线**：SWDIO（接 PA13）、SWCLK（接 PA14）、GND，再加一个 VCC（3.3V）和可选的 NRST、SWO（接 PB3）。
- **JTAG 五线**：TMS（=SWDIO/PA13）、TCK（=SWCLK/PA14）、TDI（PA15）、TDO（PB3）、NRST，再加 GND 和 VCC。

确认要点：①引脚编号与网络标号一一对应，防止插反烧毁；②是否带 3.3V 供电脚、与调试器电平一致；③有些开发板把 PA15/PB3/PB4 等 JTAG 引脚复用为普通 GPIO，下载时需注意是否被占用。

### 串口转 USB 电路（如 CH340/CP2102）怎么看？

串口转 USB 芯片（CH340/CP2102/CH343）原理图按"USB 侧 → 芯片 → 串口侧"三部分看：

- **USB 侧**：芯片 D+/D- 接 USB 座，注意 USB 座是否带 ESD 保护（TVS 阵列）、是否加 22Ω 串联电阻。
- **芯片工作条件**：CH340 需要外部 12MHz 晶振（内置晶振型号如 CH340N 不需要）；VCC 供电和去耦电容；GND 连接。
- **串口侧（关键）**：芯片 TXD 必须接 MCU 的 **RXD**、芯片 RXD 接 MCU 的 **TXD**，**交叉连接**，方向接反则通信失败。
- **电平匹配**：多数板卡 3.3V MCU 与 3.3V 供电的 CH340 直连；若芯片 5V 供电，则要看是否经过电平转换或分压。
- 有些板子用 DTR/RTS 引脚控制 BOOT0/复位，实现**一键自动下载**，注意看这两个信号是否连到 MCU 的 BOOT0 和 NRST。

### LED、按键等基础外设的原理图如何分析？（上拉/下拉、限流电阻）

LED 和按键是最典型的 GPIO 外设，分析时抓住"电流回路 + 默认电平"两条主线：

- **LED 电路**：一个引脚接 GPIO，另一个引脚经限流电阻接 VCC（**灌电流接法**，GPIO 输出低点亮）或接 GND（**拉电流接法**，GPIO 输出高点亮）。限流电阻计算公式 `R = (VCC − V_LED)/I`，例如 3.3V、LED 压降 2V、电流 5mA，则 R≈(3.3−2)/0.005≈260Ω，常用 330Ω 或 1kΩ。电阻过小 LED 电流过大，超过 GPIO 驱动能力会损坏引脚。
- **按键电路**：一端接 GPIO，另一端接 GND（配合 MCU 内部上拉，未按为高、按下为低），或接 VCC（配合内部下拉）。判断默认电平：悬空时引脚应被电阻稳定拉到确定电平，避免浮空误触发。
- 注意外接电容（消抖）、TVS/ESD 保护是否齐全；引脚网络名（如 LED1、KEY1）也会帮助理解功能。

### 如何从原理图中找到某个外设的引脚连接关系？（如 SPI Flash 接在哪几个引脚）

推荐用"**外设器件 → 网络标号 → MCU 引脚**"三步法，跨页找连接关系：

- **定位外设**：先找到外设器件（如 SPI Flash 位号 U3），读出它的引脚网络标号，如 `SPI1_SCK`、`SPI1_MISO`、`SPI1_MOSI`、`FCS`（片选）。
- **追踪网络**：网络标号是全局的，在 MCU 那一页搜索相同标号（原理图软件可用 Ctrl+F 查找），就能定位到 MCU 对应引脚，如 PA5=SPI1_SCK、PA6=SPI1_MISO、PA7=SPI1_MOSI、PA4=FCS。
- **验证复用**：对照数据手册引脚复用表确认该引脚确实支持这个复用功能；再检查片选、中断、电源等辅助引脚是否完整。

同一网络标号即使跨页、画在图纸不同位置，也代表电气上同一条连线，这是原理图阅读的核心规则。

### 原理图中的网络标号（Net Label）和总线（Bus）怎么看？

**网络标号（Net Label）**：给导线起的一个名字，**同名网络电气上相连**，即使图上没有画线、甚至不在同一页。命名有规律：外设功能名（`USART1_TX`、`SPI2_SCK`）、电源网络（`3V3`、`VCC`、`GND`）、信号方向（`KEY1`、`LED1`）。电源符号（VCC 三角、GND 三横线）本质也是全局网络标号。

**总线（Bus）**：一条粗线代表一组相关信号，比如数据总线 `DB[0..15]`、地址总线 `A[0..7]`。总线上的标号说明这一捆线包含哪些信号，实际每一根信号线仍以各自网络标号连接到具体引脚。看总线时要展开成单根信号，逐根确认连接。

作用：简化图纸、跨页连接、减少连线交叉，是读懂复杂原理图（尤其是 FSMC 接 LCD、SRAM 这类并行接口）的关键。

### 如何判断原理图中是否存在电平转换电路？（如 3.3V 和 5V 之间）

判断是否存在电平转换，核心是**识别电压域和转换器件**：

- **看电压网络**：图上出现 `3V3`、`5V`、`VCC_5V`、`VDD_3V3` 等多个电源网络，说明板上有多个电压域，存在电平转换的需求。
- **找转换芯片**：常见电平转换器件有 TXS0108/TXB0108（双向自动方向）、SN74LVC4245（双向带方向控制）、PCA9306（I2C 电平转换）、分立 MOS 管双向转换电路（如 2N7002）。
- **找转换电路**：电阻分压（5V→3.3V 单向）、开漏+上拉电阻（I2C 常用，上拉电压决定高电平）、三极管/MOS 开关等。
- **判断是否直连**：若 5V 器件（如 5V 供电的传感器、OLED）直接连到 3.3V MCU 引脚而无任何转换，属于电平不匹配的隐患，可能过压损坏引脚。

典型例子：I2C 总线开漏输出 + 上拉到 3.3V 即可安全连接 5V 从设备；UART 常用转换芯片或分压；SPI 高速信号则需专用电平转换芯片。

## 看懂芯片手册

### STM32 数据手册（Datasheet）和参考手册（Reference Manual）有什么区别？

**数据手册（Datasheet）**：面向**硬件选型与电路设计**，回答"这颗芯片能干什么、怎么接线、电气上是否安全"。典型内容包括：产品特性概述与功能框图、型号命名与订购信息、引脚定义与封装图、引脚复用功能表、存储器映射、电气特性（绝对最大额定值、推荐工作条件、I/O 特性、ADC 特性、功耗）、封装尺寸与订购代码。篇幅一般几十到一百多页。

**参考手册（Reference Manual）**：面向**软件开发者**，回答"软件怎么配寄存器把外设跑起来"。典型内容包括：系统架构与总线矩阵、存储器组织、时钟树与 RCC、GPIO、以及每个外设（USART/SPI/I2C/TIM/ADC/DMA 等）的功能描述与**寄存器级定义**（每个寄存器每一位的含义、复位值、读写属性）。篇幅通常数百上千页。

一句话区别：**数据手册管"硬件能不能接、怎么接"，参考手册管"软件怎么写"**。另外注意：参考手册通常覆盖一个系列（如 RM0008 覆盖整个 STM32F1 系列），而数据手册按具体型号发布（如 STM32F103C8T6 有独立的数据手册）。

### 拿到一款新的 STM32 芯片，应该先看手册的哪些部分？

推荐按"**宏观 → 引脚 → 电气 → 外设**"的顺序，先建立全貌再深入细节：

1. **产品概述与功能框图**（数据手册第 1\~2 节）：看芯片有哪些外设、多少 Flash/RAM、几路 ADC/定时器、支持哪些通信接口，形成整体印象。
2. **型号命名与订购信息**：确认具体型号的引脚数、Flash/RAM 容量、封装、温度等级，避免选错型号。
3. **引脚定义与封装图**：看引脚数量、每个引脚的默认功能和位置，为电路设计打基础。
4. **存储器映射（Memory map）**：了解 Flash、SRAM、外设寄存器的地址范围，这是写驱动和看链接脚本的前提。
5. **电气特性**：先看绝对最大额定值和推荐工作条件，确定供电电压、I/O 电平、温度范围，保证设计安全。
6. **时钟树**（参考手册 RCC 章节）：确定系统时钟怎么配、各总线频率上限。
7. **目标外设章节**：用到哪个外设就精读对应的功能描述和寄存器描述。

### 如何从数据手册中查找引脚定义和引脚复用功能表？

引脚定义和复用功能表都在**数据手册**中，查找方法如下：

**① 引脚定义表（Pin definitions）**：数据手册中通常以"Pin definitions"或"Pinouts"为标题的表格，按引脚号列出：引脚名称（如 PA9）、类型（I/O/电源/地）、默认功能（Main function，如 JTAG/SWD/NRST 等上电默认功能）、复用功能列（AF0\~AF15，F4 系列）。直接搜索引脚名（如 "PA9"）即可定位。

**② 引脚复用功能表（Alternate function mapping）**：F1 系列在数据手册中有"Alternate function mapping"表，列出引脚可重映射到的功能；F4 系列通过 GPIO 复用寄存器 AFRL/AFRH 选择 AF0\~AF15，各引脚支持的 AF 组合在数据手册的复用功能表里逐引脚列出。

**③ 使用步骤**：确定外设信号（如 USART1_TX）→ 查复用表找到候选引脚（如 PA9）→ 确认该引脚在当前封装中存在且无冲突 → 回到引脚定义表核对默认功能与电气属性 → 软件中把该引脚配置为对应 AF。

**易错点**：同一个引脚可能支持多个 AF，要确认所选 AF 编号与软件配置一致（如 F4 中 PA9 的 USART1_TX 是 AF7，配置错了外设不工作）；还要注意某些引脚默认被 JTAG/SWD 占用（PA13/PA14/PA15/PB3/PB4）。

### 如何从参考手册中找到某个外设的寄存器描述？

外设寄存器描述集中在**参考手册**中，查找路径：

1. **看目录定位外设章节**：参考手册每个外设独立成章（如"USART"、"I2C"），章节内部结构一般为"概述 → 主要特性 → 功能描述 → **寄存器描述（Registers）**"，直接跳到寄存器描述小节。
2. **用搜索定位寄存器**：在 PDF 中直接搜索寄存器名（如 `USART_SR`、`CR1`、`BRR`），可快速跳到寄存器描述表格。
3. **读寄存器描述表**：每个寄存器表格包含偏移地址（Offset）、复位值（Reset value）和每一位的定义：位名、位号（bit 0\~31）、读写属性、置位/复位的含义。
4. **计算实际地址**：外设基地址（在"内存映射/寄存器边界地址"表中查，如 USART1 基地址 0x40013800）+ 寄存器偏移 = 寄存器实际地址。CMSIS 头文件已把这些封装成结构体（如 `USART1->SR`）。

**读写属性要分清**：`rw` 可读可写、`r` 只读、`w` 只写、`rc_w0` 读可清除（写 0 清除）、`rc_w1` 写 1 清除（如中断标志位）、`rs` 置位等。按错误属性操作会导致寄存器行为异常。

### 手册中的电气特性（电气参数）需要关注哪些？（电压、电流、温度）

电气特性在**数据手册**的"Electrical characteristics"章节，重点关注三类：

- **电压参数**：VDD 供电范围（如 STM32F103 为 2.0\~3.6V）、VDDA 模拟供电、VREF+/VREF- 参考电压、I/O 输入高电平阈值 VIH 与低电平阈值 VIL（决定逻辑电平是否兼容，如与 5V 器件对接）、输出高/低电平 VOH/VOL。
- **电流参数**：单个 I/O 最大灌/拉电流（如 ±8mA 标准、±20mA 高驱动）、全芯片总电流限制（如 100mA 级）、各工作模式（运行/睡眠/停机/待机）下的 IDD 电流（用于电池供电的功耗估算）、上电浪涌电流。
- **温度参数**：环境工作温度范围（-40\~85℃ 或 -40\~105℃ 等型号后缀）、存储温度、结温 Tj 上限、封装热阻 θJA（用于热设计，估算芯片温升）。

**工程应用**：根据电压范围设计电源与电平匹配电路；根据 I/O 电流能力计算限流电阻；根据功耗电流选电池/稳压器容量；根据温度范围确认产品使用环境，必要时做热设计。

### 如何根据手册中的时钟树图配置系统时钟？

时钟树（Clock tree）位于**参考手册的 RCC 章节**，是一张从时钟源到各总线/外设的完整分发图。以 STM32F1 配置 72MHz 为例，标准流程：

1. **使能 HSE 并等待就绪**：RCC->CR 置位 HSEON，等待 HSERDY 置 1（外部 8MHz 晶振）。
2. **配置 Flash 等待周期**：72MHz 时 FLASH->ACR 需设置 2 个等待周期并开启预取缓冲，否则 CPU 取指会出错。
3. **配置 PLL**：RCC->CFGR 选择 PLL 源为 HSE（PLLSRC=1），设置倍频系数 PLLMUL=9（8MHz × 9 = 72MHz）。
4. **配置总线分频**：AHB 预分频 =1（72MHz）；APB1 预分频 =2（36MHz，不能超过 36MHz 上限）；APB2 预分频 =1（72MHz）。注意 APB 分频 ≠1 时，定时器时钟自动 ×2。
5. **使能 PLL 并等待就绪**：CR 置位 PLLON，等待 PLLRDY。
6. **切换系统时钟**：CFGR 的 SW 位选择 PLL 作为 SYSCLK，读取 SWS 确认切换成功。

**核对时钟树图的要点**：每个时钟源的最高频率、PLL 输出范围、各总线（AHB/APB1/APB2）和外设时钟的**频率上限**（如 F1：APB1≤36MHz、APB2≤72MHz），超频会导致外设工作异常。HAL 库中对应 `HAL_RCC_OscConfig()` + `HAL_RCC_ClockConfig()`。

### 手册中的"绝对最大额定值"和"推荐工作条件"有什么区别？

**绝对最大额定值（Absolute Maximum Ratings）**：芯片**不允许达到的极限值**，超过即可能造成永久损坏。例如：VDD 最大 4.0V、任意 I/O 电压 -0.3V\~VDD+0.3V、结温最大 150℃、每个引脚最大灌/拉电流等。表格通常带有明确警告："Stresses above those listed may cause permanent damage"。这些值**不是工作条件**，不能作为设计目标，也不能在此状态下长期运行。

**推荐工作条件（Recommended Operating Conditions）**：芯片**保证正常、可靠工作**的参数范围，例如 VDD 2.0\~3.6V、环境温度 -40\~85℃（或 105℃）、I/O 驱动能力等。设计必须保证芯片始终工作在这个范围内。

**核心区别**：绝对最大额定值是"损坏阈值"，推荐工作条件是"正常工作窗口"。两者之间的区间（如 VDD 3.6\~4.0V）是**不允许停留**的危险区。

**工程含义**：电源设计要留裕量，纹波/尖峰不能碰到绝对最大上限；外部瞬态（ESD、浪涌）用 TVS 等保护；热设计保证最坏工况下结温低于上限；传感器等外部信号幅值不能超出 I/O 电压范围。

### 如何从手册中查找 Flash 和 RAM 的大小及地址映射？

**Flash/RAM 容量**：最快看**型号名**（如 STM32F103**C8**T6 中 8=64KB Flash；**R**B=128KB、**Z**E=512KB 等），或查数据手册的订购信息表。

**地址映射（Memory map）**：数据手册或参考手册开头都有内存映射表/图，F1/F4 典型地址：

- Flash 主存储区：**0x0800_0000** 起始（F1/F4 一致），容量由型号决定
- SRAM：**0x2000_0000** 起始（F1）；F4 还有 CCM RAM（0x1000_0000 起始，如 64KB）
- 系统存储器（内置 Bootloader）：F1 约 0x1FFF_F000，F4 约 0x1FFF_0000（用于串口/USB 下载）
- 外设区：F1 从 0x4000_0000 起（APB1 0x4000_0000、APB2 0x4001_0000、AHB 0x4002_0000）；F4 的 AHB1 在 0x4002_0000、APB1/APB2 在 0x4000_0000/0x4001_0000
- Option Bytes、备份寄存器等也在映射表中列出

**实际使用**：链接脚本（.ld / scatter 文件）就是按内存映射定义 FLASH（ROM）和 RAM 的起始地址与长度；写 Bootloader 跳转、操作 Flash 时也依赖这些地址。查看方法：数据手册"Memory map"表按地址列出每个区域的起始/结束地址与大小。

### 中断向量表在手册的哪里？如何查找某个中断的优先级和编号？

**中断向量表位置**：在**参考手册**的 NVIC 章节（如 F1 参考手册 RM0008 的"Table of interrupt vectors"），列出全部中断：向量编号（Position / IRQn）、向量地址、中断源名称。此外，编程手册（PM）中也有异常向量表（Reset、NMI、HardFault、SysTick 等内核异常）。

**查找某个中断的编号和名称**：先确定外设中断名（如 USART1 全局中断），在向量表中找到对应行，Position 值就是 IRQn 编号；CMSIS 头文件（`stm32f1xx.h`/`stm32f4xx.h`）中的 `IRQn_Type` 枚举与之一一对应（负数为内核异常，如 -14=SysTick；0 及以上为外设中断）。

**中断服务函数名**：在启动文件（`startup_stm32f1xx.s`）中，向量表按中断名定义了 ISR 入口，如 `USART1_IRQHandler`。函数名必须与启动文件一致，否则中断触发后跳转到默认的无限循环。

**优先级配置**：优先级分组由 SCB->AIRCR 的 PRIGROUP 决定（F1 支持 4 位优先级，可配 0\~4 分组）；每个中断的抢占优先级/子优先级写在 NVIC->IPR 寄存器；HAL 中通过 `HAL_NVIC_SetPriority()` 和 `HAL_NVIC_EnableIRQ()` 配置。

### 如何根据手册中的寄存器位定义来编写外设驱动代码？

以寄存器位定义写驱动的通用流程（以配置 USART 为例）：

1. **查基地址**：从内存映射表中找到外设基地址（如 USART1 = 0x40013800）。
2. **查寄存器偏移与位定义**：在参考手册外设章节的寄存器描述表里找目标寄存器（如 CR1、BRR、SR）的偏移和每一位含义。
3. **访问寄存器**：直接用指针 `*(volatile uint32_t *)(0x40013800 + 偏移)`，或更推荐用 CMSIS 结构体 `USART1->CR1`（头文件已按基地址+偏移封装好）。
4. **按位操作**：读-改-写（读寄存器 → 置位/清位 → 写回），例如使能 UE、TE：`USART1->CR1 |= (1<<13) | (1<<3)`；查表得到位号，或用 CMSIS 宏 `USART_CR1_UE`。
5. **遵守时序/解锁要求**：某些寄存器有写保护或必须先解锁（如 Flash 编程要先写 KEY 序列），某些位必须按特定顺序配置（如先配波特率再使能外设）。
6. **轮询/等待状态位**：发送前等 TXE，发送完等 TC；接收等 RXNE。状态位在 SR 等寄存器中。
7. **验证**：编译后用调试器查看寄存器实际值，或用示波器/逻辑分析仪验证引脚波形。

**位属性注意**：中断标志多为 `rc_w0`/`rc_w1`（读可清除/写 1 清除），直接赋值 =0 可能清不掉或误清其他位，必须按手册要求操作。

### 手册中的"注意事项"（Note/Caution）通常包含哪些重要信息？

手册中的提示按严重程度分等级：

- **Note（注）**：补充说明或澄清，帮助正确理解，不影响功能；
- **Caution（注意/警告）**：不遵守会导致功能异常甚至损坏，如"访问外设寄存器前必须先使能其时钟"；
- **Warning/Important**：更高风险的提醒，通常涉及电源、引脚或安全。

常见注意事项内容：

- **外设使用前提**：必须先使能时钟/复位，否则读回 0x00 或硬件无响应
- **初始化顺序**：某些外设要求先配置参数再使能（如 DMA 要先配好通道再使能），顺序颠倒会失败
- **时序/同步要求**：如总线仲裁、DMA 与 CPU 竞争、多主机冲突的处理
- **引脚特殊要求**：I2C 必须开漏、某些引脚上电默认被调试功能占用、ADC 输入阻抗与采样时间
- **频率/等待周期限制**：Flash 等待周期、APB 分频上限
- **上下电与复位要求**：电源时序、复位脉宽
- **勘误（Errata）**：芯片已知问题（silicon bugs）与规避方法，硬件/软件设计都应查阅对应型号的勘误表

工程建议：精读所用外设章节的全部 Note/Caution，特别注意带 "must" 的强制性要求；项目异常排查时优先对照 errata。

### 不同系列 STM32（F1/F4/H7）的手册结构有什么异同？

**相同点**：三大系列都采用"数据手册 + 参考手册 + 编程手册(PM) + 勘误表"的文档体系；都有内存映射、时钟树、外设寄存器描述、电气特性等核心章节；引脚定义和复用表都在数据手册。

**不同点**：

- **内核与编程手册**：F1=Cortex-M3（PM0056）；F4=Cortex-M4F 带 FPU（PM0214）；H7=Cortex-M7（PM0253），带 L1 Cache 和 MPU，内核特性更复杂。
- **GPIO 复用机制**：F1 复用功能固定、重映射走 AFIO；F4/H7 通过 AFRL/AFRH 选择 AF0\~AF15，更灵活。
- **时钟系统**：F1 单 PLL；F4 多 PLL（主 PLL + PLLI2S 等）；H7 时钟树最复杂（多 PLL、多时钟域、独立电源域），配置难度递增。
- **内存与总线**：F1 单 AHB；F4 增加 CCM RAM、ART 加速器；H7 采用 AXI 多主总线 + 多核架构、更大 Cache，内存映射和外设基地址与 F1/F4 不同（不能直接照搬）。
- **外设差异**：H7 外设更丰富（如更多定时器、LPUART、更高主频），F4 增加 SDIO/DCMI/FMC 等，F1 外设最少。
- **手册版本**：参考手册按具体型号分组（如 F1 全系列共用 RM0008；F4 有 RM0090/RM0383 等；H7 有 RM0433 等），阅读前要确认对应自己型号的 RM 编号，避免混用手册。

**阅读建议**：先确认型号对应的参考手册编号；核心章节（memory map、时钟树、外设寄存器）阅读方法三个系列通用，但地址和细节必须查对应手册。

# 第二版

## 开发环境搭建（第1章）

### 一个 STM32 工程从建立到烧录运行，完整流程是怎样的？STM32CubeMX 和 STM32CubeIDE 各起什么作用？

一个 STM32 工程从建立到烧录运行，完整流程为：

1. **选型与建工程：**确定芯片型号（如 STM32F103C8T6），用 **STM32CubeMX** 选择芯片并图形化配置时钟树、引脚复用、外设（GPIO/UART/ADC/TIM 等）、中断和中间件（如 FreeRTOS），生成初始化代码工程（可选择 MDK-ARM / CubeIDE / GCC 等工具链）；
2. **编写业务代码：**在生成的 main.c 等文件中添加应用逻辑；
3. **编译链接：**生成可烧录的固件（.hex / .bin / .elf）；
4. **烧录下载：**通过 ST-Link / J-Link（SWD/JTAG）或串口 ISP 把固件写入 Flash；
5. **调试运行：**复位运行，用断点、单步、串口打印等方式验证功能。

**STM32CubeMX 的作用：**图形化配置器。自动完成时钟树、引脚映射和外设初始化代码的生成，避免手翻数据手册、手写寄存器配置，显著降低配置错误率，是"工程脚手架"生成工具。

**STM32CubeIDE 的作用：**集成开发环境（基于 Eclipse + GCC 工具链）。提供代码编辑、编译、烧录、调试的一体化环境，是"干活的地方"。

一句话：CubeMX 负责**生成工程**，CubeIDE 负责**编译调试运行**。

### STM32 的启动流程是怎样的？上电后第一条指令是什么？

STM32（Cortex-M 内核）的启动流程：

1. **上电/复位：**根据 BOOT0/BOOT1 引脚决定从哪启动：主 Flash（0x08000000）、系统存储器（Bootloader，用于 ISP 串口下载）或内置 SRAM；
2. **取向量表：**硬件自动到向量表地址读取两个关键值——向量表第 1 个字作为**初始 SP（栈顶地址）**，第 2 个字作为**复位向量 Reset_Handler 入口地址**；
3. **跳转执行：**PC 跳转到 Reset_Handler，**上电后第一条真正执行的指令就是 Reset_Handler 的入口指令**（即复位中断服务函数的第一条指令）；
4. **系统初始化：**Reset_Handler 内依次执行：SystemInit()（配置时钟）→ 搬运 .data 段、清零 .bss 段（C 运行环境准备）→ 调用 main()；
5. main() 中再完成外设初始化与业务逻辑。

注意点：

- 向量表默认在 0x08000000（Flash），通过 `VTOR` 寄存器可设置偏移，Bootloader 跳转 APP 时必须把向量表重定位到 APP 起始地址，否则中断会跑飞；
- “上电后第一条指令”具体指 **Reset_Handler 的第一条指令**（向量表第二个字指向的位置），不是 main()。

## GPIO控制器及其应用（第3章）

### GPIO 的 8 种工作模式分别是什么？输入模式和输出模式各自适用什么场景？

GPIO 的 8 种工作模式：

- **输入 4 种：**浮空输入、上拉输入、下拉输入、模拟输入；
- **输出 4 种：**开漏输出、推挽输出、开漏复用功能、推挽复用功能。

**输入模式适用场景：**读取外部数字电平，检测外界高低变化——按键、传感器数字输出、通信接口输入（UART RX、I2C SDA/SCL 等）。

**输出模式适用场景：**主动驱动外部设备——LED、蜂鸣器、继电器、电机控制信号；复用功能输出则交给内部外设硬件（UART TX、SPI MOSI/SCK、PWM 等）。

其中推挽输出能力强（可拉高可拉低），开漏输出只能拉低、拉高靠外部上拉，用于 I2C 等需要线与和多电平匹配的场合。

### GPIO 的输入模式内部结构是怎样的？施密特触发器起什么作用？

GPIO 输入模式的内部结构（以 STM32F1 为例）：**引脚 → 可选上下拉电阻（PUPDR）→ 施密特触发器 → IDR 寄存器 → 输入数据总线**。外部信号经施密特触发器整形后，被锁存到 IDR，CPU 读 IDR 即可获得 0/1 电平。

**施密特触发器的作用：**

- **整形：**把缓慢变化或带噪声的信号转换成陡峭的 0/1 数字电平；
- **滞回特性：**拥有两个阈值——正向阈值 V+ 和负向阈值 V-（V+ > V-），输入高于 V+ 才判高、低于 V- 才判低，中间区域保持原状态，从而**抑制信号在阈值附近抖动导致的输出反复翻转**，提高抗干扰能力；
- 在**模拟输入模式**下，施密特触发器和上下拉电阻会被断开，让模拟电压直接进入 ADC，避免数字电路影响模拟采样。

### 如何用 GPIO 实现按键输入？为什么要消抖？软硬件消抖各怎么做？

**按键输入实现：**使能 GPIO 时钟，把引脚配置为输入模式。常见接法：按键一端接 GPIO、一端接 GND，配**内部上拉输入**——未按下读到高电平，按下读到低电平（也可反过来用下拉输入）。然后循环读取 IDR（或 `HAL_GPIO_ReadPin`）判断按键状态。

**为什么要消抖：**机械按键的触点在闭合/断开瞬间会发生多次弹跳（约 5\~20ms 的杂乱脉冲），不消抖的话按一次键可能被 CPU 误判成多次按下/松开，导致功能错乱。

**软件消抖：**

- **延时消抖：**检测到电平变化后延时 10\~20ms 再读一次确认（简单但阻塞）；
- **定时器/状态机消抖：**用定时器周期性扫描，连续 N 次采样一致才判定有效（非阻塞，推荐）；
- 还可做松手检测（按下处理一次，直到松开才允许下次触发）。

```c
// 延时消抖示例：低电平有效
if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
    HAL_Delay(20);   // 消抖延时
    if (HAL_GPIO_ReadPin(GPIOA, GPIO_PIN_0) == GPIO_PIN_RESET) {
        // 确认按下，执行按键逻辑
    }
}
```

**硬件消抖：**RC 低通滤波（如 10kΩ + 0.1µF，时间常数约 1ms 级）、RS 触发器（双稳态锁存）、专用消抖芯片。

### GPIO 有哪几个关键寄存器？为什么 HAL 库的 HAL_GPIO_WritePin 效率有时不如直接操作寄存器？

**GPIO 关键寄存器（以 STM32F4 为例）：**

- `MODER`：模式选择（输入/输出/复用/模拟）；
- `OTYPER`：输出类型（推挽/开漏）；
- `OSPEEDR`：输出速度等级；
- `PUPDR`：上下拉配置；
- `IDR`：输入数据寄存器（只读，读外部电平）；
- `ODR`：输出数据寄存器（可读可写）；
- `BSRR`：置位/复位寄存器（只写，原子操作）；
- `AFRH/AFRL`：复用功能选择（F1 用 AFIO 重映射）；
- `LCKR`：端口配置锁定。

**为什么 HAL_GPIO_WritePin 效率不如直接操作寄存器：**

- `HAL_GPIO_WritePin` 每次调用包含参数校验、分支判断、读改写逻辑和函数调用/返回开销，编译后往往有几十条指令；
- 直接写寄存器（如 `GPIOA->BSRR = (1 << 5)`）只需 1\~2 条指令；
- 在高速翻转场景（IO 模拟时序、LED 点阵扫描、逐位读写传感器）差距明显；
- 优化手段：需要极致性能时用寄存器直接操作或位带操作；仅在低频、可读性优先的代码里用 HAL。

## 时钟控制器及其应用（第4章）

### STM32F4 有哪几个时钟源？系统时钟 SYSCLK 是怎么产生和分配的？

**STM32F4 的时钟源：**

- **HSI：**内部高速 RC，16MHz，上电默认时钟，精度一般（校准后约 ±1%），无外部晶振时的备用；
- **HSE：**外部高速晶振，常用 8/25MHz，精度高，系统主时钟的推荐源头；
- **LSI：**内部低速 RC，约 32kHz，供独立看门狗 IWDG、RTC（低精度）使用；
- **LSE：**外部低速晶振 32.768kHz，供 RTC 精确走时；
- **PLL：**锁相环，对 HSI/HSE 倍频得到高频时钟，是产生 SYSCLK 的核心。

**SYSCLK 的产生与分配：**

1. 选择 PLL 输入源（HSE 或 HSI），通过 PLLM/PLLN/PLLP 配置倍频，例如 25MHz HSE → 25/25 × 336 / 2 = 168MHz（F407 典型配置）；
2. 通过 SW 位选择系统时钟源为 PLL（或 HSI/HSE），得到 **SYSCLK**；
3. **分配：**SYSCLK → AHB 预分频（HPRE）得到 HCLK → APB1 预分频（最大 42MHz）和 APB2 预分频（最大 84MHz）得到外设总线时钟；
4. **定时器时钟 ×2 规则：**APB1/APB2 预分频不为 1 时，定时器时钟 = PCLK×2（如 PCLK1=42MHz 时 TIMxCLK=84MHz），保证定时器能用足 84MHz。

注意：F1 常用系统时钟 72MHz，F4 常用 168MHz（F429 180MHz），配置时钟时还要注意 Flash 等待周期（WS）与电源电压匹配。

### 什么是低功耗模式？STM32 有哪几种？各有什么特点和唤醒方式？

**低功耗模式：**通过降低或停止时钟、关闭外设电源来减小功耗，让系统在待机时省电，需要时再被唤醒。STM32 的三种主要模式（功耗从低到高排列：待机 < 停机 < 睡眠）：

| 模式 | CPU | 时钟/外设 | SRAM/寄存器 | 典型功耗 | 唤醒方式 |
|-|-|-|-|-|-|
| 睡眠 Sleep | 停止 | 全部继续运行 | 保持 | mA 级（省电有限） | 任意中断/事件（WFI/WFE） |
| 停机 Stop | 停止 | 大部分时钟停止（可留 LSI 等） | 保持 | µA 级 | EXTI 外部中断/事件、RTC 闹钟等 |
| 待机 Standby | 停止 | 全部停止 | 丢失（备份域除外） | 约 1µA（最低） | NRST、WKUP 引脚、RTC 闹钟/入侵 |

补充：

- 还有 **VBAT 备份域供电**（仅 RTC + 备份寄存器工作）用于最低功耗场景；
- 进入方式：配置 PWR 寄存器后用 `WFI/WFE` 指令进入；
- 唤醒后：Sleep/Stop 从唤醒点**继续执行**；Standby 相当于**复位重启**（需重新初始化）；
- 低功耗设计要点：不用的外设关时钟、GPIO 引脚配成模拟/下拉防漏电、待机前保存需要的数据到备份寄存器。

## 串口控制器及其应用（第5章）

### UART 的帧格式是怎样的？如何计算波特率？STM32 的波特率怎么算？

**UART 帧格式：**空闲（高电平）→ **起始位**（1 个低电平）→ **数据位**（8 或 9 位，LSB 先发）→ **校验位**（可选，奇/偶/无）→ **停止位**（0.5/1/1.5/2 位，高电平）→ 回到空闲。接收方靠起始位下降沿同步，之后按波特率逐位采样。

**波特率与比特率：**波特率是每秒传输的码元数（单位 Baud），二进制调制时每码元 1 bit，此时波特率 = 比特率（bps）。

**STM32 波特率计算：**

波特率 = 串口时钟/（过倍采样×目标波特率）

波特率 $Baud = \frac{f_{CK&#125;&#125;{16 \times USARTDIV}$，即 

$USARTDIV = \frac{f_{CK&#125;&#125;{16 \times Baud}$（16 倍过采样；8 倍过采样时分母为 8）。`USARTDIV` 写入 `BRR` 寄存器：整数部分放高 12 位，小数部分 4 位（×16 取整）。

例：F1 的 APB2 时钟 72MHz，波特率 9600：$USARTDIV = 72000000/(16 \times 9600) = 468.75$，整数 468 = 0x1D4，小数 0.75×16 = 12 = 0xC，故 `BRR = 0x1D4C`。

注意：F4 的 BRR 结构为 DIV_Mantissa（高 16 位）+ DIV_Fraction（低 4 位），计算方式与 F1 类似，整数部分直接写高位即可。

### 串口的三种收发方式（轮询/中断/DMA）有什么区别？各自适用什么场景？

串口三种收发方式的区别与适用场景：

| 方式 | 原理 | CPU 占用 | 实时性 | 代码复杂度 | 适用场景 |
|-|-|-|-|-|-|
| 轮询 | CPU 循环查询 TXE/RXNE 标志位，逐字节收发 | 高（全程占用） | 低（阻塞） | 最低 | 初始化打印、低速简单通信、发少量数据 |
| 中断 | 每收/发一字节触发中断，在 ISR 中处理 | 中（仅收发时占用） | 高（事件驱动） | 中 | 不定长数据接收、命令交互、数据量中等 |
| DMA | 外设与内存直接搬运，完成/半完成触发中断 | 低（几乎不占） | 高（适合连续流） | 较高 | 大数据量连续收发（ADC 采样、传感器数据流、文件传输） |

选择建议：

- 简单调试打印用**轮询**；
- 需要响应及时、数据长度不定用**中断**（配合空闲中断可做不定长接收）；
- 数据量大、要求不打扰 CPU 用 **DMA**（如串口 DMA + 空闲中断）。

### printf 如何重定向到串口？为什么需要重定向？

**为什么需要重定向：**C 标准库的 `printf` 默认把数据输出到"标准输出设备"，在裸机嵌入式环境下标准输出没有对应硬件（可能指向调试器或直接卡死），必须把 printf 的底层字符输出函数重定向到串口，格式化数据才能从串口发送到电脑串口助手。

**实现方法（以 HAL + MDK 为例）：**

1. 重写底层输出函数 `fputc`（GCC 下是 `_write`），在其中调用 `HAL_UART_Transmit` 发送单字符；
2. MDK 工程勾选 **MicroLIB（微库）**，避免半主机模式（否则 printf 可能卡死在半主机调用）；
3. 包含 `stdio.h`，之后即可直接使用 `printf`。

```c
/* 重定向 printf 到串口1（MDK + MicroLIB） */
int fputc(int ch, FILE *f) {
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 0xFFFF);
    return ch;
}
```

注意事项：

- 默认版 `printf` 是**阻塞式**逐字节发送，**不要在中断服务函数中直接调用**（可能长时间占用中断）；
- 追求效率可改用 DMA 版 printf 或自己封装格式化发送；
- 多任务环境（RTOS）下注意加互斥保护。

## 中断控制器及其应用（第6章）

### 什么是中断？STM32 的中断处理流程是怎样的（从触发到返回）？

**中断：**CPU 暂停当前正在执行的任务，转去执行某个事件对应的中断服务函数（ISR），处理完后再回到原任务继续执行。它让 CPU 不必轮询等待事件，是嵌入式系统响应外部事件的核心机制。

**STM32 中断处理流程（从触发到返回）：**

1. **事件发生：**外设产生中断请求（如串口收到数据、定时器溢出、GPIO 电平变化），置位中断标志；
2. **NVIC 仲裁：**中断请求送到 NVIC，NVIC 检查使能位，并按抢占优先级、子优先级仲裁——只有优先级足够高（能抢占当前执行环境）才会被响应；
3. **硬件自动压栈：**CPU 自动把 xPSR、PC、LR（EXC_RETURN）、R0\~R3、R12 压入当前栈，然后从**向量表**取出该中断对应的 ISR 入口地址并跳转；
4. **执行 ISR：**运行用户编写的中断服务函数（清中断标志、读取/处理数据）；
5. **出栈返回：**执行完 ISR 后硬件自动出栈恢复现场，通过 EXC_RETURN 回到被中断处继续执行。

要点：

- 压栈/出栈由**硬件自动完成**，无需软件干预；
- ISR 要**短小精悍**（尽快清标志、快速处理，重活放到主循环）；
- 中断里不能使用阻塞延时等影响实时性的操作。

### NVIC 是什么？STM32 的中断优先级如何分组与仲裁？

**NVIC：**嵌套向量中断控制器（Nested Vectored Interrupt Controller），是 Cortex-M 内核自带的异常/中断管理单元。它负责：中断使能/禁用、挂起与清除、优先级分组、中断嵌套仲裁，以及向量表取指（决定中断响应入口）。外设只管把请求送到 NVIC，最终能否响应由 NVIC 裁决。

**优先级分组：**

- STM32 的优先级分为**抢占优先级（可嵌套打断）**和**子优先级（同抢占下按次序）**；
- 通过 `SCB->AIRCR` 的 PRIGROUP 字段分组（F1 为 4 位优先级，分组 0\~4；F4 支持分组 0\~7），例如分组 2 表示 2 位抢占 + 2 位子优先级（F1），或 2 位抢占 + 6 位子优先级（F4，4 位有效）；
- 数值越小优先级越高。

**仲裁规则：**

1. 先比**抢占优先级**：抢占优先级高（数值小）的中断可以打断正在执行的低抢占中断（嵌套）；
2. 抢占相同则比**子优先级**：决定同抢占组内的响应先后，但不打断彼此；
3. 两者都相同，按**中断向量表编号**，编号小者先响应。

配置接口：寄存器方式 `NVIC_SetPriorityGrouping()`、`NVIC_EnableIRQ()`；HAL 方式 `HAL_NVIC_SetPriority()` + `HAL_NVIC_EnableIRQ()`。

### EXTI 外部中断的工作流程是怎样的？按键中断如何实现？

**EXTI 外部中断工作流程：**外部信号变化 → 引脚复用/映射到 EXTI 线 → 配置触发边沿（上升/下降/双边沿）→ EXTI 线使能 → NVIC 使能对应中断 → 信号触发后进入 `EXTIx_IRQHandler` → HAL 中调用 `HAL_GPIO_EXTI_IRQHandler`（清标志并分发）→ 用户回调 `HAL_GPIO_EXTI_Callback` 中执行业务逻辑。

**按键中断实现步骤：**

1. 使能 GPIO 时钟，将按键引脚配置为**输入模式**（上拉输入，按键接 GND）；
2. **引脚到 EXTI 线映射：**F1 通过 **AFIO** 配置 EXTI 线对应的端口（必须开 AFIO 时钟）；F4 由 **SYSCFG** 管理；
3. 配置 EXTI 触发方式：按键按下为低电平，选择**下降沿触发**；
4. NVIC 使能对应 EXTI 中断（如 EXTI0_IRQn）并设置优先级；
5. 编写 ISR 与回调：在回调里做**消抖**（延时再确认或定时器消抖）和按键业务处理；
6. 主循环中按需响应（如置标志位、处理按下事件）。

注意事项：

- F1 不开 AFIO 时钟，EXTI 映射配置会失效；
- 多个引脚**共用一条 EXTI 线**（如 PA0\~PG0 都对应 EXTI0），同一时刻只能有一个引脚使用该线，需查映射表避开冲突；
- EXTI 中断只负责"通知"，长任务不要在 ISR 里做。

## DMA控制器及其应用（第7章）

### 什么是 DMA？为什么需要 DMA？DMA 传输的三要素是什么？

**DMA（Direct Memory Access，直接存储器访问）：**一种由硬件完成数据传输的机制，能在**不经过 CPU 干预**的情况下，在外设与存储器、存储器与存储器之间搬运数据。传输完成后通过中断通知 CPU 处理。

**为什么需要 DMA：**

- 外设数据量大或频率高（ADC 连续采样、串口高速收发、SPI 读取传感器）时，若由 CPU 逐个字节搬运，会占用大量 CPU 时间；
- DMA 把搬运工作交给独立硬件，**CPU 只在传输开始/结束时参与**，可并行处理其他任务，提升系统吞吐量和实时性；
- 典型收益：多通道 ADC+DMA 连续采样、串口 DMA 收发不阻塞主循环。

**DMA 传输的三要素：**

1. **传输源：**数据从哪来（外设数据寄存器地址或内存地址，是否地址自增）；
2. **传输目标：**数据到哪去（内存地址或外设数据寄存器地址，是否地址自增）；
3. **传输方向 + 数据宽度 + 传输数量：**方向（外设→内存 / 内存→外设 / 内存→内存）、数据宽度（字节/半字/字）、一次传输的单元个数，以及触发源（外设 DMA 请求）和优先级配置。

配置时还需选择通道与外设的映射关系（不同外设对应固定 DMA 通道/流），并用 `HAL_DMA_Start_IT()` 等接口启动。

### 串口 DMA 接收如何实现不定长数据接收？（DMA + 空闲中断）

**原理：**DMA 负责把串口收到的数据**持续自动搬运到缓冲区**（CPU 不参与）；当总线上出现一段空闲（一帧数据发送完毕、无新数据），串口的**空闲中断（IDLE）**触发。在 ISR 中通过 DMA 剩余计数算出本次实际接收长度，从而完成一帧**不定长**数据的接收。

**实现步骤：**

1. 配置 UART 接收 DMA（正常模式或循环模式），使能 DMA 传输，接收缓冲数组；
2. 使能串口**空闲中断**（置 `CR1` 的 IDLEIE 位，HAL 中对应 `__HAL_UART_ENABLE_IT(&huart, UART_IT_IDLE)`）；
3. 在 `USARTx_IRQHandler` 中判断空闲标志：读到 `UART_FLAG_IDLE` 置位后，**先读 SR 再读 DR**（或按 HAL 宏处理）清除标志；
4. 读取 DMA 剩余计数 `__HAL_DMA_GET_COUNTER()`，计算本次接收长度 = **缓冲区大小 - 剩余计数**；
5. 按帧处理数据（解析/回调），然后根据模式恢复接收：循环模式自动继续，正常模式需重新设置 DMA 计数。

```c
// 伪代码：串口中断中处理 IDLE
void USART1_IRQHandler(void) {
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_IDLE)) {
        __HAL_UART_CLEAR_IDLEFLAG(&huart1);          // 清空闲标志
        uint16_t len = RX_BUF_SIZE - __HAL_DMA_GET_COUNTER(&hdma_usart1_rx); // 实际长度
        // 处理 len 长度的数据...
    }
    HAL_UART_IRQHandler(&huart1);
}
```

注意事项：

- DMA 计数器是**递减**的，剩余计数从初值减到 0；
- 空闲标志清除方式（读 SR 再读 DR）在不同系列略有差异，以手册为准；
- 循环模式下缓冲区满会回卷覆盖，需及时取走数据或改用双缓冲。

## ADC控制器及其应用（第8章）

### 什么是采样、量化、编码？ADC 的分辨率、量程与精度是什么关系？

ADC 把模拟信号变为数字量要经过三个步骤：

- **采样：**按固定时间间隔对连续模拟信号取值，把**时间连续**变为**时间离散**（每周期采一个电压点）；
- **量化：**把采样得到的电压值映射到有限个离散电平等级。等级数由**分辨率**决定（12 位 → 2^12=4096 级），量化必然引入误差（量化误差最大为 ±0.5 LSB）；
- **编码：**把量化等级转换为二进制数输出（如 0\~4095），供 CPU 使用。

**分辨率、量程与精度的关系：**

- **量程：**ADC 可转换的电压范围，一般等于参考电压（如 0\~3.3V）；
- **分辨率：**最小可分辨的电压变化，$LSB = \frac{量程}{2^n} = \frac{3.3V}{4096} \approx 0.8mV$（12 位）；数字值 $D = \frac{V_{in&#125;&#125;{量程} \times 2^n$；
- **精度：**实际转换结果与真实电压的偏差，受参考电压精度与温漂、输入噪声、非线性（INL/DNL）、采样时间不足等影响。

关键结论：**分辨率高不等于精度高**——分辨率只决定"分得细不细"，精度决定"测得准不准"；参考电压不稳、噪声大，即使 12 位也可能不如一个校准过的 10 位 ADC 准。

### ADC 的轮询、中断、DMA 三种模式有什么区别？单次/连续、扫描/非扫描怎么组合？

**ADC 三种模式的区别：**

| 模式 | 原理 | CPU 占用 | 适用场景 |
|-|-|-|-|
| 轮询 | 启动转换后循环等待 EOC 标志 | 高（阻塞） | 单次、低频采样，代码最简单 |
| 中断 | 转换完成触发中断，ISR 中读数据 | 中 | 中等频率、事件驱动采样 |
| DMA | 转换结果由 DMA 自动搬运到内存 | 低（几乎不占） | 多通道连续高速采样（推荐） |

**单次/连续：**单次模式转完一次就停，需要再次启动；连续模式转换完自动开始下一次，不停循环。

**扫描/非扫描：**扫描模式按规则组依次转换多个通道（配合 DMA 按顺序存结果）；非扫描模式只转换指定的一个通道。

**典型组合：**

- 单通道单次 + 轮询/中断：简单测量、按键电压检测；
- 多通道扫描 + 连续 + DMA：同时监测多路传感器，CPU 零负担（最常用）；
- 单通道连续 + DMA：连续采集波形数据（如音频、振动）。

## I2C控制器及其应用（第9章）

### I2C 总线的特点是什么？为什么 SDA/SCL 必须用开漏输出加外部上拉？

**I2C 总线的特点：**

- **双线制：**只靠 SDA（数据）和 SCL（时钟）两根线通信；
- **同步串行：**数据按 SCL 时钟同步逐位传输，SCL 高电平时数据稳定、低电平时允许变化；
- **半双工：**同一时刻只能一个方向传输；
- **主从架构、支持多主多从：**用 7 位（或 10 位）从机地址寻址，从机地址必须唯一；
- **开漏线或（Wired-AND）：**所有设备输出级都是开漏结构，通过外部上拉电阻拉高；
- **多种速率模式：**标准 100kbps、快速 400kbps、高速 3.4Mbps 等。

**为什么 SDA/SCL 必须用开漏输出 + 外部上拉：**

- **实现线与与多主机仲裁：**开漏输出只能拉低、不能主动拉高（释放后靠上拉拉高），多个设备同时驱动总线不会发生推挽输出那种"一个发高、一个发低"的短路烧毁；任何设备拉低，总线就是低，天然实现线与和仲裁；
- **支持双向通信：**设备需要既能输出（拉低）又能输入（读线上电平），开漏+上拉让同一根线可写可读；
- **支持电平转换：**上拉电阻接的电压可自由选择（3.3V/5V），让不同电压域的设备挂在同一条总线上，从机侧无需电平转换芯片。

上拉电阻阻值选择：太小功耗大、驱动能力强；太大会使信号上升沿变缓、限制速率（100k 常用 4.7k\~10kΩ，400k 常用 1k\~2.2kΩ）。

### I2C 的完整时序是怎样的（起始、地址、应答、数据、停止）？读写流程分别是什么？

**I2C 完整时序（五个要素）：**

1. **起始（START）：**SCL 保持高电平时，SDA 由高跳变为低；
2. **寻址：**主机发送 7 位从机地址 + 1 位读写位（0=写，1=读），地址匹配的从机应答；
3. **应答（ACK/NACK）：**每传输 1 字节（8 位，MSB 先发）后，第 9 个时钟周期由接收方控制 SDA——拉低=ACK（继续），保持高=NACK（结束/异常）；
4. **数据：**逐字节传输，每字节后跟一个 ACK 位；
5. **停止（STOP）：**SCL 保持高电平时，SDA 由低跳变为高，释放总线。

**写流程（主机写数据到从机）：**START → 从机地址+写(0) → 从机 ACK → 主机发数据字节 → 从机 ACK → …… → STOP。

**读流程（主机从从机读数据）：**START → 从机地址+读(1) → 从机 ACK → 从机发数据字节 → 主机 ACK（继续读）…… → 最后一个字节主机发 **NACK** → STOP。

补充：

- 读寄存器类器件常用**重复起始（Repeated START）**：先写寄存器地址，再发一次 START 转为读；
- 主机收到 NACK 表示"没有该从机 / 从机不想再发 / 数据异常"，应发 STOP 或重复 START 结束传输。

## SPI控制器及其应用（第10章）

### SPI 有哪几根线？四种工作模式（CPOL/CPHA）是怎么回事？

**SPI 的四根线：**

- **SCK：**串行时钟，由主设备产生，决定传输速率；
- **MOSI（主出从入）：**主设备发送数据到从设备；
- **MISO（主入从出）：**从设备发送数据到主设备；
- **CS/SS（片选）：**由主设备拉低选中某个从设备（低有效），一个从机一根 CS，实现"寻址"。

**四种工作模式（由 CPOL 和 CPHA 组合决定）：**

- **CPOL（时钟极性）：**空闲时 SCK 的电平——CPOL=0 空闲为低，CPOL=1 空闲为高；
- **CPHA（时钟相位）：**数据在哪个边沿被采样——CPHA=0 在第一个边沿采样，CPHA=1 在第二个边沿采样。

| 模式 | CPOL | CPHA | 特点 |
|-|-|-|-|
| Mode 0 | 0 | 0 | 空闲低，第一个边沿（上升沿）采样，最常用 |
| Mode 1 | 0 | 1 | 空闲低，第二个边沿（下降沿）采样 |
| Mode 2 | 1 | 0 | 空闲高，第一个边沿（下降沿）采样 |
| Mode 3 | 1 | 1 | 空闲高，第二个边沿（上升沿）采样 |

要点：**主从两端必须配置成相同的模式**才能正确采样；通信前查从设备数据手册确定它支持的模式（多数 SPI Flash/传感器用 Mode 0 或 Mode 3）。

### SPI 和 I2C 有什么区别？各自适用什么场景？SPI 和 UART 呢？

**SPI 与 I2C 的区别：**

| 对比维度 | SPI | I2C |
|-|-|-|
| 引脚数 | 4 根（SCK/MOSI/MISO/CS，CS 每从机一根） | 2 根（SDA/SCL） |
| 速率 | 高（可达数十 Mbps） | 低（标准 100k/快速 400k/高速 3.4M） |
| 寻址方式 | 无地址，靠片选 CS 选从机 | 7/10 位从机地址寻址 |
| 应答机制 | 无应答，靠时序和校验保证 | 每字节有 ACK/NACK |
| 通信方式 | 全双工（收发同时进行） | 半双工（同一时刻单向） |
| 物理层 | 推挽输出 | 开漏 + 上拉（线与） |

**适用场景：**SPI 适合**高速、大数据量、少设备**的场合——SPI Flash、SD 卡、LCD 屏、高速传感器；I2C 适合**低速、多设备、省引脚**的场合——温湿度/姿态传感器、EEPROM、多从机总线。

**SPI 与 UART 的区别：**UART 是**异步**通信（无时钟线，靠波特率对齐，2 根线 TX/RX），点对点、全双工，无需片选；SPI 是**同步**通信（有时钟线，速率更高、时序可控）。UART 适合与 PC/蓝牙/4G 模块等异步设备通信（即插即用，容错好），SPI 适合 MCU 与高速外设之间近距离高速传输。

总结选型：要**快**用 SPI，要**省线多设备**用 I2C，要**点对点异步**用 UART。

## TIM控制器及其应用（第11章）

### STM32 的定时器有哪些分类？基本定时器和通用定时器有什么区别？

**STM32 定时器分类（以 F1 为例）：**

- **基本定时器（TIM6/TIM7）：**只有时基单元——计数、溢出中断/事件、触发 DAC，**没有**输入捕获/输出比较/PWM/外部引脚；
- **通用定时器（TIM2\~TIM5、TIM9\~TIM14）：**在基本定时器基础上增加**4 个独立通道**，支持输入捕获、输出比较、PWM、编码器接口、外部触发等，用途最广；
- **高级定时器（TIM1/TIM8）：**在通用基础上增加**互补输出、死区插入、刹车输入、重复计数**等，专门用于电机控制（H 桥/PWM 驱动）；
- 其他定时相关资源：SysTick（系统滴答，供 HAL_Delay/RTOS 时基）、LPTIM（低功耗定时器）、独立看门狗 IWDG、窗口看门狗 WWDG、RTC（实时时钟）。

**基本定时器 vs 通用定时器：**

| 对比 | 基本定时器 | 通用定时器 |
|-|-|-|
| 时基功能 | 有（计数/溢出中断/DMA） | 有 |
| 输入捕获/输出比较 | 无 | 有（4 通道） |
| PWM 输出 | 无（仅可触发 DAC） | 有 |
| 编码器/外部信号 | 无 | 有 |
| 典型用途 | 延时/周期中断、DAC 触发 | PWM、测频率/脉宽、编码器计数 |

### 什么是 PWM？如何用定时器产生 PWM？频率、占空比、分辨率如何计算？

**PWM（脉宽调制）：**通过固定频率、可调高电平占比（占空比）的方波，等效输出"平均电压"——占空比越大平均电压越高。常用于 LED 调光、电机调速、蜂鸣器发声、舵机控制。

**如何用定时器产生 PWM：**把定时器通道配置为 PWM 模式，计数器 CNT 向上计数并与比较寄存器 `CCRx` 比较：CNT < CCRx 时输出有效电平，CNT ≥ CCRx 时输出翻转电平；CNT 计数到 `ARR` 后溢出清零，进入下一个周期。

**关键参数计算（定时器时钟 f_tim）：**

- **频率：**$F_{PWM} = \frac{f_{tim&#125;&#125;{(PSC+1) \times (ARR+1)}$；
- **占空比：**$Duty = \frac{CCRx}{ARR+1} \times 100\%$；
- **分辨率：**$\frac{1}{ARR+1}$，ARR 越大调节越细腻。

举例：定时器时钟 84MHz，PSC=83，ARR=999，则 $F = 84000000/(84 \times 1000) = 1kHz$；CCR=500 时占空比 50%。

HAL 配置：`HAL_TIM_PWM_Start()` 启动，`__HAL_TIM_SET_COMPARE()` 动态改占空比。

### 输入捕获的工作原理是什么？如何测量脉冲宽度和频率？

**输入捕获的工作原理：**把定时器通道配置为输入捕获模式，当引脚上检测到**指定边沿**（上升沿/下降沿/双边沿）时，硬件自动把当前计数器值 `CNT` 锁存到捕获寄存器 `CCRx` 并触发中断，CPU 在 ISR 中读取 CCRx 即得到该时刻的时间戳。

**测量频率：**捕获连续两个上升沿的时间戳 t1、t2，周期 $T = (t2 - t1) \times 单次计数周期$，频率 $f = 1/T$。

**测量高电平脉宽：**上升沿捕获得 t1，下降沿捕获得 t2，则高电平宽度 $W = (t2 - t1) \times 单次计数周期$；配合周期可算占空比（PWM 输入模式可一次测出频率和占空比）。

注意事项：

- **溢出处理：**若两次捕获之间计数器溢出回绕，需在 ISR 里记录溢出次数，用 (差值 + 溢出次数 × ARR) 修正；
- **输入滤波/分频：**对高频噪声可配置输入滤波和分频（ICF/PSC），避免毛刺误触发；
- **边沿选择：**先配置触发边沿，捕获后需在中断中切换边沿（测脉宽时）或保持（测频率时）；
- 保证被测信号频率 < 定时器计数频率/2，且周期不超计数范围。

## FSMC控制器及其应用（第12章）

### 什么是 FSMC？它的地址映射和时序配置是怎样的？

**FSMC（灵活的静态存储器控制器）：**STM32 用于连接外部存储器/外设的总线控制器，把外部设备映射到 CPU 的地址空间，CPU **像访问内部寄存器/内存一样读写外部设备**（SRAM、NOR Flash、PSRAM、NAND Flash 以及 8080 接口的 LCD 屏等），读写时序由 FSMC 硬件自动产生。

**地址映射：**FSMC 将外部空间划分为 4 个 Bank（Bank1\~4）：

- **Bank1（0x60000000 起）：**NOR Flash / PSRAM / SRAM，分为 4 个片选区 NE1\~NE4，每区 64MB，由片选引脚 `FSMC_NE1~NE4` 选择；
- **Bank2/3（0x64000000 / 0x68000000）：**NAND Flash；
- **Bank4（0x6C000000）：**PC 卡。

**驱动 LCD（8080 接口）的要点：**把 LCD 当作挂在 Bank1 的外部存储器，用一根地址线（如 `FSMC_A0`）接 LCD 的 RS 引脚区分命令/数据——写地址区 = 命令，写数据区 = 数据；`FSMC_NE` 接片选、`FSMC_NWE/NOE` 接读写信号、数据线接 `FSMC_D0~D15`。

**时序配置（FSMC_BCR / FSMC_BTR / FSMC_BWTR）：**

- **BCR：**总线控制——数据宽度（8/16 位）、突发模式、存储器类型等；
- **BTR（读）/ BWTR（写）：**时序参数——**地址建立时间 ADDSET**、**数据建立时间 DATAST**、总线周转时间 ADDHLD 等，需按 LCD 数据手册的 8080 时序（如 tAS/tPW）换算成 HCLK 周期数配置；
- 配置不合适会出现花屏/写不进数据：建立时间太短读不到稳定数据，太长则速度慢。

相比 GPIO 模拟 8080 时序，FSMC 由硬件按配置自动产生读写时序，**一个地址写操作只需几个时钟周期**，刷屏速度提升一个数量级以上。

## DAC控制器及应用（第13章）

### DAC 的工作原理是什么？如何用 DAC 产生任意波形？

**DAC（数模转换器）的工作原理：**把数字量转换为对应的模拟电压。内部由电阻网络（如 R-2R 梯形网络）或电流源阵列按二进制权重叠加电流/分压，输出 $V_{out} = \frac{D}{2^n} \times V_{REF}$（n 为分辨率，如 12 位，D 为 0\~4095）。写入 `DAC->DHR` 数据寄存器（或经 DMA 写入）即可改变输出电压，输出经运放缓冲后驱动负载。

**如何用 DAC 产生任意波形（查表法）：**

1. **准备波形表：**在内存中存一个周期的采样点数组（正弦/三角/锯齿/任意自定义波形），点数越多波形越细腻；
2. **定时触发：**用定时器更新事件（或软件触发）按固定频率触发 DAC 转换，采样点按序写入 DAC 数据寄存器；
3. **DMA 搬运（推荐）：**把波形表通过 DMA 循环搬运到 DAC 数据寄存器，CPU 零参与，输出连续波形；
4. **低通滤波：**DAC 输出是阶梯波，后级加 RC/运放低通滤除高频阶梯成分，得到平滑波形。

```c
// 伪代码：正弦表 + 定时器触发 + DAC
const uint16_t sine_table[128] = { /* 预计算的 128 点 12 位正弦值 */ };
HAL_DAC_Start_DMA(&hdac, DAC_CHANNEL_1, (uint32_t *)sine_table, 128, DAC_ALIGN_12B_R);
```

输出频率 = 触发频率 / 采样点数（如定时器 128kHz 触发、128 点表 → 1kHz 正弦波）。

## 独立看门狗及其应用（第14章）

### 什么是看门狗？独立看门狗（IWDG）的工作原理是什么？如何正确使用？

**看门狗：**一个独立于 CPU 主流程运行的硬件计数器，用于监控程序是否跑飞/死机：程序正常时周期"喂狗"，若长时间不喂（死循环、跑飞、硬件异常），计数器溢出就会**自动复位整个芯片**，把系统拉回正常状态。适用于工业控制、无人值守等不允许长时间死机的场合。

**独立看门狗（IWDG）的工作原理：**

- 时钟源为**独立的 LSI（约 40kHz 内部 RC）**，不依赖主时钟，即使外部晶振/主时钟故障也照常计数；
- 一个 **12 位递减计数器**（0\~4095），由预分频器 PR 和重装载值 RLR 决定超时时间：$T_{out} = \frac{4 \times 2^{PR} \times RLR}{f_{LSI&#125;&#125;$；
- 计数器减到 0 溢出即触发**系统复位**；程序周期向键寄存器 `IWDG_KR` 写 0xAAAA 重装载计数器（喂狗）；
- **一旦启动（写 0xCCCC）无法关闭**，只有上电复位或外部复位才能重新初始化。

**如何正确使用：**

1. 配置 `IWDG_PR` 预分频和 `IWDG_RLR` 重装载值，算出超时时间（留裕量）；
2. 向 `IWDG_KR` 写 0xCCCC 启动；
3. 在主循环**关键任务处理完成后**喂狗（写 0xAAAA），喂狗周期取超时时间的 1/2\~1/4；
4. **不要在中断里喂狗**（会掩盖主程序跑飞）；
5. 调试时通过 DBGMCU 的 DBG_IWDG_STOP 位冻结计数，避免一暂停就复位；
6. Bootloader/升级跳转过程中也要持续喂狗，防止升级期间被复位。

```c
/* 寄存器方式初始化：LSI=40kHz，PR=4（64分频），RLR=625 → 约 1s 超时 */
IWDG->KR = 0x5555;        /* 解除写保护 */
IWDG->PR  = 4;
IWDG->RLR = 625;
while (IWDG->SR & 0x03);   /* 等待 PVU/RVU 清零 */
IWDG->KR = 0xCCCC;         /* 启动 */
/* 主循环喂狗 */
IWDG->KR = 0xAAAA;
```

HAL 对应：`HAL_IWDG_Init()` 配置启动、`HAL_IWDG_Refresh()` 喂狗。

# 知识重点清单

### 启动流程与向量表

上电 → 硬件自动从向量表取 **①初始 SP**（第 1 个字）和 **②Reset_Handler 入口**（第 2 个字）→ 执行 SystemInit → 搬运 .data / 清零 .bss → 进入 main()。

向量表默认在 Flash 0x08000000；**Bootloader 跳 APP 必须用 VTOR 重定位向量表**，否则中断跑飞。

**易错：**“上电第一条指令”是 Reset_Handler 的第一条指令，不是 main()。

### GPIO 八种模式 / 推挽与开漏 

8 种：浮空/上拉/下拉/模拟输入 + 推挽/开漏输出 + 推挽/开漏复用功能。

**推挽**：可主动拉高拉低、驱动强（LED/蜂鸣器）；**开漏**：只能拉低、拉高靠外部上拉（I2C 线与、电平转换、防短路）。

**易错：**I2C 引脚配成推挽会导致多设备同时驱动时短路打架。

### BSRR 原子操作 

BSRR 只写：低 16 位置 1 = 置高，高 16 位置 1 = 拉低；**单条指令完成，不会被中断打断**。

翻转电平：先读 ODR 判断当前电平，再写 BSRR 对应位，避免 ODR 读-改-写被中断位冲刷。

**易错：**BSRR 不可读，读当前输出电平要用 ODR。

### 按键消抖 

机械触点弹跳产生 5\~20ms 毛刺，不消抖会误判多次触发。

软件：延时 10\~20ms 再确认 / 定时器状态机（非阻塞）；硬件：RC 低通、RS 触发器。

常用接法：上拉输入 + 按键接 GND，按下为低电平。

**易错：**只在中断里延时消抖会导致 ISR 阻塞过长。

### 时钟树与 PLL 定时器时钟 ×2 规则 

时钟源：HSI / HSE / LSI / LSE / PLL；SYSCLK → AHB → APB1 / APB2 逐级分频。

**×2 规则：**APB 预分频 ≠ 1 时，定时器时钟 = PCLK × 2（保证定时器用足主频）。

例：F1 72MHz = 8MHz HSE × 9（PLL）；F4 168MHz = 25/25 × 336 / 2。

**易错：**算 PWM 频率/延时忘了 ×2 规则，结果差一倍。

### 低功耗三模式 

**Sleep：**CPU 停、外设时钟继续运行，任意中断唤醒，mA 级；

**Stop：**大部分时钟停止、SRAM 保持，EXTI / RTC 唤醒，µA 级；

**Standby：**全部时钟停止、SRAM 内容丢失（备份域除外），NRST / WKUP / RTC 唤醒，约 1µA。

**易错：**Standby 唤醒 = 复位重启，需重新初始化；Sleep / Stop 从唤醒点继续执行。

### UART 帧格式与波特率 

帧：起始位（低）+ 数据位 8/9（LSB 先发）+ 校验位（可选）+ 停止位 1/2。

波特率：$Baud = \frac{f_{CK&#125;&#125;{16 \times USARTDIV}$；72MHz / 9600 → USARTDIV = 468.75 → BRR = 0x1D4C。

**易错：**双方波特率不一致必乱码；小数部分 ×16 取整写入 BRR 低 4 位。

### 串口三种收发方式 DMA + 空闲中断不定长接收 

轮询（阻塞占 CPU）/ 中断（事件驱动）/ DMA（几乎不占 CPU）。

不定长接收：**DMA 连续搬运 + IDLE 空闲中断**判帧结束；实际长度 = 缓冲区大小 − DMA 剩余计数。

**易错：**IDLE 标志清除需先读 SR 再读 DR；DMA 计数器是递减的。

### printf 重定向 

裸机无标准输出，重写 `fputc`（GCC 为 `_write`）调用 `HAL_UART_Transmit` 发单字符。

MDK 勾选 **MicroLIB** 避免半主机模式卡死。

**易错：**阻塞式 printf 不能放中断里；RTOS 多任务下需加互斥。

### 中断处理流程与硬件压栈 

触发 → NVIC 仲裁 → **硬件自动压栈**（xPSR / PC / LR / R0\~R3 / R12）→ 从向量表取 ISR 入口 → 执行 ISR → 硬件出栈返回。

压栈 / 出栈由硬件完成；ISR 要短小、先清标志。

**易错：**ISR 里做阻塞延时 / 长任务会拖垮实时性。

### NVIC 优先级分组与嵌套 

抢占优先级（可打断）+ 子优先级（同抢占排队），数值小优先级高；AIRCR.PRIGROUP 分组（F1 支持 0\~4，F4 支持 0\~7）。

仲裁顺序：**抢占 → 子优先级 → 向量编号**。

**易错：**抢占优先级设置不当会造成高优中断无法打断低优（嵌套失效）。

### EXTI 线共享 

每条 EXTI 线对应一组引脚（PA0\~PG0 共用 EXTI0），**同一时刻只能使用其中一个**。

F1 由 AFIO 选线（必须开 AFIO 时钟），F4 由 SYSCFG 管理。

**易错：**同一条线的两个引脚同时配置中断会冲突失效。

### DMA 三要素与地址自增 

三要素：源地址、目标地址、传输数量 / 数据宽度 / 方向。

地址自增：内存侧自增、外设寄存器地址固定；循环模式自动回卷。

**易错：**源 / 目标宽度不匹配丢数据；正常模式传完需重配计数才能再次启动。

### ADC 采样/量化/编码 

采样（时间离散）→ 量化（幅度分级，量化误差 ±0.5 LSB）→ 编码（二进制输出）。

数字值 $D = \frac{V_{in&#125;&#125;{量程} \times 2^n$。

**易错：**采样时间不足精度下降；输入超过量程会饱和削顶。

### 分辨率与精度 

分辨率：最小可分辨电压 $LSB = \frac{量程}{2^n}$（12 位 / 3.3V ≈ 0.8mV）；

精度：实际值与真实值的偏差，受参考电压精度、噪声、INL / DNL 影响。

**易错：分辨率高 ≠ 精度高。**

### 扫描模式与 DMA 

扫描：规则组多通道依次转换；连续：转换完自动重新开始；

标准组合：**多通道 + 连续 + DMA**，结果按通道配置顺序排列。

**易错：**DMA 缓冲区顺序必须与通道配置顺序一致。

### I2C 开漏线与原理 

开漏 + 外部上拉实现**线与**：多主机仲裁不短路、双向读写、支持电平转换。

上拉阻值折中：标准 100k 常用 4.7k\~10kΩ，快速 400k 常用 1k\~2.2kΩ。

**易错：**I2C 引脚配成推挽输出会导致总线打架烧毁。

### I2C 时序与应答 

START（SCL 高时 SDA↓）→ 7 位地址 + R/W → ACK → 数据字节 + ACK → STOP（SCL 高时 SDA↑）。

主机读取**最后 1 字节发 NACK**；多字节读时前 N-1 字节发 ACK。

**易错：**主收最后字节不发 NACK，从机会一直发数据停不下来。

### SPI 四种模式（CPOL/CPHA） 

CPOL：空闲电平（0 低 / 1 高）；CPHA：采样边沿（0 第一边沿 / 1 第二边沿）。

组合出 Mode 0\~3，**主从必须配置一致**；多数器件用 Mode 0 或 Mode 3。

**易错：**模式不一致会读回全 0xFF 或数据错位。

### SPI 哑字节 

SPI 全双工：**读必须同时写**——发读命令后需再发哑字节（0xFF / 0x00）提供时钟，才能把数据移出。

**易错：**只发不读 / 只读不发都会导致时钟不足、数据取不回。

### SPI/I2C/UART 对比 

引脚：SPI 4 / I2C 2 / UART 2；同步：SPI、I2C 同步，UART 异步。

全双工：SPI、UART；半双工：I2C；寻址：SPI 靠片选 / I2C 地址 + ACK / UART 点对点无寻址。

选型：**要快用 SPI，要省线多设备用 I2C，要异步点对点用 UART**。

### 定时器分类与时基单元

基本（TIM6/7）仅时基；通用（TIM2\~5）加捕获 / 比较 / PWM / 编码器；高级（TIM1/8）加互补输出 / 死区 / 刹车。

时基三件套：PSC 预分频 + CNT 计数 + ARR 自动重装；溢出时间 $T = \frac{(PSC+1)(ARR+1)}{f_{tim&#125;&#125;$。

**易错：**溢出时间计算忘了 +1。

###  PWM 频率/占空比/分辨率 

频率 $F = \frac{f_{tim&#125;&#125;{(PSC+1)(ARR+1)}$；占空比 $Duty = \frac{CCR}{ARR+1}$；分辨率 = 1/(ARR+1)。

改占空比只改 CCR；改频率需重算 PSC / ARR。

**易错：**CCR 不能大于 ARR，否则输出恒高 / 恒低。

### 输入捕获测脉宽 

指定边沿把 CNT 锁存到 CCRx；两次捕获差值 × 计数周期 = 时间。

测频率：两个上升沿之差；测高电平脉宽：上升沿 + 下降沿之差。

**易错：**捕获间隔跨越溢出需记录溢出次数修正（差值 + 溢出次数 × ARR）。

### FSMC 地址映射与时序 

Bank1（NE1\~4，各 64MB）：NOR / SRAM / PSRAM；Bank2 / 3：NAND；Bank4：PC 卡。

LCD 8080：地址线 A0 接 RS 区分命令 / 数据，NE 片选；时序按手册换算 HCLK 周期（ADDSET 地址建立、DATAST 数据建立）。

**易错：**时序太短读花屏 / 写不进，太长刷屏慢。

### DAC 查表输出波形 

输出 $V_{out} = \frac{D}{2^n} \times V_{REF}$；写 DHR 数据寄存器即输出电压。

任意波形：波形表 + 定时器触发 + **DMA 循环搬运** + 低通滤波；输出频率 = 触发频率 / 采样点数。

**易错：**波形表点数太少会失真（阶梯感强）。

### IWDG 时钟源与喂狗原则 

时钟为 **LSI \~40kHz**，独立于主时钟，主时钟故障仍计数；超时 $T = \frac{4 \times 2^{PR} \times RLR}{f_{LSI&#125;&#125;$。

启动（写 0xCCCC）后不可关闭；喂狗写 `IWDG_KR` = 0xAAAA。

喂狗原则：关键任务完成后喂，周期取超时的 1/2\~1/4；**不在中断里喂**；调试用 DBGMCU 冻结。

### IWDG 与 WWDG 区别

时钟：IWDG = LSI 独立；WWDG = PCLK1 依赖主时钟。

窗口：IWDG 溢出前任意时刻喂；WWDG 必须窗口内喂（喂早 / 喂晚都复位）。

中断：WWDG 有 EWI 提前唤醒中断，IWDG 无。

一句话：**IWDG 管“死没死”，WWDG 管“活得好不好”**。
