# STM32 GPIO控制器及其应用

[飞书原文](https://hcn4ticlccda.feishu.cn/docx/PwHydecdVo4AsWx3w7fcwqxInXd)

## 一、为什么用第一性原理学GPIO

大多数教程的顺序是："GPIO有8种模式，分别是……配置寄存器MODER……然后写代码点亮LED。"这种方式能让你快速上手，但换一个芯片、换一个场景就懵了。

第一性原理的思路是：从物理本质出发，问"一个引脚为什么需要这些功能？"，然后一步步推导出寄存器设计和工作模式。

**核心问题链：**

1. 引脚本质上是什么？→ 一根连接芯片内外的金属线
2. 这根线要能做什么？→ 输出电平、读取电平
3. 输出电平有什么讲究？→ 驱动能力、电平标准、抗干扰
4. 读取电平有什么讲究？→ 阈值、噪声、抖动
5. 芯片内部怎么管理这些？→ 控制器、寄存器、时钟

## 二、物理层：引脚的本质结构

### 2.1 从CMOS反相器说起

一个数字引脚的最底层是CMOS电路。输出引脚的核心结构是一对互补MOS管：

- **PMOS（上管）**：源极接VDD，导通时把引脚拉到高电平
- **NMOS（下管）**：源极接VSS，导通时把引脚拉到低电平

这就是**推挽输出（Push-Pull）**的物理基础。两个管子交替导通，主动驱动引脚到高或低。


::: tip

**关键推论：**推挽输出能主动输出高和低，驱动能力强；但如果两个外部推挽输出引脚直接相连，一个输出高一个输出低，就会形成VDD到VSS的短路——所以推挽输出不能"线与"。

:::


### 2.2 开漏输出：只保留下管

如果把上管PMOS去掉，只留下NMOS下拉管，就得到了**开漏输出（Open-Drain）**：

- NMOS导通 → 引脚被拉到低电平
- NMOS截止 → 引脚悬空（高阻态），需要外部上拉电阻才能到高电平


::: tip

**关键推论：**开漏输出只能主动拉低，高电平靠外部上拉；多个开漏引脚可以接在一起（线与）——任何一个拉低，总线就低；全部释放，总线才高。I2C总线就是典型的开漏+上拉电阻应用。

:::


### 2.3 高阻态：三态输出

在推挽结构基础上加一个"使能"控制，可以让上下管同时截止，此时引脚既不驱动高也不驱动低，呈现**高阻态（Hi-Z）**。这就是三态缓冲器的基础，也是双向引脚和总线共享的物理前提。

## 三、电气层：输入输出的电气特性

### 3.1 输入缓冲：施密特触发器

引脚输入信号不能直接接数字逻辑，因为外部信号可能有噪声、缓慢变化，而普通反相器的翻转阈值不固定，可能在中间区域振荡。

解决方案：**施密特触发器（Schmitt Trigger）**，它有两个不同的阈值：

- **正向阈值 V_T+**：信号上升时超过此值才判为高
- **负向阈值 V_T-**：信号下降时低于此值才判为低

迟滞特性（V_T+ > V_T-）确保了缓慢变化或带噪声的信号也能稳定识别。


::: tip

**推论：**STM32的GPIO输入路径上都有施密特触发器，这就是为什么模拟输入模式要"关掉"输入缓冲——因为模拟信号不需要被数字化，否则数字电路的开关噪声会干扰模拟信号。

:::


### 3.2 上下拉电阻

引脚悬空时电平不确定，可能受干扰随机翻转。STM32在每个引脚上集成了可配置的上拉/下拉电阻：

- **上拉（Pull-up）**：通过电阻接VDD，悬空时默认高电平
- **下拉（Pull-down）**：通过电阻接VSS，悬空时默认低电平
- **浮空（Floating）**：不接，电平由外部电路决定

**典型应用：**按键输入。按键一端接引脚，另一端接GND。配置上拉电阻后，未按下时引脚为高，按下时为低——不需要外部电阻。

### 3.3 驱动能力与速度

输出驱动能力不是无限的。STM32的GPIO可以配置输出速度（Low/Medium/High/Very High），本质上是控制输出MOS管的导通电阻和压摆率（slew rate）：

- **低速**：驱动能力弱，但电磁干扰（EMI）小，适合低速信号
- **高速**：驱动能力强，边沿陡峭，适合高速信号（如SPI、USB），但EMI大


::: tip

**推论：**不是速度越高越好。低速信号用高速模式只会增加功耗和噪声，甚至可能因为信号过冲导致EMI问题。

:::


## 四、架构层：GPIO控制器的寄存器设计

从第一性原理推导：要管理一组引脚，需要哪些寄存器？每一个寄存器的存在都对应一个物理或功能需求。

### 4.1 模式寄存器（MODER）

每个引脚需要选择工作方向和类型。STM32用2位表示4种模式：

| MODER值 | 模式 | 物理含义 |
|-|-|-|
| 00 | 输入 | 使能输入缓冲，关闭输出驱动 |
| 01 | 通用输出 | 使能输出驱动，可读取输入缓冲（回读） |
| 10 | 复用功能 | 引脚交给片上外设（USART/SPI/TIM等）控制 |
| 11 | 模拟 | 关闭输入缓冲和输出驱动，引脚直接连模拟外设（ADC/DAC） |

### 4.2 输出类型寄存器（OTYPER）

输出模式下，选择推挽还是开漏。1位即可：0=推挽，1=开漏。这直接对应物理层2.1和2.2的两种输出结构。

### 4.3 输出速度寄存器（OSPEEDR）

2位配置4档速度，对应3.3节的驱动能力与压摆率控制。

### 4.4 上下拉寄存器（PUPDR）

2位配置：00=浮空，01=上拉，10=下拉，11=保留。对应3.2节的内部上下拉电阻。

### 4.5 输出数据寄存器（ODR）

推挽输出时，写1对应引脚输出高，写0输出低。可读可写。

### 4.6 输入数据寄存器（IDR）

只读，读取引脚当前电平。注意：即使配置为输出模式，IDR仍然反映引脚的实际电平（回读功能）。

### 4.7 置位/复位寄存器（BSRR）——为什么有了ODR还需要它？

ODR是读-改-写操作：要改变某一位，需要先读ODR，修改对应位，再写回去。在中断和多任务环境下，这三步之间可能被打断，导致竞态条件。

BSRR是**原子操作**：

- 写1到低16位：对应引脚置1
- 写1到高16位：对应引脚清0
- 写0：无影响

一次写操作就能完成，不需要读-改-写，不会被中断打断。这是并发安全的硬件设计，也是HAL库底层操作引脚的首选寄存器。

### 4.8 复用功能寄存器（AFRL/AFRH）

每个引脚可以映射到不同的片上外设。用4位（AF0\~AF15）选择具体复用功能。为什么是4位？因为STM32设计了最多16种复用映射。引脚0\~7用AFRL，引脚8\~15用AFRH。

## 五、功能层：8种工作模式的完整推导

将上述要素组合，得到STM32 GPIO的8种工作模式。每一种都能从物理层找到依据：

| 模式 | 输出驱动 | 输入缓冲 | 上下拉 | 典型应用 |
|-|-|-|-|-|
| 浮空输入 | 关闭 | 使能 | 无 | 外部信号已有确定电平 |
| 上拉输入 | 关闭 | 使能 | 上拉 | 按键、开关 |
| 下拉输入 | 关闭 | 使能 | 下拉 | 按键、开关 |
| 模拟模式 | 关闭 | 关闭 | 无 | ADC采集、DAC输出 |
| 推挽输出 | 推挽使能 | 使能(回读) | 可配 | LED、控制信号 |
| 开漏输出 | 开漏使能 | 使能(回读) | 可配 | I2C、电平转换 |
| 推挽复用 | 推挽(外设控) | 使能 | 可配 | USART_TX、SPI_SCK |
| 开漏复用 | 开漏(外设控) | 使能 | 可配 | I2C_SCL/SDA |


::: tip

**记忆口诀：**输入看"拉"（浮空/上拉/下拉），输出看"漏"（推挽/开漏），复用看"外设"（推挽复用/开漏复用），再加一个模拟——4+2+2=8种。

:::


## 六、应用层：典型场景的原理分析

### 6.1 LED闪烁

- **配置：**推挽输出
- **原理：**输出高电平时电流经LED到GND（或反之），LED亮；输出低时灭
- **注意：**LED需要串联限流电阻，GPIO单个引脚最大电流约25mA，整组端口有总电流限制

### 6.2 按键检测

- **配置：**上拉输入（按键接GND）或下拉输入（按键接VDD）
- **原理：**利用内部上下拉电阻确定悬空电平
- **抖动问题：**机械按键按下/释放时会有ms级抖动，需要硬件消抖（RC电路）或软件消抖（延时后重读）

### 6.3 I2C总线

- **配置：**开漏复用输出 + 外部上拉电阻
- **原理：**SCL和SDA都是开漏，多个设备可以共享总线。任何设备拉低SDA，总线就是低；全部释放，上拉电阻把总线拉高。这就是I2C的"线与"仲裁机制。

### 6.4 SPI通信

- **配置：**推挽复用输出（SCK/MOSI）、输入（MISO）
- **原理：**SPI是全双工、推挽驱动，时钟线由主机主动驱动，不需要上拉。速度可以很高（几十MHz），所以要配置高速输出模式。

### 6.5 ADC采集

- **配置：**模拟输入模式
- **原理：**关闭施密特触发器和上下拉，避免数字电路对模拟信号的干扰。引脚直接连接ADC输入通道，此时读取IDR无意义。

## 七、从原理到代码：寄存器级与HAL库对照

以PA0推挽输出为例，理解HAL库参数背后的寄存器操作。

### 7.1 寄存器级

```c
// 1. 使能GPIOA时钟（AHB1总线）
RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

// 2. PA0设为通用输出（MODER[1:0] = 01）
GPIOA->MODER &= ~GPIO_MODER_MODE0;   // 清0
GPIOA->MODER |= GPIO_MODER_MODE0_0;  // 置位0位

// 3. 推挽输出（OTYPER[0] = 0，默认就是）
GPIOA->OTYPER &= ~GPIO_OTYPER_OT0;

// 4. 低速输出
GPIOA->OSPEEDR &= ~GPIO_OSPEEDR_OSPEED0;

// 5. 无上下拉
GPIOA->PUPDR &= ~GPIO_PUPDR_PUPD0;

// 6. 输出高电平（BSRR原子操作）
GPIOA->BSRR = GPIO_BSRR_BS0;  // 置位
// 输出低电平
GPIOA->BSRR = GPIO_BSRR_BR0;  // 复位
```

### 7.2 HAL库

```c
GPIO_InitTypeDef GPIO_InitStruct = {0};

// 使能时钟
__HAL_RCC_GPIOA_CLK_ENABLE();

// 配置结构体
GPIO_InitStruct.Pin = GPIO_PIN_0;
GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;   // 推挽输出
GPIO_InitStruct.Pull = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;

HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

// 操作
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0, GPIO_PIN_SET);   // 高
HAL_GPIO_WritePin(GPIOA, GPIO_PIN_0, GPIO_PIN_RESET); // 低
HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_0);                  // 翻转
```


::: tip

HAL库的 `GPIO_MODE_OUTPUT_PP` 背后就是设置 MODER=01 + OTYPER=0，和寄存器级完全对应。理解了原理，HAL库的参数就不再是魔法值——每一个枚举值都对应一组寄存器位的组合。

:::


## 八、常见陷阱与调试思路

1. **忘记使能时钟**：GPIO外设默认时钟关闭，配置寄存器无效。这是最常见的"为什么我的引脚没反应"。原理：为了降低功耗，未使用的外设时钟默认关闭。
2. **调试器引脚被复用**：PA13/PA14是SWD调试引脚，PA15/PB3/PB4是JTAG引脚。复用为GPIO前需要关闭调试功能，否则可能丢失调试连接。
3. **5V容忍问题**：并非所有STM32引脚都容忍5V输入，只有FT（Five-volt Tolerant）标记的引脚才可以。直接接5V可能损坏芯片。
4. **电流超限**：单个引脚25mA，整个VDD引脚的总电流有上限（如120mA）。驱动多个LED或继电器时需要外部驱动电路（三极管/MOS管/驱动器）。
5. **开漏忘记上拉**：开漏输出不接上拉电阻，高电平是悬空的，读回来可能是随机值。I2C总线必须有上拉电阻（通常4.7kΩ）。

## 九、第一性原理总结

学习GPIO的核心不是记住8种模式和10个寄存器，而是理解这条因果链：


::: tip

**物理结构（CMOS管）→ 电气特性（推挽/开漏/施密特/上下拉）→ 功能需求（输入/输出/复用/模拟）→ 寄存器设计（MODER/OTYPER/OSPEEDR/PUPDR/ODR/IDR/BSRR/AFR）→ 代码实现（寄存器/HAL）**

:::


任何一个寄存器位、任何一种工作模式，都能在物理层找到它存在的理由。当你能从"为什么需要这个"推导出"它是怎么设计的"，就真正掌握了GPIO，而不是记住了GPIO。

换一款芯片（如GD32、ESP32、RP2040），物理层是一样的，只是寄存器映射和命名不同——用第一性原理的眼光看，它们都是同一套因果链的不同实现。

# GPIO控制器原理

## 第一章 GPIO控制器介绍

### 1.1 什么是GPIO

GPIO（General Purpose Input/Output）代表通用输入/输出，是一种用于与外部设备通信的通用接口。在嵌入式系统中，GPIO通常是一组可以通过软件配置为输入或输出的引脚，用于与外部电子元件（如传感器、执行器、LED、按键等）进行数字通信。

GPIO的核心价值在于**通用性**：同一个引脚可以根据软件配置扮演不同角色——读按键、亮LED、输出PWM、模拟I2C时序等，这使得MCU能用有限的引脚连接丰富的外设。

### 1.2 STM32F407 GPIO控制器引脚分布

以STM32F407IGH6为例：

- 芯片共 **176个引脚**，其中GPIO引脚共 **140个**
- GPIO引脚分为 **9组**（GPIOA\~GPIOI）
- GPIOA\~GPIOH 共8组，每组16个引脚（pin0\~pin15）
- GPIOI组12个引脚（pin0\~pin11）


::: tip

**记忆要点：**每组GPIO最多16个引脚（对应16位寄存器），这就是为什么ODR、IDR、BSRR等寄存器都是32位但低16位有效——每一位对应一个引脚。

:::


### 1.3 GPIO控制器框图分析

从信号流向理解GPIO控制器的内部结构：

1. **引脚（Pad）**：芯片与外部世界的物理连接点
2. **输入路径**：引脚 → 上下拉电阻 → 施密特触发器 → 输入数据寄存器（IDR）
3. **输出路径**：输出数据寄存器（ODR）/ 位设置/复位寄存器（BSRR） → 输出控制 → PMOS/NMOS驱动管 → 引脚
4. **复用路径**：片上外设（USART/SPI/I2C/TIM等）→ 复用功能选择 → 输出驱动 / 输入缓冲
5. **模拟路径**：引脚 → 直接连接ADC/DAC（绕过施密特触发器和数字逻辑）

理解框图的关键：**每条路径对应一种工作模式，模式选择本质上是开关切换哪条路径连通**。

### 1.4 GPIO的模式总览

| 大类 | 具体模式 | 典型应用 |
|-|-|-|
| 输出模式 | 推挽输出、开漏输出 | LED控制、I2C总线 |
| 输入模式 | 上拉输入、下拉输入、浮空输入 | 按键检测、外部信号读取 |
| 模拟模式 | 模拟输入/输出 | ADC采集、DAC输出 |
| 复用模式 | 推挽复用、开漏复用 | USART、I2C、SPI、TIM等外设 |

## 第二章 GPIO输入模式

### 2.1 输入模式原理

GPIO输入模式常用来检测芯片外部IO引脚的状态。外部电压经过**TTL施密特触发器**整形之后，输出逻辑电平（0或1），最终写入输入数据寄存器（IDR），CPU通过读取IDR获知引脚状态。

信号路径：**外部引脚 → 上下拉电阻（可选） → 施密特触发器 → IDR寄存器 → CPU读取**

### 2.2 TTL施密特触发器

施密特触发器是一种**整形电路**，可以将输入信号整形为标准方波信号。它的核心特性是**迟滞（Hysteresis）**——拥有两个不同的阈值电压：

- 当输入电压**高于正向阈值电压**时，输出为高电平
- 当输入电压**低于负向阈值电压**时，输出为低电平

IO口信号经过触发器后，可以将连续变化的模拟电平分为高电平与低电平，也就是1和0的数字信号。**迟滞特性确保了缓慢变化或带噪声的信号不会在阈值附近反复振荡**。


::: tip

**为什么需要施密特触发器？**如果用普通反相器（单阈值），当输入信号在阈值附近缓慢变化或叠加噪声时，输出会在0和1之间反复跳变。施密特触发器的双阈值设计解决了这个问题——信号必须上升超过高阈值才判1，必须下降低于低阈值才判0，中间区域保持原状态。

:::


### 2.3 输入电压范围（STM32F407具体参数）

以下数据摘自STM32F407xx数据手册（datasheet）：

| 参数 | 数值 | 条件 |
|-|-|-|
| TTL施密特触发器上触发点（V_T+） | 2.31V（0.7 × VDD） | 1.7V ≤ VDD ≤ 3.6V |
| TTL施密特触发器下触发点（V_T-） | 0.99V（0.3 × VDD） | 1.7V ≤ VDD ≤ 3.6V |
| 5V容忍输入电压范围 | -0.3V \~ 5.5V | 2V ≤ VDD ≤ 3.6V，仅FT引脚 |


::: tip

**注意：**以VDD=3.3V为例，正向阈值约2.31V，负向阈值约0.99V。也就是说，输入电压在0.99V\~2.31V之间时，引脚的逻辑状态是"不确定"的——取决于之前的状态（迟滞保持）。设计电路时应确保高电平高于2.31V、低电平低于0.99V。

:::


### 2.4 浮空输入

浮空输入模式是一种**高阻态模式**，不设置上拉或下拉电阻，引脚不连接到芯片内部的任何确定电平，处于高阻抗状态。

- **特点：**引脚电平完全由外部电路决定
- **适用场景：**外部信号已有确定电平（如标准通信接口的接收端、外部已有上拉/下拉的电路）
- **风险：**如果引脚悬空（什么都不接），电平会受电磁干扰随机浮动，读取值不稳定

### 2.5 上拉输入

上拉输入的特点是具有**内部上拉电阻**，引脚的默认电平为高电平。当外部信号将引脚拉低时，读取到低电平。

- **默认状态：**高电平（内部电阻将引脚拉向VDD）
- **典型应用：**检测外部低电平信号，如按键（按键一端接引脚，另一端接GND）
- **优势：**无需外部上拉电阻，节省BOM成本和PCB空间

### 2.6 下拉输入

下拉输入的特点是具有**内部下拉电阻**，引脚的默认电平为低电平。当外部信号将引脚拉高时，读取到高电平。

- **默认状态：**低电平（内部电阻将引脚拉向VSS）
- **典型应用：**检测外部高电平信号，如按键（按键一端接引脚，另一端接VDD）


::: tip

**输入模式选择口诀：**外部有确定电平 → 浮空输入；按键接GND → 上拉输入；按键接VDD → 下拉输入。核心原则是让引脚在"无信号"时处于确定电平，避免悬空浮动。

:::


## 第三章 三极管与MOS管

GPIO输出驱动的核心是MOS管，但要真正理解MOS管，需要先从更基础的半导体器件讲起。

### 3.1 二极管

二极管是一种具有两个电极（阴极、阳极）的半导体器件，由单个PN结构成，具有**单向导电性**。

- **正向导通：**给阳极和阴极加上正向电压（阳极电位高于阴极）时，二极管导通
- **反向截止：**给阳极和阴极加上反向电压时，二极管截止，几乎无电流通过

| 参数 | 描述 | 典型值 |
|-|-|-|
| 导通电压（V_T） | 二极管开始导通的正向电压 | 硅管：0.5\~0.7V；锗管：0.1\~0.3V |
| 正向导通压降（V_F） | 二极管导通后的正向电压降 | 硅管：0.6\~0.8V；锗管：0.2\~0.3V |

**在GPIO中的体现：**引脚的ESD保护电路就是由二极管构成的——引脚到VDD和VSS各有一个**钳位二极管**，当引脚电压超出范围时导通，将电压钳位在安全范围内。

### 3.2 三极管（BJT）

三极管全称"晶体三极管"，也称作"晶体管"（BJT, Bipolar Junction Transistor），是一种具有**电流放大功能**的半导体器件。

三个电极：

- **基极（Base, B）：**用于激活/控制晶体管
- **集电极（Collector, C）：**三极管的正极（电流流入端）
- **发射极（Emitter, E）：**三极管的负极（电流流出端）

#### 三极管的三种工作状态

| 状态 | 条件 | 特点 | 类比 |
|-|-|-|-|
| 截止状态 | 发射结电压小于PN结导通电压，基极电流为零 | 集电极电流和发射极电流都为零，C-E之间相当于开关断开 | 开关断开 |
| 放大状态 | 发射结正向偏置，集电结反向偏置，基极电流处于恰当范围 | 基极电流对集电极电流起控制作用（I_C = β × I_B），具有电流放大作用 | 可调电阻 |
| 饱和导通 | 基极电流增大到一定程度，集电极电流不再随基极电流增大 | C-E之间电压很小（约0.2\~0.3V），相当于开关导通 | 开关闭合 |


::: tip

**数字电路中的三极管：**在数字电路和GPIO驱动中，三极管只工作在**截止**和**饱和导通**两种状态（即开关状态），不使用放大状态。这就是为什么三极管可以作为电子开关使用。

:::


#### 三极管类型：NPN与PNP

- **NPN型三极管：**由P型半导体夹在两个N型半导体之间构成。基极接**正电压（高电平）**触发导通
- **PNP型三极管：**由N型半导体夹在两个P型半导体之间构成。基极接**负电压（低电平）**触发导通

### 3.3 MOS管（MOSFET）

MOS管（Metal-Oxide-Semiconductor Field-Effect Transistor，金属氧化物半导体场效应管）是一种**电压控制型**器件，广泛用于**功率放大、开关控制、电机驱动、DC-DC转换、射频信号处理**等领域。

**与三极管的核心区别：**MOS管是电压控制型器件，工作时几乎不消耗控制电流（栅极绝缘），因此更适合低功耗和高速开关电路。GPIO的输出驱动级就是由MOS管构成的。

三个电极：

- **栅极（Gate, G）：**控制端，通过电压控制沟道导通
- **漏极（Drain, D）：**电流流入端
- **源极（Source, S）：**电流流出端

#### MOS管类型：NMOS与PMOS

- **N沟道MOS管（NMOS）：**栅极G相对源极S加**正电压（高电平）**时导通。导通时电流从D流向S，将节点拉向低电平（接地）
- **P沟道MOS管（PMOS）：**栅极G相对源极S加**负电压（低电平）**时导通。导通时电流从S流向D，将节点拉向高电平（接VDD）


::: tip

**GPIO输出驱动的本质：**推挽输出 = PMOS（上拉到VDD）+ NMOS（下拉到VSS）交替导通；开漏输出 = 只有NMOS工作，PMOS始终关闭。这就是第四章输出模式的物理基础。

:::


### 3.4 三极管与MOS管对比

| 特性 | 三极管（BJT） | MOS管（MOSFET） |
|-|-|-|
| 控制方式 | 电流控制型（I_B控制I_C） | 电压控制型（V_GS控制I_D） |
| 控制极功耗 | 较高（需要持续基极电流） | 极低（栅极绝缘，几乎无电流） |
| 开关速度 | 较慢（少数载流子存储效应） | 更快（多数载流子器件） |
| 导通压降 | 饱和压降约0.2\~0.3V | R_DS(on) × I_D，可做得很低 |
| 典型应用 | 低频、信号放大、模拟电路、低功率驱动 | 高频、高功率应用、开关电源、电机驱动、MCU引脚驱动 |

## 第四章 GPIO输出模式

### 4.1 输出模式原理

GPIO控制器输出模式，主要是由**P-MOS管和N-MOS管**组成的一个结构单元（即第三章讲的CMOS推挽结构）：

- 当P-MOS管和N-MOS管**同时工作**（交替导通），可组成**推挽输出模式**
- 当**只有N-MOS管工作**（P-MOS始终关闭），可组成**开漏输出模式**

输出数据来源：输出控制逻辑可以从ODR寄存器或BSRR寄存器获取输出电平数据，然后控制PMOS和NMOS的导通/截止。

### 4.2 推挽输出

推挽输出模式，是根据P-MOS和N-MOS管的工作方式命名的——两个管子像"推"和"拉"一样交替工作。

- 当输入控制信号为**低电平**时：P-MOS管导通，N-MOS管截止，电流从VDD经PMOS流向引脚，对外输出**高电平**
- 当输入控制信号为**高电平**时：P-MOS管截止，N-MOS管导通，电流从引脚经NMOS流向VSS，对外输出**低电平**


::: tip

**推挽输出特点：**能主动输出高电平和低电平，驱动能力强（可输出/吸入较大电流），边沿陡峭速度快。适用于LED、控制信号、SPI时钟等需要主动驱动的场景。

:::



::: tip

**推挽输出的限制：**两个推挽输出引脚不能直接短接在一起——如果一个输出高、一个输出低，会形成VDD→PMOS→导线→NMOS→VSS的直流通路，大电流可能烧毁芯片。因此推挽输出不支持"线与"。

:::


### 4.3 开漏输出

开漏输出（Open-Drain）模式时，不论输入是高电平还是低电平，**P-MOS管总处于关闭状态**，只有N-MOS管参与工作：

- 当输入**高电平**时：N-MOS管导通，引脚被拉到VSS，输出即为**低电平**
- 当输入**低电平**时：N-MOS管截止，引脚既不接VDD也不接VSS，状态既不是高电平也不是低电平，称之为**高阻态**

如果想让引脚输出高电平，那么引脚必须**外接一个上拉电阻**，由上拉电阻将引脚拉向高电平。

### 4.4 开漏输出的特点与应用

#### 线与逻辑（Wired-AND）

多个开漏输出引脚可以直接连接在一起，共享一条总线，形成"线与"逻辑：

- 只有当**所有连接设备都释放总线**（输出高阻态），上拉电阻才会将总线上拉为高电平
- 如果**任何一个设备输出低电平**，总线将被拉低

这种设计可以方便实现总线仲裁和同步——多个设备可以共享同一条线，不会发生推挽输出那样的短路冲突。

#### 典型应用场景

1. **I2C总线：**SCL和SDA都是开漏输出+外部上拉电阻，支持多主设备仲裁
2. **电平转换：**通过选择上拉电阻的电压，可以实现不同电压域之间的通信（如3.3V MCU与5V外设通信）
3. **LED驱动（共阳接法）：**开漏输出拉低时LED亮，释放时LED灭

### 4.5 ODR与BSRR寄存器对比

**ODR（Output Data Register，输出数据寄存器）** 

**BSRR（Bit Set/Reset Register，位设置 / 复位寄存器）**

设置IO口引脚状态有两种方式，操作步骤和安全性有本质区别：

| 对比项 | ODR寄存器 | BSRR寄存器 |
|-|-|-|
| 操作步骤 | ①读取ODR寄存器数据   <br/>②位操作修改目标引脚   <br/>③写回ODR寄存器 | ①设置目标引脚状态（置位对应位[0:15]，复位对应位[16:31]）   <br/>②直接写入BSRR寄存器 |
| 操作类型 | 读-改-写（三步） | 原子写（一步） |
| 并发安全 | 不安全，中断可能在三步之间打断，导致竞态 | 安全，单次写操作不可被打断 |
| 写0的含义 | 写0对应引脚输出低电平 | 写0表示不改变该引脚状态（无影响） |
| 可读性 | 可读可写，读取可获知当前输出状态 | 只写，读取无意义（始终返回0） |


::: tip

**实践建议：**修改单个或多个引脚电平时优先使用BSRR（原子操作）；需要读取当前输出状态时读取ODR。HAL库的 `HAL_GPIO_WritePin()` 和 `HAL_GPIO_TogglePin()` 底层就是使用BSRR/BRR实现的。

:::


## 第五章 模拟模式

### 5.1 模拟模式原理

GPIO模拟输入的原理相对简单：IO引脚上的模拟电压在GPIO部分**不做任何处理**，直接输入到芯片内部的ADC（模数转换器）控制器部分进行采样处理。

在模拟模式下：

- **施密特触发器被关闭**：避免数字电路的开关噪声耦合到模拟信号上，同时减少功耗
- **输出驱动被关闭**：PMOS和NMOS都截止，引脚不驱动任何电平
- **上下拉电阻被禁用**：避免上下拉电阻影响模拟信号的精度
- **IDR读取无意义**：因为施密特触发器已关闭，IDR中的值不确定


::: tip

**为什么模拟模式要关闭数字电路？**施密特触发器在信号经过阈值时会快速翻转，产生高频开关噪声，这些噪声会通过衬底耦合到ADC的模拟前端，降低采样精度。关闭数字电路后，引脚直接连接ADC输入通道，获得最纯净的模拟信号。

:::


### 5.2 模拟模式的应用

- **ADC采集：**读取外部模拟电压（如电位器、温度传感器、电池电压等），配置为模拟输入模式
- **DAC输出：**STM32的DAC输出引脚也需要配置为模拟模式，此时引脚由DAC外设直接驱动
- **比较器输入：**部分STM32型号的模拟比较器输入引脚也需配置为模拟模式

## 第六章 复用模式

### 6.1 复用模式原理

IO复用模式主要是为后续各种控制器驱动对应外设时提供的一个配置。将IO引脚设置为复用模式后，该管脚状态的控制**不再由GPIO控制器控制其高低状态**，而是由对应的外设控制器（如USART、I2C、SPI、TIM等）进行状态控制。

信号路径变化：

- **输出方向：**外设控制器 → **复用功能选择器（AFR寄存器）** → 输出驱动（推挽/开漏） → 引脚
- **输入方向：**引脚 → 施密特触发器 → 复用功能选择器 → 外设控制器

### 6.2 复用功能的选择

STM32的每个引脚可以映射到多种不同的外设功能，通过**复用功能寄存器（AFRL/AFRH）**的4位（AF0\~AF15）来选择具体映射哪一个外设。

- **AFRL（GPIOx_AFRL）：**控制引脚0\~7的复用功能，每个引脚4位
- **AFRH（GPIOx_AFRH）：**控制引脚8\~15的复用功能，每个引脚4位

例如STM32F407的PA2引脚：AF0=系统功能、AF1=TIM5_CH3、AF7=USART2_TX。通过设置AFRL的对应位，可以将PA2切换为不同外设的引脚。

### 6.3 复用模式的输出类型

复用模式下仍然可以选择**推挽或开漏**输出类型（由OTYPER寄存器控制）：

- **推挽复用：**外设通过推挽结构驱动引脚，适用于USART_TX、SPI_SCK、SPI_MOSI等需要主动驱动的信号
- **开漏复用：**外设通过开漏结构驱动引脚，适用于I2C_SCL、I2C_SDA等需要线与逻辑的信号


::: tip

**复用模式配置要点：**①设置MODER为复用模式（10）；②设置AFRL/AFRH选择具体外设；③根据外设需求设置OTYPER（推挽/开漏）；④设置OSPEEDR（速度）；⑤设置PUPDR（上下拉）。I2C必须开漏+外部上拉，USART/SPI通常推挽即可。

:::


### 6.4 常见外设的复用配置参考

| 外设 | 信号方向 | 推荐输出类型 | 上下拉 | 外部元件 |
|-|-|-|-|-|
| USART | TX输出 / RX输入 | 推挽 | RX可上拉 | 无 |
| I2C | SCL/SDA双向 | 开漏 | 无 | **必须外部上拉电阻** |
| SPI | SCK/MOSI输出 / MISO输入 | 推挽 | 无/CS上拉 | 无 |
| TIM PWM | CHx输出 | 推挽 | 无 | 无 |
| CAN | TX输出 / RX输入 | 推挽 | 无 | 需CAN收发器 |

# GPIO控制器HAL库常用接口

## 一、GPIO寄存器映射

STM32 的每组 GPIO（GPIOA\~GPIOI）都有独立的寄存器块，基址依次相差 0x400。以 GPIOA 基址 0x40020000 为例，各寄存器偏移如下：

| 寄存器 | 名称 | 偏移 |
|-|-|-|
| GPIOx_MODER | 端口模式寄存器 | 0x00 |
| GPIOx_OTYPER | 端口输出类型寄存器 | 0x04 |
| GPIOx_OSPEEDER | 端口输出速度寄存器 | 0x08 |
| GPIOx_PUPDIR | 端口上拉/下拉寄存器 | 0x0C |
| GPIOx_IDR | 端口输入数据寄存器 | 0x10 |
| GPIOx_ODR | 端口输出数据寄存器 | 0x14 |
| GPIOx_BSRR | 端口置位/复位寄存器 | 0x18 |
| GPIOx_AFRL | 复用功能低位寄存器 | 0x20 |
| GPIOx_AFRH | 复用功能高位寄存器 | 0x24 |


::: tip

**记忆要点：**前 4 个是配置寄存器（模式、输出类型、速度、上下拉），中间 3 个是数据寄存器（输入 IDR、输出 ODR、置位/复位 BSRR），最后 2 个是复用功能寄存器（AFRL 管引脚 0\~7，AFRH 管引脚 8\~15）。

:::


## 二、核心数据结构

## 2.1 GPIO_InitTypeDef — 引脚初始化配置结构体

使用 GPIO 前必须填充此结构体，再传给 `HAL_GPIO_Init()` 完成初始化。

```c
typedef struct {
    uint32_t Pin;       /* 要配置的GPIO引脚，如 GPIO_PIN_0 */
    uint32_t Mode;      /* 工作模式：输入/输出/复用/模拟 */
    uint32_t Pull;      /* 上拉/下拉：无/上拉/下拉 */
    uint32_t Speed;     /* 电平反转速度：低/中/高/极高 */
    uint32_t Alternate; /* 复用功能编号，仅复用模式下有效 */
} GPIO_InitTypeDef;
```

| 成员 | 常用取值 | 说明 |
|-|-|-|
| Pin | GPIO_PIN_0 \~ GPIO_PIN_15 | 可按位或组合，同时配置多个引脚 |
| Mode | GPIO_MODE_INPUT  <br/>GPIO_MODE_OUTPUT_PP  <br/>GPIO_MODE_AF_PP  <br/>GPIO_MODE_ANALOG | 输入 / 推挽输出 / 复用推挽 / 模拟 |
| Pull | GPIO_NOPULL  <br/>GPIO_PULLUP  <br/>GPIO_PULLDOWN | 无上拉下拉 / 上拉 / 下拉 |
| Speed | GPIO_SPEED_FREQ_LOW  <br/>GPIO_SPEED_FREQ_HIGH | 速度越高，边沿越陡，EMI 越大 |
| Alternate | GPIO_AF0_USART1 等 | 仅 Mode 为复用模式时需设置 |

## 2.2 GPIO_PinState — 引脚电平状态枚举

```c
typedef enum {
    GPIO_PIN_RESET = 0,  /* 低电平状态 */
    GPIO_PIN_SET          /* 高电平状态 */
} GPIO_PinState;
```

这是 `HAL_GPIO_ReadPin()` 的返回值类型，也是 `HAL_GPIO_WritePin()` 的第三个参数类型。

## 三、HAL库常用接口

## 3.1 HAL_GPIO_Init — 初始化GPIO

| **功能** | 根据配置结构体初始化 GPIO 引脚 |
|-|-|
| **原型** | `void HAL_GPIO_Init(GPIO_TypeDef *GPIOx, GPIO_InitTypeDef *GPIO_Init)` |
| **参数** | GPIOx：GPIO 组基址（GPIOA / GPIOB / ...）  <br/>GPIO_Init：指向初始化配置结构体的指针 |
| **返回值** | 无 |

```c
GPIO_InitTypeDef GPIO_InitStruct = {0};
GPIO_InitStruct.Pin   = GPIO_PIN_5;
GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;
GPIO_InitStruct.Pull  = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);
```

## 3.2 HAL_GPIO_ReadPin — 读取引脚电平

| **功能** | 读取指定 GPIO 引脚的当前电平状态 |
|-|-|
| **原型** | `GPIO_PinState HAL_GPIO_ReadPin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)` |
| **参数** | GPIOx：GPIO 组基址  <br/>GPIO_Pin：引脚编号（GPIO_PIN_0 \~ GPIO_PIN_15） |
| **返回值** | GPIO_PIN_SET（高电平）或 GPIO_PIN_RESET（低电平） |


::: tip

**注意：**此函数底层读取的是 IDR（输入数据寄存器），反映的是引脚**实际电平**，而非 ODR 中设置的输出值。当引脚被外部电路拉低时，即使 ODR 写 1，ReadPin 也可能返回 RESET。

:::


## 3.3 HAL_GPIO_WritePin — 设置引脚电平

| **功能** | 设置指定 GPIO 引脚的输出电平 |
|-|-|
| **原型** | `void HAL_GPIO_WritePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin, GPIO_PinState PinState)` |
| **参数** | GPIOx：GPIO 组基址  <br/>GPIO_Pin：引脚编号  <br/>PinState：GPIO_PIN_SET（高）或 GPIO_PIN_RESET（低） |
| **返回值** | 无 |


::: tip

**底层实现：**WritePin 并不是写 ODR，而是写 BSRR 寄存器——置位时写低 16 位，复位时写高 16 位。因此是原子操作，不会影响同组其他引脚。

:::


## 3.4 HAL_GPIO_TogglePin — 翻转引脚电平

| **功能** | 将指定 GPIO 引脚的输出电平取反（高变低、低变高） |
|-|-|
| **原型** | `void HAL_GPIO_TogglePin(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)` |
| **参数** | GPIOx：GPIO 组基址  <br/>GPIO_Pin：引脚编号 |
| **返回值** | 无 |

典型用途：LED 闪烁、方波输出、心跳指示等。

```c
while (1) {
    HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);
    HAL_Delay(500);  /* 延时500ms，即1秒一个周期 */
}
```

## 四、接口速查表

| 函数 | 底层寄存器 | 典型用途 |
|-|-|-|
| HAL_GPIO_Init | MODER / OTYPER / OSPEEDER / PUPDR / AFRL/AFRH | 引脚初始化配置 |
| HAL_GPIO_ReadPin | IDR | 读取按键、传感器输入 |
| HAL_GPIO_WritePin | BSRR | 控制 LED、继电器、使能信号 |
| HAL_GPIO_TogglePin | ODR → BSRR | LED 闪烁、方波、心跳灯 |

## 五、实践要点


::: tip

**使用流程三步走：**
1. 使能 GPIO 时钟（`__HAL_RCC_GPIOx_CLK_ENABLE()`）——不使能时钟，配置无效。
2. 填充 `GPIO_InitTypeDef`，调用 `HAL_GPIO_Init()` 完成配置。
3. 使用 ReadPin / WritePin / TogglePin 进行读写操作。

:::



::: tip

**常见坑：**
- 忘记使能 GPIO 时钟，导致引脚无反应。
- 输出模式下读 ReadPin 得到的是引脚实际电平，不一定等于设置值（外部负载可能拉低）。
- 开漏输出（OD）必须接上拉电阻才能输出高电平。
- 复用功能模式下必须同时设置 Mode 为 AF 模式和 Alternate 编号。

:::


# LED灯控制应用

## 一、LED工作原理

LED（发光二极管）是一种具有单向导电性的半导体器件，只有当阳极电压高于阴极电压并达到导通压降时，才会发光。

| 条件 | 结果 |
|-|-|
| 阳极电压 > 阴极电压 + 导通压降 | LED 点亮（正向导通） |
| 阳极电压 ≤ 阴极电压 | LED 熄灭（反向截止或零偏） |


::: tip

**核心要点：**LED 发光的本质是在两端形成足够的正向压降。因此 LED 的亮灭取决于**两端的电压差**，而不是某一端绝对的高/低电平。

:::


## 二、硬件连接方式

STM32 控制 LED 有两种常见接法，决定了 GPIO 输出高/低电平时 LED 的亮灭状态。

### 2.1 共阳极接法（LED 阳极接 VCC）

LED 阳极通过限流电阻接 VCC（3.3V），阴极接 GPIO 引脚。

| GPIO 输出 | LED 两端电压 | LED 状态 |
|-|-|-|
| 低电平（0V） | 阳极 3.3V，阴极 0V → 正向导通 | **点亮** |
| 高电平（3.3V） | 阳极 3.3V，阴极 3.3V → 无压差 | **熄灭** |


::: tip

**低电平点亮：**共阳极接法下，GPIO 输出低电平 LED 才亮。这是开发板上最常见的接法（如 STM32F4 探索者板的 LED0）。

:::


### 2.2 共阴极接法（LED 阴极接 GND）

LED 阴极接 GND，阳极通过限流电阻接 GPIO 引脚。

| GPIO 输出 | LED 两端电压 | LED 状态 |
|-|-|-|
| 高电平（3.3V） | 阳极 3.3V，阴极 0V → 正向导通 | **点亮** |
| 低电平（0V） | 阳极 0V，阴极 0V → 无压差 | **熄灭** |


::: tip

**高电平点亮：**共阴极接法下，GPIO 输出高电平 LED 才亮。逻辑更直观，但需要 GPIO 能提供足够的驱动电流。

:::


### 2.3 限流电阻的作用

LED 导通后内阻很小，必须串联限流电阻防止电流过大烧毁 LED 和 GPIO。

| 参数 | 典型值 | 说明 |
|-|-|-|
| LED 导通压降 Vf | 1.8V \~ 2.2V（红/黄）  <br/>2.8V \~ 3.4V（蓝/绿/白） | 不同颜色 LED 的导通压降不同 |
| 工作电流 If | 2mA \~ 20mA | 一般指示灯取 5\~10mA 即可 |
| 限流电阻 R | 220Ω \~ 1kΩ | R = (VCC - Vf) / If |

## 三、GPIO配置步骤

以共阳极接法、PA5 引脚控制 LED 为例，完整配置流程如下：


::: tip

**配置四步走：**
1. 使能 GPIOA 时钟：`__HAL_RCC_GPIOA_CLK_ENABLE()`
2. 配置引脚为推挽输出模式：`GPIO_MODE_OUTPUT_PP`
3. 设置输出速度和上下拉：一般低速、无上拉下拉
4. 调用 `HAL_GPIO_Init()` 完成初始化

:::


## 四、代码实现

### 4.1 HAL库方式

```c
/* LED 引脚定义 */
#define LED0_PIN     GPIO_PIN_5
#define LED0_PORT    GPIOA

/* LED 亮灭宏（共阳极：低电平点亮） */
#define LED0_ON()    HAL_GPIO_WritePin(LED0_PORT, LED0_PIN, GPIO_PIN_RESET)
#define LED0_OFF()   HAL_GPIO_WritePin(LED0_PORT, LED0_PIN, GPIO_PIN_SET)
#define LED0_TOGGLE() HAL_GPIO_TogglePin(LED0_PORT, LED0_PIN)

/* LED 初始化函数 */
void LED_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    /* 1. 使能GPIOA时钟 */
    __HAL_RCC_GPIOA_CLK_ENABLE();

    /* 2. 配置PA5为推挽输出 */
    GPIO_InitStruct.Pin   = LED0_PIN;
    GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;  /* 推挽输出 */
    GPIO_InitStruct.Pull  = GPIO_NOPULL;           /* 无上下拉 */
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;   /* 低速 */
    HAL_GPIO_Init(LED0_PORT, &GPIO_InitStruct);

    /* 3. 默认熄灭（共阳极：高电平熄灭） */
    LED0_OFF();
}
```

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    LED_Init();

    while (1)
    {
        LED0_TOGGLE();   /* 翻转LED状态 */
        HAL_Delay(500);  /* 延时500ms，周期1秒 */
    }
}
```

### 4.2 寄存器级方式

```c
/* 使能GPIOA时钟（RCC AHB1ENR寄存器第0位） */
RCC->AHB1ENR |= (1 << 0);

/* 配置PA5为推挽输出模式
   MODER寄存器：每2位控制一个引脚，PA5对应位[11:10]
   01 = 通用输出模式 */
GPIOA->MODER &= ~(3 << (5 * 2));   /* 清除原有配置 */
GPIOA->MODER |=  (1 << (5 * 2));   /* 设置为输出模式 */

/* 配置输出类型：推挽（OTYPER寄存器第5位写0） */
GPIOA->OTYPER &= ~(1 << 5);

/* 配置输出速度：低速（OSPEEDR寄存器位[11:10]写00） */
GPIOA->OSPEEDR &= ~(3 << (5 * 2));

/* 无上下拉（PUPDR寄存器位[11:10]写00） */
GPIOA->PUPDR &= ~(3 << (5 * 2));

/* 点亮LED（共阳极：BSRR高16位写1，复位PA5输出低电平） */
GPIOA->BSRR = (1 << (5 + 16));  /* BR5 = 1，PA5输出低 */

/* 熄灭LED（BSRR低16位写1，置位PA5输出高电平） */
GPIOA->BSRR = (1 << 5);          /* BS5 = 1，PA5输出高 */
```

## 五、HAL库与寄存器对照

| 操作 | HAL库函数 | 底层寄存器 |
|-|-|-|
| 初始化引脚 | HAL_GPIO_Init() | MODER / OTYPER / OSPEEDER / PUPDR |
| 点亮LED（低电平） | HAL_GPIO_WritePin(RESET) | BSRR 高16位（BR） |
| 熄灭LED（高电平） | HAL_GPIO_WritePin(SET) | BSRR 低16位（BS） |
| 翻转LED状态 | HAL_GPIO_TogglePin() | 读ODR → 异或 → 写BSRR |

## 六、常见问题与调试


::: tip

**常见坑：**
- **LED不亮：**检查是否使能了 GPIO 时钟；检查接法是共阳还是共阴，亮灭电平是否搞反。
- **LED亮度不够：**限流电阻过大，或 GPIO 驱动电流不足（可降低电阻值，但不要超过 GPIO 最大灌/拉电流，一般 25mA）。
- **LED微亮（熄灭时仍有微光）：**引脚配置为浮空输入时，LED 两端可能有微弱漏电；应明确配置为输出模式并设置确定电平。
- **多个LED互相干扰：**不要用 ODR 直接赋值（会覆盖同组其他引脚），应使用 BSRR 或 HAL 库函数进行原子操作。
- **复位后LED异常亮：**STM32 复位后 GPIO 默认浮空输入，若 LED 接在该引脚上可能因不确定电平而微亮；应在初始化时立即设置确定电平。

:::




# 按键输入应用

## 一、按键输入原理

按键是嵌入式系统中最常见的人机交互输入设备。其本质是一个机械开关，按下时触点闭合导通，松开时触点断开。单片机通过 GPIO 引脚读取按键两端的电平状态，即可判断按键是否被按下。

| 按键状态 | 电路行为 |
|-|-|
| 未按下（松开） | 触点断开，GPIO 引脚由上拉/下拉电阻维持在确定电平 |
| 按下 | 触点闭合，GPIO 引脚被连接到 VCC 或 GND，电平翻转 |


::: tip

**核心要点：**按键本身只是一个开关，必须配合上拉或下拉电阻才能在松开时给 GPIO 一个确定的电平。如果没有上下拉电阻，松开时引脚处于浮空状态，电平不确定，读取结果不可靠。

:::


## 二、硬件连接方式

### 2.1 上拉输入接法（最常见）

按键一端接 GND，另一端接 GPIO 引脚，GPIO 引脚通过上拉电阻接 VCC。这是开发板上最常见的接法。

| 按键状态 | GPIO 引脚电平 | ReadPin 返回值 |
|-|-|-|
| 未按下（松开） | 高电平（上拉电阻拉高） | GPIO_PIN_SET |
| 按下 | 低电平（按键接通 GND） | GPIO_PIN_RESET |


::: tip

**低电平有效：**上拉接法下，按键按下时 GPIO 读取到低电平。判断按键按下的条件是 `HAL_GPIO_ReadPin() == GPIO_PIN_RESET`。

:::


### 2.2 下拉输入接法

按键一端接 VCC，另一端接 GPIO 引脚，GPIO 引脚通过下拉电阻接 GND。

| 按键状态 | GPIO 引脚电平 | ReadPin 返回值 |
|-|-|-|
| 未按下（松开） | 低电平（下拉电阻拉低） | GPIO_PIN_RESET |
| 按下 | 高电平（按键接通 VCC） | GPIO_PIN_SET |


::: tip

**高电平有效：**下拉接法下，按键按下时 GPIO 读取到高电平。逻辑更直观，但需要注意按键接 VCC 时的静电防护。

:::


### 2.3 硬件消抖电路

PDF 中提到的"上拉电阻与滤波电容并联按键"就是一种硬件消抖电路。在按键两端并联一个电容（通常 100nF \~ 1μF），利用电容充放电的延时特性来滤除机械抖动产生的毛刺。

| 组件 | 典型值 | 作用 |
|-|-|-|
| 上拉电阻 | 10kΩ | 松开时将引脚拉高到确定电平 |
| 滤波电容 | 100nF | 并联在按键两端，滤除抖动毛刺 |
| 按键 | 轻触开关 | 按下时接通 GND，松开时断开 |

## 三、按键消抖

机械按键的触点在闭合和断开的瞬间会产生弹性抖动，导致电平在短时间内多次跳变。如果不做消抖处理，一次按键可能被误判为多次按下。

### 3.1 机械抖动原理

| 阶段 | 电平表现 |
|-|-|
| 按下瞬间 | 触点弹跳，电平在高/低之间快速跳变，持续约 5\~10ms |
| 稳定按下 | 触点稳定接触，电平保持在低电平（上拉接法） |
| 松开瞬间 | 触点弹跳，电平再次跳变，持续约 5\~10ms |
| 稳定松开 | 触点稳定断开，电平恢复高电平 |

### 3.2 软件消抖（最常用）

检测到电平变化后，延时一段时间（通常 10\~20ms）再重新读取电平，如果两次读取结果一致，才确认按键状态发生了变化。

```c
/* 读取按键状态，返回1表示按下，0表示松开 */
uint8_t Key_Scan(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)
{
    /* 检测按键是否按下（低电平有效） */
    if (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_RESET)
    {
        HAL_Delay(10);  /* 延时消抖，等待抖动结束 */

        /* 再次确认按键仍然按下 */
        if (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_RESET)
        {
            /* 等待按键松开，避免连续触发 */
            while (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_RESET);
            return 1;  /* 确认按下一次 */
        }
    }
    return 0;  /* 未按下或抖动 */
}
```


::: tip

**消抖三要素：**① 首次检测到电平变化 → ② 延时 10\~20ms 跳过抖动期 → ③ 再次读取确认状态稳定。三步缺一不可。

:::


### 3.3 硬件消抖 vs 软件消抖对比

| 对比项 | 硬件消抖（RC滤波） | 软件消抖（延时重读） |
|-|-|-|
| 实现方式 | 上拉电阻 + 滤波电容 | 检测到变化后延时再读 |
| 成本 | 需要额外电容元件 | 纯软件，零硬件成本 |
| CPU占用 | 无，硬件自动完成 | 需要延时（阻塞或定时器） |
| 适用场景 | 按键数量少、对实时性要求高 | 按键数量多、成本敏感 |
| 缺点 | 增加 PCB 面积和 BOM 成本 | 阻塞式延体会浪费 CPU 时间 |

## 四、GPIO配置步骤

以上拉输入接法、PA0 引脚读取按键为例，完整配置流程如下：


::: tip

**配置四步走：**
1. 使能 GPIOA 时钟：`__HAL_RCC_GPIOA_CLK_ENABLE()`
2. 配置引脚为输入模式：`GPIO_MODE_INPUT`
3. 设置上拉：`GPIO_PULLUP`（硬件无上拉电阻时必须开启内部上拉）
4. 调用 `HAL_GPIO_Init()` 完成初始化

:::


## 五、代码实现

### 5.1 HAL库方式

```c
/* 按键引脚定义 */
#define KEY1_PIN     GPIO_PIN_0
#define KEY1_PORT    GPIOA

/* 按键状态宏（上拉接法：低电平=按下） */
#define KEY1_PRESSED  (HAL_GPIO_ReadPin(KEY1_PORT, KEY1_PIN) == GPIO_PIN_RESET)
#define KEY1_RELEASED (HAL_GPIO_ReadPin(KEY1_PORT, KEY1_PIN) == GPIO_PIN_SET)

/* 按键初始化函数 */
void KEY_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    /* 1. 使能GPIOA时钟 */
    __HAL_RCC_GPIOA_CLK_ENABLE();

    /* 2. 配置PA0为上拉输入 */
    GPIO_InitStruct.Pin  = KEY1_PIN;
    GPIO_InitStruct.Mode = GPIO_MODE_INPUT;    /* 输入模式 */
    GPIO_InitStruct.Pull = GPIO_PULLUP;        /* 内部上拉（硬件无上拉时必须开） */
    HAL_GPIO_Init(KEY1_PORT, &GPIO_InitStruct);
}
```

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    KEY_Init();
    LED_Init();  /* 假设LED已初始化，PA5控制 */

    uint8_t key_flag = 0;

    while (1)
    {
        /* 扫描按键，按下一次翻转LED */
        if (Key_Scan(KEY1_PORT, KEY1_PIN) == 1)
        {
            HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);  /* 翻转LED */

    }
}
```

### 5.2 寄存器级方式

```c
/* 使能GPIOA时钟（RCC AHB1ENR寄存器第0位） */

/* 配置PA0为输入模式
   MODER寄存器：每2位控制一个引脚，PA0对应位[1:0]
   00 = 输入模式 */
GPIOA->MODER &= ~(3 << (0 * 2));  /* 清除，设置为输入模式 */

/* 配置上拉（PUPDR寄存器位[1:0]写01 = 上拉） */

/* 读取按键状态（IDR寄存器第0位）
   上拉接法：0 = 按下，1 = 松开 */
if ((GPIOA->IDR & (1 << 0)) == 0)
{
    /* 按键按下 */
}
else
{
    /* 按键松开 */
}
```

## 六、HAL库与寄存器对照

| 操作 | HAL库函数 | 底层寄存器 |
|-|-|-|
| 初始化输入引脚 | HAL_GPIO_Init() | MODER / PUPDR |
| 读取引脚电平 | HAL_GPIO_ReadPin() | IDR（输入数据寄存器） |
| 软件消抖 | HAL_Delay() + 重读 | 无对应寄存器，纯软件逻辑 |

## 七、常见问题与调试


::: tip

**常见坑：**
- **按键无反应：**检查是否使能了 GPIO 时钟；检查引脚是否配置为输入模式；检查上下拉设置是否与硬件接法匹配。
- **一次按下触发多次：**没有做消抖处理，机械抖动被误判为多次按下。添加 10\~20ms 软件消抖或硬件 RC 滤波。
- **按键松开后仍触发：**消抖函数中没有等待按键松开（缺少 while 循环等待释放），导致长按期间连续返回按下。
- **读取电平不稳定/乱跳：**引脚浮空，没有配置上拉或下拉电阻。硬件有外部上下拉时可设为 NOPULL，否则必须开启内部上下拉。
- **消抖延时导致系统卡顿：**使用 HAL_Delay() 阻塞式消抖会占用 CPU。优化方案：用定时器记录时间戳，非阻塞式消抖；或使用外部中断 + 定时器消抖。
- **长按和短按无法区分：**需要记录按键按下的持续时间，按下时记录起始时间，松开时计算时长，根据阈值判断是短按还是长按。

:::


# 调压信号发生器应用

## 一、实验概述

本实验利用 STM32 的 GPIO 开漏输出（Open-Drain）模式，配合外部电阻分压网络和运算放大器，构建一个**可调电压的方波信号发生器**。通过调节电位器改变分压比，从而控制输出方波的高电平幅值。


::: tip

**实验目标：**
- 理解 GPIO 开漏输出模式的工作原理与应用场景
- 掌握电阻分压网络的计算方法
- 了解运算放大器作为电压跟随器（缓冲器）的作用
- 实现通过 GPIO 输出可调幅值的方波信号

:::


## 二、电路原理图

**电路连接关系：**

- **分压主回路**：+5V → R110（1kΩ）→ R111（10kΩ 电位器）→ R112（10kΩ）→ GND，三者串联构成可调分压网络
- **SW-OD 节点**：接在 R111 与 R112 之间，同时连接单片机 GPIO（开漏输出模式）。GPIO 输出低电平时 SW-OD = 0V；输出高电平时引脚高阻，SW-OD 电压由分压网络决定
- **运放缓冲级**：SW-OD → R113（100kΩ）→ U110A（LMV358）同相输入端（脚3）；运放反相输入端（脚2）直接接输出端（脚1），构成电压跟随器；R114（100kΩ）为反馈/偏置电阻
- **输出端**：运放输出（脚1）→ SW-TEST 端子，同时经 C110（100nF）滤波到 GND


::: tip

**信号流向：**GPIO 开漏输出控制 SW-OD 节点电平 → 电阻分压网络决定高电平幅值 → R113 限流送入运放同相端 → 电压跟随器缓冲输出 → SW-TEST 输出可调幅值方波。运放的作用是隔离分压网络与负载，保证输出电压不受外接负载影响。

:::


### 2.1 电路元件清单

| 元件编号 | 参数 | 封装 | 作用 |
|-|-|-|-|
| R110 | 1kΩ ±5%, 100mW | 0603 | 分压上电阻 |
| R111 | 10kΩ ±10% 电位器 | 3386P-1-103TLF | 可调电阻，调节输出电压 |
| R112 | 10kΩ ±5%, 100mW | 0603 | 分压下电阻 |
| R113 | 100kΩ ±5%, 100mW | 0603 | 运放同相端偏置/限流 |
| R114 | 100kΩ ±5%, 100mW | 0603 | 运放反馈电阻 |
| U110A | LMV358 | SOP-8 | 运算放大器（电压跟随器） |
| C110 | 100nF ±10%, 50V | 0603/X7R | 输出滤波/去耦 |

## 三、工作原理

### 3.1 开漏输出模式

SW-OD 节点连接单片机的 I/O 口。当 I/O 配置为**开漏输出**模式时：

- **输出低电平（0）**：内部 NMOS 导通，引脚被直接拉到 GND，SW-OD 电压为 **0V**
- **输出高电平（1）**：内部 PMOS 不工作（开漏模式无上拉），引脚呈**高阻态**，SW-OD 的电压完全由外部电路决定


::: tip

**开漏输出的关键特性：**高电平不是芯片主动驱动的，而是由外部上拉/分压电路决定。这使得开漏输出可以实现"线与"逻辑、电平转换和可调电压输出。

:::


### 3.2 分压网络分析

当 GPIO 输出高电平时（高阻态），电流从 +5V 经 R110 → R111（电位器）→ R112 → GND 形成串联回路。SW-OD 节点的电压由 R112 上的分压决定。

**分压计算公式：**

$$V_{SW-OD} = \frac{R_{112&#125;&#125;{R_{110} + R_{111} + R_{112&#125;&#125; \times 5V$$

### 3.3 输出电压范围计算

电位器 R111 可调范围为 0 \~ 10kΩ，因此输出电压范围为：

| R111 阻值 | 总电阻 | SW-OD 电压 |
|-|-|-|
| 0Ω（最小） | 1k + 0 + 10k = 11kΩ | 10/11 × 5V ≈ **4.55V** |
| 10kΩ（最大） | 1k + 10k + 10k = 21kΩ | 10/21 × 5V ≈ **2.38V** |

因此，通过调节电位器，SW-OD 的高电平可在 **2.38V \~ 4.55V** 之间连续调节。低电平均为 0V，从而产生幅值可调的方波。

### 3.4 运算放大器的作用

U110A（LMV358）接成**电压跟随器**（同相输入，输出直接反馈到反相输入端）：

- **高输入阻抗**：运放同相端输入阻抗极高，几乎不从分压网络取电流，保证分压精度不受负载影响
- **低输出阻抗**：运放输出阻抗极低，可以直接驱动外部负载（SW-TEST 输出端）
- **电压缓冲**：V_out = V_in，输出电压精确跟随 SW-OD 节点电压，起到隔离和驱动增强的作用


::: tip

**为什么需要运放缓冲？**如果直接从 SW-OD 节点输出，外接负载会与 R112 并联，改变分压比导致输出电压不准确。运放电压跟随器完美解决了这个问题。

:::


## 四、代码实现思路

### 4.1 GPIO 配置

```c
// 使能 GPIO 时钟
__HAL_RCC_GPIOx_CLK_ENABLE();

GPIO_InitTypeDef GPIO_InitStruct = {0};
GPIO_InitStruct.Pin   = GPIO_PIN_x;          // SW-OD 对应引脚
GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_OD; // 开漏输出模式
GPIO_InitStruct.Pull  = GPIO_NOPULL;         // 不使用内部上下拉（外部电路决定）
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW; // 方波频率不高，低速即可
HAL_GPIO_Init(GPIOx, &GPIO_InitStruct);
```

### 4.2 方波输出

```c
while (1)
{
    HAL_GPIO_WritePin(GPIOx, GPIO_PIN_x, GPIO_PIN_RESET); // 输出低电平 0V
    HAL_Delay(500);                                        // 低电平持续 500ms
    HAL_GPIO_WritePin(GPIOx, GPIO_PIN_x, GPIO_PIN_SET);   // 输出高电平（高阻态，由外部分压决定）
    HAL_Delay(500);                                        // 高电平持续 500ms
}
```


::: tip

**注意：**在开漏输出模式下，`GPIO_PIN_SET` 并不是输出高电平，而是让引脚进入高阻态，此时电压由外部分压电路决定。这是开漏输出与推挽输出最本质的区别。

:::


## 五、实验要点与常见问题

1. **必须配置为开漏模式**：如果配置为推挽输出，高电平时芯片会主动输出 VDD（通常 3.3V），外部分压电路将无法控制电压。
2. **不要开启内部上拉**：内部上拉电阻会与外部分压网络并联，改变分压比，导致输出电压不符合计算值。
3. **电位器调节方向**：R111 阻值越大，分压比越小，输出高电平越低；反之则越高。
4. **运放电源**：LMV358 需接 +5V 单电源供电，GND 共地。输出电压范围受运放限制（轨到轨接近 0\~5V）。
5. **测量点**：SW-OD 是分压节点（高阻），SW-TEST 是运放输出（低阻），测量输出电压应在 SW-TEST 端。

## 六、知识延伸

### 6.1 开漏输出的典型应用

- **I2C 总线**：SDA/SCL 均为开漏输出，配合上拉电阻实现多设备通信
- **电平转换**：通过外部上拉到不同电压，实现 3.3V 与 5V 系统间的通信
- **线与逻辑**：多个开漏输出接在一起，任一输出低电平则总线为低
- **可调电压输出**：如本实验，利用外部电路控制高电平幅值

### 6.2 方波频率控制

本实验使用 HAL_Delay() 实现简单的方波输出。若需要精确频率，可使用：

- 定时器 PWM 输出（但 PWM 通常是推挽模式，需额外电路配合）
- 定时器中断翻转 GPIO 电平
- DMA + 定时器实现高精度波形输出

# 继电器控制应用

## 一、实验概述

本实验利用 STM32 的 GPIO 输出控制 NPN 三极管的导通与截止，进而驱动 5V 继电器线圈，实现**用小电流控制大电流/高电压**的开关功能。继电器是嵌入式系统中最常用的电控开关器件之一，广泛应用于家电控制、工业自动化、智能插座等场景。


::: tip

**实验目标：**
- 理解电磁继电器的结构与工作原理
- 掌握 NPN 三极管开关驱动电路的设计
- 理解续流二极管（Flyback Diode）的作用与必要性
- 实现通过 GPIO 控制继电器通断，驱动外部负载

:::


## 二、继电器结构与工作原理

**继电器内部结构与连接关系：**

- **控制回路（线圈侧）**：D、E 为线圈两端，电流从 D 流入、E 流出时，电磁铁产生磁场
- **执行机构**：电磁铁上方为衔铁（可动铁片），衔铁左端由弹簧拉住，右端带动触点动作
- **触点回路（负载侧）**：A 为常闭端（NC），B 为公共端（COM），C 为常开端（NO）

  - 线圈不通电时：弹簧拉起衔铁，A-B 接触（常闭闭合），B-C 断开（常开断开）
  - 线圈通电时：电磁铁吸下衔铁，A-B 断开，B-C 接触（常开闭合，负载通电）


::: tip

**动作过程：**DE 通电 → 电磁铁生磁 → 吸下衔铁 → BC 接触导通 → 负载电路工作；DE 断电 → 电磁铁失磁 → 弹簧拉回衔铁 → BC 断开 → 负载电路停止。整个过程实现了"小电流控制大电流、低压控制高压"的电气隔离开关功能。

:::


### 2.1 结构组成

电磁继电器主要由以下部分组成：

- **电磁铁（线圈 DE）**：通电后产生磁场，是继电器的"控制端"
- **衔铁**：可动的铁质部件，受磁场吸引而动作
- **弹簧**：断电时将衔铁拉回原位，实现复位
- **触点（A/B/C）**：继电器的"被控端"，随衔铁动作而切换

### 2.2 工作过程

| 状态 | 线圈 DE | 电磁铁 | 衔铁 | 触点 |
|-|-|-|-|-|
| 吸合（ON） | 有电流流过 | 通电产生磁性 | 被吸下来 | B、C 接触，相当于导线导通 |
| 释放（OFF） | 无电流流过 | 断电失去磁性 | 被弹簧拉起 | B、C 断开，切断工作电路 |


::: tip

**核心思想：**继电器实现了"控制回路"与"工作回路"的电气隔离——线圈侧只需很小的电流（几十毫安），就能控制触点侧较大的电流（几安）和较高的电压。

:::


### 2.3 触点类型说明

- **常开端（NO, Normally Open）**：线圈不通电时断开，通电后闭合（本实验中 B-C 即常开触点）
- **常闭端（NC, Normally Closed）**：线圈不通电时闭合，通电后断开（图中 A-B）
- **公共端（COM, Common）**：触点的公共连接点（图中 B）

## 三、控制电路分析

**控制电路连接关系：**

- **输入控制路径**：Relay1（单片机 IO 口）→ R100（100Ω 基极限流电阻）→ Q100（S8050 NPN 三极管）基极
- **基极下拉**：R101（1kΩ）接在基极与 GND 之间，确保单片机复位/浮空时三极管可靠截止，防止继电器误动作
- **三极管驱动回路**：Q100 发射极 → GND；Q100 集电极 → 继电器 K100 线圈下端；线圈上端 → +5V
- **续流保护**：D100（1N4148）反向并联在线圈两端（阴极接 +5V，阳极接集电极），三极管截止时为线圈感性电流提供泄放回路，防止反电动势击穿三极管
- **负载输出**：继电器 K100（SRD-05VDC-SL-C）的常开/常闭/公共触点 → J100/J101/J102 接线端子，外接被控负载


::: tip

**工作流程：**Relay1 输出高电平（3.3V）→ 经 R100 限流后使 Q100 基极获得约 26mA 电流 → 三极管饱和导通（VCE≈0.2V）→ 继电器线圈两端加约 4.8V 电压 → 触点吸合，外接负载通电；Relay1 输出低电平（0V）→ 三极管截止 → 线圈断电，D100 续流泄放能量 → 触点释放，负载断电。

:::


### 3.1 电路元件清单

| 元件编号 | 型号/参数 | 封装 | 作用 |
|-|-|-|-|
| R100 | 100Ω ±1%, 100mW | 0603 | 三极管基极限流电阻 |
| R101 | 1kΩ ±5%, 100mW | 0603 | 基极下拉电阻，确保可靠截止 |
| Q100 | S8050（NPN） | SOT-23 | 开关三极管，驱动继电器线圈 |
| D100 | 1N4148WS | SOD-323 | 续流二极管，吸收线圈反电动势 |
| K100 | SRD-05VDC-SL-C | — | 5V 直流继电器（松乐） |
| J100/J101/J102 | K14 Terminal | — | 外部负载接线端子 |

### 3.2 控制逻辑

Relay1 连接单片机的 I/O 口，通过 GPIO 输出电平控制三极管：

| Relay1 输出 | 三极管 Q100 | 继电器线圈 | 触点状态 |
|-|-|-|-|
| 低电平（0V） | 截止 | 无电流，不动作 | 常开触点断开 |
| 高电平（3.3V） | 饱和导通 | 有电流，吸合 | 常开触点闭合 |

## 四、三极管驱动原理

### 4.1 为什么需要三极管？

STM32 的 GPIO 引脚输出电流有限（通常最大 25mA，推荐不超过 8mA），而继电器线圈工作电流通常在 **50\~100mA** 左右，GPIO 无法直接驱动。NPN 三极管起到**电流放大**作用：用 GPIO 的小电流控制基极，进而让集电极通过较大的线圈电流。

### 4.2 基极限流电阻计算

R100 为基极限流电阻，防止基极电流过大损坏三极管：

$$I_B = \frac{V_{OH} - V_{BE&#125;&#125;{R_{100&#125;&#125; = \frac{3.3V - 0.7V}{100\Omega} = 26mA$$

S8050 的直流放大倍数 hFE 通常 ≥ 100，理论集电极电流可达 26mA × 100 = 2.6A，远大于继电器线圈电流（约 70mA），三极管工作在**饱和导通**状态，压降 VCE(sat) ≈ 0.2V。

### 4.3 基极下拉电阻 R101 的作用

- 单片机复位或上电瞬间，GPIO 可能处于高阻态（浮空），R101 将基极拉到 GND，确保三极管**可靠截止**，防止继电器误动作
- 提供基极电荷泄放通路，加快三极管关断速度

## 五、续流二极管的作用


::: tip

**关键保护元件，不可省略！**

:::


继电器线圈是感性负载，当三极管由导通变为截止时，线圈中的电流突然被切断，根据楞次定律，线圈会产生**很高的反向电动势**（可能达到几十伏），这个尖峰电压可能击穿三极管。

D100（1N4148）反向并联在线圈两端：

- **三极管导通时**：二极管反向偏置（阴极接+5V，阳极接集电极≈0.2V），不导通，不影响电路
- **三极管截止时**：线圈产生的反电动势使二极管正向偏置，为线圈电流提供**续流回路**，将能量消耗在线圈电阻和二极管压降上，电压被钳位在约 0.7V，保护三极管

## 七、实验要点与常见问题

1. **继电器线圈电压匹配**：本实验使用 5V 继电器，线圈供电必须为 +5V，不能用 3.3V 供电，否则吸力不足无法吸合。
2. **续流二极管方向**：必须反向并联（阴极接线圈正极+5V，阳极接三极管集电极），接反会导致线圈短路、三极管烧坏。
3. **共地问题**：单片机 GND 与继电器控制电路 GND 必须共地，否则三极管无法正常导通。
4. **触点侧与控制侧隔离**：继电器触点可以控制交流 220V 或其他高压负载，但接线时务必注意安全，触点侧与控制侧不要共地。
5. **继电器动作有延迟**：机械继电器吸合时间约 5\~10ms，释放时间约 2\~5ms，高频开关场景不适用，应使用固态继电器（SSR）。
6. **触点灭弧**：控制大电流或感性负载时，触点断开会产生电弧，建议在触点两端并联 RC 吸收电路或使用额定电流更大的继电器。

## 八、知识延伸

### 8.1 继电器的主要参数

- **线圈额定电压**：5V / 12V / 24V 等，需与供电匹配
- **线圈电阻/电流**：决定驱动功耗，SRD-05VDC 线圈电阻约 70Ω，工作电流约 70mA
- **触点额定电流/电压**：如 10A/250VAC，表示触点最大可切换的负载能力
- **机械寿命/电气寿命**：机械寿命通常 1000 万次，电气寿命约 10 万次（带额定负载）

### 8.2 其他驱动方案对比

| 驱动方案 | 优点 | 缺点 | 适用场景 |
|-|-|-|-|
| NPN 三极管（本实验） | 简单、成本低 | 有压降、需限流电阻 | 通用小功率继电器 |
| ULN2003 达林顿阵列 | 集成 7 路、内置续流二极管 | 压降较大（约 1V） | 多路继电器/步进电机 |
| MOSFET | 压控、低导通电阻、高速 | **需注意栅极驱动电压** | 大电流、高频开关 |
| 光耦 + 继电器 | 完全电气隔离、抗干扰强 | 成本高、体积大 | 工业控制、强电隔离 |

### 8.3 继电器 vs 固态继电器（SSR）

- **电磁继电器**：有机械触点，导通压降小，可交直流通用，但有寿命限制、动作慢、有噪音
- **固态继电器（SSR）**：无机械触点，寿命长、速度快、无噪音，但有导通压降、发热大、通常只能控交流或直流单一类型

# 整体串讲

## 一、知识地图：从物理到应用的五层架构

整个文档围绕 GPIO 展开，但并非零散知识点的堆砌，而是一条从**物理本质**到**工程应用**的完整链路。理解这条链路，就掌握了"为什么"，而不仅仅是"怎么做"。

| 层级 | 核心问题 | 关键内容 | 对应章节 |
|-|-|-|-|
| **物理层** | 引脚到底是什么？ | CMOS 反相器、PMOS/NMOS 互补结构、一根金属线的物理本质 | 第一章 二、三节 |
| **电气层** | 电平怎么定义？电流能有多大？ | VIL/VIH 阈值、驱动能力、上下拉电阻、开漏与推挽的电气差异 | 第一章 三、四节 |
| **架构层** | 芯片内部怎么管理引脚？ | MODER/OTYPER/OSPEEDR/PUPDR/IDR/ODR/BSRR 寄存器组 | 第一章 四节 + 第二章 |
| **功能层** | 8 种模式怎么来的？ | 输入浮空/上拉/下拉/模拟、输出推挽/开漏、复用推挽/开漏的推导 | 第一章 五节 + 第二章 |

**核心理念：**每一层都是上一层的必然结果。8 种模式不是背出来的，而是从"引脚要解决什么问题"一步步推导出来的。理解了推导过程，换任何一款 MCU（STM32、ESP32、GD32、NXP……）都能快速上手。

## 二、四大应用场景横向对比

文档中的四个应用场景覆盖了 GPIO 最典型的用法，它们之间的对比能帮你建立"模式选择直觉"：

| 应用场景 | 方向 | GPIO 模式 | 核心外部电路 | 关键技术点 |
|-|-|-|-|-|
| LED 灯控制 | 输出 | 推挽输出 (PP) | LED + 限流电阻 | 电流计算、高/低电平点亮差异 |
| 按键输入 | 输入 | 输入上拉/下拉 | 按键开关 | 消抖（软件/硬件）、长短按识别 |
| 调压信号发生器 | 输出 | 开漏输出 (OD) | 电阻分压网络 + 运放跟随器 | 开漏高阻态、分压计算、电压缓冲 |
| 继电器控制 | 输出 | 推挽输出 (PP) | NPN 三极管 + 续流二极管 + 继电器 | 电流放大、感性负载保护、电气隔离 |

### 2.1 从对比中提炼规律

- **输出类应用**（LED、继电器、调压）：核心矛盾是**"GPIO 驱动能力够不够"**。不够就加驱动电路（三极管/MOSFET/运放）。
- **输入类应用**（按键）：核心矛盾是**"信号是否稳定可靠"**。需要处理浮空、抖动、噪声等问题。
- **推挽 vs 开漏的选择**：需要主动驱动电压→推挽；需要外部电路决定电压或多设备总线→开漏。

## 三、GPIO 应用的通用分析方法论（核心）

这是本节最重要的部分——**遇到任何一个新的 GPIO 应用场景，按以下五步走，就能从零设计出完整方案**。这就是"授人以渔"。

### 第一步：明确需求边界

动手之前先回答四个问题：

1. **方向**：是输入（读外部信号）还是输出（控制外部设备）？还是双向？
2. **信号类型**：数字信号（0/1）还是模拟信号（连续电压）？模拟信号需要 ADC/DAC，GPIO 只能处理数字。
3. **电气参数**：电压是多少？（3.3V？5V？12V？220V？）电流需要多大？（mA 级？A 级？）
4. **速度要求**：低速（Hz\~kHz 级，如按键、继电器）还是高速（MHz 级，如 SPI 通信）？

### 第二步：选择 GPIO 工作模式

根据需求，按以下决策树选择模式：

| 需求特征 | 选择模式 | 典型场景 |
|-|-|-|
| 输出 + 主动驱动电压 + 电流小 | 推挽输出 (OUTPUT_PP) | LED、直接驱动三极管基极 |
| 输出 + 高电平由外部决定 / 总线 | 开漏输出 (OUTPUT_OD) | I2C、调压输出、电平转换 |
| 输入 + 外部有确定电平 | 浮空输入 (INPUT_FLOATING) | 接标准数字信号源 |
| 输入 + 外部开关/不确定电平 | 上拉或下拉输入 (INPUT_PULLUP/PULLDOWN) | 按键、开关检测 |
| 输入 + 模拟电压采集 | 模拟输入 (ANALOG) | ADC 采集、电压检测 |
| 片上外设信号（UART/SPI/PWM等） | 复用功能 (AF_PP / AF_OD) | 串口、SPI、定时器 PWM |

### 第三步：设计外部电路

这是最能体现工程能力的一步，核心是回答三个问题：

1. **驱动能力匹配**：GPIO 输出电流（通常 ≤8mA 安全）能否驱动负载？不能则加驱动级：

   - 小功率（几十 mA）：NPN/PNP 三极管（如继电器电路）
   - 中大功率（几百 mA\~几 A）：MOSFET（注意栅极驱动电压）
   - 需要隔离：光耦 + 驱动级
   - 需要电压跟随/缓冲：运放电压跟随器（如调压电路）
2. **电平匹配**：外部电路电压与 MCU 电压（通常 3.3V）是否一致？

   - 5V → 3.3V 输入：分压电阻或电平转换芯片
   - 3.3V → 5V 输出：开漏 + 上拉到 5V，或三极管/MOSFET 电平转换
3. **保护与可靠性**：

   - 感性负载（继电器、电机、蜂鸣器）：必须加续流二极管
   - 输入端：加 RC 滤波、TVS 管防 ESD
   - 输出端：串联合适的限流电阻
   - 不确定状态：上下拉电阻确保默认电平

### 第四步：编写驱动代码

所有 GPIO 应用的代码都遵循同一个骨架：

```c
// ===== 1. 初始化（只执行一次）=====
void GPIO_App_Init(void)
{
    // 1.1 使能时钟（忘记这步是最常见的 bug！）
    __HAL_RCC_GPIOx_CLK_ENABLE();

    // 1.2 配置引脚模式、速度、上下拉
    GPIO_InitTypeDef GPIO_InitStruct = {0};
    GPIO_InitStruct.Pin   = GPIO_PIN_x;
    GPIO_InitStruct.Mode  = GPIO_MODE_xxx;  // 根据第二步选择
    GPIO_InitStruct.Pull  = GPIO_NOPULL;    // 或 PULLUP/PULLDOWN
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;  // 按需选择
    HAL_GPIO_Init(GPIOx, &GPIO_InitStruct);

    // 1.3 设置初始安全状态（如继电器默认断开、LED默认熄灭）
    HAL_GPIO_WritePin(GPIOx, GPIO_PIN_x, GPIO_PIN_RESET);
}

// ===== 2. 运行时操作（循环或中断中调用）=====
// 输出类：
HAL_GPIO_WritePin(GPIOx, GPIO_PIN_x, GPIO_PIN_SET);   // 输出高
HAL_GPIO_WritePin(GPIOx, GPIO_PIN_x, GPIO_PIN_RESET); // 输出低
HAL_GPIO_TogglePin(GPIOx, GPIO_PIN_x);                // 翻转

// 输入类：
GPIO_PinState state = HAL_GPIO_ReadPin(GPIOx, GPIO_PIN_x);

// ===== 3. 信号处理（按需）=====
// 输入：消抖、滤波、状态机识别（短按/长按/双击）
// 输出：PWM 调光、频率控制、时序生成
```

对应的**寄存器级实现**如下（以 STM32F4 为例，F1 系列寄存器名略有差异，原理一致）。理解寄存器操作，才能真正明白 HAL 库函数背后做了什么：

```c
// ===== 1. 初始化（只执行一次）=====
void GPIO_Reg_Init(void)
{
    // 1.1 使能 GPIOA 时钟（RCC_AHB1ENR 寄存器 bit0）
    // 忘记这步，后续所有寄存器写入都无效！
    RCC->AHB1ENR |= RCC_AHB1ENR_GPIOAEN;

    // 1.2 配置 MODER：PA5 为通用输出模式 (01)
    // MODER 每 2 bit 控制一个引脚：00=输入, 01=输出, 10=复用, 11=模拟
    GPIOA->MODER &= ~(3U << (5 * 2));      // 先清除 PA5 的 2 bit
    GPIOA->MODER |=  (1U << (5 * 2));      // 设置为 01（输出模式）

    // 1.3 配置 OTYPER：PA5 为推挽输出 (0)
    // OTYPER 每 1 bit 控制一个引脚：0=推挽, 1=开漏
    GPIOA->OTYPER &= ~(1U << 5);           // 推挽输出

    // 1.4 配置 OSPEEDR：PA5 为低速 (00)
    // OSPEEDR 每 2 bit 控制一个引脚：00=低速, 01=中速, 10=高速, 11=极高速
    GPIOA->OSPEEDR &= ~(3U << (5 * 2));    // 低速

    // 1.5 配置 PUPDR：PA5 无上下拉 (00)
    // PUPDR 每 2 bit 控制一个引脚：00=无, 01=上拉, 10=下拉
    GPIOA->PUPDR &= ~(3U << (5 * 2));      // 无上下拉

    // 1.6 设置初始输出低电平（ODR 寄存器）
    GPIOA->ODR &= ~(1U << 5);              // PA5 输出低
}

// ===== 2. 运行时操作 =====

// 2.1 输出高电平（方法一：写 ODR 寄存器）
void GPIO_Set_High(void)
{
    GPIOA->ODR |= (1U << 5);               // 直接置位 ODR bit5
}

// 2.2 输出高电平（方法二：写 BSRR 寄存器，原子操作，推荐！）
void GPIO_Set_High_Atomic(void)
{
    // BSRR 低 16 bit 写 1 = 置位对应引脚，写 0 无影响
    // 优势：读-改-写三步合并为一次写操作，中断安全
    GPIOA->BSRR = (1U << 5);
}

// 2.3 输出低电平（方法一：写 ODR 寄存器）
void GPIO_Set_Low(void)
{
    GPIOA->ODR &= ~(1U << 5);              // 直接清除 ODR bit5
}

// 2.4 输出低电平（方法二：写 BSRR 高 16 bit，原子操作，推荐！）
void GPIO_Set_Low_Atomic(void)
{
    // BSRR 高 16 bit 写 1 = 复位对应引脚
    GPIOA->BSRR = (1U << (5 + 16));
}

// 2.5 翻转输出电平（读 ODR 再异或写回）
void GPIO_Toggle(void)
{
    GPIOA->ODR ^= (1U << 5);               // 异或翻转 bit5
}

// 2.6 读取引脚输入电平（IDR 寄存器，只读）
int GPIO_Read(void)
{
    // IDR 低 16 bit 对应 16 个引脚的实际电平
    return (GPIOA->IDR >> 5) & 0x1;        // 返回 PA5 的电平：0 或 1
}

// ===== 3. HAL 库与寄存器的对应关系 =====
// HAL_GPIO_Init()       → 配置 MODER + OTYPER + OSPEEDR + PUPDR
// HAL_GPIO_WritePin()   → 写 BSRR 寄存器（原子置位/复位）
// HAL_GPIO_TogglePin()  → 读 ODR 异或后写 ODR
// HAL_GPIO_ReadPin()    → 读 IDR 寄存器
// __HAL_RCC_GPIOx_CLK_ENABLE() → 写 RCC_AHB1ENR 对应位
```


::: tip

**为什么推荐用 BSRR 而不是 ODR？**写 ODR 是"读-改-写"三步操作，如果在读取和写入之间发生中断，且中断里也修改了同一端口的其他引脚，就可能丢失修改。BSRR 是单次原子写操作，置位和复位互不干扰，在多中断/多任务环境中更安全。HAL 库的 `HAL_GPIO_WritePin()` 内部就是用 BSRR 实现的。

:::


下面用表格和笔记的形式，系统总结 GPIO 8 个寄存器的角色分工、配置顺序和关键区别，配合上面的代码理解效果更佳：

### 4.1 GPIO 寄存器角色分配表

| 寄存器 | 英文全称 | 角色定位 | 核心作用 | 什么时候配置 |
|-|-|-|-|-|
| **MODER** | Mode Register | 老大（决策者） | 决定引脚是输入、输出、复用还是模拟模式 | 管方向：任何引脚使用前，第一个要配的 |
| **OTYPER** | Output Type Register | 执行者（输出风格） | 决定输出是推挽（Push-Pull）还是开漏（Open-Drain） | 管输出能力：仅在输出模式时有效 |
| **OSPEEDR** | Output Speed Register | 执行者（输出速度） | 决定输出引脚的压摆率（翻转速度，如 2MHz、25MHz） | 管输出品质：仅输出模式配置，够用即可，过快增加功耗和噪声 |
| **PUPDR** | Pull-Up / Pull-Down Register | 辅助者（初始状态） | 决定内部是否接上拉/下拉电阻 | 管空闲状态：输入模式常用，输出模式有时也用 |
| **ODR** | Output Data Register | 执行者（实际输出） | 写 1 引脚输出高电平，写 0 输出低电平 | 管写操作：HAL_GPIO_WritePin 最终写的就是它 |
| **IDR** | Input Data Register | 观察者（实际输入） | 读取引脚当前的物理电平（0 或 1） | 管读操作：HAL_GPIO_ReadPin 读的就是它 |
| **BSRR** | Bit Set / Reset Register | 执行者（原子操作） | 一个地址同时完成置位（BS）和复位（BR），不会被中断打断 | 管高性能输出：中断里翻转 IO 用它比 ODR 更安全 |
| **AFRL/AFRH** | Alternate Function Register Low/High | 老大（功能指派） | 复用模式时，指定引脚具体复用到哪个外设（如 USART_TX、SPI_SCK） | 管特殊功能：使用串口、I2C、SPI 等外设时必须配置 |

### 4.2 GPIO 配置顺序（严格按依赖关系）

配置 GPIO 时有一个严格的逻辑顺序，按这个顺序走，根本不用背寄存器名字：

1. **第一步：定方向（MODER）**——到底是输入、输出、复用还是模拟？这是所有配置的前提。
2. **第二步（输出/复用时）：定输出类型和速度（OTYPER + OSPEEDR）**——推挽还是开漏？跑多快？
3. **第三步（输入/输出时）：定上下拉（PUPDR）**——高阻、上拉还是下拉？
4. **第四步（复用时）：定具体功能（AFRL/AFRH）**——比如引脚要当串口的 TX，选 AF1 还是 AF7？
5. **第五步（实际读写时）：读用 IDR，写用 ODR 或 BSRR**。

### 4.3 ODR 与 BSRR 的核心区别

| 对比项 | ODR（输出数据寄存器） | BSRR（位置位/复位寄存器） |
|-|-|-|
| 读写属性 | 可读可写 | 只写 |
| 操作方式 | 读-修改-写三步（如 `ODR \|= 0x0001`） | 单次写操作完成置位或复位 |
| 位操作方式 | 直接读写对应位 | 低 16 位写 1 = 置位；高 16 位写 1 = 复位 |
| 中断安全 | 不安全：三步之间可能被中断打断，导致"位冲刷" | 安全：单条原子指令，不会被中断打断 |
| 推荐场景 | 需要同时读取输出状态时 | 中断里操作 IO、多任务环境，永远优先用 BSRR |


::: tip

HAL 库的 `HAL_GPIO_WritePin()` 底层就是用 BSRR 实现的，所以用 HAL 库时天然就是原子操作。只有直接操作寄存器时才需要注意这个区别。

:::



::: tip

**一句话助记：**MODER 定生死（模式），OTYPER 定性格（推挽/开漏），OSPEEDR 定快慢（速度），PUPDR 定品格（上下拉），IDR/ODR 是眼睛和手（读/写），BSRR 是快刀手（原子操作），AFR 是变脸专家（复用功能）。

:::


### 第五步：调试与验证

写完代码不代表完成，必须用仪器验证：

1. **万用表**：测量引脚电平是否符合预期（高电平应接近 VDD，低电平应接近 0V）
2. **示波器**：观察输出波形（方波是否失真、上升/下降沿、噪声）、输入信号（按键抖动长什么样）
3. **逻辑分析仪**：多路数字信号时序分析，适合通信协议调试
4. **常见问题排查顺序**：时钟使能 → 模式配置 → 硬件连接 → 共地 → 外部电路 → 代码逻辑


::: tip

**方法论总结：**需求分析 → 模式选择 → 电路设计 → 代码实现 → 调试验证。这五步不仅适用于 GPIO，也适用于几乎所有嵌入式外设开发（UART、SPI、I2C、ADC、PWM……），是通用的嵌入式开发思维框架。

:::


## 四、嵌入式 GPIO 设计的工程原则

### 4.1 可靠性原则

- **默认安全状态**：上电/复位时，GPIO 应处于安全状态（继电器断开、电机停止、LED 熄灭），通过上下拉电阻和初始输出值保证
- **避免浮空**：未使用的引脚不要悬空，配置为模拟输入或带上下拉的输入，降低功耗和噪声干扰
- **关键输入加硬件滤波**：工业环境中，仅靠软件消抖不够，输入端应加 RC 滤波（如 10kΩ + 100nF）

### 4.2 功耗原则

- 低功耗设计中，未使用的引脚配置为模拟输入（功耗最低）
- 输出引脚避免长期输出高电平驱动大电流负载，能用电平触发就不用持续驱动
- 上下拉电阻阻值不宜过小（通常 10kΩ\~100kΩ），否则静态电流大

### 4.3 可维护性原则

- 用宏定义封装引脚，避免代码中出现魔法数字：`#define RELAY_PIN GPIO_PIN_5`
- 每个外设写独立的 init/read/write 函数，主程序只调用接口，不直接操作寄存器
- 关键操作加注释说明"为什么这样配置"，而不是"配置了什么"

## 五、从 GPIO 到更复杂外设的思维迁移

GPIO 是嵌入式系统中最简单的外设，但它的学习方法可以迁移到所有外设。掌握了 GPIO 的第一性原理分析方法，再学其他外设就会触类旁通：

| 外设 | 与 GPIO 的关系 | 核心关注点（类比 GPIO） |
|-|-|-|
| UART 串口 | TX 是复用推挽输出，RX 是复用输入 | 电平标准（TTL/RS232/RS485）、波特率、驱动能力 |
| SPI | SCK/MOSI 复用输出，MISO 复用输入 | 时钟频率、片选时序、电平匹配 |
| I2C | SDA/SCL 都是复用开漏输出 | 上拉电阻计算、总线电容、多设备地址 |
| PWM | 定时器通道复用输出 | 频率/占空比、驱动能力、电平转换 |
| ADC | GPIO 配置为模拟输入模式 | 输入电压范围、采样时间、分压电路设计 |
| 外部中断 | GPIO 输入 + EXTI 控制器 | 触发边沿、消抖、中断优先级 |


::: tip

**迁移要点：**所有外设本质上都是"GPIO 的特定模式 + 专用控制器"。学任何新外设，先搞清楚：它用了哪些引脚？这些引脚是什么模式？外部电路需要什么？然后再看专用控制器的寄存器和协议。这就是第一性原理的迁移能力。

:::


## 六、学习路径与能力进阶建议

### 6.1 实践项目递进

1. **入门级**：LED 闪烁 → LED PWM 调光 → 按键控制 LED（本文档前三个应用）
2. **进阶级**：继电器控制家电 → 调压信号发生器 → 红外遥控接收（本文档后两个应用 + 扩展）
3. **综合级**：智能插座（WiFi + 继电器 + 按键 + LED 指示灯）、环境监测站（ADC + I2C 传感器 + 串口上传）
4. **工程级**：考虑 EMC 设计、低功耗优化、故障检测与自动恢复

### 6.2 必备调试工具

- **万用表**：最基础也最重要，测通断、测电平、测电流
- **USB-TTL 串口模块**：打印调试信息，与 PC 通信
- **逻辑分析仪**：数字协议分析的利器，性价比高（十几元的 USB 逻辑分析仪即可入门）
- **示波器**：模拟波形观察的终极工具，有条件必入

### 6.3 能力进阶方向

- **从 HAL 库到寄存器**：熟练后尝试直接操作寄存器，理解 HAL 库背后做了什么
- **从轮询到中断/DMA**：提升系统响应速度和 CPU 利用率
- **从裸机到 RTOS**：多任务管理、信号量、消息队列
- **从功能到可靠性**：看门狗、异常恢复、EMC 抗干扰设计

---


::: tip

**最终寄语：**GPIO 是嵌入式开发的"第一课"，但绝不是"简单课"。它背后蕴含的电气特性、驱动设计、可靠性思维，贯穿了整个嵌入式开发生涯。把 GPIO 学透，不是记住 8 种模式和几个函数，而是建立起"从物理本质到工程实现"的分析能力。拥有了这种能力，面对任何新芯片、新外设、新场景，你都能从容应对——这才是真正的"授人以渔"。

:::
