# I2C 总线协议概述

## 什么是 I2C

I2C（Inter-Integrated Circuit，集成电路总线）由飞利浦（Philips，现为 NXP）公司在 20 世纪 80 年代开发，是一种广泛用于嵌入式系统的**同步、串行、半双工**通信协议，用于在同一块电路板上的集成电路之间进行短距离通信。

从第一性原理来看，I2C 的设计目标是：**用最少的引脚，在一块 PCB 上连接多个低速外设芯片**。相比 SPI 需要 4 根线（SCK、MOSI、MISO、CS）且每个从设备多一根片选线，I2C 仅需 2 根线（SDA、SCL）即可挂载最多 127 个从设备，极大简化了板级布线。

## I2C 总线 vs I2C 协议

这两个概念经常被混用，但严格来说它们是不同层次的东西：

- **I2C 总线**：是一种**物理通信架构**，指 SDA、SCL 两根线加上拉电阻组成的硬件连接拓扑，用于连接多个设备、实现设备之间的电气信号传输。
- **I2C 协议**：是一套**规则**，定义了 I2C 总线上数据通信的过程，包括如何启动通信、传输数据、应答信号、结束通信等时序规范。

类比理解：总线是"公路"（物理基础设施），协议是"交通规则"（谁先走、怎么超车、怎么停车）。

## 典型应用场景

- EEPROM 存储器（AT24C02 等）
- 实时时钟 RTC（DS3231、PCF8563）
- 温度传感器（LM75、SI7021）
- OLED/LCD 显示屏驱动（SSD1306）
- 触摸屏控制器（FT5xx6）
- 加速度计/陀螺仪（MPU6050）
- 音频编解码器（WM8978）


::: tip

**核心记忆点**：I2C = 2 根线 + 主从架构 + 地址寻址 + 开漏输出 + 上拉电阻。这五个要素构成了 I2C 的全部本质。

:::


# I2C 总线的特点

## 双线通信

I2C 仅使用两根信号线：

- **SDA（Serial Data）**：数据线，负责传输实际数据位。
- **SCL（Serial Clock）**：时钟线，负责同步数据采样。

两根线都是**双向**的，既可以输出也可以输入，这是通过开漏输出结构实现的（详见第 3 章）。

## 同步通信

数据传输由 SCL 时钟信号控制，发送方在 SCL 低电平期间改变 SDA 数据，接收方在 SCL 高电平期间采样 SDA 数据。时钟由主设备产生，从设备不需要自己的时钟源，降低了硬件成本。

**同步 vs 异步的本质区别**：同步通信有独立的时钟线，收发双方靠时钟沿对齐；异步通信（如 UART）没有时钟线，靠约定的波特率和起始位来同步，对时序精度要求更高。

## 串行数据传输

每次只传输一位（bit）数据，通过时间序列完成完整的字节（8 bit）传输。串行的优势是引脚少，劣势是速度相对并行慢，但在板级短距离通信中，I2C 的速度已经足够。

## 半双工传输

在同一时间内，通信双方只能有一个方向的数据传输。SDA 只有一根线，要么主设备发、从设备收，要么从设备发、主设备收，不能同时双向传输。

方向切换是通过协议中的"读/写位"和"应答机制"来协调的，不会出现两个设备同时驱动 SDA 的情况（开漏结构也保证了即使同时驱动也不会短路，而是线与）。

## 主从架构

- **主设备（Master）**：控制通信过程，生成 SCL 时钟信号，发起起始和停止条件。总线上可以有多个主设备。
- **从设备（Slave）**：被动响应主设备的命令，不会主动发起通信。从设备可以通过拉低 SCL 来延长时钟周期（时钟拉伸），以此请求主设备等待。

## 支持多主多从

同一总线上可以连接多个主设备和从设备。当多个主设备同时想占用总线时，需要进行**冲突检测和仲裁**（Arbitration）。I2C 的仲裁机制非常巧妙：利用开漏输出的线与特性，主设备在发送数据的同时监听 SDA，如果自己发的是高电平但读到的是低电平，说明有另一个主设备在发低电平，自己就主动退出竞争。

## 从机地址唯一性

每个从设备都有**唯一的 7 位或 10 位从机地址**，主设备通过从机地址指定要通信的从设备。7 位地址理论上可挂载 127 个设备（0x00\~0x7F，其中部分地址保留），10 位地址可挂载 1024 个设备。


::: tip

**地址冲突陷阱**：同一种芯片的地址通常是固定的或通过引脚配置的。如果总线上挂了两个相同地址的从设备，通信会失败。设计硬件时要检查所有从设备的地址是否唯一。

:::


## 速度模式

I2C 协议定义了多种速度模式，不同模式对总线电容、上升时间、上拉电阻有不同要求：

| 模式 | 最大速率 | 最大总线电容 | 最大上升时间 |
|-|-|-|-|
| 标准模式（Standard Mode） | 100 KHz | 400 pF | 1000 ns |
| 快速模式（Fast Mode） | 400 KHz | 400 pF | 300 ns |
| 高速模式（High-Speed Mode） | 3.4 MHz | 550 pF | 120 ns |
| 超高速模式（Ultra-Fast Mode） | 5 MHz | — | — |

实际项目中最常用的是标准模式（100 KHz）和快速模式（400 KHz）。高速模式需要主设备有电流驱动能力，且协议更复杂，较少使用。

# I2C 总线的开漏结构（物理层）

## 为什么需要上拉电阻

I2C 芯片的 SCL 和 SDA 引脚是**开漏输出（Open-Drain Output）**结构。开漏输出只能驱动低电平（将引脚拉到 GND），不能驱动高电平（不能将引脚拉到 VCC）。当输出高电平时，引脚处于**高阻态（High Impedance State）**，相当于电路开路，不驱动总线。

因此，必须在 SDA 和 SCL 上接入**上拉电阻**到 VCC，当所有设备都释放总线（高阻态）时，上拉电阻将信号线拉到高电平。

**高阻态的三个特点**：

1. 不驱动信号线，对总线电平没有主动影响。
2. 输出端对总线的影响极小（漏电流在 μA 级）。
3. 需要依赖外部电路（上拉电阻）决定信号线的电平。

## 开漏输出的电路原理

从第一性原理拆解开漏输出的内部电路：引脚内部是一个 N沟道 MOSFET，漏极（Drain）接引脚，源极（Source）接 GND，栅极（Gate）由内部控制逻辑驱动。

- 当栅极为高电平时，MOSFET 导通，引脚通过导通的 MOSFET 连接到 GND → **输出低电平**。
- 当栅极为低电平时，MOSFET 截止，引脚与 GND 断开 → **高阻态**，此时引脚电平由外部上拉电阻决定。

这就是"开漏"名称的由来：MOSFET 的漏极是"开着的"（没有内部上拉到 VCC），必须外接上拉电阻才能输出高电平。

## 线与逻辑（Wired-AND）

开漏输出的一个关键特性是可以实现**线与逻辑**：多个开漏输出的引脚可以直接连在一起，不需要额外的逻辑门。

原理：只要有任何一个设备将引脚拉低（MOSFET 导通），整个总线就是低电平；只有所有设备都释放总线（高阻态），上拉电阻才能将总线拉到高电平。这在逻辑上等价于"所有设备都输出高，总线才是高"，即**逻辑与**。

线与逻辑是 I2C 能支持多主设备的物理基础：多个主设备同时驱动总线时不会发生电源短路（因为没有设备能主动输出高电平），而是自然地进行线与，低电平"胜出"。

## 多主仲裁机制

当多个主设备同时发起通信时，I2C 通过以下机制实现仲裁：

1. **线与避免冲突**：开漏输出保证多个主设备同时驱动总线不会造成物理损坏，总线电平是所有驱动者的线与结果。
2. **仲裁机制**：每个主设备在发送数据位的同时，回读 SDA 上的实际电平。如果自己发的是"1"（释放总线，期望高电平），但读到的是"0"（低电平），说明有另一个优先级更高的主设备在拉低总线，自己立即停止发送，退出竞争。
3. **从设备寻址**：每个从设备有唯一地址，主设备通过地址选择目标从设备，多个从设备可以共存于同一总线。

仲裁过程对从设备透明，从设备只会响应最终赢得总线的那个主设备。仲裁不会丢失任何数据，因为赢得仲裁的主设备从一开始就在正常发送。

## 上拉电阻的阻值计算

上拉电阻的阻值不是随便选的，它直接影响总线的信号质量和速度。

**上升时间公式**：

$$T_{rise} = 0.8473 \times R_{pull-up} \times C_{bus}$$

其中：

- $T_{rise}$：信号从低电平上升到高电平的时间（通常按 0.3VDD 到 0.7VDD 计算）
- $R_{pull-up}$：上拉电阻阻值
- $C_{bus}$：总线等效电容（包括引脚电容、PCB 走线电容、连接器电容等）

**阻值范围的约束**：

- **最小值限制**：电阻太小，当设备拉低总线时流过 MOSFET 的电流过大，可能超过器件的灌电流能力（通常最大 3mA），导致低电平电压升高。最小阻值约为 $R_{min} = (V_{DD} - V_{OL}) / I_{OL}$，典型值约 1kΩ。
- **最大值限制**：电阻太大，上升时间过长，不满足速度模式的上升时间要求。最大阻值由 $R_{max} = T_{rise(max)} / (0.8473 \times C_{bus})$ 决定。

| 速度模式 | 总线电容 | 推荐上拉电阻范围 |
|-|-|-|
| 标准模式 100KHz | ≤ 400 pF | 2.2kΩ \~ 10kΩ（常用 4.7kΩ） |
| 快速模式 400KHz | ≤ 400 pF | 1kΩ \~ 4.7kΩ（常用 2.2kΩ） |


::: tip

**工程经验**：大多数 STM32 开发板上 I2C 的上拉电阻用 4.7kΩ（标准模式）或 2.2kΩ（快速模式）。如果总线挂的设备多、线长、电容大，需要适当减小上拉电阻阻值。

:::


# I2C 协议层详解

## 起始条件（START）

起始条件标志着一次 I2C 通信的开始，由主设备发起。

**定义**：当 SCL 为高电平时，SDA 从高电平跳变为低电平（下降沿）。

**时序要求**：

- SDA 下降沿必须在 SCL 高电平期间发生。
- 起始条件前，SDA 和 SCL 都必须是高电平（总线空闲状态）。
- 建立时间（SDA 下降沿前 SCL 高电平的持续时间）≥ 4.7μs（标准模式）。

从设备持续监测 SDA 和 SCL，一旦检测到起始条件，就准备接收地址字节。

## 停止条件（STOP）

停止条件标志着一次 I2C 通信的结束，由主设备发起。

**定义**：当 SCL 为高电平时，SDA 从低电平跳变为高电平（上升沿）。

**时序要求**：

- SDA 上升沿必须在 SCL 高电平期间发生。
- 停止条件后，总线回到空闲状态（SDA 和 SCL 都为高）。
- 停止条件后需要至少 4.7μs 的总线空闲时间，才能发起下一次起始条件。

## 数据有效性

I2C 协议对 SDA 数据何时可以改变、何时必须稳定有严格规定：

- **SCL 高电平期间**：SDA 必须保持稳定，不能变化。接收方在 SCL 高电平期间采样 SDA。
- **SCL 低电平期间**：SDA 可以变化，发送方在 SCL 低电平期间更新下一位数据。

这个规则的唯一例外是起始条件和停止条件——它们正是在 SCL 高电平时改变 SDA，因此可以被唯一识别为控制信号而非数据。

## 字节传输格式

I2C 上的数据以字节（8 bit）为单位传输，**高位在前（MSB First）**。

每个字节传输后跟随一个**应答位（ACK/NACK）**，所以一个完整的字节传输实际上是 9 个时钟周期：8 个数据位 + 1 个应答位。

**传输顺序**：Bit7 → Bit6 → Bit5 → Bit4 → Bit3 → Bit2 → Bit1 → Bit0 → ACK/NACK

## 应答信号（ACK / NACK）

应答机制是 I2C 可靠性的核心，它让发送方知道接收方是否成功收到了字节。

**ACK（应答，Acknowledge）**：

- 接收方在第 9 个时钟周期将 SDA 拉低，表示"我收到了"。
- 发送方在第 9 个时钟周期读取 SDA，如果为低，则确认接收成功。

**NACK（非应答，Not Acknowledge）**：

- 接收方在第 9 个时钟周期释放 SDA（保持高电平），表示"我不想继续了"或"我没收到"。
- 主设备发送 NACK 通常表示"这是最后一个字节，读完就停止"。
- 从设备发送 NACK 通常表示"设备不存在"或"设备忙"。


::: tip

**常见错误**：主设备发送从机地址后，如果收到 NACK（SDA 为高），说明总线上没有这个地址的从设备，或者从设备没有正常响应。此时主设备应该发送停止条件并报错，而不是继续传输数据。

:::


## 重复起始条件（Repeated START）

重复起始条件是指在不发送停止条件的情况下，再次发送一个起始条件。它用于在同一次通信中切换通信方向（从写切换到读），而不释放总线。

**典型用途**：读 EEPROM 的过程——主设备先发送从机地址+写位，再发送要读的存储单元地址，然后发送重复起始条件，再发送从机地址+读位，最后读取数据。

重复起始条件的时序与普通起始条件完全相同，只是它发生在总线已经被占用的状态下，而不是空闲状态下。

## 完整的写操作时序

主设备向从设备写入 N 个字节的完整流程：

1. 主设备发送**起始条件**（START）。
2. 主设备发送**从机地址 + 写位（0）**（7位地址 + 1位R/W = 8位）。
3. 从设备返回**ACK**。
4. 主设备发送**数据字节 1**。
5. 从设备返回**ACK**。
6. ... 重复发送数据字节和接收 ACK ...
7. 主设备发送**数据字节 N**。
8. 从设备返回**ACK**。
9. 主设备发送**停止条件**（STOP）。

## 完整的读操作时序

主设备从从设备读取 N 个字节的完整流程：

1. 主设备发送**起始条件**（START）。
2. 主设备发送**从机地址 + 读位（1）**。
3. 从设备返回**ACK**。
4. 从设备发送**数据字节 1**。
5. 主设备返回**ACK**（表示还要继续读）。
6. ... 重复接收数据字节和发送 ACK ...
7. 从设备发送**数据字节 N**。
8. 主设备返回**NACK**（表示这是最后一个字节）。
9. 主设备发送**停止条件**（STOP）。


::: tip

**关键区别**：写操作中，ACK 由从设备发送；读操作中，ACK 由主设备发送。读操作的最后一个字节，主设备必须发送 NACK 而不是 ACK，否则从设备会继续发送下一个字节，导致总线冲突。

:::


## 时钟拉伸（Clock Stretching）

时钟拉伸是从设备的一种"暂停"机制：从设备在接收到数据后，如果需要时间处理（比如 EEPROM 正在写入内部存储），可以将 SCL 拉低，强制主设备等待。

主设备在产生 SCL 高电平之前会检测 SCL 是否真的变高了。如果 SCL 被从设备拉低，主设备就等待，直到从设备释放 SCL（SCL 变高），才继续下一个时钟周期。

时钟拉伸是 I2C 协议中从设备唯一能主动影响总线时序的机制。不是所有从设备都支持时钟拉伸，也不是所有主设备都能正确处理时钟拉伸（软件模拟 I2C 通常不支持）。

## 从机地址字节与通信场景全景

### 从机地址字节的构成

I2C 总线上传输的"地址字节"不是单纯的 7 位从机地址，而是 **7 位从机地址 + 1 位读/写方向位** 组成的 8 位字节。

**地址字节格式（MSB 在前）**：

| Bit7 | Bit6 | Bit5 | Bit4 | Bit3 | Bit2 | Bit1 | Bit0 (R/W) |
|-|-|-|-|-|-|-|-|
| A6 | A5 | A4 | A3 | A2 | A1 | A0 | 0=写, 1=读 |

**移位计算**：假设从机的 7 位地址为 0x50（二进制 1010000），则：

- **写地址字节**：(0x50 << 1) | 0x00 = 0xA0（二进制 10100000）
- **读地址字节**：(0x50 << 1) | 0x01 = 0xA1（二进制 10100001）


::: tip

**地址混淆陷阱**：很多资料和代码中直接写"从机地址 0xA0"，这实际上是**已经左移一位并包含写位的 8 位地址字节**，不是 7 位从机地址。7 位地址是 0x50。在使用 STM32 硬件 I2C 库函数时，`I2C_Send7bitAddress()` 函数的参数是 7 位地址（0x50），函数内部会自动左移并加上 R/W 位；而软件模拟 I2C 时通常直接发送 8 位地址字节（0xA0 / 0xA1）。两者不要搞混。

:::


### 应答信号的产生者

I2C 的应答信号（ACK/NACK）由谁产生，取决于当前的数据传输方向：

- **写操作（主机→从机）**：每发送一个字节后，**从机**产生 ACK/NACK。
- **读操作（从机→主机）**：每接收一个字节后，**主机**产生 ACK/NACK。读操作的最后一个字节，主机必须产生 NACK，通知从机停止发送。

因此，**NACK（非应答信号）只能由主机产生**——从机不会主动发送 NACK。如果主机发送地址后收到 NACK（SDA 为高），说明从机不存在或未响应。

### 总线空闲状态

**总线空闲（Bus Free / Idle）**的定义：SDA 和 SCL 同时为高电平。此时没有任何设备在驱动总线，主设备可以发起新的起始条件。

停止条件之后，总线需要至少 4.7μs（标准模式）的空闲时间，才能发起下一次起始条件。STM32 硬件 I2C 的 SR2 寄存器中 BUSY 位为 0 时，表示总线空闲。

### 通信场景的三维分类

I2C 的实际通信场景可以按三个维度分类，共 8 种典型组合：

| 编号 | 从机内部结构 | 方向 | 数据量 | 典型器件/说明 |
|-|-|-|-|-|
| 1 | 无寄存器/地址区分 | 读 | 单字节 | 简单传感器（如温度寄存器直接输出）、I/O 扩展器 |
| 2 | 无寄存器/地址区分 | 读 | 多字节 | 连续读取传感器数据、FIFO 型设备 |
| 3 | 无寄存器/地址区分 | 写 | 单字节 | DAC、简单 I/O 扩展器写命令 |
| 4 | 无寄存器/地址区分 | 写 | 多字节 | 连续写命令、配置流 |
| 5 | 有寄存器/地址区分 | 读 | 单字节 | AT24C02 随机读、传感器寄存器读 |
| 6 | 有寄存器/地址区分 | 读 | 多字节 | AT24C02 顺序读、传感器多寄存器连续读 |
| 7 | 有寄存器/地址区分 | 写 | 单字节 | AT24C02 字节写、传感器寄存器配置 |
| 8 | 有寄存器/地址区分 | 写 | 多字节 | AT24C02 页写、传感器批量配置 |

**"有无寄存器/地址区分"的本质区别**：

- **无寄存器的从机**：从机内部只有一个数据寄存器或直接是数据流，主机发送从机地址后直接读写数据，不需要先发送"寄存器地址"或"存储单元地址"。
- **有寄存器的从机**：从机内部有多个寄存器/存储单元，主机需要先发送一个"寄存器地址字节"（或称为"字地址"/"指针地址"），告诉从机要访问哪个内部单元，然后再进行数据读写。读操作需要用**重复起始条件**切换方向。

### 场景 1：无寄存器 — 读单字节

最简的读操作，主机直接读从机的当前输出值：

1. 主机发送 **起始条件**。
2. 主机发送 **从机读地址字节**（7位地址<<1 | 0x01），从机返回 ACK。
3. 从机发送 **1 个数据字节**。
4. 主机返回 **NACK**（表示不再继续读）。
5. 主机发送 **停止条件**。

时序简图：START → 地址+R(1) → ACK → 数据 → NACK → STOP

### 场景 2：无寄存器 — 读多字节

1. 主机发送 **起始条件**。
2. 主机发送 **从机读地址字节**，从机返回 ACK。
3. 从机发送 **数据字节 1**，主机返回 ACK（表示还要继续读）。
4. 从机发送 **数据字节 2**，主机返回 ACK。
5. ... 重复 ...
6. 从机发送 **最后一个数据字节 N**，主机返回 **NACK**。
7. 主机发送 **停止条件**。

时序简图：START → 地址+R → ACK → 数据1 → ACK → 数据2 → ACK → ... → 数据N → NACK → STOP

### 场景 3：无寄存器 — 写单字节（不考虑）

1. 主机发送 **起始条件**。
2. 主机发送 **从机写地址字节**（7位地址<<1 | 0x00），从机返回 ACK。
3. 主机发送 **1 个数据字节**，从机返回 ACK。
4. 主机发送 **停止条件**。

时序简图：START → 地址+W(0) → ACK → 数据 → ACK → STOP

### 场景 4：无寄存器 — 写多字节

1. 主机发送 **起始条件**。
2. 主机发送 **从机写地址字节**，从机返回 ACK。
3. 主机发送 **数据字节 1**，从机返回 ACK。
4. 主机发送 **数据字节 2**，从机返回 ACK。
5. ... 重复 ...
6. 主机发送 **最后一个数据字节 N**，从机返回 ACK。
7. 主机发送 **停止条件**。

时序简图：START → 地址+W → ACK → 数据1 → ACK → 数据2 → ACK → ... → 数据N → ACK → STOP

### 场景 5：有寄存器 — 读单字节（随机读）

这是最复杂的读操作，需要先用写操作设置内部地址指针，再用重复起始切换到读模式：

1. 主机发送 **起始条件**。
2. 主机发送 **从机写地址字节**，从机返回 ACK。
3. 主机发送 **寄存器地址字节**（要读取的内部单元地址），从机返回 ACK。
4. 主机发送 **重复起始条件**（不释放总线）。
5. 主机发送 **从机读地址字节**，从机返回 ACK。
6. 从机发送 **1 个数据字节**。
7. 主机返回 **NACK**。
8. 主机发送 **停止条件**。

时序简图：START → 地址+W → ACK → 寄存器地址 → ACK → ReSTART → 地址+R → ACK → 数据 → NACK → STOP

### 场景 6：有寄存器 — 读多字节（顺序读）

1. 主机发送 **起始条件**。
2. 主机发送 **从机写地址字节**，从机返回 ACK。
3. 主机发送 **起始寄存器地址字节**，从机返回 ACK。
4. 主机发送 **重复起始条件**。
5. 主机发送 **从机读地址字节**，从机返回 ACK。
6. 从机发送 **数据字节 1**，主机返回 ACK。
7. 从机发送 **数据字节 2**，主机返回 ACK。
8. ... 重复（从机内部地址指针自动递增）...
9. 从机发送 **最后一个数据字节 N**，主机返回 **NACK**。
10. 主机发送 **停止条件**。

时序简图：START → 地址+W → ACK → 寄存器地址 → ACK → ReSTART → 地址+R → ACK → 数据1 → ACK → ... → 数据N → NACK → STOP

### 场景 7：有寄存器 — 写单字节

1. 主机发送 **起始条件**。
2. 主机发送 **从机写地址字节**，从机返回 ACK。
3. 主机发送 **寄存器地址字节**，从机返回 ACK。
4. 主机发送 **1 个数据字节**，从机返回 ACK。
5. 主机发送 **停止条件**。

时序简图：START → 地址+W → ACK → 寄存器地址 → ACK → 数据 → ACK → STOP

### 场景 8：有寄存器 — 写多字节（页写）

1. 主机发送 **起始条件**。
2. 主机发送 **从机写地址字节**，从机返回 ACK。
3. 主机发送 **起始寄存器地址字节**，从机返回 ACK。
4. 主机发送 **数据字节 1**，从机返回 ACK。
5. 主机发送 **数据字节 2**，从机返回 ACK。
6. ... 重复（从机内部地址指针自动递增）...
7. 主机发送 **最后一个数据字节 N**，从机返回 ACK。
8. 主机发送 **停止条件**。

时序简图：START → 地址+W → ACK → 寄存器地址 → ACK → 数据1 → ACK → ... → 数据N → ACK → STOP


::: tip

**页写边界警告**：有寄存器的多字节写（页写）必须注意页边界。以 AT24C02 为例，页大小为 8 字节，如果写入起始地址不是页对齐且数据超过当前页剩余空间，地址会回绕到当前页开头，覆盖已有数据。跨页写入必须分页处理。

:::

# 软件 I2C（GPIO 模拟 IIC）

## 为什么需要软件 I2C

STM32 的硬件 I2C 外设存在一些历史问题（尤其是 F1 系列），例如：

- 硬件 I2C 在某些情况下会卡死（SB 位不置位、BUSY 位一直为 1）。
- 硬件 I2C 不支持某些非标准时序的从设备。
- 可用的硬件 I2C 引脚被其他功能占用，需要用任意 GPIO 模拟。
- 需要精确控制时序或实现特殊协议变体。

软件 I2C 的本质是：**用 GPIO 手动控制 SDA 和 SCL 的电平变化，按照 I2C 协议的时序要求模拟出起始、数据、应答、停止等信号**。

## GPIO 配置要求

软件 I2C 的 SDA 和 SCL 引脚需要配置为**开漏输出**模式（GPIO_Mode_Out_OD），这样才能模拟 I2C 的开漏物理层特性。

如果配置为推挽输出（Push-Pull），当主设备释放 SDA（想让从设备控制）时，推挽输出会主动驱动高电平，从设备无法拉低 SDA 来发送 ACK，导致通信失败。

**配置要点**：

- SDA：开漏输出 + 上拉（或外部上拉电阻），速度 50MHz。
- SCL：开漏输出 + 上拉（或外部上拉电阻），速度 50MHz。
- 不需要配置为输入模式，因为开漏输出在输出高电平时就是高阻态，可以直接读取输入寄存器获取引脚电平。

## 延时函数

软件 I2C 的时序由延时函数控制。标准模式 100KHz 的周期是 10μs，半周期是 5μs。实际中通常用 2\~5μs 的延时来控制 SCL 的高低电平时间。

```c
// 简单的微秒级延时（基于SysTick或空循环）
void I2C_Delay(void)
{
    uint8_t i = 10;
    while (i--);
}

// 更精确的延时（使用SysTick）
void I2C_Delay_us(uint32_t us)
{
    uint32_t start = SysTick->VAL;
    uint32_t ticks = us * (SystemCoreClock / 1000000);
    while ((start - SysTick->VAL) & 0xFFFFFF) < ticks);
}
```

## 起始条件模拟

```c
void I2C_Start(void)
{
    SDA_HIGH();   // 确保SDA为高
    SCL_HIGH();   // 确保SCL为高
    I2C_Delay();
    SDA_LOW();    // SCL高电平时，SDA下降沿 → 起始条件
    I2C_Delay();
    SCL_LOW();    // 拉低SCL，准备发送数据
    I2C_Delay();
}
```

## 停止条件模拟

```c
void I2C_Stop(void)
{
    SDA_LOW();    // 确保SDA为低
    SCL_HIGH();   // SCL拉高
    I2C_Delay();
    SDA_HIGH();   // SCL高电平时，SDA上升沿 → 停止条件
    I2C_Delay();
}
```

## 发送一个字节

```c
void I2C_SendByte(uint8_t byte)
{
    uint8_t i;
    for (i = 0; i < 8; i++)
    {
        // 高位在前，先发送bit7
        if (byte & 0x80)
            SDA_HIGH();
        else
            SDA_LOW();
        I2C_Delay();
        SCL_HIGH();       // SCL高电平期间，SDA稳定，从设备采样
        I2C_Delay();
        SCL_LOW();        // SCL低电平期间，可以改变SDA
        byte <<= 1;       // 左移一位，准备下一位
    }
    // 第9个时钟：等待ACK
    SDA_HIGH();           // 释放SDA，让从设备控制
    I2C_Delay();
    SCL_HIGH();
    I2C_Delay();
    // 读取SDA电平判断ACK（低=ACK，高=NACK）
    SCL_LOW();
    I2C_Delay();
}
```

## 读取一个字节

```c
uint8_t I2C_ReadByte(uint8_t ack)
{
    uint8_t i, byte = 0;
    SDA_HIGH();           // 释放SDA，让从设备发送数据
    for (i = 0; i < 8; i++)
    {
        byte <<= 1;
        SCL_HIGH();       // SCL高电平期间读取SDA
        I2C_Delay();
        if (SDA_READ())
            byte |= 0x01;
        SCL_LOW();
        I2C_Delay();
    }
    // 发送ACK或NACK
    if (ack)
        SDA_LOW();        // ACK：拉低SDA
    else
        SDA_HIGH();       // NACK：释放SDA
    I2C_Delay();
    SCL_HIGH();
    I2C_Delay();
    SCL_LOW();
    I2C_Delay();
    SDA_HIGH();           // 释放SDA
    return byte;
}
```

## 软件 I2C 的优缺点

| 对比项 | 软件 I2C | 硬件 I2C |
|-|-|-|
| 引脚选择 | 任意 GPIO，灵活 | 固定引脚（有重映射选项） |
| CPU 占用 | 高，全程需要 CPU 控制 | 低，硬件自动完成时序 |
| 速度 | 受限于 CPU 和延时精度，通常 ≤ 400KHz | 可稳定工作在 400KHz 甚至更高 |
| 时钟拉伸 | 通常不支持 | 硬件自动支持 |
| 稳定性 | 时序可控，不会卡死 | F1 系列有卡死风险，需要复位机制 |
| DMA | 不支持 | 支持，可大幅降低 CPU 占用 |

# AT24C02 EEPROM 芯片

## 芯片概述

AT24C02 是 Atmel（现为 Microchip）公司生产的 2Kbit（256 字节）串行 EEPROM 存储器，采用 I2C 接口，是嵌入式开发中最常用的非易失性存储芯片之一。

| 参数 | 值 |
|-|-|
| 存储容量 | 2Kbit = 256 字节 |
| 接口 | I2C，支持 100KHz / 400KHz |
| 工作电压 | 1.8V \~ 5.5V |
| 写周期时间 | 最大 5ms（内部写入时间） |
| 擦写次数 | 100 万次 |
| 数据保持时间 | 100 年 |
| 页大小 | 8 字节（AT24C02） |
| 封装 | SOP-8 / TSSOP-8 / DIP-8 |

## 引脚定义

| 引脚 | 名称 | 功能 |
|-|-|-|
| 1 | A0 | 地址位 0，硬件配置从机地址 |
| 2 | A1 | 地址位 1，硬件配置从机地址 |
| 3 | A2 | 地址位 2，硬件配置从机地址 |
| 4 | GND | 地 |
| 5 | SDA | I2C 数据线 |
| 6 | SCL | I2C 时钟线 |
| 7 | WP | 写保护，高电平时禁止写入，低电平时允许读写 |
| 8 | VCC | 电源 |

## 从机地址

AT24C02 的从机地址由 4 位固定前缀 + 3 位硬件地址（A2/A1/A0）+ 1 位 R/W 位组成：

**地址格式**：1 0 1 0 A2 A1 A0 R/W

当 A2/A1/A0 都接地（000）时，从机地址为：

- 写地址：0b10100000 = 0xA0
- 读地址：0b10100001 = 0xA1

通过 A2/A1/A0 引脚的不同接法，同一总线上最多可以挂 8 片 AT24C02（地址 0xA0\~0xAE）。


::: tip

**地址注意**：7 位地址是 0x50（0b1010000），写操作时左移一位变成 0xA0，读操作时变成 0xA1。很多代码中直接用 0xA0 作为写地址，这是已经包含了 R/W 位的 8 位格式，不要和 7 位地址混淆。

:::


## 字节写（Byte Write）

向指定地址写入一个字节：

1. 主设备发送起始条件。
2. 主设备发送从机写地址（0xA0），接收 ACK。
3. 主设备发送存储单元地址（0x00\~0xFF），接收 ACK。
4. 主设备发送数据字节，接收 ACK。
5. 主设备发送停止条件。
6. 等待内部写周期完成（最大 5ms）。

## 页写（Page Write）

AT24C02 的页大小是 8 字节，可以一次性写入最多 8 个连续字节，比逐字节写效率高得多。

1. 主设备发送起始条件。
2. 主设备发送从机写地址（0xA0），接收 ACK。
3. 主设备发送起始存储单元地址，接收 ACK。
4. 主设备连续发送最多 8 个数据字节，每个字节后接收 ACK。
5. 主设备发送停止条件。
6. 等待内部写周期完成（最大 5ms）。


::: tip

**页写回绕陷阱**：页写时，如果写入的起始地址不是页对齐的（不是 8 的倍数），且写入数据超过当前页剩余空间，地址会回绕到当前页的开头，覆盖已有数据！例如从地址 0x06 开始写 4 个字节，实际写入的地址是 0x06、0x07、0x00、0x01，而不是 0x06\~0x09。页写必须处理页边界。

:::


## 当前地址读（Current Address Read）

AT24C02 内部有一个地址计数器，记录上一次访问的地址 + 1。当前地址读不需要发送存储单元地址，直接读取地址计数器指向的单元：

1. 主设备发送起始条件。
2. 主设备发送从机读地址（0xA1），接收 ACK。
3. 从设备发送数据字节。
4. 主设备发送 NACK。
5. 主设备发送停止条件。

## 随机读（Random Read）

读取指定地址的一个字节，需要先用写操作设置内部地址计数器，再用读操作读取数据（这就是重复起始条件的典型应用）：

1. 主设备发送起始条件。
2. 主设备发送从机写地址（0xA0），接收 ACK。
3. 主设备发送存储单元地址，接收 ACK。
4. 主设备发送**重复起始条件**。
5. 主设备发送从机读地址（0xA1），接收 ACK。
6. 从设备发送数据字节。
7. 主设备发送 NACK。
8. 主设备发送停止条件。

## 顺序读（Sequential Read）

在随机读或当前地址读的基础上，主设备持续发送 ACK（而不是 NACK），从设备就会连续发送后续地址的数据，直到主设备发送 NACK 并停止：

1. 按随机读流程设置起始地址并读取第一个字节。
2. 主设备发送 ACK（表示还要继续读）。
3. 从设备发送下一个地址的数据。
4. ... 重复 ...
5. 读取最后一个字节后，主设备发送 NACK。
6. 主设备发送停止条件。

顺序读可以一次性读取整个 256 字节的存储空间，地址到 0xFF 后会回绕到 0x00。

# STM32 I2C 控制器原理

## 硬件架构概述

STM32 的 I2C 外设是一个完整的硬件 I2C 控制器，它在硬件层面实现了 I2C 协议的全部时序逻辑，CPU 只需要配置寄存器和读写数据寄存器，不需要手动控制每个时钟周期。

**主要组成部分**：

- **SDA/SCL 引脚控制**：开漏输出 + 输入采样，支持时钟拉伸检测。
- **时钟发生器**：根据 PCLK1 和配置的时钟频率自动产生 SCL 时钟。
- **移位寄存器**：并行数据 ↔ 串行数据的转换，MSB 在前。
- **数据寄存器（DR）**：CPU 与移位寄存器之间的缓冲。
- **地址寄存器（OAR1/OAR2）**：配置从模式下的自身地址。
- **控制寄存器（CR1/CR2）**：配置 I2C 的工作模式、使能、中断等。
- **状态寄存器（SR1/SR2）**：反映当前总线状态、事件标志、错误标志。
- **时钟控制寄存器（CCR）**：配置 SCL 时钟频率和占空比。
- **DMA 接口**：支持 DMA 方式传输数据，降低 CPU 占用。

## 关键寄存器

### CR1（控制寄存器 1）

- **PE（Peripheral Enable）**：I2C 外设使能位，置 1 使能 I2C。
- **START**：起始条件生成位，置 1 后硬件自动发送起始条件。
- **STOP**：停止条件生成位，置 1 后硬件自动发送停止条件。
- **ACK**：应答使能位，置 1 后在接收到字节后自动发送 ACK。
- **SWRST**：软件复位，用于在 I2C 卡死时复位整个外设。

### CR2（控制寄存器 2）

- **FREQ[5:0]**：外设时钟频率配置，必须写入 PCLK1 的频率值（MHz），用于内部时序计算。例如 PCLK1=36MHz 时写入 36。
- **ITEVTEN**：事件中断使能。
- **ITBUFEN**：缓冲区中断使能。
- **DMAEN**：DMA 请求使能。

### CCR（时钟控制寄存器）

- **CCR[11:0]**：时钟控制因子，SCL 频率 = PCLK1 / (2 × CCR)（标准模式）。例如 PCLK1=36MHz，要产生 100KHz，CCR = 36000000 / (2 × 100000) = 180。
- **DUTY**：快速模式下的占空比选择，0=16:9，1=2:1。
- **FS**：主模式选择，0=标准模式，1=快速模式。

### SR1（状态寄存器 1）

- **SB（Start Bit）**：起始条件已发送，读 SR1 后写 DR 清除。
- **ADDR（Address Sent）**：地址已发送（主模式）或地址匹配（从模式），读 SR1 后读 SR2 清除。
- **BTF（Byte Transfer Finished）**：字节传输完成，数据寄存器和移位寄存器都空了（发送）或都满了（接收）。
- **RXNE（Receive Buffer Not Empty）**：接收缓冲区非空，可以读 DR。
- **TxE（Transmit Buffer Empty）**：发送缓冲区空，可以写 DR。
- **AF（Acknowledge Failure）**：应答失败，收到 NACK。
- **BERR（Bus Error）**：总线错误，检测到非法的起始或停止条件。
- **ARLO（Arbitration Lost）**：仲裁丢失（多主模式）。

### SR2（状态寄存器 2）

- **MSL（Master/Slave）**：主/从模式标志，1=主模式，0=从模式。
- **BUSY（Bus Busy）**：总线忙标志，1=总线正在通信中。
- **TRA（Transmitter/Receiver）**：发送/接收方向，1=发送，0=接收。

## 主模式发送流程

STM32 作为主设备发送数据的完整流程（轮询方式）：

1. 等待 BUSY=0（总线空闲）。
2. 置 CR1 的 START=1，发起起始条件。
3. 等待 SB=1（起始条件已发送）。
4. 写 DR = 从机地址 + 写位（0）。
5. 等待 ADDR=1（地址已发送并收到 ACK）。
6. 读 SR1，再读 SR2，清除 ADDR 标志。
7. 等待 TxE=1（发送缓冲区空）。
8. 写 DR = 第一个数据字节。
9. 等待 BTF=1（字节传输完成）。
10. 写 DR = 下一个数据字节。
11. ... 重复直到所有数据发送完毕 ...
12. 等待 BTF=1。
13. 置 CR1 的 STOP=1，发送停止条件。

## 主模式接收流程

STM32 作为主设备接收数据的完整流程（轮询方式）：

1. 等待 BUSY=0。
2. 置 ACK=1（使能应答）。
3. 置 START=1，发起起始条件。
4. 等待 SB=1。
5. 写 DR = 从机地址 + 读位（1）。
6. 等待 ADDR=1。
7. 读 SR1，再读 SR2，清除 ADDR。
8. **如果只接收 1 个字节**：在清除 ADDR 后立即置 ACK=0，然后置 STOP=1，等待 RXNE=1，读 DR。
9. **如果接收 N 个字节（N>1）**：等待 RXNE=1，读 DR（第 1 个字节），重复直到剩最后 2 个字节；当 BTF=1 时（倒数第 2 个字节已收到），置 ACK=0，置 STOP=1，读 DR（倒数第 2 个），等待 RXNE=1，读 DR（最后 1 个）。


::: tip

**单字节接收的特殊处理**：接收 1 个字节时，必须在 ADDR 清除之后、字节接收完成之前关闭 ACK（ACK=0）并设置 STOP。如果等 RXNE=1 再关 ACK，就已经太晚了——硬件已经在第 9 个时钟发送了 ACK，从设备会继续发送下一个字节，导致总线冲突。这是 STM32 I2C 最容易出错的地方之一。

:::


## I2C 卡死问题与复位

STM32F1 系列的硬件 I2C 有一个著名的问题：在某些异常情况下（如从设备异常复位、电磁干扰导致时序错乱），I2C 会进入卡死状态，表现为 BUSY 位一直为 1，SB 位无法置位，通信完全失败。

**标准复位流程**：

```c
void I2C_Reset(I2C_TypeDef *I2Cx)
{
    // 1. 关闭 I2C 外设
    I2Cx->CR1 &= ~I2C_CR1_PE;
    // 2. 将 SDA/SCL 配置为通用开漏输出，手动模拟 9 个时钟
    //    （解锁可能被从设备拉低的 SDA）
    GPIO_InitTypeDef GPIO_InitStructure;
    GPIO_InitStructure.GPIO_Pin = SCL_PIN | SDA_PIN;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_Out_OD;
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(SCL_PORT, &GPIO_InitStructure);

    for (uint8_t i = 0; i < 9; i++) {
        SCL_HIGH();
        delay_us(5);
        SCL_LOW();
        delay_us(5);
    }
    // 3. 重新配置为 I2C 复用开漏功能
    // 4. 重新使能 I2C 外设
    I2Cx->CR1 |= I2C_CR1_PE;
}
```

在实际项目中，建议在每次 I2C 操作前检查 BUSY 位，如果超时则执行上述复位流程。

## I2C 初始化配置

```c
void I2C1_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    I2C_InitTypeDef I2C_InitStructure;

    // 1. 使能时钟
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOB, ENABLE);
    RCC_APB1PeriphClockCmd(RCC_APB1Periph_I2C1, ENABLE);

    // 2. 配置 PB6(SCL) PB7(SDA) 为复用开漏输出
    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_6 | GPIO_Pin_7;
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_OD;  // 复用开漏
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz;
    GPIO_Init(GPIOB, &GPIO_InitStructure);

    // 3. 配置 I2C1
    I2C_InitStructure.I2C_Mode = I2C_Mode_I2C;          // I2C 模式
    I2C_InitStructure.I2C_DutyCycle = I2C_DutyCycle_2;  // 占空比 2:1
    I2C_InitStructure.I2C_OwnAddress1 = 0x00;            // 自身地址（主模式用不到）
    I2C_InitStructure.I2C_Ack = I2C_Ack_Enable;          // 使能应答
    I2C_InitStructure.I2C_AcknowledgedAddress = I2C_AcknowledgedAddress_7bit; // 7位地址
    I2C_InitStructure.I2C_ClockSpeed = 100000;           // 100KHz 标准模式
    I2C_Init(I2C1, &I2C_InitStructure);

    // 4. 使能 I2C1
    I2C_Cmd(I2C1, ENABLE);
}
```

## 写一个字节到 AT24C02

```c
#define AT24C02_ADDR_WRITE  0xA0
#define AT24C02_ADDR_READ   0xA1

void AT24C02_WriteByte(uint8_t addr, uint8_t data)
{
    // 等待总线空闲
    while (I2C_GetFlagStatus(I2C1, I2C_FLAG_BUSY));

    // 1. 发送起始条件
    I2C_GenerateSTART(I2C1, ENABLE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT)); // 等待 SB

    // 2. 发送从机写地址
    I2C_SendData(I2C1, AT24C02_ADDR_WRITE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED)); // 等待 ADDR

    // 3. 发送存储单元地址
    I2C_SendData(I2C1, addr);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTING)); // 等待 TxE

    // 4. 发送数据
    I2C_SendData(I2C1, data);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTED)); // 等待 BTF

    // 5. 发送停止条件
    I2C_GenerateSTOP(I2C1, ENABLE);

    // 6. 等待内部写周期完成（最大5ms）
    delay_ms(5);
}
```

## 从 AT24C02 读一个字节

```c
uint8_t AT24C02_ReadByte(uint8_t addr)
{
    uint8_t data;

    while (I2C_GetFlagStatus(I2C1, I2C_FLAG_BUSY));

    // 1. 发送起始条件
    I2C_GenerateSTART(I2C1, ENABLE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT));

    // 2. 发送从机写地址（用于设置内部地址指针）
    I2C_SendData(I2C1, AT24C02_ADDR_WRITE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED));

    // 3. 发送存储单元地址
    I2C_SendData(I2C1, addr);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTED));

    // 4. 发送重复起始条件
    I2C_GenerateSTART(I2C1, ENABLE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT));

    // 5. 发送从机读地址
    I2C_SendData(I2C1, AT24C02_ADDR_READ);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED));

    // 6. 单字节接收：关闭 ACK，发送 STOP
    I2C_AcknowledgeConfig(I2C1, DISABLE);  // ACK=0
    I2C_GenerateSTOP(I2C1, ENABLE);         // STOP=1

    // 7. 等待接收完成
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_RECEIVED));
    data = I2C_ReceiveData(I2C1);

    // 8. 重新使能 ACK（为下一次通信做准备）
    I2C_AcknowledgeConfig(I2C1, ENABLE);

    return data;
}
```

## 连续读多个字节

```c
void AT24C02_ReadBuffer(uint8_t addr, uint8_t *buf, uint8_t len)
{
    while (I2C_GetFlagStatus(I2C1, I2C_FLAG_BUSY));

    // 设置内部地址指针（写操作）
    I2C_GenerateSTART(I2C1, ENABLE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT));
    I2C_SendData(I2C1, AT24C02_ADDR_WRITE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_TRANSMITTER_MODE_SELECTED));
    I2C_SendData(I2C1, addr);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_TRANSMITTED));

    // 重复起始，切换到读模式
    I2C_GenerateSTART(I2C1, ENABLE);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_MODE_SELECT));
    I2C_SendData(I2C1, AT24C02_ADDR_READ);
    while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_RECEIVER_MODE_SELECTED));

    // 接收 len 个字节
    while (len)
    {
        if (len == 1)
        {
            // 最后一个字节：关闭 ACK，发送 STOP
            I2C_AcknowledgeConfig(I2C1, DISABLE);
            I2C_GenerateSTOP(I2C1, ENABLE);
        }
        // 等待接收完成
        while (!I2C_CheckEvent(I2C1, I2C_EVENT_MASTER_BYTE_RECEIVED));
        *buf++ = I2C_ReceiveData(I2C1);
        len--;
    }

    // 重新使能 ACK
    I2C_AcknowledgeConfig(I2C1, ENABLE);
}
```

## 常见问题与调试技巧

| 问题现象 | 可能原因 | 解决方法 |
|-|-|-|
| BUSY 位一直为 1，无法通信 | I2C 总线卡死，从设备拉低 SDA | 执行软件复位流程，手动发 9 个时钟解锁 SDA |
| 发送地址后收到 NACK（AF=1） | 从机地址错误、从设备未上电、SDA/SCL 接反 | 用示波器测量 SDA/SCL，检查地址、电源、接线 |
| 写入数据后读出全 0xFF | WP 引脚为高（写保护使能）、写周期未完成就读取 | WP 接地，写操作后延时 5ms 再读 |
| 读出数据不正确，有位错误 | 上拉电阻过大、总线电容过大、速度过快 | 减小上拉电阻（4.7k→2.2k），降低速度到 100KHz |
| 多字节读最后一个字节错误 | 最后一个字节前没有正确发送 NACK | 确保在接收最后一个字节前 ACK=0 且 STOP=1 |
| 页写数据覆盖了其他地址 | 写入跨越了页边界，地址回绕 | 分页写入，每页起始地址对齐到 8 的倍数 |


::: tip

**调试利器**：调试 I2C 最有效的工具是逻辑分析仪（Logic Analyzer）。它可以抓取 SDA 和 SCL 的波形，自动解码出起始条件、地址、数据、ACK/NACK、停止条件，一眼就能看出问题出在哪一步。常用的有 Saleae、Kingst LA1010 等，价格从几十到几百元不等。

:::

## 面试高频问题

1. **I2C 和 SPI 的区别？** I2C 是 2 线、半双工、有地址、支持多主、开漏输出；SPI 是 4 线（+片选）、全双工、无地址、单主（通常）、推挽输出。I2C 速度较低但引脚少、可挂载设备多；SPI 速度高但引脚多。
2. **I2C 为什么需要上拉电阻？** 因为 I2C 引脚是开漏输出，只能拉低不能拉高，必须靠上拉电阻提供高电平。同时上拉电阻和总线电容决定上升时间，影响最高通信速度。
3. **I2C 的起始和停止条件是什么？** 起始：SCL 高电平时 SDA 下降沿；停止：SCL 高电平时 SDA 上升沿。数据传输时 SCL 高电平期间 SDA 不能变化，因此起始/停止条件可以被唯一识别。
4. **什么是时钟拉伸？** 从设备在需要处理时间时拉低 SCL，强制主设备等待。主设备在产生 SCL 高电平前检测 SCL 是否真的变高，如果被拉低就等待。
5. **STM32 硬件 I2C 为什么会卡死？怎么解决？** F1 系列硬件 I2C 在异常时序下可能 BUSY 位一直为 1。解决方法：软件复位 I2C 外设，将 SCL/SDA 配置为 GPIO 手动发 9 个时钟解锁从设备，再重新配置为 I2C 功能。
6. **AT24C02 页写需要注意什么？** 页大小 8 字节，写入不能跨越页边界，否则地址回绕覆盖当前页开头的数据。跨页写入需要分页处理。
