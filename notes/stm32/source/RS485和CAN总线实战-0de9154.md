# RS485总线专题

## RS485总线介绍

### 什么是 RS485

RS485（EIA-485 标准）是一种基于差分平衡传输的串行通信物理层标准。它只规定电气特性（电平、阻抗、驱动能力），不规定上层协议，因此可以承载 Modbus、Profibus 或自定义协议，是工业现场总线中最常用的有线通信方式之一。

RS485 使用 A、B 两根差分信号线，靠两线之间的电压差表示逻辑电平，而不是像 RS232 那样以“对地电压”表示，因此天然具备共模干扰抑制能力，适合工业环境下的远距离、多设备组网。

### 差分信号与逻辑电平

接收端以 A、B 两线的电压差 UAB = VA − VB 判定逻辑电平：

- 逻辑 1：UAB ≥ +200 mV（典型：A=+3.5V，B=+1.5V）
- 逻辑 0：UAB ≤ −200 mV（典型：A=+1.5V，B=+3.5V）
- 两线差值在 −200 mV \~ +200 mV 之间属于不确定区，应避免


::: tip

差分信号的优势：外部干扰会同时叠加在 A、B 两根线上，两线差值基本不变（共模抑制），接收端只识别差值，因此抗干扰能力强、传输距离远。

:::


| 对比项 | RS232 | RS422 | RS485 |
|-|-|-|-|
| 信号方式 | 单端（对地） | 差分 | 差分 |
| 典型距离 | 约 15 米 | 约 1200 米 | 约 1200 米 |
| 节点数 | 1 对 1 | 1 主多从（接收多） | 多对多（典型 32 节点） |
| 通信方式 | 全双工 | 全双工 | 半双工（4 线接法可全双工） |
| 逻辑电平 | ±3 \~ ±15V | 差分 ±2 \~ ±6V | 差分 ±1.5 \~ ±5V |

### RS485 组网特点

- 远距离通信：典型可达 1200 米（与速率和线缆质量相关）
- 多设备组网：单条总线可挂多个设备，典型 32 个（使用低负载芯片可扩展更多）
- 抗干扰能力强：差分传输有效抵抗共模干扰，适合工业复杂电磁环境
- 双向半双工通信：支持双向数据传输，同一时刻只能一个方向，需控制方向切换
- 布线成本低：仅需一对双绞线（A、B）和参考地线，布线简单、经济可靠

### 典型组网结构与布线要点

- 一主多从：主站（Master）发起通信，从站（Slave）响应，设备地址需唯一
- 总线采用手拉手（菊花链）连接，避免星型连接
- 总线两端各接入一个 120Ω 终端电阻，跨接在 A 与 B 之间，减少信号反射、提升通信稳定性
- 使用屏蔽双绞线，屏蔽层单端接地；参考地 GND 独立
- 合理控制支线长度（建议 ≤0.3 米）；尽量远离强电电缆和干扰源

### 常用器件与电平转换

MCU 的 UART 输出的是 TTL 单端电平，不能直接接入 RS485 总线，需要 RS485 收发器完成 TTL ↔ 差分电平转换：

- MAX485 / SP485 / ISL83485 等半双工收发器芯片（带 DE 发送使能、RE 接收使能）
- USB 转 RS485 适配器（PC 调试用）
- RS232 转 RS485 转换器（兼容老设备）

### 常见应用场景

- 工业自动化控制系统（PLC、HMI 组网）
- 楼宇自控与安防系统
- 能源监控与电力系统
- 传感器与仪表数据采集（温湿度、电量、流量、压力等）

## RS485通信实验

### 实验目的与器材

验证 RS485 半双工差分通信：掌握 TTL 电平到差分电平的转换、总线接线与终端匹配，以及 DE/RE 方向控制方法。

- USB 转 RS485 适配器 ×1（连接 PC）
- RS485 收发模块（MAX485 等）×2
- STM32 / Arduino 开发板 ×2（或 1 块开发板 + PC）
- 双绞线（A、B、GND）与 120Ω 终端电阻
- 串口调试助手 / 逻辑分析仪

### 接线方法

- A 接 A，B 接 B，GND 接 GND（参考地必须共地）
- 总线两端各接 120Ω 终端电阻（跨接 A-B）
- 模块 RO 接 MCU RX、DI 接 MCU TX，DE/RE 并联后由 GPIO 控制方向
- DE/RE 为高电平进入发送模式；DE/RE 为低电平进入接收模式（注意 RE 为低电平有效）

### 实验步骤

1. 环回测试：单节点发送数据并自收，验证 UART 与转换链路是否正常
2. 双机通信：开发板 A 发送帧，开发板 B 接收并回显，验证差分传输
3. 干扰测试：加长线缆或靠近电机运行，观察误码，验证终端电阻与屏蔽接地的效果

### 示例代码（方向控制要点）

```c
// 发送前拉高 DE/RE 进入发送模式
RS485_DE_HIGH();
HAL_UART_Transmit(&huart2, buf, len, 100);
// 发送完成后拉低 DE/RE 回到接收模式
RS485_DE_LOW();
HAL_UART_Receive(&huart2, rx, rx_len, 1000);
```


::: tip

半双工必须严格“先切方向、再收发”。发送完成后要留出总线释放时间（一般不少于 1 个字节时间）再切回接收，否则会撞车或丢失首字节。

:::


### 调试工具推荐

- 串口调试助手：直接查看 HEX 收发帧，对比请求与响应
- 逻辑分析仪：抓取 A-B 差分波形与 UART 时序，定位起始位、停止位和空闲态
- USB 转 RS485 适配器：PC 直接挂到总线上监听
- Modbus Poll / Modbus Slave：协议层调试工具

### 故障排查清单

- 通信速率越高，传输距离越短，需合理权衡
- 设备地址需唯一，避免地址冲突
- 信号异常时，优先检查接线、A-B 终端电阻和参考地线
- 推荐使用标准通信协议（如 Modbus RTU）以提高兼容性
- 检查半双工方向切换时序，避免首字节丢失

## Modbus协议

### Modbus 简介

- Modbus 是由 Modicon（现施耐德电气）提出的通信协议
- 基于主从（Master/Slave）架构，主站发起请求，从站响应
- 支持 RTU（串口）和 ASCII 两种传输模式，工业中 RTU 更常用
- 开放免费、易于实现，常用于 PLC、传感器、变频器、仪表等设备通信

### Modbus RTU 数据帧结构

| 地址（1 字节） | 功能码（1 字节） | 数据域（N 字节） | CRC16（2 字节） |
|-|-|-|-|
| 1\~247（0 为广播地址，不返回） | 定义操作类型 | 具体的操作数据 | 低字节在前，高字节在后 |

RTU 帧内字节间不能停顿，帧与帧之间空闲时间 ≥ 3.5 个字符时间，用于从站判断一帧结束。

### 常用功能码

| 功能码 | 名称 | 说明 | 读/写 |
|-|-|-|-|
| 01（0x01） | 读取线圈状态 | 读单个/多个线圈（开关量） | 读 |
| 02（0x02） | 读取离散输入 | 读单个/多个离散输入（开关量） | 读 |
| 03（0x03） | 读取保持寄存器 | 读单个/多个保持寄存器（模拟量） | 读 |
| 04（0x04） | 读取输入寄存器 | 读单个/多个输入寄存器（模拟量） | 读 |
| 05（0x05） | 写单个线圈 | 写单个线圈（开关） | 写 |
| 06（0x06） | 写单个寄存器 | 写单个保持寄存器 | 写 |
| 15（0x0F） | 写多个线圈 | 写多个线圈（开关） | 写 |
| 16（0x10） | 写多个寄存器 | 写多个保持寄存器 | 写 |

### 通信流程

1. 主站发送请求帧（地址 + 功能码 + 数据 + CRC）
2. 从站校验地址与 CRC，匹配后返回响应帧
3. 主站校验并处理数据

异常时从站返回异常帧：功能码最高位置 1（功能码 + 0x80），并附带异常码，如 01 非法功能、02 非法数据地址、03 非法数据值。

### 寄存器模型

Modbus 将数据分为四类：线圈（可读写位）、离散输入（只读位）、保持寄存器（可读写字）、输入寄存器（只读字）。功能码 01/02 操作位，03/04 操作字，05/06/0F/10 用于写操作。

### 实例：温湿度传感器寄存器表

| 寄存器地址 | 内容 | 操作 | 定义说明 |
|-|-|-|-|
| 0000H | 含水率 | 只读 | 含水率实时值（扩大 10 倍） |
| 0001H | 温度值 | 只读 | 温度实时值（扩大 10 倍） |
| 0050H | 温度校准值 | 读写 | 整数（扩大 10 倍） |
| 0051H | 含水率校准值 | 读写 | 整数（扩大 10 倍） |
| 07D0H | 设备地址 | 读写 | 1\~254（出厂默认 1） |
| 07D1H | 设备波特率 | 读写 | 0=2400，1=4800，2=9600 |


::: tip

注意寄存器地址换算：协议帧中的起始地址以 0 为基准；部分厂家说明书写的是寄存器编号（从 1 开始），需要减 1 才是帧内地址，具体以设备说明书为准。

:::


## Modbus通信实验

### 实验目标

通过 PC 串口助手或 Modbus Poll，使用功能码 03 读取 RS485 温湿度传感器的温度寄存器，验证“请求帧 → 响应帧 → 数据解析”全流程。

### 读取保持寄存器实例（功能码 03）

场景：读取从站地址为 0x01 的温湿度传感器的温度值（寄存器地址 0x0001，1 个寄存器）。

**主站请求帧：**01 03 00 01 00 01 D5 CA

| 从站地址 | 功能码 | 起始地址高字节 | 起始地址低字节 | 寄存器数量高字节 | 寄存器数量低字节 | CRC16 |
|-|-|-|-|-|-|-|
| 01 | 03 | 00 | 01 | 00 | 01 | D5 CA |

帧含义：从站地址 01 + 功能码 03（读保持寄存器）+ 起始地址 0x0001 + 寄存器数量 0x0001（1 个）+ CRC16 校验 D5 CA。

**从站响应帧：**01 03 02 01 2C B8 09

| 从站地址 | 功能码 | 字节数 | 数据高字节 | 数据低字节 | CRC16 |
|-|-|-|-|-|-|
| 01 | 03 | 02 | 01 | 2C | B8 09 |

**数据解释：**0x012C = 300（十进制），根据传感器说明书，温度 = 300 / 10 = 30.0°C。


::: tip

课件中该响应帧 CRC 标注为 39 84，经标准 Modbus CRC16（多项式 0xA001）核算应为 B8 09（低字节在前），此处以核算结果为准。

:::


### CRC16 校验算法

RTU 模式采用 CRC16（多项式 0x8005 的反射形式 0xA001，初值 0xFFFF），校验范围覆盖地址 + 功能码 + 数据域（不含 CRC 本身），发送时低字节在前、高字节在后。

```c
uint16_t crc16(uint8_t *p, uint8_t len) {
    uint16_t crc = 0xFFFF;
    while (len--) {
        crc ^= *p++;
        for (int i = 0; i < 8; i++) {
            crc = (crc & 1) ? (crc >> 1) ^ 0xA001 : crc >> 1;
        }
    }
    return crc; // 发送时低字节在前
}
```

### 上位机实验步骤（Modbus Poll）

1. USB 转 RS485 连接传感器，串口参数 9600-8-N-1
2. Modbus Poll 新建连接：从站地址 1，功能码 03
3. 读取起始地址 0x0001、长度 1，观察返回温度值并换算（×0.1）
4. 使用功能码 06 写 07D0H（设备地址）与 07D1H（波特率）寄存器，验证写操作

### 常见问题排查

- 超时无响应：检查从站地址、波特率、A/B 接线与终端电阻
- CRC 错误：确认 CRC 低字节在前，帧间空闲时间 ≥ 3.5 字符
- 数据异常：核对寄存器地址换算与数据放大倍数（×10）
- 修改地址/波特率后需重启设备并重新连接对应参数

# CAN总线专题

## CAN总线基础

### 什么是 CAN 总线

CAN（Controller Area Network，控制器局域网）是一种**多主、异步、半双工**的串行通信总线协议，由德国 Bosch 公司在 20 世纪 80 年代推出，最初用于汽车电子通信。它是工业控制、汽车电子等领域最重要、应用最广泛的现场总线之一。

- 高可靠性：具备差错检测、自动重发机制，抗电磁干扰能力强
- 实时性好：基于优先级的总线仲裁，满足实时控制需求
- 多主节点：任意节点均可主动发送数据，无需中心主站
- 组网灵活：只需 CAN_H、CAN_L 两根信号线即可构建多节点通信网络

### CAN 发展历史

- 1983 年：Bosch 公司为解决汽车电子控制单元（ECU）之间的通信问题，开发出 CAN 协议
- 1986 年：CAN 2.0 发布（标准帧 11 位 ID、扩展帧 29 位 ID），成为国际标准 ISO 11898
- 1990 年代：在汽车工业大规模应用，成为车载网络事实标准，广泛用于发动机、ABS、气囊等系统
- 2003 年：CAN FD（Flexible Data-Rate）发布，支持更高数据速率（最高 5 Mbps）
- 2012 年至今：CAN XL 等新规范持续演进，在汽车、工业、能源、机器人等领域不断拓展

| 协议版本 | 处理能力 |
|-|-|
| CAN 2.0A | 只能处理标准数据帧，将扩展帧内容识别为错误 |
| CAN 2.0B Active | 能够同时正确处理标准数据帧和扩展数据帧 |
| CAN 2.0B Passive | 只能处理标准数据帧，直接忽略扩展帧内容 |

### 拓扑结构与布线建议

CAN 总线采用**多主、线性总线**拓扑：所有节点并联在两根差分信号线（CAN_H、CAN_L）上，通过终端电阻实现信号完整性。

- 多主并联：所有节点平等接入，任意节点均可发送数据
- 差分传输：CAN_H 与 CAN_L 差分信号抗干扰能力强
- 终端匹配：总线两端各接 120Ω 终端电阻（高速总线），减少信号反射
- 线性总线：推荐菊花链连接，支线尽量短，减少信号失真
- 采用菊花链连接：节点按顺序接入主干线，避免星型连接
- 控制支线长度：支线尽量短，建议不超过 0.3 m
- 正确配置终端电阻：高速总线两端接 120Ω，中低速接 2.2kΩ
- 使用双绞线：采用双绞屏蔽线，保证差分信号质量
- 接地与屏蔽：合理接地与屏蔽，提升抗干扰能力

### 物理层与信号特征

CAN 物理层分两类标准：

- ISO 11898（High Speed，25k \~ 1Mbps）：闭环总线结构，两端各接 120Ω 终端电阻，抗干扰能力强，适用于汽车动力、底盘控制等实时性要求极高的场景
- ISO 11519-2（Low Speed，10k \~ 125kbps）：开环总线结构，各节点独立配置匹配电阻（如 2.2kΩ），具备较强容错与断线恢复能力，适用于车身舒适系统等低速场景

**显性 / 隐性电平：**

- 显性（Dominant）= 逻辑 0，代表高优先级：收发器主动驱动总线，使 CAN_H 升高、CAN_L 降低，产生明显压差
- 隐性（Recessive）= 逻辑 1，代表低优先级：收发器不驱动（高阻态），两线电压被匹配电阻拉至相近电平


::: tip

线与机制（Wired-AND）：当多个节点同时发送时，显性信号（0）会自动物理覆盖隐性信号（1），以此实现非破坏性的总线仲裁。

:::


| 物理层参数 | ISO 11898（高速） | ISO 11519-2（低速） |
|-|-|-|
| 通信速度 | 最高 1 Mbps | 最高 125 kbps |
| 总线拓扑 | 闭环总线（终端匹配 120Ω） | 开环总线（节点独立匹配 2.2kΩ） |
| 隐性电平（CAN_H / CAN_L） | 2.5V / 2.5V，压差 0V | 1.75V / 3.25V，压差 −1.5V |
| 显性电平（CAN_H / CAN_L） | 3.5V / 1.5V，压差 2.0V | 4.0V / 1.0V，压差 3.0V |
| 线缆阻抗 | 120Ω（Min 85Ω，Max 130Ω） | 无严格要求，通常使用双绞线 |

**通信速率与总线长度关系：**速率越高，允许的总线长度越短。典型对应：1000 m @ 40 kbps，400 m @ 100 kbps，40 m @ 1 Mbps。

### CAN 与具身智能的应用场景

具身智能（Embodied AI）强调智能体通过感知、决策与执行和物理世界持续交互，对底层通信的实时性与可靠性要求很高。CAN 以其高可靠、实时、分布式的特性成为机器人物理侧网络的理想选择。

- 机器人关节控制：连接伺服驱动器、编码器等，实现多关节高实时协同控制
- 多源传感器接入：连接力传感器、IMU、激光雷达等，构建稳定的感知网络
- 移动底盘控制：用于 AGV/AMR 等移动机器人，实现电机、转向、制动等安全可靠的实时通信
- 能源与安全管理：电池管理、急停等关键模块通过 CAN 传输，保障系统安全

## CAN总线帧的种类

### 五种帧类型概览

CAN 总线共有 5 种基本帧：

- 数据帧（Data Frame）：发送节点向接收节点传送数据，最常用、最核心，分为标准帧（11 位 ID）与扩展帧（29 位 ID）
- 遥控帧（Remote Frame）：接收节点向具有相同 ID 的发送节点请求发送数据
- 错误帧（Error Frame）：任何节点检测到总线错误时发出，刻意打破位填充规则，破坏当前数据传输并通知所有节点
- 过载帧（Overload Frame）：接收节点尚未准备好接收新数据时，向总线发送过载信号，请求发送节点延迟发送
- 帧间隔（Interframe Space）：将数据帧或遥控帧与前面的任何帧隔开，强制提供总线空闲时间，确保节点有时间处理上一帧

### 数据帧格式（标准帧与扩展帧）

标准格式宏观结构：起始 1 位 + 仲裁段 12 位 + 控制段 6 位 + 数据段 0\~64 位 + CRC 段 16 位 + ACK 2 位 + 结束 7 位；扩展格式的扩展仲裁段为 32 位，其余段与标准格式相同。

| 位域 | 标准帧 | 扩展帧 |
|-|-|-|
| 帧起始 SOF | 1 位，显性 | 1 位，显性 |
| 仲裁段 | ID 11 位 + RTR 1 位 | SRR 1 位 + IDE 1 位 + ID 18 位 + r1 1 位 + RTR 1 位 |
| 控制段 | IDE 1 位 + r0 1 位 + DLC 4 位 | r1 1 位 + r0 1 位 + DLC 4 位 |
| 数据段 | 0\~64 位（最多 8 字节） | 0\~64 位（最多 8 字节） |
| CRC 段 | CRC 15 位 + DEL 1 位 | CRC 15 位 + DEL 1 位 |
| ACK | ACK 1 位 + ACK 界定符 1 位 | ACK 1 位 + ACK 界定符 1 位 |
| 帧结束 EOF | 7 位隐性 | 7 位隐性 |

### 遥控帧

- 遥控帧用于接收节点向发送节点请求数据，结构类似数据帧，但**没有数据段**，且 RTR 位为隐性（1）
- 即便数据帧长度为 0（没有数据段），数据帧和遥控帧依然可通过 RTR 位的显隐性严格区分
- 遥控帧的数据长度码（DLC），必须以所请求对应数据帧的数据长度码来表示
- 无数据段的数据帧用途：网络中各单元定期连接确认/应答（心跳检测）；或仲裁段本身带有实质性信息时（通过 ID 直接传达命令或状态）

### 错误帧、过载帧与帧间隔

| 帧类型 | 构成 | 作用 |
|-|-|-|
| 错误帧 | 错误标志 6 位（主动/被动）+ 错误界定符 8 位（隐性） | 通知其他节点总线发生错误 |
| 过载帧 | 过载标志 6 位（显性）+ 过载界定符 8 位（隐性） | 接收节点请求发送节点延迟发送 |
| 帧间隔 | 间歇段 3 位（隐性）+ 总线空闲（长度任意） | 分隔帧并提供总线空闲时间 |

错误标志分为“主动错误标志”（6 个连续显性位）和“被动错误标志”（6 个连续隐性位），取决于发送节点的错误状态。主动错误标志通过连续发送 6 个显性位人为制造位填充错误，强制破坏当前帧，使所有节点丢弃当前数据，确保数据一致性。

### 帧起始 SOF 解析

- 功能：标志着数据帧或遥控帧的开始
- 电平特性：固定为 1 个显性位（Dominant）
- 作用：总线空闲时任何节点都可以通过发送 SOF 尝试占有总线；所有其它节点在此刻同步到该发送节点的时钟边界，实现硬同步（Hard Synchronization）

## CAN总线优先级仲裁

### 仲裁基本原理

CAN 是非破坏性总线仲裁：

- 总线空闲时，最先开始发送消息的单元获得发送权
- 多个单元同时开始发送时，各发送单元从仲裁段的第一位开始逐位仲裁
- 利用线与机制：显性位（逻辑 0）物理覆盖隐性位（逻辑 1），发送隐性位却读到显性位的节点**仲裁失利**，从下一位开始转为接收状态工作
- 连续输出显性电平最多的单元可继续发送，即 **ID 数值越小优先级越高**


::: tip

仲裁过程对高优先级帧是非破坏性的：获胜节点继续发送自己的帧，不会因冲突而重发，这正是 CAN 实时性好的原因。

:::


### 数据帧和遥控帧的优先级

具有相同 ID 的数据帧和遥控帧在总线上竞争时，仲裁段的最后一位（RTR）为**显性位的数据帧具有优先权**，可继续发送；遥控帧的 RTR 为隐性，仲裁失利转为接收状态。

### 标准格式和扩展格式的优先级

标准格式 ID 与具有相同 ID 的遥控帧或扩展格式的数据帧在总线上竞争时，标准帧在扩展帧的 SRR 位处发送**显性 RTR**，而扩展帧该位为隐性 SRR，因此**标准格式具有优先权**，可继续发送。

### 仲裁优先级总结

| 竞争情形 | 优先级更高者 | 原因 |
|-|-|-|
| 不同 ID | ID 数值小的帧 | 高位更早出现显性位，线与机制下胜出 |
| 相同 ID 的数据帧 vs 遥控帧 | 数据帧 | RTR 为显性（0）优先于隐性（1） |
| 相同 ID 的标准帧 vs 扩展帧 | 标准帧 | 标准帧 RTR 显性优先于扩展帧 SRR 隐性 |

## CAN总线时序同步

### 位时序与 Time Quantum（Tq）

**时间份额 Tq** 是 CAN 总线位时间的最小基本单位。一个完整的“位”由多个 Tq 组成（通常设定为 8\~25 个），Tq 的绝对时间长度由总线控制器的波特率预分频器（BRP）和振荡器频率决定。

位时间（1 bit）分为四个段：

| 段 | 名称 | 作用 |
|-|-|-|
| SS | 同步段 | 多个连接在总线上的单元通过此段实现时序同步；下降沿应当落在此段内，固定为 1 Tq |
| PTS | 传播时间段 | 补偿网络上的物理延迟（总线信号传播延迟 + 节点内部发送/接收延迟） |
| PBS1 | 相位缓冲段 1 | 补偿边沿阶段的误差，可通过再同步操作**加长** |
| PBS2 | 相位缓冲段 2 | 可通过再同步操作**缩短** |

设定示例：1 bit = 10 Tq（SS=1，PTS=3，PBS1=2，PBS2=4），采样点位于 PBS1 与 PBS2 交界处。PTS+PBS1 小而 PBS2 加大时采样点前移；PTS+PBS1 大而 PBS2 减小时采样点后移。

### 硬件同步（Hardware Synchronization）

由于发送单元和接收单元可能存在**时钟频率误差**及传输路径上的（电缆、驱动器等）**相位延迟**，会引起同步偏差，接收单元需要通过硬件同步或再同步调整时序进行接收。

- 硬件同步：接收单元在**总线空闲状态检测出帧起始（SOF）**时进行的同步调整
- 当检测出隐性到显性的边沿时，视为位的起始（SS），所有节点以此边沿对齐位时间

### 再同步（Resynchronization）

- 再同步：接收过程中检测出总线上的电平变化（边沿）时进行的同步调整
- 每当检测出边沿时，根据 SJW 值通过**加长 PBS1 段**或**缩短 PBS2 段**调整同步
- 如果发生了超出 SJW 值的误差，最大调整量不能超过 SJW 值

**SJW（Synchronization Jump Width）同步跳转宽度：**定义了每次再同步时可以延长或缩短的最大 Tq 数量。例如 SJW=2 时：隐性→显性边沿延迟 2 Tq 出现在 PTS 中，则在 PBS1 后插入 SJW 长度调整同步；边沿提前出现在 PBS2 中，则在 PBS2 中减小 SJW 长度调整同步。

## bxCAN控制器简介

### bxCAN 外设简介

bxCAN（Basic Extended CAN）是 STM32 的 CAN 控制器外设，旨在以最少的 CPU 负载高效管理大量传入消息，并按需要的优先级实现消息发送。

- 协议支持：支持 CAN 2.0A 及 2.0B Active 版本协议，最高速率 1 Mb/s
- 双 CAN 架构：CAN1（主）和 CAN2（从）单元共享 512 字节 SRAM；CAN2 无法直接访问该存储区，由 CAN1 负责管理
- 3 个发送邮箱：支持可配置的优先级发送，提供最高效的帧调度，记录 SOF 发送时间戳
- 2 个接收 FIFO：每个具有三级深度，支持配置上溢模式，同样记录 SOF 接收时间戳
- 28 个筛选器组：支持标识符列表与掩码功能，CAN1 与 CAN2 共享，减轻 CPU 过滤压力
- 邮箱映射与中断：在唯一地址空间通过软件实现高效邮箱映射，具备多种可屏蔽中断机制

### 双 CAN 架构与主从分配

- CAN1（主 bxCAN）：负责管理与 512 字节 SRAM 之间的通信，直接控制存储器接口
- CAN2（从 bxCAN）：无法直接访问 SRAM 存储器，必须通过 CAN1 的存储器访问控制器进行读写操作
- 发送邮箱：每路 CAN 均独立拥有 3 个发送邮箱
- 接收 FIFO：每路 CAN 拥有 2 个接收 FIFO（FIFO0 / FIFO1），每个 FIFO 内含 3 个接收邮箱（3 级报文深度）
- 筛选器组：CAN1 与 CAN2 共同共享 28 个验收筛选器组；可通过 CAN_FMR 寄存器的 CAN2SB[5:0] 位配置 CAN2 起始筛选器存储区编号

### bxCAN 工作模式

bxCAN 具有三种主要工作模式，通过配置控制寄存器并等待硬件状态位确认，确保状态安全切换与硬件同步：

| 模式 | 说明 | 进入/退出 |
|-|-|-|
| 睡眠模式（Sleep） | 低功耗状态，硬件复位后的默认模式；时钟停止但邮箱仍可访问 | 软件置 SLEEP=1 请求进入；将 SLEEP 清零或硬件检测到 CAN 总线活动即可唤醒 |
| 初始化模式（Initialization） | 只有在此模式下才能配置波特率（CAN_BTR）及位定时参数，此时总线传输完全停止 | 软件置 INRQ=1 请求，硬件置位 INAK=1 确认（ACK） |
| 正常模式（Normal） | 完成初始化后参与总线通信，可在总线上接收和发送 | 软件请求后，硬件必须监测到连续 11 个隐性位（SYNC）才真正切入（清零 INAK 确认） |

### 测试与自检模式

通过配置 CAN_BTR 寄存器中的 SILM 和 LBKM 位，可将 bxCAN 置于不同测试模式：

- 静默模式（SILM=1）：正常接收有效帧，但发送总被强制拉高（隐性 1）；控制器内部可处理自身显性位，但不输出到物理总线。用于纯监听网络流量，不产生 ACK 或错误帧干扰总线
- 环回模式（LBKM=1）：发送信号正常输出到 CANTX，同时内部反馈到接收端，外部 CANRX 输入被忽略断开。用于本地硬件逻辑的隔离自检
- 环回 + 静默组合（LBKM=1, SILM=1）：既内部环回又对外静默（CANTX 恒为隐性，断开外部 CANRX）。用于“热自检”：对运行中的物理网络零干扰，进行自身软硬件全功能测试

### 发送处理与邮箱状态

bxCAN 包含 3 个发送邮箱，由硬件自动调度，经历 4 种核心状态：

| 状态 | 说明 |
|-|-|
| 空（Empty） | 可写入新消息数据；设置 TXRQ（发送请求）后退出空状态进入挂起 |
| 挂起（Pending） | 等待参与硬件优先级仲裁；若置位 ABRQ 请求中止发送，邮箱立刻恢复为空 |
| 已安排（Scheduled） | 在所有挂起邮箱中赢得最高优先级，等待 CAN 总线空闲以启动物理发送 |
| 发送（Transmit） | 硬件正在物理层发送帧；成功则变空，失败可根据 NART 位决定是否重新参与调度 |

### 接收处理与 FIFO 状态

接收 FIFO 完全由硬件管理，每个 FIFO 具有 3 级深度（最多挂起 3 条完整消息）：

- 空（Empty）：FIFO 中没有有效消息（FMP=0），硬件初始化或复位后处于此状态
- PENDING_1 / PENDING_2：接收到 1 或 2 条有效消息后挂起对应数量；软件读取后置位 RFOM 释放邮箱
- PENDING_3：FIFO 已填满（3 级深度），必须尽快处理；再接收到新有效消息将触发上溢
- 上溢（Overrun）：FIFO 满时又收到新消息（FOVR=1），新消息被丢弃（或覆盖，取决于配置）

### 标识符筛选

- 28 个筛选器组由 CAN1 与 CAN2 共享，每组可配置为 16 位或 32 位尺度（FSCx），掩码模式（FBMx=1）或列表模式（FBMx=0）
- 掩码模式：指定 ID 与掩码，掩码位为 1 的位必须匹配，为 0 的位不关心，可放行一段 ID 范围
- 列表模式：多个指定 ID 构成白名单，传入 ID 命中列表即放行，精确匹配
- 筛选器可分配到 FIFO0 或 FIFO1，接收到的报文按匹配规则进入对应 FIFO

### CAN 位时序与波特率计算

位时序逻辑监视串行总线，执行采样并调整采样点。关键公式：

- 时间片：tq = (BRP[9:0] + 1) × tPCLK（BRP 为波特率预分频器）
- 波特率 = 1 / (1 × tq + tBS1 + tBS2)
- SYNC_SEG：同步段，固定为 1 个 tq
- 位段 1（BS1）：定义采样点位置，tBS1 = tq × (TS1[3:0] + 1)
- 位段 2（BS2）：tBS2 = tq × (TS2[2:0] + 1)


::: tip

配置推演：42MHz APB1 时钟 → 500 kbps。Step1 位时间 = 1/500k = 2μs；Step2 设 BRP+1=7，tq = 7/42MHz ≈ 166.7ns；Step3 总时间片 = 2μs/166.7ns = 12 个 tq；Step4 分配 SYNC=1、BS1=8、BS2=3，采样点 = (1+8)/12 = 75%。最终 CAN_BTR 寄存器填入：BRP=6、TS1=7、TS2=2。

:::


### bxCAN 中断机制

bxCAN 共有四个专用中断向量，每个中断源均可通过 CAN_IER（中断使能寄存器）单独使能或禁止：

- 发送中断：发送邮箱 0/1/2 变空时，CAN_TSR 寄存器的 RQCP0/1/2 位置 1
- FIFOx 中断（x=0,1）：FIFOx 满（FULLx）或上溢（FOVRx）时触发
- 错误与状态中断：发生错误（错误警告 EWG、错误被动 EPV、总线关闭 BOF）或状态改变（唤醒 WKU、睡眠 SLAK）时触发

### HAL 库接口（STM32F407）

主要配置结构体：

- CAN_InitTypeDef：Prescaler（波特率预分频器）、Mode（工作模式）、SyncJumpWidth（SJW）、TimeSeg1（BS1）、TimeSeg2（BS2）、TimeTriggeredMode、AutoBusOff、AutoWakeUp、AutoRetransmission、ReceiveFifoLocked、TransmitFifoPriority
- CAN_FilterTypeDef：FilterIdHigh/Low、FilterMaskIdHigh/Low、FilterFIFOAssignment、FilterBank（0\~27）、FilterMode（掩码/列表）、FilterScale（16 位/32 位）、FilterActivation、SlaveStartFilterBank

| 函数 | 功能 |

| HAL_CAN_ConfigFilter | 配置接收过滤器，筛选允许接收的报文 ID |

| HAL_CAN_GetError | 获取最新错误代码标志 |

## CAN总线发送程序和接收程序编写（HAL库）

### 实验目标与器材

本节目标：在 STM32F407 上使用 HAL 库完成 CAN 总线通信程序的编写，实现节点间的报文发送与接收。完成本节学习后应能够：

- 使用 STM32CubeMX 完成 CAN 外设的时钟、引脚、波特率与中断配置
- 使用 HAL_CAN_AddTxMessage 完成报文发送（轮询与中断两种方式）
- 通过过滤器 + 中断回调完成报文接收
- 独立完成双板 CAN 通信联调

实验器材：

- STM32F407 开发板 ×2（本实验以 STM32F407ZGT6 为例）
- TJA1050 等 CAN 收发器模块 ×2（将 CAN 控制器的 TTL 电平转换为 CAN_H / CAN_L 差分信号）
- 杜邦线若干、USB 转串口模块（用于打印调试信息）、示波器或逻辑分析仪（可选）

### CubeMX 配置步骤

**1. 时钟配置**：使用外部高速晶振 HSE，将系统时钟 SYSCLK 配置为 168 MHz，APB1 分频为 42 MHz。CAN 外设挂载在 APB1 总线上，其时钟频率直接决定波特率计算，务必确认。

**2. 引脚配置**：在 Pinout 视图中将 CAN1_RX 与 CAN1_TX 配置到对应引脚（复用功能 AF9），常用引脚如下：

| 信号 | 引脚 | 复用功能 | 说明 |
|-|-|-|-|
| CAN1_TX | PA12 或 PB9 | AF9 | 接收发器 TXD |
| CAN1_RX | PA11 或 PB8 | AF9 | 接收发器 RXD |
| GND | GND | — | 与收发器及对端共地 |

**3. CAN 参数配置**（CAN1 → Parameter Settings）：

- Bit Timings Parameters：Prescaler = 6，Time Quanta in Bit Segment 1 = 11，Time Quanta in Bit Segment 2 = 2，Synchronisation Jump Width = 1，对应波特率 500 kbps
- Basic Parameters：Mode 选 Normal（单板自测时选 Loopback）；Auto Bus-Off Management、Auto Retransmission 建议开启；其余按需

波特率计算公式：波特率 = APB1_CLK ÷（Prescaler ×（1 + TimeSeg1 + TimeSeg2）），采样点 =（1 + TimeSeg1）÷（1 + TimeSeg1 + TimeSeg2）。APB1 = 42 MHz 时常见配置如下：

| 波特率 | Prescaler | TimeSeg1 | TimeSeg2 | SJW |
|-|-|-|-|-|
| 1 Mbps | 3 | 11 | 2 | 1 |
| 500 kbps | 6 | 11 | 2 | 1 |
| 250 kbps | 12 | 11 | 2 | 1 |

**4. 中断配置**：NVIC Settings 中勾选 CAN1 RX0 interrupt（FIFO0 接收中断）；若使用中断发送，同时勾选 CAN1 TX interrupts（发送邮箱空中断）。

**5. 生成代码**：Project Manager 中设置工程名与工具链，勾选 Generate peripheral initialization as a pair of '.c/.h' files per peripheral，点击 GENERATE CODE。

### 发送程序设计

bxCAN 外设内置 3 个发送邮箱，HAL 库发送报文的核心流程：构造 CAN_TxHeaderTypeDef 报文头 → 填充数据缓冲区 → 调用 HAL_CAN_AddTxMessage 将报文挂入空闲邮箱并请求发送。发送完成可通过中断回调或查询邮箱状态确认。

**1. 轮询方式发送**：在应用层封装一个发送函数，发送前先调用 HAL_CAN_GetTxMailboxesFreeLevel 检查空闲邮箱数量，避免邮箱占满导致添加失败。

```c
void CAN_SendFrame(uint32_t StdId, uint8_t *pData, uint8_t Dlc)
{
    CAN_TxHeaderTypeDef TxHeader;
    uint32_t TxMailbox = 0;
    if (HAL_CAN_GetTxMailboxesFreeLevel(&hcan1) == 0) {
        return;                 // 3 个邮箱均满，放弃本次发送
    }
    TxHeader.StdId = StdId;     // 标准帧 ID，范围 0x000~0x7FF
    TxHeader.ExtId = 0;         // 扩展帧 ID，仅 IDE 为 CAN_ID_EXT 时有效
    TxHeader.IDE = CAN_ID_STD;  // 标准帧（CAN_ID_EXT 为扩展帧）
    TxHeader.RTR = CAN_RTR_DATA; // 数据帧（CAN_RTR_REMOTE 为遥控帧）
    TxHeader.DLC = Dlc;         // 数据长度 0~8 字节
    if (HAL_CAN_AddTxMessage(&hcan1, &TxHeader, pData, &TxMailbox) != HAL_OK) {
        /* 添加失败，可在此记录错误 */
    }
}
```

主循环中周期性调用即可实现周期发送：

```c
uint8_t TxData[8] = {0x01, 0x02, 0x03, 0x04, 0x05, 0x06, 0x07, 0x08};
while (1) {
    CAN_SendFrame(0x123, TxData, 8);
    HAL_Delay(1000);            // 每 1 秒发送一帧
}
```

**2. 中断方式发送**：先使能发送邮箱空中断，AddTxMessage 后由硬件在发送完成时触发中断回调，适合连续多帧发送场景（一帧发送完成后自动发下一帧）。

```c
HAL_CAN_ActivateNotification(&hcan1, CAN_IT_TX_MAILBOX_EMPTY);
```

```c
void HAL_CAN_TxMailbox0CompleteCallback(CAN_HandleTypeDef *hcan)
{
    /* 邮箱 0 报文发送完成，可在回调中继续发送下一帧 */
    if (HAL_CAN_GetTxMailboxesFreeLevel(hcan) > 0) {
        /* CAN_SendFrame(0x123, NextData, 8); */
    }
}
```

**3. 发送注意事项**：

- DLC 最大为 8（标准 CAN），发送数据缓冲区至少为 DLC 字节
- 标准帧 ID 只能使用 11 位（0x000\~0x7FF），超出部分会被截断
- 开启自动重传时，发送失败（如总线错误）硬件会自动重发，回调不会触发，需自行做超时保护
- HAL 回调函数为弱定义，用户重写同名函数即可生效；回调中不要做耗时操作

### 接收程序设计

CAN 接收采用「过滤器 + FIFO + 中断回调」的典型结构：报文先经过滤器筛选，匹配的报文存入 FIFO0/FIFO1，随后触发中断，用户在回调中调用 HAL_CAN_GetRxMessage 取出报文。使用中断接收时，接收流程完全由硬件驱动，无需在主循环中轮询。

**1. 配置接收过滤器**：在初始化函数中调用 HAL_CAN_ConfigFilter。掩码模式（IDMASK）下，掩码位为 1 表示该位必须匹配，为 0 表示不关心；掩码全 0 表示接收所有报文。

```c
CAN_FilterTypeDef Filter;
Filter.FilterActivation = ENABLE;
Filter.FilterMode = CAN_FILTERMODE_IDMASK;   // 掩码模式
Filter.FilterScale = CAN_FILTERSCALE_32BIT;   // 32 位
Filter.FilterIdHigh = 0x0000;
Filter.FilterIdLow = 0x0000;
Filter.FilterMaskIdHigh = 0x0000;            // 掩码全 0，不关心任何位
Filter.FilterMaskIdLow = 0x0000;
Filter.FilterFIFOAssignment = CAN_RX_FIFO0;   // 分配到 FIFO0
Filter.FilterBank = 0;                        // 过滤器组号 0~27
HAL_CAN_ConfigFilter(&hcan1, &Filter);
```

只接收 ID = 0x123 的报文时，将 ID 左移 5 位填入 FilterIdHigh，掩码高 16 位填入 0x7FF << 5：

```c
Filter.FilterIdHigh = 0x123 << 5;
Filter.FilterIdLow = 0x0000;
Filter.FilterMaskIdHigh = 0x7FF << 5;
Filter.FilterMaskIdLow = 0x0000;
```

**2. 启动 CAN 并使能接收中断**：

```c
HAL_CAN_Start(&hcan1);
HAL_CAN_ActivateNotification(&hcan1, CAN_IT_RX_FIFO0_MSG_PENDING);
```

**3. 编写接收中断回调**：

```c
volatile uint8_t CanRxFlag = 0;
CAN_RxHeaderTypeDef RxHeader;
uint8_t RxData[8];
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &RxHeader, RxData) == HAL_OK) {
        /* RxHeader.StdId 为帧 ID，RxHeader.DLC 为实际数据长度 */
        /* 在此处理 RxData[0]~RxData[DLC-1]，如存入全局数组或置标志位 */
        CanRxFlag = 1;
    }
}
```

**4. 轮询方式接收（可选）**：不使用中断时，可在主循环中查询 FIFO 填充级别并取报文，适用于实时性要求不高的场景。

```c
CAN_RxHeaderTypeDef RxHeader;
uint8_t RxData[8];
if (HAL_CAN_GetRxFifoFillLevel(&hcan1, CAN_RX_FIFO0) > 0) {
    HAL_CAN_GetRxMessage(&hcan1, CAN_RX_FIFO0, &RxHeader, RxData);
}
```

### 单板回环自测

正式联调前，可先用单板回环模式验证发送与接收链路。将 CAN 模式设为 CAN_MODE_LOOPBACK，此时发送的报文不经总线、直接进入本节点的接收 FIFO，无需外接收发器即可完成自测。

```c
hcan1.Init.Mode = CAN_MODE_LOOPBACK;   // 回环模式，报文不经过总线
```

```c
uint8_t TxData[8] = {0xAA, 0xBB, 0xCC, 0xDD, 0xEE, 0xFF, 0x00, 0x11};
CAN_SendFrame(0x123, TxData, 8);
HAL_Delay(100);
if (CanRxFlag) {                 // 回调中置位说明自环收发成功
    printf("loopback ok\r\n");
    CanRxFlag = 0;
}
```

回环测试通过后，将模式改回 CAN_MODE_NORMAL 即可进行双板联调。

### 双板通信实例

两套开发板各接一个 TJA1050 收发器，按下述方式接线：

- 板 1 CANH 接板 2 CANH，板 1 CANL 接板 2 CANL（使用双绞线更佳）
- 总线两端各接一个 120 Ω 终端电阻（多数收发器模块已焊好，检查跳线或拨码开关）
- 两块板 GND 必须相连，否则共模电压漂移会导致通信失败

**发送端**：周期性发送 ID 为 0x123 的报文，每帧携带 8 字节数据。

```c
uint8_t TxData[8];
uint32_t Count = 0;
while (1) {
    TxData[0] = Count >> 24;
    TxData[1] = Count >> 16;
    TxData[2] = Count >> 8;
    TxData[3] = Count;
    TxData[4] = 0x5A;
    TxData[5] = 0xA5;
    TxData[6] = 0x00;
    TxData[7] = 0xFF;
    CAN_SendFrame(0x123, TxData, 8);
    Count++;
    HAL_Delay(500);
}
```

**接收端**：过滤器接收所有报文，中断回调中取出报文并通过串口打印。示例中的 printf 需在工程中完成串口重定向（重写 fputc），或改用 HAL_UART_Transmit 直接输出。

```c
CAN_RxHeaderTypeDef gRxHeader;
uint8_t gRxData[8];
volatile uint8_t gRxFlag = 0;
void HAL_CAN_RxFifo0MsgPendingCallback(CAN_HandleTypeDef *hcan)
{
    if (HAL_CAN_GetRxMessage(hcan, CAN_RX_FIFO0, &gRxHeader, gRxData) == HAL_OK) {
        gRxFlag = 1;
    }
}
while (1) {
    if (gRxFlag) {
        gRxFlag = 0;
        printf("RX ID=0x%03X DLC=%d Data=", gRxHeader.StdId, gRxHeader.DLC);
        for (uint8_t i = 0; i < gRxHeader.DLC; i++) printf("%02X ", gRxData[i]);
        printf("\r\n");
    }
}
```

两端波特率必须一致（本实验均为 500 kbps）。若接收端串口持续打印数据且计数递增，说明双板通信正常。

### 调试要点与故障排查

| 现象 | 可能原因 | 排查方法 |
|-|-|-|
| 发送失败，AddTxMessage 返回错误 | 未调用 HAL_CAN_Start；邮箱全满；CAN 进入 Bus-Off | 确认初始化后已 Start；检查 HAL_CAN_GetTxMailboxesFreeLevel；读取 HAL_CAN_GetError |
| 发送成功但对端收不到 | 波特率不一致；未接 120 Ω 终端电阻；未共地；收发器供电异常 | 核对两端波特率配置；检查总线两端电阻与共地；用示波器观察 CANH/CANL 波形 |
| 能发送但接收中断不触发 | 过滤器掩码配置错误；未使能接收中断；报文被过滤器丢弃 | 先按「接收所有」配置过滤器；确认已调用 ActivateNotification；核对中断优先级 |
| 回调收到数据但内容异常 | DLC 与实际数据长度不符；数据缓冲区越界；收发数据格式不一致 | 以 RxHeader.DLC 为准处理数据；核对两端数据字节序与打包方式 |
| 总线错误频繁，进入 Bus-Off | 物理层问题：无终端电阻、线缆过长、干扰；波特率不匹配 | 检查双端 120 Ω；总线长度按波特率控制（1 Mbps 约 40 m，500 kbps 约 100 m）；开启 Auto Bus-Off 自动恢复 |

调试建议：

- 先用单板回环模式排除软件问题，再上总线联调
- 用串口打印 HAL_CAN_GetError 错误标志与空闲邮箱数，辅助定位
- 用逻辑分析仪或示波器观察 CANH-CANL 差分波形，确认显性/隐性电平（约 2.5 V 上下跳变）
- 排查过滤器时先全部放行，验证接收链路正常后再收紧掩码
