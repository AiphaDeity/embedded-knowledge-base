# 处理器与汇编学习第一性原理

## 一、处理器的第一性原理（Cortex‑M 内核）

### 处理器本质

CPU 只做一件事：从内存取指令 → 译码 → 执行，循环往复。 所有复杂功能（中断、函数调用、异常、流水线），全部是这套循环的扩展。

1. 指令存放在 Flash，数据存放在 RAM；CPU 自己只拥有少量寄存器，寄存器是 CPU 内部极速存储，比 RAM 快得多，CPU 运算只能直接操作寄存器，不能直接操作内存。

> 重要第一公理：运算必须在寄存器中完成，内存只能读入寄存器、或者把寄存器结果写回内存。所以才有 LDR（读内存）、STR（写内存）内存访问指令。

### Cortex‑M4 核心硬件事实（对应 2.2 内核寄存器）

1. R0‑R12：通用寄存器，用来临时存放运算数据。
2. R13 (SP)：堆栈指针。栈就是 RAM 里一块内存区域，SP 永远指向栈顶。函数局部变量、函数返回地址、现场保护全部依赖栈。
3. R14 (LR)：链接寄存器，保存函数返回地址。BL 跳转的时候自动把下一条指令地址存入 LR。
4. R15 (PC)：程序计数器，PC 的值就是下一条要取的指令地址。改变 PC，程序就跳转。
5. xPSR 状态寄存器：保存运算结果标志位（零、负、进位、溢出），条件分支全部依赖 PSR 的标志位。
6. 特殊功能寄存器：CONTROL、PRIMASK 等，控制特权级、中断开关，需要专用 MSR/MRS 访问，不能用普通 MOV。

> 第一性推论：
> 
> - 函数调用 = BL，把返回地址给 LR；函数返回 = BX LR，把 LR 送入 PC。
> - 条件跳转不是指令自带判断，是先运算修改 PSR，再根据 PSR 标志决定是否跳转。

### 处理器两种工作模式（2.3 处理器工作模式）

- 线程模式：普通应用代码运行，可以是特权 / 非特权。
- 处理模式：发生异常 / 中断时自动进入，永远特权，用来处理中断服务函数。

> 底层事实：发生中断，硬件自动压栈 R0‑R3、LR、PC、xPSR 到栈；中断结束自动出栈恢复。这就是异常处理硬件自动完成的动作，对应 2.9 异常处理流程。

### 流水线（2.11 流水线技术）

M4 是 3 级流水线：取指 → 译码 → 执行，三条指令同时并行工作。

> 关键第一性事实：Cortex‑M 中 PC = 当前执行指令地址 + 4。 不是指向正在执行的指令，而是流水线下一条指令地址，很多汇编 bug 根源来自这里。

### M4 上电启动流程（2.13）

上电硬件自动做，不是软件写的：

1. 从 Flash 起始地址 0x0 取初始 SP 值，设置 R13；
2. 从 0x4 取复位向量地址，赋值给 PC；
3. 开始执行复位程序，之后初始化 BSS、数据段，跳转到 main。

> 第一性理解：main 不是 CPU 天然入口，是启动汇编人工跳转过去的。

## 二、ARM 汇编的第一性原理

### 汇编语言本质（2.1、2.4 汇编基础）

汇编 = CPU 机器指令的文本别名。 每一条真实汇编指令，对应一条机器码，CPU 硬件可以直接译码执行。 伪指令（2.12）不是 CPU 指令，是给汇编器的提示，编译阶段处理，不会生成机器码。

> 区分：
> 
> - 真正指令：ADD、LDR、STR、BL、BX → 生成机器码，CPU 运行期执行
> - 伪指令：EQU、DCD、SPACE、AREA → 汇编器预处理，编译完就消失

### 四大类指令底层逻辑（2.5‑2.7）

1. 数据处理指令（ADD/SUB/MOV/AND 等） 只操作寄存器，不访问内存。计算全部发生在 CPU 内部寄存器。`ADD R0,R1,R2`：R0 = R1 + R2，全程不碰 RAM。
2. 内存访问指令 LDR / STR 唯一读写内存的指令。

- LDR：把内存的数据读到寄存器（Load）
- STR：把寄存器的数据写到内存（Store）

> 牢记公理：ARM 不能直接 `MOV R0, [0x20000000]`，MOV 只能寄存器‑寄存器，访问内存必须 LDR/STR。

1. 分支跳转指令 B / BL / BX（2.6） 本质就是修改 PC 寄存器的值。

- B label：无条件跳转，不保存返回地址
- BL label：跳转，同时把返回地址存入 LR（函数调用）
- BX Rm：跳转到 Rm 存放的地址，用于函数返回（BX LR）

1. 特殊寄存器访问 MRS / MSR（2.10） 普通 MOV 不能读写 xPSR、CONTROL 这类内核特殊寄存器。

- MRS：特殊寄存器 → 通用寄存器
- MSR：通用寄存器 → 特殊寄存器

### AAPCS 规则（2.8，C 与汇编交互核心）

AAPCS 是C 编译器和汇编之间的契约，不是 CPU 硬件强制，是软件约定。

> 第一性：CPU 硬件不在乎 R0‑R12 怎么用，AAPCS 是人定的调用约定，保证 C 调用汇编、汇编调用 C 可以正常工作。 核心规则：

1. R0‑R3：函数入口参数，返回值放 R0；被调用函数可以随便破坏，不需要保存。
2. R4‑R11：被调用函数必须保护，如果要用，入函数先压栈，退出前出栈恢复。
3. SP (R13)：栈指针，栈向下增长，SP 必须 4 字节对齐。
4. LR (R14)：函数返回地址。

> 这也是内联汇编（2.15）背后的底层约束，写内联汇编必须遵守 AAPCS，否则 C 变量会被莫名破坏。

## 三、整套学习路线的第一性原则（对应你截图目录）

按这个逻辑顺序学，不要死记指令：

1. 先懂硬件模型：寄存器是什么、栈是什么、PC/SP/LR 到底硬件行为是什么。

> 不要一上来背 ADD、SUB 指令。先搞懂：CPU 只能操作寄存器，内存必须 LDR/STR。

1. 再学指令：每学一条指令，问自己三件事 1）这条指令修改哪些寄存器？ 2）会不会访问内存？ 3）会不会改变 PC，会不会影响 PSR 标志位？
2. 理解 AAPCS 契约：看懂 C 语言函数调用，翻译成汇编是什么样子。
3. 理解中断异常：硬件自动压栈出栈，处理模式切换。
4. 流水线：搞懂 PC 偏移 + 4 的来源，读懂汇编跳转地址。
5. 启动流程：看懂复位后，硬件干了什么，汇编启动文件干了什么，怎么到 main。
6. 动手：汇编点灯（2.14），裸写汇编操作寄存器点亮 LED，不调用 C 库。
7. 内联汇编：在 C 里面嵌入汇编，理解 C 变量和寄存器之间怎么交互，AAPCS 约束。

## 四、几条非常重要的第一性公理（做题、写代码遇到想不通就回来对照）

1. CPU 运算只能在寄存器中完成，内存不能直接参与运算。
2. PC 的值决定下一条取哪条指令，修改 PC 就是跳转。
3. 栈就是 RAM 的一块内存，SP 只是指向这块内存的指针，栈没有魔法，就是内存读写。
4. 函数调用本质：BL 保存返回地址到 LR；函数返回本质：BX LR 把 LR 赋值给 PC。
5. 条件执行不来自指令本身，来自 xPSR 状态标志，由上一条运算指令设置。
6. AAPCS 是软件约定，CPU 硬件不检查，违背约定不会报错，但程序会随机崩溃。
7. 伪指令只在编译期生效，不会生成运行时机器码。
8. 中断不是软件跳过去的，是硬件自动压栈、切模式、修改 PC。

## 五、学习实操建议（第一性原理落地）

1. 每学一个指令，去看它对应的机器码，明白汇编只是机器码助记符。
2. 使用调试器，单步跑汇编：观察每一步后 R0‑R15、PSR、内存、SP 的值变化。看寄存器变化胜过看书十遍。
3. 不要记 “这个指令用来干什么”，而是记 “这条指令改变了哪些硬件状态”。
4. 写简单汇编：不用 HAL 库，直接汇编操作 GPIO 寄存器，实现点灯。
5. 写简单 C 函数，编译反汇编，对照 AAPCS 看懂编译器生成的汇编，看懂参数传递、局部变量在栈上如何存储。

# 汇编语言基础

## 01 处理器原理与汇编语言概述

**1.1 为什么学习汇编语言**

1. 深入理解计算机工作原理：汇编直接和硬件交互，看透处理器底层逻辑。
2. 优化程序性能：直接操控硬件，实现高级语言达不到的极致性能。
3. 系统内核 & 驱动开发：操作系统启动、异常处理、底层驱动大量依赖汇编。
4. 提升编程、调试能力：看懂高级语言编译后的行为，定位诡异 bug。
5. 调试与逆向工程：固件调试、漏洞分析、恶意程序分析必备基础。

**1.2 机器码、汇编、汇编器**

- 机器码：计算机唯一能直接执行的二进制 0/1 序列。 

历史：ENIAC 冯・诺依曼架构：程序和数据全部以二进制存储在存储器，早期使用打孔纸带输入二进制机器码。

- 汇编指令：机器码的文本助记别名。 示例：`MOV R1, #2` 对应一串二进制机器码，人阅读编写更容易。
- 汇编器（Assembler）：把汇编源代码翻译成二进制机器码的工具。

> ✨第一性补充：
> 
> - 机器码 = CPU 硬件真正执行；汇编 = 人类可读的别名；汇编器只是翻译工具。
> - 伪指令不会生成机器码，仅汇编编译阶段生效。

**1.3 指令集**

指令集是处理器硬件定义好的全部指令集合，规定每条机器码代表什么动作。 示例 ARM 指令：`MOV`、`ADD`、`SUB`、`CMP`、`BL`、`STR`、`LDR`。

## 02 进制转换

**2.1 各进制基础**

- 十进制：基数 0‑9，逢 10 进 1
- 十六进制：`0x`前缀，0\~F，逢 16 进 1，单片机、汇编最常用。
- 二进制：只有 0、1，逢 2 进 1，硬件底层存储形式。

**2.2 进制互相转换**

1. 十进制 → 二进制：除 2 取余，逆序排列 示例十进制`101`：不断除以 2 取余数，最后得到的余数是最高位，最先得到是最低位。 结果：`101 = 0b1100101`。
2. 二进制 → 十进制：按权展开求和 每一位乘以 $2^n$，n 从 0 开始（最右侧低位）。 

示例无符号二进制`10010111`：

$$1\times2^7+0\times2^6+0\times2^5+1\times2^4+0\times2^3+1\times2^2+1\times2^1+1\times2^0 =151$$

> 补充：有符号二进制最高位为符号位：`0=正数`，`1=负数`；但是⚠️注意：硬件内存存储负数用补码，不能直接拿符号位后面数值直接算，PDF 此处示例写法简略，详见第 4 章补码。

1. 十进制 → 十六进制：除 16 取余逆序 示例十进制`4138`，得到 `0x102A`。
2. 十六进制 → 十进制：按 16 的权展开`0x2AD = 2*16² + 10*16¹ + 13*16⁰ = 685`
3. 二进制 ↔ 十六进制：4 位分组法

> 核心：1 位十六进制恰好等价 4 位二进制

- 二进制转十六进制：从右往左每 4 位一组，不足 4 位左侧补 0；每组转成 1 位 16 进制。 
- 例：`1110110101011` → 补 0：`0001 1101 1010 1011` → `0x1DAB`
- 十六进制转二进制：每 1 位直接展开 4 位二进制。例`0x5D` → `0101 1101`。

**2.3 存储单位：字节、半字、字（Cortex‑M4）**

```text
1 Bit    ：1个二进制位 0/1
1 Byte   = 8 bit  字节
Half‑Word(半字) = 16 bit = 2字节
Word(字)        = 32 bit =4字节
```

> ✨第一性补充（Cortex‑M4）： Cortex‑M4 是 32 位内核，字 Word 固定 32bit；CPU 内部通用寄存器 R0‑R15 全部 32 位。 内存访问指令 LDR/STR 支持：字节 (8bit)、半字 (16bit)、字 (32bit) 读写。
> 
> - `LDRB`：读字节；`LDRH`：读半字；`LDR`：读字
> - `STRB`：写字节；`STRH`：写半字；`STR`：写字

存储容量换算：

$$1KB=1024Byte,\quad1MB=1024KB,\quad1GB=1024MB$$

## 03 立即数判断（ARMv7‑M Cortex‑M4）

**3.1 什么是立即数**

立即数：汇编指令中直接写的常数，例如`MOV R1,#0xFF`，`#`代表立即数。

> ⚠️Cortex‑M4 的 Thumb‑2 指令集，不是所有 32 位常数都可以直接当立即数写在 MOV/MVN 里面，存在合法 / 非法立即数。如果是非法立即数，汇编器报错。

**3.2 为什么会存在非法立即数**

机器指令编码长度有限，MOV 指令编码里，不能完整放下全部 32bit 数值，硬件只支持特定格式的立即数编码。 Cortex‑M4 Thumb‑2 MOV 合法立即数两类：

1. 8bit 原始字节复制模式： 

   - 0x000000xx
   - 0x00xx00xx
   - 0xx00xx00
   - 0xxxxxxxx
2. 8bit 数值循环右移偶数位得到的 32 位数：一个 8bit 数据，循环右移 0,2,4…23 位生成 32 位立即数。

示例 

✅合法立即数：`0x5D`、`0xFF0000`、`0x122`、`0x234`、`0xFFFFFFFF` 

❌非法立即数：`0x101`、`0x1FF`、`0x1234`、`0xF000000F`

**3.3 遇到非法立即数怎么处理【实操补充】**

不能写`MOV R0,#0x101`，两种解决办法：

1. 从内存常量池加载：`LDR R0, =0x101`；`LDR Rn,=xxx`是伪指令，汇编器把常量存到 ROM，用 LDR 读取。工程最常用。
2. 多条指令组合构造：例如 MOV+ORR 拼接出目标数值。

> 重点区分：
> 
> - `MOV R0,#imm`：真正指令，受立即数编码限制。
> - `LDR R0,=value`：伪指令，不受立即数限制，几乎可以加载任意 32 位常数。

## 04 二进制存储与运算：原码、反码、补码

> 📌第一公理：计算机硬件中，所有有符号整数全部存储、运算都使用补码，没有原码、反码；原码反码只是人类推导补码用的中间概念。

**4.1 原码**

- 最高位符号位：0 正数，1 负数；其余位保存数字绝对值二进制。 4bit 原码示例：

- 正数反码 = 原码不变；
- 负数反码：符号位不变，其余所有数据位全部按位取反。

缺陷：依然存在`+0`、`‑0`两个零，不能彻底解决减法硬件问题。

**4.3 补码（硬件实际使用）**

规则：

1. 正数补码 = 原码，完全不变
2. 负数补码 = 对应正数原码全部按位取反 + 1（符号位参与运算）

4bit 补码表示范围：`‑8 ~ +7`


<table v-pre><tbody><tr><td>十进制</td><td>补码</td></tr><tr><td>+1</td><td>1</td></tr><tr><td>-1</td><td>1111</td></tr><tr><td>-2</td><td>1110</td></tr><tr><td>-8</td><td>1000</td></tr></tbody></table>


> 关键优势：

1. 只有一个 0，消除‑0；4bit 补码多出来一个编码用来表示‑8。
2. 减法可以直接转换成加法运算：CPU 只需要加法器一套硬件电路，`A‑B = A + (−B的补码)`。

补码运算示例：`‑2 + (−4)`，4bit 补码：`1110 + 1100 = 11010`，最高进位直接丢弃，结果`1010`，对应十进制‑6。

> 📌补充易错点： 调试器看到内存、寄存器里面的十六进制，都是补码。 例如寄存器值`0xFFFFFFF1`，作为 32 位有符号数是‑15，不能直接把十六进制当成原码解读。

**4.4 溢出**

补码运算结果超出 bit 位能表示范围，发生溢出，运算结果错误。Cortex‑M4 运算后会设置 PSR 状态寄存器的 V 溢出标志位，程序可以检测溢出。

## 05 STM32F4 / Cortex‑M4 地址空间分布（内存映射）

> 第一性原理：Cortex‑M 内核把 Flash、RAM、GPIO、定时器、NVIC 全部统一当做内存地址访问，这就是内存映射 I/O。读写外设寄存器等价读写特定内存地址。

**每个区域详细解读**

1. Code 域 0x00000000 STM32 上电后，从`0x0`读取初始 SP 栈指针；从`0x4`读取复位入口地址。

> ⚠️STM32Flash 物理起始地址 0x08000000，上电后系统会把 Flash 重映射到`0x0`地址，实现启动。

1. SRAM `0x20000000` 栈 SP 指向这片区域；局部变量函数栈、堆 malloc 内存全部放在这里；CPU 读写速度很高。
2. Peripherals `0x40000000` GPIOA 寄存器地址例如`0x40020000`，直接汇编`LDR/STR`读写该地址就可以操作引脚输出高低电平，裸机汇编点灯本质就是读写这片地址。
3. PPB `0xE0000000` NVIC 中断使能、中断优先级、系统异常配置都在这个地址段；普通 LDR/STR 也可以访问，也可以 MRS/MSR 访问内核特殊寄存器。

> ✨重要推论： 汇编写驱动，不需要特殊 IO 指令！不像 x86 有 IN/OUT 指令。ARM Cortex‑M没有独立 IO 指令，全部是内存读写指令 LDR/STR 操控硬件。

**综合：本阶段必须记住的第一性原理汇总**

1. 一切程序最终形态是二进制机器码；汇编只是机器码助记符，汇编器负责翻译。伪指令编译后消失，不生成机器码。
2. 处理器所有有符号数存储运算全部使用补码；原码反码仅用于推导。
3. Cortex‑M 是纯 Thumb‑2 指令集，32 位寄存器；MOV 立即数有编码限制，复杂常数用`LDR Rn,=xxx`伪指令加载。
4. Cortex‑M 采用内存映射 IO，外设寄存器就是一段内存地址，用 LDR 读取、STR 写入，没有专门 IO 指令。
5. CPU 运算只能在寄存器完成，内存只能读入寄存器、寄存器写回内存，不能直接内存做算术运算。
6. Flash (Code) 存代码断电保存；SRAM 存运行时变量断电丢失。

**学习实操建议**

1. 进制：随手练习十进制、二进制、十六进制互相手算，熟悉 4 位分组转换。
2. 补码：随便拿一个负数，手动推演补码；写简单程序看寄存器内存观察补码表现。
3. 立即数：尝试写 MOV 非法立即数，看汇编器报错，对比`LDR R0,=xxx`的编译结果。
4. 内存映射：查阅 STM32F4 参考手册，找 GPIOA 基地址，看懂每个寄存器对应哪一段地址。
5. 调试：使用 Keil 单步调试，观察寄存器、内存窗口，看指令执行前后寄存器、内存值变化。

# Cortex-M4内核寄存器

## 01 通用寄存器

**1.1 寄存器的第一性本质**

**内核寄存器**是 CPU 内部的高速存储单元，是处理器运算的唯一直接操作对象。

> 第一公理：CPU 不能直接对内存数据做算术、逻辑运算，必须先把数据从内存加载到寄存器，运算完成后再写回内存。寄存器的读写速度远高于片内 SRAM，是整个处理器运行效率的核心。

Cortex-M4 内核共包含16 个 32 位通用架构寄存器 + 若干特殊功能寄存器，其中 R0\~R12 为通用数据寄存器，R13\~R15 为专用功能寄存器。

**1.2 通用寄存器分组**

通用寄存器 R0\~R12 本身无硬件强制用途，可自由存放临时数据；但受指令编码限制，分为低段与高段两组：


<table v-pre><tbody><tr><td>分组</td><td>寄存器范围</td><td>访问规则</td></tr><tr><td>低段寄存器</td><td>R0 ~ R7</td><td>所有 16 位 Thumb 指令、32 位 Thumb-2 指令均可访问</td></tr><tr><td>高段寄存器</td><td>R8 ~ R12</td><td>仅 32 位 Thumb-2 指令可访问，16 位 Thumb 指令无法编码寻址</td></tr></tbody></table>


> ✨底层补充：为什么分高低段？ 16 位 Thumb 指令的寄存器编码位只有 3 位，最多表示 0\~7 共 8 个寄存器，因此 R8\~R12 无法被 16 位指令访问。32 位 Thumb-2 指令扩展了寄存器编码位，支持全部 13 个通用寄存器。 
> 
> 实操影响：纯 16 位 Thumb 汇编代码只能使用 R0\~R7；开启 Thumb-2 后可自由使用全部寄存器，代码效率更高。

**1.3 通用寄存器的软件约定（AAPCS 铺垫）**

硬件层面 R0\~R12 完全平等，但 ARM 有标准的AAPCS 调用约定（后续章节详解），编译器和汇编函数默认遵循以下分工：

- R0\~R3：函数入参、返回值传递，函数内部可自由修改，无需保存
- R4\~R11：函数内若要使用，必须先压栈保存、退出前恢复，否则会破坏调用者数据
- R12：临时调用寄存器，常用于函数跳转间的暂存

## 02 专用寄存器（R13 / R14 / R15）

### **2.1 栈指针寄存器 R13 (SP)**

R13 永远指向当前栈顶地址，是栈操作的唯一基准指针。

**2.1.1 双栈指针：MSP 与 PSP**

Cortex-M4 内置两个独立的栈指针，硬件自动切换：

1. MSP（主栈指针）： 特权级

   - 复位后默认使用，处理模式（异常 / 中断）强制使用 MSP
   - 用于操作系统内核、中断服务函数、系统初始化代码
2. PSP（进程栈指针）： 基础级

   - 仅线程模式可配置使用
   - 用于普通应用代码、用户任务，实现任务栈与内核栈隔离

> 补充：双栈设计的核心意义 操作系统场景下，每个用户任务拥有独立的 PSP 栈，内核异常统一使用 MSP。既避免用户栈溢出破坏内核，也保证中断响应时无需切换任务栈，提升实时性。裸机开发通常全程使用 MSP，PSP 闲置。

**2.1.2 Cortex-M4 的栈类型：满减栈**

ARM 架构标准采用满减栈（Full Descending），这是理解 PUSH/POP 行为的核心：

- 满：SP 始终指向栈中最后一个已写入的有效数据（栈顶元素）
- 减：栈向低地址方向增长，入栈时 SP 递减，出栈时 SP 递增

四种栈类型对比：


<table v-pre><tbody><tr><td>栈类型</td><td>SP 指向</td><td>入栈动作</td><td>出栈动作</td></tr><tr><td>满减栈（Cortex-M 采用）</td><td>已有数据的栈顶</td><td>先 SP 减，再写数据</td><td>先读数据，再 SP 加</td></tr><tr><td>满增栈</td><td>已有数据的栈顶</td><td>先 SP 加，再写数据</td><td>先读数据，再 SP 减</td></tr><tr><td>空减栈</td><td>下一个可写入的空位置</td><td>先写数据，再 SP 减</td><td>先 SP 加，再读数据</td></tr><tr><td>空增栈</td><td>下一个可写入的空位置</td><td>先写数据，再 SP 加</td><td>先 SP 减，再读数据</td></tr></tbody></table>


> 实操示例：`PUSH {R0}` 硬件真实行为
> 
> 1. SP = SP - 4
> 2. 将 R0 的值写入 SP 当前指向的内存地址
> 
> `POP {R0}` 硬件真实行为
> 
> 1. 读取 SP 指向的内存数据，存入 R0
> 2. SP = SP + 4

**2.1.3 栈对齐规则与常见错误**

- SP 硬件自动忽略 bit [1:0]，强制4 字节对齐
- 异常入栈时硬件要求8 字节对齐，AAPCS 标准也要求栈保持 8 字节对齐
- 若栈未对齐，访问多字节数据时可能触发 HardFault，是嵌入式最常见底层 bug 之一

### 2.2 程序计数器 R15 (PC)

PC 保存的是当前正在取指的指令地址，直接决定程序执行流向。修改 PC 的值，程序就会发生跳转。

**2.2.1 PC 与三级流水线的关系**

Cortex-M4 采用三级流水线：取指 → 译码 → 执行，三条指令同时并行处理。

- 执行阶段：当前正在执行的指令
- 译码阶段：下一条待执行的指令
- 取指阶段：再下一条指令，PC 指向此处

因此：读取 PC 寄存器得到的值 = 当前正在执行的指令地址 + 4。

> ⚠️高频易错点 很多初学者以为 PC 指向当前执行指令，实际是 + 4 偏移。这是基于流水线设计的硬件行为，不是软件约定，写汇编寻址、计算相对偏移时必须考虑该偏移，否则地址计算完全错误。

**2.2.2 PC 的对齐特性**

PC 的 bit [0] 硬件恒为 0，意味着指令地址必须至少半字（2 字节）对齐。

> 注意：BX/BLX 跳转时，目标地址的 bit [0] 不表示地址，用于通知硬件切换指令集状态。写 1 表示进入 Thumb 状态，Cortex-M 中跳转目标 bit [0] 必须为 1，否则会触发用法 Fault。

### 2.3 链接寄存器 R14 (LR)

LR 用于保存函数 / 子程序的返回地址，是函数调用机制的硬件基础。

**2.3.1 函数调用的硬件本质**

执行`BL 子程序标号`时，硬件自动完成两件事：

1. **将当前指令的下一条指令地址存入 LR 寄存器**
2. **修改 PC，跳转到子程序入口地址**

子程序**返回时，执行`BX LR`**，硬件将 LR 的值加载到 PC，程序回到调用处继续执行。

**2.3.2 LR 的覆盖问题与入栈保护**

LR 只有一个，如果子程序内部再次调用其他函数（嵌套调用），新的 BL 指令会覆盖 LR 原值，导致外层函数无法正确返回。

> 标准解决方案：进入子程序后，先将 LR 压栈保存；函数返回前从栈中弹出 LR，再执行 BX LR。 
> 
> 汇编示例：
> 
> ```Assembly language
> Func:
>     PUSH {LR}       ; 保存返回地址
>     BL  SubFunc     ; 嵌套调用，会修改LR
>     POP  {PC}       ; 弹出栈中保存的LR直接赋值给PC，等价于POP LR + BX LR
> ```

**2.3.3 异常返回的特殊 LR 值**

发生异常时，硬件自动写入的不是普通返回地址，而是固定的特殊值（EXC_RETURN），例如`0xFFFFFFF9`、`0xFFFFFFFD`等。异常服务函数退出时，检测到 LR 为该类特殊值，硬件会自动执行异常出栈、恢复现场、切换模式。这部分在「异常处理流程」章节详细展开。

## 03 特殊功能寄存器

特殊功能寄存器用于控制处理器状态、中断、特权等级，不能用普通 MOV 指令读写，必须通过 MRS/MSR 专用指令访问。

### 3.1 程序状态寄存器 xPSR

xPSR 是 32 位寄存器，按功能分为三个独立位域，可单独访问也可整体访问：

- APSR：应用程序状态寄存器，运算标志位
- IPSR：中断程序状态寄存器，当前异常编号
- EPSR：执行程序状态寄存器，指令集状态

**3.1.1 应用程序状态寄存器 APSR（核心重点）**

APSR 保存算术逻辑运算的结果标志，是所有条件跳转、条件执行的判断依据。


<table v-pre><tbody><tr><td>标志位</td><td>位号</td><td>含义</td><td>详细规则</td></tr><tr><td>N</td><td>bit31</td><td>负条件标志</td><td>运算结果为负数时置 1，正数 / 零时置 0，本质等于结果的最高位</td></tr><tr><td>Z</td><td>bit30</td><td>零条件标志</td><td>运算结果为 0 时置 1，非零时置 0</td></tr><tr><td>C</td><td>bit29</td><td>进位 / 借位标志</td><td>加法：结果产生进位则置 1；减法：发生借位则置 0（与直觉相反）</td></tr><tr><td>V</td><td>bit28</td><td>有符号溢出标志</td><td>有符号运算结果超出表示范围时置 1</td></tr><tr><td>Q</td><td>bit27</td><td>饱和标志</td><td>DSP 饱和运算发生截断时置 1，用于信号处理</td></tr></tbody></table>


> 📌深度补充
> 
> 1. 不是所有指令都会修改标志位：只有带`S`后缀的数据处理指令（如`ADDS`、`SUBS`、`CMP`）才更新 APSR；普通`ADD`、`MOV`、`LDR`默认不改变标志位。
> 2. C 标志易错点：减法借位时 C=0，无借位时 C=1。例如无符号数比较`CMP R0, R1`，若 R0 < R1 则发生借位，C=0；无符号大于等于则 C=1。
> 3. C 与 V 的区别：C 用于无符号数的进位 / 借位判断，V 用于有符号数的溢出判断，二者适用场景完全不同。

**3.1.2 中断程序状态寄存器 IPSR**

- bit [8:0] 保存当前正在响应的异常编号
- 0 表示当前处于线程模式，非 0 表示处于处理模式，数值对应异常号
- 常见异常号：复位 = 1、NMI=2、HardFault=3，外部中断从 16 开始编号
- IPSR 为只读寄存器，软件不能直接修改，由硬件自动更新

**3.1.3 执行程序状态寄存器 EPSR**

- T 位（bit24）：Thumb 状态位，Cortex-M4 中该位恒为 1，处理器只支持 Thumb 指令集，无法切换到 ARM 模式
- ICI/IT 位：用于 If-Then 条件执行块、中断续行，普通开发很少直接操作

### 3.2 异常屏蔽寄存器

用于全局开关中断、屏蔽特定优先级中断，是临界区保护的核心机制。

> 实操场景
> 
> - 裸机进入短临界区：常用 PRIMASK 关总中断，操作完成后打开
> - 操作系统精细调度：常用 BASEPRI，只屏蔽低优先级中断，保留高优先级实时中断不被阻塞
> - FAULTMASK 极少用于普通应用，多在内核 Fault 处理、调试场景使用

### 3.3 控制寄存器 CONTROL

控制处理器的特权等级和线程模式栈选择，共两个有效位：


<table v-pre><tbody><tr><td>控制位</td><td>位号</td><td>功能</td></tr><tr><td>SPSEL</td><td>bit1</td><td>线程模式栈选择：<br/>0 = 使用主栈 MSP，<br/>1 = 使用进程栈 PSP</td></tr><tr><td>nPRIV</td><td>bit0</td><td>线程模式特权级：<br/>0 = 特权级，<br/>1 = 非特权级</td></tr></tbody></table>


> ✨关键补充
> 
> 1. 复位后 CONTROL 默认值为 0：线程模式特权级，使用 MSP
> 2. SPSEL、nPRIV 仅在线程模式下生效；进入处理模式后，强制使用 MSP、特权级，CONTROL 对应位被忽略
> 3. 非特权模式下，无法修改 CONTROL、PRIMASK 等特殊寄存器，也不能直接访问部分内核外设，用于操作系统用户态隔离

### 3.4 特殊功能寄存器的访问方式

所有特殊功能寄存器（xPSR、PRIMASK、CONTROL 等）必须通过专用指令访问：

- `MRS Rn, <特殊寄存器>`：将特殊寄存器的值读到通用寄存器
- `MSR <特殊寄存器>, Rn`：将通用寄存器的值写入特殊寄存器

示例：关总中断

```text
MOVS R0, #1
MSR  PRIMASK, R0
```

**本章第一性原理汇总**

1. 运算只能发生在寄存器，内存仅用于存储，所有运算必经「加载→运算→写回」三步。
2. 栈本质是一块普通 RAM，SP 只是一个指针；PUSH/POP 等价于 SP 自增自减 + 内存读写，没有额外魔法。
3. 函数调用的硬件本质：BL 修改 LR 并跳转；函数返回本质：把 LR 赋值给 PC。
4. PC 值 = 当前执行指令地址 + 4，由三级流水线硬件决定，不是软件约定。
5. 条件跳转不做真实比较，只读取 APSR 的标志位；标志位必须由前一条带 S 后缀的指令更新。
6. 特殊功能寄存器控制处理器核心状态，只能用 MRS/MSR 访问，普通 MOV 指令无法操作。

**本章易错点与实操提醒**

1. 不要在 16 位 Thumb 指令中使用 R8\~R12，会汇编报错。
2. 嵌套函数调用必须保存 LR，否则返回地址丢失导致程序跑飞。
3. 计算 PC 相对地址时必须考虑 + 4 偏移，否则地址错误。
4. 减法借位时 C=0，无借位时 C=1，与直觉相反，无符号条件跳转务必注意。
5. 栈必须保持 4 字节对齐，推荐始终 8 字节对齐，否则可能触发 HardFault。
6. 处理模式下永远使用 MSP，修改 SPSEL 不会影响异常服务函数的栈指针。

# 处理器工作模式

## 01 处理器两种工作模式

Cortex‑M4 内核只有两种工作模式：线程模式 (Thread mode)、处理模式 (Handler mode)。

> 第一性：模式决定当前是跑普通应用代码，还是处理中断 / 异常；处理模式只能由异常触发进入，软件不能直接手动切换进入处理模式。

### 线程模式 Thread mode

- 用途：执行普通应用程序（main 函数、普通任务代码）
- 复位行为：**处理器上电复位后，默认进入线程模式**，**并且是特权级别**
- 权限控制：**可通过修改`CONTROL`寄存器，在线程模式下切换 特权 / 非特权 运行级别**
- 栈指针选择：线程模式可以选择使用 MSP（主栈）或者 PSP（进程栈），由`CONTROL.bit1(SPSSEL)`控制。

> 裸机开发：一般全程线程模式 + MSP；RTOS 操作系统：任务线程模式使用 PSP，内核使用 MSP。

### 处理模式 Handler mode

- 用途：专门用来处理异常、中断（HardFault、外部中断、SVC 等）
- 进入方式：**发生异常，硬件自动进入处理模式；软件无法直接写寄存器强行进入处理模式**
- 退出方式：异常服务函数执行完毕，执行 EXC_RETURN 特殊 LR 值，硬件自动退出处理模式，回到线程模式。
- 权限固定：处理模式永远是特权级别，不受 CONTROL 寄存器控制。
- 栈指针：进入处理模式，硬件强制使用 MSP 主栈指针，PSP 会被保存暂存。不管线程模式原来用的是 MSP 还是 PSP，进中断一律切 MSP。

> ✨关键总结模式切换： 线程模式 →【发生中断 / 异常硬件自动】→ 处理模式 处理模式 →【执行 EXC_RETURN 硬件自动】→ 线程模式

---

## 02 软件运行权限级别：特权 / 非特权

> 模式和权限是两套独立概念！
> 
> - 工作模式：线程 / 处理模式（干什么：跑应用 or 处理异常）
> - 权限级别：特权 / 非特权（能做什么：访问权限）
> 
> 只有线程模式才区分特权 / 非特权；处理模式固定特权。

### 非特权 Unprivileged

非特权，也叫用户级。线程模式下可以配置为此级别，存在访问限制：

1. 有限访问`MRS / MSR`特殊寄存器指令；完全不能使用 CPS 指令。
2. 不能直接访问内核外设：SysTick、NVIC、SCB 系统控制块。
3. 内存、外设访问会受 MPU 内存保护单元限制，部分地址空间禁止访问，访问会触发 Fault。
4. 如果非特权代码需要执行特权操作：只能通过`SVC`指令触发 SVC 软中断异常，进入处理模式（自动特权）完成操作，再返回。

> 典型使用场景：RTOS 操作系统里的用户任务，运行在非特权，防止用户代码破坏内核。裸机一般不用非特权。

### 特权 Privileged

特权级别拥有全部硬件访问权限：

1. 可以完整使用 MRS/MSR 访问 PRIMASK、FAULTMASK、CONTROL 等特殊寄存器。
2. 可以访问全部外设、内核寄存器 NVIC/SCB/SysTick。
3. 可以写 CONTROL 寄存器，修改线程模式的栈选择 SPSSEL 和权限 nPRIV。
4. 处理模式永远特权；线程模式复位默认特权。

> ⚠️重要坑：非特权模式下，你无法直接写 CONTROL 寄存器把自己切回特权！只能靠 SVC 异常，进入 Handler 模式后修改。

## 03 CONTROL 寄存器详解（衔接前面寄存器笔记）

CONTROL 寄存器有效位只有 2 位：Bit1 (SPSSEL)、Bit0 (nPRIV)

> 
> 1. CONTROL 寄存器仅在线程模式生效；一旦进入处理模式，硬件忽略 CONTROL，强制 MSP + 特权。
> 2. 非特权状态，软件不能修改 CONTROL 寄存器。

```text
ISB                ; 必须指令同步，刷新流水线
```

## 05 模式与权限切换完整流程补充

1. 复位启动 上电复位 → 硬件自动进入【线程模式，特权，MSP】，执行 main 函数。
2. 线程特权 → 线程非特权 特权线程模式写 CONTROL，nPRIV 置 1，切换为非特权。
3. 非特权想要做特权操作 非特权代码执行 `SVC #0` → 触发 SVC 异常 → 硬件进入【处理模式，特权，MSP】；在 SVC 中断服务函数完成特权操作；执行 EXC_RETURN 返回回到线程模式，回到非特权。
4. 任意线程模式发生中断 不管线程是特权 / 非特权、MSP/PSP；触发中断，硬件自动保存现场，切 MSP，进入处理模式（特权）。 中断结束执行 EXC_RETURN，硬件恢复现场，回到进入中断之前的线程模式、原来的栈、原来的特权等级。

> ❗ 误区纠正：
> 
> 1. 不能通过修改 CONTROL 寄存器进入 Handler 处理模式；处理模式只能由异常事件触发。
> 2. 进入中断一定会切 MSP，PSP 会硬件保存，中断返回自动恢复 PSP。

**第一性原理汇总**

1. 两种工作模式：线程模式跑普通应用；处理模式专门处理异常中断，只能硬件自动进入。
2. 权限等级和工作模式是两套独立概念；处理模式永远特权，不受 CONTROL 寄存器控制。
3. CONTROL 寄存器只在线程模式生效，两个 bit 分别控制栈指针选择、特权 / 非特权；非特权状态不能改写 CONTROL。
4. 非特权不能直接访问内核寄存器 MRS/MSR/NVIC；想要特权操作，只能借助 SVC 软中断异常。
5. 进入中断，硬件强制切换 MSP 栈；退出中断硬件自动恢复进入中断之前的栈、模式、权限。
6. 修改 CONTROL 之后，必须执行 ISB 指令同步流水线，配置才会真正生效。

**实操易错点**

1. 裸机项目，永远使用线程模式 + MSP 特权，不要碰非特权，否则访问 NVIC/SCB 直接 HardFault。
2. RTOS 任务切换，本质就是修改 CONTROL 的 SPSSEL 位切换 PSP 栈，保存恢复任务上下文。
3. 非特权代码想改 CONTROL 寄存器，写了也无效，不会报错，但是不会生效，需要 SVC 异常中转。
4. 忘记写 ISB 指令修改 CONTROL，会出现莫名其妙的不稳定 bug。

# 汇编语言概述

## 01 汇编语言本质

**1.1 汇编指令与机器码**

汇编指令是机器码的文本助记符，每一条真实的汇编指令，对应处理器可以直接执行的一条二进制机器码。

- 示例：`MOV R1, #2` 对应一串固定格式的二进制编码，CPU 硬件可直接译码执行
- 汇编器：**将人类可读的汇编代码，逐行翻译为二进制机器码的工具，是汇编开发的核心编译工具**

> ✨第一性原理 **汇编语言和机器码**是一一对应的（真实指令），它没有额外的抽象层，写汇编就是直接操控硬件行为。高级语言一行代码可能对应多条机器指令，而汇编一条指令就对应一条机器码。

**1.2 指令集**

指令集是处理器硬件定义的全部机器指令的集合，是软件与硬件的接口标准。 常见 ARM 指令示例：`MOV`、`ADD`、`SUB`、`CMP`、`BL`、`LDR`、`STR`。

> 补充区分：
> 
> - 架构（ARMv7-M）：定义指令集标准、寄存器模型、异常模型
> - 内核（Cortex-M4）：基于架构的硬件实现，支持对应指令集
> - 汇编器：将汇编助记符翻译为对应指令集的机器码

**1.3 真实指令与伪指令**

- 真实指令：最终会生成机器码，CPU 运行时执行，如`MOV`、`ADD`、`BL`
- 伪指令：仅给汇编器看的编译期指令，不会生成机器码，编译后消失，如`EQU`、`DCD`、`LDR Rn,=xxx`

## 02 ARM 内核三大指令集详解

ARM 架构历史演进中形成了三套主流指令集，Cortex-M4 基于 ARMv7-M 架构，仅支持 Thumb 与 Thumb-2 指令集，不支持原生 32 位 ARM 指令集—— 这是 Cortex-M 与 Cortex-A 系列最核心的区别之一。

### 2.1 ARM 指令集（32 位）

- 编码长度：所有指令固定 32 位
- 核心特点： 

  1. 指令功能强，数据处理指令可访问全部通用寄存器 R0\~R15
  2. 第二操作数支持灵活的移位操作，指令表达能力强
  3. 执行效率高，但代码密度低，占用 Flash 空间大
- 支持情况：Cortex-M 内核未实现该指令集，仅 Cortex-A 系列、早期 ARM7/ARM9 内核支持
- 适用场景：高性能应用处理器，运行大型操作系统

### 2.2 Thumb 指令集（16 位）

- 编码长度：所有指令固定 16 位
- 设计初衷：针对存储资源紧张的嵌入式场景优化，提升代码密度
- 核心特点： 

  1. 代码密度高，程序体积约为纯 ARM 代码的 65%，节省 Flash 空间
  2. 是 ARM 指令集的功能子集，复杂操作需要多条 Thumb 指令组合完成
  3. 数据处理指令只能访问低段寄存器 R0\~R7，无法直接操作 R8\~R12
  4. 立即数范围小，通常仅支持 0\~255 的 8 位立即数
  5. 不支持协处理器指令
- 支持情况：Cortex-M 全系列均支持
- 适用场景：资源极度受限的低功耗单片机，如 Cortex-M0/M0+

### 2.3 Thumb-2 指令集（16/32 位混合）

- 编码长度：16 位窄指令与 32 位宽指令混合使用，汇编器自动选择
- 定位：T**humb 指令集的升级扩展，兼顾代码密度与执行效率，是 Cortex-M3/M4/M7 的主力指令集**
- 核心特点： 

  1. 实现了绝大多数 ARM 指令集的功能，能力接近原生 32 位 ARM 指令
  2. 32 位宽指令可访问全部通用寄存器 R0\~R12，支持大立即数、灵活移位
  3. 常用功能用 16 位指令保证密度，复杂功能用 32 位指令保证效率
  4. 综合性能：代码密度比纯 ARM 指令高约 26%，执行效率比纯 Thumb 指令高约 25%
  5. Cortex-M4 在此基础上扩展了 DSP 指令、SIMD 指令，带 FPU 版本还支持硬件浮点指令

## 03 UAL 统一汇编语言规范

### 3.1 为什么需要 UAL

早期 ARM、Thumb、Thumb-2 指令集的汇编语法不统一，同一种操作在不同指令集下写法不同，增加了学习和迁移成本。 ARM 公司推出 **UAL（Unified Assembly Language，统一汇编语言**），提供一套通用语法，开发者无需区分底层指令集，由汇编器自动根据目标架构生成对应的 16 位或 32 位指令。

### 3.2 位宽后缀：.N 与 .W

UAL 语法下，可通过后缀手动强制指令位宽，也可省略由汇编器自动优化：

- 无后缀：`MOV R1, #55`，汇编器自动选择最优位宽，优先 16 位，16 位无法实现则自动用 32 位
- `.N`（Narrow，窄指令）：`MOV.N R1, #55`，强制生成 16 位 Thumb 指令，若操作数超出 16 位编码能力则汇编报错
- `.W`（Wide，宽指令）：`MOV.W R9, #0x55005500`，强制生成 32 位 Thumb-2 指令，即使功能可由 16 位实现也强制 32 位编码

> 💡实操建议 绝大多数开发场景不需要手动加后缀，让汇编器自动优化即可；仅在需要精确控制指令长度、地址对齐、指令占位等特殊场景，才手动指定.N 或.W。

### 3.3 UAL 的优势

1. 一套语法兼容 Thumb/Thumb-2/ARM 指令集，降低学习成本
2. 汇编器自动做位宽优化，开发者专注逻辑，不用纠结编码细节
3. 代码可移植性强，在不同 ARM 内核间迁移修改量小

## 04 补充：指令集状态与 T 位

衔接前文程序状态寄存器 EPSR 的 T 位，从硬件层面理解指令集切换：

1. xPSR 的 T 位（bit24）：指示当前处理器的指令集状态 

   - T=0：ARM 指令集状态
   - T=1：Thumb/Thumb-2 指令集状态
2. Cortex-M4 硬件固定 T 位恒为 1，永久运行在 Thumb 状态，无法切换到 ARM 指令集状态
3. 跳转指令`BX`/`BLX`中，目标地址的 bit0 不表示地址偏移，用于更新 T 位；Cortex-M 中跳转目标 bit0 必须为 1，否则会触发用法 Fault
4. 这也是 Cortex-M 不支持 ARM 指令集的硬件根源：内核物理上就没有 ARM 指令译码电路

## 本章第一性原理汇总

1. 汇编指令是机器码的文本助记符，一条真实汇编指令对应一条机器码，由汇编器翻译生成。
2. Cortex-M4 仅支持 Thumb 和 Thumb-2 指令集，不支持原生 32 位 ARM 指令集，T 位恒为 1，永久运行在 Thumb 状态。
3. 指令集的能力限制本质是编码位数限制：16 位编码空间小，只能访问低段寄存器、小立即数；32 位编码空间大，功能更强。
4. Thumb 是 16 位窄指令，代码密度高但功能受限；Thumb-2 是 16/32 混合指令集，兼顾密度与性能，是 Cortex-M4 的主力指令集。
5. UAL 统一汇编语法让开发者无需手动区分位宽，汇编器自动优化；.N/.W 后缀仅用于强制指定位宽，日常开发极少使用。

## 本章易错点与实操提醒

1. ❌ 不要直接照搬 Cortex-A、ARM9 的 ARM 指令集代码到 STM32，绝大多数会汇编报错，因为 M4 内核不支持 ARM 指令。
2. ❌ 不要默认所有指令都能访问 R8\~R12，纯 16 位 Thumb 指令只能使用 R0\~R7；复杂操作建议省略后缀，让汇编器自动选择 32 位宽指令。
3. ✅ 日常写汇编无需加.N/.W 后缀，汇编器会自动选择最优编码，手动指定反而可能限制优化效果。
4. ✅ 遇到 “非法立即数” 报错，优先考虑是 16 位指令立即数超限；可改用`LDR Rn,=常量`伪指令加载任意 32 位数值。
5. ✅ 汇编函数、跳转目标的地址必须保证 bit0 为 1，否则会触发用法 Fault；C 语言调用汇编函数时，编译器会自动处理该属性。

# 数据处理指令

所有数据处理指令仅在 CPU 寄存器内部完成运算，不访问内存；内存数据必须先通过 LDR 加载到寄存器，才能参与运算。

## 01 数据搬移指令

数据搬移是汇编最基础的操作，核心功能是在寄存器之间传递数据、将立即数加载到寄存器，不做算术逻辑运算。

### 1.1 MOV 数据传送指令

功能：将源操作数（立即数 / 寄存器）复制到目标寄存器，源操作数本身不变。

#### 1.1.3 MOVW / MOVT 双指令加载 16 位立即数

这是 Thumb-2 专门用于构造 32 位常数的指令组合，是工程中加载任意 32 位立即数的标准方案之一。

- MOVW：`MOVW{cond} <Rd>, #imm16` **将 16 位立即数写入 Rd 的低 16 位，高 16 位自动清零**。
- MOVT：`MOVT{cond} <Rd>, #imm16` **将 16 位立即数写入 Rd 的高 16 位，低 16 位保持不变**。

> ✅ 构造任意 32 位立即数示例
> 
> ```Assembly language
> MOVW R0, #0x1234    ; R0 = 0x00001234
> MOVT R0, #0x5678    ; R0 = 0x56781234
> ```

> - 16 位常数用`MOVW`
> - 32 位任意常数优先`LDR Rn,=xxx`，汇编器会自动优化：合法立即数转 MOV，16 位转 MOVW，否则用常量池。

### 1.2 MVN 按位取反 传送指令

功能：将源操作数按位取反后写入目标寄存器，即 `Rd = ~Src`。

**指令格式**

- Thumb：`MVN <Rd>, <Rm>` / `MVNS <Rd>, <Rm>`（仅寄存器操作）
- Thumb-2：支持立即数、寄存器移位，格式同 MOV

**典型应用场景**

1. 构造全 1 常数：`MVN R0, #0` → R0 = 0xFFFFFFFF，等价于`MOV R0, #-1`
2. 配合位操作：快速生成特定位为 0 的掩码，例如`MVN R1, #0x0F`生成低 4 位为 0、其余为 1 的掩码
3. 替代非法立即数：部分无法直接 MOV 的常数，可以通过 MVN 取反得到

### 1.3 搬移指令高频易错点

1. ❌ 16 位 Thumb 指令不能操作 R8\~R12，必须用 Thumb-2 宽指令
2. ❌ `MOV R0, #0x101` 汇编报错：16 位指令立即数超限，且不属于 Thumb-2 合法立即数
3. ❌ 混淆 MOV 与 LDR：MOV 只能寄存器→寄存器、立即数→寄存器，不能从内存读数据，内存读取必须用 LDR
4. ✅ MOVT 只改高 16 位，不会影响低 16 位；MOVW 会自动清零高 16 位

- V：有符号运算溢出则置 1

### 2.2 SUB 减法指令

功能：被减数减去减数，结果存入目标寄存器。

**分类与格式**

与 ADD 对称，分为立即数减法、寄存器减法、SP 相关减法三类。

**⚠️ 减法 C 标志的核心易错点**

减法的进位标志 C 含义与加法完全相反，是嵌入式汇编最高频坑点：

- 加法：产生进位 → C=1
- 减法：发生借位（被减数 < 减数） → C=0；无借位 → C=1

> 举例：`SUBS R0, R1, R2`
> 
> - 若 R1 ≥ R2：无借位，C=1
> - 若 R1 < R2：有借位，C=0
> 
> 对应无符号比较：C=1 代表大于等于，C=0 代表小于。

### 2.3 ADC 带进位加法 / SBC 带借位减法

这两条指令是为**大于 32 位的大数运算设计的**，利用 APSR 的 C 标志位传递进位 / 借位，**实现 64 位、128 位等任意长度整数运算**。

**2.3.1 ADC 带进位加法**

- 功能：`Rd = Rn + Op2 + C`，两个操作数相加后，再加上上一次运算留下的进位标志 C
- 典型用途：64 位加法的高 32 位运算

> ✅ 64 位加法完整示例 计算 0x1FFFFFFFF + 0x100000002 = 0x300000001
> 
> ```Assembly language
> ; 低32位运算：R1 = 0xFFFFFFFF + 0x00000002
> MOVS R0, #0xFFFFFFFF
> MOVS R1, #0x2
> ADDS R1, R1, R0    ; 低32位相加，结果0x00000001，产生进位C=1
> 
> ; 高32位运算：R3 = 0x1 + 0x1 + C
> MOVS R2, #0x1
> MOVS R3, #0x1
> ADC  R3, R3, R2    ; 高32位加进位，结果0x3
> 
> ; 最终64位结果：R3(高):R1(低) = 0x300000001
> ```

**2.3.2 SBC 带借位减法**

- 功能：`Rd = Rn - Op2 - !C`，被减数减去减数，再减去借位标志的反码
- 本质：C=0 表示有借位，所以要多减 1；C=1 表示无借位，不减
- 典型用途：64 位减法的高 32 位运算

> ✅ 64 位减法完整示例 计算 0x200000001 - 0x100000002 = 0x0FFFFFFFF
> 
> ```Assembly language
> ; 低32位运算：R1 = 0xFFFFFFFF + 0x00000002
> MOVS R0, #0xFFFFFFFF
> MOVS R1, #0x2
> ADDS R1, R1, R0    ; 低32位相加，结果0x00000001，产生进位C=1
> 
> ; 高32位运算：R3 = 0x1 + 0x1 + C
> MOVS R2, #0x1
> MOVS R3, #0x1
> ADC  R3, R3, R2    ; 高32位加进位，结果0x3
> 
> ; 最终64位结果：R3(高):R1(低) = 0x300000001
> ```

### 2.4 RSB 反向减法

- 功能：`Rd = Op2 - Rn`，用第二操作数减去第一操作数，与 SUB 顺序相反
- Thumb 仅支持`RSB <Rd>, <Rn>, #0`，即对 Rn 取负
- Thumb-2 支持立即数、寄存器移位，功能完整

**典型用途：快速取负**

`RSBS R0, R0, #0` 等价于 `R0 = -R0`，是标准的整数取负汇编实现。

## 03 逻辑运算指令

逻辑运算按位操作，是寄存器位操作、外设寄存器配置的核心指令。

### 3.1 AND 按位与

- 功能：`Rd = Rn & Op2`，对应位同时为 1 结果才为 1
- 核心用途：屏蔽位、清零特定位、保留指定位
- 示例：`ANDS R0, R0, #0x0F` → 保留 R0 低 4 位，其余位全部清零

### 3.2 ORR 按位或

- 功能：`Rd = Rn | Op2`，对应位有一个为 1 结果就为 1
- 核心用途：置位特定位
- 示例：`ORR R0, R0, #(1<<5)` → 将 R0 的第 5 位置 1，其余位不变

### 3.3 EOR 按位异或

- 功能：`Rd = Rn ^ Op2`，对应位不同则为 1，相同则为 0
- 核心用途：翻转特定位、交换两个寄存器值
- 示例 1：`EOR R0, R0, #0xFF` → 翻转 R0 低 8 位
- 示例 2：不借助第三寄存器交换 R0 和 R1 

```text
EOR R0, R0, R1
EOR R1, R0, R1
EOR R0, R0, R1
```

### 3.4 BIC 位清零指令

- 功能：`Rd = Rn & (~Op2)`，**将源操作数取反后再做与运算**
- 核心用途：清零指定的位，比 AND + 取反更高效
- 示例：`BIC R0, R0, #0x0F` → 清零 R0 低 4 位，其余位不变

### 3.5 ORN 或非指令（仅 Thumb-2指令集）

- 功能：`Rd = Rn | (~Op2)`，第二操作数取反后做或运算
- 用途：将指定位置为 1 的补集操作，实际开发使用频率较低

### 3.6 位操作四大标准手法（实操必备）

**逻辑运算标志位说明（带 S 后缀）**

- N、Z：正常更新，与算术指令一致
- C：由第二操作数的移位器更新，无移位则不变
- V：逻辑运算不会改变 V 标志，保持原值

## 04 测试比较指令

比较指令本质是做一次算术 / 逻辑运算，**但只更新 APSR 标志位，不保存运算结果，专门为条件跳转、条件执行服务**。

### 4.1 CMP 比较指令

- 功能：执行 `Rn - Op2`，结果丢弃，仅更新 **N/Z/C/V** 标志位
- 等价于`SUBS`但不保存结果
- 用途：判断两个数的大小关系，配合条件跳转使用
- 示例： 

```text
CMP R0, #10   ; 比较R0和10
BEQ label     ; 如果相等(Z=1)则跳转
```

### 4.2 CMN 反相比较指令

- 功能：执行 `Rn + Op2`，结果丢弃，仅更新标志位
- 等价于`ADDS`但不保存结果
- 用途：比较一个数和另一个数的负数，常用于和负数比较

### 4.3 TST 位测试指令

- 功能：执行 `Rn & Op2`，结果丢弃，仅更新 N/Z/C 标志位
- 等价于`ANDS`但不保存结果
- 用途：测试寄存器中某一位或某几位是否为 0
- 示例：`TST R0, #(1<<5)` → 若 bit5 为 0 则 Z=1，非 0 则 Z=0

### 4.4 TEQ 相等测试指令

- 功能：执行 `Rn ^ Op2`，结果丢弃，仅更新 N/Z 标志位
- 用途：测试两个数是否相等，同时不影响 V 标志；也可用于测试符号位是否相同

### 4.5 条件码表详解（核心重点）

所有数据处理指令、跳转指令都支持条件执行，条件判断完全依赖 APSR 的标志位。必须区分无符号数和有符号数两套条件体系。

### 4.6 IT 条件执行块补充

原文多次提到 “在 IT 控制块内使用”，此处做前置说明：

- Thumb-2 支持 IT（If-Then）指令块，可让块内最多 4 条指令条件执行，无需跳转
- IT 块内的指令默认不更新标志位，IT 块外的指令若要更新标志位必须加 S 后缀
- 该机制用于短小的条件分支，比跳转更高效，后续分支跳转章节会详细讲解

## 05 移位指令

移位指令是 ARM 指令集的特色功能，硬件内置桶形移位器，移位操作零额外时钟开销。移位既可以作为独立指令，也可以作为数据处理指令的第二操作数。

### 5.1 移位指令总览


<table v-pre><tbody><tr><td>指令</td><td>名称</td><td>移出位去向</td><td>移入位</td><td>典型用途</td></tr><tr><td>LSL</td><td>逻辑左移</td><td>进入 C 标志</td><td>低位补 0</td><td>无符号数乘 2^n</td></tr><tr><td>LSR</td><td>逻辑右移</td><td>进入 C 标志</td><td>高位补 0</td><td>无符号数除 2^n</td></tr><tr><td>ASR</td><td>算术右移</td><td>进入 C 标志</td><td>高位补符号位</td><td>有符号数除 2^n</td></tr><tr><td>ROR</td><td>循环右移</td><td>进入 C 标志</td><td>低位循环到高位</td><td>循环位移、位域操作</td></tr><tr><td>RRX</td><td>带扩展位右移</td><td>进入 C 标志</td><td>C 位移入最高位</td><td>33 位循环移位、大数移位</td></tr></tbody></table>


### 5.2 LSL 逻辑左移

- 功能：各位向左移动 N 位，低位补 0，最高位移入 C 标志
- 数学意义：无符号数乘以 2^N
- 示例：`LSLS R0, R0, #2` → R0 = R0 × 4

### 5.3 LSR 逻辑右移

- 功能：各位向右移动 N 位，高位补 0，最低位移入 C 标志
- 数学意义：无符号数除以 2^N，向下取整
- 示例：`LSRS R0, R0, #1` → R0 = R0 / 2（无符号）

### 5.4 ASR 算术右移

- 功能：各位向右移动 N 位，最高位保持符号位不变，最低位移入 C 标志
- 数学意义：有符号数除以 2^N，向负无穷取整
- 关键区别：负数时高位补 1，保证符号不变，这是和 LSR 的核心差异

### 5.5 ROR 循环右移

- 功能：各位向右移动 N 位，低位从最高位重新移入，最低位移入 C 标志
- 特点：32 位闭环移动，位不会丢失

### 5.6 RRX 带扩展循环右移（仅 Thumb-2指令集）

- 功能：仅右移 1 位，C 标志移入最高位，最低位移入 C 标志
- 本质：33 位（32 位寄存器 + C 标志）的循环右移 1 位
- 用途：配合大数运算，实现 64 位联合移位

### 5.7 核心补充：第二操作数灵活移位（桶形移位器）

ARM 指令集最具特色的设计：所有数据处理指令的第二操作数，都可以先经过桶形移位器移位，再参与运算，不额外消耗时钟周期。

**语法格式**

```text
<指令> <Rd>, <Rn>, <Rm>, <移位类型> #<移位位数>
```

**常用示例**

```text
; R0 = R1 + R2 * 4
ADD R0, R1, R2, LSL #2

; R0 = R1 & (~(R3 << 4))
BIC R0, R1, R3, LSL #4

; 测试R0的第8位
TST R0, #1, LSL #8
```

> ✨ 硬件意义 
> 
> 桶形移位器是 ALU 的前置模块，移位和运算在同一个时钟周期完成。这也是 ARM 代码效率高的重要原因之一，无需单独写移位指令。

## 06 其他数据处理指令

### 6.1 CLZ 前导零计数指令（仅 Thumb-2）

- 功能：统计寄存器数值从最高位开始，连续 0 的个数，结果存入 Rd
- 语法：`CLZ{cond} <Rd>, <Rm>`
- 示例：`CLZ R0, R1` → 若 R1=0x0000FFFF，则 R0=16

**典型应用场景**

1. 快速计算整数的有效位数、近似对数运算
2. 快速查找最高位为 1 的位置
3. 内存对齐计算、位扫描算法
4. 调度算法中的优先级快速计算

---

**本章第一性原理汇总**

1. 所有数据处理指令仅操作寄存器，不访问内存；内存数据必须先加载再运算。
2. 指令加 S 后缀才会更新 APSR 标志位；比较指令天然更新标志位，无需加 S。
3. 减法的 C 标志含义与加法相反：借位时 C=0，无借位时 C=1，是无符号比较的核心依据。
4. ADC/SBC 利用 C 标志传递进位 / 借位，可实现任意长度的大数运算。
5. 第二操作数移位是 ARM 硬件特色，零额外开销，是代码优化的重要手段。
6. 条件判断分无符号（C/Z）和有符号（N/V）两套体系，不可混用。
7. 16 位 Thumb 指令能力受编码限制，仅支持低寄存器、小立即数；Thumb-2 宽指令功能完整。

**本章高频易错点**

1. ❌ 混淆 MOV 与 LDR：MOV 不能读内存，内存访问必须用 LDR/STR
2. ❌ 减法 C 标志记反：无符号小于对应 C=0，不是 C=1
3. ❌ 有符号比较用了无符号条件码，或反之，导致判断完全错误
4. ❌ 16 位 Thumb 指令操作 R8\~R12 导致汇编报错
5. ❌ 认为移位指令必须单独写，忽略第二操作数可以直接移位
6. ❌ 忘记加 S 后缀，导致条件跳转判断的标志位没更新，程序逻辑异常

**实操练习建议**

1. 用 MOV、ADD、SUB 写简单的四则运算，单步调试观察寄存器和 APSR 变化
2. 手动实现 64 位加法、减法，验证 ADC/SBC 和 C 标志行为
3. 练习位操作四大手法：置位、清零、翻转、测试
4. 写 CMP + 条件跳转的简单分支，验证各条件码的触发条件
5. 对比 MOVW+MOVT 和 LDR 伪指令生成的机器码差异

# 分支跳转指令

任何跳转指令的最终效果都是修改 PC 寄存器；不同跳转指令的差异仅在于：是否保存返回地址、是否切换指令集状态、跳转目标是标号还是寄存器。

## 01 B 跳转指令（分支跳转）

### 1.1 指令功能与语法

B 是最基础的跳转指令，直接修改 PC 跳转到目标地址，不保存返回地址，不切换指令集状态。 语法格式：

```text
B{<cond>} label    ; 跳转到label标号处
```

- `cond`：可选条件码，和前文条件码完全一致（EQ/NE/CS/CC 等），省略则为无条件跳转
- `label`：汇编标号，汇编器自动计算相对于当前 PC 的偏移量

### 1.2 两种跳转形式

#### 1.2.1 无条件跳转 B

不判断任何条件，直接跳转，等价于高级语言的`goto`。 示例：

```text
B start       ; 无条件跳转到start标号
MOV R0, R1    ; 不会执行
ADD R0, #1
start:
    CMP R0, R1
```

#### 1.2.2 条件跳转 B {cond}

根据 APSR 的标志位决定是否跳转，是实现 if、while、for 等分支循环的基础。 必须配合能更新标志位的指令使用（如 CMP、CMN、TST、带 S 后缀的数据处理指令）。 示例：

```text
CMP R0, #10    ; 比较R0和10，更新标志位
BEQ equal      ; 如果相等(Z=1)，跳转到equal
B not_equal    ; 否则跳转到not_equal
equal:
    MOV R1, #1
not_equal:
    MOV R1, #0
```

### 1.3 底层原理：相对寻址

B 指令是PC 相对寻址，机器码中存储的是跳转偏移量，不是绝对地址。

- 优势：生成的代码位置无关（PIC），程序在内存中任意位置都能正确运行
- 偏移计算基准：以当前指令的 PC 值（当前指令地址 + 4，三级流水线特性）为基准
- 跳转方向：可以向前跳，也可以向后跳

### 1.4 跳转范围补充（高频实操知识点）

受指令编码位数限制，不同格式的 B 指令跳转范围不同：


<table v-pre><tbody><tr><td>指令格式</td><td>编码长度</td><td>跳转范围</td><td>说明</td></tr><tr><td>B.N（16 位 Thumb）</td><td>16 位</td><td>±2KB</td><td>短距离跳转，超出范围汇编报错</td></tr><tr><td>B.W（32 位 Thumb-2）</td><td>32 位</td><td>±16MB</td><td>长距离跳转，汇编器自动选择</td></tr></tbody></table>


> 💡 实操说明： 写代码时无需手动加.N/.W 后缀，汇编器会自动根据跳转距离选择最优编码；如果短跳转超出范围，汇编器会自动升级为 32 位宽指令。

### 1.5 注意事项

1. 条件跳转必须依赖前置指令更新的标志位，标志位不会自动保持，中间不能插入修改标志位的指令
2. B 指令不会修改 LR 寄存器，跳转后无法直接返回，适合同函数内的分支、循环
3. Cortex-M 中 B 跳转目标地址 bit0 必须为 1，保持 Thumb 状态，汇编器处理标号时会自动处理

## 02 BL 跳转指令（带链接跳转 / 函数调用）

### 2.1 指令功能与语法

BL = Branch with Link，带链接的跳转，是ARM 汇编函数调用的标准指令。 语法格式：

```text
BL{<cond>} label    ; 带链接跳转到label标号处
```

### 2.2 硬件执行流程（核心原理）

执行 BL 指令时，硬件自动完成两步操作：

1. 保存返回地址：将当前指令的下一条指令地址存入 LR (R14) 寄存器
2. 跳转：修改 PC 寄存器，跳转到目标标号处执行

> 对应高级语言：调用一个函数。BL 对应函数调用，`BX LR`对应函数返回。

### 2.3 典型函数调用示例

```text
; 主程序
BL func2        ; 调用func2函数，返回地址自动存入LR
MOV R0, #1      ; 函数返回后从这里继续执行

; 子程序
func2:
    MOV R1, #2
    BX LR       ; 函数返回：把LR的值加载到PC
```

### 2.4 跳转范围

- 16 位 Thumb 无 BL 指令，BL 原生就是 32 位 Thumb-2 指令
- 跳转范围：±16MB，足够覆盖绝大多数单片机程序空间
- 同样是 PC 相对寻址，位置无关

### 2.5 核心易错点：LR 覆盖问题

LR 寄存器只有一个，如果函数内部再次调用其他函数（嵌套调用），新的 BL 指令会覆盖原来的 LR 值，导致外层函数无法正确返回。

> ✅ 标准解决方案：函数入口先将 LR 压栈保存，返回前弹出。

asm

```text
func1:
    PUSH {LR}       ; 保存返回地址到栈
    BL func2        ; 嵌套调用，会修改LR
    POP {PC}        ; 弹出栈中保存的返回地址，直接赋值给PC，等价于POP LR + BX LR
```

### 2.6 补充说明

1. BL 指令不会切换指令集状态，始终保持 Thumb 状态
2. 条件 BL 可以实现条件函数调用，满足条件才调用函数
3. 高级语言中的函数调用，编译后底层几乎都是 BL 指令实现

---

## 03 BX 跳转指令（带状态切换的寄存器跳转）

### 3.1 指令功能与语法

BX = Branch and eXchange，跳转到寄存器存储的绝对地址，并且可以切换指令集状态。 语法格式：

```text
BX{<cond>} Rn     ; 跳转到Rn寄存器保存的地址处
```

- 跳转目标不是标号，是通用寄存器中存储的地址值
- Rn 的 bit0 不表示地址偏移，用于指示目标指令集状态

### 3.2 指令集切换规则

Rn 寄存器的最低位（bit [0]）决定跳转后的指令集状态：

- bit0 = 0：切换（或保持）为 ARM 指令集状态
- bit0 = 1：切换（或保持）为 Thumb 指令集状态

### 3.3 Cortex-M4 硬性约束

Cortex-M4 内核仅支持 Thumb 指令集，永久处于 Thumb 状态，因此：

> ⚠️ 强制要求：所有 BX 跳转的目标地址 bit0 必须为 1，否则会触发用法 Fault，程序崩溃。

汇编器处理标号时会自动将 bit0 置 1；但如果是手动写地址、函数指针，必须注意给地址加 1。

### 3.4 两大核心用途

**3.4.1 函数返回（最常用）**

`BX LR`是 ARM 标准的函数返回指令，将 LR 中保存的返回地址赋值给 PC，回到调用处。

```text
BX LR   ; 函数返回，跳转到LR存储的返回地址
```

**3.4.2 函数指针跳转**

跳转到寄存器中动态计算的地址，是 C 语言函数指针的底层实现。

```text
MOV R0, #func_addr   ; R0中存放函数入口地址
BX R0                ; 跳转到R0指向的函数
```

### 3.5 特点补充

1. 绝对跳转：目标地址在寄存器中，可以跳转到 4GB 地址空间的任意位置，没有范围限制
2. 不保存返回地址，不会修改 LR
3. 是唯一可以切换指令集状态的基础跳转指令

---

## 04 BLX 跳转指令（带链接 + 状态切换）

### 4.1 指令功能与语法

BLX = Branch with Link and eXchange，相当于 BL + BX 的组合：**保存返回地址到 LR，跳转到寄存器中的地址，同时切换指令集状态**。 

语法格式：

```text
BLX{<cond>} Rm    ; 带链接跳转到Rm保存的地址，切换指令集
```

### 4.2 硬件执行流程

1. 将下一条指令地址存入 LR 寄存器
2. 根据 Rm 的 bit0 切换指令集状态
3. 修改 PC，跳转到 Rm 指向的地址

### 4.3 核心用途

1. 调用不同指令集的函数指针：早期 ARM 芯片中 ARM 状态调用 Thumb 函数、Thumb 调用 ARM 函数
2. Cortex-M 中调用函数指针：虽然不需要切换状态，但 BLX 是寄存器间接调用的标准方式，硬件会自动处理 bit0

### 4.4 注意事项

1. 同样存在 LR 覆盖问题，嵌套调用必须压栈保护 LR
2. Cortex-M 中目标地址 bit0 必须为 1，否则触发 Fault
3. 跳转目标是寄存器中的绝对地址，无范围限制

## 05 IT 控制块指令（If-Then 条件执行块）

### 5.1 指令功能与设计意义

IT 指令是 Thumb-2 的特色功能，用于构造一个条件执行块，让块内的指令根据条件决定是否执行，不需要跳转，不会冲刷流水线。

- 优势：短小的 if-else 分支用 IT 实现，避免分支预测失败，性能更高，代码密度更好
- 限制：IT 块最多包含 4 条指令

### 5.2 语法格式

```text
IT{T|E}{T|E}{T|E}  <cond>
```

- 基础：`IT <cond>` 对应 1 条条件指令（默认 Then 分支）
- 后缀：每增加一个 T 或 E，就多一条指令，最多加 3 个，总共最多 4 条指令 

  - `T`（Then）：条件成立时执行该指令，指令条件与 IT 条件一致
  - `E`（Else）：条件不成立时执行该指令，指令条件与 IT 条件相反

### 5.3 IT 块长度与对应格式


<table v-pre><tbody><tr><td>IT 指令</td><td>指令数量</td><td>分支结构</td></tr><tr><td>IT cond</td><td>1 条</td><td>单 if</td></tr><tr><td>ITE cond</td><td>2 条</td><td>if-else</td></tr><tr><td>ITTE cond</td><td>3 条</td><td>if 两条 + else 一条</td></tr><tr><td>ITTEE cond</td><td>4 条</td><td>if 两条 + else 两条</td></tr></tbody></table>


### 5.4 使用规则

1. 指令必须加条件后缀：IT 块内的每一条指令，都必须加上对应的条件码后缀
2. T 对应原条件：T 位置的指令，条件码和 IT 的条件一致
3. E 对应反条件：E 位置的指令，条件码是 IT 条件的相反条件
4. 数量严格匹配：IT 后缀的字母数量 + 1 = 块内指令数量，不能多也不能少

### 5.5 典型示例

**示例 1：if-else 两分支（ITE）**

C 语言逻辑：

```c
if (r0 == 0) {
    r1 += 1;
} else {
    r2 += 1;
}
```

汇编实现（IT 方案，无跳转）：

```text
CMP R0, #0
ITE EQ          ; if-then-else，条件EQ，共2条指令
ADDEQ R1, R1, #1   ; T：条件成立执行，EQ
ADDNE R2, R2, #1   ; E：条件不成立执行，NE
```

对比普通跳转方案：

```text
CMP R0, #0
BNE else
ADD R1, R1, #1
B end
else:
ADD R2, R2, #1
end:
```

> IT 方案代码更短，无跳转无流水线冲刷，短分支性能更优。

**示例 2：4 指令 IT 块（ITTEE）**

C 语言逻辑：

```c
if (r0 == 0) {
    r0 = *r1;
    r0 += 2;
} else {
    r0 = *r2;
    r0 += 4;
}
```

汇编实现：

```text
CMP R0, #0
ITTEE EQ
LDREQ R0, [R1]
ADDEQ R0, #2
LDRNE R0, [R2]
ADDNE R0, #4
```

### 5.6 适用场景与限制

**适合用 IT 的场景**

1. 1\~4 条指令的短小分支
2. 对性能要求极高的热点代码，避免分支预测失败
3. 代码空间极度受限的场景，压缩代码体积

**不适合用 IT 的场景**

1. 分支内指令超过 4 条
2. 分支内有跳转、函数调用
3. 分支内需要更新标志位（IT 块内更新标志位有严格限制，容易出错）

### 5.7 高频易错点

1. ❌ IT 块内的指令忘记加条件后缀，汇编报错
2. ❌ T/E 的数量和指令数量不匹配，比如 ITE 后面写了 3 条指令
3. ❌ 条件后缀写反，E 位置写成原条件，T 位置写成反条件
4. ❌ IT 块内指令超过 4 条，汇编不支持
5. ❌ 在 IT 块内修改标志位，导致后续逻辑异常

### 5.8 补充：IT 块与标志位

- IT 块内的数据处理指令，默认行为与 IT 块外相反：默认不更新标志位
- 如果需要更新标志位，必须显式加 S 后缀，但仅最后一条指令允许更新标志位，前面的指令不可以
- 实际开发中，强烈建议不要在 IT 块内更新标志位，避免逻辑混乱

---

**本章第一性原理汇总**

1. 所有跳转指令的本质都是修改 PC 寄存器；区别仅在于是否存返回地址、是否切状态、目标是标号还是寄存器。
2. B/BL 是 PC 相对寻址，位置无关，有跳转范围限制；BX/BLX 是寄存器绝对寻址，无范围限制。
3. BL 是函数调用的硬件基础，自动保存返回地址到 LR；BX LR 是标准函数返回。
4. 跳转目标地址的 bit0 用于切换指令集状态；Cortex-M 中必须为 1，否则触发 Fault。
5. IT 条件执行块通过指令级条件执行避免跳转，适合短分支，性能更优，最多 4 条指令。
6. 嵌套函数调用必须压栈保护 LR，否则返回地址被覆盖，程序跑飞。

**本章高频易错点**

1. ❌ 条件跳转前没有更新标志位的指令，导致跳转逻辑随机错误
2. ❌ 嵌套调用忘记压栈保存 LR，函数返回后跑飞
3. ❌ 手动写跳转地址忘记加 1，bit0 为 0 触发 HardFault
4. ❌ IT 块内指令不加条件后缀，或数量、条件不匹配
5. ❌ 混淆 B 和 BL，用 B 调用函数导致无法返回
6. ❌ 认为 BL 可以跳转到任意地址，超出相对跳转范围导致汇编报错

**实操练习建议**

1. 用 CMP+Bxx 实现 if-else、while 循环，单步观察 PC 和标志位变化
2. 写一个简单的嵌套函数调用，验证 PUSH LR/POP PC 的执行效果
3. 分别用跳转和 IT 实现同一个短分支，对比生成的机器码长度和执行流程
4. 尝试用函数指针的方式调用函数，反汇编查看底层是否为 BLX 指令

# 内存访问指令

Cortex-M4 没有专门的 IO 指令，所有外设、内存、Flash 的读写，唯一途径就是 LDR/STR 家族指令；数据处理指令只能操作寄存器，永远无法直接读写内存。

## 01 LDR/STR 单寄存器内存访问指令

### 1.1 指令总览

LDR（Load）：从内存读取数据到寄存器；

STR（Store）：将寄存器数据写入内存。 通用语法：

```text
LDR{<size>}{<cond>}  Rd, <address>   ; 内存 → 寄存器
STR{<size>}{<cond>}  Rd, <address>   ; 寄存器 → 内存
```

- `size`：数据宽度，省略默认字（32 位）
- `cond`：可选条件码，满足条件才执行内存访问
- `address`：内存地址，支持多种灵活的寻址方式

### 1.2 按数据宽度分类

Cortex-M4 支持字节、半字、字、双字四种宽度，读取还区分有符号 / 无符号扩展。


<table v-pre><tbody><tr><td>指令</td><td>宽度</td><td>功能</td><td>寄存器行为</td></tr><tr><td>LDR / STR</td><td>32 位 字</td><td>读写一个字（4 字节）</td><td>读写完整 32 位寄存器</td></tr><tr><td>LDRH / STRH</td><td>16 位 半字</td><td>读写一个半字（2 字节）</td><td>STRH 只取寄存器低 16 位；LDRH 高位自动补 0</td></tr><tr><td>LDRB / STRB</td><td>8 位 字节</td><td>读写一个字节（1 字节）</td><td>STRB 只取寄存器低 8 位；LDRB 高位自动补 0</td></tr><tr><td>LDRSB</td><td>8 位 有符号字节</td><td>读取有符号字节</td><td>高位全部填充符号位（bit7），扩展为 32 位有符号数</td></tr><tr><td>LDRSH</td><td>16 位 有符号半字</td><td>读取有符号半字</td><td>高位全部填充符号位（bit15），扩展为 32 位有符号数</td></tr><tr><td>LDRD / STRD</td><td>64 位 双字</td><td>读写两个连续字（8 字节）</td><td>操作 Rd 和 Rd+1 两个连续寄存器</td></tr></tbody></table>


> ✨ 核心补充：为什么只有读有符号，写没有？ 写内存时只取寄存器低位对应宽度，高位不影响；读入 32 位寄存器时，无符号数需要高位补 0，有符号数需要高位补符号位，因此读指令区分 SB/SH，写指令不需要。

示例：

```text
LDRB  R0, [R1]    ; 读取R1指向的1字节，高位补0存入R0
STRB  R0, [R1]    ; 将R0低8位写入R1指向的内存
LDRSB R0, [R1]    ; 读取1字节有符号数，符号扩展为32位存入R0
```

### 1.3 四大寻址方式详解

LDR/STR 的地址计算非常灵活，按是否更新基址、偏移计算时机分为四类。

**1.3.1 寄存器间接寻址（无偏移）**

```text
LDR R0, [R1]   ; R0 = 内存[R1]
STR R0, [R1]   ; 内存[R1] = R0
```

- 地址 = 基寄存器 R1 的值
- 不修改基寄存器 R1
- 适用场景：指针解引用、访问固定地址的外设寄存器

**1.3.2 基址加偏移寻址**

```text
; 立即数偏移
LDR R0, [R1, #8]    ; R0 = 内存[R1 + 8]
; 寄存器偏移
LDR R0, [R1, R2]    ; R0 = 内存[R1 + R2]
; 寄存器移位偏移
LDR R0, [R1, R2, LSL #2]  ; R0 = 内存[R1 + R2*4]
```

- 地址 = 基寄存器 + 偏移量
- 不修改基寄存器 R1
- 适用场景：结构体成员访问、数组元素访问（移位偏移对应下标乘以元素大小）

> 💡 典型场景：数组遍历`LDR R0, [R1, R2, LSL #2]` R1 = 数组首地址，R2 = 数组下标，每个 int 占 4 字节，左移 2 位等价于 ×4，一条指令完成下标到地址的计算，零额外开销。

**1.3.3 前索引寻址（Pre-indexed，带！后缀）**

```text
LDR R0, [R1, #8]!   ; 先算地址R1+8，读取内存，再把R1更新为R1+8
```

- 执行顺序：① 计算地址 = R1 + 偏移 ② 访问内存 ③ 更新 R1 = 新地址
- 必须带`!`后缀才会更新基寄存器
- 适用场景：指针先移动再访问，适合正向遍历数组

**1.3.4 后索引寻址（Post-indexed）**

```text
LDR R0, [R1], #8    ; 先用R1原地址读内存，再把R1更新为R1+8
```

- 执行顺序：① 用 R1 原值访问内存 ② 更新 R1 = R1 + 偏移
- 不需要`!`后缀，偏移写在括号外
- 适用场景：先访问再移动指针，是循环拷贝、遍历数组最常用的写法

### 1.4 易混淆点：真实 LDR 指令 vs LDR 伪指令

初学者最容易混淆两个完全不同的 LDR 写法，必须严格区分：


<table v-pre><tbody><tr><td>写法</td><td>类型</td><td>功能</td></tr><tr><td>LDR R0, [R1]</td><td>真实内存访问指令</td><td>读取 R1 指向的内存数据到 R0</td></tr><tr><td>LDR R0, =0x12345678</td><td>汇编伪指令</td><td>将 32 位立即数 / 地址加载到 R0</td></tr></tbody></table>


> 补充：`LDR Rn,=xxx`伪指令的底层实现 汇编器会判断常量是否是合法立即数：
> 
> - 合法：自动优化为`MOV`/`MVN`指令
> - 不合法：将常量存入 Flash 常量池，用真实`LDR`指令从常量池读取 本质是 “加载常量”，不是 “访问内存变量”。

### 1.5 内存对齐规则

**1.5.1 对齐要求**

- 字（4 字节）访问：地址建议 4 字节对齐（地址低 2 位为 00）
- 半字（2 字节）访问：地址建议 2 字节对齐（地址最低位为 0）
- 字节访问：无对齐要求

**1.5.2 非对齐访问的行为**

Cortex-M4 默认支持普通内存的非对齐访问，不会触发 Fault，但有两个重要限制：

1. 性能惩罚：非对齐访问会拆分成多次对齐访问，执行速度变慢
2. 外设空间不支持：外设寄存器地址（0x40000000 段）必须严格对齐，非对齐访问会触发 HardFault

> 实操建议：始终保持内存访问对齐，既是性能最优，也能避免外设访问的 HardFault。

## 02 LDM/STM 多寄存器内存访问指令

### 2.1 指令功能

LDM（Load Multiple）：一次从内存加载多个连续字到多个寄存器； STM（Store Multiple）：一次将多个寄存器的值写入连续内存。 相比多次单寄存器 LDR/STR，代码密度更高、执行效率更好。

通用语法：

```text
LDM{<addr_mode>}{<cond>}  Rb{!}, <寄存器列表>
STM{<addr_mode>}{<cond>}  Rb{!}, <寄存器列表>
```

- `addr_mode`：地址增减模式，共 4 种
- `Rb`：基址寄存器，指向内存起始地址
- `!`：可选，执行后更新基址寄存器为新地址
- 寄存器列表：`{R0-R3, R5, LR}` 形式，支持范围和单个组合

### 2.2 四种地址模式详解

按地址增减方向、操作先后顺序分为四种，对应不同的栈类型。

IA和DB只支持thumb指令集


<table v-pre><tbody><tr><td>模式助记符</td><td>全称</td><td>执行顺序</td><td>地址变化方向</td></tr><tr><td>IA</td><td>Increment After</td><td>先访问内存，后地址递增</td><td>向高地址增长</td></tr><tr><td>IB</td><td>Increment Before</td><td>先地址递增，后访问内存</td><td>向高地址增长</td></tr><tr><td>DA</td><td>Decrement After</td><td>先访问内存，后地址递减</td><td>向低地址增长</td></tr><tr><td>DB</td><td>Decrement Before</td><td>先地址递减，后访问内存</td><td>向低地址增长</td></tr></tbody></table>


### 2.3 与四种栈类型的对应关系

栈的 “满 / 空” 指 SP 是否指向有效数据，“增 / 减” 指栈增长方向。LDM/STM 四种模式恰好对应四种栈的入栈出栈：


<table v-pre><tbody><tr><td>栈类型</td><td>入栈指令</td><td>出栈指令</td><td>说明</td></tr><tr><td>满减栈（Cortex-M 默认）</td><td>STMDB</td><td>LDMIA</td><td>SP 指向最后一个有效数据，栈向低地址增长</td></tr><tr><td>满增栈</td><td>STMIB</td><td>LDMDA</td><td>SP 指向最后一个有效数据，栈向高地址增长</td></tr><tr><td>空减栈</td><td>STMDA</td><td>LDMIB</td><td>SP 指向下一个空位，栈向低地址增长</td></tr><tr><td>空增栈</td><td>STMIA</td><td>LDMDB</td><td>SP 指向下一个空位，栈向高地址增长</td></tr></tbody></table>


> ✨ 核心结论：Cortex-M4 使用满减栈
> 
> - 入栈 PUSH 本质等价于 `STMDB SP!, {寄存器列表}`
> - 出栈 POP  本质等价于 `LDMIA SP!, {寄存器列表}`

### 2.4 寄存器列表规则

1. 自动排序：无论列表中寄存器书写顺序如何，汇编器永远按编号从小到大排列
2. 地址对应：编号最小的寄存器对应最低内存地址，编号最大的对应最高内存地址
3. 连续范围写法：`R0-R7` 表示 R0 到 R7 共 8 个寄存器
4. 基址带`!`时，执行完后基寄存器更新为最后一个访问地址的下一个地址

示例：

```text
LDM R10!, {R0, R1, R4}
; 从R10地址开始，依次读取3个字到R0、R1、R4
; R0对应最低地址，R4对应最高地址
; R10自动增加 3×4 = 12 字节
```

### 2.5 典型应用：内存块拷贝

**方案 1：单寄存器循环拷贝**

```text
; R8=源起始地址，R9=源结束地址，R10=目标起始地址
LOOP
    LDR R0, [R8], #4    ; 读1个字，源地址后移
    STR R0, [R10], #4   ; 写1个字，目标地址后移
    CMP R8, R9
    BLO LOOP            ; 没拷贝完继续
```

**方案 2：多寄存器批量拷贝（效率更高）**

```text
LOOP
    LDM R8!, {R0-R7}    ; 一次读8个字到R0~R7，共32字节
    STM R10!, {R0-R7}   ; 一次写8个字
    CMP R8, R9
    BLO LOOP
```

> 性能差异：多寄存器方案减少循环次数，总线利用率更高，大内存拷贝速度显著更快。

### 2.6 补充：中断续行机制

LDM/STM 是多周期指令，Cortex-M4 支持中断续行：指令执行中途到来中断，硬件会暂停指令，保存当前进度到 EPSR 的 ICI 位；中断返回后自动从断点继续执行，无需重头开始。

- 既保证了中断实时性，又保留了多寄存器指令的效率优势
- 这也是前面 xPSR 中 ICI 位的硬件用途

## 03 PUSH/POP 栈操作指令

### 3.1 本质：栈专用的多寄存器指令别名

PUSH/POP 不是独立的硬件指令，是为满减栈设计的 LDM/STM 语法糖：

- `PUSH {regs}`  =  `STMDB SP!, {regs}`
- `POP  {regs}`  =  `LDMIA SP!, {regs}`

专门针对 SP 栈指针优化，是函数现场保护、栈操作的标准指令。

### 3.2 语法与执行流程

```text
PUSH{<cond>}  <寄存器列表>   ; 寄存器压入栈
POP{<cond>}   <寄存器列表>   ; 栈中数据弹出到寄存器
```

**PUSH 入栈执行顺序（满减栈）**

1. SP 指针先向下递减（每个寄存器减 4 字节）
2. 将寄存器按编号从小到大，依次写入栈内存
3. 低编号寄存器对应低地址，高编号对应高地址
4. SP 最终指向最后一个入栈的数据（栈顶）

**POP 出栈执行顺序**

1. 从 SP 指向的栈顶开始，依次读取数据到寄存器
2. 低地址数据弹出到低编号寄存器，高地址到高编号
3. SP 指针向上递增，最终指向新的栈顶

### 3.3 核心用途：函数现场保护与恢复

衔接前面 BL 跳转指令的 LR 覆盖问题，标准 ARM 函数的入口出口写法：

```text
Func_Example:
    PUSH {R4-R7, LR}    ; 保存被调用者保护寄存器 + 返回地址LR
    
    ; 函数主体，可自由使用R4~R7，可嵌套调用其他函数
    
    POP {R4-R7, PC}     ; 恢复寄存器，同时把栈中LR值直接弹到PC，实现函数返回
```

> 💡 为什么 POP 可以直接弹到 PC？ 把栈中保存的 LR 值直接加载到 PC 寄存器，等价于 `POP {LR}` + `BX LR`，一条指令完成返回，代码更紧凑、效率更高。

### 3.4 栈平衡规则（铁则）

- 函数入口 PUSH 了多少个寄存器，出口 POP 必须对应相同数量
- 入栈和出栈的寄存器可以不同，但数量必须一致，保证 SP 指针回到原位
- 栈不平衡会导致函数返回地址错误，程序直接跑飞，是汇编最高频 bug 之一

### 3.5 栈对齐要求

1. 每个寄存器 4 字节，PUSH/POP 天然保证 4 字节对齐
2. AAPCS 调用约定要求栈保持8 字节对齐，因此 PUSH/POP 的寄存器数量建议为偶数
3. 异常入栈时硬件强制 8 字节对齐，若栈不对齐可能触发 HardFault

> 实操技巧：`PUSH {R4-R7, LR}` 共 5 个寄存器，5×4=20 字节，不是 8 的倍数；部分编译器会额外压一个寄存器凑齐 6 个，保证 8 字节对齐。

**本章第一性原理汇总**

1. 所有内存、外设的读写只能通过 LDR/STR 家族完成，数据处理指令永远无法直接操作内存。
2. LDR 读内存到寄存器，STR 写寄存器到内存；方向永远是 “从右往左”：右边源，左边目标。
3. 四种寻址方式的核心差异：是否更新基寄存器、更新发生在访问前还是访问后。
4. PUSH/POP 本质是 LDM/STM 的栈别名，Cortex-M 为满减栈，入栈先减 SP 再存，出栈先读再加 SP。
5. 寄存器列表永远按编号排序，小编号对应低地址，与书写顺序无关。
6. 多寄存器指令效率更高，且支持中断续行，是大块内存操作的首选。
7. 外设地址必须严格对齐访问，普通内存非对齐仅带来性能损耗。

**本章高频易错点**

1. ❌ 混淆`LDR R0, [R1]`和`LDR R0, =xxx`，一个读内存一个加载常量
2. ❌ 以为基址加偏移会自动更新基寄存器，只有带！或后索引才更新
3. ❌ 前索引和后索引搞反，导致地址计算顺序错误
4. ❌ PUSH 和 POP 寄存器数量不匹配，栈不平衡导致程序跑飞
5. ❌ 访问外设寄存器地址不对齐，触发 HardFault
6. ❌ 认为 PUSH/POP 和书写顺序有关，实际永远按寄存器编号排序
7. ❌ 有符号字节 / 半字读取用了 LDRB/LDRH，导致负数数值错误

**实操练习建议**

1. 用 LDR/STR 直接读写 GPIO 外设寄存器，实现汇编点灯，验证内存映射 IO 的本质
2. 分别用单寄存器和多寄存器实现内存拷贝，对比执行效率和代码长度
3. 写一个标准汇编函数，包含 PUSH 保护、嵌套调用、POP 返回，单步观察 SP 和栈内存变化
4. 故意制造栈不平衡，观察程序跑飞的现象，加深栈平衡重要性的理解
5. 测试 LDRSB 与 LDRB 读取负数的差异，验证符号扩展行为

# AAPCS规则

硬件只管执行指令；AAPCS 是人定的接口契约，规定寄存器、栈、参数传递、返回值怎么使用，实现 C 与汇编互相调用

## 01 AAPCS 简介

AAPCS：`ARM Architecture Procedure Call Standard`，ARM 架构过程调用标准。 

目的：不同编译器编译出来的目标文件、C 语言、汇编子程序之间可以互相调用，统一寄存器、堆栈、参数传递、返回值的使用规则。

> ⚠️重点：硬件不会校验 AAPCS，违背规则不会编译报错，但运行时随机破坏寄存器、栈，出现莫名其妙 HardFault、变量被篡改。

## 02 AAPCS 寄存器使用规则（原文整理 + 扩充表格）

**概念区分**

1. 调用者保存（Caller‑saved / 易失寄存器）：被调用函数可以随意改写，不需要恢复；调用函数如果调用后还要继续使用该寄存器，必须自己提前压栈保存。
2. 被调用者保存（Callee‑saved / 非易失寄存器）：被调用函数如果要使用该寄存器，入口 PUSH 保存，返回前 POP 恢复原值；调用者可以信任：调用完函数，寄存器内容不会被破坏。

**原文 6 条规则文字复述**

1. 子程序前 4 个参数用 R0‑R3 传递；参数超过 4 个，多出参数通过堆栈传递；被调用子程序不需要恢复 R0‑R3。
2. R4‑R11 用于保存局部变量；子程序如果使用 R4‑R11，进入函数必须 PUSH 保存，返回前 POP 恢复；没有用到的寄存器不用保存。Thumb (16 位) 只能正常使用 R4‑R7。
3. R12 (IP) 为过程临时 scratch 寄存器，子程序间临时暂存，不需要恢复。
4. R13 (SP) 栈指针，不能用作普通寄存器；进入子程序时 SP 值和退出子程序 SP 值必须完全相等（栈平衡）。
5. R14 (LR) 保存子程序返回地址；如果已经把 LR 压栈保存到栈，则 LR 可以临时当做普通寄存器使用。
6. R15 (PC) 程序计数器，禁止用作普通通用寄存器。

## 03 参数传递完整规则（补充原文没有的细节）

1. 前 4 个整型 / 指针参数依次放入 R0、R1、R2、R3

```c
int calc(int a,int b,int c,int d);
// a→R0，b→R1，c→R2，d→R3
```

1. 第 5 个及之后参数，压入调用者的栈；被调用函数从栈里面读取多余参数。

```c
int calc(int a,int b,int c,int d,int e,int f);
// a→R0,b→R1,c→R2,d→R3；e、f存放在栈上
```

1. 返回值规则

- 32 位返回值：结果存放在 R0
- 64 位 long long 返回值：R0 存低 32bit，R1 存高 32bit
- 大于 64 位大结构体返回：调用者在栈分配内存，传入指针参数

> 示例：汇编调用 C 函数

```text
MOV R0,#10    ; 参数1 a=10
MOV R1,#20    ; 参数2 b=20
MOV R2,#30    ; 参数3 c=30
MOV R3,#40    ; 参数4 d=40
BL calc       ; 调用C函数calc
; 返回结果在R0
```

## 04 栈相关 AAPCS 强制约定（重要补充）

1. Cortex‑M 使用满减栈 FD（Full Descending），PUSH=STMDB SP!，POP=LDMIA SP!
2. 公共函数接口，SP 必须保持 8 字节对齐，C 编译器全部遵循；如果栈不对齐，部分库函数、浮点运算会 HardFault。
3. 栈平衡铁律：函数执行结束返回时，SP 必须等于刚进入函数那一刻的 SP；函数内部临时开辟栈空间，退出前要收回。
4. 多出来的函数参数，由调用者负责压栈、清理栈。

## 05 两种函数典型汇编模板（AAPCS 实操示例）

**模板 1：叶子函数（函数内部不调用别的函数，不需要 BL）**

> 叶子函数：内部没有 BL，不会覆盖 LR，不用保存 LR；如果不用 R4‑R11，不需要 PUSH/POP。

```text
; int add(int a,int b)  a(R0),b(R1) 返回R0
add:
    ADD R0,R0,R1
    BX LR       ; LR保存返回地址，直接返回
```

**模板 2：非叶子函数（函数内部调用其他函数，会执行 BL，LR 会被覆盖）**

> 必须 PUSH LR；如果使用 R4‑R11，一并压栈保护。

```text
; int func(int a,int b)
func:
    PUSH {R4‑R7,LR}   ;保存被调用保存寄存器 + LR返回地址

    ; 函数业务逻辑，这里可以自由BL调用别的子函数
    MOV R0,#1
    BL sub_func

    POP {R4‑R7,PC}    ;恢复R4‑R7；栈中的LR直接弹入PC完成返回，等价POP {LR}+BX LR
```

> ✨重点：`POP {...,PC}`是 Thumb‑2 特性，直接把栈数据给到 PC 实现函数返回，非常常用。

## 06 混合编程场景

1. C 调用汇编函数：C 按照 AAPCS 把参数放入 R0‑R3；汇编函数遵守 AAPCS，返回结果放 R0。
2. 汇编调用 C 函数：汇编手动填充 R0‑R3，多余参数压栈，BL 调用 C 函数；返回值读取 R0。
3. 内联汇编：写内联汇编也必须遵守 AAPCS，否则破坏编译器寄存器上下文，C 代码逻辑错乱。

## 07 AAPCS 高频易错点

1. ❌ 把 R4‑R11 当做临时寄存器随便改写，没有 PUSH/POP；调用者的变量被悄无声息破坏。

> R0‑R3/R12 可以随便改写；R4‑R11 只要你用，就必须先保存后恢复。

1. ❌ 非叶子函数忘记 PUSH {LR}，BL 调用子函数之后 LR 被覆盖，返回地址丢失，程序跑飞。
2. ❌ SP 拿来当普通寄存器做数据存储；AAPCS 禁止，栈平衡被破坏。
3. ❌ 函数退出 SP 不等于进入时候的 SP（栈不平衡），直接 HardFault。
4. ❌ 参数大于 4 个，全部放 R0‑R3；第 5 个往后必须读栈。
5. ❌ 误以为 CPU 硬件检查 AAPCS；硬件完全不检查，错误只会运行期随机发作，很难调试。
6. ❌ 16 位 Thumb 指令操作 R8‑R11；16 位 Thumb 无法访问 R8‑R11，只能 Thumb‑2 宽指令。

## 08 本章第一性原理汇总

1. AAPCS 是软件契约，CPU 硬件不做检查，C 编译器、汇编双方都必须遵守。
2. R0‑R3、R12 是调用者保存寄存器；被调用函数可随便改写；调用者需要保留数据，调用前自己压栈。
3. R4‑R11 属于被调用者保存寄存器；只要被调用函数要使用，必须入口保存，出口恢复。
4. SP 绝对不能当普通寄存器；进入函数和退出函数 SP 必须完全一致（栈平衡），公共接口栈要 8 字节对齐。
5. 前 4 个参数 R0‑R3；>=5 个参数放在调用者栈上；返回值放 R0。
6. 非叶子函数内部会 BL 调用其他函数，LR 会被覆盖，所以必须 PUSH LR 保护返回地址。

**实操练习建议**

1. 手写叶子函数、非叶子函数汇编，严格遵守 AAPCS；单步调试观察 R4‑R11、LR、SP 的变化。
2. 在 Keil 写简单 C 函数，反汇编，观察编译器生成的 AAPCS prologue/epilogue（PUSH/POP 代码）。
3. 故意违反 AAPCS：函数改写 R4 不保存，观察运行后上层 C 变量被破坏的现象。

# 异常处理流程

异常是硬件自动触发，软件不能直接写寄存器进入处理模式；进入 / 退出异常的现场压栈、模式切换、栈切换、LR 改写全部由硬件自动完成，不是软件 PUSH/POP

## 01 NVIC 嵌套向量中断控制器

NVIC（Nested Vectored Interrupt Controller），内核私有外设，位于 PPB 地址段`0xE000E000`。

1. 功能：管理全部系统异常 + 外部中断；负责中断使能、清除挂起、优先级配置、异常嵌套控制。
2. STM32F407：**10 个系统异常，82 个可屏蔽外部中断**。
3. 信号流向：外设产生中断请求 → 送到 NVIC → NVIC 判断优先级、屏蔽位，向 Cortex‑M 内核发起异常请求。

> 补充：NVIC 属于内核外设，特权模式才可以直接配置；非特权模式不能访问 NVIC 寄存器。

## 02 异常向量表

向量表存放各个异常的入口地址，向量表第 0 项不是中断函数，是初始 MSP 栈指针；从 0x04 开始才是各个异常服务函数入口。

### 向量表关键特性补充

1. 每个向量占 4 字节，存放异常服务函数入口地址（bit0 必须等于 1，Thumb 状态）。
2. 复位时内核从地址`0x00`读 MSP 初值；`0x04`读取复位函数入口，开始执行启动汇编。
3. 向量表可以重定向：通过`SCB‑>VTOR`向量表偏移寄存器修改向量表基地址；但上电启动时刻，内核仍然会从`0x00`读取前两个条目完成启动。
4. IPSR 寄存器会保存当前活动异常的向量编号；线程模式 IPSR=0。

## 03 异常进入（硬件自动执行流程）

> ⚠️这里的 PUSH8 个寄存器，是硬件自动压栈，不是汇编 PUSH 指令！ 当 CPU 正在线程模式执行代码，收到有效异常请求，硬件自动执行整套动作，软件不需要写任何 PUSH。

### 硬件自动执行步骤

1. 如果当前正在执行长周期指令（LDM/STM/PUSH/POP/MUL/DIV）：**允许指令执行完毕**；

LDM/STM 支持中断续行，中断返回后继续完成剩余传输。

1. **自动保存上下文（压栈）**：**把 8 个寄存器压入当前正在使用的栈（**线程模式如果用 PSP，就压 PSP；如果是 MSP 就压 MSP）

> 硬件自动压入 8 个寄存器：`xPSR（程序状态）, PC（返回值）, LR（程序返回地址）, R12（临时链接寄存器）, R3, R2, R1, R0`（参数传递）

1. 从向量表读取该异常的服务函数入口地址。
2. 改写 LR 为特殊 EXC_RETURN 魔术值（例如`0xFFFFFFF9 / 0xFFFFFFFD / 0xFFFFFFF1`等），不是普通函数返回地址。
3. 强制切换到处理模式，自动切换 MSP 主栈：无论进入异常之前线程模式用 MSP 还是 PSP，进入处理模式后一律使用 MSP，处理模式永远特权。
4. IPSR 寄存器更新为当前异常编号。
5. PC 赋值异常服务函数入口，开始执行中断服务程序 ISR。

> 周期开销：**普通异常进入，大约12 个指令周期**。

### 硬件自动压栈的 8 个寄存器说明

- R0‑R3，R12：调用者保存寄存器，AAPCS 契约，发生异常需要保存
- LR：进入异常时刻线程模式下的 LR
- PC：被打断的那一条指令的返回地址
- xPSR：程序状态标志寄存器 N/Z/C/V/T 等

> 注意：R4‑R11 硬件不会自动压栈！ 如果中断服务函数要使用 R4‑R11，必须在 ISR 汇编代码里面手动 PUSH 保存，POP 恢复。硬件只自动保存 8 个。

### EXC_RETURN 魔术 LR 值（重点）

进入异常后，LR 不再是普通返回地址，而是特殊 32 位常量，叫 EXC_RETURN。中断服务函数执行`BX LR`，硬件识别这是 EXC_RETURN 值，触发异常退出流程，而不是普通函数跳转。 常用 EXC_RETURN 编码含义：


<table v-pre><tbody><tr><td>EXC_RETURN 值</td><td>含义</td></tr><tr><td>0xFFFFFFF9</td><td>返回线程模式，使用 MSP 主栈</td></tr><tr><td>0xFFFFFFFD</td><td>返回线程模式，使用 PSP 进程栈</td></tr><tr><td>0xFFFFFFF1</td><td>返回处理模式（用于异常嵌套）</td></tr></tbody></table>


> 你写 C 语言中断服务函数，编译器会在 ISR 函数末尾自动生成`BX LR`，不用手动写。

## 04 异常退出（硬件自动执行流程）

中断服务函数末尾执行`BX LR`（LR 为 EXC_RETURN 魔术值），硬件识别，自动执行退出流程：

1. 解析 EXC_RETURN 标志位，确定返回之后：线程 / 处理模式、使用 MSP 还是 PSP。
2. 恢复栈指针（PSP/MSP）。
3. 硬件自动弹出之前压栈的 8 个寄存器（POP xPSR,PC,LR,R12,R3‑R0），软件不需要写 POP。
4. 切回对应模式、特权等级，IPSR 清零（回到线程模式）。
5. PC 恢复为被打断的程序地址，继续运行被打断的代码。

> 周期开销：**普通异常退出大约 10 个指令周期**。

## 05 异常嵌套、尾链、晚到达中断

### 5.1 异常嵌套

> 条件：正在执行某中断 ISR（处理模式），来了一个优先级更高的新异常请求。

1. 当前 ISR 暂停，硬件再次执行一套异常进入流程；再次压栈上下文，继续使用 MSP 栈。
2. 高优先级 ISR 执行完毕退出，回到原来低优先级中断继续执行。
3. 低优先级中断不能抢占高优先级。

> 示意图逻辑：Foreground → 触发 IRQ2 (低) → 执行 ISR2 → IRQ1 高优先级到来，抢占 → 执行 ISR1 → ISR1 退出 → 回到 ISR2 继续运行 → ISR2 退出回到 Foreground。

### 5.2 尾链 Tail‑Chaining（TC）

> 场景：一个异常刚退出，还没完全返回线程模式，又挂起另一个异常。 硬件跳过完整的出栈、再入栈开销，直接切换到下一个异常服务函数。

- 尾链开销仅**约 6 个周期**，大大减少中断延迟。
- 不需要回到线程模式，直接在处理模式切换异常。

### 5.3 晚到达中断 Late‑arriving

在响应某个异常、正在做入栈的硬件流程时，来了一个优先级更高的异常。硬件放弃正在准备处理的低优先级，直接响应高优先级，向量表直接取高优先级异常入口。

## 06 模式、栈变化完整案例（线程模式 PSP 用户任务发生中断）

1. 线程模式，nPRIV=1 非特权，SPSEL=1，使用 PSP。运行用户任务。
2. 来了中断请求。硬件把 R0‑R3,R12,LR,PC,xPSR 压入PSP 栈。
3. LR 改写 EXC_RETURN=0xFFFFFFFD。
4. 自动进入处理模式，强制切换 MSP，特权模式。开始跑 ISR。
5. ISR 执行完，BX LR。硬件识别 EXC_RETURN。
6. 切回线程模式、非特权，恢复 PSP，硬件自动弹出 8 个寄存器，继续原来用户任务。

> 关键点：PSP 内容在进入异常瞬间被硬件保存，中断内部全程用 MSP；退出时硬件自动恢复 PSP，ISR 内部绝对不要手动修改 PSP。

## 07 中断服务函数的 AAPCS 约束

1. 硬件自动保存 R0‑R3,R12；R4‑R11 硬件不保存。
2. 如果 C 编译器编译 ISR：编译器自动检测 ISR 内部用到哪些 R4‑R11，函数入口 PUSH，出口 POP，遵循 AAPCS 被调用者保存规则。
3. 如果手写汇编中断服务函数：用到 R4‑R11 必须自己 PUSH/POP，否则寄存器被篡改，退出后前台代码崩溃。
4. ISR 属于处理模式，永远特权，默认使用 MSP 栈。

## 08 关键易错点

1. ❌ 误以为进入异常的 8 寄存器压栈是汇编 PUSH 指令：完全硬件自动做，看不见汇编代码。
2. ❌ 误以为 R4‑R11 硬件自动保存：硬件不保存，ISR 使用必须手动保存恢复。
3. ❌ 在中断服务函数中手动修改 PSP 寄存器：处理模式下 PSP 只由硬件保存恢复，软件不要碰。
4. ❌ 普通 BL 返回逻辑套用到中断：中断 LR 是 EXC_RETURN 魔术数字，不是普通函数返回地址；用 BX LR 触发硬件退出，不是 BX 普通地址。
5. ❌ 向量表 0 地址是 MSP 初始值，不是复位函数入口；复位入口是 0x04。
6. ❌ VTOR 重定向向量表后，上电启动依旧读取 0 地址的原始向量表前两项。
7. ❌ 异常嵌套：只有更高优先级才可以抢占；同等 / 更低优先级不能抢占正在运行的 ISR。

## 本章第一性原理汇总

1. NVIC 负责中断优先级、使能挂起管理；异常进入退出整套上下文保存、模式切换全部是硬件自动行为，非软件指令。
2. 向量表首项是初始 MSP；复位从 0x0 取 SP，0x04 取复位入口；VTOR 可以重定向向量表。
3. 进入异常硬件自动压栈 8 个寄存器 (R0‑R3,R12,LR,PC,xPSR)；R4‑R11 不自动保存。
4. 进入异常强制切换处理模式，强制使用 MSP；无论线程模式原本用 MSP 还是 PSP。LR 被改写为 EXC_RETURN 魔术值。
5. BX LR 在 ISR 末尾，硬件识别 EXC_RETURN，自动完成现场恢复、模式切换，退出异常。
6. 异常嵌套：高优先级抢占低优先级；尾链 TC 优化连续异常切换，降低中断延迟。
7. IPSR 寄存器记录当前活动异常号，线程模式 IPSR=0。

## 实操练习与验证建议

1. 打开启动文件看向量表，观察 0x00 存放\_\_initial_sp，0x04 存放 Reset_Handler。
2. Keil 调试，打中断断点；观察进入中断瞬间：MSP、PSP、LR 变为 EXC_RETURN 魔术值，IPSR 寄存器数值变化。
3. 观察栈内存，硬件压栈的 8 个寄存器在栈上排布。
4. 手写汇编 ISR，故意不保存 R4，退出后看前台代码变量被破坏。

# 特殊功能寄存器访问指令

普通数据处理指令只能操作通用寄存器 R0‑R15；内核特殊功能寄存器属于 CPU 内部系统状态硬件，拥有独立访问通路，只能通过 MRS 读、MSR 写，MOV、LDR/STR 都无法直接操作。

## 01 指令总览

**CPS指令**：通过比较简洁的指令改变处理器的状态

Cortex‑M4 只有两条用于访问特殊寄存器的指令：

1. **MRS**：Move to Register from Special register

> 把特殊功能寄存器 → 读到通用寄存器（读操作）

1. **MSR**：Move to Special register from Register

> 把通用寄存器的值 → 写入特殊功能寄存器（写操作）
> 
> ⚠️重要限制：
> 
> - 源 / 目标只能是通用寄存器 R0‑R12，不允许直接使用立即数。 不能写 `MSR PRIMASK,#1`！！必须先把立即数加载进通用寄存器，再 MSR 写入。

### 完整语法格式

```text
MRS{cond}  Rd, <特殊寄存器>    ;读：特殊寄存器 → Rd通用寄存器
MSR{cond}  <特殊寄存器>, Rn    ;写：Rn通用寄存器 → 特殊寄存器
```

- `cond`：可选条件后缀，支持 EQ/NE/CS 等全部条件码；条件不成立指令无效果。
- Rd / Rn：只能 R0\~R12，禁止 R13 (SP)、R14 (LR)、R15 (PC)。

## 02 MRS 读特殊寄存器

> MRS：拷贝内核特殊寄存器内容，放到通用寄存器，后续可以用 ADD/CMP/STR 等普通指令处理。

示例 1：读取 CONTROL 寄存器，查看当前栈选择、特权等级

```text
MRS R0, CONTROL    ; 将CONTROL读到R0
```

示例 2：读取 PRIMASK，查看中断是否已经被屏蔽

```text
MRS R0, PRIMASK    ; PRIMASK值送入R0
CMP R0,#1
BEQ int_masked     ; 如果PRIMASK=1，说明中断被屏蔽
```

示例 3：读取 PSP 进程栈指针

```text
MRS R1, PSP
```

示例 4：读取 xPSR 整体状态寄存器

```text
MRS R2, xPSR
```

> 实操提示：IPSR 只读，可以 MRS 读取当前异常编号，用来判断当前代码是线程模式还是处理模式：

```text
MRS R0,IPSR
CMP R0,#0
BNE is_in_interrupt   ; IPSR≠0，处于中断处理模式
```

## 03 MSR 写特殊寄存器

> MSR：把通用寄存器的值，写入内核特殊寄存器，修改处理器系统状态。 ❗严禁直接写立即数，错误写法 `MSR PRIMASK,#1` 汇编报错！

✅正确写法：先给通用寄存器赋值，再 MSR 写入

```text
MOVS R0,#1
MSR PRIMASK,R0     ; PRIMASK=1，屏蔽全部可屏蔽中断，进入临界区
```

### 示例集合

#### 示例 1：开关全局中断 PRIMASK（临界区）

```text
; =====关闭全局可屏蔽中断（进入临界区）=====
MOVS R0,#1
MSR PRIMASK, R0
DSB
ISB          ; 同步屏障，保证修改生效

; 临界区，不会被可屏蔽中断打断

; =====打开全局可屏蔽中断（退出临界区）=====
MOVS R0,#0
MSR PRIMASK, R0
DSB
ISB
```

> 补充 DSB、ISB 内存屏障：修改系统控制寄存器之后，需要指令同步屏障 ISB 刷新流水线，否则流水线可能使用旧状态，产生不稳定 bug。

#### 示例 2：修改 CONTROL 寄存器，切换 PSP 进程栈 + 特权级

> 规则：CONTROL 寄存器仅线程模式下生效；处理模式写 CONTROL 寄存器硬件会忽略，不会起作用；修改 CONTROL 之后必须 ISB！

```text
MOVS R0,#0x2    ; bit1=1(SPSEL=1 使用PSP), bit0=0特权
MSR CONTROL,R0
ISB             ; 必须ISB刷新流水线！！不可省略
```

#### 示例 3：操作 FAULTMASK

```text
MOVS R0,#1
MSR FAULTMASK,R0   ; 屏蔽除Reset、NMI之外全部异常
ISB
```

#### 示例 4：写 APSR 标志位（手动设置 N/Z/C/V 标志）

```text
MOVS R0,# (1<<29)  ; C标志置1
MSR APSR,R0
```

## 04 特权级别对 MRS / MSR 的访问限制【高频重点】

处理器分为特权模式、非特权（用户）模式，访问权限不一样。

> 非特权模式 = 线程模式 nPRIV=1

**核心结论**

1. 非特权模式：可以 MRS 读取大部分特殊寄存器看状态；但是不能 MSR 写入任何系统控制寄存器。
2. 如果非特权线程模式执行 MSR 写 CONTROL / PRIMASK 等，硬件直接忽略写入操作，不会报错、不会触发 Fault，寄存器值不变，程序静默异常，极难调试。
3. 非特权代码想要修改内核状态，**只能触发`SVC #0`软中断，进入处理模式（特权），在 SVC 服务函数中执行 MRS/MSR 完成操作**。

> 这是 RTOS 操作系统用户任务隔离的硬件基础，用户任务运行非特权，禁止直接修改中断屏蔽、栈、特权级。

MRS、MSR 支持条件后缀，可以放在 IT 条件块内条件执行。

```text

ITE NE
MRSNE R1,PRIMASK
MSREQ PRIMASK,R0
```

## 06 常见错误汇总（高频坑）

### 坑 1：MSR 直接写立即数，汇编报错

❌错误

```text
MSR PRIMASK,#1
```

✅正确，必须通过通用寄存器中转

```text
MOVS R0,#1
MSR PRIMASK,R0
```

### 坑 2：修改 CONTROL 寄存器，忘记 ISB 指令

> CONTROL 修改之后，流水线还保留旧的控制状态，必须 ISB 指令刷新，否则栈选择、特权级不会立刻生效，产生随机 bug。 ❌错误

```text
MOVS R0,#0x2
MSR CONTROL,R0
;缺少ISB！！
```

✅正确

```text
MOVS R0,#0x2
MSR CONTROL,R0
ISB
```

### 坑 3：企图 MSR 写 IPSR 寄存器切换进入中断处理模式

IPSR 只读。软件不能写 IPSR 强行进入 Handler 模式，只有硬件异常事件才会进入处理模式。

### 坑 4：非特权模式执行 MSR，以为修改成功

非特权模式 MSR 写 PRIMASK/CONTROL，硬件静默丢弃写入，不会 HardFault，寄存器维持原值，逻辑随机错乱。

> 排查技巧：写完 MSR 之后紧跟 MRS 读回寄存器，对比是否和预期一致。

### 坑 5：在 MSR/MRS 使用 R13/R14/R15 作为操作数

```text
MRS SP,CONTROL  ; ❌ SP(R13)不能作为MRS/MSR的Rd/Rn
MSR PRIMASK,LR  ; ❌ LR(R14)禁止
```

> MRS、MSR 源 / 目标寄存器只能 R0‑R12。

### 坑 6：忘记屏障指令 DSB / ISB 操作中断屏蔽寄存器

修改 PRIMASK/FAULTMASK 之后，内存和指令流水线没有同步，临界区保护可能失效。

## 08 在 C 语言、内联汇编中的应用补充

**Keil MDK 内联汇编关闭全局中断示例**

```c
__asm void DisableIRQ(void)
{
    MOVS R0,#1
    MSR PRIMASK,R0
    DSB
    ISB
    BX LR
}
```

**CMSIS 库底层本质**

`__disable_irq()` 底层就是 MRS/MSR 操作 PRIMASK。CMSIS 封装后不需要手写汇编，底层硬件就是这两条指令。

**本章第一性原理汇总**

1. MRS/MSR 是 Cortex‑M唯一可以访问内核特殊寄存器的指令；MOV/LDR/STR 都不能操作 xPSR、PRIMASK、CONTROL 等。
2. MSR不支持立即数，必须先把数值放到 R0‑R12 通用寄存器中转。
3. IPSR 只读，软件无法写入；不能靠写 IPSR 进入处理模式。
4. 非特权模式可以 MRS 读取特殊寄存器状态，但 MSR 写入会被硬件静默丢弃，不会报错。
5. 修改 CONTROL、中断屏蔽寄存器，写完之后需要`ISB`指令刷新流水线，部分场景搭配 DSB 数据同步屏障。
6. MRS/MSR 操作的特殊寄存器不属于内存地址空间，不属于 NVIC 外设寄存器，是内核核心状态。
7. MRS/MSR 可以加条件后缀，支持 IT 条件块条件执行。

**实操练习建议**

1. 写汇编，MRS 读取 CONTROL、IPSR、PRIMASK，单步调试观察寄存器变化，区分线程模式和中断模式 IPSR 值。
2. 写汇编实现关闭打开全局中断，加入 DSB/ISB，在 Keil 寄存器窗口观察 PRIMASK 变化。
3. 故意去掉 ISB 修改 CONTROL，观察行为异常现象。
4. 查看 CMSIS 库`__disable_irq`反汇编，看底层 MRS/MSR 机器码。

# 流水线技术

流水线把一条指令拆分为多步，多个指令的不同阶段并行工作，以此提升 CPU 指令吞吐；流水线会产生**等待 Stall（停顿）、分支冲刷**现象，会影响实际执行周期。Cortex‑M4 内核是**三级流水线（取指 Fetch、译码 Decode、执行 Execute）**

## 01 基础概念

**1.1 时钟周期、指令周期**

1. **时钟周期**：CPU 主时钟最小时间单位，主频 (MHz/GHz) 由硬件设计决定；主频越高，单个时钟的时间越短。
2. **指令周期**：CPU 取出并且完整执行完**一条指令**所耗费的全部时间。

> 没有流水线（串行执行）：执行完一条完整指令，才取下一条，硬件单元大量空闲，性能很低。 **流水线思想**：本条指令还没有执行完毕，就启动下一条指令的取指、译码，硬件单元并行重叠工作，提高整体吞吐量。

**1.2 性能衡量指标 CPI、吞吐量**

- **CPI（Cycles Per Instruction）**：平均每条指令消耗的时钟周期。CPI 越小性能越高。 

  - CPI = 总时钟周期数 ÷ 指令总条数
- **吞吐量**：单位时间完成多少条指令。理想流水线，简单寄存器操作指令`CPI=1`，即**每 1 个时钟周期完成 1 条指令**。

> 理想情况：连续简单寄存器运算指令，流水线满负荷，CPI=1。 遇到内存访问 (LDR/STR)、跳转分支，会产生流水线停顿 Stall，CPI 会变大，性能下降。

## 02 Cortex‑M4 三级流水线阶段

Cortex‑M4（ARMv7‑M）采用**三级流水线**，三级分别是：

1. **F 取指 Fetch（预取址）**：从 Flash / 内存读取指令二进制机器码。
2. **D 译码 Decode**：解析机器码，识别是什么指令，读取通用寄存器操作数。
3. **E 执行 Execute**：ALU 运算、桶形移位、乘除法、AGU 地址生成、LDR/STR 内存访问、分支判断、结果写回寄存器。

> 注意：M4 流水线没有独立 MEM、WB 阶段；内存访问、写回寄存器全部合并放在 Execute 执行阶段内部完成。 Execute 执行阶段内部包含多个子模块：ALU、移位单元、乘法除法单元、AGU 地址生成单元、Load‑Store 单元、分支处理单元。

流水线硬件简图拆解：

- Fetch：预取指令
- Decode：指令译码 + 读寄存器堆
- Execute：AGU 地址生成；ALU 运算；乘除；移位；内存读写；分支；结果写回寄存器。

**✨理想流水线（全部为寄存器‑寄存器简单运算指令）**

示例：ORR、EOR 这类只操作寄存器，不访问内存、无跳转。

> 连续 6 条简单寄存器指令，6 个时钟周期完成 6 条指令，**CPI=1**。

每一个周期都有一条指令完成执行，流水线满载。

## 03 流水线停顿 Stall（气泡）

> Stall：流水线暂停，部分阶段空转，不能继续推进，叫做流水线气泡。

**场景 1：LDR / STR 内存访问指令产生 Stall**

LDR/STR 需要在 Execute 阶段访问内存（Flash/SRAM/ 外设）。内存访问速度比 ALU 寄存器运算慢，流水线必须等待内存操作完成，产生**Stall(S)**停顿周期。

示例：混合 ADD、LDR、AND、ORR 指令，出现 Stall 气泡，6 个周期只完成 4 条指令，**CPI=1.5＞1**。

> 现象：流水线不再每周期输出一条指令，性能下降。

产生 Stall 的常见来源：

1. 访问速度慢的外设寄存器（0x40000000 外设区域）
2. Flash 等待周期多（Flash‑WS 等待）
3. LDR 读取内存，后续指令马上要使用这条加载出来的结果（数据相关）

> 补充：硬件具备数据前递 (Forwarding) 机制，可以消除一部分数据相关的 Stall；但内存访问带来的延迟无法完全消除。

**场景 2：分支跳转指令冲刷流水线（分支惩罚）**

跳转指令（B、BL、BX）：

1. 取指阶段，流水线已经顺序预取**后续连续地址的多条指令**。
2. 在 Execute 阶段，才真正计算得到跳转目标地址，确认需要跳转。
3. 预取到流水线里面、顺序读取出来的指令是无效的，必须全部丢弃（流水线冲刷）。
4. 流水线重新从跳转目标地址开始取指，中间产生若干无效周期。

示例：`BX R5`跳转指令

- 0x8000 BX R5：F 取指 → D 译码 → E 执行，在 E 阶段才算出跳转目标。
- 在确认跳转之前，硬件已经预取了地址 0x8002 SUB、0x8004 ORR 两条后续指令。
- 判定跳转之后，SUB、ORR 直接作废丢弃；流水线重新从跳转目标地址取新指令。

> 分支惩罚：跳转发生就会损失若干时钟周期。 IT (If‑Then) 条件执行块的价值：用条件执行代替分支跳转，**避免流水线冲刷损失周期，提升短分支性能**。

## 04 和前面课程关联的重点现象

1. **ISB 指令（指令同步屏障）作用本质** 

ISB 会冲刷流水线，清空已经预取的指令；修改 CONTROL、VTOR、PRIMASK 等系统寄存器之后，流水线内还保存旧状态的指令，ISB 把流水线全部清空，强制后续指令重新取指，保证新的系统设置生效。

1. **异常进入时流水线行为** 

收到异常请求，当前正在执行的指令允许执行完毕；流水线里面还没有执行的指令会被丢弃，转而取异常向量的 ISR 服务函数。LDM/STM 多寄存器指令支持中断续行，不会直接打断，执行完当前传输再响应异常。

1. 为什么 IT 块可以提升性能： 

小 if‑else 如果用 Bxx 条件跳转，一旦跳转发生就冲刷流水线；IT 指令条件执行，不修改 PC，**没有分支，没有流水线冲刷开销**。

## 05 高频易错点

1. ❌误以为 Cortex‑M4 是 5 级流水线。Cortex‑M3/M4 是**三级流水线 (F‑D‑E)**。Cortex‑A 系列才是多级流水线。
2. ❌所有指令 CPI 都等于 1。只有连续简单寄存器运算才 CPI=1；LDR/STR 内存访问、跳转分支会产生 Stall / 冲刷，CPI 变大。
3. ❌跳转指令在译码阶段就知道目标地址；BX、BL 跳转目标地址要到 Execute 执行阶段才解析完成。
4. ❌不理解 ISB：ISB 不仅仅是软件标记，硬件行为就是**冲刷整个流水线，丢弃预取指令**。
5. ❌Flash 等待周期 WS 和流水线无关；Flash 等待会额外增加取指阶段的 Stall，进一步降低性能。

**本章第一性原理汇总**

1. 流水线把指令拆分为多阶段，多条指令不同阶段并行重叠执行，目标提升指令吞吐量；理想简单寄存器指令 CPI=1。
2. Cortex‑M4 为三级流水线：Fetch 取指、Decode 译码、Execute 执行；内存访问、写回都放在 Execute 阶段。
3. Stall 流水线停顿（气泡）：LDR/STR 内存访问、数据相关会造成流水线暂停，CPI 上升，性能下降。
4. 分支跳转：流水线已经预取顺序后续指令；确认跳转后要冲刷丢弃预取指令，带来分支惩罚，损失时钟周期。
5. IT 条件执行避免分支跳转，消除流水线冲刷开销；ISB 指令硬件行为就是冲刷流水线。
6. CPI：平均每条指令时钟周期，越小代表 CPU 执行效率越高。

**实操理解建议**

1. 阅读反汇编，对比：if‑else 用 Bxx 跳转版本 VS IT 条件执行版本，理解分支冲刷的开销。
2. 理解 ISB 指令：修改 CONTROL 之后必须 ISB，本质就是刷新流水线。
3. 思考：频繁 LDR 访问外设寄存器，为什么代码运行速度会变慢（流水线 Stall）。

# 常用伪指令

伪指令不会生成 CPU 机器码，仅在汇编编译阶段给汇编器 / 链接器提供信息；编译完成之后伪指令全部消失，CPU 运行时完全看不到伪指令。 区分：真实指令（MOV、ADD、LDR、STR、MRS、MSR）生成机器码，CPU 执行；伪指令是汇编器的控制命令，只在编译期生效。

## 01 伪指令基础概念

1. 伪指令不是处理器指令集的一部分，汇编器在预处理阶段解析处理。
2. 作用：定义符号、分配内存、划分段、设置对齐、声明符号属性、生成常量。
3. 不会产生可执行机器码；部分数据定义伪指令（`.byte`/`.word`）会在目标文件生成数据字节，但是不属于 CPU 执行指令。

> ⚠️重要：`LDR Rn,=expr` 是伪指令，和真实内存访问指令 `LDR Rn,[Rm]` 完全不是同一个东西，必须区分。

## 02 符号与符号属性伪指令

## 05 对齐伪指令 `.align`

```text
.align n
```

- n 是 2 的幂次；`.align 4` = 2⁴ = 16 字节对齐
- 汇编器自动填充 0 字节，把当前地址补齐到 2^n 的整数倍地址
- 用途：保证数组、向量表、缓冲区满足内存对齐，避免 HardFault、性能损失

示例：

```text
.align 4     ; 4字节对齐（2^2）
buf: .word 0,0,0
```

> ⚠️注意：参数 n 是 2 的指数，不是直接字节数！`.align 4`不是 4 字节对齐，是 16 字节对齐；4 字节对齐写 `.align 2`。

## 06 地址加载伪指令（高频重点，极易混淆）

**6.1 `LDR reg, =expr` 伪指令**

> ❗伪指令，不等同于真实内存访问指令 `LDR R0,[R1]` 语法：

```text
LDR R1, =0x12345678
LDR R2, =g_variable
LDR R3, =Reset_Handler
```

工作原理：

1. 汇编器判断这个常数 / 地址是否属于 Thumb‑2 合法 MOV 立即数： 

   - ✅合法立即数：汇编器直接优化为真实`MOV`指令，不占用常量池
   - ❌非法立即数：把这个数值放到当前`.rodata`常量池（Flash），生成一条真实 LDR 内存读取指令，从常量池读取数值到寄存器。

> 优点：一行代码加载任意 32 位常数、变量地址、函数地址，不用手动 MOVW+MOVT。 缺点：非法立即数会占用 Flash 常量池，产生一次内存读取。

**6.2 ADR 小范围 PC 相对地址伪指令**

```text
ADR R3, label
```

- PC 相对寻址，计算 label 和当前 PC 之间偏移，用 ADD/SUB 构造地址
- 偏移范围：‑255 \~ +255 字节，范围很小
- 不占用常量池，不访问内存，纯寄存器运算
- label 必须和当前代码段在很近范围，超出范围汇编报错。

**6.3 ADRL 中等范围 PC 相对地址伪指令**

```text
ADRL R3, label
```

- 内部生成两条数据处理指令构造地址
- 偏移范围：‑64K \~ +64K
- 同样不使用常量池，不访问内存；超出 64K 汇编报错。

## 09 高频易错坑汇总

1. ❌混淆伪指令`LDR R0,=0x1234` 和真实指令`LDR R0,[R1]`

   - `LDR R0,=xxx`：伪指令，加载立即数 / 地址到寄存器，不一定访问内存。
   - `LDR R0,[R1]`：真实指令，访问 R1 指向的内存读取数据。
2. ❌`.align n`把 n 当成字节数，`.align 4`不是 4 字节对齐，是 16 字节对齐；4 字节对齐写`.align 2`。
3. ❌忘记`.global`，外部 C 文件无法调用汇编的函数 / 变量，链接报 undefined reference。
4. ❌`.equ`误以为会分配内存；equ 只是编译期符号替换，不占用 Flash/RAM。
5. ❌Cortex‑M 汇编写`.arm`伪指令，生成 ARM 指令，触发 UsageFault；M 内核必须`.thumb`。
6. ❌ADR/ADRL 超出偏移范围，汇编不报错，生成错误地址；大范围地址请用`LDR Rn,=label`。
7. ❌`.bss`段放初始化数据：bss 段启动时会全部清零；初始化非零数据必须放`.data`段。
8. ❌忘记`.type xxx,%function`；函数符号 bit0 没有自动置 1，BX 跳转触发 UsageFault。

**本章第一性原理汇总**

1. 伪指令只属于汇编器 / 连接器，运行时 CPU 完全看不到，不会生成机器码（数据定义伪指令生成存储字节，不是执行指令）。
2. `.equ`是编译期符号替换，不占内存；`.byte/.word/.string`会在目标文件分配存储空间。
3. 段：`.text`代码，`.rodata`只读常量，`.data`已初始化全局变量，`.bss`零初始化全局变量。
4. `.global`导出符号给外部；`.weak`弱符号，没有定义就使用本处默认实现，中断 Handler 大量使用。
5. `LDR Rn,=expr`是伪指令，不要和真实内存 LDR 指令混淆；ADR/ADRL 是 PC 相对地址，有严格范围限制。
6. `.align n`参数是 2 的指数，不是直接字节数。
7. Cortex‑M 必须使用`.thumb`，禁止`.arm`伪指令。

**实操练习建议**

1. 打开 STM32 启动`.s`文件，识别本笔记所有伪指令，看懂向量表构建逻辑。
2. 写简单汇编，分别测试 ADR 和 LDR Rn,=label，反汇编观察生成机器码差异。
3. 对比.equ 与.word，看.map 链接文件，确认 equ 不占用存储空间。
4. 去掉`.type ...,%function`，观察链接后函数入口 bit0 状态。

# Cortex-M4启动流程

`main()`不是 CPU 硬件入口；上电复位，硬件先执行固定动作，再执行汇编复位启动代码，搭建 C 语言运行环境，最后才跳转到 main 函数。 整个流程分为三大阶段：【硬件复位阶段】→【Reset_Handler 汇编启动阶段】→【C 运行时库初始化→进入 main】。

## 0 前置背景

STM32F4 (Cortex‑M4) 上电复位，BOOT 引脚决定启动映射：

- BOOT0=0：从主 Flash 启动；Flash 物理地址`0x08000000`被重映射到内核访问地址`0x00000000`。
- BOOT0=1：从系统存储器（片上 Bootloader）启动。

> 内核硬件固定从地址`0x00000000`读取向量表前两项，不是直接访问 0x08000000，依靠内存重映射机制。

## 阶段一：硬件复位自动执行（完全硬件行为，没有软件代码）

> 复位释放瞬间，CPU 自动完成下面两步，不需要任何指令。

1. 从映射地址 `0x00000000`（向量表第 0 项）读取初始 MSP 主栈指针值，写入 R13 (MSP)。 

> 1. 向量表第一项不是函数，是栈顶地址`__initial_sp / _estack`，栈放在 SRAM (`0x2000xxxx`) 区域。

1. 从映射地址 `0x00000004`（向量表第 1 项，复位向量）读取`Reset_Handler`函数入口地址，写入 PC 程序计数器。 

> 1. ⚠️该地址 bit0 必须等于 1，保证 Thumb‑2 状态，否则触发 UsageFault。

1. CPU 跳转到`Reset_Handler`开始执行汇编启动代码。

> 复位后内核状态：
> 
> - 工作模式：线程模式，特权级，使用 MSP
> - IPSR=0；T 位 = 1，Thumb‑2 开启；PRIMASK/FAULTMASK 全部清零，中断开启。
> 
> ❗重要：\`VTOR 向量表偏移寄存器此时还没有生效，上电读取 0 地址的向量表是硬件硬行为；VTOR 只能在软件执行后修改后续中断的向量表基地址，不能改变复位时刻读取 0x00、0x04 的行为。

## 阶段二：Reset_Handler 复位处理函数（汇编启动文件 startup_xxx.s）

> 硬件跳转到 Reset_Handler，这是复位后第一条软件执行代码，汇编编写。

**Reset_Handler 完整执行步骤**

1. 调用`SystemInit()`（C 函数） 

   - 配置 Flash 等待周期
   - 配置时钟树、PLL，设置系统主频
   - 配置 FPU 浮点单元（M4 带 FPU 芯片）
   - 设置`SCB‑>VTOR`向量表偏移，把向量表基地址重定向到 Flash 真实地址`0x08000000`。
2. 搬运.data 段：把 Flash 中已初始化全局变量初值拷贝到 SRAM

> 1. C 代码示例：`int a = 10;` 初值存放在 Flash `.rodata`区域，运行时必须复制到可读写 RAM，变量才能修改。

1. 清零.bss 段：把未初始化全局 / 静态变量内存全部置 0

> 1. C 代码示例：`int b;`没有写初值，C 标准要求全局变量默认等于 0；.bss 段只占用 RAM，不占用 Flash 存储空间。

1. 调用`__libc_init_array`：执行 C++ 全局对象构造函数；C 语言项目这个函数是空的。
2. 跳转到编译器库入口`__main`；`__main`内部完成 C 运行环境初始化，最终调用用户`main()`函数。

> ⚠️注意：`main`函数执行完返回的话，程序会跑飞；裸机 main 一般写死 while (1) 死循环，不允许 return。

**简化的 Reset_Handler 汇编模板（MDK‑ARM 语法）**

```text
Reset_Handler:
    LDR R0,=SystemInit
    BLX R0          ;调用系统初始化

    ; 拷贝.data段 Flash → RAM
    LDR R0, =_sdata
    LDR R1, =_edata
    LDR R2, =_sidata
CopyDataLoop:
    CMP R0,R1
    BEQ CopyDataEnd
    LDR R3,[R2],#4
    STR R3,[R0],#4
    B CopyDataLoop
CopyDataEnd:

    ;清零 .bss段 RAM
    LDR R0, =_sbss
    LDR R1, =_ebss
    MOVS R2,#0
ZeroBssLoop:
    CMP R0,R1
    BEQ ZeroBssEnd
    STR R2,[R0],#4
    B ZeroBssLoop
ZeroBssEnd:

    LDR R0,=__libc_init_array
    BLX R0

    LDR R0,=__main
    BX R0           ;跳C库入口，永不返回
```

## 阶段三：链接脚本 / 启动文件关键组成

启动文件`.s`包含 4 大模块，使用前面学过的伪指令（`.word`、`.global`、`.weak`、`.section`）。

## 完整时序流程图（文字版）

```text
上电/硬件复位
    ↓
硬件自动读取0x00000000 → MSP = __initial_sp
硬件自动读取0x00000004 → PC = Reset_Handler
    ↓
执行Reset_Handler汇编启动代码
    ├─ BL SystemInit （时钟、FPU、VTOR向量表重定向）
    ├─ 拷贝.data段：Flash初值复制到SRAM
    ├─ 清零.bss段：SRAM未初始化全局变量置0
    ├─ 调用 __libc_init_array（C++构造）
    └─ BX __main 跳转C库
    ↓
__main C运行时库初始化
    ↓
调用用户main()函数
    ↓
用户业务代码，while(1)死循环
```

**高频易错点**

1. ❌误区：CPU 上电直接跑 main。

> main 是软件层层初始化之后才调用的，硬件完全不知道 main 函数存在。

1. ❌误区：向量表 0 地址存放 Reset_Handler。

> `0x00`：MSP 栈顶；`0x04`才是 Reset_Handler 复位入口地址。

1. ❌修改 VTOR 向量表偏移寄存器，可以改变复位时刻读取的向量表。

> 不可以；复位读取 0 地址是硬件固定行为；VTOR 只修改复位之后的中断向量基地址。

1. ❌`.bss`段占用 Flash 空间。

> .bss 只占用 SRAM；链接阶段只记录大小，Flash 不存储内容，启动时软件把 RAM 对应区域全部写 0。

1. ❌BOOT 引脚修改程序内部向量表；BOOT 引脚只决定上电瞬间哪块存储器映射到地址 0，运行时 BOOT 引脚不再起作用。
2. ❌main 函数允许 return；裸机 main 返回会回到`__main`，无处理，程序跑飞，main 末尾必须死循环`while(1);`。
3. ❌忘记.data 拷贝；全局变量写了初始值，但变量运行时值随机，就是.data 段没有搬运。

**本章第一性原理汇总**

1. Cortex‑M4 复位是硬件固定行为，硬件只读取 0x00 拿 MSP 栈顶，0x04 拿 Reset_Handler 入口，和 main 无关。
2. Reset_Handler 汇编启动的核心任务：搭建 C 语言运行环境，拷贝.data，清零.bss。没有这两步，C 全局变量行为不符合 C 语言标准。
3. 向量表、栈、堆全部是汇编伪指令 + 链接脚本定义出来，编译链接阶段确定地址。
4. VTOR 只修改复位之后的中断向量基地址，不能干预上电复位硬件读取 0 地址向量表的行为。
5. BOOT 引脚仅决定上电瞬间哪块存储映射到地址`0x00000000`，程序运行后 BOOT 引脚无效。
6. 执行路径：硬件复位 → Reset_Handler → \_\_main → main；main 是软件调用，不是硬件入口。

**实操验证建议**

1. 打开 STM32 启动`s`文件，找到向量表、Reset_Handler，对照笔记阅读。
2. 打开 map 链接文件，查看`_sidata/_sdata/_edata/_sbss/_ebss`各个段地址。
3. Keil 调试复位，在 Reset_Handler 打断点，观察复位刚进入时 MSP 寄存器的值。
4. 故意注释掉.data 拷贝代码，观察带初值的全局变量运行时数值异常现象。

# 汇编语言点灯

STM32 所有 GPIO 外设寄存器都是内存映射地址，读写寄存器等价读写对应内存地址，只用 LDR、STR 指令完成硬件控制。

## 第一部分 STM32F407 最小系统

> STM32 芯片仅仅接上电源不能工作，必须配套外部电路，组成最小系统，芯片才可以上电、复位、运行程序、下载调试。 最小系统由**电源模块、内部调压器、复位模块、时钟模块、BOOT 启动配置电路、SWD 调试下载接口**六大部分组成。

### 1.1 电源模块

- 功能：**给单片机提供稳定 3.3V 工作电源；外部输入一般 5V，通过 LDO 稳压芯片转为 3.3V**。
- 原理图关键点： 

  - 输入 5V 进入稳压芯片，输出稳定`3V3`给芯片内核、外设供电。
  - 输入输出两端搭配滤波电容（大容量电解 + 小容值陶瓷电容），滤除电源噪声。
  - C10、C11：输入端滤波；C12、C13：3.3V 输出滤波。

> 常见故障：电源滤波电容缺失，芯片运行不稳定、随机死机。

### 1.2 内部调压器（VCAP 引脚）

STM32F4 内核电压由片内调压器产生，VCAP1、VCAP2 引脚必须外接 2.2μF 电容到 GND。

- 作用：**稳定内核调压器输出电压**。
- 硬件风险：如果电容漏接、容值错误，会出现：程序无法下载、芯片运行不稳定、频繁死机。
- 器件：C50、C51，2.2uF，一端接 VCAP，一端接 GND。

### 1.3 复位模块（NRST）

- 电路结构：**RC 上电复位电路 + 手动复位按键**。
- RC 上电复位：上电瞬间电容 C30 电压为 0，NRST 引脚被拉低，芯片保持复位；电容充电，电压上升，NRST 释放，芯片开始启动运行。
- K30 轻触按键：手动复位，按下直接把 NRST 拉低，松开完成上电复位流程。

> NRST 是低电平复位：低电平 = 芯片处于复位；高电平 = 芯片正常运行。

### 1.4 BOOT 启动模式配置电路

BOOT0、BOOT1 引脚，只在上电复位瞬间采样一次电平，运行之后引脚可以复用为普通 GPIO。


<table v-pre><tbody><tr><td>BOOT1</td><td>BOOT0</td><td>启动模式</td><td>说明</td></tr><tr><td>X</td><td>0</td><td>主闪存存储器 (Flash)</td><td>日常产品开发，从 0x08000000 Flash 启动，Flash 重映射到 0x00000000</td></tr><tr><td>0</td><td>1</td><td>系统存储器 (ISP)</td><td>芯片出厂内置 BOOTloader，串口下载程序（一般无法更改）</td></tr><tr><td>1</td><td>1</td><td>内置 SRAM 启动</td><td>调试用，程序直接在 RAM 运行（断电丢失）</td></tr></tbody></table>


> 开发板正常调试使用：BOOT0 接 GND（0），从主 Flash 启动。 ⚠️注意：复位采样完成后，BOOT0/BOOT1 引脚不再影响运行，可作为普通 GPIO 使用。

### 1.5 外部高速晶振时钟模块（HSE）

- 原理图：8MHz 外部晶振 Y40，搭配起振电容 C40、C41（12pF）接 PH0‑OSC_IN、PH1‑OSC_OUT。
- 作用：提供外部高精度时钟源，PLL 倍频生成系统主时钟（例如 168MHz）。

> 如果没有外部晶振，**芯片可以使用内部 RC HSI 时钟运行**，但精度较差。

### 1.6 SWD 调试下载接口

- 引脚：SWDIO、SWCLK、NRST、GND、3V3。
- 功能：仿真器通过 SWD 接口完成：程序烧录、单步调试、寄存器查看、内存查看。

> SWD 相比 JTAG 引脚更少，现在 STM32 主流调试方式； 注意：不要给仿真器输出 5V，芯片 IO 是 3.3V 耐压。

## 第二部分 GPIO 原理 & 汇编点灯实操

### 2.1 LED 硬件电路分析

开发板 LED：上拉电阻 3V3 接到 LED 阳极，LED 阴极接 STM32 PF8 引脚

- PF8 输出低电平 (0)：LED 形成电流回路，点亮 LED
- PF8 输出高电平 (1)：LED 两端电位接近，熄灭 LED

> 硬件关键点：这个是灌电流电路，引脚输出低电平点亮灯。

### 2.2 GPIO 内部框图理解

GPIO 模块主要寄存器（内存映射 IO，全部在`0x40000000`外设段）

1. MODER 模式寄存器：设置引脚模式：输入 / 通用输出 / 复用功能 / 模拟输入。点灯需要设置为通用输出模式。
2. OTYPER 输出类型寄存器：推挽输出 / 开漏输出；点灯使用推挽输出。
3. OSPEEDR 速度寄存器：设置 GPIO 输出速度（低速 / 中速 / 高速）。
4. PUPDR 上拉下拉寄存器：配置引脚上拉 / 下拉电阻。
5. ODR 输出数据寄存器：写这个寄存器的 bit 位，直接控制引脚输出电平。 

> 1. PF8 对应 ODR 寄存器 bit8；写 bit8=0 → PF8 输出低电平，LED 点亮。
> 
> 第一性：GPIO 是内存映射外设，没有 IN/OUT 专用 IO 指令；汇编只能使用`LDR`读寄存器、`STR`写寄存器。

**GPIOF 外设基地址**

GPIOF 基地址：`0x40022000`


<table v-pre><tbody><tr><td>寄存器</td><td>偏移地址</td><td>完整地址</td></tr><tr><td>GPIOF_MODER</td><td>0x00</td><td>0x40022000</td></tr><tr><td>GPIOF_OTYPER</td><td>0x04</td><td>0x40022004</td></tr><tr><td>GPIOF_OSPEEDR</td><td>0x08</td><td>0x40022008</td></tr><tr><td>GPIOF_PUPDR</td><td>0x0C</td><td>0x4002200C</td></tr><tr><td>GPIOF_ODR</td><td>0x14</td><td>0x40022014</td></tr></tbody></table>


> 重要前提：GPIO 外设挂载在 AHB1 总线上，必须先打开 GPIOF 的时钟，否则寄存器读写无效！ RCC AHB1 使能寄存器地址：`0x40023030`；GPIOF 时钟对应 bit5，把 bit5 置 1，开启 GPIOF 外设时钟。

### 2.3 完整裸机汇编点灯代码（MDK‑ARM 汇编，无 C 库）

> 综合运用：伪指令`.equ`，`LDR`伪指令加载地址，LDR/STR 内存访问指令，循环延时，死循环。

```text
.syntax unified
.thumb

; 寄存器地址定义，equ伪指令，编译期替换
.equ RCC_AHB1ENR,   0x40023030
.equ GPIOF_BASE,    0x40022000
.equ GPIOF_MODER,   GPIOF_BASE + 0x00
.equ GPIOF_OTYPER,  GPIOF_BASE + 0x04
.equ GPIOF_OSPEEDR, GPIOF_BASE + 0x08
.equ GPIOF_PUPDR,   GPIOF_BASE + 0x0C
.equ GPIOF_ODR,     GPIOF_BASE + 0x14

.section .text
.global _start
.type _start,%function

_start:
    ; =========1.开启GPIOF外设时钟 bit5置1 =========
    LDR R0,=RCC_AHB1ENR
    LDR R1,[R0]
    ORR R1,R1,#(1<<5)
    STR R1,[R0]

    ; =========2.设置PF8为通用输出模式 MODER =========
    LDR R0,=GPIOF_MODER
    LDR R1,[R0]
    BIC R1,R1,#(0x3 << (8*2))   ; 先清空PF8对应的两位
    ORR R1,R1,#(0x1 << (8*2))   ; 设置01：通用输出模式
    STR R1,[R0]

    ; =========3.推挽输出 OTYPER PF8=0 =========
    LDR R0,=GPIOF_OTYPER
    LDR R1,[R0]
    BIC R1,R1,#(1<<8)
    STR R1,[R0]

    ; =========4.设置高速OSPEEDR PF8 =========
    LDR R0,=GPIOF_OSPEEDR
    LDR R1,[R0]
    BIC R1,R1,#(0x3 << (8*2))
    ORR R1,R1,#(0x2 << (8*2))
    STR R1,[R0]

    ; =========5.关闭上拉下拉PUPDR PF8 =========
    LDR R0,=GPIOF_PUPDR
    LDR R1,[R0]
    BIC R1,R1,#(0x3 << (8*2))
    STR R1,[R0]

main_loop:
    ; PF8输出低电平，点亮LED
    LDR R0,=GPIOF_ODR
    LDR R1,[R0]
    BIC R1,R1,#(1<<8)
    STR R1,[R0]

    ;简单软件延时
    LDR R2,=0x100000
delay_on:
    SUBS R2,R2,#1
    BNE delay_on

    ; PF8输出高电平，熄灭LED
    LDR R0,=GPIOF_ODR
    LDR R1,[R0]
    ORR R1,R1,#(1<<8)
    STR R1,[R0]

    ;软件延时
    LDR R2,=0x100000
delay_off:
    SUBS R2,R2,#1
    BNE delay_off

    B main_loop    ;无限循环闪烁

.end
```

### 2.4 汇编点灯关键知识点总结

1. 必须打开外设时钟，不打开时钟，GPIO 寄存器读写无效，灯不会亮，这是 STM32 非常高频踩坑点。
2. 寄存器位操作套路： 

   - BIC：清零指定 bit；ORR：置位指定 bit；读取寄存器→修改 bit→写回寄存器。
3. LED 硬件逻辑：PF8 输出 0 点亮，输出 1 熄灭，由原理图硬件决定，软件不能反过来。
4. 软件延时：用 SUBS+BNE 循环做延时；软件延时不精确，CPU 主频改变延时时间会变化。
5. 全部使用内存映射 IO，没有特殊 IO 指令；只有 LDR 读外设寄存器，STR 写外设寄存器。

### 2.5 高频踩坑点

1. ❌忘记开启 GPIO 外设时钟，读写寄存器完全无效。
2. ❌MODER 模式没有设置输出模式，引脚保持输入，LED 无反应。
3. ❌电平逻辑搞反：硬件是上拉接法，输出高电平点亮，写反逻辑灯不亮。
4. ❌寄存器偏移算错，操作别的引脚寄存器。
5. ❌软件延时循环没有写 S 后缀`SUBS`，不更新 Z 标志，BNE 永远不会跳转。

**本章第一性原理汇总**

1. STM32 最小系统是芯片上电运行的硬件基础：电源、调压器电容、复位、晶振、BOOT 启动、SWD 调试缺一不可。BOOT 引脚仅复位瞬间采样。
2. GPIO 外设是内存映射 IO，没有专门 IO 指令，汇编只能 LDR 读取外设寄存器，STR 写入外设寄存器。
3. 使用 GPIO 外设第一步必须开启对应总线外设时钟，时钟关闭状态下寄存器读写无效果。
4. LED 亮灭逻辑由硬件原理图决定，软件要和硬件匹配。
5. 裸机汇编点灯综合练习：伪指令、立即数、数据处理指令（BIC ORR SUBS）、分支跳转 B/BNE、LDR/STR 内存访问指令。

**实操练习建议**

1. 对照最小系统原理图，看懂每部分电路功能。
2. 将汇编点灯工程在 MDK 中创建，不使用启动文件，自定义向量表，单步调试，观察各个 GPIO 寄存器内存地址数值变化。
3. 单步观察时钟开启前后 GPIOF 寄存器读写行为。
4. 修改延时循环的计数值，观察 LED 闪烁速度变化。

> 至此整套 Cortex‑M4 汇编完整学习链路全部完成： 
> 
> 进制与补码 → 内存映射 IO → 内核寄存器 → 处理器模式 & 特权级 → 数据处理指令 → 分支跳转 → LDR/STR 内存访问 → AAPCS 调用标准 → NVIC 异常处理 → MRS/MSR 特殊寄存器访问 → 汇编伪指令 → 启动流程 → 硬件最小系统 + 汇编裸机点灯。

# 内联汇编

内联汇编是把汇编片段嵌入 C 语言代码，运行在 C 编译器管理的寄存器、栈环境中；必须遵守 AAPCS，要告诉编译器哪些寄存器被修改，否则编译器缓存的变量会被破坏，产生诡异 bug。 

两种形式：1）Keil MDK 的`__asm`裸汇编；2）GCC 扩展汇编（`asm volatile`带输出输入约束，PDF 文档讲的是 GCC 风格扩展内联汇编）。

## 01 什么是内联汇编

**1.1 概念**

内联汇编：在 C/C++ 源代码内部嵌入汇编代码片段，区别于独立`.s`汇编源文件。

两大使用场景：

1. 性能优化：对时序、周期要求极高的热点小段代码，手写汇编提升效率。
2. 硬件特殊操作：C 语言无法直接完成的操作：MRS/MSR 读写特殊寄存器、操作 EXC_RETURN、开关中断、桶形移位特殊运算等。

> ⚠️重要风险： C 编译器会自主分配、缓存变量到通用寄存器；如果汇编随意改写寄存器，编译器不知情，C 变量值会被悄悄破坏。 所以内联汇编必须通过输入、输出、破坏列表向编译器报备资源改动。

**1.2 GCC 扩展内联汇编标准语法（PDF 原文）**

```c
asm(
    "汇编代码字符串\n\t"
    "汇编代码字符串\n\t"
: 输出操作数列表     /* 可选，逗号分隔 */
: 输入操作数列表     /* 可选，逗号分隔 */
: 被更改资源列表     /* 可选，告诉编译器哪些寄存器/内存被修改 */
);
```

- `asm`：关键字；一般加上`volatile`：`asm volatile(...)`，禁止编译器优化删掉这段汇编。
- `\n\t`：字符串内换行、Tab，汇编器解析语法格式化，生成中间汇编文件可读性更好，不可省略。

示例（PDF 原文示例）

```c
int sum,a,b;
asm(
    "add %0,%1,%2\n\t"
    "mov r1,%1\n\t"
:"+r"(sum)         //输出操作数
:"r"(a),"r"(b)    //输入操作数
:"r1"              //被更改资源：r1寄存器被汇编修改
);
```

## 02 操作数约束符号详解


<table v-pre><tbody><tr><td>约束字符</td><td>含义</td></tr><tr><td>r</td><td>把变量放到通用寄存器 R0‑R12；汇编内部使用%0 %1 %2引用</td></tr><tr><td>i</td><td>立即数，编译期常量</td></tr><tr><td>m</td><td>内存地址，直接访问内存</td></tr><tr><td>x</td><td>仅用作输入，只读</td></tr></tbody></table>


**输出操作数修饰符**


<table v-pre><tbody><tr><td>修饰</td><td>含义</td></tr><tr><td>=</td><td>只写：汇编只向这个变量写，不读取原来的值</td></tr><tr><td>+</td><td>可读可写：汇编既会读原来的值，又会写回新值（最常用）</td></tr><tr><td>&amp;</td><td>早破坏输出；输出寄存器不能复用输入寄存器</td></tr></tbody></table>


**占位符编号规则**

- `%0` → 输出输入列表第 1 个成员
- `%1` → 输出输入列表第 2 个成员
- `%2` → 输出输入列表第 3 个成员

> 注意：编号顺序：先数输出列表全部，再继续数输入列表。

示例解析上面 PDF 代码片段：

```c
:"+r"(sum)      // %0 → sum，可读可写，放入通用寄存器
:"r"(a),"r"(b)  // %1 → a；%2 → b
:"r1"           //通知编译器：汇编里面修改了R1，编译器不要把变量放在R1
```

汇编展开：`add %0,%1,%2` 等价 `add sum_reg, a_reg, b_reg`。

**第三段：被更改资源（clobber 破坏列表）**

> ✨这是最容易踩坑！告诉编译器：这段汇编会改写哪些寄存器 / 内存，编译器不要把 C 变量存放在这些寄存器中。

常见填写：

1. `"r0","r1","r2"`：汇编修改了 R0/R1/R2，写进列表
2. `"memory"`：汇编内部直接读写内存，告诉编译器 C 缓存的寄存器变量需要回写到内存
3. `"cc"`：汇编修改 APSR 条件标志位 (N/Z/C/V)，必须写！

> 如果汇编使用了某些寄存器，但是不写进破坏列表，编译器不知道，依旧把 C 变量放在这些寄存器，运行变量被篡改，bug 随机复现，极难调试。

## 03 简单实操示例（GCC）

**示例 1：两数相加**

```c
int add_inline(int a,int b)
{
    int res;
    asm volatile(
        "add %0, %1, %2\n\t"
        :"=r"(res)    /* =r 只写，res是输出 */
        :"r"(a),"r"(b)
        :"cc"         /* 修改了标志位 */
    );
    return res;
}
```

**示例 2：读取 CONTROL 特殊寄存器（MRS，C 不能直接写）**

```c
uint32_t get_control(void)
{
    uint32_t val;
    asm volatile(
        "mrs %0, control\n\t"
        :"=r"(val)
        :
        :"cc"
    );
    return val;
}
```

**示例 3：关闭全局中断（PRIMASK）**

```c
void disable_irq(void)
{
    asm volatile(
        "movs r0,#1\n\t"
        "msr primask,r0\n\t"
        "dsb\n\t"
        "isb\n\t"
        :
        :
        :"r0","memory","cc"
    );
}
```

> 这里修改 R0，破坏列表写上`"r0"`；加`memory`防止编译器跨汇编优化内存访问。

## 04 Keil MDK (ARMCC) 两种内联汇编

> ⚠️注意：Keil MDK‑ARMCC 不支持 GCC 这种扩展 asm 语法！两套语法不兼容，很多人混淆踩坑。

**方式 1：`__asm { }` 裸内联汇编（MDK 专用）**

直接写汇编指令，没有输入输出约束。

> 巨大风险：编译器不会帮你保存寄存器！你改写 R0‑R3/R12 没问题（调用者保存）；一旦改写 R4‑R11，必须自己手动 PUSH/POP 保存恢复，严格遵守 AAPCS。

```c
__asm void disable_irq_mdk(void)
{
    MOVS R0,#1
    MSR PRIMASK,R0
    DSB
    ISB
    BX LR
}
```

> MDK 的`__asm`函数，如果函数内部会修改 R4‑R11，必须 PUSH/POP，否则破坏 C 上层变量。

**方式 2：MDK 嵌入代码块在 C 函数内部**

```c
void test(void)
{
    int a = 10;
    __asm
    {
        ADD R0,R0,#1
    }
}
```

> 缺点：没有输入输出约束，需要自己手动处理寄存器，牢记 AAPCS 规则。

## 05 内联汇编重要约束 & AAPCS 关系（重点）

1. GCC 扩展汇编：编译器自动分配输入输出的寄存器；不需要自己随便写 R4‑R11。
2. MDK 裸`__asm`块：你直接操作物理寄存器，必须遵守 AAPCS： 

   - R0‑R3、R12 属于调用者保存，汇编随意改写没问题。
   - 如果汇编使用 R4\~R11，必须 PUSH 保存，POP 恢复，否则上层 C 变量被破坏。
3. 不要随意修改 SP、LR、PC；会直接破坏 C 函数栈帧。
4. 如果汇编修改标志位 APSR，GCC 破坏列表必须写`"cc"`。
5. 如果汇编读写内存，破坏列表加上`"memory"`，阻止编译器做寄存器缓存优化。
6. `volatile`作用：告诉编译器汇编有副作用，不要把这段汇编删除、不要重排和周围 C 代码顺序。

> 如果省略 volatile，编译器检测不到输出，会直接把汇编整个优化删掉。

## 06 高频易错坑汇总

1. ❌GCC 内联汇编忘记`volatile`，汇编代码被编译器直接优化删掉。
2. ❌汇编修改寄存器，但是没有写到破坏列表，C 变量随机被篡改，bug 偶现。
3. ❌GCC 和 MDK 语法混用：把 GCC 的`asm( :输出:输入:clobber )`直接复制到 Keil MDK，编译报错。
4. ❌输出操作数误用`=`，实际需要读写却不用`+`，读到垃圾旧值。
5. ❌汇编修改 APSR 标志位，不写`"cc"`，编译器不知道标志被改动，后续条件判断出错。
6. ❌直接在内联汇编修改 SP、LR、PC，栈帧崩溃，HardFault。
7. ❌MDK 的`__asm`裸汇编随意改写 R4‑R11，没有 PUSH/POP，违反 AAPCS。
8. ❌忘记`\n\t`分隔多条汇编语句，生成中间汇编文件语法错误。

## 07 什么时候用内联汇编，什么时候用独立.s 汇编文件


<table v-pre><tbody><tr><td>方案</td><td>优点</td><td>缺点</td><td>适用场景</td></tr><tr><td>GCC 扩展内联汇编</td><td>C 和汇编参数自然交互，编译器自动分配寄存器，遵守 AAPCS</td><td>GCC 专属，MDK 不兼容，语法抽象难懂</td><td>小段硬件操作：MRS/MSR，临界区开关中断，简单运算</td></tr><tr><td>MDK __asm 裸内联</td><td>直接写汇编指令，直观</td><td>需要手动管理寄存器，极易破坏 C 上下文</td><td>MDK 环境短小硬件操作</td></tr><tr><td>独立.s汇编源文件</td><td>完全掌控，完整 AAPCS，适合复杂子程序</td><td>C‑汇编交互要遵循调用约定，函数传参依靠 R0‑R3、栈</td><td>复杂汇编函数，中断服务函数，启动代码</td></tr></tbody></table>


> 经验：中断服务函数、复杂算法，优先写独立`.s`；简单 MRS/MSR 开关中断，可使用内联汇编。

**本章第一性原理汇总**

1. 内联汇编运行在 C 编译器管理的环境；汇编修改的资源必须告诉编译器，否则 C 变量被静默破坏。
2. GCC 扩展内联汇编三部分：输出操作数、输入操作数、被更改资源（clobber 破坏列表）。
3. `volatile`防止编译器优化删除汇编代码；`\n\t`用于生成合法中间汇编文本。
4. GCC 与 MDK (ARMCC) 两套内联汇编语法不兼容，不可直接复制粘贴。
5. MDK 裸`__asm`汇编块，必须严格遵守 AAPCS；使用 R4‑R11 要手动 PUSH/POP 保存恢复。
6. 若汇编修改条件标志位 APSR，GCC 破坏列表必须写`"cc"`；读写内存添加`"memory"`。
7. 禁止随意修改 SP、LR、PC，会摧毁 C 函数栈帧。

**实操练习建议**

1. GCC 环境写读取 PRIMASK 的内联汇编，反汇编观察生成机器码。
2. 故意漏写破坏列表，观察变量被随机破坏现象。
3. MDK 写`__asm`开关中断，看反汇编寄存器行为。
4. 对比内联汇编与独立.s 汇编函数的反汇编差异。
