# EXTI与NVIC控制器原理

## 一、中断的基本概念

**中断**是指 MCU 在运行过程中，出现某些意外情况需处理时，MCU 能自动停止正在运行的程序并转入处理新情况的程序，处理完毕后又返回原被暂停的程序继续运行。


::: tip

中断的核心价值：让 CPU 从"不断轮询外设状态"中解放出来，外设有事时主动通知 CPU，实现 CPU 与外设的异步并行工作。

:::


## 二、中断处理完整流程

一次外部中断从产生到被 CPU 处理，需要经过三个硬件模块的接力：

1. **外部 IO 引脚电平变化**：外部事件导致引脚上产生上升沿或下降沿
2. **EXTI 控制器**：检测到边沿跳变后，挂起对应中断线的状态，向 NVIC 发出中断请求
3. **NVIC 控制器**：接收中断请求，挂起中断，根据优先级仲裁决定是否以及何时让 CPU 响应
4. **CPU 处理**：CPU 保存现场，从中断向量表取出 ISR 地址并跳转执行，执行完毕后恢复现场返回


::: tip

信号流向：GPIO 引脚 → EXTI（边沿检测+挂起）→ NVIC（优先级仲裁+挂起）→ CPU（取向量+执行 ISR）。EXTI 管"有没有外部事件"，NVIC 管"先处理谁"。

:::


## 三、EXTI 控制器原理

### 3.1 基本特性

- EXTI（External Interrupt/Event Controller，外部中断/事件控制器）包含 **23 个**用于产生事件/中断请求的边沿检测器
- 每根输入线都可单独配置：选择类型（中断或事件）和触发事件（上升沿、下降沿或双边沿）
- 每根输入线可单独屏蔽（使能/禁用）

### 3.2 23 条中断/事件输入线映射（STM32F407）

| 中断线 | 连接对象 |
|-|-|
| EXTI0 \~ EXTI15 | 外部 GPIO 引脚（共 16 根，每根对应一个 Pin 编号） |
| EXTI16 | PVD 输出（可编程电压检测器） |
| EXTI17 | RTC 闹钟事件 |
| EXTI18 | USB OTG FS 唤醒事件 |
| EXTI19 | 以太网唤醒事件 |
| EXTI20 | USB OTG HS 唤醒事件 |
| EXTI21 | RTC 入侵和时间戳事件 |
| EXTI22 | RTC 唤醒事件 |


::: tip

GPIO 映射规则：EXTI0 连接所有端口的 Pin0（PA0/PB0/PC0...），EXTI1 连接所有端口的 Pin1，以此类推。同一编号的引脚不能同时使用外部中断，需通过 AFIO 选择具体端口。

:::


### 3.3 中断 vs 事件

| 对比项 | 中断（Interrupt） | 事件（Event） |
|-|-|-|
| 是否经过 CPU | 需要 CPU 介入，执行 ISR | 不经过 CPU，直接通知片上外设动作 |
| 用途 | 需要软件处理的外部事件 | 硬件自动联动（如触发 ADC、DMA） |
| 延迟 | 有中断响应延迟 | 硬件直接触发，延迟极低 |

**事件**是指当外部触发一个电平跳变时，在不经过 CPU 干预的情况下，可以通知相应芯片内部控制器进行动作。

### 3.4 触发方式

- **上升沿触发**：电平从低变高时触发
- **下降沿触发**：电平从高变低时触发
- **双边沿触发**：上升沿和下降沿都触发

## 四、NVIC 控制器原理

### 4.1 基本特性

- NVIC（Nested Vectored Interrupt Controller，嵌套向量中断控制器）是 Cortex-M 架构中的中断控制器，用于管理和分配中断优先级
- 在 STM32 中，NVIC 用于控制中断系统，允许开发者配置和管理中断优先级、使能或禁用中断，以及处理中断请求
- **STM32F407 具有 82 个可屏蔽中断，10 个系统异常**

### 4.2 中断 vs 异常

| 对比项 | 中断（Interrupt） | 异常（Exception） |
|-|-|-|
| 触发源 | 外部设备（定时器、外部输入等），是外部事件的反应 | 执行指令引起（除零、访问越界内存等） |
| 引起原因 | 外部硬件或外设产生的异步事件，通知处理器设备需要处理 | 程序执行期间发生的条件，表示程序错误、非法操作或意外情况 |
| 同步/异步 | 异步（与指令执行无关） | 同步（由特定指令触发） |

### 4.3 STM32 系统异常源

| 编号 | 异常源 | 名称 | 作用 |
|-|-|-|-|
| 1 | Reset | 复位异常 | 系统上电或外部复位引脚触发时发生 |
| 2 | NMI | 不可屏蔽中断 | 用于处理紧急事件，如 RCC 时钟安全系统(CSS)连接到 NMI |
| 3 | HardFault | 硬件错误 | 所有错误都可能引发，前提是相应错误异常未使能（兜底） |
| 4 | MemManage | 存储器管理异常 | 存储器访问错误，如访问未分配的内存区域 |
| 5 | BusFault | 总线异常 | AHB 总线接口收到 APB1/APB2 总线错误响应时产生 |
| 6 | UsageFault | 使用异常 | 程序错误或试图访问协处理器导致的错误 |
| 11 | SVCall | 系统服务异常 | 用户程序由非特权切换为特权态，如操作系统的系统调用 |
| 12 | Debug Monitor | 调试监控 | 软件调试时，断点和监视点等调试事件的异常 |
| 14 | PendSV | 可悬起异常 | 允许开发者在软件中请求任务切换，不需要硬件中断触发 |
| 15 | SysTick | 系统嘀嗒定时器 | 内核中的定时器触发，可用于实现定时器中断 |
| 16\~97 | 外部中断 0\~81 | 外设中断 | WWDG、EXTI、USART、TIM、ADC、FPU 等片上外设中断 |

### 4.4 中断向量表

**中断向量表**是一张记录系统所有中断服务程序（ISR）地址的表。当一个中断被触发时，处理器根据中断号找到对应的中断处理函数地址，进而跳转执行该函数。

| 地址偏移 | 向量号 | 名称 | 存储内容 |
|-|-|-|-|
| 0x00 | N/A | 初始主 SP | 主堆栈指针初始值（\_\_initial_sp），非函数地址 |
| 0x04 | 1 | Reset | Reset_Handler（复位处理函数，程序入口） |
| 0x08 | 2 | NMI | NMI_Handler（不可屏蔽中断处理函数） |
| 0x0C | 3 | HardFault | HardFault_Handler（硬件错误处理函数） |
| 0x10 | 4 | MemManage | MemManage_Handler（存储器管理异常处理函数） |
| 0x14 | 5 | BusFault | BusFault_Handler（总线异常处理函数） |
| 0x18 | 6 | UsageFault | UsageFault_Handler（使用异常处理函数） |
| 0x1C\~0x28 | 7\~10 | Reserved（保留） | 保留（0 或默认弱定义处理函数） |
| 0x2C | 11 | SVCall | SVC_Handler（系统服务调用处理函数） |
| 0x30 | 12 | Debug Monitor | DebugMon_Handler（调试监控处理函数） |
| 0x34 | 13 | Reserved | 保留 |
| 0x38 | 14 | PendSV | PendSV_Handler（可悬起异常处理函数） |
| 0x3C | 15 | SysTick | SysTick_Handler（系统嘀嗒定时器处理函数） |
| 0x40 起 | 16\~255 | 外部中断 0\~239 | 各外设中断服务函数，如 EXTI0_IRQHandler、USART1_IRQHandler、TIM2_IRQHandler 等 |


::: tip

向量表关键特性：①第一个条目是初始主 SP，其余都是异常处理程序入口地址；②向量表最多支持 240 个外部中断；③可通过向量表偏移寄存器重新定义位置；④在 0x0 地址仍需最小表项用于引导核心启动。

:::


### 4.5 挂起与解挂

**挂起（Pending）**：中断被置于一种等待处理器处理的状态。

- 若处理器正在处理更高或同等优先级的中断，挂起请求会一直保持，直到其他中断处理结束
- 多个中断同时产生时，优先级高的先被处理，优先级低的处于挂起状态等待

**解挂**：清除中断的挂起状态。解挂一般是硬件行为——当挂起的中断被处理器处理时，一旦进入异常处理，当前异常的挂起状态就会被硬件自动清除。


::: tip

注意区分两层"清除"：①NVIC 的挂起位由硬件在进入 ISR 时自动清除；②外设（如 EXTI）的中断请求标志需要在 ISR 中软件手动清除，否则外设会持续发出中断请求。

:::


### 4.6 激活状态

每个中断都有一个**活跃状态位**：

- 处理器开始执行中断处理时，该位被置 1
- 中断返回时被清 0
- 整个中断执行期间，活跃状态位都是 1，处于激活状态

挂起状态和激活状态共同描述中断的生命周期：**请求 → 挂起 → 激活（处理中）→ 结束**。

## 五、中断优先级体系

Cortex-M 的中断优先级分为**固定优先级**和**可配置优先级**两类。Reset、NMI、HardFault 三个异常拥有固定的负优先级，数值越小优先级越高，且不可通过寄存器修改；其余所有异常和外部中断的优先级均可配置，复位后默认值为 0。

| 异常/中断 | 优先级值 | 优先级类型 | 配置寄存器 |
|-|-|-|-|
| Reset | **-3** | 固定（最高） | 不可配置 |
| NMI | **-2** | 固定 | 不可配置 |
| HardFault | **-1** | 固定 | 不可配置 |
| MemManage | 0（复位默认） | 可配置 | SHPR1 |
| BusFault | 0（复位默认） | 可配置 | SHPR1 |
| UsageFault | 0（复位默认） | 可配置 | SHPR1 |
| SVCall | 0（复位默认） | 可配置 | SHPR2 |
| DebugMonitor | 0（复位默认） | 可配置 | SHPR3 |
| PendSV | 0（复位默认） | 可配置 | SHPR3 |
| SysTick | 0（复位默认） | 可配置 | SHPR3 |
| 外部中断 IRQ0\~n | 0（复位默认） | 可配置 | NVIC_IPR |

负优先级的意义：固定优先级异常（-3、-2、-1）高于任何可配置中断（≥0）。因此 PRIMASK 将当前优先级提升到 0 时，NMI 和 HardFault 仍能响应；只有 FAULTMASK 将优先级提升到 -1 时才能屏蔽 HardFault，但 NMI(-2) 和 Reset(-3) 依然不受影响。

### 5.1 优先级寄存器

中断优先级由优先级寄存器（IPRx）控制，每个中断线都有一个 IPRx 寄存器，一般有效位宽为 3\~8 位，由芯片设计厂商决定。


::: tip

STM32 只实现了 4 位优先级（高 4 位 Bit7\~Bit4 有效），低 4 位（Bit3\~Bit0）未实现：读取低 4 位总是 0，对低 4 位写入会被忽略。

:::


### 5.2 优先级分组

Cortex-M 中断优先级分为两部分：**抢占优先级**和**响应优先级**。4 位有效位如何在两者之间分配，由优先级分组决定（通过 AIRCR 寄存器配置）：

| 分组 | AIRCR[10:8] | 抢占:响应 | 抢占位数 | 抢占等级 | 响应位数 | 响应等级 |
|-|-|-|-|-|-|-|
| Group0 | 111 | 0:4 | 0 | 0（无嵌套） | 4 | 16 |
| Group1 | 110 | 1:3 | 1 | 2 | 3 | 8 |
| Group2 | 101 | 2:2 | 2 | 4 | 2 | 4 |
| Group3 | 100 | 3:1 | 3 | 8 | 1 | 2 |
| Group4 | 0xx | 4:0 | 4 | 16 | 0 |  |


::: tip

数值越小，优先级越高。整个系统只能设置一个优先级分组，所有中断共享同一分组方式。

:::


### 5.3 抢占优先级

- **抢占优先级高，处理器先处理**：多个中断同时发生时，抢占优先级高的优先被处理
- **抢占优先级高，发生中断抢占**：处理器正在处理低抢占优先级中断时，又来了高抢占优先级中断请求，会发生中断抢占（嵌套）

### 5.4 响应优先级

- **抢占优先级相同，响应优先级高先处理**：多个中断同时产生，抢占优先级相同时，比较响应优先级，高者先处理
- **抢占优先级相同，响应优先级高不发生抢占**：响应优先级低的中断正在处理时，又来了响应优先级高的中断，**不会**打断当前中断（只有抢占优先级不同才能嵌套）

### 5.5 自然优先级

当抢占优先级和响应优先级都相同时，比较**自然优先级**：

- 自然优先级是不可编程的，它是中断/异常源在中断向量表中的位置编号
- 向量表中的位置编号越小，自然优先级越高
- 自然优先级高的优先被处理器响应执行

### 5.6 优先级仲裁完整规则

多个中断同时请求时，NVIC 按以下顺序逐级比较：

1. 先比较**抢占优先级**，高者先执行；高者可抢占低者（嵌套）
2. 抢占优先级相同，比较**响应优先级**，高者先执行；但不能抢占
3. 响应优先级也相同，比较**自然优先级**（向量表编号，小者优先）

## 六、CPU 中断屏蔽寄存器组

Cortex-M 内核提供三个特殊寄存器，用于在软件中灵活控制中断的屏蔽：

### 6.1 PRIMASK

- 用于暂时禁止所有中断，以执行时序关键的任务
- 禁止除 **NMI、HardFault 和复位**外的所有异常
- 实际效果：将当前处理器的优先级设置为 0

### 6.2 FAULTMASK

- 行为与 PRIMASK 类似，但屏蔽范围更大
- 将当前处理器的优先级修改为 **-1**，甚至可以屏蔽 HardFault
- 当 FAULTMASK 置位时，只有 **NMI 和 Reset** 异常处理才能执行

### 6.3 BASEPRI

- 只想禁止优先级低于某特定等级的中断时使用
- 将所需的屏蔽优先级写入 BASEPRI 寄存器，优先级低于该值的中断被屏蔽
- 优先级高于或等于该值的中断仍可正常响应

| 寄存器 | 屏蔽效果 | 仍可响应 | 典型用途 |
|-|-|-|-|
| PRIMASK | 优先级设为 0，屏蔽所有可屏蔽中断 | NMI、HardFault、Reset | 短时临界区、时序关键代码 |
| FAULTMASK | 优先级设为 -1，屏蔽包括 HardFault 在内 | NMI、Reset | 极端关键操作（极少使用） |
| BASEPRI | 屏蔽优先级低于设定值的中断 | 优先级 ≥ 设定值的中断、NMI、HardFault | 精细屏蔽，只关低优先级中断 |

# STM32CubeMX中断接口介绍

## 一、NVIC 寄存器映射

NVIC 寄存器位于 Cortex-M 内核私有外设总线（PPB）上，起始地址为 **0xE000E000**。所有 NVIC 寄存器均可按字（32位）访问，每个寄存器的每一位对应一个中断通道。

| 地址范围 | 寄存器名称 | 符号 | 功能 |
|-|-|-|-|
| 0xE000E100 \~ 0xE000E11C | 中断设置使能寄存器 | ISER0 \~ ISER2（最大 ISER7） | 写 1 设置使能对应中断；写 0 无效 |
| 0xE000E180 \~ 0xE000E19C | 中断清除使能寄存器 | ICER0 \~ ICER2（最大 ICER7） | 写 1 清除（禁用）对应中断；写 0 无效 |
| 0xE000E200 \~ 0xE000E21C | 中断设置挂起寄存器 | ISPR0 \~ ISPR2（最大 ISPR7） | 写 1 设置中断挂起状态（软件触发中断） |
| 0xE000E280 \~ 0xE000E29C | 中断清除挂起寄存器 | ICPR0 \~ ICPR2（最大 ICPR7） | 写 1 清除中断挂起状态 |
| 0xE000E300 \~ 0xE000E31C | 中断活跃位寄存器 | IABR0 \~ IABR2（最大 IABR7） | 活跃状态位，**只读**，指示当前正在处理的中断 |
| 0xE000E400 \~ 0xE000E4EF | 中断优先级寄存器 | IP0 \~ IP81（最大 IP239） | 每个中断 8 位宽，设置中断优先级（STM32 仅高 4 位有效） |


::: tip

设计要点：使能/禁用、挂起/解挂都采用"写 1 有效"的独立寄存器对（SET/CLEAR），而不是读-改-写，这样可以避免多任务环境下的竞态问题——直接写 1 到对应位即可，不影响其他位。

:::


## 二、SCB 寄存器映射

SCB（System Control Block，系统控制块）也是 Cortex-M 内核的内置模块，负责管理系统异常、向量表偏移和优先级分组等全局配置。

| 地址 | 寄存器名称 | 符号 | 功能 |
|-|-|-|-|
| 0xE000ED04 | 系统异常控制和状态寄存器 | ICSR | NMI、PendSV 等异常挂起控制与状态 |
| 0xE000ED08 | 向量表偏移寄存器 | VTOR | 设置异常向量表的基地址（可重定位向量表） |
| 0xE000ED0C | 应用中断/复位控制寄存器 | AIRCR | 设置优先级分组（PRIGROUP 字段）、系统复位 |
| 0xE000ED18 \~ 0xE000ED23 | 系统处理优先级寄存器 | SHPR0 \~ SHPR3（最大 SHPR11） | 设置系统异常（MemManage、BusFault、UsageFault、SVC、PendSV、SysTick 等）的优先级 |
| 0xE000ED24 | 系统处理控制和状态寄存器 | SHCSR | 系统异常的使能与激活状态（MemManage、BusFault、UsageFault 使能位等） |


::: tip

NVIC 管"外部中断"（IRQ0\~IRQn），SCB 管"系统异常"（Reset、NMI、HardFault、SVC、PendSV、SysTick 等）。两者配合构成完整的中断异常系统。优先级分组通过 SCB 的 AIRCR 寄存器全局设置，对 NVIC 和系统异常同时生效。

:::


## 三、HAL 库 NVIC 接口大全

STM32 HAL 库对 NVIC 寄存器操作进行了封装，提供了 10 个标准函数，覆盖优先级管理、中断使能、挂起控制和状态查询四大类操作。

### 3.1 优先级分组管理

| 函数 | 功能 | 原型 | 参数 | 返回值 |
|-|-|-|-|-|
| HAL_NVIC_SetPriorityGrouping | 设置优先级分组 | void HAL_NVIC_SetPriorityGrouping(uint32_t PriorityGroup) | PriorityGroup：优先级组（NVIC_PRIORITYGROUP_0 \~ \_4） | 无 |
| HAL_NVIC_GetPriorityGrouping | 读取当前系统优先级分组 | uint32_t HAL_NVIC_GetPriorityGrouping(void) | 无 | 当前优先级分组值 |

### 3.2 中断优先级设置与查询

| 函数 | 功能 | 原型 | 参数 | 返回值 |
|-|-|-|-|-|
| HAL_NVIC_SetPriority | 设置中断优先级 | void HAL_NVIC_SetPriority(IRQn_Type IRQn, uint32_t PreemptPriority, uint32_t SubPriority) | IRQn：中断编号  <br/>PreemptPriority：抢占优先级  <br/>SubPriority：响应优先级 | 无 |

## 五、典型使用流程

在 STM32CubeMX 生成的工程中，NVIC 配置通常在 `MX_NVIC_Init()` 或外设初始化函数中完成。以下是手动配置一个中断的完整流程：

```c
// 1. 设置优先级分组（通常在 main 开头全局设置一次）
HAL_NVIC_SetPriorityGrouping(NVIC_PRIORITYGROUP_2);

// 2. 设置指定中断的抢占优先级和响应优先级
//    Group2 下：抢占优先级 0~3，响应优先级 0~3
HAL_NVIC_SetPriority(EXTI0_IRQn, 1, 0);

// 3. 使能中断
HAL_NVIC_EnableIRQ(EXTI0_IRQn);

// --- 其他可用操作 ---
// 读取当前优先级分组
uint32_t group = HAL_NVIC_GetPriorityGrouping();

// 读取中断优先级
uint32_t preempt, sub;
HAL_NVIC_GetPriority(EXTI0_IRQn, group, &preempt, &sub);

// 软件触发中断（设置挂起）
HAL_NVIC_SetPendingIRQ(EXTI0_IRQn);

// 读取挂起状态
uint32_t pending = HAL_NVIC_GetPendingIRQ(EXTI0_IRQn);

// 清除挂起
HAL_NVIC_ClearPendingIRQ(EXTI0_IRQn);

// 读取激活状态
uint32_t active = HAL_NVIC_GetActive(EXTI0_IRQn);

// 禁用中断
HAL_NVIC_DisableIRQ(EXTI0_IRQn);
```


::: tip

注意事项：①优先级分组整个系统只能设置一次，通常在 main 函数最开头调用；②设置优先级和使能中断的顺序：先 SetPriority，后 EnableIRQ；③IRQn 参数使用枚举类型（如 EXTI0_IRQn、USART1_IRQn），不要直接写数字；④HAL_NVIC_GetPriority 需要传入当前 PriorityGroup 才能正确解码出抢占和响应优先级。

:::


# 按键中断实验

## 实验概述

**按键中断实验**是利用外部中断（EXTI）检测按键按下/释放事件，实现 CPU 异步响应按键操作的基础实验。典型效果：按下按键触发中断，在中断服务函数中翻转 LED 状态或执行其他动作。

与轮询方式（CPU 不断读取按键电平）相比，中断方式的优势是 CPU 平时可以执行其他任务，只有按键事件发生时才暂停处理，大幅提高 CPU 利用率。

## 硬件资源

| 资源 | 作用 |
|-|-|
| GPIO（输入引脚） | 连接按键，配置为上拉/下拉输入，检测电平变化 |
| GPIO（输出引脚） | 连接 LED，用于直观展示中断响应效果 |
| AFIO | 复用功能 IO，将指定 GPIO 端口映射到对应 EXTI 中断线 |
| EXTI 控制器 | 边沿检测器，检测上升沿/下降沿，产生中断请求并挂起状态 |
| NVIC 控制器 | 中断优先级管理，决定中断是否响应、何时响应 |
| 中断服务函数（ISR） | EXTIx_IRQHandler，中断触发后 CPU 自动跳转执行的函数 |

## 工作原理

**信号流向：**

1. 按键按下 → GPIO 引脚电平发生跳变（如上拉输入时产生下降沿）
2. EXTI 控制器的边沿检测器检测到预设触发沿 → 置位对应中断线的挂起位（EXTI_PR）
3. EXTI 向 NVIC 发出中断请求信号
4. NVIC 检查该中断是否使能、优先级是否高于当前处理 → 若满足则挂起中断并通知 CPU
5. CPU 保存现场（xPSR/PC/LR/R12/R3\~R0 压栈）→ 从中断向量表取出 EXTIx_IRQHandler 地址 → 跳转执行
6. ISR 中检查中断标志、执行动作（如翻转 LED）、清除 EXTI 挂起位
7. CPU 恢复现场 → 返回被中断的主程序继续执行


::: tip

核心原理：EXTI 管"检测到没有"（边沿检测+挂起），NVIC 管"让不让进、什么时候进"（优先级仲裁+使能），CPU 管"进来后做什么"（取向量+执行 ISR）。三者协作完成一次按键中断响应。

:::


## 配置与实现

### 配置步骤

1. **使能时钟**：开启 GPIO 端口时钟和 AFIO 时钟（EXTI 和 NVIC 不需要单独开时钟）
2. **配置 GPIO**：按键引脚设为上拉/下拉输入，LED 引脚设为推挽输出
3. **配置 GPIO 与 EXTI 映射**：通过 HAL_GPIO_Init() 配置 GPIO 为中断模式（GPIO_MODE_IT_FALLING 等），CubeMX 自动配置 SYSCFG 选择具体端口
4. **配置 EXTI**：设置中断线编号、中断模式（非事件模式）、触发沿（上升/下降/双边沿）、使能该线
5. **配置 NVIC**：设置优先级分组（全局一次）、设置该中断的抢占优先级和响应优先级、使能该中断通道
6. **编写 ISR**：实现 EXTIx_IRQHandler 函数，检查标志→执行动作→清除挂起位

### 中断服务函数

```c
void EXTI0_IRQHandler(void)
{
    // 1. 检查中断标志（确认是本线触发，共享线时尤其重要）
    if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_0) != RESET)
    {
        // 2. 执行中断处理动作（如翻转 LED）
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);

        // 3. 清除中断挂起位（必须！否则反复进入中断）
        __HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0);
    }
}
```


::: tip

常见问题：①忘记清除中断挂起位（\_\_HAL_GPIO_EXTI_CLEAR_IT）→ 中断反复触发；②ISR 函数名写错 → 跳到启动文件默认死循环；③同编号引脚（如 PA0 和 PB0）同时用中断 → 冲突，需通过 SYSCFG 二选一；④机械按键抖动 → 一次按下触发多次中断，需硬件消抖或软件延时消抖。

:::




# 串口接收中断实验

## 实验概述

**串口接收中断实验**是利用 USART 外设的接收中断（RXNE）实现异步数据接收的实验。当串口接收到一帧数据时，硬件自动触发中断，CPU 在中断服务函数中读取数据并处理，无需 CPU 持续轮询接收寄存器。

典型应用：串口调试助手发送字符/指令，STM32 收到后立即响应（如回显、控制 LED、执行命令），是串口通信、指令解析、数据采集等功能的基础。

## 硬件资源

| 资源 | 作用 |
|-|-|
| GPIO（TX 引脚） | 串口发送引脚，配置为复用推挽输出 |
| GPIO（RX 引脚） | 串口接收引脚，配置为浮空/上拉输入 |
| USART 外设 | 串口控制器，含波特率发生器、发送/接收移位寄存器、数据寄存器 DR、状态寄存器 SR、中断控制 |
| NVIC 控制器 | 管理 USART 中断的优先级和使能 |
| 中断服务函数（ISR） | USARTx_IRQHandler，接收中断触发后 CPU 自动跳转执行 |
| 接收缓冲区（可选） | 全局数组或环形缓冲区，ISR 中存入数据，主循环中处理 |

## 工作原理

**信号与数据流向：**

1. 外部设备（如电脑串口助手）通过 TX 线发送数据帧（起始位+数据位+校验位+停止位）
2. 数据位流进入 STM32 的 RX 引脚 → USART 接收移位寄存器逐位接收
3. 一帧接收完成后，数据从接收移位寄存器转入数据寄存器 **DR**
4. 硬件自动置位状态寄存器 SR 中的 **RXNE 位**（Read Data Register Not Empty，接收数据寄存器非空）
5. 若此前已使能接收中断（CR1 寄存器的 RXNEIE 位 = 1），USART 向 NVIC 发出中断请求
6. NVIC 仲裁通过后，CPU 保存现场 → 从向量表取出 USARTx_IRQHandler 地址 → 跳转执行
7. ISR 中读取 DR 寄存器（**读 DR 会硬件自动清除 RXNE 标志**）→ 将数据存入缓冲区或直接处理
8. ISR 返回 → CPU 恢复现场 → 继续主程序


::: tip

核心原理：USART 硬件自动完成逐位接收和帧解析，CPU 只在"一帧数据就绪"时被打断一次。读 DR 寄存器会自动清除 RXNE 标志，无需手动清除——这与 EXTI 中断需要手动清除挂起位不同，是串口中断的重要特点。

:::



::: tip

USART 可触发的中断源不止 RXNE：还包括 TXE（发送数据寄存器空）、TC（发送完成）、IDLE（总线空闲）、ORE（溢出错误）、PE（校验错误）等。本实验主要使用 RXNE 接收中断。

:::


## 配置与实现

### 配置步骤

1. **使能时钟**：开启 GPIO 端口时钟和 USART 外设时钟（注意 USART1 在 APB2，USART2/3 在 APB1）
2. **配置 GPIO**：通过 HAL_GPIO_Init() 配置，TX 引脚设为复用推挽输出（GPIO_MODE_AF_PP），RX 引脚设为浮空输入（GPIO_MODE_INPUT）
3. **配置 USART 参数**：设置波特率（如 115200）、数据位（8位）、停止位（1位）、校验位（无）、硬件流控（无）
4. **使能接收中断**：调用 \_\_HAL_UART_ENABLE_IT(&huartx, UART_IT_RXNE)，使能 RXNE 中断
5. **配置 NVIC**：设置 USARTx 中断的抢占优先级和响应优先级，使能该中断通道
6. **编写 ISR**：实现 USARTx_IRQHandler，检查 RXNE 标志→读 DR→处理数据

### 中断服务函数

```c
// 全局接收缓冲区
volatile uint8_t rx_buf[256];
volatile uint8_t rx_len = 0;

void USART1_IRQHandler(void)
{
    uint8_t data;

    // 1. 检查接收中断标志（RXNE）
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_RXNE) != RESET)
    {
        // 2. 读取数据寄存器（读 DR 自动清除 RXNE 标志）
        data = (uint8_t)(huart1.Instance->DR & (uint8_t)0x00FF);

        // 3. 存入接收缓冲区（或直接处理）
        if (rx_len < 256)
        {
            rx_buf[rx_len++] = data;
        }

        // 可选：回显收到的数据
        HAL_UART_Transmit(&huart1, &data, 1, 100);
    }

    // 4. 检查溢出错误（可选，ORE 标志需读 SR 再读 DR 清除）
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_ORE) != RESET)
    {
        __HAL_UART_CLEAR_OREFLAG(&huart1);
    }
}
```


::: tip

常见问题：①忘记使能 RXNE 中断（\_\_HAL_UART_ENABLE_IT）→ 收数据但不触发中断；②ISR 中未读 DR → RXNE 标志一直置位，反复进入中断；③波特率不匹配 → 收到乱码；④未处理 ORE 溢出错误 → 数据覆盖丢失；⑤共享变量未加 volatile → 主循环读取缓冲区时编译器优化导致不一致。

:::




# 串讲

按"为什么→是什么→怎么管→怎么写→怎么用"一条主线重新编排为五讲。

## 第一讲 为什么需要中断——本质

### 中断 vs 轮询

中断的本质是**CPU与外设之间的异步通信机制**。

- **轮询**：CPU每隔一段时间去查询外设状态，大部分时间在空等（像每隔10秒去门口看有没有人）。
- **中断**：外设准备好后主动通知CPU，CPU平时执行主任务，收到通知后暂停当前工作去处理外设事件，处理完再回到原任务（像门铃响了再去开门）。

### 中断系统的三个根本问题

1. **谁在请求？**——中断源识别（向量表）
2. **先处理谁？**——优先级仲裁（NVIC）
3. **处理完怎么回来？**——上下文保存与恢复（硬件自动完成）

## 第二讲 一次中断的完整旅程——硬件架构

### 信号流向四步

记住这条信号链，后面所有内容都是这条链上某个环节的展开：

**外设/GPIO → EXTI → NVIC → CPU（取向量→执行ISR→返回）**

| 模块 | 管什么 | 关键动作 |
|-|-|-|
| 外设/GPIO | 事件源 | 按键跳变、串口收完一帧、定时器溢出 |
| EXTI | 有没有外部事件 | 边沿检测（上升/下降/双边沿）→ 置挂起位 → 发请求给NVIC |
| NVIC | 让不让进、先处理谁 | 检查使能位 → 优先级仲裁 → 挂起/激活管理 → 通知CPU |
| CPU | 进来后做什么 | 自动压栈8个寄存器 → 查向量表取ISR地址 → 执行 → 出栈返回 |

### 中断 vs 事件（EXTI的两种模式）

| 对比项 | 中断（Interrupt） | 事件（Event） |
|-|-|-|
| 是否经过CPU | 需要CPU介入，执行ISR | 不经过CPU，直接通知片上外设动作 |
| 用途 | 需要软件处理的外部事件 | 硬件自动联动（如触发ADC、DMA） |
| 延迟 | 有中断响应延迟 | 硬件直接触发，延迟极低 |

### 中断 vs 异常

| 对比项 | 中断（Interrupt） | 异常（Exception） |
|-|-|-|
| 触发源 | 外部设备（定时器、外部输入等） | 执行指令引起（除零、访问越界内存等） |
| 同步/异步 | 异步（与指令执行无关） | 同步（由特定指令触发） |
| 编号 | 从0开始（IRQ0\~） | 负编号（Reset=-3、NMI=-2、HardFault=-1） |

两者在NVIC里统一管理，异常编号为负，外设中断从0开始。

## 第三讲 三大核心机制

### 机制一：中断向量表

向量表是一个**函数指针数组**，位于存储器起始位置（默认0x08000000），CPU根据中断号从中取出ISR地址直接跳转。这就是"向量中断"的含义——硬件直接根据中断号跳转到对应处理函数，而不是进入一个统一入口再由软件查询，大大降低了中断延迟。

| 偏移 | 名称 | 说明 |
|-|-|-|
| 0x00 | 初始MSP | 主堆栈指针初始值（不是函数地址） |
| 0x04 | Reset | 复位中断，程序入口，优先级-3（最高） |
| 0x08 | NMI | 不可屏蔽中断，优先级-2 |
| 0x0C | HardFault | 硬件错误，所有未处理错误的兜底，优先级-1 |
| 0x10\~0x3C | 内核异常 | MemManage/BusFault/UsageFault/SVC/PendSV/SysTick等 |
| 0x40起 | 外设中断 | EXTI、USART、TIM、ADC等片上外设 |


::: tip

**ISR函数名是固定的**，由启动文件中的向量表定义决定。例如：EXTI0→EXTI0_IRQHandler，USART1→USART1_IRQHandler，TIM2→TIM2_IRQHandler，SysTick→SysTick_Handler。
函数名写错→中断触发后跳到启动文件的弱符号默认处理函数（通常是死循环）→表现为程序卡死。这是初学者最常见的错误之一。

:::


**三种编号系统的区别**

STM32的中断/异常在不同场景下使用三种不同的编号，初学者容易混淆。下表将三者完整对照：

| 异常编号（向量表位置） | CMSIS IRQn值（代码中用） | 固定优先级值 | 名称 |
|-|-|-|-|
| 1 | -15 | -3（最高） | Reset |
| 2 | -14 | -2 | NMI |
| 3 | -13 | -1 | HardFault |
| 4 | -12 | 可配置（默认0） | MemManage |
| 5 | -11 | 可配置（默认0） | BusFault |
| 6 | -10 | 可配置（默认0） | UsageFault |
| 11 | -5 | 可配置（默认0） | SVCall |
| 12 | -4 | 可配置（默认0） | DebugMonitor |
| 14 | -2 | 可配置（默认0） | PendSV |
| 15 | -1 | 可配置（默认0） | SysTick |
| 16起 | 0起 | 可配置（默认0） | 外设中断（IRQ0\~） |


::: tip

**换算关系**：CMSIS IRQn值 = 异常编号 - 16。例如Reset的异常编号是1，IRQn = 1 - 16 = -15。代码中使用HAL_NVIC_SetPriority()等函数时，传入的是IRQn值（如Reset_IRQn、EXTI0_IRQn），不是异常编号。
**注意区分**：优先级值（-3/-2/-1）是另一套体系，仅Reset、NMI、HardFault三个异常拥有固定负优先级，不可修改；其余异常和外设中断的优先级可配置，复位后默认值为0。不要把"异常编号"和"优先级值"搞混。

:::


### 机制二：优先级体系（二维模型）

STM32的中断优先级不是一个简单的数字，而是由**抢占优先级**和**子优先级（响应优先级）**共同组成的二维体系。STM32只实现了4位优先级（高4位Bit7\~Bit4有效），低4位未实现：读取低4位总是0，对低4位写入会被忽略。

**两个优先级的区别**

| 维度 | 能否打断当前中断 | 作用 |
|-|-|-|
| 抢占优先级 | **能**——高抢占可打断低抢占（嵌套） | 区分紧急程度（如紧急停止>普通通信） |
| 子优先级 | **不能**——仅多个中断同时pending时排序 | 区分同级别内的先后顺序 |
| 自然优先级 | 不能 | 前两者都相同时，中断号小者优先（不可编程） |

**数值越小，优先级越高。**

**优先级分组**

4位优先级寄存器如何在抢占位和子优先级位之间分配，由优先级分组决定（通过SCB->AIRCR寄存器配置）。


::: tip

整个系统只能设置**一个**优先级分组，所有中断共享同一分组方式，通常在系统初始化时调用一次HAL_NVIC_SetPriorityGrouping()即可。

:::


| 分组 | 抢占:子 | 抢占等级数 | 子优先级等级数 |
|-|-|-|-|
| NVIC_PriorityGroup_0 | 0:4 | 1（无嵌套） | 16 |
| NVIC_PriorityGroup_1 | 1:3 | 2 | 8 |
| NVIC_PriorityGroup_2 | 2:2 | 4 | 4 |
| NVIC_PriorityGroup_3 | 3:1 | 8 | 2 |
| NVIC_PriorityGroup_4 | 4:0 | 16 | 1（无子优先级） |

**优先级仲裁规则**

1. 先比较**抢占优先级**，高者先执行；高者可抢占低者（嵌套）
2. 抢占优先级相同，比较**子优先级**，高者先执行；但不能抢占
3. 两者都相同，比较**自然优先级**（中断向量表编号，小者优先）
4. 只有抢占优先级不同才能发生嵌套；子优先级不同不能嵌套

**固定负优先级**

Reset(-3)、NMI(-2)、HardFault(-1)三个异常拥有固定的负优先级，不可通过寄存器修改，永远高于任何可配置中断（≥0）。

这就是为什么PRIMASK将当前优先级提升到0时，NMI和HardFault仍能响应；只有FAULTMASK将优先级提升到-1时才能屏蔽HardFault，但NMI(-2)和Reset(-3)依然不受影响。

### 机制三：中断生命周期与两层清除

每个中断经历四个阶段：

1. **请求**：外设产生事件
2. **挂起（Pending）**：NVIC置位，中断已请求但CPU还没响应（可能在处理更高优先级中断）
3. **激活（Active）**：CPU进入ISR执行，活跃状态位置1
4. **结束**：ISR执行完毕返回主程序，活跃状态位清0


::: tip

**两层"清除"必须区分：**
① NVIC层挂起位：进入ISR时由**硬件自动清除**。
② 外设层中断标志（如EXTI_PR、USART_SR的RXNE）：**必须在ISR中软件手动清除**，否则外设会持续发出中断请求，导致反复进入中断。
不同外设的清标志方式不同：EXTI需调用\_\_HAL_GPIO_EXTI_CLEAR_IT()；USART读DR寄存器会自动清除RXNE标志。

:::


## 第四讲 寄存器与编程接口

### NVIC寄存器

NVIC寄存器位于Cortex-M内核私有外设总线（PPB）上，起始地址0xE000E100。所有寄存器均可按字（32位）访问，每一位对应一个中断通道。

| 寄存器 | 功能 | 设计要点 |
|-|-|-|
| ISER[8] | 中断使能寄存器 | 写1使能对应中断，写0无效 |
| ICER[8] | 中断禁用寄存器 | 写1禁用对应中断，写0无效 |
| ISPR[8] | 中断挂起寄存器 | 写1手动挂起中断（软件触发） |
| ICPR[8] | 清除挂起寄存器 | 写1清除挂起状态 |
| IABR[8] | 激活位寄存器 | **只读**，指示当前正在处理的中断 |
| IPR[60] | 优先级寄存器 | 每个中断8位（STM32仅高4位有效） |


::: tip

设计要点：使能/禁用、挂起/解挂都采用"写1有效"的独立寄存器对（SET/CLEAR），而不是读-改-写，这样可以避免多任务环境下的竞态问题——直接写1到对应位即可，不影响其他位。

:::


### SCB寄存器

SCB（System Control Block，系统控制块）也是Cortex-M内核的内置模块，负责管理系统异常、向量表偏移和优先级分组等全局配置。

| 寄存器 | 功能 |
|-|-|
| AIRCR | 应用中断/复位控制寄存器，设置优先级分组（PRIGROUP字段）、系统复位 |
| VTOR | 向量表偏移寄存器，可重定位向量表基地址 |
| SHPR0\~3 | 系统处理优先级寄存器，设置系统异常（MemManage/BusFault/UsageFault/SVC/PendSV/SysTick）的优先级 |
| SHCSR | 系统处理控制和状态寄存器，系统异常的使能与激活状态 |
| ICSR | 系统异常控制和状态寄存器，NMI、PendSV等异常挂起控制与状态 |

NVIC管"外部中断"（IRQ0\~IRQn），SCB管"系统异常"（Reset/NMI/HardFault/SVC/PendSV/SysTick等）。优先级分组通过SCB的AIRCR寄存器全局设置，对NVIC和系统异常同时生效。

### HAL库NVIC接口

STM32 HAL库对NVIC寄存器操作进行了封装，提供10个标准函数，覆盖四类操作：

| 类别 | 函数 | 对应寄存器 |
|-|-|-|
| 优先级分组 | HAL_NVIC_SetPriorityGrouping | SCB->AIRCR |
| 优先级分组 | HAL_NVIC_GetPriorityGrouping | SCB->AIRCR |
| 中断优先级 | HAL_NVIC_SetPriority | NVIC->IP[IRQn] |
| 中断优先级 | HAL_NVIC_GetPriority | NVIC->IP[IRQn] |
| 中断使能 | HAL_NVIC_EnableIRQ | NVIC->ISER[IRQn/32] |
| 中断使能 | HAL_NVIC_DisableIRQ | NVIC->ICER[IRQn/32] |
| 挂起控制 | HAL_NVIC_SetPendingIRQ | NVIC->ISPR[IRQn/32] |
| 挂起控制 | HAL_NVIC_GetPendingIRQ | NVIC->ISPR[IRQn/32] |
| 挂起控制 | HAL_NVIC_ClearPendingIRQ | NVIC->ICPR[IRQn/32] |
| 激活状态 | HAL_NVIC_GetActive | NVIC->IABR[IRQn/32] |


::: tip

使用顺序：先SetPriorityGrouping（全局一次，通常在main开头）→ 再SetPriority → 最后EnableIRQ。IRQn参数使用枚举类型（如EXTI0_IRQn、USART1_IRQn），不要直接写数字。HAL_NVIC_GetPriority需要传入当前PriorityGroup才能正确解码出抢占和响应优先级。

:::


### HAL库与寄存器的关系

本文档统一使用**HAL库**（如HAL_NVIC_xxx、HAL_GPIO_Init、\_\_HAL_UART_ENABLE_IT、\_\_HAL_GPIO_EXTI_GET_IT等）。HAL库函数是对底层寄存器操作的封装，函数名不同但操作的底层寄存器完全一样。理解了寄存器层（如NVIC->ISER、NVIC->IP、EXTI->PR等），就能更好地理解HAL库函数的作用和行为。

### 中断屏蔽寄存器（CPU层）

Cortex-M内核提供三个特殊寄存器，用于在软件中灵活控制中断的屏蔽：

| 寄存器 | 屏蔽效果 | 仍可响应 | 典型用途 |
|-|-|-|-|
| PRIMASK | 优先级设为0，屏蔽所有可屏蔽中断 | NMI、HardFault、Reset | 短时临界区、时序关键代码 |
| FAULTMASK | 优先级设为-1，连HardFault也屏蔽 | NMI、Reset | 极端关键操作（极少使用） |
| BASEPRI | 屏蔽优先级低于设定值的中断 | ≥设定值的中断、NMI、HardFault | 精细屏蔽，只关低优先级中断 |

## 第五讲 实战——配置步骤与两个实验

### 通用配置六步

任何中断的配置都遵循以下六步，缺一不可：

1. **使能时钟**：开启GPIO端口时钟和外设时钟（EXTI和NVIC不需要单独开时钟）
2. **配置GPIO**：输入/输出模式、上拉/下拉
3. **配置外设映射**：如AFIO将GPIO映射到EXTI线；USART配置波特率等参数
4. **配置外设中断**：EXTI触发方式+使能；USART使能RXNE中断
5. **配置NVIC**：优先级分组（全局一次）→ 设置抢占/子优先级 → 使能中断通道
6. **编写ISR**：检查标志 → 执行动作 → 清除外设挂起位

### 实验一：按键外部中断（EXTI）

**信号流向**

按键按下 → PA0下降沿 → EXTI0检测到边沿 → 置EXTI_PR挂起位 → 发请求给NVIC → NVIC仲裁通过 → CPU跳转到EXTI0_IRQHandler → 翻转LED → 清EXTI_PR → 返回

**EXTI要点**

- 16条线对应Pin0\~Pin15，**同编号引脚（如PA0和PB0）不能同时用中断**，通过AFIO的EXTICR寄存器选择具体端口
- 16条线只对应7个ISR：EXTI0\~4各一个，EXTI5\~9共享EXTI9_5_IRQHandler，EXTI10\~15共享EXTI15_10_IRQHandler（共享时必须在ISR中检查具体是哪条线）
- 触发方式：上升沿/下降沿/双边沿
- STM32F407有23条中断/事件输入线：16条GPIO线 + 7条内部线（PVD、RTC闹钟、USB唤醒、以太网唤醒等）

**中断服务函数**

```c
void EXTI0_IRQHandler(void)
{
    // 第一步：确认中断标志（必须！共享中断线时尤其重要）
    if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_0) != RESET)
    {
        // 处理中断事件，如翻转LED
        HAL_GPIO_TogglePin(GPIOA, GPIO_PIN_5);

        // 第二步：清除中断挂起位（必须！否则会反复进入中断）
        __HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0);
    }
}
```


::: tip

两个"必须"：① ISR开头必须检查中断标志位，确认是本通道触发（共享中断线时尤其重要）；② 处理完毕必须清除中断挂起位，否则中断会一直pending，导致反复进入。

:::


### 实验二：串口接收中断（USART RXNE）

**信号流向**

外部发送数据帧 → RX引脚逐位接收 → 一帧完成 → 数据移入DR寄存器 → 硬件置RXNE标志 → 若RXNEIE已使能则发中断请求 → NVIC → CPU跳转到USART1_IRQHandler → 读DR（自动清RXNE）→ 存入缓冲区 → 返回

**与EXTI的关键区别**


::: tip

串口读DR寄存器会**硬件自动清除RXNE标志**，不需要手动调用清除函数；而EXTI必须手动调用\_\_HAL_GPIO_EXTI_CLEAR_IT()。这是初学者容易混淆的点。
USART可触发的中断源不止RXNE：还包括TXE（发送数据寄存器空）、TC（发送完成）、IDLE（总线空闲）、ORE（溢出错误）、PE（校验错误）等。

:::


**配置步骤**

1. 使能时钟：开启GPIO端口时钟和USART外设时钟（注意USART1在APB2，USART2/3在APB1）
2. 配置GPIO：通过HAL_GPIO_Init()配置，TX引脚设为复用推挽输出（GPIO_MODE_AF_PP），RX引脚设为浮空输入（GPIO_MODE_INPUT）
3. 配置USART参数：波特率（如115200）、数据位（8位）、停止位（1位）、校验位（无）、硬件流控（无）
4. 使能接收中断：调用\_\_HAL_UART_ENABLE_IT(&huartx, UART_IT_RXNE)
5. 配置NVIC：设置USARTx中断的抢占优先级和响应优先级，使能该中断通道
6. 编写ISR：实现USARTx_IRQHandler，检查RXNE标志→读DR→处理数据

**中断服务函数**

```c
// 全局接收缓冲区
volatile uint8_t rx_buf[256];
volatile uint8_t rx_len = 0;

void USART1_IRQHandler(void)
{
    uint8_t data;

    // 1. 检查接收中断标志（RXNE）
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_RXNE) != RESET)
    {
        // 2. 读取数据寄存器（读DR自动清除RXNE标志）
        data = (uint8_t)(huart1.Instance->DR & (uint8_t)0x00FF);

        // 3. 存入接收缓冲区（或直接处理）
        if (rx_len < 256)
        {
            rx_buf[rx_len++] = data;
        }

        // 可选：回显收到的数据
        HAL_UART_Transmit(&huart1, &data, 1, 100);
    }

    // 4. 检查溢出错误（可选，ORE标志需读SR再读DR清除）
    if (__HAL_UART_GET_FLAG(&huart1, UART_FLAG_ORE) != RESET)
    {
        __HAL_UART_CLEAR_OREFLAG(&huart1);
    }
}
```

### ISR设计原则（五条铁律）

1. **越短越好**：ISR中只做最必要的操作，耗时任务（如数据处理、通信）放到主循环中通过标志位触发
2. **不调用阻塞函数**：ISR中不能使用延时、等待等阻塞操作
3. **注意共享变量**：ISR与主循环共享的变量必须用volatile修饰，防止编译器优化导致不一致
4. **避免printf**：串口打印耗时较长，尽量不在ISR中使用（调试时可临时用）
5. **先判断后清除**：先检查标志位确认中断源，处理完再清除挂起位

```c
// 共享标志位
volatile uint8_t key_pressed = 0;

void EXTI0_IRQHandler(void)
{
    if (__HAL_GPIO_EXTI_GET_IT(GPIO_PIN_0) != RESET)
    {
        key_pressed = 1;  // 只设标志
        __HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0);
    }
}

int main(void)
{
    // ... 初始化 ...
    while (1)
    {
        if (key_pressed)
        {
            key_pressed = 0;
            // 耗时的处理逻辑放在这里
            process_key_event();
        }
    }
}
```

### 常见问题速查

| 现象 | 可能原因 | 排查方法 |
|-|-|-|
| 中断完全不触发 | ①时钟未使能 ②NVIC未使能 ③函数名写错 ④GPIO模式错误 | 逐项检查六步配置；在ISR中打断点确认是否进入 |
| 反复进入中断 | 未清除外设中断挂起位 | 确认ISR中调用了\_\_HAL_GPIO_EXTI_CLEAR_IT()（EXTI）或读了DR（USART） |
| 程序卡死在启动文件 | ISR函数名与向量表不匹配 | 检查函数名拼写，对照启动文件中的弱符号定义 |
| 中断嵌套不生效 | 抢占优先级相同，或优先级分组设置不当 | 确认两个中断的抢占优先级不同；检查优先级分组 |
| 变量值异常 | 共享变量未加volatile | ISR与主循环共享的变量加volatile修饰 |
| 按键抖动导致多次触发 | 机械按键抖动，边沿多次跳变 | 硬件加消抖电容，或软件延时消抖（ISR中不建议，可在主循环处理） |
| 串口收数据但不触发中断 | 忘记使能RXNE中断（\_\_HAL_UART_ENABLE_IT） | 确认调用了\_\_HAL_UART_ENABLE_IT(&huartx, UART_IT_RXNE) |
| 串口收到乱码 | 波特率不匹配 | 检查发送端和接收端波特率是否一致 |

### 学习路径建议

1. **理解概念**：先搞懂中断vs轮询、抢占vs子优先级、向量表的本质
2. **跑通最小例程**：用一个按键外部中断控制LED，完整走一遍六步配置
3. **实验嵌套**：配置两个不同抢占优先级的中断，验证嵌套效果
4. **阅读启动文件**：打开startup_stm32fxxx.s，找到向量表，理解弱符号机制
5. **接触更多中断源**：定时器中断、串口接收中断、ADC转换完成中断，逐步扩展
6. **深入异常处理**：学习HardFault等内核异常的排查方法
