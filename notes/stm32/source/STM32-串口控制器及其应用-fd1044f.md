# STM32 串口控制器及其应用学习第一性原理

## 第一性原理学习法


::: tip

**核心思想：**不背寄存器、不抄例程，从"信息如何从一根线传到另一根线"这个最基本的问题出发，逐层推导到硬件实现和代码。

:::


学习串口的三个追问层次：

1. **物理层：**一根线上的电压如何变成 0 和 1？
2. **协议层：**接收方怎么知道哪几个 bit 组成一个字节？
3. **实现层：**STM32 用什么硬件电路自动完成上述过程，CPU 只需读写寄存器？

## 串口通信的本质

### 物理层：单端信号与电平标准

串口（UART）只用两根数据线就能实现全双工通信：

- **TX（Transmit）：**发送端输出
- **RX（Receive）：**接收端输入

连接规则：**A 的 TX 接 B 的 RX，A 的 RX 接 B 的 TX**，GND 共地。

<table><colgroup><col/><col/><col/><col/><col/></colgroup><thead><tr><th>电平标准</th><th>逻辑 1</th><th>逻辑 0</th><th>典型电压</th><th>用途</th></tr></thead><tbody><tr><td>TTL/CMOS</td><td>高电平</td><td>低电平</td><td>3.3V / 5V</td><td>板内、短距离</td></tr><tr><td>RS232</td><td>负电压</td><td>正电压</td><td>±3V ~ ±15V</td><td>工业、长距离</td></tr><tr><td>RS485</td><td colspan="2">差分信号 A/B</td><td>±200mV 以上</td><td>多机、远距离</td></tr></tbody></table>


::: tip

**关键认知：**STM32 引脚输出的是 TTL 电平（3.3V）。如果要接 RS232 设备，中间必须加 MAX3232 等电平转换芯片；接 RS485 需加 SP3485 等收发器。

:::


### 协议层：UART 帧格式

UART 是**异步通信**——没有单独的时钟线。接收方靠约定的波特率和帧格式来解析数据。

一个完整的 UART 数据帧（以最常用的 8N1 为例）：

```text
空闲  起始位  D0  D1  D2  D3  D4  D5  D6  D7  停止位  空闲
─────┐     ┌────┬────┬────┬────┬────┬────┬────┬────┐     ┌─────
     │     │    │    │    │    │    │    │    │    │     │
     └─────┴────┴────┴────┴────┴────┴────┴────┴────┴─────┘
     (1bit) (          8 bit 数据          ) (1bit)
```

| 组成部分 | 位数 | 电平特征 | 作用 |
|-|-|-|-|
| 空闲位 | 任意 | 高电平 | 线路空闲状态 |
| 起始位 | 1 | 低电平 | 标志一帧开始，接收方据此同步 |
| 数据位 | 5\~9 | — | 实际传输的数据，低位在前（LSB First） |
| 校验位 | 0/1 | — | 奇校验/偶校验，可选 |
| 停止位 | 1/1.5/2 | 高电平 | 标志一帧结束，留出同步余量 |


::: tip

**第一性原理推导：**为什么需要起始位和停止位？因为异步通信没有时钟，接收方必须靠"从高到低的跳变"来定位每个 bit 的采样时刻。起始位提供这个跳变，停止位保证下一个起始位一定有"高→低"的跳变。

:::


### 波特率与采样

**波特率（Baud Rate）：**每秒传输的符号数，单位 bps。常用值：9600、115200、921600。

接收方为了准确采样每个 bit，通常使用**16 倍过采样**（Oversampling by 16）：

- 检测到起始位下降沿后，计数器开始计数
- 在第 8 个采样周期（即 bit 周期的中点）采样起始位，确认是低电平
- 之后每隔 16 个采样周期（即每个 bit 的中点）采样一次数据位

这就是为什么波特率有误差容忍度——只要双方频率偏差不超过一定范围（通常 ±2%\~±5%），中点采样仍然有效。

## STM32 USART 控制器硬件架构

### 3.1 整体结构

STM32 的 USART（Universal Synchronous/Asynchronous Receiver/Transmitter）是一个完整的硬件通信外设，CPU 只需配置寄存器和读写数据，其余时序由硬件自动完成。

```text
         ┌─────────────────────────────────────────────┐
         │                  USART 外设                   │
         │                                               │
  TX ────┤  发送移位寄存器 ── 发送数据寄存器(TDR) ──┤  总线
         │     (移位输出)        (CPU写)                │
         │                                               │
  RX ────┤  接收移位寄存器 ── 接收数据寄存器(RDR) ──┤  总线
         │     (移位采样)        (CPU读)                │
         │                                               │
         │  波特率发生器(BRR)  控制寄存器(CR1/2/3)    │
         │  中断控制           DMA 请求                  │
         └─────────────────────────────────────────────┘
```

### 发送过程（硬件自动完成）

1. CPU 把数据写入 **TDR（Transmit Data Register）**
2. 硬件把 TDR 的数据搬运到**发送移位寄存器**，同时置位 TXE（TDR 空）标志
3. 移位寄存器按照配置的波特率，依次输出：起始位 → 数据位（LSB 在前）→ 校验位 → 停止位
4. 一帧发完后，硬件置位 TC（Transmission Complete）标志

### 接收过程（硬件自动完成）

1. RX 引脚检测到下降沿（起始位）
2. 硬件按 16 倍过采样确认起始位有效
3. 逐位采样数据位，移入**接收移位寄存器**
4. 收完一帧后，硬件把数据搬运到 **RDR（Receive Data Register）**，置位 RXNE（Read Data Register Not Empty）标志
5. CPU 读取 RDR，硬件自动清除 RXNE


::: tip

**关键认知：**TDR/RDR 是 CPU 与移位寄存器之间的"缓冲"。有了这层缓冲，CPU 写 TDR 后可以立刻去做别的事，硬件慢慢移位输出；同样，硬件收到数据后放进 RDR 等 CPU 来读，不会因为 CPU 没及时读就丢掉当前帧（但如果下一帧又来了还没读，就会置 ORE 溢出错误）。

:::


## 关键寄存器详解

### 寄存器总览

| 寄存器 | 全称 | 核心作用 |
|-|-|-|
| USART_CR1 | Control Register 1 | 使能、字长、校验、中断使能 |
| USART_CR2 | Control Register 2 | 停止位、LIN 模式、时钟引脚 |
| USART_CR3 | Control Register 3 | DMA、错误中断、智能卡、半双工 |
| USART_BRR | Baud Rate Register | 波特率分频系数 |
| USART_SR / ISR | Status / Interrupt Status | 各种状态标志（TXE/RXNE/TC/错误） |
| USART_DR / RDR/TDR | Data Register | 读写数据（F0/F1/L0 系列分开） |

*注：STM32F1 等旧系列用 SR/DR；F0/F3/F4/L0/L4 等新系列用 ISR/RDR/TDR 分开的寄存器。原理相同，命名不同。*

### USART_CR1 关键位

| 位 | 名称 | 含义 |
|-|-|-|
| 13 | UE | USART 使能（1=开启） |
| 12 | M | 字长（0=8位，1=9位） |
| 10 | PCE | 校验使能（1=开启校验） |
| 9 | PS | 校验选择（0=偶校验，1=奇校验） |
| 7 | TXEIE | 发送寄存器空中断使能 |
| 6 | TCIE | 发送完成中断使能 |
| 5 | RXNEIE | 接收寄存器非空中断使能 |
| 3 | TE | 发送使能（1=开启发送） |
| 2 | RE | 接收使能（1=开启接收） |

### 状态寄存器关键标志

| 标志 | 含义 | 何时置 1 | 如何清除 |
|-|-|-|-|
| TXE | TDR 空 | 数据从 TDR 移入移位寄存器 | 写 DR 自动清除 |
| TC | 发送完成 | 最后一帧的停止位已发出 | 读 SR + 写 DR，或软件写 0 |
| RXNE | RDR 非空 | 收到一帧数据，已移入 RDR | 读 DR 自动清除 |
| IDLE | 检测到空闲线路 | RX 线上持续一帧时间的高电平 | 读 SR + 读 DR |
| ORE | 溢出错误 | **RDR 数据未读，又收到新一帧** | 读 SR + 读 DR |
| FE | 帧错误 | 停止位采样为低电平 | 读 SR + 读 DR |
| NE | 噪声错误 | 采样时检测到噪声 | 读 SR + 读 DR |
| PE | 校验错误 | 校验位不匹配 | 读 SR + 读 DR（需使能 PEIE） |


::: tip

**新手最常踩的坑：**ORE 溢出错误。如果用查询方式接收但读得不够快，或者中断优先级太低导致 RXNE 没及时处理，新数据覆盖旧数据就会置 ORE。ORE 一旦置位，如果不清除，后续接收可能异常。清除方式是"先读 SR，再读 DR"。

:::


## 波特率计算

### 计算公式

USART 的波特率由 BRR 寄存器决定。核心公式：

$$\text{USARTDIV} = \frac{f_{CK&#125;&#125;{16 \times \text{BaudRate&#125;&#125;$$

其中 $f_{CK}$ 是 USART 的时钟源频率（通常是 PCLK1 或 PCLK2）。

### BRR 寄存器结构

BRR 是一个 16 位寄存器，分为两部分：

- **DIV_Mantissa[15:4]：**USARTDIV 的整数部分（12 位）
- **DIV_Fraction[3:0]：**USARTDIV 的小数部分 × 16（4 位）

### 计算示例

以 STM32F103 为例，USART1 挂在 APB2 上，PCLK2 = 72MHz，目标波特率 115200：

```text
USARTDIV = 72000000 / (16 × 115200)
         = 72000000 / 1843200
         = 39.0625

整数部分 = 39  → DIV_Mantissa = 39 = 0x27
小数部分 = 0.0625 × 16 = 1 → DIV_Fraction = 1 = 0x1

BRR = 0x271
```


::: tip

**为什么是 16？**因为接收端用 16 倍过采样。波特率发生器产生的不是 bit 时钟，而是 16 倍于波特率的采样时钟，所以分频系数要除以 16。部分系列支持 8 倍过采样（OVER8=1），此时公式中的 16 换成 8，精度更高但抗噪略差。

:::


## 三种工作方式

### 查询方式（Polling）

CPU 不断检查状态标志，就绪后才读写数据。

```c
// 等待 TDR 为空（TXE=1）
while (!(USART1->SR & USART_SR_TXE));
// 写入数据，硬件自动开始发送
USART1->DR = data;

// 等待发送完成（TC=1），如果需要确保最后一个字节发完
while (!(USART1->SR & USART_SR_TC));
```

```c
// 等待收到数据（RXNE=1）
while (!(USART1->SR & USART_SR_RXNE));
// 读取数据，读 DR 自动清除 RXNE
uint8_t data = (uint8_t)USART1->DR;
```

**优缺点：**简单直观，但 CPU 被阻塞，无法同时做其他事；接收时如果 CPU 去做别的事没及时读，容易 ORE 溢出。

### 中断方式（Interrupt）

配置好中断使能后，CPU 正常运行，事件发生时进入中断服务函数处理。

```c
// 使能 RXNE 中断：收到数据时触发中断
USART1->CR1 |= USART_CR1_RXNEIE;

// NVIC 配置 USART1 中断
NVIC_SetPriority(USART1_IRQn, 1);
NVIC_EnableIRQ(USART1_IRQn);
```

```c
void USART1_IRQHandler(void)
{
    // 接收中断：收到一个字节
    if (USART1->SR & USART_SR_RXNE)
    {
        uint8_t data = (uint8_t)USART1->DR; // 读 DR 清除 RXNE
        // 处理数据：存入缓冲区、解析协议等
        rx_buffer[rx_head++] = data;
    }

    // 发送中断：TDR 已空，可以写下一个字节
    if (USART1->SR & USART_SR_TXE)
    {
        if (tx_tail != tx_head)
        {
            USART1->DR = tx_buffer[tx_tail++];
        }
        else
        {
            // 缓冲区发完，关闭 TXE 中断（否则会一直进中断）
            USART1->CR1 &= ~USART_CR1_TXEIE;
        }
    }

    // 发送完成中断（可选）
    if (USART1->SR & USART_SR_TC)
    {
        USART1->SR &= ~USART_SR_TC; // 软件清除 TC
    }
}
```


::: tip

**TXE 中断的经典坑：**TXE 标志在 TDR 为空时就为 1，所以一旦使能 TXEIE 且 TDR 为空，就会**持续进入中断**。正确做法是：有数据要发时才使能 TXEIE，发完缓冲区后立刻关闭 TXEIE。不要在初始化时就使能 TXEIE。

:::


### DMA 方式

DMA（直接存储器访问）可以在不占用 CPU 的情况下，把数据从内存搬到 USART 的 TDR（发送），或从 RDR 搬到内存（接收）。

**适用场景：**大量数据传输（如固件升级、音频流、高速数据采集），CPU 可以同时做计算。

```c
// 1. 配置 DMA 通道：内存 → USART_DR
//    - 外设地址 = &USART1->DR
//    - 内存地址 = tx_buffer
//    - 数据长度 = 要发送的字节数
//    - 方向：内存到外设
//    - 内存地址递增，外设地址不递增

// 2. 使能 USART 的 DMA 发送请求
USART1->CR3 |= USART_CR3_DMAT;

// 3. 使能 DMA 通道，硬件自动完成传输
// 4. 传输完成后触发 DMA 中断，通知 CPU
```

```c
// 1. 配置 DMA 通道：USART_DR → 内存
//    - 外设地址 = &USART1->DR
//    - 内存地址 = rx_buffer
//    - 数据长度 = 缓冲区大小（循环模式下可设为缓冲区总大小）

// 2. 使能 USART 的 DMA 接收请求
USART1->CR3 |= USART_CR3_DMAR;

// 3. 使能 DMA 通道（建议用循环模式 Circular Mode）
// 4. 配合 IDLE 中断：检测到一帧结束时，CPU 去读 DMA 已传输的数量
```


::: tip

**DMA + IDLE 是接收不定长数据的经典方案：**DMA 循环把收到的字节不断写入缓冲区，USART 的 IDLE 中断在"总线空闲一帧时间"时触发，CPU 在 IDLE 中断里根据 DMA 计数器算出本次收到了多少字节，然后处理。这样既不丢数据，又不需要每个字节都进中断。

:::


## 典型应用

### printf 重定向

最常用的调试手段：把 printf 的输出通过串口发到电脑的串口助手。

```c
#include &lt;stdio.h&gt;

int fputc(int ch, FILE *f)
{
    // 等待发送寄存器空
    while (!(USART1->SR & USART_SR_TXE));
    USART1->DR = (uint8_t)ch;
    return ch;
}
```

```c
int _write(int fd, char *ptr, int len)
{
    for (int i = 0; i &lt; len; i++)
    {
        while (!(USART1->SR & USART_SR_TXE));
        USART1->DR = (uint8_t)ptr[i];
    }
    return len;
}
```

### 与传感器/模块通信

很多模块（蓝牙 HC-05、WiFi ESP8266、GPS、指纹模块等）都用串口通信，通常遵循"发送命令 → 等待回复"的模式。

```c
/**
 * @brief  发送命令，等待指定长度的回复
 * @param  cmd: 命令缓冲区
 * @param  cmd_len: 命令长度
 * @param  reply: 回复缓冲区
 * @param  reply_len: 期望回复长度
 * @param  timeout: 超时时间(ms)
 * @retval 0=成功，-1=超时
 */
int uart_send_cmd(uint8_t *cmd, uint16_t cmd_len,
                  uint8_t *reply, uint16_t reply_len,
                  uint32_t timeout)
{
    // 1. 清空接收缓冲区和计数
    rx_count = 0;

    // 2. 发送命令
    for (uint16_t i = 0; i &lt; cmd_len; i++)
    {
        while (!(USART1->SR & USART_SR_TXE));
        USART1->DR = cmd[i];
    }

    // 3. 等待回复（用中断把数据存入 rx_buffer/rx_count）
    uint32_t start = HAL_GetTick();
    while (rx_count &lt; reply_len)
    {
        if ((HAL_GetTick() - start) &gt; timeout)
            return -1; // 超时
    }

    // 4. 拷贝回复
    memcpy(reply, rx_buffer, reply_len);
    return 0;
}
```

### 自定义通信协议设计

当需要在两个 MCU 之间传输结构化数据时，需要设计自己的协议。一个健壮的协议至少包含：

| 字段 | 长度 | 作用 |
|-|-|-|
| 帧头 | 1\~2 字节 | 固定值（如 0xAA 0x55），用于帧同步 |
| 长度 | 1 字节 | 数据区长度，接收方知道要收多少 |
| 命令/类型 | 1 字节 | 标识这帧数据的含义 |
| 数据 | N 字节 | 实际载荷 |
| 校验 | 1\~2 字节 | 累加和 / CRC16，检测传输错误 |

## 常见问题与调试

###  完全收不到数据

1. **接线错误：**检查 TX/RX 是否接反，GND 是否共地
2. **电平不匹配：**3.3V 的 STM32 接 5V 设备可能需要电平转换（但多数 5V 设备的 RX 能识别 3.3V 高电平）
3. **波特率不一致：**双方必须配置相同的波特率、数据位、停止位、校验
4. **时钟配置错误：**BRR 计算依赖 PCLK 频率，如果系统时钟配置错了，实际波特率就不对
5. **GPIO 复用未配置：**TX 引脚要配为复用推挽输出，RX 引脚要配为浮空/上拉输入

### 收到乱码

1. **波特率误差过大：**用示波器测一个 bit 的宽度，反推实际波特率。常见原因是外部晶振频率与代码中定义的不一致（如代码写 8MHz 实际焊了 12MHz）
2. **帧格式不匹配：**数据位/停止位/校验位设置不一致
3. **共地不良：**长距离或强干扰环境下，地电位差导致采样错误

### 丢数据 / ORE 溢出

1. **查询方式读得太慢：**改用中断或 DMA
2. **中断优先级太低：**提高 USART 中断优先级，确保能及时响应
3. **中断服务函数太长：**ISR 里只做"存数据"，解析放到主循环
4. **忘记清除 ORE：**ORE 置位后必须"读 SR + 读 DR"清除，否则后续接收可能异常

### 调试工具

- **USB 转 TTL 模块：**CH340、CP2102、FT232，连接电脑和 MCU 串口
- **串口助手软件：**SSCOM、串口调试助手、Putty、MobaXterm
- **示波器 / 逻辑分析仪：**抓波形看实际波特率、帧格式、是否有噪声

## 学习路径与思考题

### 推荐学习顺序

1. **理解协议：**用逻辑分析仪或示波器抓一帧 8N1 数据，亲手数出起始位、数据位、停止位
2. **寄存器版发送：**不看库函数，直接配置 CR1/BRR，用查询方式发一个字节，在串口助手上看到
3. **寄存器版接收：**用查询方式接收电脑发来的字节，再发回去（回显）
4. **中断版收发：**改成中断方式，实现收发环形缓冲区
5. **printf 重定向：**能用 printf 打印变量
6. **DMA + IDLE：**实现不定长数据接收
7. **自定义协议：**设计帧格式，实现两个 MCU 之间的结构化通信
8. **实战项目：**用串口控制某个模块（如 ESP8266 连 WiFi、蓝牙透传、GPS 解析）

### 思考题（检验是否真正理解）

1. 为什么 UART 数据位是低位在前（LSB First），而不是高位在前？

# UART控制器原理

## 串口通信协议

### 什么是串口通讯

串口通讯是一种通过**串行（一位接着一位地）**传输数据的通信方式。在嵌入式系统中，串口通讯通常通过**UART控制器**实现，常用于嵌入式系统、传感器、单片机和外围设备之间的数据传输。

### 硬件连接

串口硬件连接非常简单，只需要 **Tx、Rx 和 GND** 三条线：

- 两个设备的 **Tx 与 Rx 交叉连接**（A的Tx接B的Rx，A的Rx接B的Tx）
- GND 直接连接（共地）

### 波特率

波特率表示在 1 秒钟内，两个串口设备之间能传输多少个码元。在串口通信中，**波特率等于比特率**。


::: tip

**公式：**比特率 = 波特率 × 单个调制状态（码元）对应的二进制位数

:::


常用波特率：**2400、4800、9600、115200**。

### 波特率的计算

波特率由 USART_BRR 寄存器配置，核心公式：

```text
Baud rate = fCK / (8 × (2 - OVER8) × USARTDIV)
```

以 STM32F407 为例（fCK = 42MHz，OVER8 = 0，Baud rate目标波特率 115200）：

```text
USARTDIV = fCK / (16 × Baud rate)
         = 42MHz / (16 × 115200)
         ≈ 22.78

DIV_Mantissa（整数部分）= 22
DIV_Fraction（小数部分）= 16 × 0.78 = 12.48 ≈ 12
```


::: tip

**关键理解：**OVER8=0 时使用 16 倍过采样，公式中分母为 16；OVER8=1 时使用 8 倍过采样，分母为 8，精度更高但抗噪略差。

:::


### 数据帧格式

一帧完整的串口数据帧由四部分组成：

1. **开始位**：以**低电平**开始，标志一帧的起始
2. **传输数据**：实际传输的数据位
3. **校验位**：可选，用于错误检测
4. **停止位**：总是以**高电平**结束，标志一帧结束

### 数据位

STM32F407 串口控制器可发送 **8 位或 9 位**数据：

- **8 位数据位**：最常用模式，用于一般数据收发
- **9 位数据位**：通常是为了使用校验位（多出的 1 位作为校验位）

### 奇偶校验

校验位分为**奇校验**和**偶校验**两种：

- **奇校验**：保证一帧数据中高电平（1）的个数为**奇数**
- **偶校验**：保证一帧数据中高电平（1）的个数为**偶数**


::: tip

**注意：**如果启用了校验位，数据位将被占用 1 位用作校验位。例如配置为 8 位数据位并启用校验，实际有效数据位为 7 位，有 1 位被用做校验位。

:::


### 停止位

停止位可配置为多种长度：**0.5 位、1 位、1.5 位、2 位**。最常用的是 1 位停止位（8N1 格式）。

## 数据收发流程与状态

### 发送流程

1. 将串口数据写入内存
2. 程序将内存中的数据填入串口控制器的 **TDR（发送数据寄存器）**
3. TDR 寄存器中的数据自动传入**发送移位寄存器**
4. 由移位寄存器将数据从 TX 引脚逐位发送出去

### 接收流程

1. 当 RX 引脚上有数据时，数据依次流入**接收移位寄存器**
2. 接收移位寄存器接收完成后，将数据写入 **RDR（接收数据寄存器）**
3. 程序读取 RDR 寄存器的数据，写入内存中使用

### 常用状态标志

| 状态标志 | 含义 | 说明 |
|-|-|-|
| **TXE** | 发送数据寄存器为空 | TDR 中的数据已移入移位寄存器，可写入新数据 |
| **TC** | 发送完成 | 发送移位寄存器已空，最后一帧的停止位已发出 |
| **IDLE** | 检测到空闲线路 | RX 线上持续一帧时间的高电平 |
| **RXNE** | 接收数据寄存器不为空 | 已收到一帧数据存入 RDR，等待 CPU 读取 |
| **ORE** | 接收溢出错误 | RDR 数据未读，又收到新一帧，导致数据覆盖 |
| **PE** | 奇偶校验错误 | 接收到的数据校验位不匹配 |

### 串口中断

每个状态标志都有对应的中断使能位，使能后状态置位时会触发中断：

| 中断事件 | 事件标志 | 中断使能位 |
|-|-|-|
| 发送数据寄存器为空 | TXE | TXEIE |
| 发送完成 | TC | TCIE |
| 准备好读取接收到的数据 | RXNE | RXNEIE |
| 奇偶校验错误 | PE | PEIE |
| 检测到空闲线路 | IDLE | IDLEIE |

### DMA 自搬运

通过串口 DMA 可以在**不需要 CPU 干涉**的情况下，自动完成数据搬运：

- **DMA 发送**：开启 DMA 发送功能后，当 TXE 标志置 1 时，自动将数据从内存加载到发送寄存器
- **DMA 接收**：开启 DMA 接收功能后，当 RXNE 标志置 1 时，自动将接收寄存器中的数据加载到内存


::: tip

**适用场景：**大量数据传输（如固件升级、音频流、高速数据采集），CPU 可以同时做其他计算，无需每个字节都进入中断。

:::


## 硬件流控

### 硬件流控概述

串口硬件流控是一种通过**物理信号线**控制数据传输的机制，用于协调两个设备间的数据流动，以**防止数据丢失或溢出**。

硬流控主要涉及两个信号线：

- **RTS（Request To Send）**：**输出信号**，用于指示本设备是否准备好接收数据
- **CTS（Clear To Send）**：**输入信号**，用于判断是否可以向对方设备发送数据

### RTS 流控制

如果使能 RTS 流控制（RTSE=1）：

- 只要 USART 接收器准备好接收新数据，便会将 **nRTS 变为有效（低电平）**
- 当接收寄存器已满时，会将 **nRTS 变为无效（高电平）**，表明发送过程会在当前帧结束后停止

### CTS 流控制

如果使能 CTS 流控制（CTSE=1）：

- 发送器在发送下一帧前检查 **nCTS**
- 如果 nCTS 有效（低电平），则发送下一数据；否则不发送
- 如果在发送过程中 nCTS 变为无效，则当前发送完成之后，发送器停止


::: tip

**配对使用：**RTS 和 CTS 交叉连接——A 的 RTS 接 B 的 CTS，A 的 CTS 接 B 的 RTS。这样当 A 的接收缓冲区满时，A 通过 RTS 通知 B 暂停发送，B 通过 CTS 检测到该信号后停止发送，从而防止溢出。

:::

## HAL库接口

### 初始化配置结构体

HAL 库通过 `UART_InitTypeDef` 结构体配置 UART 的基本参数：

```c
typedef struct {
    uint32_t BaudRate;    /* 波特率 */
    uint32_t WordLength;  /* 数据宽度（8位或9位）*/
    uint32_t StopBits;    /* 停止位宽度 */
    uint32_t Parity;      /* 校验位模式（无/奇/偶）*/
    uint32_t Mode;        /* 是否启用接收或发送模式 */
    uint32_t HwFlowCtl;   /* 是否启用硬件流控 */
} UART_InitTypeDef;
```

各字段常用取值：

| 字段 | 常用宏定义 | 说明 |
|-|-|-|
| BaudRate | 直接写数值，如 115200 | 每秒传输的比特数 |
| WordLength | UART_WORDLENGTH_8B / \_9B | 数据位宽度 |
| StopBits | UART_STOPBITS_1 / \_0_5 / \_1_5 / \_2 | 停止位个数 |
| Parity | UART_PARITY_NONE / \_EVEN / \_ODD | 校验模式 |
| Mode | UART_MODE_TX / \_RX / \_TX_RX | 收发模式 |
| HwFlowCtl | UART_HWCONTROL_NONE / \_RTS / \_CTS / \_RTS_CTS | 硬件流控 |

### 初始化函数

配置好结构体后，调用 `HAL_UART_Init` 完成 UART 控制器的初始化：

```c
HAL_StatusTypeDef HAL_UART_Init(UART_HandleTypeDef *huart);
```

| 项目 | 说明 |
|-|-|
| **功能** | 初始化 UART 控制器，根据句柄中的 Init 结构体配置寄存器 |
| **参数** | huart：UART 句柄指针，包含实例（如 USART1）和初始化参数 |
| **返回值** | HAL_OK 表示成功，其他表示错误 |

### 轮询方式收发

轮询方式通过不断检查状态标志来完成数据收发，函数会阻塞直到发送/接收完成或超时。

```c
/* 轮询方式发送数据 */
HAL_StatusTypeDef HAL_UART_Transmit(
    UART_HandleTypeDef *huart, /* UART句柄 */
    const uint8_t *pData,   /* 要发送数据的首地址 */
    uint16_t Size,          /* 要发送的字节数 */
    uint32_t Timeout        /* 超时时间（ms）*/
);

/* 轮询方式接收数据 */
HAL_StatusTypeDef HAL_UART_Receive(
    UART_HandleTypeDef *huart,
    uint8_t *pData,         /* 存放接收数据的首地址 */
    uint16_t Size,          /* 要接收的字节数 */
    uint32_t Timeout        /* 超时时间（ms）*/
);
```


::: tip

**特点：**函数阻塞执行，CPU 在此期间无法做其他事。适合简单场景和数据量小的情况；接收时如果超时时间设置不当，可能导致程序长时间卡住。

:::


### 中断方式收发

中断方式启动收发后立即返回，数据收发完成后通过中断回调函数通知 CPU。

```c
/* 中断方式发送数据 */
HAL_StatusTypeDef HAL_UART_Transmit_IT(
    UART_HandleTypeDef *huart,
    const uint8_t *pData,   /* 要发送数据的首地址 */
    uint16_t Size           /* 要发送的字节数 */
);

/* 中断方式接收数据 */
HAL_StatusTypeDef HAL_UART_Receive_IT(
    UART_HandleTypeDef *huart,
    uint8_t *pData,         /* 存放接收数据的首地址 */
    uint16_t Size           /* 要接收的字节数 */
);
```


::: tip

**回调函数：**发送完成后调用 `HAL_UART_TxCpltCallback()`，接收完成后调用 `HAL_UART_RxCpltCallback()`。用户可重写这两个回调函数处理收发完成后的逻辑。中断方式不阻塞 CPU，适合需要同时处理其他任务的场景。

:::


### DMA方式收发

DMA 方式由 DMA 控制器自动完成数据搬运，CPU 仅需启动传输，传输完成后通过 DMA 中断通知。

```c
/* DMA方式发送数据 */
HAL_StatusTypeDef HAL_UART_Transmit_DMA(
    UART_HandleTypeDef *huart,
    const uint8_t *pData,   /* 要发送数据的首地址 */
    uint16_t Size           /* 要发送的字节数 */
);

/* DMA方式接收数据 */
HAL_StatusTypeDef HAL_UART_Receive_DMA(
    UART_HandleTypeDef *huart,
    uint8_t *pData,         /* 存放接收数据的首地址 */
    uint16_t Size           /* 要接收的字节数 */
);
```


::: tip

**适用场景：**大量数据传输（如固件升级、音频流、高速数据采集）。DMA 搬运期间 CPU 可以并行做计算，效率最高。使用前需在 CubeMX 中配置对应 DMA 通道，并使能 UART 的 DMA 请求。

:::


### 三种收发方式对比

| 对比项 | 轮询（Polling） | 中断（IT） | DMA |
|-|-|-|-|
| **CPU占用** | 高（阻塞等待） | 中（每字节进中断） | 低（仅启动和完成） |
| **函数返回** | 收发完成后返回 | 启动后立即返回 | 启动后立即返回 |
| **超时参数** | 有 | 无 | 无 |
| **适用数据量** | 小数据 | 中等数据 | 大数据 |
| **完成通知** | 函数返回值 | 回调函数 | DMA中断/回调 |

# USB串口通讯应用

## 4.1 USB串口通讯概述

USB串口通讯是嵌入式开发中最常用的调试与数据交互方式之一。STM32单片机的UART串口管脚输出的是TTL电平，而PC机通常只有USB接口，因此需要通过TTL转USB芯片实现电平与协议的转换，使单片机能够与PC进行串口通讯。


::: tip

**核心思路：**STM32（TTL电平）→ TTL转USB芯片 → USB线缆 → PC机（虚拟串口）

:::


## 4.2 TTL电平标准

TTL（Transistor-Transistor Logic）电平是单片机串口最基础的电平标准，其定义如下：

| 逻辑值 | 电压范围 | 说明 |
|-|-|-|
| 逻辑 0（低电平） | 0V \~ 0.4V | 典型值 0V（GND） |
| 逻辑 1（高电平） | 2.4V \~ 5V | 典型值 3.3V 或 5V（取决于单片机供电） |

STM32单片机通常采用3.3V供电，因此其串口高电平典型值为3.3V，落在2.4V\~5V的TTL高电平范围内。

## 4.3 TTL转USB原理

由于STM32单片机串口管脚发出的都是TTL电平，而PC机的USB接口使用的是差分信号（D+ / D-），二者电平标准和协议完全不同，无法直接连接。因此需要在STM32单片机串口电路上增加一个TTL电平转USB信号的转换芯片。

### 4.3.1 常用转换芯片

| 芯片型号 | 厂商 | 特点 |
|-|-|-|
| CH340 / CH340G | 沁恒（WCH） | 国产芯片，价格低廉，使用广泛，需安装驱动 |
| CP2102 | Silicon Labs | 稳定性好，需安装驱动 |
| PL2303 | Prolific | 老牌方案，需安装驱动 |
| FT232RL | FTDI | 工业级稳定性，价格较高，驱动完善 |

## 4.4 硬件连接步骤

以下是STM32与USB转串口模块的详细连接步骤：

1. **确认模块引脚：**USB转串口模块通常引出4个引脚——VCC、GND、TXD、RXD。
2. **连接电源：**将模块的VCC引脚连接到STM32开发板的3.3V或5V电源（根据模块要求），GND引脚连接到开发板的GND。


::: tip

   **注意：**必须共地！STM32与USB转串口模块的GND必须连接在一起，否则电平参考不一致，通讯会失败。

:::

3. **交叉连接串口线：**

   - STM32的TX（发送）→ USB转串口模块的RX（接收）
   - STM32的RX（接收）→ USB转串口模块的TX（发送）


::: tip

   **记忆口诀：**发接收，收接发，TX接RX，RX接TX。

:::

4. **连接USB线缆：**用USB数据线将模块连接到PC机的USB接口。
5. **安装驱动：**首次使用时，在PC上安装对应芯片的USB转串口驱动（如CH340驱动）。
6. **确认串口号：**打开PC的设备管理器，在"端口（COM和LPT）"中查看新出现的虚拟串口号（如COM3、COM4等）。

## 4.5 软件配置步骤

### 4.5.1 STM32CubeMX配置

1. 打开STM32CubeMX，选择对应芯片型号（如STM32F103C8T6）。
2. 在"Pinout & Configuration"页面，点击左侧"Connectivity"→"USART1"（或其他可用USART）。
3. 将Mode设置为"Asynchronous"（异步模式）。
4. 在"Parameter Settings"中配置串口参数：

   - Baud Rate（波特率）：115200（常用值，也可选9600等）
   - Word Length（数据位）：8 Bits
   - Parity（校验位）：None
   - Stop Bits（停止位）：1
   - Data Direction（数据方向）：Receive and Transmit
5. 确认引脚映射：PA9为USART1_TX，PA10为USART1_RX（以F103为例）。
6. 配置时钟树，确保系统时钟正确（如72MHz）。
7. 生成代码（Project Manager → 填写工程名和路径 → 选择IDE → GENERATE CODE）。

### 4.5.2 串口发送数据（轮询方式）

在生成的代码中，使用HAL库函数发送数据：

```c
// 定义发送缓冲区
uint8_t tx_buffer[] = "Hello, USB Serial!\r\n";

// 在main函数的while循环中发送数据
HAL_UART_Transmit(&huart1, tx_buffer, sizeof(tx_buffer) - 1, 100);
HAL_Delay(1000);
```

### 4.5.3 串口接收数据（中断方式）

1. 在STM32CubeMX中使能USART1全局中断（NVIC Settings → 勾选USART1 global interrupt）。
2. 在代码中定义接收缓冲区并启动接收中断：

```c
uint8_t rx_buffer[1];  // 单字节接收缓冲区

// 在main函数初始化后启动接收中断
HAL_UART_Receive_IT(&huart1, rx_buffer, 1);

// 接收完成回调函数（接收1字节后自动调用）
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART1)
    {
        // 将接收到的数据回显（回环测试）
        HAL_UART_Transmit(&huart1, rx_buffer, 1, 100);
        // 重新启动接收中断，准备下一字节
        HAL_UART_Receive_IT(&huart1, rx_buffer, 1);
    }
}
```

## 4.6 PC端串口调试助手使用步骤

1. 下载并安装串口调试助手（如XCOM、SSCOM、SecureCRT、MobaXterm等）。
2. 打开串口调试助手，选择正确的串口号（在设备管理器中确认的COM口）。
3. 配置串口参数，与STM32端保持一致：

   - 波特率：115200
   - 数据位：8
   - 校验位：None
   - 停止位：1
   - 流控：None
4. 点击"打开串口"按钮。
5. 观察接收区：如果STM32正在发送数据，应能看到"Hello, USB Serial!"等内容周期性输出。
6. 测试发送：在发送区输入字符，点击"发送"，观察STM32是否回显相同字符（如果使用了回环代码）。

## 4.7 常见问题与排查

| 问题现象 | 可能原因 | 排查方法 |
|-|-|-|
| 设备管理器中看不到COM口 | 驱动未安装 / USB线仅供电不传输数据 | 重新安装驱动；更换确认可传输数据的USB线 |
| 串口助手收不到数据 | TX/RX接反 / 未共地 / 波特率不匹配 / 串口未打开 | 检查TX-RX交叉连接；确认GND相连；核对两端波特率；确认串口已打开 |
| 收到乱码 | 波特率不匹配 / 时钟配置错误 / 数据位/校验位/停止位不一致 | 核对两端串口参数；检查STM32时钟树配置；用示波器测量实际波特率 |
| 只能发不能收 | STM32的RX引脚未正确配置 / 接收中断未使能 | 检查CubeMX中USART的Mode是否为Asynchronous；确认接收中断已使能并启动 |

# RS232串口通讯应用

## 5.1 RS232串口通讯概述

RS232是美国电子工业协会（EIA）制定的串行物理接口标准，全称是"数据终端设备（DTE）和数据通讯设备（DCE）之间串行二进制数据交换接口技术标准"。RS232采用负逻辑电平，具有较强的抗干扰能力，是工业控制和嵌入式领域中经典的串口通讯方式。


::: tip

**核心思路：**STM32（TTL电平）→ MAX232电平转换芯片 → RS232电平（DB9接口）→ RS232设备

:::


## 5.2 常见串口电平标准对比

两个设备间的串口通讯根据传输距离、现场环境等因素需要选择不同的物理电平标准。常用的标准有TTL标准、RS232标准、RS485标准。

| 特性 | TTL | RS232 | RS485 |
|-|-|-|-|
| 逻辑0电平 | 0V \~ 0.4V | +3V \~ +15V | A < B（差分） |
| 逻辑1电平 | 2.4V \~ 5V | -3V \~ -15V | A > B（差分） |
| 信号方式 | 单端信号 | 单端信号 | 差分信号 |
| 最大传输距离 | 约1米 | 约15米 | 约1200米 |
| 最大通讯速率 | 较高（受距离限制） | 20kbps（标准） | 10Mbps（短距离） |
| 抗干扰能力 | 弱 | 较强 | 强 |
| 接线方式 | TX、RX、GND（3线） | TX、RX、GND（3线）或全握手（9线） | A、B（2线半双工）或A、B、GND |
| 典型应用 | 板内/板间短距离通讯 | PC串口、工业设备、调试接口 | 工业现场总线、长距离多机通讯 |

## 5.3 TTL转RS232电平原理

由于STM32单片机串口管脚发出的都是TTL电平，想要使用RS232还需要在STM32单片机串口电路上增加一个电平转换芯片。最常用的转换芯片是MAX232。

### 5.3.1 电平转换规则

MAX232芯片完成TTL电平与RS232电平之间的双向转换，具体转换关系如下：

| 方向 | TTL电平 | RS232电平 | 逻辑值 |
|-|-|-|-|
| TTL → RS232（发送） | > 2.4V（高电平） | -3V \~ -15V | 逻辑1 |
| TTL → RS232（发送） | < 0.8V（低电平） | +3V \~ +15V | 逻辑0 |
| RS232 → TTL（接收） | 输出高电平（\~3.3V/5V） | -3V \~ -15V | 逻辑1 |
| RS232 → TTL（接收） | 输出低电平（\~0V） | +3V \~ +15V | 逻辑0 |


::: tip

**注意负逻辑：**RS232采用负逻辑，即负电压表示逻辑1，正电压表示逻辑0，这与TTL的正逻辑正好相反。MAX232在转换电平的同时也完成了逻辑极性的翻转。

:::


### 5.3.2 RS232电平范围与抗干扰优势

RS232最大的好处就是抗干扰能力有了很大的提升。原因如下：

1. **电压摆幅大：**RS232的信号摆幅可达±15V（典型±5V\~±12V），远大于TTL的0\~3.3V/5V摆幅。大摆幅意味着信号在传输过程中即使叠加了较大的噪声，接收端仍能正确区分逻辑0和逻辑1。
2. **阈值区间宽：**RS232的不确定区间为-3V\~+3V，逻辑0和逻辑1之间有6V的隔离带，噪声容限大。
3. **负逻辑设计：**空闲状态为负电压（逻辑1），与地电位有明显区分，减少了地线干扰的影响。

## 5.4 MAX232芯片详解

### 5.4.1 芯片功能

MAX232是Maxim公司推出的一款专为RS232串口设计的电平转换芯片，内部包含：

- 2路TTL→RS232发送驱动器（T1、T2）
- 2路RS232→TTL接收器（R1、R2）
- 内置电荷泵电压倍增器，可将单5V电源转换为±10V的RS232工作电压

### 5.4.2 外围电路（电容配置）

MAX232需要外接4个1μF的电解电容（或钽电容）用于电荷泵升压和电压反转：

| 电容 | 连接引脚 | 功能 |
|-|-|-|
| C1 | C1+（引脚2）与C1-（引脚1）之间 | 第一级升压电容 |
| C2 | C2+（引脚4）与C2-（引脚5）之间 | 第二级电压反转电容 |
| C3 | V+（引脚3）与GND（引脚15）之间 | 正电源滤波电容（+10V） |
| C4 | V-（引脚6）与GND（引脚15）之间 | 负电源滤波电容（-10V） |


::: tip

**提示：**MAX3232是MAX232的低电压版本，支持3.0V\~5.5V供电，电容可使用0.1μF，更适合3.3V系统的STM32。

:::


### 5.4.3 引脚连接关系

| MAX232引脚 | 连接对象 | 说明 |
|-|-|-|
| T1IN（引脚11） | STM32 TX（如PA9） | TTL发送输入，接单片机的发送脚 |
| T1OUT（引脚14） | DB9的第2脚（RXD） | RS232发送输出，接对方的接收脚 |
| R1IN（引脚13） | DB9的第3脚（TXD） | RS232接收输入，接对方的发送脚 |
| R1OUT（引脚12） | STM32 RX（如PA10） | TTL接收输出，接单片机的接收脚 |
| VCC（引脚16） | +5V 电源 | 芯片供电 |
| GND（引脚15） | 地 | 芯片地 |

## 5.5 DB9接口定义

RS232通讯线缆连接时常用DB9接头，来将两个设备间的线缆进行连接。DB9是一种9针的D-sub连接器，分为公头（针式）和母头（孔式）。

### 5.5.1 DB9引脚定义（DTE视角，公头）

| 引脚号 | 缩写 | 名称 | 方向（DTE） | 功能说明 |
|-|-|-|-|-|
| 1 | DCD | 数据载波检测 | 输入 | 检测到对方载波信号时有效 |
| 2 | RXD | 接收数据 | 输入 | 接收串行数据 |
| 3 | TXD | 发送数据 | 输出 | 发送串行数据 |
| 4 | DTR | 数据终端就绪 | 输出 | 通知对方本端已准备好 |
| 5 | GND | 信号地 | — | 公共参考地 |
| 6 | DSR | 数据设备就绪 | 输入 | 对方通知已准备好 |
| 7 | RTS | 请求发送 | 输出 | 请求对方准备接收数据 |
| 8 | CTS | 清除发送 | 输入 | 对方允许发送 |
| 9 | RI | 振铃指示 | 输入 | 检测到振铃信号时有效 |

### 5.5.2 三线制最简连接（无硬件流控）

在大多数嵌入式应用中，只需要3根线即可完成全双工通讯：

| 设备A（DTE） | 设备B（DTE/STM32侧） |
|-|-|
| 引脚2 RXD | 引脚3 TXD |
| 引脚3 TXD | 引脚2 RXD |
| 引脚5 GND | 引脚5 GND |


::: tip

**记忆口诀：**DB9对接时，2接3、3接2、5接5。如果是STM32经MAX232接PC，PC端DB9的2脚（RXD）接MAX232的T1OUT，PC端DB9的3脚（TXD）接MAX232的R1IN。

:::


## 5.6 硬件连接步骤

1. **准备材料：**STM32开发板、MAX232模块（或MAX3232模块）、DB9公头/母头连接器、RS232串口线、PC机（需有RS232接口或USB转RS232适配器）。
2. **连接MAX232模块电源：**将MAX232模块的VCC接+5V（MAX3232可接3.3V或5V），GND接开发板GND。
3. **连接STM32与MAX232的TTL侧：**

   - STM32的TX（PA9）→ MAX232的T1IN（引脚11）
   - STM32的RX（PA10）→ MAX232的R1OUT（引脚12）
4. **连接MAX232的RS232侧与DB9：**

   - MAX232的T1OUT（引脚14）→ DB9的第2脚（RXD，对DTE而言是接收）
   - MAX232的R1IN（引脚13）→ DB9的第3脚（TXD，对DTE而言是发送）
   - GND → DB9的第5脚（GND）
5. **连接RS232线缆：**用RS232串口线将DB9连接器与PC的RS232接口（或USB转RS232适配器）连接。
6. **确认PC端串口号：**如果使用USB转RS232适配器，在设备管理器中确认虚拟串口号。


::: tip

**重要提醒：**RS232电平最高可达±15V，切勿将RS232侧的信号线直接接到STM32的GPIO引脚上，否则会烧毁单片机！必须经过MAX232等电平转换芯片。

:::


## 5.7 软件配置步骤

RS232通讯的软件配置与USB串口通讯（TTL串口）完全相同，因为电平转换是由MAX232硬件完成的，STM32侧仍然是标准的UART外设。以下是简要步骤：

1. 在STM32CubeMX中配置USART为异步模式（Asynchronous）。
2. 设置波特率（常用9600或115200）、8位数据位、无校验、1位停止位。
3. 如需接收，使能USART全局中断。
4. 生成代码，使用HAL_UART_Transmit()发送数据，使用HAL_UART_Receive_IT()接收数据。

```c
uint8_t tx_data[] = "Hello, RS232!\r\n";
// 发送数据（与TTL串口代码完全一致）
HAL_UART_Transmit(&huart1, tx_data, sizeof(tx_data) - 1, 100);
```

## 5.8 实验验证步骤

1. 将STM32开发板通过ST-Link连接到PC，下载程序。
2. 用RS232线缆连接STM32侧的DB9与PC的RS232接口（或USB转RS232适配器）。
3. 打开PC端串口调试助手，选择对应的COM口。
4. 配置串口参数：波特率115200、数据位8、校验位None、停止位1、流控None。
5. 点击"打开串口"，观察接收区是否收到"Hello, RS232!"等数据。
6. 在发送区输入测试字符，点击"发送"，观察STM32是否正确接收并回显（如使用了回环代码）。
7. 验证完成后，关闭串口，断开连接。

## 5.9 常见问题与排查

| 问题现象 | 可能原因 | 排查方法 |
|-|-|-|
| 完全收不到数据 | TX/RX接反 / MAX232电容接错或漏接 / 未共地 / DB9引脚对应错误 | 检查交叉连接；确认4个电容正确连接；确认GND相连；用万用表通断档检查DB9焊接 |
| 收到乱码 | 波特率不匹配 / 时钟配置错误 / MAX232供电不稳定 | 核对两端波特率；检查STM32时钟树；测量MAX232的VCC引脚电压是否稳定 |
| 数据时有时无 | 接触不良 / 线缆过长 / 电容容量不足 | 重新插拔DB9连接器；缩短RS232线缆（≤15米）；更换为1μF正品电容 |
| 只能发不能收 | MAX232接收器损坏 / R1IN/R1OUT接反 / STM32 RX引脚配置错误 | 用示波器测量R1IN是否有RS232电平信号；检查R1OUT是否有TTL电平输出；确认CubeMX引脚配置 |
| STM32引脚发烫或烧毁 | RS232电平直接接到了STM32引脚（未经过MAX232） | 立即断电！检查接线，确保RS232侧信号只接MAX232的RS232侧引脚，不直接接触STM32 |

# printf串口终端重定向

## 6.1 为什么需要重定向

printf是C标准库函数，默认将输出发送到stdout（标准输出）。在PC上stdout对应屏幕，但STM32单片机没有屏幕，printf的输出无处可去。因此需要将printf的输出重定向到串口，通过串口调试助手在PC上查看打印信息。


::: tip

**核心原理：**printf底层最终调用_write()函数（GCC/CubeIDE）或fputc()函数（KEIL）输出单个字符。重写这个函数，让它把字符通过串口发送出去，即可实现printf重定向。

:::


## 6.2 实现步骤（CubeIDE环境）

1. **配置串口：**在STM32CubeMX中配置USART1为异步模式，波特率115200，生成代码。
2. **确认工程配置：**CubeIDE默认使用newlib-nano精简C库，无需像KEIL那样勾选MicroLIB。若程序卡在printf处，需在工程属性 → C/C++ Build → Settings → Tool Settings → MCU GCC Linker → Miscellaneous中，确认Linker flags包含`-specs=nosys.specs`（禁用半主机模式）。
3. **重写_write函数：**在main.c中添加以下代码：

```c
#include <stdio.h>  // 必须包含，用于printf声明

// 重写_write函数，将printf输出重定向到USART1
int _write(int file, char *ptr, int len)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)ptr, len, 100);
    return len;
}
```

## 6.3 使用方法

完成上述配置后，就可以像在PC上一样直接使用printf：

```c
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_USART1_UART_Init();

    int count = 0;
    while (1)
    {
        printf("Hello STM32! count = %d\r\n", count++);
        printf("温度: %.1f C, 电压: %.2f V\r\n", 25.5, 3.30);
        HAL_Delay(1000);
    }
}
```

打开串口调试助手（波特率115200），即可看到打印输出。

## 6.4 KEIL环境的区别

如果使用KEIL编译器，需要勾选Use MicroLIB，且重写的是`fputc`函数而非`_write`函数：

```c
#include <stdio.h>

// KEIL环境：重写fputc函数，需先勾选Use MicroLIB
int fputc(int ch, FILE *f)
{
    HAL_UART_Transmit(&huart1, (uint8_t *)&ch, 1, 100);
    return ch;
}
```

## 6.5 注意事项

- **串口句柄名：**代码中的`&huart1`要与实际使用的串口号一致（USART2对应`&huart2`）。
- **换行符：**串口调试助手显示换行需要`\r\n`（回车+换行），只用`\n`可能显示异常。
- **阻塞发送：**上述方法使用轮询发送，printf会阻塞直到发送完成。对实时性要求高的场景可改用DMA或环形缓冲区。
- **浮点支持：**CubeIDE/GCC环境下若浮点打印为空白，需在工程属性 → MCU GCC Linker → Miscellaneous中添加链接选项`-u _printf_float`；KEIL中默认支持printf浮点输出。

# PM2.5传感器数据采集

## 7.1 传感器概述

本实验选用的PM2.5传感器型号为**GP2Y1026AU0F**，是一款使用TTL串口通信的光学灰尘传感器，通常用于空气质量监测，测量大气中颗粒物（PM2.5和PM10）的浓度。

传感器每隔一段时间主动发送一帧当前环境数据，单片机只需通过串口接收并解析即可。

## 7.2 通信参数与数据帧协议

### 7.2.1 串口通信参数

| 参数 | 值 |
|-|-|
| 波特率 | 2400 |
| 数据位 | 8位 |
| 停止位 | 1位 |
| 校验位 | 无 |
| 通信方式 | 传感器主动发送，单片机接收（单向） |

### 7.2.2 数据帧格式（7字节）

| 字节序号 | 字段 | 说明 | 示例值 |
|-|-|-|-|
| 第1字节 | 起始位 | 固定为 0xAA，帧头标识 | 0xAA |
| 第2字节 | Vout(H) | 输出电压高字节 | 0x01 |
| 第3字节 | Vout(L) | 输出电压低字节 | 0x3A |
| 第4字节 | Vref(H) | 参考电压高字节 | 0x00 |
| 第5字节 | Vref(L) | 参考电压低字节 | 0x36 |
| 第6字节 | 校验位 | 数据校验 | 0x71 |
| 第7字节 | 结束位 | 固定为 0xFF，帧尾标识 | 0xFF |

## 7.3 数据解析与浓度计算

### 7.3.1 电压换算公式

将Vout高低字节合并为原始值，再换算为实际电压：

```c
Vout = (Vout_H * 256 + Vout_L) / 1024.0 * 5.0;

// 示例：Vout_H=0x01, Vout_L=0x3A
// Vout = (1 * 256 + 58) / 1024 * 5 = 1.533 V
```

### 7.3.2 粉尘浓度换算公式

将电压转换为粉尘浓度，比例系数 A = 3300 ug/m³：

```c
Ud = A * Vout;
// Ud：粉尘浓度，单位 ug/m³
// Vout：传感器输出电压，单位 V
// A：比例系数，取 3300 ug/m³（即 3.3 mg/m³）

// 示例：Ud = 3300 * 1.533 = 5058.9 ug/m³
```


::: tip

**注意：**示例中的浓度值偏高，实际环境中PM2.5浓度通常在几十到几百ug/m³之间。换算系数A需根据传感器 datasheet 或实际校准调整。

:::


## 7.4 CubeIDE实现流程

### 7.4.1 STM32CubeMX配置

1. 打开STM32CubeMX，选择芯片型号（如STM32F103C8T6）。
2. 配置USART2（或其他空闲USART）为异步模式（Asynchronous）。
3. 参数设置：Baud Rate = **2400**，Word Length = 8 Bits，Parity = None，Stop Bits = 1。
4. 在NVIC Settings中勾选USART2全局中断，使能接收中断。
5. 配置时钟树，生成代码。

### 7.4.2 中断接收与数据解析代码

在main.c中添加以下代码，使用中断方式逐字节接收，检测帧头0xAA后缓存7字节，收到帧尾0xFF后解析：

```c
#include <stdio.h>

uint8_t pm25_rx_byte;       // 单字节接收缓冲
uint8_t pm25_buf[7];        // 7字节数据帧缓冲
uint8_t pm25_index = 0;     // 当前接收位置
uint8_t pm25_receiving = 0; // 是否正在接收帧
float pm25_voltage = 0;     // 解析出的电压
float pm25_density = 0;     // 解析出的浓度 ug/m³

// 在main函数中启动接收中断
HAL_UART_Receive_IT(&huart2, &pm25_rx_byte, 1);

// 串口接收完成回调
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART2)
    {
        if (pm25_rx_byte == 0xAA)  // 检测到帧头
        {
            pm25_index = 0;
            pm25_receiving = 1;
            pm25_buf[pm25_index++] = pm25_rx_byte;
        }
        else if (pm25_receiving)
        {
            pm25_buf[pm25_index++] = pm25_rx_byte;
            if (pm25_index >= 7)  // 收满7字节
            {
                pm25_receiving = 0;
                if (pm25_buf[6] == 0xFF)  // 校验帧尾
                {
                    // 解析电压
                    uint16_t vout_raw = (pm25_buf[1] << 8) | pm25_buf[2];
                    pm25_voltage = vout_raw / 1024.0f * 5.0f;
                    // 换算浓度，A=3300
                    pm25_density = 3300.0f * pm25_voltage;
                }
            }
        }
        // 重新启动接收中断
        HAL_UART_Receive_IT(&huart2, &pm25_rx_byte, 1);
    }
}
```

## 7.5 寄存器方式实现

不使用HAL库，直接操作USART寄存器完成接收与解析。适用于需要精简代码或深入理解硬件的场景。

### 7.5.1 USART寄存器初始化

```c
void USART2_Register_Init(void)
{
    // 1. 使能GPIOA和USART2时钟
    RCC->APB2ENR |= RCC_APB2ENR_IOPAEN;
    RCC->APB1ENR |= RCC_APB1ENR_USART2EN;

    // 2. 配置PA3为浮空输入（RX），PA2为复用推挽输出（TX）
    GPIOA->CRL &= ~(GPIO_CRL_CNF3 | GPIO_CRL_MODE3);
    GPIOA->CRL |= GPIO_CRL_CNF3_0;  // PA3浮空输入
    GPIOA->CRL &= ~(GPIO_CRL_CNF2 | GPIO_CRL_MODE2);
    GPIOA->CRL |= GPIO_CRL_CNF2_1 | GPIO_CRL_MODE2_1;  // PA2复用推挽50MHz

    // 3. 设置波特率 2400（假设PCLK1=36MHz）
    // USARTDIV = 36000000 / (16 * 2400) = 937.5
    // DIV_Mantissa = 937 = 0x3A9, DIV_Fraction = 0.5*16 = 8
    USART2->BRR = 0x3A98;

    // 4. 配置数据格式：8位数据、1停止位、无校验
    USART2->CR1 = 0;  // 清零，M=0(8位), PCE=0(无校验)
    USART2->CR2 = 0;  // STOP=00(1停止位)

    // 5. 使能接收中断、接收器和发送器
    USART2->CR1 |= USART_CR1_RXNEIE;  // 接收缓冲区非空中断
    USART2->CR1 |= USART_CR1_RE;      // 使能接收
    USART2->CR1 |= USART_CR1_TE;      // 使能发送
    USART2->CR1 |= USART_CR1_UE;      // 使能USART

    // 6. 配置NVIC中断优先级
    NVIC_SetPriority(USART2_IRQn, 1);
    NVIC_EnableIRQ(USART2_IRQn);
}
```

### 7.5.2 中断服务函数与数据解析

```c
uint8_t reg_buf[7];

uint8_t recv_flag = 0;
float reg_voltage = 0, reg_density = 0;

{

    {

        if (data == 0xAA)  // 帧头
        {

            recv_flag = 1;
            reg_buf[reg_idx++] = data;

        else if (recv_flag)
        {
            reg_buf[reg_idx++] = data;
            if (reg_idx >= 7 && reg_buf[6] == 0xFF)
            {
                recv_flag = 0;
                uint16_t raw = (reg_buf[1] << 8) | reg_buf[2];
                reg_voltage = raw / 1024.0f * 5.0f;
                reg_density = 3300.0f * reg_voltage;
            }
        }
    }
}
```

# 土壤温湿度数据采集

## 8.1 传感器概述

土壤温湿度传感器采用**RS485**物理接口和**Modbus-RTU**通信协议，单片机通过RS485转换芯片与传感器通信。

通信采用**应答机制**：单片机先发送请求帧，传感器收到后返回包含温湿度数据的响应帧。

## 8.2 RS485电平标准与硬件转换

### 8.2.1 RS485电平标准

RS485采用差分信号，用A线与B线的电压差值确定逻辑值：

| 逻辑值 | 电压差 (A - B) |
|-|-|
| 逻辑 1 | +2V \~ +6V |
| 逻辑 0 | -2V \~ -6V |

差分信号具有很强的抗干扰能力，支持长距离传输（最大约1200米）和多设备总线组网。

### 8.2.2 TTL转RS485

STM32单片机串口管脚输出的是TTL电平，使用RS485通讯时需要增加TTL转RS485电平转换芯片（如MAX485、SP3485）。

芯片包含DE（发送使能）和RE（接收使能）引脚，通常短接在一起由一个GPIO控制：

- DE/RE = 高电平 → 发送模式
- DE/RE = 低电平 → 接收模式

## 8.3 Modbus-RTU协议概述

Modbus是一种基于串行通信的工业通信协议，RTU模式使用二进制编码。一帧Modbus-RTU数据包含四部分：

| 域 | 长度 | 说明 |
|-|-|-|
| 地址域 | 1字节 | 从机地址，0x01\~0xF7 |
| 功能码 | 1字节 | 0x03=读保持寄存器 |
| 数据域 | N字节 | 起始地址、数据长度或寄存器数据 |
| 差错校验 | 2字节 | CRC16，低字节在前，高字节在后 |

## 8.4 通信参数

| 参数 | 值 |
|-|-|
| 波特率 | 4800 |
| 数据位 | 8位 |
| 停止位 | 1位 |
| 校验位 | 无 |
| 设备地址 | 默认 0x01 |
| 功能码 | 0x03（读保持寄存器） |

## 8.5 请求与响应数据帧

### 8.5.1 请求帧（8字节，单片机→传感器）

| 字段 | 地址码 | 功能码 | 起始地址(H) | 起始地址(L) | 数据长度(H) | 数据长度(L) | CRC低 | CRC高 |
|-|-|-|-|-|-|-|-|-|
| 值 | 0x01 | 0x03 | 0x00 | 0x00 | 0x00 | 0x02 | 0xC4 | 0x0B |

含义：读取地址为0x01的从机，从保持寄存器0x0000开始，读取2个寄存器（湿度+温度）。

### 8.5.2 响应帧（9字节，传感器→单片机）

| 字段 | 地址码 | 功能码 | 字节数 | 湿度(H) | 湿度(L) | 温度(H) | 温度(L) | CRC低 | CRC高 |
|-|-|-|-|-|-|-|-|-|-|
| 值 | 0x01 | 0x03 | 0x04 | 0x01 | 0xE6 | 0xFF | 0x9F | 0x1B | 0xA0 |

## 8.6 数据解析

### 8.6.1 湿度计算

湿度值为无符号16位整数，除以10得到实际湿度百分比：

```c
uint16_t hum_raw = (buf[3] << 8) | buf[4];  // 0x01E6 = 486
float humidity = hum_raw / 10.0f;               // 48.6 %
```

### 8.6.2 温度计算

温度值为有符号16位整数，低于0℃时以补码形式上传，除以10得到实际温度：

```c
int16_t temp_raw = (int16_t)((buf[5] << 8) | buf[6]);  // 0xFF9F = -97（补码）
float temperature = temp_raw / 10.0f;                      // -9.7 ℃
```


::: tip

**补码说明：**0xFF9F作为有符号16位数，最高位为1表示负数。其绝对值 = \~0xFF9F + 1 = 0x0061 = 97，因此温度 = -97 / 10 = -9.7℃。使用int16_t强制转换可自动处理补码。

:::


## 8.7 CubeIDE实现流程

### 8.7.1 STM32CubeMX配置

1. 配置USART3（或其他空闲USART）为异步模式，波特率**4800**，8位数据，1停止位，无校验。
2. 配置一个GPIO作为RS485的DE/RE控制脚（如PB0），输出模式，默认低电平（接收模式）。
3. 在NVIC Settings中使能USART3全局中断。
4. 配置时钟树，生成代码。

### 8.7.2 完整代码实现

```c
#include <stdio.h>
#include <stdint.h>

#define RS485_DE_PORT GPIOB
#define RS485_DE_PIN  GPIO_PIN_0
#define RS485_TX_EN()  HAL_GPIO_WritePin(RS485_DE_PORT, RS485_DE_PIN, GPIO_PIN_SET)
#define RS485_RX_EN()  HAL_GPIO_WritePin(RS485_DE_PORT, RS485_DE_PIN, GPIO_PIN_RESET)

uint8_t soil_tx_buf[8] = {0x01, 0x03, 0x00, 0x00, 0x00, 0x02, 0xC4, 0x0B};
uint8_t soil_rx_buf[9];
uint8_t soil_rx_idx = 0;
uint8_t soil_rx_byte;
uint8_t soil_data_ready = 0;
float soil_humidity = 0, soil_temperature = 0;

// CRC16-Modbus校验计算
uint16_t Modbus_CRC16(uint8_t *buf, uint8_t len)
{
    uint16_t crc = 0xFFFF;
    for (uint8_t i = 0; i < len; i++)
    {
        crc ^= buf[i];
        for (uint8_t j = 0; j < 8; j++)
        {
            if (crc & 0x0001)
                crc = (crc >> 1) ^ 0xA001;
            else
                crc >>= 1;
        }
    }
    return crc;
}

// 发送Modbus请求
void Soil_SendRequest(void)
{
    soil_rx_idx = 0;
    soil_data_ready = 0;
    RS485_TX_EN();                              // 切换到发送模式
    HAL_UART_Transmit(&huart3, soil_tx_buf, 8, 100);
    RS485_RX_EN();                              // 发送完切回接收模式
    HAL_UART_Receive_IT(&huart3, &soil_rx_byte, 1);
}

// 串口接收中断回调
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    if (huart->Instance == USART3)
    {
        if (soil_rx_idx < 9)
            soil_rx_buf[soil_rx_idx++] = soil_rx_byte;
        if (soil_rx_idx >= 9)
        {
            // 校验CRC
            uint16_t crc_recv = soil_rx_buf[7] | (soil_rx_buf[8] << 8);
            uint16_t crc_calc = Modbus_CRC16(soil_rx_buf, 7);
            if (crc_recv == crc_calc && soil_rx_buf[0] == 0x01 && soil_rx_buf[1] == 0x03)
            {
                uint16_t hum_raw = (soil_rx_buf[3] << 8) | soil_rx_buf[4];
                int16_t temp_raw = (int16_t)((soil_rx_buf[5] << 8) | soil_rx_buf[6]);
                soil_humidity = hum_raw / 10.0f;
                soil_temperature = temp_raw / 10.0f;
                soil_data_ready = 1;
            }
        }
        else
        {
            HAL_UART_Receive_IT(&huart3, &soil_rx_byte, 1);
        }
    }
}

// main函数中周期性查询
int main(void)
{
    HAL_Init();
    SystemClock_Config();
    MX_USART3_UART_Init();
    MX_GPIO_Init();
    RS485_RX_EN();  // 默认接收模式
    HAL_UART_Receive_IT(&huart3, &soil_rx_byte, 1);

    while (1)
    {
        Soil_SendRequest();
        HAL_Delay(500);  // 等待响应
        if (soil_data_ready)
            printf("Humidity: %.1f%%, Temperature: %.1f C\r\n",
                   soil_humidity, soil_temperature);
        HAL_Delay(1500);
    }
}
```

## 8.8 寄存器方式实现

### 8.8.1 USART3与GPIO初始化

```c
void RS485_Register_Init(void)
{
    // 使能GPIOB、GPIOD和USART3时钟（F103: USART3在APB1，PB10=TX, PB11=RX）
    RCC->APB2ENR |= RCC_APB2ENR_IOPBEN;
    RCC->APB1ENR |= RCC_APB1ENR_USART3EN;

    // PB0：推挽输出（DE/RE控制）
    GPIOB->CRL &= ~(GPIO_CRL_CNF0 | GPIO_CRL_MODE0);
    GPIOB->CRL |= GPIO_CRL_MODE0_1;  // 50MHz推挽输出
    GPIOB->BRR = GPIO_BRR_BR0;        // 默认低电平=接收模式

    // PB10(TX)：复用推挽输出；PB11(RX)：浮空输入
    GPIOB->CRH &= ~(GPIO_CRH_CNF10 | GPIO_CRH_MODE10 | GPIO_CRH_CNF11 | GPIO_CRH_MODE11);
    GPIOB->CRH |= GPIO_CRH_CNF10_1 | GPIO_CRH_MODE10_1;  // PB10复用推挽50MHz
    GPIOB->CRH |= GPIO_CRH_CNF11_0;                         // PB11浮空输入

    // 波特率4800（PCLK1=36MHz）：USARTDIV=36000000/(16*4800)=468.75
    // DIV_Mantissa=468=0x1D4, DIV_Fraction=0.75*16=12=0xC
    USART3->BRR = 0x1D4C;

    // 8位数据、1停止位、无校验
    USART3->CR1 = 0;
    USART3->CR2 = 0;

    // 使能接收中断、接收、发送、USART
    USART3->CR1 |= USART_CR1_RXNEIE | USART_CR1_RE | USART_CR1_TE | USART_CR1_UE;

    NVIC_SetPriority(USART3_IRQn, 1);
    NVIC_EnableIRQ(USART3_IRQn);
}
```

### 8.8.2 寄存器方式发送与中断接收

```c
uint8_t reg_tx[8] = {0x01,0x03,0x00,0x00,0x00,0x02,0xC4,0x0B};
uint8_t reg_rx[9], reg_idx = 0, reg_done = 0;
float reg_hum = 0, reg_temp = 0;

// 寄存器方式发送单字节
void USART3_SendByte(uint8_t data)
{
    while (!(USART3->SR & USART_SR_TXE));
    USART3->DR = data;
    while (!(USART3->SR & USART_SR_TC));
}

// 发送Modbus请求
void Reg_SendRequest(void)
{
    reg_idx = 0; reg_done = 0;
    GPIOB->BSRR = GPIO_BSRR_BS0;  // DE=1发送模式
    for (uint8_t i = 0; i < 8; i++)
        USART3_SendByte(reg_tx[i]);
    GPIOB->BRR = GPIO_BRR_BR0;    // DE=0接收模式
}

// USART3中断服务函数
void USART3_IRQHandler(void)
{
    if (USART3->SR & USART_SR_RXNE)
    {
        uint8_t data = (uint8_t)USART3->DR;
        if (reg_idx < 9) reg_rx[reg_idx++] = data;
        if (reg_idx >= 9)
        {
            uint16_t crc_r = reg_rx[7] | (reg_rx[8] << 8);
            uint16_t crc_c = Modbus_CRC16(reg_rx, 7);
            if (crc_r == crc_c)
            {
                uint16_t h = (reg_rx[3]<<8)|reg_rx[4];
                int16_t t = (int16_t)((reg_rx[5]<<8)|reg_rx[6]);
                reg_hum = h/10.0f; reg_temp = t/10.0f;
                reg_done = 1;
            }
        }
    }
}
```
