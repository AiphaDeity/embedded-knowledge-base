# FS-6ULL硬件资源介绍

## 实验平台

**i.MX6ULL**：NXP（原飞思卡尔）推出的基于ARM Cortex-A7内核的低功耗应用处理器，主频800MHz，面向工业控制、物联网网关等嵌入式场景。

FS-6ULL是华清远见基于i.MX6ULL设计的教学开发板，核心板+底板分离设计，板载512MB DDR3、8GB eMMC及多种常用外设。

| 硬件 | 参数 |
|-|-|
| **CPU** | MCIMX6Y2CVM08AB，Cortex-A7内核，主频800MHz，BGA289封装 |
| **DDR3** | 512MB |
| **eMMC** | 8GB |
| **核心板尺寸** | 42mm×38mm，邮票孔引出146个引脚 |

底板外设：4个用户LED、六轴姿态传感器QMI8658A、两路RS232、地磁传感器、以太网、USB、LCD接口等。

# Cortex-A处理器概述

## ARM架构

**ARM架构**：ARM公司设计的RISC指令集架构，采用IP授权模式——ARM提供CPU设计，由合作伙伴（NXP、三星等）实现为具体芯片。

Cortex-A7是ARMv7-A架构下的高能效内核，主打低功耗与高性能平衡，广泛应用于嵌入式Linux设备。


::: tip

**为什么学裸机汇编**：直接操作寄存器、理解CPU工作原理、看懂U-Boot和Linux内核启动代码。不学裸机直接学驱动，很多底层概念（地址映射、中断、时钟树）会一头雾水。

:::


# Cortex-A7架构与工作模式

## 9种工作模式

**处理器工作模式**：Cortex-A7基于ARMv7-A架构，根据当前执行的代码权限和异常状态，CPU可工作在不同模式下，不同模式可访问的寄存器和系统资源不同。

除用户模式外，其余8种均为特权模式，可访问全部硬件资源并自由切换模式。

| 模式 | 简写 | 进入条件 |
|-|-|-|
| **用户模式** | usr | 正常程序运行模式（非特权），应用程序默认运行于此 |
| **快速中断** | fiq | 高优先级中断触发，用于高速数据传输 |
| **外部中断** | irq | 普通中断触发，常规中断处理 |
| **特权模式** | svc | 复位或软中断指令执行，操作系统保护模式 |
| **数据访问中止** | abt | 访存异常触发，用于虚拟存储与存储保护 |
| **未定义指令中止** | und | 执行未定义指令时触发 |
| **系统模式** | sys | 运行特权级操作系统任务，寄存器集与用户模式相同 |
| **监控模式** | mon | 安全与非安全模式间转换 |
| **虚拟化监控** | hyp | 虚拟化扩展，支持单系统多OS并行 |


::: tip

**模式分级的意义**：用户模式无法修改系统寄存器、无法直接切换模式，从而保证应用程序异常不会破坏系统安全；模式切换必须通过异常（中断/软中断）由操作系统控制。

:::


## 寄存器组织

**寄存器**：CPU内部高速存储单元，用于临时存放运算数据和中间结果，访问速度远高于内存。ARM寄存器通过编号访问（R0\~R15），无内存地址。

Cortex-A7共43个32位寄存器，按分组方式分为未分组寄存器与分组寄存器两类。

| 类型 | 说明 |
|-|-|
| **未分组寄存器** | R0\~R7，所有模式共用同一物理寄存器 |
| **分组寄存器** | R8\~R14，不同模式对应不同物理寄存器（banked），模式切换时自动切换 |

### 通用寄存器 R0\~R12

- **R0\~R7**：未分组，所有模式共用。中断进入时内容直接被覆盖，中断处理程序需自行保存恢复。
- **R8\~R12**：分组，每寄存器对应两个物理实例——普通模式一套，FIQ模式专用一套。


::: tip

**FIQ快速性原理**：FIQ模式拥有独立的R8_fiq\~R12_fiq，中断进入时无需保存这些寄存器，省去push/pop开销，因此响应更快。

:::


### R13 = SP 栈指针

**栈指针（Stack Pointer）**：R13约定用作栈指针，指向当前栈顶位置。栈是一块"先进后出"的内存区域，用于保存函数调用现场与局部变量。

每种异常模式拥有独立的SP，互不干扰。ARM栈为满递减（FD）：栈从高地址向低地址增长，push时SP先减再存，pop时先取再加。

```text
mov r5, #0x11
mov r6, #0x23
stmfd sp!, {r5, r6}   ; SP先减8，存入r5 r6
ldmfd sp!, {r7, r8}   ; 先取出，SP再加8

```

### R14 = LR 链接寄存器

**链接寄存器（Link Register）**：R14约定用作链接寄存器。执行BL指令调用子程序时，CPU自动将返回地址写入LR，子程序末尾跳转LR即可返回调用处。

```text
bl  delay    ; 跳转到delay，下一条指令地址存入LR
...          ; delay返回后从此继续

delay:
    ; delay函数体
    mov pc, lr   ; 返回

```

### R15 = PC 程序计数器

**程序计数器（Program Counter）**：R15存储当前指令地址，CPU取指后自动加4指向下一条指令。

### CPSR / SPSR 程序状态寄存器

**CPSR（Current Program Status Register）**：当前程序状态寄存器，记录CPU当前状态——条件标志位（N/Z/C/V）、中断使能位、工作模式位，所有模式均可读取。

**SPSR（Saved Program Status Register）**：备份程序状态寄存器，每种异常模式各有独立实例。异常进入时硬件自动将CPSR存入SPSR，退出时恢复。

| 寄存器 | 作用 |
|-|-|
| **CPSR** | 当前程序状态寄存器，存条件标志位+中断开关+当前模式 |
| **SPSR** | 备份程序状态寄存器，异常进入时自动保存CPSR |

CPSR关键位：

- **N/Z/C/V**：条件标志位（负数/零/进位/溢出），由比较与算术指令设置
- **I位**：IRQ中断禁止位（1=关闭）
- **F位**：FIQ中断禁止位（1=关闭）
- **M[4:0]**：当前模式位

# ARM指令系统

## 指令格式

**ARM指令**：固定32位长度，一条指令完成一个操作。由操作码、条件码、目标寄存器、操作数组成。

```text
<opcode>{<cond>}{S} <Rd>, <Rn>, <operand2>

示例：ADDEQS r0, r1, #5
含义：条件EQ满足时执行加法，结果影响标志位，r0 = r1 + 5

```

| 字段 | 说明 |
|-|-|
| **opcode** | 操作码（MOV/ADD/SUB等） |
| **cond** | 条件码（EQ/NE/CS/CC等），省略则为AL（无条件执行） |
| **S** | 带S则更新CPSR条件标志位 |
| **Rd** | 目标寄存器 |
| **Rn** | 第一操作数寄存器 |
| **operand2** | 第二操作数：立即数/寄存器/寄存器移位 |

## 寻址方式

**寻址方式**：CPU确定操作数位置的方式——操作数可直接编码于指令中、存于寄存器、或位于内存某地址。

| 寻址方式 | 示例与说明 |
|-|-|
| **立即寻址** | `mov r0, #5` —— 立即数直接编码于指令中 |
| **寄存器寻址** | `add r0, r1, r2` —— 操作数存于寄存器 |
| **寄存器间接寻址** | `ldr r0, [r1]` —— r1存储内存地址，从中取数据 |
| **基址加偏移** | `ldr r0, [r1, #4]` —— r1+4地址处取数据 |
| **多寄存器寻址** | `ldmia sp!, {r0-r3}` —— 批量读写多个寄存器 |

## 数据处理指令

| 指令 | 功能 |
|-|-|
| `MOV` | 数据传送：`mov r0, #0x12` |
| `ADD` | 加法：`add r0, r1, r2` → r0 = r1 + r2 |
| `SUB` | 减法：`sub r0, r1, #5` → r0 = r1 - 5 |
| `AND` | 按位与 |
| `ORR` | 按位或 |
| `BIC` | 位清零 |
| `CMP` | 比较（仅修改标志位，不写结果） |

## 分支跳转指令

| 指令 | 功能 |
|-|-|
| `B` | 无条件跳转，不保存返回地址 |
| `BL` | 跳转并保存返回地址至LR，用于子程序调用 |
| `BX` | 跳转并切换指令集（ARM/Thumb） |

## Load/Store内存访问指令

**Load/Store架构**：ARM为RISC架构，内存访问必须通过专用Load/Store指令完成，不支持内存直接参与运算。

| 指令 | 功能 |
|-|-|
| `LDR` | 从内存读取32位数据至寄存器 |
| `STR` | 将寄存器32位数据写入内存 |
| `LDRB` | 读取单字节 |
| `STRB` | 写入单字节 |
| `LDM/STM` | 多寄存器批量读写，栈操作常用 |


::: tip

**LDR伪指令与LDR真指令的区别**：`ldr r0, =0x12345678`（带等号）为伪指令，由汇编器将常量存于文字池后读入；`ldr r0, [r1]`为真指令，从r1地址读取内存。

:::


## 特殊寄存器访问指令

| 指令 | 功能 |
|-|-|
| `MRS` | 读取CPSR/SPSR至通用寄存器 |
| `MSR` | 将通用寄存器写入CPSR/SPSR |

```text
; 开启IRQ中断
mrs r0, cpsr
bic r0, #0x80    ; 清除I位
msr cpsr, r0

; 关闭IRQ中断
mrs r0, cpsr
orr r0, #0x80
msr cpsr, r0

```

# AAPCS 调用约定

**AAPCS（ARM Architecture Procedure Call Standard）**：ARM架构过程调用标准，规定函数调用时参数传递、返回值位置、寄存器保存规则，保证C与汇编代码可正确互调。

| 寄存器 | 用途 |
|-|-|
| **R0\~R3** | 传递前4个参数，R0同时存放返回值 |
| **R4\~R11** | 被调用者需保存（使用前需压栈） |
| **R13(SP)** | 栈指针 |
| **R14(LR)** | 返回地址 |
| **R15(PC)** | 程序计数器 |


::: tip

**参数超过4个时**：R0\~R3传递前4个，第5个及以后通过栈传递。因此编写汇编函数时，R0\~R3可自由使用无需保存，R4\~R11若使用则必须压栈保护。

:::


# 流水线

**指令流水线（Pipeline）**：将一条指令的执行拆分为取指、译码、执行等阶段，各阶段并行处理不同指令，提升CPU吞吐率。

```text
时刻1: 取指(指令3)
时刻2: 译码(指令3) + 取指(指令2)
时刻3: 执行(指令3) + 译码(指令2) + 取指(指令1)

```


::: tip

**PC值偏移原因**：流水线同时处理多条指令，PC始终指向下一条待取指指令，而非当前执行指令，因此调试时PC值比当前指令地址大8。

:::

# GPIO控制器

## GPIO

**GPIO（General Purpose Input/Output）**：通用输入输出端口，CPU引脚可通过软件配置为输入（读取电平）或输出（控制电平）。

## I.MX6ULL引脚结构

单个引脚使用需配置三层寄存器：

1. **引脚复用（IOMUXC MUX）**：选择引脚功能（GPIO/UART/SPI等）
2. **电气属性（IOMUXC PAD）**：上下拉、驱动强度、压摆率
3. **GPIO方向与数据**：输入/输出方向，输出电平值

| 寄存器 | 功能 |
|-|-|
| **IOMUXC_SW_MUX_CTL_PAD_XX** | 引脚复用功能选择（ALT0\~ALT8） |
| **IOMUXC_SW_PAD_CTL_PAD_XX** | 电气属性配置（上下拉/驱动强度） |
| **GPIOx_DR** | 数据寄存器：写入为输出电平，读取为输入电平 |
| **GPIOx_GDIR** | 方向寄存器：1=输出，0=输入 |

## 点灯代码（C语言）

```c
// LED接在GPIO1_IO03
#define MUX_CTL   0x020E006C
#define PAD_CTL   0x020E02F8
#define GPIO_DR   0x0209C000
#define GPIO_GDIR 0x0209C004

// 1. 配置引脚复用为GPIO功能
*(volatile unsigned int *)MUX_CTL = 5;
// 2. 配置电气属性
*(volatile unsigned int *)PAD_CTL = 0x10B0;
// 3. 设置方向为输出
*(volatile unsigned int *)GPIO_GDIR |= (1 << 3);
// 4. 输出低电平点亮LED
*(volatile unsigned int *)GPIO_DR &= ~(1 << 3);

```


::: tip

**volatile关键字的作用**：硬件寄存器值可能随时变化，volatile告诉编译器不要优化缓存该地址，每次读写必须真实访问内存。

:::


# 时钟控制器

## 时钟门控

**时钟门控（Clock Gating）**：为降低功耗，I.MX6ULL默认关闭所有外设时钟。使用外设前必须先开启对应时钟门控，否则寄存器操作无效。

## 时钟树

**时钟树**：外部晶振经PLL倍频与分频后，生成不同频率的时钟供给CPU内核、DDR、总线及各外设。

| 时钟域 | 用途 |
|-|-|
| **PLL1(ARM)** | CPU内核时钟 |
| **PLL2(SYS)** | 系统总线、DDR |
| **PLL3(USB)** | USB |
| **PLL4(AUDIO)** | 音频接口 |
| **PLL5(OTHER)** | USB、网络、UART等外设 |

# UART串口

## UART

**UART（Universal Asynchronous Receiver/Transmitter）**：通用异步收发器，串行通信接口，无时钟线，双方约定波特率后逐位收发数据。

| 参数 | 常用值 |
|-|-|
| **波特率** | 115200 |
| **数据位** | 8位 |
| **停止位** | 1位 |
| **校验位** | 无校验 |

## 串口初始化步骤

1. 开启UART与GPIO时钟
2. 配置引脚复用为UART功能
3. 设置波特率
4. 设置数据格式（8N1）
5. 使能收发

# 异常与中断

## 异常向量表

**异常向量表（Exception Vector Table）**：固定地址的跳转表，每种异常对应一个表项，CPU复位后从表首开始执行。

| 偏移 | 异常类型 | 进入模式 |
|-|-|-|
| 0x00 | 复位 | svc |
| 0x04 | 未定义指令 | und |
| 0x08 | 软中断SWI | svc |
| 0x0C | 指令中止 | abt |
| 0x10 | 数据中止 | abt |
| 0x18 | IRQ中断 | irq |
| 0x1C | FIQ中断 | fiq |

## GIC中断控制器

**GIC（Generic Interrupt Controller）**：通用中断控制器，管理系统所有中断源的优先级、使能与CPU分发。

## 中断处理流程

1. 中断触发，CPU自动切换至对应模式，CPSR存入SPSR，返回地址存入LR
2. PC跳转至异常向量表对应入口
3. 中断处理程序：保存现场 → 处理中断 → 恢复现场 → 中断返回
4. 中断返回使用 `movs pc, lr`（带S标志同时恢复CPSR）


::: tip

**中断返回必须使用movs**：普通mov仅跳转回LR，不恢复CPSR；movs同时将SPSR恢复至CPSR，保证中断前状态完整恢复。

:::


# MMU地址映射

## MMU

**MMU（Memory Management Unit）**：内存管理单元，负责将CPU发出的虚拟地址转换为物理地址，并执行内存访问权限控制。

| 无MMU | 有MMU |
|-|-|
| 程序直接操作物理地址 | 程序使用虚拟地址，MMU翻译为物理地址 |
| 所有程序共享地址空间，易互相破坏 | 各进程独立虚拟地址空间，互不干扰 |
| 不支持Cache与内存保护 | 支持Cache、内存保护、虚拟内存 |

## 页表

**页表（Page Table）**：MMU地址映射的查找表，记录虚拟页与物理页的对应关系。Linux采用多级页表，单页大小通常为4KB。


::: tip

**裸机开启MMU的意义**：开启MMU后才能启用Cache，可显著提升系统性能。U-Boot与Linux内核启动阶段均会开启MMU与Cache。

:::
