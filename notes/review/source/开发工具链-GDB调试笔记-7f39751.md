# 开发工具链-GDB调试笔记

::: tip

本笔记整理自嵌入式开发工具链核心考点，共 **8 组** 问答，覆盖GDB调试、交叉编译、Makefile、Git、JTAG调试等。

## 1. GDB调试的基本流程是什么？

1. 编译时加 -g 参数生成调试信息；2. 启动gdb ./程序名；3. 设置断点：break 行号/函数名；4. run运行程序；5. 程序停在断点后，用next/step单步执行；6. print 变量名查看变量；7. continue继续运行。

## 2. GDB中next和step的区别？

next（n）：单步执行，但不会进入函数内部，把函数调用当一步执行。step（s）：单步执行，会进入函数内部，逐行执行函数里的代码。

## 3. 交叉编译是什么？

在一个平台（比如x86的PC）上编译出能在另一个不同架构平台（比如ARM开发板）上运行的程序。因为嵌入式设备性能弱，不方便本地编译，所以在PC上用交叉编译工具链（如arm-linux-gcc）编译。

## 4. Makefile的作用是什么？

自动化编译管理工具，定义了源文件之间的依赖关系和编译规则。输入make命令就会自动根据修改时间判断哪些文件需要重新编译，不用手动敲gcc命令。

## 5. Git常用命令有哪些？

git init初始化仓库；git add .添加文件；git commit -m '说明'提交；git push推送远程；git pull拉取更新；git branch查看分支；git checkout 分支名切换分支；git merge合并分支。

## 6. 嵌入式调试的常用方法有哪些？

1. 打印调试：printf输出关键变量；2. GDB调试：在线调试断点；3. JTAG/SWD调试：硬件级调试；4. 逻辑分析仪：看时序；5. 串口日志：看运行状态；6. 单元测试：模块级验证。

## 7. 什么是JTAG/SWD？

硬件调试接口，JTAG是标准的4线接口，SWD是ARM简化的2线接口。可以连接调试器（如J-Link）直接读写CPU寄存器、内存，设置断点，单步运行，是嵌入式开发最常用的硬件调试手段。

## 8. 编译时为什么要加-g参数？

-g参数告诉编译器生成调试信息，把源码行号、变量名等信息写入可执行文件，这样GDB调试时才能知道当前执行到哪一行，变量是什么名字。不加-g的话GDB只能看到汇编代码。
