# Modbus–MQTT 网关的数据交接

网关在 RS-485 上读取 Modbus 从站，将寄存器解释为采集值，再经存储交给 MQTT 上报路径。这篇笔记对应公开源码的 `34a5303` 版本。

## 采集值怎样走到 MQTT

| 交接 | 阅读时要找什么 |
| --- | --- |
| RS-485 → Modbus 校验 | 哪个分支接收应答，超时和 CRC 错误什么时候结束本轮 |
| 寄存器 → 点表 | 站号、寄存器位置、数据类型和缩放因子如何决定工程量 |
| 采集快照 → 存储 | 有效数据何时形成上报记录，记录何时入队，何时可从存储取回 |
| 存储 → MQTT | 发送端按哪个序号发布，收到确认后怎样把结果交回存储 |

## 排查一条没有上报的采集值

先用站号和寄存器定位一次从站请求，在应答中核对原始字节。解析结果正确后，沿同一个记录序号查入队、存储提交、MQTT 发布和确认。采集日志里的 `queued` 说明写请求进入队列。确认是否提交时，继续查存储端的相应记录。

源码和应答错误分支已在对应版本的阅读路线中核对。整机数据路径的实测结果需要与当时的从站配置、网关版本和设备记录一起保存。
